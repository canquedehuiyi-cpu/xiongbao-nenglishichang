# 执行层协议

## 一、渐进增强架构

三级降级体系，确保任何环境下可用：

| 级别 | 模式 | 条件 | 能力 |
|------|------|------|------|
| L1 | 脚本增强 | Node.js ≥18 与 Python ≥3.8 均可用 | 全部脚本可执行，精确计算 |
| L2 | CLI基础 | 仅Python或仅Node.js可用 | 可用部分脚本，其余降级为LLM推理 |
| L3 | 纯知识 | 无脚本环境 | 仅SKILL.md+references知识，LLM直接推理；易变事实无法实时核实时必须标注"估算/未实时核实" |

### 降级策略

1. **脚本调用失败** → 优雅降级：输出错误信息 + 切换为LLM推理 + 记录降级事件
2. **连续失败**（同一脚本3次） → 标记脚本不可用，本次会话不再调用
3. **环境检测** → 首次调用脚本前检测运行时，缺失则直接进入L3

## 二、环境前置检查

调用任何脚本前，必须验证：

```bash
# Python 脚本
python --version 2>&1 || python3 --version 2>&1

# Node.js 脚本
node --version 2>&1
```

- Python ≥3.8 → 可用 financial_calculator.py（仅依赖标准库）
- Node.js ≥18 → 可用 state.mjs / knowledge-filter.mjs（仅依赖内置模块）
- 两者均不可用 → 进入L3纯知识模式

## 三、脚本清单

| 脚本 | 类型 | 用途 | 降级行为 |
|------|------|------|----------|
| financial_calculator.py | Python | 财务模型计算（一次性/订阅/对比） | 降级为LLM估算并标注"估算" |
| state.mjs | Node.js | 项目状态管理（写入当前项目目录 .project-state/） | 降级为LLM记忆+手动记录 |
| knowledge-filter.mjs | Node.js | 知识库精准加载过滤 | 降级为按需手动读取 references/ |

## 四、知识加载策略

- 每次交互最多加载5个reference文件（通过knowledge-filter.mjs过滤）
- 入口驱动加载：根据用户请求的入口点（全链路/国家定向/行业定向/单层/每日/新手）精准匹配
- 层级驱动加载：全链路模式下按当前层级加载对应reference
- 溢出保护：超过5个文件时按优先级截断，优先加载与当前入口/层级最相关的
- execution-protocol.md 与 evolution-protocol.md 为元规则，由 SKILL.md 直接约束，不占用5个加载配额

## 五、失败处理规则

1. 脚本输出非JSON → 解析失败 → 降级为LLM推理 + 记录错误
2. 脚本退出码≠0 → 读取stderr → 向用户展示错误 + 提供替代方案
3. 脚本超时（>30秒） → 终止 → 降级为LLM推理
4. 文件不存在 → 跳过 + 记录 + 继续执行其余流程
5. 脚本参数非法（如层级越界、负数成本）→ 按脚本返回的错误信息提示用户修正，不得自行编造计算结果
6. 实时联网检索不可用（离线/无检索能力）→ 易变事实（价格、政策、版本、具体数字）一律按 `evolution-protocol.md` 降级标注"估算/未实时核实"，不得把模型记忆当作已核实事实；环境恢复后应补做核实
