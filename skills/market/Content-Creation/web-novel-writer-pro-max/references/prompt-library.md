## 一、知识卡系统

知识卡 = 把一份知识压缩成"一段可直接粘贴给 AI 的指令卡"。适用于在多轮对话中快速注入能力。

### 1.1 知识卡格式

```markdown

## 知识卡：<主题>
【角色】<定义>
【知识】<3-6条核心规则/数据>
【指令】<执行动作：创作/检查/替换>
【反AI】<本主题的AI雷区与规避>
【来源】<references 文件名，便于深查>

```

### 1.2 常用知识卡清单

| 卡片 | 适用场景 | 核心内容来源 |
|------|----------|--------------|
| 自然度卡 | 写作前加载 | `anti-ai-engine.md` 九大支柱 |
| 四库替换卡 | 去AI味 | `ai-pools.md` 词/语/句/通感替换池 |

**知识卡使用**：创作/诊断前先按需加载对应知识卡（见 1.2 索引），再执行任务——避免全文注入、按需精确加载。

### 1.3 成卡全量（8 张常用卡均有实体，可直接粘贴）

**样例一：自然度卡**（写作前加载）

```markdown

## 知识卡：自然度优化
【角色】你是有十年连载经验的叙事写手，专抓AI腔。
【知识】
1. 禁用连接词：首先/其次/最后/综上所述/值得注意的是/总而言之
2. 破折号铁律：每章"——"≤1处；"——特别是/也就是/不是"等标点替代直接删，换逗号/句号/冒号
3. 对称结构扎堆（同结构≥2次或300字内3种）必打碎：不是X而是Y/越X越Y/一边X一边Y/三连排比
4. 情感标签词（感动/愤怒/绝望等）用身体反应替代：手抖、咽口水、指甲掐进掌心
5. 对话用「」直角引号；段落长度不均匀（最长/最短>3:1）
【指令】检查并清洗以下文本，逐条输出：命中处→替换前→替换后→依据（1-5编号）
【反AI】不许补"综上所述"式总结句收尾；不许句句带"了"；不许"他/她"连续句首
【来源】anti-ai-engine.md 九大支柱 + ai-pools.md 四库

```

**样例二：爽点卡**（排布章节爽点时加载）

```markdown

## 知识卡：爽点排布
【角色】你是爽点节奏设计师，深谙"蓄势-引爆-余波"。
【知识】
1. 10式爽点：打脸/升级/获宝/复仇/装逼/救美/守护/智斗/身份/绝境翻盘
2. 前10章每章≥1小爽（小爽/爽点伏笔都算）；中期每2章1大爽
3. 四步节拍：打压→蓄力→打击→余波（每式有固定节拍，见 signing-standards 总矩阵）
4. 大爽前要有小爽铺；爽点不能白给（主角付代价/冒风险）
5. 同类型爽点不连用2次；章末钩子10型轮换
【指令】给以下章节排布爽点：标注爽点类型、四步节拍落在哪几句、蓄势来源、余波承接
【反AI】不许无脑碾压（打击要配代价）；不许爽点脱离主线（纯炫技爽是注水）
【来源】signing-standards.md 爽点库总矩阵 + emotion-recipes.md 四步 + highlight-scenes.md 高光

```

**样例三：四库替换卡**（去AI味/润色时加载）

```markdown

## 知识卡：四库替换
【角色】你是AI腔清洗工，手执词/语/句/通感四库，只动该动的。
【知识】
1. 词级：顿时/瞬间/或许/几乎/深邃/一丝→删或换可见动作（"顿时"删掉句子照样成立）
2. 语级：心中一凛/微微挑眉/话锋一转/指节泛白/不动声色→换身体细节（"指节泛白"三次以上必换）
3. 句级：不是X而是Y/戏剧性倒数/自问自答/"从X到Y"→打碎成白描（对照对称结构库 ai-pools.md 4.7，S1-S35）
4. 通感级：铁锈味/雪松冷香/苦杏仁味/臭氧味→真人懒得形容，直接推进核心动作
5. 破折号铁律：每章"——"≤1处，仅打断插入/节奏转折/戏剧性补充三种合法用途
【指令】对以下文本做四库替换：逐条输出 原句→替换后→依据（词/语/句/通感）→保留理由（若不动）
【反AI】替换后不许引入新模板（如把"顿时"换成"猛然"）；不认识的词不硬换；每处替换必须让句子更短更直
【来源】ai-pools.md 词/语/句/通感四库 + smart-replacement.md 五步决策 + anti-ai-engine.md 支柱一二三

```

**样例四：题材卡**（确定题材后加载）

```markdown

## 知识卡：题材适配
【角色】你是题材老编辑，深谙10大题材的读者预期与AI雷区。
【知识】
1. 玄幻修仙：废柴/藏拙开局，金手指第一章亮相，打脸节奏1-2章一次（避免"灵力涌动"式AI意象）
2. 都市异能：日常切入+异能亮相第一章内完成（避免"主角捡到老爷爷"模板化开局）
3. 悬疑灵异：前50字必须丢一个反常细节，信息分阶给（避免平铺背景介绍）
4. 言情甜宠：微动作+心理拉丝，对话占35-55%，情绪曲线先甜后小虐再甜
5. 轻小说：口语化吐槽+内心戏，段落短（2-3行），对话占比40-60%
【指令】按题材输出：①300字开篇示例 ②本章AI雷区清单 ③改善方向（对照 genre-templates 要素表）
【反AI】不许写"空气仿佛凝固"式题材万金油开头；不许每个题材都用同一套打脸模板
【来源】genre-templates.md 10题材要素表 + platform-guide.md 题材偏好

```

**样例五：节奏卡**（写作/续写时加载）

```markdown

## 知识卡：节奏控制
【角色】你是节奏鼓手，管段落长短、句子起伏、章末钩子。
【知识】
1. 段落长度变异：最长/最短>3:1，CV≥0.5；高潮段切短句（1-3字/句）
2. 句长混排：连续同长句≤3句；句长CV要有起伏（长短交替制造呼吸感）
3. 憋-释放节奏：压抑段(铺垫/困境)后用释放段(反转/爽点)落点，压抑≤释放1.5倍
4. 章末钩子10型轮换：悬念/危机/反转/身份/情感/宝物/约定/预告/选择/对决，不连用2次同型
5. 对话节奏四档：快答（1-3字）/慢答（转折）/沉默（不答）/岔开（答非所问），交替用
【指令】扫描以下文本：标出段落CV、句长CV、憋释放失衡点、章末钩子类型，逐处给改法
【反AI】不许段落全部等长（3行一断是AI节律）；不许每章结尾都用悬念型钩子
【来源】rhythm-patterns.md 段落节奏 + hook-templates.md 10型 + emotion-recipes.md 四步节拍

```

**样例六：人设卡**（角色创作/防OOC时加载）

```markdown

## 知识卡：人设锚定
【角色】你是角色医生，专治OOC与纸片人。
【知识】
1. 三锚点：欲望（驱动）/恐惧（底色）/反差点（记忆点），三角缺一不立体
2. 四力：张力（他想要却得不到）/压强（环境逼他）/冲击力（观众惊叹）/爆发力（蓄压释放）
3. 对话DNA：语音指纹四维（语速/用词档/口癖/情绪泄口）——角色开口3句认得出是谁
4. 行为指纹：同一性格遇到同类处境行为可预测（对照 behavior-logic 决策树）
5. 主角≠完美：给1个真实弱点（路痴/怕黑/嘴硬心软），弱点要付出代价
【指令】检查以下角色设定：输出三锚点、四力缺项、对话DNA四维、行为一致性风险点
【反AI】不许给角色贴标签式设定（"腹黑""高冷"）；不许所有角色说话一个味
【来源】character-depth.md 三锚点四力 + dialogue-engineering.md 语音指纹 + behavior-logic.md 决策树

```

**样例七：伏笔卡**（大纲/写中/回收时加载）

```markdown

## 知识卡：伏笔管理
【角色】你是伏笔会计，管埋设、跟踪、回收三本账。
【知识】
1. 伏笔四型：线索/预言/身份/因果（与 `plot-resources.md` 1.1 一致），每型埋法不同（线索型用"物件/行为暗示"，预言型用"开头话/梦应验"，身份型用"反常身份细节"，因果型用"早年因/后来果"）
2. 三规则：埋时登记、回收必闭环、超期预警（短伏3-5章收，中伏1卷内，长伏全书）
3. 密度谱：每2-3章1个新伏笔；单章埋≤2个（多则乱）；回收强度三档（点破/代价/反转）
4. 连锁伏笔：A伏回收引爆B伏（回收不做减法做乘法）
5. 防断线：每卷末对照伏笔登记清点未回收项
【指令】给以下大纲/章节标伏笔：位置→类型→预计回收章→回收强度→与既有伏笔的连锁关系
【反AI】不许"伏笔回收=随便解释一下"；不许埋了不记（账本外无伏笔）
【来源】plot-resources.md 伏笔四型 + memory-engineering.md 伏笔登记 + hook-templates.md 联动

```

**样例八：平台卡**（投稿/签约前加载）

```markdown

## 知识卡：平台适配
【角色】你是平台投手，知道每家编辑手里的尺子。
【知识】
1. 起点：数据说话（收藏/追读/月票），前3章节奏快，爽点密度高
2. 番茄：免费+完读率权重高，每章末强钩子，单章较短（区间见 platform-data-registry）
3. 晋江：情感细腻+人设新颖，女频重氛围，雷区：女强男更强模板
4. 盐言故事：中短篇完结体（单篇区间见 platform-data-registry），开头 3 行定生死；抖音故事：碎片连载（单章区间见 registry），钩子前置
5. 英文平台（Wattpad/KDP/Webnovel）：高概念+强情绪，每章Cliffhanger，避开中文腔翻译感
【指令】按目标平台检查稿件：①字数/章节结构是否达标 ②开篇钩子强度 ③题材与平台偏好匹配 ④违规词扫描
【反AI】不许套用平台模板同质化（平台要的是"符合预期的意外"）；投稿材料必须真实可核
【来源】platform-guide.md 11平台参数 + signing-standards.md 签约标准 + english-creation.md 3英文平台

```

> 用法：把任意"常用知识卡"按上两例格式填成成卡——先写【角色】立场，再写【知识】≤6条可执行规则，最后【指令】明确动作、【反AI】标雷区、【来源】留可查路径。只有格式没有实体内容的卡不可交付。

## 二、通用创作提示词（直接可用）

### 2.1 一句话创作提示词（模块A 极速创作）

```

请按【网文小说签约专家】的标准创作：
题材：{题材}
体量：{短篇1万/中篇10万/长篇100万}，本次产出第{1}章，{2500}字左右
平台：{番茄/起点/晋江/知乎盐言/抖音故事}
频向：{男频/女频/全频}
要求：
1. 章节结构：冲突进入→推进→变化→钩子（结尾必断章）
2. 每段自然度优化：禁用AI高频词/语/句/通感（参考四库替换）
3. 白描推进：用动作/对话/心理推进，不写无关比喻
4. 结尾钩子：{悬念/反转/危机/承诺}型
产出：正文 + 自然度自检报告

```

### 2.2 逐题材创作提示词（差异化核心）

| 题材 | 提示词追加指令 |
|------|----------------|
| 玄幻修仙 | 境界用事件呈现不用说明书；修炼有代价；战斗用短句+环境破坏细节 |
| 都市异能 | 装逼留白靠第三方反应；金手指有限制（代价/时效） |
| 历史穿越 | 现代知识落地交代限制；古人智商在线；时代细节查证 |
| 科幻末世 | 硬规则自洽；资源与生存压力可见 |
| 悬疑灵异 | 信息分阶给；视角锁定；反转有伏笔支撑 |
| 言情甜宠 | 情感细节走微动作；对话有潜台词；误会不过夜 |
| 系统流 | 系统规则明确；结算画面感；任务与主线挂钩 |

### 2.3 对话创作模式

**模式定义**：用户与 AI 以"对话推进"方式共创——AI 每轮给"情节选项"，用户选择或自定义，AI 据此续写。

```

对话创作流程：
1. 首轮：AI 给世界观 + 主角 + 当前处境（2-3句），列出3个走向选项
2. 用户选择或自定义 → AI 续写 1 段正文（300-600字）+ 新3个选项
3. 每3轮触发一次状态快照（按 `memory-engineering.md` 更新）：角色状态/伏笔/关系变更
4. 关键节点触发名场面判定（`highlight-scenes.md`）

```

**对话创作规则**：选项必须"互相冲突"（用户选择才有意义）；每轮都有信息增量；用户自定义方向必须被尊重并合理化。

## 三、平台定制提示词

### 3.1 平台信息→提示词流程

```

1. 获取平台最新信息（榜单/规则/用户提供截图）
2. 映射到题材模板（genre-templates）+ 平台参数（platform-guide）
3. 生成定制提示词，注入以下差异项：
   - 字数档位（该平台每章范围）
   - 节奏档位（爽点密度/钩子强度）
   - 规范边界（平台禁区，见 legal-compliance）
   - 读者画像（该平台主要受众）
4. 输出带来源标注（"参考值，以平台公告为准"）

```

### 3.2 平台差异提示词对照

| 平台 | 提示词注入 |
|------|-----------|
| 番茄 | 单章区间见 platform-data-registry；爽点前置；完读率优先；章末必断章 |
| 起点 | 单章区间见 platform-data-registry；设定可铺；逻辑自洽优先 |
| 晋江 | 单章区间见 platform-data-registry；情感细腻；人物魅力优先 |
| 知乎盐言 | 单篇区间见 platform-data-registry；首段即冲突；故事感优先 |
| 抖音故事 | 单章区间见 platform-data-registry；前 3 句抓人；反转高频 |
| Wattpad/KDP | 英文；短段落；钩子前置；AI声明合规 |

## 四、封面生成提示词

### 4.1 封面设计五要素（与书名/卖点联动）

| 要素 | 设计内容 | 来源 |
|------|----------|------|
| 主角形象 | 1-2个关键特征（服装/神态/道具） | 人设卡 |
| 核心意象 | 一个可视化符号（剑/月/城市/血脉） | 卖点 |
| 情绪色调 | 主色调表达情绪（金=爽/暗=悬疑/暖=甜） | 题材 |
| 构图 | 留白/聚焦/背景氛围 | 平台风格 |
| 文案位 | 书名+副标题的排版空间 | 书名工程 |

### 4.2 封面生成提示词模板（AI绘画）

```

正向提示词：
{主角形象：如"黑袍青年持剑"}，{核心意象：如"燃烧的符咒"}，{情绪色调：如"暗金主色调，压迫感"}，
构图：{居中/对角线/特写}，{风格：如"国风厚涂/赛博朋克/唯美插画"}，
高细节，电影感光影，无文字/预留文字位
反向提示词：
多余肢体，水印，模糊，畸形，低质量，文字错乱，多人

```

**封面合规**：不使用真实人物肖像；不侵权（不用他人作品元素）；平台对封面的规范（无裸露/血腥，见 `legal-compliance.md`）；商用素材版权自查。

### 4.3 封面验收

- 缩略图尺寸下主角仍可辨识（放大识别度）
- 主色调与题材情绪一致
- 有文字位且不遮挡主体
- 与对标书封面有差异化（不撞风格）

## 五、自定义/用户提示词处理

**用户自定义规则**：用户用自己提示词时——
1. 先识别提示词中的明确约束（题材/风格/字数/禁忌）
2. 补全缺失维度（体量/平台/频向默认值，可追问）
3. 注入本 Skill 强制层：自然度优化 + 合规边界 + 反幻觉（不可被自定义覆盖）
4. 冲突处理：用户明示 > 默认规则；强制层（合规/反幻觉）> 用户明示
