# 责编/交叉审稿体系（签约编辑视角 + 多专家交叉评审）

> 责编审稿（编辑视角）+ 交叉审稿（多专家互审）+ 审稿报告模板 + 平台标准对标
> 版本：1.7.0
> 架构定位：本文件提供「签约责编视角」的审稿清单与报告模板，是 `red-blue-review.md` 红蓝对抗审稿中**红方的责编视角来源之一**（红方还含读者、平台审核、竞品等视角）；需要对抗式挑刺与逐条闭环时进入 red-blue-review，本文件负责责编这一视角的判稿标准。
> 联动：质量门控见 `quality-loop-engine.md`（六门控总装）与 `quality-metrics.md`（量化指标）；AI 诊断见 `ai-diagnosis.md`；市场验证见 `market-validation.md`；多专家视角见 `expert-panel.md`。

## 一、责编审稿（编辑视角：这稿子要不要签/推）

签约编辑 30 秒内扫三样：**书名+简介是否卖货、开篇是否留人、人设金手指是否清晰**。全文审时看五关：

### 第一关：开篇留人

| 检查项 | 标准 | 不达标信号 |
|--------|------|------------|
| 前三段 | 冲突/悬念/反转/危机至少一个 | 天气/风景/背景铺垫开场 |
| 第一章 | 金手指或核心设定亮相 | 30%篇幅在交代背景 |
| 章末钩子 | 有悬念或选择 | 平收章 |

### 第二关：节奏密度

| 检查项 | 标准 |
|--------|------|
| 爽点密度 | 前10章每章≥1爽点 |
| 对话占比 | 25-55%达标（硬性指标），推荐核心区间30-40%；无大段独白 |
| 每章字数 | 在 platform-data-registry 目标平台区间内（实时核实） |

### 第三关：人设清晰

| 检查项 | 标准 |
|--------|------|
| 三锚点 | 欲望/恐惧/边界明确（见 character-depth 2.1） |
| 金手指 | 类型+边界+代价清晰 |
| 记忆点 | 口头禅/标志动作/反差 |

### 第四关：自然度（编辑反感"AI稿"）

| 检查项 | 依据 |
|--------|------|
| 词/语/句/通感四库命中 | ai-pools.md |
| 八维诊断总分 | ai-diagnosis.md（≥75分） |
| 模板化开场/收尾 | anti-ai-engine 支柱一 4/5类 |

### 第五关：平台合规

| 检查项 | 依据 |
|--------|------|
| 敏感内容 | legal-compliance.md |
| 平台风格 | platform-guide.md |
| 签约字数/格式 | signing-standards.md |

## 二、交叉审稿（多专家互审）

> 借用 `expert-panel.md` 的模拟专家（均为模拟角色，不指向真实个人），同一稿件至少 2 位专家视角交叉审，观点冲突时以平台标准+读者观感裁决。

### 审稿视角矩阵

| 视角 | 关注 | 交叉问题示例 |
|------|------|--------------|
| 主编（商业） | 卖点/市场/续写空间 | 这稿的差异化卖点是什么？ |
| 责编（结构） | 节奏/爽点/钩子 | 第三章读者为什么留下？ |
| 女频/男频编辑 | 受众适配 | 目标读者画像清晰吗？ |
| 自然度专家 | 去AI/人味 | 哪三句最像AI？怎么改？ |
| 版权/合规顾问 | 合规/侵权 | 是否有抄袭/敏感风险？ |

### 交叉审稿流程（三步）

```

1. 独立审：每位专家视角独立给出清单与评分（互不干扰）
2. 交锋审：把冲突项摆出来逐条裁定（以证据+平台标准为准，不以"我认为"压人）
3. 汇总结：合并去重 → 按严重度排序 → 输出修改清单

```


### 交叉审稿报告样例（演示）

> 以下为演示填写，审一部都市异能开篇（约 4500 字）：主角林凡，普通汽修工，车祸后获得"读取物品残留记忆"的异能。参审：主编（商业）+ 责编（结构）+ 自然度专家。

```

══ 交叉审稿报告 ══
稿件：《读物的汽修工》第1章 字数：4520 参审视角：主编/责编/自然度专家

【一致结论】4条（多数视角共识，优先修改）
1. 前三段在修车铺日常，第4段才出车祸——违反门控 G"前50字直接进入冲突或悬念"（anti-ai-engine 附录F；主编+责编同判"开篇留人失败"）。
2. 金手指亮相太晚：第1章末才点出"能读物品记忆"，首章约 90% 篇幅在铺背景（责编判，见第一关·第一章标准）。
3. "他若有所思地点了点头""眼神中闪过一丝复杂"等模板句共 6 处，四库命中超标；AI 六维分 62（远超章节交付硬门 45，自然度专家判）。
4. 破折号 3 处（L180/L320/L405），超出"每章≤1处"铁律。

【分歧裁定】2条（争议点→双方理由→裁定→依据）
1. 争议点：异能要不要在第1章就显形？
   主编理由：不显形没卖点，读者撑不过试读。
   责编理由：显形太早没铺垫，金手指立不住。
   裁定：第4段车祸后立刻显形一次（读到扳手上一个使用者留下的记忆），但只露一半（读到"一把钥匙"就断），后半章再回收。
   依据：第一关要求"第一章金手指或核心设定亮相"，同时平台习惯"钩子分两次给"（rhythm-patterns 憋-释放节奏）。
2. 争议点：章末怎么写？
   责编：章末钩子必须闭环，写"他握住了那把钥匙"。
   主编：闭环就没有下一章的入口。
   裁定：写「钥匙是冰的。他数了数，三把。」——给信息不给结论，留未闭合动作。
   依据：章末钩子标准是"悬念或选择"而非"预告"，对应 anti-ai-engine 支柱八指纹8"完美收尾"。

【修改清单】按严重度（🔴必须/🟡建议/🟢可改可不改）
🔴 1. 重写前三段：删修车铺日常，直接开在"黑色轿车撞进铺子门口"现场（前 50 字出冲突），修车铺信息挪到第2章和老周的对白里补。
🔴 2. L180 破折号改句号拆句；L320、L405 直接删（每章配额 1 处，留给章末）。
🟡 3. L88"眼神中闪过一丝复杂"改为行为泄露：他低头，把扳手在裤腿上擦了两下。其余 5 处模板句按四库替换池逐句处理。
🟡 4. 第1章对话占比 21%（<25%），把第2章一段设定说明改写成对白——老周把烟灰磕在油桶上：「一天到晚净琢磨没用的。」——补到 28%。
🟢 5. 章末"钥匙"线索从第1章就开始给（L205 先让林凡摸到一次），防第3章再用时显得空降。

【复检建议】修改后重审"责编（结构）"视角：重点复核前三段钩子与章末未闭合动作。
══ 结束 ══

```

> 填写要点（反套话）：一致结论必须带"位置/行号 + 判据（门控表或第一关标准）+ 改法"；分歧裁定必须写"争议点→双方理由→裁定→依据（引平台标准或节奏规则）"；修改清单的"改法"要具体到"哪句改哪句"，不允许"优化节奏""增强冲突"这类空话。

### 判例对照（开篇留人关）

> 同一世界观下的两种开篇对照。判据：门控 G（前 50 字无冲突/悬念/反转）+ 第一关三检查项（前三段/第一章/章末钩子）。

**不达标开篇（约 200 字：平铺背景+无冲突+模板化描写）**：

> 临江市是一座临江而建的城市，经济发达，人口众多。在这座城市的东南角，有一家开了二十年的修车铺，老板姓周，手艺好，方圆几条街的人都爱来这儿修车。林凡就在这家铺子里当学徒，每天递扳手、换机油、擦零件。这天下午，阳光正好，他像往常一样蹲在车底换机油，心里想着，日子虽然平淡，但安稳，也不错。远处传来一阵汽车的轰鸣声，由远及近。

**达标开篇（约 200 字：前50字冲突+动作先行+章末钩子）**：

> 撞车的声音比想象中闷。林凡从车底钻出来，一辆黑色轿车斜插在铺子门口，前保险杠碎了一半。驾驶座的人没下车，只降下半个车窗：「修不修？」他弯腰看了眼车头，忽然愣住。这辆车他见过。三个月前，就是在这条街上，监控拍下的那辆肇事车。他伸手摸了摸车灯，手背上起了一层鸡皮疙瘩。他没接话，先弯腰把扳手放回工具箱，直起身才问：「车主呢？」车里的人沉默了两秒：「我就是。」林凡在车门的缝隙里摸到什么东西，冰的。他把它攥进手心，没让任何人看见。

**点评（3句）**：
1. 不达标开篇前 50 字是城市介绍与修车铺背景，没有任何事件，"轰鸣声由远及近"到结尾才出现——直接违反门控 G"前 50 字直接进入冲突或悬念"，读者 10 秒内放下。
2. 达标开篇首句即事件（"撞车的声音比想象中闷"），动作先行，一句"这辆车他见过"把旧案悬念埋进读者心里，金手指在"摸车灯起鸡皮疙瘩"的动作中露头，不靠旁白交代。
3. 章末"摸到冰的东西、攥进手心"是未闭合钩子，读者会追问"是什么、和肇事案什么关系"——不达标开篇让人放下，达标开篇让人点下一章。

## 四、审稿原则与边界

- 审稿是**建议不是判决**：最终以作者意图与读者反馈为准
- 避免套话式审稿（"节奏可以更好""人设可以更鲜明"——必须给出具体位置与改法）
- 反幻觉：审稿引用平台标准时标注"通行做法，非官方明文"（见 anti-hallucination 触发器）
- 交叉审稿的专家均为模拟角色，无真实资历声明（见 expert-panel 免责）
