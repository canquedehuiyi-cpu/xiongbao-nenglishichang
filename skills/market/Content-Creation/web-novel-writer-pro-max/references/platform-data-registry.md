## 〇、实时核实与缓存规则

本表为查证日快照，仅作基线。凡交付涉及本表数据，先按 `verify-protocol.md` 核实目标平台最新官方口径，时效以本次对话日期为准：

| 平台 | 核实渠道方向 |
|------|--------------|
| 起点 | 起点中文网官网 / 作家专区 / 作家助手公告 |
| 番茄 | 番茄作家助手 / 官网帮助中心 / 作者后台规则页 |
| 晋江 | 晋江文学城作者中心 / 官方公告 |
| 七猫 | 七猫作家助手 / 官网创作者中心 |
| 长佩/刺猬猫/纵横/豆瓣 | 各平台官网 / 创作者中心 / 官方公告 |
| 盐言/抖音故事/快手短剧 | 各平台官网 / 创作者中心 / 官方公告 |
| 海外 | Wattpad Help / Amazon KDP Help / Webnovel 官网 |

保鲜期（差异化 TTL）与 FIFO 规则的唯一事实源是 `verify-protocol.md` 第七节，本文件不重复数值。核实结果与本表不一致时以官方最新为准，交付同时标注查证日与本次核实日期，并按 FIFO 规则只保留最新值。

## 九、参数结构与引用约定

每条平台参数按 `verify-protocol.md` 的 schema 登记，带 `source_level`、`verified_date`、`ttl_days`、`status` 字段。

- 各 references 出现平台硬数据处，一律引用本表数值；无法同步时标注「以 platform-data-registry.md 为准」。
- 本表与 `ai-compliance-redlines.md` 是两类参数的各自唯一 owner：本表管「平台硬数据」，红线库管「AI 使用规则」，互不复制。
- 创作引擎类文件（human-fingerprint / quality-loop-engine 等）只引用、不内嵌任何平台数值。
- grep 校验：除本文件与红线库外，其余文件不应出现平台硬数据数值副本。
