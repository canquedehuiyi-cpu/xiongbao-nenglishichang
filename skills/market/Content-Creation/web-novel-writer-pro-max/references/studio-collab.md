# 工作室协作库（多人创作流程与一致性管理）

> 一人单写到多人工作室的完整协作体系：分工模式、统一设定库、交接规范、多写手风格一致性、质量门禁。适配单作者（自管流程）到工作室（多人协作）。
> 版本：1.7.0
> 声明：签约平台普遍要求"本人创作"，多人代写/枪手代笔涉及平台违规与法律风险（见 `ai-creation-ethics.md` 代写界限与 `legal-compliance.md`）。本库用于**合法协作**（分章节创作、共同署名、编辑审校等平台允许的方式），不指导违规代写。
> 联动：多人交付前统一过 `quality-loop-engine.md` 六门控；风格一致性见 `narrative-style.md`；行为一致性见 `behavior-logic.md` 与 `entity-state-machine.md`（实体状态机）；伏笔/承诺追踪见 `promise-ledger.md`；共享素材与设定卡见 `asset-library.md`；过程状态记录见 `memory-engineering.md`。

## 一、工作室常见分工模式

| 模式 | 分工 | 适用 | 协作要点 |
|------|------|------|----------|
| 主笔+协作 | 主笔定主线大纲，协作写指定章节 | 长篇多开 | 主笔控总纲，协作按章纲填肉 |
| 统筹+写手 | 统筹管人设/世界观/伏笔，写手只写正文 | 中大型工作室 | 设定库必须权威统一 |
| 作者+编辑 | 作者写，编辑审稿提改 | 个人工作室 | 用责编审稿模块M做门禁 |
| 共创署名 | 多人共同创作、共同署名 | 版权清晰的团队 | 权属提前书面约定 |

**分工自检**：谁定主线？谁写正文？谁审质量？三个答案清晰且不重叠=分工成立。

## 二、统一设定库（协作的单一事实源）

> 多人写作最怕"设定漂移"——A写主角左撇子，B写主角右手出招。解法：统一设定库。

### 2.1 设定库结构

```

设定库（每本书一套，存项目目录）
├── 项目配置.md           体量/平台/题材/语言
├── 世界设定.md            力量/货币/地理/势力（worldview-engineering 产出）
├── 人物卡.md              每人一张（含行为指纹+语音指纹）
├── 大纲.md                卷纲+章纲（每章目标/钩子/爽点）
├── 伏笔追踪.md            伏笔埋设/回收排期
└── 风格样板段.md          六轴定位+样板段（narrative-style 产出）

```

### 2.2 设定库管理规则

1. **单一事实源**：任何设定变更先改库，再写正文（禁止"顺手改设定"）
2. **变更留痕**：重大设定变更记录"变更人+日期+原因"
3. **发布制**：设定库由负责人（主笔/统筹）更新，写手只读
4. **开写前读库**：每次动笔前读"该章涉及的人物卡+章纲+样板段"

## 三、章节交接规范

### 3.1 交接清单（写手交稿时必须附）

```

【交接单】章节号____ 写手____ 日期____
□ 本章目标是否完成（对照章纲）
□ 结尾钩子类型
□ 涉及角色与当前状态（对照人物卡）
□ 新增伏笔/线索（登记伏笔追踪）
□ 遗留问题/待统筹决策项
□ 字数：____（对照体量档位）

```

### 3.2 交接流程

```

写手：读章纲+人物卡+样板段 → 写作 → 自检（行为/指纹/风格）→ 填交接单
统筹：对照设定库审（一致性/伏笔/风格）→ 通过/打回 → 归档到章节摘要

```

## 四、多写手风格一致性（四锚校准）

| 校准锚 | 内容 | 频率 |
|--------|------|------|
| 风格样板段 | 写作前朗读/对齐（narrative-style 3.3） | 每次动笔 |
| 六轴定位卡 | 温度/密度/距离/庄谐/显隐/叙述对照 | 每卷校准 |
| 行为指纹表 | 角色行为/口头禅/微动作核对（behavior-logic 4.2） | 每次涉及该角色 |
| 语音指纹表 | 对白风格核对（dialogue-engineering 3.2） | 每次写对话 |

**漂移检测**：每 10 章由统筹随机抽 2 章匿名混排，让写手互相辨认"哪章是谁写的"——辨认不出=风格统一达标。

## 五、质量门禁（多人协作的验收标准）

| 门禁 | 检查项 | 工具 |
|------|--------|------|
| 语法/基础 | 错别字/病句/标点 | 按质量指标核验（quality-metrics.md） |
| 一致性 | 设定/伏笔/行为/风格 | 设定库对照 |
| 质量 | 六维评分（情节/人物/文笔/世界观/情感/商业） | 模块H诊断 |
| 签约级 | 责编五关+平台标准 | 模块M审稿 |
| 版权合规 | 原创性/平台规则/署名 | `ai-creation-ethics.md` + `legal-compliance.md` |

**门禁规则**：未过门禁的章节不进正文库；连续 3 章不过的写手需回炉培训或调整分工。

## 六、项目与版权管理

### 6.1 项目管理

- 更新节奏：定"日更几章"并拆到写手（体量参考 `length-engineering.md`）
- 进度看板：章节状态（规划/写作/审校/发布/存档）
- 断更预案：主笔/写手请假时的替代排期

### 6.2 版权与署名（合规底线）

- **权属书面化**：共同创作、委托创作的版权归属、署名顺序、收益分成，开工前签书面协议
- **平台合规**：签约平台普遍要求本人创作，代笔/枪手/工作室顶名签约=违规风险
- **AI使用边界**：工作室使用AI辅助须遵守平台AI规则与声明义务（见 `ai-creation-ethics.md`）
