> **定位**：质量闭环 planning 阶段的执行器。把「题材 + 目标平台 + 目标体量 + 更新频率」转化为可执行的全书—卷—章规划、节拍排布、字数配额与更新排期，从源头保证结构完整、节奏可控、更新可持续。

## 一、输入与前置

启动规划前必须确认：

| 输入 | 说明 | 缺失处理 |
|------|------|----------|
| 题材/子类型 | 决定节奏基准与爽点密度 | 未明确先协助定位，不默认 |
| 目标平台 | 决定单章字数、更新形态、红线 | 未指定先询问；平台规则经 `verify-protocol.md` 核实 |
| 目标体量 | 超短/短/中/长篇（档位见 `length-engineering.md`） | 未明确按平台主流体量建议 |
| 更新频率 | 日更字数/每周天数 | 结合作者可持续产能，不排无法坚持的计划 |
| 核心设定 | 主角、金手指、主线、卖点 | 来自人物卡/世界观，缺则先补设定 |

## 二、三层规划结构

```

全书层（Book）
  ├─ 一句话卖点、主线、结局方向
  ├─ 总字数目标、总章数、分卷数
  └─ 全书承诺清单（交 promise-ledger：主线伏笔/结局承诺）
卷层（Volume）
  ├─ 每卷核心目标、卷级冲突、卷末高潮
  ├─ 卷字数、卷章数、本卷新埋/兑现承诺
  └─ 卷情绪曲线（谷→峰，交 emotion-curve-engine）
章节层（Chapter）
  ├─ 每章功能（铺垫/冲突/爽点/过渡/钩子）
  ├─ 章节字数、场景列表、章末钩子
  └─ 本章涉及实体（交 entity-state-machine）与承诺动作

```

原则：上层约束下层，章节规划不得偏离卷目标，卷规划不得偏离主线；任何一层调整要向上同步。

## 三、字数配额计算

计算链路（数值口径全部来自 `platform-data-registry.md`，不在本文件写死）：

```

总字数目标 ÷ 平台单章字数 = 总章数
每卷章数 = 总章数 ÷ 卷数（按卷功能微调，允许 ±10%）
每章字数 = 平台区间内取值，按章节功能浮动（爽点章可偏长，过渡章不拖长）
全书字数 = Σ 各章配额，与目标误差控制在 ±5%

```

纪律：

- 单章字数严格落在目标平台区间内，跨平台分发时分别按各平台口径出配额。
- 不为凑字数注水：字数配额服从内容，信息密度不足时优先压缩（联动 `reader-signal-alert.md` 水文检测）。
- 短篇/盐言等完结体按「总字数倒推段落」，不套用连载章配额。

## 四、节拍排布

1. 从 `rhythm-patterns.md` 取对应题材的节拍骨架与节奏型。
2. 把节拍落到卷与章：每个节拍标注所在章、对应情绪强度、承担的承诺（埋/兑现）。
3. 黄金区间（前三章/开篇）优先排布钩子与核心冲突，节拍密度高于后文。
4. 爽点间距按同题材基线（来自 `novel-deconstruction.md` 爽点密度层），避免长期无回报。
5. 节拍排布结果同步给 `promise-ledger.md`（每个悬念/爽点承诺登记应兑现位置）与 `emotion-curve-engine.md`（情绪曲线基线）。

## 五、更新排期

```

日更目标字数 ÷ 单章字数 = 每日章节数
每周更新天数 × 每日章节数 = 周更章数
总章数 ÷ 周更章数 = 预计完结周数

```

- 排期必须匹配作者真实产能，预留存稿缓冲（建议常备若干章存稿应对断更）。
- 平台全勤/更新奖励规则经 `verify-protocol.md` 核实后纳入排期（不在本文件写死奖励数值）。
- 输出更新日历：日期 → 章节 → 字数 → 状态（待写/草稿/已审/已发）。
- 长篇允许「卷」为单位做排期滚动更新，不要求一次排死全书每一天。

```

【基本信息】题材/平台/体量/更新频率/总字数/总章数/卷数
【全书层】卖点、主线、结局方向、全书承诺

【字数核算】总配额与目标误差、单章是否落在平台区间
【更新日历】周更计划、存稿缓冲、全勤节点
【风险点】开篇留存、爽点间距、产能匹配的预警

```

## 七、执行与动态调整

- 规划进入 `quality-loop-engine.md` planning 门控：要素齐全、字数落在平台区间、承诺有兑现位置，才进入 generating。
- 写作中允许调整，但须留痕：改了哪层规划、为什么改、影响哪些下游（承诺/实体/排期）。
- 每卷结束复盘实际字数/节奏/留存信号，滚动校准下一卷规划。
- 平台规则或榜单风向变化（`market-radar.md`）时，评估是否调整后续卷规划，已发布部分不回改。

## 八、交付前核验清单

- [ ] 五项输入是否齐全，平台字数/规则是否取自登记表并实时核实？
- [ ] 三层规划是否完整、上下层一致？
- [ ] 总章数/卷章数/单章字数是否由平台口径现算、误差可控？
- [ ] 节拍是否落到章，并同步回报账本与情绪曲线？
- [ ] 更新排期是否匹配真实产能、含存稿缓冲？
- [ ] 规划调整是否留痕并同步下游？

### 自检标准（可验证）

1. 给定平台/体量/频率，能现算出总章数、卷章数、完结周期，且单章落在平台区间。
2. 规划书中每个悬念/爽点都能在回报账本找到对应承诺与兑现位置。
3. 故意排一个「日更两万字且无存稿」的计划时，能识别为不可持续并给出修正。
