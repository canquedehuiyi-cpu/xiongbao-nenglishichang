## 一、触发与前置

### 1.1 何时进入本文件

满足任一条件即进入：
- 作品在创作任一环节使用了 AI（构思、大纲、正文生成、润色、翻译、配图、封面、简介），准备发布/投稿/上架；
- 平台发布页出现"是否包含 AI 生成内容""AI 辅助创作声明"等勾选项或说明位；
- 用户主动问"我这段要不要说明用了 AI""声明怎么写"；
- 作品要做跨平台/跨境分发（中文平台与海外平台口径不同，必须分别判）。

### 1.2 前置事实（开工前必须确认）

| 前置项 | 确认方式 | 缺失时 |
|--------|----------|--------|
| 目标平台清单 | 用户明确发布到哪些平台 | 先问清，不默认单一平台 |
| AI 参与环节清单 | 逐环节核对（构思/大纲/正文/润色/翻译/配图/封面/简介） | 与用户逐项过一遍，不替用户假设"只用了一点" |
| 各平台当期约定 | 查 `ai-compliance-redlines.md`，过期按 `verify-protocol.md` 核实 | 带快照日期，提示"以平台当期说明为准" |
| 人机贡献比例 | 哪些是 AI 生成、哪些是人工原创/改写 | 区分 generated 与 assisted（见第二节） |

### 1.3 三条不可动摇的原则

1. **如实原则**：只如实陈述 AI 参与的环节与程度，不夸大、不隐瞒、不替用户编造"纯人工"事实。
2. **一稿一声明原则**：声明随作品走，不同作品、不同版本分别判断；作品大幅更新或新增 AI 环节后重新评估，不沿用旧声明。
3. **分平台原则**：同一部作品在不同平台按各自要求分别声明，不把 A 平台话术照搬到 B 平台。

## 二、总决策流程

### 2.1 第一步：逐环节区分 AI-generated 与 AI-assisted

这是所有平台披露的共同底层分类，先定性再谈文案。

| 环节 | AI-generated（AI 产出了内容本体） | AI-assisted（AI 只做辅助，内容本体是人写的） |
|------|-----------------------------------|----------------------------------------------|
| 构思/选题 | AI 直接产出核心创意并被采用 | AI 仅头脑风暴、提供候选，人最终定创意 |
| 大纲 | AI 生成大纲主干 | AI 仅整理/排版人写的大纲 |
| 正文 | AI 生成整段/整章正文（无论是否再人工编辑） | 人写正文，AI 仅查错、语法、同义改写建议 |
| 润色 | AI 大段重写、改变了表达主体 | AI 仅纠错、标点、轻度措辞建议且由人取舍 |
| 翻译 | AI 产出译文主体 | AI 仅校对人译稿 |
| 配图/封面 | AI 生成或大幅扩图的图像 | AI 仅做尺寸裁剪、格式转换 |
| 简介/文案 | AI 生成简介主体 | AI 仅润色人写的简介 |

**关键判定**：AI 生成的内容**即使经过人工编辑、改写、润色，仍属于 AI-generated**（"编辑过"不改变其生成来源）；只有内容本体从一开始由人创作、AI 仅提供辅助，才算 AI-assisted。拿不准时按更严格的一类（generated）处理。

### 2.2 第二步：按平台分流

```
逐环节定性（generated / assisted / 纯人工）
        │
        ├─ 中文平台（微信/起点/番茄/晋江等）→ 走第三节 + 第五节
        │       └─ 读者可见说明 + 发布页勾选分别落实
        ├─ Amazon KDP → 走第四节决策树（文本/图像/翻译分别判）
        └─ 其他海外平台 → 走第六节（按当期平台要求，规则查 redlines）
```

### 2.3 第三步：产出并落位

- 选定对应模板（第七节），填入真实环节与程度；
- 放到平台要求的位置（发布勾选位 / 作者的话 / 作品页 / 版权页）；
- 过第八节核验清单。

## 三、中文平台说明怎么落

> 各平台具体要求与适用清单以 `ai-compliance-redlines.md` 实时核实为准，本节只讲说明放哪、文案怎么写。

### 3.1 两种说明方式

| 方式 | 含义 | 作者要做什么 |
|----------|------|--------------|
| **发布页勾选/标签** | 平台发布流程里的 AI 相关选项，勾选后由平台展示 | 按实际情况如实勾选 |
| **作者自述说明** | 作者在作品页、作者的话、简介区写的文字说明 | 在读者容易看到的位置，用一句话如实说明人机分工 |

### 3.2 中文平台通用落地要点

1. **平台有勾选/声明位的，优先用平台提供的入口**如实勾选；平台标签与自写说明不冲突时可并存。
2. **自述说明位置**：作品页标签、章节作者的话、文末说明、简介区（按平台允许的位置选读者容易看到之处）。
3. **如实填写**：AI 生成内容就如实说明为 AI 辅助生成，不标注为"纯人工原创"；这既是平台要求，也让声明与作品实际情况一致（与 `anti-washing.md` 的原创底线一致）。
4. **AI 辅助但非生成**：平台只要求说明"AI 生成内容"时，纯辅助（语法纠错/查资料）通常不属于需要说明的范围；是否自愿多说一句由作者按平台要求决定，拿不准就简要说明、不夸大。

### 3.3 说明的清晰度要求

- 文字说明应清晰可读，不用与背景同色、不用极小字号、不折叠到读者难以发现的位置；
- 措辞与实际参与程度一致：多环节协作就如实说明，局部使用就说明局部，不用模糊话术掩盖实际程度。

## 四、Amazon KDP 披露决策树

> KDP 要求可能更新，以下决策结构稳定，具体字段名与展示措辞以 KDP 当期帮助页为准（按 `verify-protocol.md` 核实，规则源 `ai-compliance-redlines.md`）。

### 4.1 决策树（文本、图像、翻译三条线分别走一遍）

```
对 文本 / 图像 / 翻译 每一类分别问：
Q1. 这一类内容是否存在 AI 直接产出的内容本体？
    ├─ 否（纯人写 / AI 仅 brainstorming、纠错、语法、轻度润色建议且人取舍）
    │       → AI-assisted，KDP 无需在发布流程披露（仍可自愿在作者的话说明）
    └─ 是（AI 生成过整段正文 / 图像 / 译文，哪怕之后人工编辑过）
            → AI-generated，进入 Q2
Q2. 该 AI-generated 内容是"仅人工少量调整"还是"经过大量人工创作性改写"？
    ├─ 无论哪种 → 都在 KDP 发布流程如实披露 AI-generated
    │            （KDP 口径：人工编辑不改变 AI-generated 性质）
    └─ 披露后作品页会出现平台侧 AI 内容说明，这是正常结果，不是惩罚
Q3. 三类是否至少一类为 AI-generated？
    ├─ 是 → 发布流程对应项逐一勾选披露
    └─ 全部为 assisted/纯人工 → 无需披露，但不得把 generated 谎称为 assisted
```

### 4.2 三条线的常见易错点

| 内容线 | 容易误判为 assisted、实际是 generated 的情况 |
|--------|----------------------------------------------|
| 文本 | AI 起草整章后人工改了措辞/调整情节顺序；用 AI 扩写后并入正文 |
| 图像 | AI 生成封面/插图后用修图软件调色、局部重绘、加文字（仍 generated） |
| 翻译 | 用 AI 全文翻译后人工校对（译文主体来自 AI，属 generated 翻译） |

### 4.3 KDP 披露的表达分寸

- 在 KDP 后台按实际勾选即可，不需要长篇自我检讨；
- 面向读者的作者说明（如 A note from the author）可简述人机分工，重点写"人做了什么"（世界观设定、情节决策、最终改写与把关），不必渲染 AI；
- 如实披露即可，不需要也不应该把 generated 内容说成纯人工（创作伦理见 `ai-creation-ethics.md`）。

## 五、其他中文平台声明

> 各中文网文/内容平台对 AI 创作的准入与声明要求不同且持续更新，要求一律以 `ai-compliance-redlines.md` 核实结果为准；本节给声明落位与写法。

### 5.1 落位优先级

1. **平台提供的声明入口**（投稿/发布页的 AI 相关勾选、标签）——第一位，如实填；
2. **作品简介/作品页说明**——无平台入口或需要补充说明时使用；
3. **作者的话/单章说明**——局部章节使用 AI 时就近说明；
4. **版权页/完本感言**——整体人机分工的总说明。

### 5.2 不同参与程度的声明口径

| 参与程度 | 声明口径（只陈述事实） |
|----------|------------------------|
| AI 辅助（资料/纠错/灵感） | 可自愿简述"创作中借助 AI 进行资料整理与文字校对，正文为本人创作"，不强制时可不标 |
| 局部 AI 生成（如个别段落、配图） | 明确说明使用范围："第 X 章插图由 AI 生成""部分场景在本人大纲基础上由 AI 辅助成稿并经本人改写" |
| 深度人机协作（大纲到正文多环节） | 整体说明协作方式与人工把关环节，并按平台要求勾选 AI 内容项 |

### 5.3 中文平台通用注意

- 不写"100% 纯人工、绝无 AI"这类与事实不符的绝对化表述；创作过程平时留痕、需要说明时有据可查（见 `misjudge-defense.md`）；
- 声明只如实陈述，不写与平台要求对着干的内容；
- 不使用"AI 全自动生成、与本人无关"来推卸作品责任——作者对发布内容始终负责。

## 六、其他海外平台披露

> 海外平台（含其他自助出版、连载、原创内容平台）要求各异且更新频繁，本节给通用判断框架，具体规则查 `ai-compliance-redlines.md` 并按 `verify-protocol.md` 核实当期官方页，不凭记忆下结论。

### 6.1 通用判断框架

1. 平台是否区分 AI-generated 与 AI-assisted？区分则按第二节定性分别处理；
2. 平台是否要求在发布流程披露、是否在作品页展示 AI 说明？按其流程如实填写；
3. 平台对 AI 封面/插图是否有独立要求？图像与文本分开判（多数平台图像要求更明确）；
4. 平台是否不接受某类 AI 内容（如特定题材、真人肖像、未授权风格）？准入问题先于披露问题，红线见 `ai-compliance-redlines.md`。

### 6.2 跨平台一致性

- 事实层一致：同一部作品在各平台声明的"哪些环节用了 AI"必须一致，不能 A 平台说纯辅助、B 平台说深度生成；
- 形式层本地化：措辞、字段、披露位置按各平台要求本地化，不逐字硬翻中文声明。

## 七、文案模板库

> 以下模板为可直接改写的规范表达，方括号处按真实情况填写；只陈述事实，不夸大、不隐瞒、不自我贬低。禁止直接照抄与事实不符的模板。

### 7.1 作者的话 / 创作说明（中文）

**局部使用（如实说明范围）**：

```
创作说明：本书世界观、情节与人物由本人设计；[第 X 章插图 / 个别场景初稿]
在本人主导下借助人工智能工具生成，并经本人逐处改写、校对与定稿。
特此说明，感谢阅读。
```

**深度人机协作**：

```
创作说明：本书采用人机协作方式完成——本人负责选题、大纲、情节决策与最终把关，
人工智能工具用于辅助成稿与文字打磨，全部内容经本人审定，文责由本人自负。
```

**仅辅助（自愿说明，非强制时）**：

```
创作说明：正文由本人独立创作，过程中借助工具进行资料整理与文字校对。
```

### 7.2 作品页 / 简介区声明（中文，短版）

```
标签：AI 辅助创作（本人主导并完成最终改写与定稿）
```

### 7.3 版权页声明（中文，正式版）

```
本书在创作过程中使用了人工智能辅助工具，具体环节为：[大纲辅助 / 部分正文初稿 /
封面图像 / 翻译]。上述内容均由作者[笔名]进行创作性改写、审核与定稿，作者对全书内容承担责任。
```

### 7.4 KDP / 英文平台读者说明（A note from the author）

**AI-assisted（无需后台披露时的自愿说明）**：

```
A note from the author: This story was written by the author. AI tools were used
only for brainstorming and proofreading assistance.
```

**AI-generated（后台已披露，面向读者的中性说明）**：

```
A note from the author: The author designed the story, characters and plot, and used
AI as a drafting assistant for [text / cover art / translation]. Every section was
revised, edited and finalized by the author, who takes full responsibility for the work.
```

### 7.5 模板使用注意

- 不得把"局部使用"模板套用到"深度协作"事实，反之亦然；
- 不得保留模板里的方括号占位直接发布；
- 不出现"绝对纯人工""零 AI""保证通过检测"等绝对化或与事实不符的表述；
- 一份声明只对应一部作品/一个版本，不跨稿复用。

## 八、交付前核验清单与自检标准

### 8.1 交付前核验清单

- [ ] 已逐环节（构思/大纲/正文/润色/翻译/配图/封面/简介）定性 generated / assisted / 纯人工，无遗漏
- [ ] "编辑过的 AI 内容仍算 generated"这一判定已对文本、图像、翻译三条线各走一遍
- [ ] 每个目标平台的当期要求已查 `ai-compliance-redlines.md`，必要时按 `verify-protocol.md` 实时核实并带快照日期
- [ ] 有平台声明/勾选入口的均已如实勾选
- [ ] 中文平台读者可见说明已置于清晰位置
- [ ] KDP 三条线分别判断，generated 项已在后台披露
- [ ] 各平台声明的"事实层"一致，仅"形式层"本地化
- [ ] 声明措辞与实际参与程度一致，无"100% 纯人工/零 AI"等绝对化表述
- [ ] 模板方括号已全部替换为真实信息，无占位残留
- [ ] 作品更新或新增 AI 环节后已重新评估、更新声明（一稿一声明）

### 8.2 自检标准（合格线）

| 维度 | 合格标准 |
|------|----------|
| 完整性 | 八个环节无遗漏，三条内容线（文本/图像/翻译）分别判完 |
| 真实性 | 声明与实际人机分工一致，不夸大不隐瞒 |
| 合规性 | 符合每个目标平台当期要求，读者说明与后台勾选均落实 |
| 一致性 | 跨平台事实一致、同一作品前后版本声明连续 |
| 分寸感 | 中性、干净，不自我贬低，不渲染 |
| 可追溯 | 平台要求带核实日期，AI 参与环节有记录（配合 `misjudge-defense.md` 留痕） |

### 8.3 与其他模块的协作边界

- 规则"是什么、改没改"→ `ai-compliance-redlines.md` + `verify-protocol.md`，本文件不重复写规则；
- "能不能这么用 AI、伦理边界"→ `ai-creation-ethics.md`；
- "创作过程怎么留痕"→ `misjudge-defense.md`；
- "把他人成果洗成自己的、把 AI 内容伪装成纯人工"→ **不属于本文件职责，一律不提供**（原创底线，见 `anti-washing.md`）。
