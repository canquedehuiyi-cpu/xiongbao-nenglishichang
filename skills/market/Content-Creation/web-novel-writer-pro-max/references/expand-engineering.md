## 与续写/润色的边界

| 能力 | 输入 | 产出 | 与扩写区别 |
|------|------|------|-----------|
| **扩写** | 已有片段 + 扩写目标（类型/字数/方向） | 拉长后的片段 | **不改变剧情走向**，只丰富表达、放大张力 |
| 续写 | 已有前文 + 续写要求 | 新章节正文 | 推进剧情产生新事件 |
| 润色 | 已有文本 | 改写后文本 | 不增内容，只调表达，成稿不短于原文 80% |

判定：用户给了片段并要求"写长/写细/写全/放大"，走扩写；要求"接下去发生什么"的，走续写。

## 扩写六类型

常见的扩写工具只有单一"拉长"，本库按扩写目标细分六型，每型指定技法与禁忌：

| 类型 | 适用场景 | 核心技法（引用对应库） | 字数倍数 | 禁忌 |
|------|----------|------------------------|----------|------|
| **① 场景展开** | 一句话/干瘪场景 → 完整场景 | 五感入场+镜头推拉（`writing-techniques.md`） | 3-5x | 不堆形容词，用白描 |
| **② 细节填充** | 关键事件 → 有质感的细节层 | 细节六类+密度控制+贯穿物（`detail-engine.md`） | 1.5-3x | 细节不抢主线 |
| **③ 对话延展** | 简短对白 → 潜台词交锋 | 台词四功能+潜台词+语音指纹（`dialogue-engineering.md`） | 2-4x | 不写完美对话 |
| **④ 情绪放大** | 情绪点 → 心理三层递进+微动作 | 心理通道+微动作库（`writing-techniques.md`） | 1.5-3x | 不整段内心独白 |
| **⑤ 节奏拉满** | 平缓段 → 张力拉升 | 矛盾升级+四步节拍+章末钩子（`rhythm-patterns.md`、`hook-templates.md`） | 2-4x | 不无限抬爽点失真实 |
| **⑥ 名场面化** | 重要节点 → 高光时刻 | 蓄势-爆发六步+类型库（`highlight-scenes.md`） | 3-5x | 不滥用长蓄势拖节奏 |

多类型可组合（如 ①场景展开+④情绪放大），组合时主次分明，标注"主类型：X"。

## 执行流程（五步）

### 第 1 步：确认输入（先问，不做假设）
- **片段来源**：直接贴文本，或 `项目路径 + 章号 + 起止段落`（选中片段）
- **扩写类型**：六型之一（可组合）
- **目标字数**：未指定则默认原片段 2 倍；单章上限遵守目标平台章节字数口径（`platform-data-registry.md`）
- **方向说明**：用户额外要求的（如"多写环境""突出某个角色反应"）

### 第 2 步：注入记忆（片段在项目内时必做，防 OOC/防穿帮）
- 按 `memory-engineering.md` 注入 L3→L1 记忆（核心设定/角色状态/时间线/伏笔）
- 涉及出场角色时按 `entity-state-machine.md` 复核当前状态（伤势/等级/关系），已终结角色不得出现、角色行为不得越过一致性红线
- 片段若涉及已登记伏笔/承诺，查询 `promise-ledger.md` 对应条目与状态

### 第 3 步：锁定风格指纹
- 从片段按 `style-distillation.md` 提取风格参数：句长分布/用词习惯/语气/节奏/视角人称
- 扩写文本必须与片段**无缝衔接**（开头承接原句、结尾自然过渡到原片段后续），不得改变视角与叙述人称

### 第 4 步：写中校验
- 每扩写一段自检一次自然度（规则核验六维，判据见 `ai-detection-dimensions.md`），命中模板词立即按 `smart-replacement.md` 替换
- 扩写新增内容不得出现：新金手指、新势力、新身份、角色反常言行（OOC）

### 第 5 步：产出扩写正文 + 报告
- 输出扩写后完整片段（标注插入位置与替换范围）
- 按"产出报告模板"输出对比报告

## 伏笔安全红线（扩写不破坏剧情引擎）

1. **不提前回收**：扩写不得揭晓/兑现未到期伏笔或承诺（与 `promise-ledger.md` 登记的兑现时机冲突即硬伤）
2. **不改变走向**：扩写只丰富"已发生"的表达，不新增剧情事件、不改既定情节结果
3. **不新增设定**：扩写不得引入原文没有的金手指/力量等级/人物关系/地点
4. **不遗漏铺垫**：扩写若触及某伏笔的铺垫环节，必须保持原文铺设方向一致（线索/预言/身份/因果四型不得混写）
5. 扩写在项目内完成且触发了伏笔铺垫时，状态按 `memory-engineering.md` 与 `promise-ledger.md` 登记更新，扩写本身不直接改状态

## 自然度优化要求

- 扩写后按规则核验六维模板化痕迹分 ≤45 才交付（口径见 `quality-metrics.md`，诊断见 `ai-diagnosis.md`）
- 扩写最容易堆模板的部位：环境描写堆砌、心理独白、完美对白——逐段对照 `anti-ai-engine.md` 的通用自然度检查清单
- 新增字数的"3-gram 重复率"不得高于原文（防扩写产生复读）
- 扩写是做加法，但信息密度不得被稀释：每段仍要有增量，杜绝借扩写注水（联动 `reader-signal-alert.md` 水文检测）

## 产出报告模板

```markdown
## 扩写报告
- 扩写类型：场景展开（主）+ 情绪放大（辅）
- 原片段字数 → 扩写后字数：320 → 1150（约 3.6x）
- 扩写位置：第 3 章"他推开院门"段
- 新增元素：环境五感（夜色/虫鸣/风）、主角微动作（握拳/停顿）、一句潜台词对话
- 伏笔影响：无（未触及登记伏笔）；若触及，列出对应承诺 id 与处理方式
- 风格一致性：句长分布与原文一致 / 视角未变 / 无 OOC
- 张力变化：平静 → 紧张（暗涌）【若在项目中：扩写后按张力档位人工对比原文】
- 自然度：规则核验六维分 __（≤45 交付）
```

## 质量验收

- [ ] 扩写内容不改变原剧情走向
- [ ] 已注入记忆复核（若在项目内），角色状态/时间线无矛盾（过 `entity-state-machine.md`）
- [ ] 伏笔红线 5 条全过，承诺状态无冲突
- [ ] 规则核验六维分 ≤45，自然度自检通过
- [ ] 与片段衔接无缝（开头承接、结尾过渡）
- [ ] 单章字数落在目标平台区间（`platform-data-registry.md`）
- [ ] 无借扩写注水，每段有增量
- [ ] 产出报告已附
