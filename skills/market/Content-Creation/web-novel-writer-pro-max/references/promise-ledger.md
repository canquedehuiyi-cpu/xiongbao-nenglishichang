## 一、为什么需要账本

读者弃书、平台判定「结构失常」的一大来源是承诺管理失败：埋了伏笔不收、吊了胃口不兑现、人物立了目标却消失、金手指规则前后不一。人脑记不住长篇里几十上百条承诺，必须外部化为账本，随写随记、随章核对。

---

## 二、承诺类型

| 类型 | 例子方向 | 兑现方式 |
|------|----------|----------|
| 伏笔 | 提前出现、后文揭晓的物件/台词/细节 | 回收并产生情节作用 |
| 悬念 | 抛出的谜题、身份、真相 | 给出答案（可分阶段） |
| 爽点承诺 | 预告的打脸、复仇、升级、对决 | 按预期或超预期兑现 |
| 人物目标 | 主角想要什么、阶段性 KPI | 达成/失败/转化，都要有交代 |
| 关系承诺 | CP 走向、结盟、背叛预告 | 关系按铺垫推进或合理反转 |
| 规则承诺 | 金手指/力量体系/世界规则的边界 | 后文严格遵守，破例需先铺垫代价 |
| 情绪承诺 | 章末钩子、卷末高潮预告 | 下一章/下一卷及时回应 |

## 三、承诺状态机

每条承诺在账本中处于且仅处于一种状态：

```

planted 已埋设 → due 已到期（到了该兑现的位置）→ paid 已兑现
   │
   ├─ deferred 已延期（主动延后，记录新到期位置与原因）
   ├─ broken 烂尾/遗忘（到期未兑现，必须修复）
   └─ dropped 主动废弃（作者决定放弃，需在文中自然消解，不能凭空消失）

```

状态流转规则：

- `planted → due`：到达预设兑现位置，或读者期待已被充分拉高。
- `due → paid`：完成兑现，并记录兑现位置与兑现方式。
- `due → deferred`：确需延后，必须给出新位置，同一承诺延期不超过两次，否则读者流失。
- `due/deferred → broken`：超过最晚兑现位置仍无回应，标记 broken，属必须修复的结构缺陷。
- `planted → dropped`：主动放弃时，要在正文用一句话/一个情节自然消解，避免悬空。

## 四、账本结构

```

| ID | 类型 | 承诺内容 | 埋设位置(章/场景) | 承诺强度 | 应兑现位置 | 当前状态 | 兑现位置 | 兑现方式 | 备注 |

```

字段说明：

- **承诺强度**：强（主线/卷级，必须兑现）/ 中（支线/阶段性）/ 弱（氛围级，可自然消解）。强度越高，broken 的伤害越大。
- **应兑现位置**：写作规划时就给出预期章/卷，不允许「以后再说」。
- **兑现方式**：正常兑现 / 反转兑现（超预期）/ 悲剧兑现（反向但合理）。

**分卷汇总**：每卷结束输出一张「本卷新埋 / 本卷兑现 / 跨卷未兑现」清单，跨卷强承诺单独置顶追踪。

## 五、维护流程

```

写前（planning）：把本章计划埋设/兑现的承诺预登记
写中：实际埋设或兑现时回填位置
写后（reviewing）：
  1. 扫描本章新产生的承诺，全部入账（无遗漏）
  2. 检查 due 承诺是否在本章兑现；未兑现则 deferred 或标 broken
  3. 核对规则承诺：金手指/世界规则是否被违反
  4. 结果进入质量闭环连贯性门控
卷末：出分卷汇总，强承诺零 broken 才允许进入下一卷
结项（全书完本前）：全表过一遍，只允许 paid / 合理 dropped，不允许 due/deferred/broken 残留

```

## 六、防烂尾检查

完本前的硬性核对：

- [ ] 是否存在 `broken` 承诺？有则补兑现或自然消解。
- [ ] 是否存在超过两次延期的承诺？有则尽快兑现或重写其埋设。
- [ ] 主线强承诺是否全部 `paid`？
- [ ] 每个主要人物的目标是否都有结局交代（达成/失败/转化）？
- [ ] 金手指/力量体系规则是否前后一致、破例是否都付了代价？
- [ ] 章末钩子是否在下一章得到回应，没有「吊了就忘」？
- [ ] `dropped` 承诺是否都在正文有自然交代？

**与其他引擎联动**：实体/设定层面的一致性由 `entity-state-machine.md` 追踪；本账本追踪「对读者的承诺」，两者共同构成质量闭环门控 4（连贯性）的输入。

---

## 七、交付前核验清单

- [ ] 本章新承诺是否全部入账、字段完整？
- [ ] due 承诺是否兑现或合规延期，无静默遗漏？
- [ ] 强承诺是否零 broken？
- [ ] 规则承诺是否未被违反（违反处是否有铺垫与代价）？
- [ ] 卷末/完本汇总是否输出且无悬空承诺？

### 自检标准（可验证）

1. 构造「埋三条伏笔、只兑现一条」的样稿，能准确标出两条 broken 并给修复建议。
2. 任一承诺状态流转都符合状态机，不存在无位置、无原因的延期。
3. 完本检查时，账本最终只含 paid 与合理 dropped，可逐行复核。
