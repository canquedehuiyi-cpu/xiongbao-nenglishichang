# 记忆工程：超长记忆四层金字塔

> 长篇网文 30-300 万字不忘记设定：L0 章摘要归档 / L1 结构化事实卡 / L2 卷级滚动压缩 / L3 全书核心注入
> 版本：1.7.0
> 实现方式: 纯指令式记忆维护（无外部数据库与脚本）——由 AI 在会话内按本协议结构化维护，跨会话由用户保存记忆文档
> 分工边界（避免重复）：本文件负责**过程归档**（章摘要/事实卡/卷压缩/核心注入的时间线记忆）；角色与实体的「当前状态 + 变更合法性」由 `entity-state-machine.md` 负责（无因果不变更、OOC 三道检查）；伏笔与承诺的兑付状态由 `promise-ledger.md` 负责（planted→due→paid/deferred/broken/dropped）；可跨作品复用的设定要素沉淀到 `asset-library.md`。
> 联动：`length-engineering.md` 4.4 长篇超长记忆；`plot-resources.md` 桥段素材。

---

## 一、为什么需要四层金字塔（问题 → 方案）

| 长书记忆问题 | 单层方案缺陷 | 四层方案 |
|--------------|--------------|----------|
| 上下文窗口有限，全书全文无法常驻 | 只存摘要会丢失细节；只存全文会爆窗口 | L0 按章归档摘要 + 按需回查 |
| 角色实力/关系/状态随时变化 | 摘要里找角色状态太慢，易 OOC | L1 事实卡独立维护，快速回查 |
| 300 万字摘要链也会超窗 | 全部摘要常驻同样超窗 | L2 卷级滚动压缩，只取最近一卷 |
| 写到后面忘了初衷 | 设定散落各章，无从统一 | L3 核心注入永远挂载，全书不跑偏 |

核心原则：
- **数据层与生成层分离**：记忆以结构化形式独立维护，创作生成时不混入记忆细节
- **上下文卸载**：旧章全文/旧卷摘要不常驻，只注入当前需要的最小记忆块
- **冲突仲裁**：事实卡是最新事实来源，续写内容与事实卡冲突时以事实卡为准并提醒修正

## 二、四层金字塔总览

```

   L3 核心     书名/简介/大纲/主题/金手指/核心冲突/结局/铁律
              （全书不变式，永远挂载）
   L2 卷压缩   最近一卷：摘要链/新增角色/待回收伏笔
              （滚动压缩，随卷推进叠加）
   L1 事实卡   活跃角色快照 / 设定实体 / 时间线
              （结构化事实，快速回查）
   L0 章归档   每章 200-300 字摘要 + 提及角色 + 关键事件
              （最近3章常驻，旧章按需回查）

```

注入顺序：**L3 → L2 → L1 → L0**（先定盘心，再补近况，最后精确回忆）。

---

## 三、L0 章归档（精确记忆层）

每章完成后记录：
- **章节摘要**：200-300 字，覆盖本章推进的情节与变化
- **提及角色**：本章出场的角色名
- **关键事件**：1-3 个推动剧情的关键事件
- **AI 分/自然度分**：本章诊断得分（供趋势追踪）

用途：续写到第 200 章需确认第 5 章细节时，回查该章摘要与事件；角色出场情况可反查。

---

## 四、L1 结构化事实卡（语义事实层）

### 4.1 角色快照

每个主要角色维护一张事实卡：身份 / 实力 / 关系 / 状态 / 登场章 / 备注。

**防 OOC 铁律**：每个角色写完一章后同步其实力与状态；跨章引用角色信息前必须回查事实卡，禁止凭印象。

### 4.2 设定实体

势力 / 力量 / 道具 / 地图 / IP 五大类型设定实体登记成卡，跨章引用一律回查（对应体系树，见 `worldview-engineering.md`）。

### 4.3 时间线

记录关键剧情事件（每章 1-3 条），按章排序。

**防时空错乱**：续写时核对当前时间点，杜绝"主角上一章还在 A 地，这一章瞬移 B 地"类硬伤。

---

## 五、L2 卷级滚动压缩（压缩记忆层）

每卷结束时汇总：本卷各章摘要链、本卷新增角色、本卷全部待回收伏笔。

**滚动压缩机制**：
- 首次压缩：保存本卷各章摘要链
- 后续卷：在卷摘要头部标注"前 N 卷已压缩为上一级摘要"，滚动叠加——注入时只读最近一卷
- 语义级再压缩：续写前将本卷摘要链压成 200-300 字卷纲，回填核心大纲

**防遗忘**：固化每卷末未回收伏笔清单，卷间衔接时逐条确认（配合超期预警）。

---

## 六、L3 全书核心注入（核心记忆层）

维护全书不变式：书名 / 简介 / 大纲 / 主题 / 金手指 / 核心冲突 / 结局 / 铁律（8 项）。

**核心注入铁律**：
- **盘心永不漂移**：书名/主题/金手指/铁律四项开书时确立，全书续写永远挂载
- **冲突仲裁**：当某章剧情与铁律/核心冲突冲突时，以核心注入为准，回炉该章
- **8 项全注入才是完成态**：写作计划期建议 8 项全部确立

---

## 七、四层注入视图

续写/诊断/拆书前，输出完整记忆块（L3→L2→L1→L0）作为上下文：

```

【L3 全书核心】   → 已确立项全量
【L2 卷级压缩】   → 最近一卷：章数/字数/新增角色/待回收伏笔
【L1 事实卡】     → 全部角色快照 + 实体 + 时间线
【L0 章节摘要链】 → 最近 3 章摘要

```

数据量级膨胀后：
- L0 只注入最近 3 章（旧章按需回查摘要）
- L1 只注入活跃角色（实体按类型过滤）
- L2 只注入最近一卷（历史卷按需回查）

---

## 八、完整工作流（每章闭环）

```

写作计划期：确立书名/主题/金手指/核心冲突/结局/铁律 → 8 项全注入
每章开始  ：注入记忆（L3→L2→L1→L0）+ 核对时间点 + 超期伏笔预警
每章写完  ：记录摘要（200-300字）→ 更新角色状态 → 记录关键事件
           → 登记新设定 → 登记新伏笔
每卷结束  ：卷级滚动压缩 → 卷末复盘（待回收伏笔逐条确认）
遇到遗忘  ：回查单章摘要 / 回查历史卷摘要

```

**记忆规则总纲**：凡跨章节引用的设定（人名/地名/能力/时间/伏笔），写作时一律回查事实卡，禁止凭印象写；事实卡与正文冲突时以事实卡为准并修正正文。

## 九、记忆维护协议说明

| 能力 | 落地方式 |
|------|----------|
| 分层记忆 | L0 章归档 / L1 事实卡 / L2 卷压缩 / L3 核心注入 |
| 上下文卸载 | 注入只取 L3+L2最近卷+L1活跃+L0最近3章 |
| 冲突仲裁 | 铁律/事实卡为准，正文回炉 |
| 持久化 | 会话内结构化维护，跨会话由用户保存记忆文档 |

> 说明：本协议为纯指令式记忆维护（无外部数据库与脚本），适用单机创作场景；结构、字段与命名均为本 Skill 原创。
