# 跨形态内容指挥官

> **定位**：把一部网文的既有资产（人物、世界观、风格、剧情）转译为**其他内容形态可直接使用的完整指令包**——漫画/图像、短剧/剧本、有声播讲等。本文件只产出「内容指令文本」，**不内置任何图像/视频/音频生成运行时**；真正的生产由作者选择的外部工具完成，本文件负责让指令完整、一致、合规。
> 版本：1.7.0 ｜ 资产来源：`asset-library.md`、`character-depth.md`、`worldview-engineering.md`、`style-distillation.md` ｜ 剧本：`screenplay-creation.md`

## 一、能力边界

**做什么**：

- 输出结构化、可直接粘贴给外部生产工具或合作方的「指令包 / 设定文档 / 分镜脚本 / 风格词」。
- 保证跨形态改编时人物、世界观、剧情、风格与原作一致。
- 给出每个形态的合规提示（尤其 AI 生成图像/内容的披露义务）。

**不做什么**：

- 不直接生成图片、视频、音频，不内置生成引擎、运行时或工具调用。
- 不替代 `screenplay-creation.md` 的剧本格式规范，只做跨形态的统一调度与打包。
- 交互式小说/游戏属于另一套设计范式（分支、变量、多周目），本版本不建设其生产能力，仅在 `evolution-protocol.md` 未来方向保留观察位。

## 二、统一指令包结构

无论转成哪种形态，指令包都由五部分组成，缺一项视为不完整：

```
① 设定卡：人物（外貌/性格/三锚点/关系）、世界观、关键场景，来自既有资产，逐字对齐
② 风格词：目标形态的风格描述（画风/影调/播讲风格），可直接作为外部工具提示词
③ 结构/分镜：按目标形态重排的内容骨架（分镜表/场次表/播讲段落）
④ 一致性守则：跨集/跨话/跨段必须保持不变的要素与禁止改动项
⑤ 边界声明：AI 参与环节、版权来源、需披露事项、需作者确认项
```

改编原则：**保灵魂、换语法**——人物内核、主线、核心冲突不变；叙事语法按目标形态重写（漫画用画面叙事、短剧用强冲突前置、有声用听觉节奏）。

## 三、漫画 / 图像指令包

```
【人物设定卡】每个角色：脸型/发型/发色/瞳色/体型/标志性服饰/配色/性格气质/经典表情（逐话统一）
【场景设定卡】关键场景：空间布局/光线/色调/时代质感/标志性物件
【画风风格词】题材匹配的画风描述、线条、上色、镜头语言倾向（一段可直接使用的提示词）
【分镜表】
| 格序 | 景别(远/中/近/特写) | 画面内容 | 人物动作/表情 | 对白/旁白 | 镜头意图 |
【封面/单幅要点】主角识别度、题材信号、标题排版安全区
【一致性守则】人物五官与配色跨格跨话一致；服化道不随格变化；分镜连续
【边界声明】若使用 AI 生图，标注 AI 参与环节；平台对 AI 配图的披露要求经 `verify-protocol.md` 核实
```

要点：漫画靠画面推进，内心独白转为表情/动作/旁白短字；每格只表达一个信息点；分镜要标景别与阅读流向。

## 四、短剧 / 视频脚本指令包

```
【人物设定卡】演员可理解的人物小传：身份/欲望/缺陷/关系/标志性动作
【风格词】影调、节奏、题材类型标签
【场次表】（格式细节遵循 `screenplay-creation.md`，并对齐平台单集体量 `platform-data-registry.md`）
| 集/场 | 时长 | 场景 | 人物 | 核心冲突 | 钩子(开场/结尾) | 台词要点 |
【强冲突前置】每集开场钩子、集末悬念；爽点密度高于网文，删减心理描写
【一致性守则】人物动机不漂移、单集冲突闭环+连续悬念、服化道与设定统一
【边界声明】AI 参与环节、改编来源、平台 AI 声明义务经 `verify-protocol.md` 核实
```

要点：竖屏短剧用「开场 3 秒钩子 + 每集一个冲突 + 集末反转」；小说大段心理与设定转为动作和台词；体量按目标平台单集字数/时长口径。

## 五、有声 / 播讲指令包

```
【人物声音卡】每个角色：性别/音色/年龄感/语速/口癖/情绪基调
【旁白风格词】播讲人称、节奏、留白、氛围处理
【播讲段落表】
| 段 | 原文位置 | 旁白处理 | 角色台词 | 情绪/停顿提示 | 音效/氛围方向(仅文字描述) |
【一致性守则】同一角色全书声线统一；叙事人称统一；章节衔接有过渡
【边界声明】AI 配音/AI 生成音频的平台义务经 `verify-protocol.md` 核实后标注
```

要点：听觉线性、不可回看，复杂设定要口语化拆解；用停顿与语气替代书面标点；对话声线必须可区分。

## 六、一致性守则（跨形态通用）

1. **人物内核不变**：欲望、缺陷、关系、弧光与原作一致，外在呈现可按形态调整。
2. **设定不矛盾**：世界观规则、力量体系、时间线与原作及 `entity-state-machine.md` 对齐。
3. **主线不跑偏**：改编可压缩、可重排顺序，但不改变核心因果与结局方向（魔改方向另见 `fan-remix.md` 且需自洽）。
4. **承诺不丢**：原作伏笔/悬念在改编中保留或合理合并，对照 `promise-ledger.md`。
5. **风格可辨**：跨形态后仍能识别出原作的题材气质与作者风格（风格来自 `style-distillation.md`）。
6. **可追溯**：指令包每个要素标注来自哪份原作资产，便于核对。

---

## 七、合规边界声明

- 每份指令包必须包含「AI 参与环节 + 版权来源 + 披露事项」：AI 生成图像/音频/文本在哪些平台需要披露，按 `ai-disclosure-writer.md` 与 `verify-protocol.md` 处理（例如 KDP 对 AI 生成封面/插图同样要求披露）。
- 改编他人作品需先过 `anti-washing.md` 与 `fan-remix.md` 版权边界；指令包不产出侵权内容。
- 指令包是「给外部工具/合作方的生产说明」，不承诺外部工具的生成结果质量；生成结果仍需回到质量闭环审稿。

## 八、交付前核验清单

- [ ] 指令包五部分（设定卡/风格词/结构分镜/一致性守则/边界声明）是否齐全？
- [ ] 人物/世界观/主线是否与原作资产逐字对齐、无矛盾？
- [ ] 是否只产出指令文本、未内置任何生成运行时？
- [ ] 目标形态体量/格式是否对齐平台口径与对应专门文件？
- [ ] 是否包含 AI 参与与披露提示并经实时核实？
- [ ] 互动小说是否未越界建设（仅保留观察位）？

### 自检标准（可验证）

1. 给定一部小说的人物与世界观，能产出任一形态的完整五件套指令包。
2. 指令包不包含「调用某生成模型」的运行时步骤，只含可粘贴的文本说明。
3. 每份指令包都带一致性守则与合规边界声明，且要素可追溯到原作资产。
