# 专家团评审协议

> 模拟真实编辑团队的多人评审决策。7 位模拟专家全程介入，从选题到交付每个环节都有对应视角把关，目标是避免单一视角盲区、关键决策需多视角共识。以下专家均为模拟角色，不指向任何真实个人或机构，无虚构资历与战绩。
> 版本：1.7.0
> **定位与收敛**：本文件提供「多专家评审视角与否决标准」；最高强度的对抗式审稿统一由 `red-blue-review.md` 三层对抗承载，本文件的 7 位专家作为红方的多视角输入，不再另起一套并列审稿结论。平台 AI 合规判定一律引用 `ai-compliance-redlines.md`（实时核实），本文件不自行设定平台占比或处理口径。

## 二、全程介入机制

### 2.1 创作流程中的专家介入点

```

用户输入意图
    │
    ├─[选题阶段] 故事架构师：题材可行性分析 + 市场定位建议
    │             伦理审查：题材合规预检（是否触及平台禁区）
    │
    ├─[大纲阶段] 故事架构师：主线逻辑/伏笔布局/节奏规划
    │             角色设计师：主要角色差异化检查
    │
    ├─[人设阶段] 角色设计师：人设深度/对话DNA/记忆点审核
    │             一致性检查员：角色设定可扩展性检查
    │
    ├─[正文阶段] 叙事写手：自然度优化引擎全开/段落节奏/钩子设计
    │             角色设计师：对话是否符合角色DNA
    │
    ├─[交付前]   全员评审（关键章节）或轻量评审（过渡章节）
    │             伦理审查：AI使用声明检查/合规终检
    │
    └─[改编阶段] 改编专家：方案可行性/版权链审查
                  伦理审查：改编合规性检查

```

### 2.3 专家会诊机制

当单一专家发现跨维度问题时，触发**专家会诊**：

```

专家A发现跨维度问题 → 标记"需会诊" → 召集相关专家
                                              ↓
                                    各专家从自己维度评估
                                              ↓
                                    综合意见 → 出具会诊报告
                                              ↓
                                    按争议解决优先级裁决

```

**会诊触发条件**：
- 故事架构师发现角色行为影响主线逻辑 → 会诊角色设计师
- 角色设计师发现对话风格影响模板化痕迹 → 会诊叙事写手
- 伦理审查发现改编方案有版权风险 → 会诊改编专家
- 一致性检查员发现时间线问题影响后续伏笔 → 会诊故事架构师

## 三、模拟编辑审稿标准

### 3.1 平台编辑审稿流程模拟

模拟起点/番茄/晋江等平台的编辑审稿流程：

| 审稿环节 | 对应专家 | 平台真实标准 | 本 Skill 对应 |
|----------|----------|-------------|--------------|
| **初审（秒拒判定）** | 叙事写手 | 前300字是否有吸引力、是否有明显模板化痕迹 | 前50字钩子检查 + 模板化痕迹评分 |
| **复审（签约判定）** | 故事架构师 | 大纲是否完整、主线是否清晰、有无签约价值 | 主线逻辑检查 + 伏笔布局评估 |
| **终审（上架判定）** | 全员 | 整体质量是否达到平台标准、有无合规风险 | 六维评分 + 合规终检 |

### 3.2 各平台编辑关注重点

| 平台 | 编辑最关注 | 对应专家 | 审稿标准 |
|------|-----------|----------|----------|
| 番茄 | 读完率/追读率/前50字吸引力 | 叙事写手 | 钩子评分>7 + 模板化痕迹<45 |
| 起点 | 收藏量/IP潜力/世界观完整度 | 故事架构师 | 大纲评分>7 + 主线清晰度 |
| 晋江 | 角色魅力/情感张力/文笔质感 | 角色设计师 | 角色评分>7 + 对话DNA保持 |
| 七猫 | 快节奏/爽感/开头冲击力 | 叙事写手 | 钩子评分>8 + 节奏紧凑 |
| 豆瓣 | 文学性/深度/原创性 | 故事架构师 | 创意评分>7 + 文笔质感 |

|------|------|----------|--------|----------|

## 四、否决权（Veto）机制

任一专家在自己负责维度发现**硬伤**，可行使否决权：

### 否决触发条件

| 专家 | 否决条件（任一） |
|------|-----------------|
| 故事架构师 | ① 主线逻辑矛盾 ② 伏笔埋设后无法回收 ③ 核心冲突缺失 |
| 角色设计师 | ① 角色行为与设定矛盾（OOC） ② 对话DNA丢失 ③ 主要角色无记忆点 |
| 叙事写手 | ① 模板化痕迹评分>60（六维体系，见下注） ② 连接词密度超标 ③ 段落节奏崩坏（段落长度变异系数 CV<0.5） |
| 一致性检查员 | ① 时间线错乱 ② 设定前后矛盾 ③ 伏笔超期未回收且未说明 |
| 改编专家 | ① 改编方案破坏原作核心 ② 版权链不清 ③ 格式不可执行 |
| 伦理审查 | ① AI 使用越过「真人主导」边界（判定见 legal-compliance / ai-creation-ethics，平台口径以红线库实时核实为准） ② 涉及内容禁区 ③ 版权/洗稿风险 |
| 责编审稿人 | ① 开篇不留人 ② 爽点密度不达标 ③ 自然度八维诊断<75分 ④ 平台合规问题 |

### 否决流程

```

专家发现硬伤 → 行使否决权 → 标记问题 + 给出修改方向
                            ↓
              产出退回对应模块修复
                            ↓
                  修复后重新评审（同一专家复审）
                            ↓
                  通过 → 撤销否决 → 进入下一环节

```

**否决不是否决整篇，而是否决"不达标的部分"**。整篇可部分通过、部分退回。

> **两套评分体系显式区分（勿混用）**：
> - **六维检测体系**（规则核验口径，见 `anti-ai-engine.md` 与 `ai-diagnosis.md`）：词/语/句/感/构/标累计分 0-100，**分数越高 AI 味越重**，合格线 ≤45，叙事写手否决线 >60。
> - **八维诊断体系**（`ai-diagnosis.md`）：100 分扣分制，**分数越高越自然**，合格线 ≥75，责编审稿人否决线 <75。
> 两个体系量纲相反、用途不同（前者规则核验、后者人工诊断），评审时按各自阈值判定，不可交叉引用。

## 五、争议解决优先级

当专家意见冲突时：

| 优先级 | 原则 | 示例 |
|--------|------|------|
| 1 | **伦理/合规 > 一切** | 伦理审查否决 → 无论其他专家多认可，必须先解决合规 |
| 2 | **一致性 > 文笔** | 设定冲突必须修，文笔可为一致性让路 |
| 3 | **逻辑 > 美感** | 逻辑硬伤优先于语言优美 |
| 4 | **自然度优化 > 个人风格** | 模板化痕迹超标时，风格让步于自然度优化（除非用户明确优先风格） |
| 5 | **多数意见 > 单一意见** | 上述都不触发时，多数专家认可即可通过 |

## 七、轻量评审模式

非关键章节（如过渡章/日常章）可用轻量评审：
- 仅叙事写手 + 一致性检查员参与
- 无否决权，仅给建议
- 适合快速产出场景

关键章节（前3章/高潮章/转折章）必须全量评审。

### 关键章节判定标准

| 章节 | 评审等级 | 原因 |
|------|----------|------|
| 第1章 | 全量 | 签约/推荐的决定性章节 |
| 第2-3章 | 全量 | 读者留存关键期 |
| 高潮章 | 全量 | 质量决定口碑 |
| 转折章 | 全量 | 逻辑要求最高 |
| 伏笔回收章 | 全量 | 一致性检查员必审 |
| 过渡章/日常章 | 轻量 | 风险较低 |
| 改编方案 | 全量 | 版权+可行性双重风险 |

## 八、与红蓝对抗审稿的收敛关系

- 本文件的 7 位专家视角，是 `red-blue-review.md` 红方攻击时轮换佩戴的「视角库」：故事架构师/角色设计师/叙事写手/一致性检查员/改编专家/伦理审查/责编审稿人分别对应红方的结构、人物、语言、逻辑、改编、合规、商业视角。
- 专家否决权（第四节）的硬伤判定，作为红方「致命问题」的重要来源；否决项必须进入红蓝对抗终局的修订清单。
- 争议解决优先级（第五节）在红蓝对抗中继续生效：合规 ＞ 一致性 ＞ 逻辑 ＞ 自然度 ＞ 多数意见。
- 最终审稿结论以 `red-blue-review.md` 的「修订清单 + 不修订理由 + 残留争议」为准，本文件不单独输出与之并列的最终审稿结果，避免两套结论并存。
- 专家均为模拟评审角色，只对文本提供多视角分析，不代表任何真实编辑或机构意见。
