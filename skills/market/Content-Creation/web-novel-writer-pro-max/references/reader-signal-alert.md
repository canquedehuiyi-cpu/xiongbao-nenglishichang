# 读者侧低质预警

> **定位**：从读者真实反应侧（弃读、完读、追读、评论毒点）反推文本低质问题。平台内容质量要求（尤其番茄「四类低质」）本质是对读者流失信号的规模化识别；本文件把这些信号前置到创作环节，交付前先替读者「弃一次书」。

## 一、读者信号与平台低质的对应

| 平台低质类型（以番茄四类为例） | 读者侧信号 | 本质问题 |
|------------------------------|------------|----------|
| AI 粗制滥造 | 「像 AI 写的」「没灵魂」、滑走 | 机器痕迹重、无个人表达（对接 `human-fingerprint.md`） |
| 格式混乱 | 排版劝退、段落糊成一片、对话不分段 | 可读性工程问题（对接 `quality-metrics.md`） |
| 结构失常 | 看不懂、节奏乱、前后矛盾、烂尾感 | 结构与一致性问题（对接质量闭环门控 4） |
| 空洞水文 | 「水字数」「划了三屏没进展」、弃读 | 信息密度不足、无增量 |

> 平台低质分类以 `verify-protocol.md` 实时核实为准；上表给方向，不写死易变表述。

## 二、弃读信号清单

### 2.1 开篇弃读（黄金区间内流失）

- 前若干段没有冲突、没有悬念，只有背景/设定/自我介绍。
- 第一段信息过载，专有名词堆砌，读者无法建立代入。
- 主角不行动、无目标，被情节推着走。
- 开篇即大段说明（info dump），没有场景。

### 2.2 中段弃读（追读断裂）

- 连续多章无主线推进、无新信息增量（水文）。
- 爽点承诺长期不兑现，压抑无回报。
- 支线喧宾夺主，主角长期消失。
- 重复打怪/重复冲突，读者能预判后续。
- 人物降智、强行误会、为冲突而冲突。

### 2.3 细节弃读（出戏点）

- 前后设定矛盾、时间线错乱、人物 OOC。
- 常识/专业错误、数值崩坏。
- 对话不像人说的、全员一个腔调。
- 视角乱跳、称谓混乱。
- 排版密集、无分段、长段墙。

### 2.4 情绪弃读（毒点）

- 价值观冒犯、主角行为令人反感。
- 虐主无下限、憋屈不释放。
- 重要角色无意义死亡/强行 BE。
- 说教、喊口号、作者下场。

## 三、诊断与修复映射

| 信号 | 诊断 | 修复方向 |
|------|------|----------|
| 开篇背景倾倒 | 设定先于冲突 | 冲突开场，设定切片化后置（`asset-library.md` 世界观切片） |
| 三屏无进展 | 信息密度低 | 每段至少一个增量（新信息/新冲突/新关系变化），删无效描写 |
| 爽点不兑现 | 承诺悬空 | 用 `promise-ledger.md` 登记并按期兑现 |
| 前后矛盾 | 状态失控 | 用 `entity-state-machine.md` 核对实体状态 |
| 人物降智/OOC | 一致性破坏 | 回到人物卡「一致性红线」，补行为动机 |
| 全员一个腔调 | 语言无差异 | 按 `dialogue-engineering.md` 做人物语言分化 |
| 像 AI/没灵魂 | 机器痕迹 | 走 `human-fingerprint.md` 五维 + `ai-ratio-tester.md` |
| 排版劝退 | 格式问题 | 按 `quality-metrics.md` 重排（段落长度、对话独立成段） |
| 节奏可预测 | 突发性不足 | 句长/场景节奏交错，加入意外转折 |

## 四、自检走查流程

```

1. 模拟读者：以「第一次看到、没耐心、随时划走」的状态从头读
2. 标记弃读点：每一次想划走/出戏/困惑的位置都记录，不自我宽容
3. 归类：按第二节四类信号归档
4. 定级：致命弃读点（开篇/主线断裂/价值观）优先清零
5. 修复：按第三节映射到对应引擎处理
6. 复读：修复后再以读者视角走一遍，确认弃读点消失

```

**量化辅助**：结合 `emotion-curve-engine.md` 曲线，情绪长期低位且无期待张力的区段，几乎必然对应弃读点；结合 `novel-deconstruction.md` 同题材爽点/钩子密度基线，判断自己是否低于同题材常规密度。

## 五、交付前核验清单

- [ ] 是否以「陌生读者」视角完整走查并标记了所有弃读点？
- [ ] 开篇黄金区间是否有冲突/钩子，无设定倾倒？
- [ ] 是否不存在连续多章零增量的水文段？
- [ ] 四类平台低质是否都有对应读者信号排查？
- [ ] 每个弃读点是否映射到修复引擎并已处理？
- [ ] 致命弃读点是否清零后才交付？

### 自检标准（可验证）

1. 对一篇故意「开篇设定堆砌 + 中段水文」的样稿，能分别定位并给出修复方向。
2. 每个读者信号都能追溯到至少一个具体修复文件，无悬空信号。
3. 走查结论与情绪曲线、质量闭环门控结果一致，不互相矛盾。
