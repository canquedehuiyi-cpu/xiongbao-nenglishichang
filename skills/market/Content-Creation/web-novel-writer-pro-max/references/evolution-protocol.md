## 二、自然度规则自进化

### 2.1 进化触发

| 触发器 | 动作 |
|--------|------|
| 用户反馈「这个词也被 AI 用」 | 记入会话内模板词清单 |
| 检测中发现新的模板化表达 | 记入会话内模板词清单 |
| 模板化痕迹趋势连续 3 章恶化 | 提示加强自然度优化并复查清单 |

### 2.2 模板词学习流程

```

用户/检测发现新模板词 → 过滤（①不在已知词库 ②长度≥2字 ③非常见正常词）
                     → 纳入会话内「避免使用」清单 → 下次创作/润色生效

```

### 2.3 误报回收

| 信号 | 判定 | 动作 |
|------|------|------|
| 某词被正常使用且无 AI 感 | 疑似误报 | 移出清单 |
| 用户明确表示可保留 | 确认误报 | 移出并记入会话白名单 |
| 某词连续多章不再命中 | 失效规则 | 从清单移除 |

只记录用户明确反馈或反复出现的模式，单次疑似不纳入，避免误判污染规则。

## 三、平台规则变更闭环

当 `verify-protocol.md` 核实到平台规则/参数相对本地快照发生变化时，按下列闭环处理，不允许「核实到了却没同步」：

```

1. 定位事实源：AI 使用规则 → ai-compliance-redlines；平台硬数据 → platform-data-registry
2. 回写新值：按 FIFO 只保留最新值，旧值转入变更日志
3. 标影响面：列出引用该规则的下游文件（执行层/应用层/输出层）
4. 同步口径：下次这些文件被调用时读取新值；如输出模板含旧表述，当场修正
5. 留痕：在本文件第六节变更记录追加一条
6. 复核：确认全包不存在与新值冲突的旧口径副本（grep 校验单一事实源）

```

变更记录格式：

```

## YYYY-MM-DD 规则/参数变更
| 平台 | 规则类型 | 旧值 → 新值 | 来源级别 | 影响文件 | 是否已同步 |

```

纪律：

- 只记录真实核实到的变化，不记录推测；无法取得权威来源的条目标记待核实，不写入事实源。
- 平台差异化保鲜（7/14/30 天）由 `verify-protocol.md` 管理，本协议只负责「变化后的同步闭环」。

## 四、趋势反馈

```

趋势 = 改善 → 当前自然度策略有效，维持
趋势 = 恶化 → ①提示近期模板化痕迹偏高 ②建议对偏高章节走润色流程 ③排查是否引入新 AI 写作模式
趋势 = 稳定 → 维持；绝对值仍偏高则提示加强

```

每完成一卷（约 30-50 章）整体复查一次模板词清单与五维信号趋势（五维见 `human-fingerprint.md`）。

## 五、未来方向观察位

以下方向与本 Skill「签约专家（文本 + 合规 + 市场）」定位相关但能力栈不同，**仅保留观察，不在本版本建设文件、不排期**；当平台形态或用户需求发生实质变化时再评估是否单独立项：

- **交互式小说 / 游戏叙事**：可复用世界观、人物、剧情资产，但分支剧情、变量、多周目是另一套设计范式，现阶段不纳入。
- **多模态生产（AI 配图/视频/音频生成运行时）**：属多模态生产工具赛道；本 Skill 仅通过 `cross-form-orchestrator.md` 输出内容指令包，不内置生成运行时。

观察方式：在市场雷达中留意上述方向对网文签约的影响，只记录、不建设。

## 六、进化记录与复查

- 自然度：每次诊断可附带「本次新增/移除模板词」清单供用户确认。
- 规则：每次规则变更按第三节格式留痕，形成可追溯的变更历史。
- 复查周期：自然度规则每卷复查；平台参数按 TTL 保鲜；重大平台新规即时全量复查相关条目。
