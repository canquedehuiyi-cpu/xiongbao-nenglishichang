# 任务链（Prompt Chaining）与并行执行

> 用途：把复杂任务拆成多个单目标子任务，逐个调用模型（可串行可并行），适用于超复杂任务、分阶段任务、多模型协作。选型信号：任务超过一次调用能力 / 需分阶段 / 需不同模型/工具接力。

## 1. 为什么拆链

单次调用塞太多目标时，模型容易"顾此失彼"（指令遵循一致性下降）。拆链让**每个子任务只有一个目标**，质量可隔离、可调试、可复用。

## 2. 拆链原则

- **单步单目标**：每个子任务只做一件事（如"抽取要素"→"生成初稿"→"合规自查"→"润色"）。
- **交接物明确**：每步输出是下一步的输入，交接物要有稳定格式（文本/JSON/结构化摘要）。
- **隔离调试**：哪一步失败就在哪一步修，不重跑全链。
- **控制链长**：链不是越长越好，3-5 步内能完成的不拆 8 步；每步都是独立价值。

## 3. 串行链的交接格式

用固定标签或 JSON 作为交接物，避免自然语言歧义：

```text
第 1 步输出：
<output>（结构化结果）</output>

第 2 步输入：
请基于 <output> 中的 {目标字段}，完成 {下一步任务}。
```

## 4. 并行执行

多个**相互独立**的子任务可并行：
- 多个独立材料的独立分析 → 并行。
- 多方案并发生成 → 并行。
- 有依赖关系（B 依赖 A 的输出）→ 必须串行，不可并行。

## 5. 混合编排（链 + 并行）

复杂任务 = 若干并行组 + 若干串行段。例：需求分析（串行第 1 段）→ 多个独立方案并行生成 → 汇总评估（串行第 2 段）。

## 6. 无锚 Chain 禁用（硬约束）

- 链中的每一步必须**锚定在可验证的输入/中间产物**上（有明确的交接物）。
- 禁止"无锚 chain"：即每一步凭空发挥、没有上一步产物作为依据的伪链条（会逐级放大幻觉）。
- 任何一步若上一步产物缺失或不可用，必须**停链**并明确报告，而不是硬编中间结果。

## 7. 反例（不要这样用）

- 把简单任务拆成 10 步 → 无谓烧 token 与延迟。
- 有依赖的任务并行 → 结果错乱。
- 无交接物的"伪链" → 幻觉放大（见 §6 硬约束）。

## 8. 与其它模块联动

- 模板：PIPELINE.md（批量分步处理）、AGENT.md（常驻多步 agent）。
- 引擎：`diagnose.mjs` 的失败现象分析可定位到具体链步。
- 压缩：链步间压缩见 context-management.md §4。
