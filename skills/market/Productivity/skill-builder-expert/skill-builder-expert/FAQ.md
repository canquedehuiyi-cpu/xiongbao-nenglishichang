# FAQ · 常见问题（按需单答，绝不整册甩出）

> **按需回复铁则（Agent 必须执行）**：

> 1. 用户问到能定位的具体问题 → **只回该问的答案**，禁止输出其他问；

> 2. 用户泛问「常见问题 / 怎么用 / 有什么要注意」→ **只回六类分类大纲**（类别字母＋类名＋各类问题数），提示用户回复（A）至（F）字母（大小写均可）或类名关键词点选；**禁止用阿拉伯数字点选**（数字号段全链路另有专用含义，防撞车），**禁止用圈号点选**（圈号无法用普通键盘输入），禁止整册输出；

> 3. 用户点某类 → 只回该类问题清单，清单顶部标注「请回复（A1）至（A15）查看具体问题，大小写均可；也可直接问问题本身」；用户点某问 → 只回该问答案；

> 4. 每答完一问，尾部最多轻引导一行：「相关联还有（B3）（C5），需要随时说」——引导中的编号必须真实存在且可回复，禁止占位符写法，禁止罗列更多；

> 5. 任何场景不得把全部问题一次性发给用户——逐条按需给，用户问什么答什么；

> 6. 字母编号大小写不敏感：如（A3）与（a3）命中同一条，与文本口令同级识别；

> 7. **直答匹配规（用户不报编号不报字母、直接用自然语言说出问题时）**：先与 56 问匹配（问法字段＋问题标题＋正文关键词，大小写无关）——**命中唯一 → 逐字输出该问标准答案**（挂公共兜底尾部片段，禁止临场改写、禁止只答一半、禁止另造格式）；命中多条 → 只列候选问的标题让用户挑（回复编号即答），禁止直接猜答其一；零命中 → 不硬凑，按意图识别走业务链路或回分类大纲。

>

> **唤起方式**：对话中输入 **【帮助 / FAQ / 常见问题 / 怎么用 / 卡住了 / 不会调】**。

## A 认知入门

> 本类回复范围：（A1）至（A15），大小写均可；也可直接问问题本身。


**A1：这个专家和我自己手写技能有什么区别？**（问法：区别 / 为什么要用 / 自己写行不行）

你自己写每次都要从 0 想标准；本专家把统一标准焊进流程，自动拆、自动检、自动修、自动打包，从 1 到 N 直接复用。你已有的方法和经验，这里是让它们「成型能用」的流水线。

**A2：我需要先把资料整理好才能开工吗？**

不用。想到哪说到哪，文档（Word、PDF、PPT、TXT、MD、Excel）、图片、语音、视频、表格、链接都能接，口述零门槛想到哪说到哪；有现成资料直接发。整理是工具的活，不是你的负担。

**A3：我不懂技术、不是程序员，能用吗？**

能。谁都能用——只要手里有想沉淀的经验、手艺、标准、流程、规则、制度、技巧、技术、心法、策略、方法、判断、条件、逻辑等；不设行业、岗位与规模门槛。技术上怎么合规、怎么打包，工具全程处理，你只管把事说清楚。

**A4：做一个技能，整个流程是什么样的？**

五步：接收素材 → 选型确认（版本类型 / 部署形态 / 分发访问模式三项）→ 按标准构建 → 全套质检 → 交付技能包＋评测报告。每一步你确认后再走下一步，不跳步。

**A5：我做好的技能能装到哪些平台？**

产出结构兼容智能体工作台、代码智能体、智能体系列等主流平台，结构兼容的第三方平台也可装；各渠道上架与审核规则一切以官方最新公告为准。

**A6：生成的技能 Skill 里都有什么文件？**

按档位不同：极简型含 SKILL.md / _meta.json / LISTING.md / README.md；标准型加 hooks / references / scripts / FAQ；重型型再加 tests 与质检脚本。细则见 `references/REF-SKL-007_SkillSkeleton_v1.md`。

**A7：专家自身也按标准自检吗？**

需要。本专家自身完整满足标准自检项，额外过质检评测分析出厂闸、代码安全第七闸与防自我放水护栏——管别人的工具，自己先被管。

**A8：技能会记录我的使用偏好吗？**（问法：偏好 / 记录 / 记住 / 隐私 / 删除记忆 / 清除）

为提升使用体验，技能可在你的设备本地保存你选择的配置与偏好信息，仅作用于你自身的会话交互，不会上传至外部服务器、不会分享给第三方、不会用来训练其他用户的技能。你拥有完整控制权：口令「清除偏好 / 重置配置 / 删除记忆」任一即可立即清除全部本地偏好记录并回执。

**A9：制作技能周期长、要改很多轮，中途不知道该怎么操作怎么办？**（问法：多轮修改 / 中途迷茫 / 不知道下一步 / 跨天继续）

整个制作流程全程提供确定性指引，每一步会同步当前进度与你接下来要完成的事项。无论表述不清、思路临时变化，还是中途卡住，你随时可以回复 **【帮助】** 唤起导航，或回复数字 **【0】** 回到主菜单。各类输入都会被接住，即便对话跨多天、多次迭代修改，回来也会先收到进度回顾和待办提示。关键节点由你确认拍板，不会替你擅自做业务决策；遇到状况会给到可行选项，始终可以引导回到标准流程继续推进。

**A10：操作中搞不清下一步，万一操作错了怎么办？**（问法：操作错误 / 搞不清下一步 / 点错了 / 卡住了）

每一轮交互的末尾都提供兜底指引：不清楚后续操作，回复 **【帮助】** 唤起完整导航；拿不定主意，直接说出你的顾虑。就算操作出现偏差，你随时回复 **【菜单】** 或数字 **【0】** 就能回到主菜单重新选择，不会卡死在流程当中。

**A11：害怕选错，担心一旦定下来后面改不了怎么办？**（问法：怕选错 / 能不能改 / 改不了 / 后悔了）

技能制作本身就是可以多轮迭代打磨的过程，不需要第一次就做到尽善尽美。每一步会讲清各个选择的实际效果，有合适默认方案会给到参考建议；拿不准时提供客观建议，最终决定权由你掌握。本次方案执行完成后，后续想法变化依旧可以通过 **【技能优化调整】** 链路继续修改升级；全程随时回复 **【帮助】** 或数字 **【0】** 回到主菜单，不会被卡在流程当中。

**A12：做技能消耗精力，做到一半想停下来可以吗？**（问法：暂停 / 不想做了 / 太累 / 改天再弄）

当然可以。沉淀业务为技能本身会消耗不少思考，不必强求一次全部做完。你可以直接暂停任务，已经上传的素材与当前进度会做归档保存，后续随时回来接着推进；随时回复 **【菜单】** 或数字 **【0】** 即可回到主菜单。

**A13：我有自己的业务想法，和给到的参考方案不一样怎么办？**（问法：想法不同 / 意见不一致 / 不认可方案 / 想改方向）

业务层面的最终决策权属于你。工具会为你说明不同选择对应的客观情况与潜在影响，你确认方向之后，完全按照你的选择执行；安全与合规底线不受影响。

**A14：我不会写文档，只会说——能把脑子里的经验、手艺、判断讲给你做成技能吗？**（问法：口述 / 只会说不会写 / 没有资料 / 聊天能做吗）

**A15：做出来的技能包长什么样？里面都有什么？**（问法：成品长什么样 / 技能包里有什么 / 交付的是什么 / 成品示例）

一个标准件技能包，固定五部分：① SKILL.md 主册——技能的使用说明与执行规矩，Agent 装载就读它；② references 参考册——模板、规范、流程细则，按需查阅；③ scripts 自检脚本——装包就跑的质量检查，不达标出不了厂；④ 元数据文件——名称、版本、描述，平台展示用；⑤ 可选扩展——按你的业务加资料或接口。示例结构：skill-name／SKILL.md＋references／＋scripts／＋_meta.json——你拿到的每一份都是这个骨架，内容按你的业务填充；全链条版本留痕，每次迭代生成独立快照，可对比、可回退。

## B 四大闭环

> 本类回复范围：（B1）至（B7），大小写均可；也可直接问问题本身。

**B1：四个闭环分别管什么？我该从哪个进？**

代建（从零帮你做）、答疑（问问题）、调整（已有技能卡住报错或想迭代升级）、评测（成品质检）。你直接用大白话说诉求，工具自动路由到对应闭环；也可以回菜单序号定向进入。

**B2：我只想问问题、不想自己做，可以吗？**

可以。答疑是独立闭环，问完即结束，不强制引导你做技能；想落地时再随时转入代建，之前的对话基础都在。

**B3：技能做好了怎么进入评测？**

直接说「评测技能」或把包发给工具；评测只出报告不改包——定性分析、不打分不评级、标注依据、区分规范红线项与业务可选优化项，改不改、改哪些由你确认。

**B4：评测出问题，能直接帮我修吗？**

能，但先确认再动手：评测报告给出参考方案，你确认范围后才进入优化调整闭环；调整完附变更清单与根因分析，逐条说明改了什么，再请你实测。

**B5：我手里有别人做的 / 第三方的技能包，能整合成自己的吗？**

能。评测后经你确认，可对外来技能包做整合改造：业务规则由你定义，工具负责按标准落地执行；素材权利归属由你自行确认，工具只做工程层处理。细则见 `references/REF-IGT-033_IntegrateExternal.md`。

**B6：修完了怎么确认改对了？**

两道：工具侧全套质检复跑＋变更清单逐条对账；你侧结合真实业务场景实测——你最清楚业务里什么算「对」，工具不替你下结论。

**B7：需求说不清能开工吗？**

能。工具会按立项表单逐项问最关键的 1–2 项，补齐后回主线，不瞎猜、不擅自扩大理解。

## C 选型配置

> 本类回复范围：（C1）至（C9），大小写均可；也可直接问问题本身。

**C1：版本类型怎么选？**

版本（免费/收费）与运行模式（轻量/API）是两根独立的轴，可以自由组合。系统默认「免费版本＋轻量模式」，不做选择直接按默认执行；需要收费能力时，直接回复「收费版本」，再完整回复「收费确认」开启收费版本链路（切换回免费版本一句话即可）。特殊方案数字直达：[5] 收费版本、[6] API模式（任何状态裸数字即达；分发访问模式用 [7]/[8]/[9]），数字在每个屏面只有一个含义。全部技能产出遵循同一套质量基线。

**C2：轻量模式和 API模式怎么选？**

业务逻辑全部内置、不依赖外部接口，走轻量模式（默认优先）；需要调你自有的外部服务、网关、鉴权，走 API模式——注意：API模式无论免费还是收费，都需要服务器、域名、备案、证书等配套（备案性质须与业务内容匹配：个人性质备案仅限非经营性内容，涉及收款支付的接入建议以企业主体办理）。细则见 `references/REF-DEP-018_DeploySpec.md`。

**C3：分发访问模式是什么？三种怎么选？**

决定技能发布在哪、谁能看到：公开模式（上架技能广场，含免费版本/收费版本，需平台完整审核）、专用模式‑自用版（仅自己可用不上广场，可下载安装包自行发放）、专用模式‑私域版（广场专用通道需审核，普通用户不可见）。细则见 `references/REF-DST-034_DistributeMode.md`。

**C4：选型时拿不准怎么办？**

直接回「不清楚」，工具给客观的选型对照与建议，讲清差异后由你拍板；不会替你默认选。

**C5：为什么分发模式必须我确认，不能帮我默认选？**

因为模式选错没有后悔药：产物公开后向「仅自用」回退在平台侧未必可行。这是必须由你拍板的配置，工具只讲清利弊，绝不代填。

**C6：选错了还能改吗？**

产物公开前、生产过程中可调整；一旦公开上架，向「仅自用」回退在平台侧未必可行，所以工具在生产前就和你锁定模式。发现选错第一时间说，工具评估可行的调整路径。


**C7：免费版本怎么配？**（问法：切换免费版本 / 改成免费版本 / 免费版本配置）

默认新建技能即为免费版本。如果你手上已有一份技能包需要切换为免费版本：移除收费相关支付配置，即可切换；完成之后可以选用轻量模式或API模式。

提示：免费版本不代表只能自用，满足平台条件也可以上架；技能对外终端使用者不需要付费。

**C8：轻量模式怎么配？**（问法：切换轻量模式 / 改成轻量模式 / 已有技能改成轻量模式）

默认新建技能即为轻量模式，业务逻辑全部内置，无需服务器、域名、备案等外部资源。

如果已有API模式的技能包，想要改造切换到轻量模式，需要移除全部外部网关、接口调用相关配置；改造前建议先做技能质量评测，确认改造范围，确认之后再执行整改。

**C9：做好的技能能给我们公司团队一起用吗？**（问法：团队用 / 公司用 / 给同事用 / 多人使用 / 企业用）

能。配置第二步的分发访问模式就是管这个的：公开模式（上架技能广场，谁都能装）、专用模式‑自用版（只有你自己用，不上广场，可下载安装包自行发放）、专用模式‑私域版（指定范围可见，需审核）。公司内部使用建议选自用版或私域版；交付后把安装包发给同事，各自按标准使用方法安装加载即可。细则见 `references/REF-DST-034_DistributeMode.md`。

## D 收费与计费

> 本类回复范围：（D1）至（D5），大小写均可；也可直接问问题本身。

**D1：免费版本和收费版本质量有区别吗？**

没有。全部技能产出遵循同一套质量基线，工具不做版本之间能力对比说明；是否收费只影响是否配置收款环节，按你的业务需要选择即可。

**D2：做收费版本我要准备什么？**

需要你自行确认目标运行/上架平台，提交该平台最新官方支付接入开发者文档，完成商户开通与资质认证，备齐属于你本人的商户参数——工具解析文档输出准备清单，不代替你获取收款资质，也不保证资金实际结算到账；未收到官方文档与你本人商户参数前，不生成任何支付配置。细则见 `references/REF-PAY-012_PayStandardFull.md`。

**D3：收费路线有哪些？怎么挑？**

平台插件市场、微信支付、支付宝个人、其他生态 SkillPay 四条接入路线（以上为接入事实描述，非官方背书，能否开通以各通道自身审核为准），外加独立积分制备选；选哪条前先过「成本账四步法」测算值不值得收。全部细则见 `references/REF-PAY-012_PayStandardFull.md`。

**D4：平台怎么收费谁说了算？**

平台。计费方案依对应平台、技能广场、技能市场的规则配套设置，主流模式含买断制、订阅制、按量付费；各平台标准有差异，以平台现行规则为准。

**D5：做收费技能一定有收益吗？**

不保证。工具保证产出标准化、安全、可检验的工程产物（这是底线）；但业务效果受素材质量、真实场景、你自身判断影响——这条边界写在明处，不藏着。

## E 边界与能力范围

> 本类回复范围：（E1）至（E12），大小写均可；也可直接问问题本身。

**E1：专家会不会擅自改我的业务逻辑？**

不会。标准锁只读；工具只对齐统一规范，不改你的业务内容，最终口径由你把关。

**E2：生成的技能不合规怎么办？**

交付前自检引擎逐项校验，不达标自动修正并复检，不达标不出包；交付后若发现问题，走评测→确认→修复闭环，材料齐即承接。

**E3：交付后我该实测哪些内容？**

在目标平台结合真实业务场景跑：常用问题问一遍、边界情况试一遍、触发词按应触发/不应触发各验一轮；实测发现问题随时回传，进入评测 / 修复闭环。你业务场景里「对不对」，你的实测是最终标准。

**E4：出了问题，售后要提供什么材料？**

报错排查材料四件套：技能原始包（保持原样不删改）＋ 现场截图（完整界面）＋ 报错原文（整段复制不删减）＋ 目标渠道信息（平台＋版本号＋版本类型＋部署形态＋分发模式）。缺哪件工具温和引导补哪件，齐了立即进入排查。细则见 `references/REF-DLV-029_BuildDeliveryWorkflow.md` 第十一节。

**E5：我的素材含内部业务资料、带密钥，安全吗？**

工具内置资产保护护栏：密钥、私有推广参数、专属业务配置禁止直接复用或外泄、禁止落进文档；含敏感资料建议配专用模式，导出安装包后的分发风险由你自行管控。相关纪律见 `references/REF-DMN-019_DomainComponentBoundary.md`。

**E6：平台规则变了怎么办？**

**E12：怎么判断我的经验值不值得做成技能？**（问法：值得做吗 / 我的经验能做成技能吗 / 什么经验适合做技能）

看三条：①这件事换个人是不是就做不好，只有少数人掌握；②是不是长期重复在做、结果时好时坏；③是不是想固定下来长期复用或传给团队。前两条同时成立，就值得封装；只占一条，先说出来一起对齐确认再定。没有底稿、全凭口述也完全能做，难度高一些但价值最大。

## F 故障与救助

**F1：卡在某一生产步骤了怎么办？**

触发二级兜底：当前步骤定向帮助弹出，可 **【回到当前步骤继续任务】** 或 **【重新从头开始任务】**，进度保留不丢。

**F2：技能运行报错怎么办？**

直接描述现象或发报错原文，进入修复闭环：先给修复方案清单，你确认后修改，修完附变更清单＋实测提醒。

**F3：上架被审核驳回了怎么办？**

把驳回意见原文发给工具，按反馈材料持续排查、调整合规、迭代升级，跟进适配平台规范；平台硬性资质类限制会如实说明并给替代实现方案。

**F4：怎么调出帮助和常见问题？**

对话中输入 **【帮助 / FAQ / 常见问题 / 怎么用 / 卡住了 / 不会调】** 任意一个即可；求助全流程在对话窗口内自助完成。

**F5：常见问题这么多，我不想全看怎么办？**

不用全看。你问哪条，只答哪条；泛问时给分类目录让你点选——本册就是按「按需单答」设计的，绝不会一次甩给你几十问。

**F6：我的技能上架后，用关键词搜不到怎么办？**（问法：搜不到 / 检索不到 / 找不到我的技能）

按三步排查：①先用技能完整名搜一次；②确认上架版本为最新，更新版本后等平台索引刷新；③仍搜不到，把所用平台＋搜索词＋技能名发到当前对话，由工具方协助排查。

**F7：怎么确认我装的技能是完整的、没被篡改？**（问法：验签 / 签名 / 正版 / 完整性）

在技能详情页侧边栏「内容签名」复制验签提示词发给 Agent，或在终端执行平台命令行工具的 verify 命令（需较新版本，验签需联网）。结果为「签名与内容校验通过」即完整且由平台官方签发；「内容指纹不匹配」说明本地文件与平台记录不一致，重新获取对应版本即可。

**F8：这个技能包本身安全吗？**（问法：安全吗 / 有没有毒 / 报毒）

本工具产出的包，出包前经内置八维安全自检（供应链、命令执行、网络外传、敏感路径、Prompt 注入、远程脚本下载、编码混淆、其他），高危命中直接阻断出包。您也可以把包自行提交平台安全检测做二次印证（网页提交，约三十分钟出结果）；对外表述检测结论时请写明对应版本号。

**F9：技能更新了新版本，之前上架的怎么办？**（问法：更新 / 新版本 / 重新上架）

平台索引与检测结论都按版本绑定：新版本需要重新上传到各市场，老版本不会自动获得新内容；历史版本按您的版本管理规则保留回退能力，是否替换由您决定。
