# AI Skill 技能Skill开发通用规则标准手册

> **文档定位**：本手册是运行宿主生态下所有 Skill 技能Skill立项、设计、开发、测试、上线验收、迭代监控的标准化规则手册，供开发者与评审 Agent 共同使用。  

> **核心逻辑**：Agent 技能不是凭空创造需求，而是对用户现有解决方案做优化替代；必须先守边界、匹配人群、分清交付类型、做好风险告知、配置退出机制与防呆路由，再做成本、效率、稳定、容错四维价值比对。  

> **执行原则**：串行校验、条件刚性、指标可量化、全程可观测、权责可隔离。任一前置校验不通过，终止立项；价值比对四项不全合格，终止或返回优化；测试不通过，禁止上线。  



> **【平台优先声明】本手册为开发者内部标准，不与平台强制规则冲突时有效；当本手册与运行宿主平台、第三方智能体平台等各 Agent 平台的官方强制规则冲突时，以平台强制规则为准。**

> 本册何时读：需要技能骨架规范全文（结构/字段/元信息）做逐项比对时按节查阅；日常搭建只查 SKILL.md 与直达层。

## 1. 适用范围与角色

### 1.1 适用范围
- 运行宿主生态下所有 Skill 技能Skill的立项、设计、开发、测试、上线验收、迭代。
- 技能方案评审 Agent、开发 Agent、开发者、测试人员、上线评审人员。
- **适用形态覆盖两类技能形态**：交互式技能（用户在线触发、多轮交互）、定时自动化技能（无人值守、按计划自动执行）。两者在前置校验与高风险节点处理上规则不同，见第 2.1 节。

### 1.2 手册作用
- 作为 Skill 开发的**内部标准化准则**（非平台规则，平台强制规则优先，见卷首声明）。
- 作为评审 Agent 的**刚性判定依据**。
- 作为提交表单、评审报告、整改清单、上线复核的**统一口径**。

### 1.3 强制要求
- 评审必须按“前置校验组 → 价值比对组 → 落地测试组”顺序串行执行。
- 前置校验任意一项不通过，直接驳回或返回优化，不再继续后续价值比对。
- 所有校验项必须输出明确结论，禁止模糊描述、主观宽松判定。
- **开发者与评审者须隔离；若由同一 Agent 既开发又评审，必须加载本手册独立标准，并额外引入外部复核或陌生环境实测，防止宽松放行（详见第 9.1 总纲第 8 条）。**

## 2. 术语定义与交付类型

| 术语 | 定义 |
|---|---|
| 过程交付型 Skill（TYPE-A） | 仅负责执行约定动作，不承诺外部业务结果；验收标准=动作准时、准确、不丢失；外部业务结果由第三方平台/客观条件决定，收益为概率性收益。 |
| 结果交付型 Skill（TYPE-B） | 输出可核验、可直接落地的成品交付物；相同输入下产出标准固定；收益为确定性人力/资金节约。 |
| 技能形态·交互式 | 用户在线触发、与 Agent 多轮交互完成任务的技能。高风险节点可设置用户手动确认。 |
| 技能形态·定时自动化 | 无人值守、按计划自动执行的技能（如定时抓取、定时推送）。**禁止包含任何需用户手动确认的高风险节点**（见校验2边界C）。 |
| 原有基准方案 | 用户当前已经在用的方式（人工、其他工具、旧流程），作为比对基线。 |
| 刚性成本 | 指令触发即产生的消耗，主要为 Token/积分调用成本。 |
| 三重边界 | 法律边界、第三方平台规则边界、用户决策权边界。 |
| **第四重边界·数据隐私与版权** | 用户上传内容（含 know-how、个人信息）归属用户、不外传未授权第三方、敏感信息脱敏、封装产物版权约定清晰。 |
| 净收益 | 用户在原有方案下的成本 − 使用本 Skill 刚性 Token 成本。 |
| **净收益复核** | 立项用预估净收益初筛；上线首月以实测数据复核，实测净收益≤0 则迭代或下线。 |
| 综合比对四要素 | 成本、时间效率、稳定确定性、鲁棒容错兜底。 |
| 鲁棒容错 | 合法指令、正常业务流程中，遇到外部异常、接口超时、第三方限流、失败时的兜底、重试、通知机制。 |
| **跨平台适配基线** | 同一技能Skill分发多平台时，以能力最弱平台为功能下限，高级平台可增强；埋点/确认/定时以各平台实际开放能力为准。 |
| 可观测指标 | 可采集的运行数据，如 Token 消耗、任务成功率、用户操作时长、失败率、取消率、防呆触发次数。 |
| 透明告知 | 技能主动向用户说明限制、概率、风险、不保证项。 |
| 防呆 & 意图兜底机制 | 对偏离流程、超出能力边界、高危违规输入做分流纠偏、友好拒绝、强制拦截，防止误操作、无效消耗、越界执行。 |
| **高危清单** | 各技能作者按领域定义的「高危请求/操作」清单，写入状态机，判定优先于一切执行。 |

### 2.1 交付类型与技能形态判定规则

**交付类型（二选一，固定标记，不可混写）**：

| 类型 | 验收标准 | 强制附加 |
|---|---|---|
| TYPE-A 过程交付型 | 动作触发准时、指令准确、定时任务不丢、链路稳定 | 前置告知用户：本技能仅执行动作，不保证外部业务结果，收益为概率性 |
| TYPE-B 结果交付型 | 同等输入，输出交付物规格、质量稳定，可复核检验 | 说明交付标准、交付范围、不包含内容 |

**技能形态（二选一，影响高风险节点规则）**：

| 形态 | 定义 | 高风险节点处理 |
|---|---|---|
| 交互式 | 用户在线、多轮交互 | 授权/确认/提交/领权益等高风险节点，强制用户手动确认 |
| 定时自动化 | 无人值守自动执行 | **禁止包含需手动确认的高风险节点**；若业务必需，拆为「自动预处理 + 交互式确认执行」两段 |

> **【自由对话边界】** 围绕本技能主线的多轮澄清、参数追问、状态确认，属于正常交互，不算漂移；跨技能跳转、开启无关能力、无边界闲聊，属于漂移，须按防呆场景A纠偏。禁止的是「无边界自由漂移」，不是「主线内多轮交互」。

## 3. 风控分层、构建规范与Skill技能搭建专家

本章从「守边界」延伸到「怎么把技能建得准、建得稳、能批量复制」：3.1 解决用户卡点自助脱困；3.2 解决内部路由精准寻址、杜绝模型自创与相似分支误命中；3.3 把本手册本身变成可反复调用的Skill技能搭建专家，根治「标准写成文档却用不上」的死结。三层机制互不替代，与四重边界、防呆、鲁棒容错共同构成完整体系。

| 层级 | 管控对象 | 触发时点 | 处理目标 |
|---|---|---|---|
| 三重合规边界 | 法律、平台规则、用户决策权 | 底层红线，立项与设计阶段一票否决 | 不违规、不越权、高风险节点由用户确认 |
| **第四重·数据隐私与版权** | 用户上传内容、个人信息、封装产物版权 | 立项与设计阶段一票否决；运行时持续执行 | 内容归属用户、不外传、脱敏、版权清晰 |
| 防呆 & 意图兜底 | 用户输入跑偏、越界、高危违规 | 输入层前置拦截，尚未进入业务执行 | 引导回归、友好拒绝、强制拦截、停止无效消耗 |
| 鲁棒容错 | 合法指令下外部接口超时、限流、失败 | 业务执行过程中 | 合理重试、通知用户、异常止损、避免爆 Token |

**禁止混淆**：
- 外部接口超时，不是防呆，属于鲁棒容错。
- 用户问无关问题，不是鲁棒容错，属于防呆意图兜底。
- 高风险授权、确认、提交、领权益，属于用户决策权边界，必须手动确认（仅限交互式形态）。

**【跨平台适配基线】** 同一技能Skill分发智能体工作台 / 代码智能体、其他智能体系列、第三方智能体平台时，功能以能力最弱平台为下限；埋点、手动确认、定时任务能力依各平台实际开放情况降级，不强制统一。

## 3.1 使用救助与受限数据观测闭环机制

> **适用背景**：Agent 平台（智能体工作台 / 代码智能体、其他智能体系列、第三方智能体平台等）强制隔离创作者与终端用户，仅提供汇总级下载/调用量，不开放用户明细行为数据。在平台隔离、数据受限、无人工客服的客观约束下，依靠技能内置逻辑就地分层应急挽救用户卡点，并以自主埋点弥补平台数据缺失。

### 3.1.1 定位与适用范围
- **交互式技能**：完整启用本机制四大子目标。
- **定时自动化技能**：无人值守，不适用卡点救助与 FAQ 主动唤起；仅保留「子目标4 自主埋点观测」作为创作者离线复盘依据。
- **启用前提**：分发到 Agent 平台且平台不开放用户明细数据时强制启用；自建环境按实际数据权限调整。
- **客观约束说明**：平台隔离创作者与用户，无人工实时对接通道；平台仅提供汇总级下载量/调用量。非创作者不愿服务，是平台架构边界。

### 3.1.2 核心底层目标
Agent 按主线连续推进；一旦中途卡点、理解障碍、操作失误、流程阻滞，若无分层应急救助，用户会停滞、任务中断、产生额外时间成本与无效 Token 消耗，破坏稳定确定性。本机制目标：不靠外部人工，依靠技能内置逻辑就地分层挽救，优先引导回正轨、保障走完流程拿到结果；无法继续时提供可控终止，避免无限卡死、无效消耗，实现低成本、高效率、稳定交付。

### 3.1.3 强制校验四大子目标
**子目标1：前置结构化自助 QA 知识库（FAQ）**
1. 整理高频问题 QA 库，覆盖：新手疑问、操作步骤、专业名词、预期结果、常见报错、功能限制。
2. 支持用户主动唤起：输入 **【帮助 / FAQ / 怎么用 / 卡住了 / 问题】** 等关键词调出 QA 目录与解答。
3. 内容对齐技能边界，不编造能力、不承诺无法实现的效果。
4. 设计原则：基于经验预判全链路潜在卡点，提前覆盖大概率卡住环节，弥补平台无用户真实问题数据的短板。

> FAQ 是用户**主动查询**的帮助文档；防呆路由分支话术是 Agent**主动纠偏**的输入层拦截话术，二者职责不同、均在状态机配置。

**子目标2：流程内卡点被动即时救助（嵌入业务流程，自动触发急救）**
- **弱触发**：用户长时间无响应 → 轻量提醒（不暂停业务、不阻断）。
- **强触发**（任一即触发）：同节点反复输入无效内容、多次同节点执行失败、用户文字明确表达困惑（不知下一步/看不懂/卡住）→ 进入救助。
- 强触发动作：暂停当前自动推进、停止不必要 Token 消耗；弹出**当前节点定向精简帮助指引**与可用操作选项；优先引导回当前主线步骤，默认不重置全盘任务，仅用户主动要求时重置；局部救援，不跳出本技能链路，保留已有进度，尽力延续至拿到预期结果。

**子目标3：自助救助穷尽后的可控兜底声明**

查阅 QA、节点指引后仍无法继续，Agent 输出固定兜底提示：明确本技能为全自动自助工具；受平台机制限制，创作者与用户相互隔离，无人工客服、无创作者对接通道、无问题上报/人工协助通路；同步提供两个入口：**【重新开始任务】【退出终止任务】**。

**硬性约束**：禁止承诺人工介入、工单反馈、联系创作者、问题上报等无法兑现的内容。

**子目标4：自主埋点观测闭环（弥补平台数据缺失）**
- 平台原生局限：仅下载总量、调用总量，无用户明细行为、卡点位置、流失节点、提问、画像。
- 技能内部自主埋点（见第 2 章统一口径）：救助触发次数（弱/强）、QA 查阅次数、卡点救助成功回归主线比例、救助后退出/重置比例、卡点节点编号、卡点类型。
- 数据用途：创作者无其他渠道感知用户问题，仅依此离线质检、定位高频卡点、修复逻辑、迭代 QA 库、优化救助话术，持续降低卡住概率。

### 3.1.4 路由隔离（四层独立触发，不可混淆）
| 层级 | 管控对象 | 触发条件 | 处理动作 |
|---|---|---|---|
| 防呆意图兜底 | 意图跑偏/超界/高危 | 输入层前置 | 拦截/纠偏/拒绝 |
| 使用障碍急救（本机制） | 意图正确但操作卡住/理解障碍 | 使用层被动触发 | 就地急救、保留进度、引导回归 |
| 鲁棒容错 | 合法指令但第三方/外部异常 | 业务执行异常 | 重试/通知/止损 |
| 自主埋点观测 | 平台不给明细时的数据补偿 | 全程采集 | 离线复盘修复 |

## 3.2 路由节点编码、静态素材预绑定、定向索引调度规范

> **适用背景**：技能内部路由若无精准文字描述、缺少唯一编号、分支边界模糊，会出现四类典型故障——① 目标分支为 C，但 B、C 高度相似，Agent 错误匹配 B 并交付错误答案；② 路由指向不明，Agent 被迫读取 A/B/C 全部分支逐一比对，耗时耗 Token；③ 无定向调取，Agent 抓取多段内容混合拼接，偏差极大；④ 规则堆砌冗余、模型绕开模板自主生成，确定性彻底失效。叠加用户侧不确定输入（卡点、随机提问、越界），若无分层兜底与回拉主线机制，兜底即终止、任务中断。

### 3.2.1 定位与核心目标
1. **常态链路**：向用户交付的全部内容都带唯一编码、精准路径，优先做到精准、稳定、标准交付。
2. **风险兜底链路**：路由调用异常、匹配失败、用户卡点、用户提问越界时，执行分级兜底。
3. **兜底后回拉**：兜底完成后提供明确入口引导回主线，争取继续完成交付，而非直接中断。

通过「唯一编号 + 路由索引表 + 静态素材绑定 + 强约束调度 + 兜底回拉闭环」杜绝四类故障与越界中断；命中分支后按编号调取绑定模板与文件，不再全库遍历。

### 3.2.2 强制校验七大子目标
**子目标1：全局唯一节点编码规范**
1. 所有业务节点、分支选项、输出分支、兜底分支统一分配不可重复编码（示例：MAIN-01、BRANCH-01-01、FALLBACK-01）；所有交付用户的输出内容绑定对应编码与路径。
2. 路由跳转条件须精准写明目标编码，禁止模糊描述（如「去下一步、相关回答、匹配合适内容」）。
3. 索引总表独立存放：编码、触发条件、目标动作、绑定模板编号、绑定素材编号、下一跳编码、兜底分支编码。

**子目标2：静态输出模板预封装，刚性禁止现场拼装固定内容**
1. 所有固定句式、固定回复、标准文案提前做成独立模板并分配编号，与节点编码绑定。
2. 固定内容不写在 Agent 推理链路里；硬性约束：不允许 Agent 临场改写、自由组织、拼接预设标准回复。
3. 仅动态变量（用户输入、第三方实时返回数据）允许注入预封装模板占位符；其余文字一字不可由模型自行生成。

**子目标3：素材（文件/附件）索引与复用调度规范**
1. 所有外部素材（文档、图片、文件）分配独立素材唯一 ID。
2. 建立素材关联表：记录 **【素材ID】** 可被哪些节点编码调用；支持一对多复用（同一文件 A，节点 B/C/D 均可沿用）。
3. 调度规则：节点命中后仅读取本表登记的素材 ID，不自动加载其他无关文件；不存在无绑定自由读取文件逻辑。

**子目标4：路由寻址隔离规则（解决四类故障的核心约束）**
1. 先匹配触发条件，算出唯一目标节点编码。
2. 寻址动作：只加载 **【当前节点编码】** 绑定的模板、绑定素材、下一跳编码。
3. 硬性禁令1：禁止 Agent 遍历全部分支、全部模板、全部素材做模糊相似度匹配。
4. 硬性禁令2：相似分支（B、C 内容相近）必须增加前置差异化判定条件，编码互相独立、索引表分开，防止混淆命中。
5. 硬性禁令3：规则不堆砌冗余限制，判定条件精简、互斥；命中指定节点后强制锁定使用其绑定模板，禁止模型自主创作、自由发挥生成替代答案。

**子目标5：分级兜底机制（覆盖路由调用异常、用户卡点、越界提问三类）**
- 一级兜底：当前节点执行异常、素材调用失败、路由匹配出错 → 触发本节点局部兜底模板（预封装），告知当前环节异常，不直接结束任务。
- 二级兜底：用户意图正确但操作卡住、看不懂、反复无效输入 → 触发卡点救助 QA（见 3.1）。
- 三级兜底：用户提问超出技能能力边界、随机无关 → 触发边界兜底模板，明确告知能力范围，不编造无关答案。

所有兜底文案同样是预封装、带独立编码的固定模板，禁止现场编造。

**子目标6：兜底后的主线回拉闭环（核心新增）**
1. 任何一级兜底输出后，兜底模板末尾固定附带 2 个入口：**【回到当前步骤继续任务】【重新从头开始任务】**。
2. 回拉逻辑：用户选择回到当前步骤，路由直接跳回兜底发生前的原始节点编码，保留已有进度，继续正常主线流转。
3. 禁止兜底后直接终止对话、丢弃进度；仅当用户主动选择退出才执行退出终止。

**子目标7：执行链路日志埋点补充**

新增埋点：命中节点编码、尝试检索的分支数量、实际加载的模板编号、加载素材 ID、是否出现跨分支误匹配、是否触发模型自创内容、兜底触发等级、兜底后选择回拉/重启/退出次数。用途：平台数据受限前提下，定位易串扰的相似分支、检索开销大的路由、易自创的节点、高频兜底类型。

### 3.2.3 与已有模块兼容
- 构思层（设计草稿）严禁写入运行包。
- 能力层存放路由索引表、节点编码、判定条件、寻址规则、素材关联关系、锁止约束、兜底跳转编码、回拉路由。
- 辅助层（防呆、救助 QA、容错、退出、风险告知）同样遵循编码＋模板绑定规范。
- 路由优先级沿用：防呆拦截 → 卡点救助 → 鲁棒容错 → 能力层主路由 → 分级兜底 → 兜底回拉判断 → 收尾埋点。

## 3.3 Skill技能搭建专家本体（标准化生产 Agent）

> **定位**：本身是一套遵循前面全部规范的 Skill，定位为标准化流水线生成引擎。使用者输入新技能需求，专家 Agent 按既定全套规范自动拆解需求、产出合规技能产物（路由索引表、节点编码、模板、素材绑定、兜底回拉逻辑、立项表单、测试用例）。它不是一次性设计文档，是可反复调用、从 1 到 N 批量生产合规技能的生产工具。

> **核心痛点**：过往规范只停留在文档/思想层，无法自动落地；新需求进来需从 1 到 N 批量产出时，标准无法自动复用、规则易跑偏、产物与原始设计产生偏差；且缺少自动化校验，不知道专家有没有严格遵守规范。本模块把「思想标准 → 专家执行规则 → 自动拆解 → 产出合规包 → 自动检测 → 偏差标记修正」闭环固化，直接解决「整理完不用、每次从 0 到 1」的核心痛苦。

### 3.3.1 强制校验六大子目标
**子目标1：专家内置标准锁（内置全套规范，不可随意漂移）**
1. 专家内部固化整套规范全集：三层隔离、节点唯一编码、索引表格式、静态模板绑定、素材 ID 复用、寻址定向约束、路由优先级、三级兜底＋主线回拉、防模型自创锁止。
2. 硬性约束：专家 Agent 解析需求、生成方案时，不允许自行修改、简化、遗忘内置标准；所有产出物必须对齐标准，不能自由发挥新增或删减规范。

**子目标2：需求输入 → 结构化拆解引擎（需求转产出）**
1. 输入：用户提交新技能业务需求。
2. 拆解步骤固定顺序：① 区分并隔离构思层（仅归档，不写入运行包）；② 提取能力层主干业务动作、交互分支、触发条件；③ 提取辅助层（防呆、卡点救助 QA、容错、退出、兜底、埋点）；④ 给每个节点/模板/素材分配唯一编码；⑤ 生成路由索引总表（跳转、兜底编码、回拉节点）；⑥ 生成静态模板清单（固定文案预封装、标记动态变量）；⑦ 生成素材关联表（素材 ID、可调用节点）；⑧ 生成全套测试用例。
3. 约束：拆解完成后产出物自动区分模块，不混写、不夹带构思层进入运行逻辑。

**子目标3：合规自检检测引擎（检测专家有没有按标准执行）**

生产完成后自动逐项校验，对照前面所有校验清单逐条打分、标记：是否剥离构思层；节点编码全局唯一、索引表完整；是否强制定向寻址无全局扫描；相似分支差异化隔离；模板预封装、无现场拼装固定文字；锁止规则禁止模型自创；三级兜底齐全、兜底后配置回拉主线路由；埋点齐全。输出自检报告：达标项、违规项、风险项、偏差位置。

**子目标4：偏差修正闭环机制**
1. 自检发现不达标项，专家不能直接放行。
2. 针对每条违规点自动输出定向修正方案，并自动重生成对应模块内容。
3. 修正完成后再次执行一轮自检，直到全部核心校验项通过。
4. 记录历史偏差类型，沉淀到专家知识库，减少后续同类偏差。

**子目标5：版本快照与复用机制（解决 0→1 之后 1→N 无法复用）**
1. 每次生产任务生成版本快照：原始需求、索引表、模板、素材关系、自检报告。
2. 支持复用已有路由片段、模板片段、素材绑定规则，新需求直接沿用已有编码体系，不需重复从零搭建。
3. 标准本体独立版本管理；标准升级后专家可同步更新内置规范，存量快照不被强制改动。

**子目标6：专家自身的路由与兜底**

专家本身也是 Skill，遵循同样的路由编码、定向寻址、兜底回拉规则；当需求模糊、信息不足时，触发专家自身兜底，向用户提问补齐缺失信息，补齐后回生产流程，而非直接产出不合格方案。

### 3.3.2 硬性执行区分规则
1. 专家的 **【标准库】**：底层基准，只读，生产环节不修改。
2. 专家的 **【拆解引擎】**：按标准库翻译需求为技能物料。
3. 专家的 **【自检引擎】**：对照标准库审计产出。
4. 专家的 **【修正引擎】**：根据审计结果修复物料。

四者职责隔离。

## 3.4 技能质量标准五维体系（出厂质检闸门）

> **定位**：在「立项前置校验（校验1-9）」之外，新增一道**出厂质检闸门**。它只回答一个问题——"这个已经产出来的包，达不达标、能不能放心交付"。它是全部技能Skill的**最低准入红线**，不是最高要求；达标只是入场券，不承诺满分。

> **与生产闭环对齐（核心约束）**：技能质量标准的判定口径必须与本手册、与专家拆解引擎的产出口径**同源、同尺**。规则是本工具写的、产物是本工具产的、评测也是本工具评的——只有三者用同一套标准，评测才测得住；若规则说 A、评测说 B、产物写的是 C，评测就失去意义（详见 §3.5 防自我放水）。因此：标准锁、拆解产出规范、技能质量标准阈值三者必须沿用同一份定义，任何一侧改口径须同步另两侧。

> **运行模式**：流水线出厂**默认自动执行**（`auto_quality_check=true`）；同时开放独立调用入口（`manual_quality_check=true`），开发者可手动对任意包跑评测。

### 3.4.1 五维定义（递进一票否决）

- **可信任度（前置红线，一票否决）**：能不能放心用。查安全合规、最小权限、敏感信息保护、网络可用性、中文交互。触碰安全红线直接判不合格，终止后续。
- **可靠性**：能不能稳定用。查同输入输出一致性、边界异常输入处理、失败异常反馈。极端输入下不静默崩溃、不空输出、不乱码。
- **适用性**：该不该在当前场景调用。查适用场景清晰、能力边界明确、触发条件无歧义、输入输出参数完整。写明"能做什么 + 不能做什么"。
- **规范性**：能不能长期维护复用。查命名与节点编码长期稳定、文档结构完整、参数说明齐全、配套示例完整。全局路由编码统一、SKILL.md 完整、模板编号绑定固定。
- **有效性**：是否真正解决业务问题。查结果准确、内容完整、格式合规、交付物可直接落地，无需大量二次返工。区别于原生模型自由输出，避免无效伪能力。

### 3.4.1a 五维核验细则（开发要求 + 评测要求 成对落地）

> 每维四要素：核验检查项（开发必须落地、评测逐条核对）＋ 开发要求 ＋ 评测要求。开发与评测共用同一套细则，保证"怎么建就怎么查"，标尺唯一。

**① 可信任度 · 核心判断：能不能放心用**
- 核验检查项：安全基线完成检测无高危风险；遵循最小权限原则，不申请业务无关权限；具备敏感信息识别与隔离机制，防止用户资料对外提供；国内环境可稳定运行；完整支持中文交互与中文提示。
- 开发要求：设计阶段同步规划安全、权限、隐私防护逻辑。
- 评测要求：核查安全配置、权限范围、敏感信息处理逻辑、运行环境适配性。

**② 可靠性 · 核心判断：能不能稳定用**
- 核验检查项：相同输入条件下输出结果保持一致；具备处理非常规、边界输入的能力；遇到无法解析、无法处理的输入或文件时，输出清晰可读的原因提示，禁止静默失败、空白返回、乱码输出。
- 开发要求：预先设计异常分支、错误反馈链路。
- 评测要求：构造边界用例测试，核查异常反馈机制是否生效。

**③ 适用性 · 核心判断：该不该在这个场景用**
- 核验检查项：清晰标注适配的业务场景；触发逻辑明确可控，降低误调用概率；清晰写明能力上限、不支持的场景；输入、输出要求定义清晰。
- 开发要求：简介与说明文档必须写明适用范围与能力边界，禁止夸大能力。
- 评测要求：核查边界说明完整性，识别能力描述模糊、范围夸大问题。

**④ 规范性 · 核心判断：能不能被理解、维护和复用**
- 核验检查项：采用渐进式信息披露，不一次性堆砌冗余信息；配套说明文档分层清晰，降低阅读门槛；写明已知局限与提示事项；附带标准使用示例，便于快速上手。
- 开发要求：交付包必须配套结构化文档、使用示例、限制说明。
- 评测要求：核查文档可读性、结构完整性、示例可用性。

**⑤ 有效性 · 核心判断：是否真正解决用户问题**
- 核验检查项：输出内容匹配业务诉求、结果正确；交付内容要素齐全，不缺失关键信息；产出物支持直接投入业务使用；减少用户二次整理、调整的成本。
- 开发要求：输出结构对齐业务目标，围绕用户要解决的问题设计产出。
- 评测要求：核验产出内容是否达成业务价值。

### 3.4.2 技能质量标准运行规则

1. 技能质量标准为本体系内部核验依据，仅用于技能质量自查，不代表任何平台的上架审核结论。
2. 校验顺序严格固定：Trust → Reliability → Adaptability → Convention → Effectiveness。
3. 前序维度未达标，直接终止评审，不进入下一环节（递进一票否决）。
4. 触发方式：出厂默认自动检测；同时支持独立调用，开发者手动发起。

### 3.4.3 两道闸门定位说明（消除冗余观感）

- **第一道闸 · 立项前置（校验1-9）**：发生在"动手做之前"，判定**这个想法该不该做**——人群对不对、边界踩不踩、类型清不清、风险告没告、退出有没有、防呆全不全、救助到不到位、路由编没编、专家合不合规。它是"idea 层面"的红线。
- **第二道闸 · 出厂质检（技能质量标准五维）**：发生在"做完了要出包时"，判定**这个成品达不达标**——安全不可信、跑起来不稳、场景说不清、没法维护、解决不了问题，任何一个不过都不让出包。它是"artifact 层面"的红线。产出物的工程质量另按 `REF-SKL-007` 第六节生成物质量标准（内核四卡：排版 / 代码 / 内容策略 / 工程适配）逐卡核验，与 技能质量标准五维并行生效、互不替代。
- 两者意图有交叉（如校验2 安全边界 vs T 安全），但生命周期阶段不同、对象不同，不构成冗余；标准表述上已各自限定范围，评审时按阶段分别核验，不重复也不漏检。

## 3.5 生产体系自监管与失效兜底（防自我放水·防规则失效）

> **问题根源（三线合一）**：本体系里，**立法**（写标准）、**生产**（产技能）、**评测**（按技能质量标准判达标）由同一套专家完成。没有任何外部制衡时，存在两类结构性风险：

> ① **自我放水**：自己写规则、自己产、自己评，体系可能悄悄把评测尺子放宽松，让不过关的包"轻松过去"；

> ② **规则失效**：哪怕主观想守规矩，规则也可能在运行时没生效、被绕过、被瞎执行——而本工具以为它执行了。

> 本模块是应对这两类的**全局护栏**，必须随标准一同落地，不可省略。

### 3.5.1 五层护栏（L1–L5）

- **L1 · 标准锁不可篡改**：标准（本手册 + 技能质量标准）作为只读锁。专家启动先算锁文件哈希，哈希不符或缺失 → **起点 fail-closed，拒绝启动**。技能质量标准阈值固化在基线文档，生产运行无权改阈值；想"过"只能改产物，不能改尺子。
- **L2 · 评测与生产物理隔离**：`skill_quality_check` 只扫描**产物包的实际文件内容**（frontmatter、路由索引、FALLBACK 模板、测试用例实跑输出），**不读专家自报的"我通过了"标记**。评测探针用例选自固定、版本钉死、生产运行不可编辑的探针用例库，不是专家为某个技能现编的。评测结果生成**签名报告**（包哈希 + 标准哈希 + 逐维结论 + 时间戳），报告不可被生产静默重生成"通过版"。
- **L3 · 步骤不可跳过 + 偏离即拦**：9 步拆解每步产出可探测中间资产（索引表/编码/模板/素材表），下一步开始前校验上一步资产存在，缺则中断。自检引擎对实际产物 vs 标准期望结构做偏离度检测，超阈值进修正闭环，不静默放行。
- **L4 · 全节点可观测埋点**：每个节点埋"编码命中 / 兜底触发 / 流程回拉"三类事件。应触发却零埋点 = 专家脱稿信号，触发即告警，不触发视为异常。
- **L5 · 外部独立复检（自我放水的终极防线，必要非充分）**：诚实承认——三线合一的体系，内部 技能质量标准防的是无意识偏差，防不住有意的自我放水。真正确认"没自我放水"只能靠体系外的人/账号：`manual_quality_check` 模式让不同人 / 独立 Agent 跑同一 `skill_quality_check`；最终由包属方用陌生账号真跑一次做第三方终验。架构任务：把 `skill_quality_check` 做成独立、可签名、可外部复跑的工具，让外部验证成本低、可信度高。

### 3.5.2 规则失效总兜底

- 任一闸门（标准锁哈希 / 步骤校验 / 技能质量标准核验 / 签名）返回 **fail OR error OR 未运行** → 一律视为不通过，专家**默认拦截，不产出 zip**。
- 增设"体系健康自检"：专家每次运行先自检五道闸门脚本是否齐全、可运行；脚本缺失即停。
- 每次拦截必须产出可读的**拒绝原因清单（负面清单）**，不许静默；拒绝原因随包归档，供包属方复核。
- 质量目标承诺：出厂闸门全维达标为底线，异常概率靠前置约束 + 三级兜底 + 主线回拉 + 出厂技能质量标准核验压缩到极低；不对任何平台评分做承诺（工程标准化消除人为偏差，但无法完全抹平模型原生概率波动）。

## 4. 标准总流程

```text
立项提交

  ↓

前置校验组（9项，串行，任一不通过终止/返回优化）

  ↓

价值比对组（4项，全部合格才通过）

  ↓

方案设计 → 开发实现 → 全量测试 → 上线评审

  ↓

上线后监控与周期复盘（含版本管理）

  ↓

指标退化 → 迭代优化 / 下线
```

**硬性规则**：
1. 前置校验全部通过，才进入价值比对。
2. 价值比对四项全部合格，才进入开发测试。
3. 测试不通过，禁止进入上线评审。
4. 上线后持续监控，指标偏移低于阈值启动迭代。
5. **版本管理**：每次上线标注版本号，变更须回归测试，历史版本可回滚，多壳/多平台分发须基线一致。
6. **付费技能**：上线前须以未绑定付费账户的陌生环境实测完整计费链路（下单→扣费→交付→退款）。

## 5. 第一部分：立项前置校验（9项，串行执行）

> Agent 执行顺序：1→2→3→4→5→6→7→8→9，串行校验，不允许跳过。  

> 任一不通过：终止立项或返回优化后重新评审。

### 校验1：目标人群匹配校验

**可量化校验项**：
1. 明确标注人群标签：`大众通用型` / `垂直行业专业型`。
2. 交互、引导话术、专业术语、操作步骤严格对齐人群认知：
   - 大众通用型：无专业黑话、分步引导、降低学习门槛、上下兼容零基础用户。
   - 垂直行业型：使用行业通用术语、贴合行业固有工作流。
3. **判定标准**：**目标人群**在引导下可以独立走完完整业务链路；目标人群无法完成流程，判定为技能设计失败，非用户问题。（区分两类人群各自判定口径。）

**输出结论**：**【人群校验通过 / 不通过 + 原因】**

### 校验2：四重边界校验（红线，一票否决）

逐条勾选：

- ✅ **边界A｜法律边界**：不违反法律法规，不构成不正当竞争、批量操控、扰乱资源分配秩序、薅取权益等违规行为。
- ✅ **边界B｜平台规则边界**：
  - 自动点击执行动作（允许）。
  - 算法抢占/抢券/高频暴力请求/篡改概率（禁止）。
  - 技能不改变第三方平台原有资源分配概率，仅代为执行点击动作。
- ✅ **边界C｜用户决策权边界**：
  - 交互式技能：所有高风险节点（授权、确认、提交、权益领取、订单类操作）强制设置用户手动确认环节。
  - **定时自动化技能：禁止包含需手动确认的高风险节点**（见第 2.1 节形态规则）；若业务必需，拆为两段式。
  - 禁止 Agent 自动替用户确认、自动同意、自动授权。
  - 确认规则：方案经确认后进入执行；确认环节仅锁定执行范围，后续效果跟进由业务侧自主安排。
- ✅ **边界D｜数据隐私与版权边界**：
  - 用户上传内容（含 know-how、个人信息）归属用户，不外传未授权第三方。
  - 敏感个人信息须脱敏处理。
  - 封装产物（如生成的技能、文档）版权归属与授权范围须向用户明示。

**输出结论**：**【边界校验通过 / 不通过 + 违规项说明】**

### 校验3：交付类型判定

二选一，固定标记，不可混写：
- TYPE-A：过程交付型 Skill。
- TYPE-B：结果交付型 Skill。

**同步标记技能形态**：交互式 / 定时自动化（影响校验2边界C 与 校验5 退出机制）。

**输出结论**：**【交付类型判定完成，输出对应验收标准 + 前置告知文案模板】**

### 校验4：透明度与风险告知校验

**可量化校验项**：
1. 技能必须在用户开启任务前，清晰告知：
   - TYPE-A：说明这是概率收益、哪些因素会影响结果、平台侧不可控。
   - TYPE-B：说明交付标准、交付范围、不包含哪些内容。
2. 告知内容不能隐藏、不能折叠在小字内，必须是用户启动任务前可见。
3. 禁止夸大承诺：禁止“一定领到、100%成功、必出结果”这类话术。

**输出结论**：**【透明度校验通过 / 不通过 + 缺失告知项】**

### 校验5：退出、撤销、终止机制校验

**可量化校验项**：
1. 用户随时可以暂停、取消定时任务、撤回授权、终止正在执行的任务。
2. 取消后不再继续消耗 Token，停止后续动作。
3. **定时自动化技能**：须提供「关闭定时任务」入口，关闭后不再自动触发；因无人值守，关闭动作本身即替代「手动确认」承担止损功能。

**输出结论**：**【退出撤销机制校验通过 / 不通过 + 缺失项说明】**

### 校验6：防呆与意图兜底机制校验（独立校验项）

必须覆盖三类分支，缺一不可：

| 场景 | 处理规则 |
|---|---|
| 场景A：用户意图跑偏、提问脱离当前技能主线 | 温和纠偏，引导回归本技能主线流程；不开启无关任务，不随意跳转其他能力；话术友好，给出清晰可用指令示例。（围绕主线的多轮澄清不属跑偏，见 2.1） |
| 场景B：请求在合规范围内，但超出本技能能力边界 | 友好告知边界，清晰说明“当前技能不支持该需求”；不编造能力、不强行尝试、不盲目调用链路消耗 Token；不承诺无法交付内容。 |
| 场景C：请求触碰红线、高危、不可受理 | 直接拦截终止，拒绝执行，**停止后续业务链路消耗**（不调用下游工具/接口）；**非「零 Token」——识别输入已耗的 Token 不可避免**，重点是阻断后续消耗；留存风控记录，不继续交互引导。 |

**【高危清单方法论】** 各技能作者须按领域定义「高危请求/操作清单」并写入状态机，高危判定优先于一切执行；清单随技能表单一并提交评审。

**硬性设计要求**：
- 必须设置意图识别路由，优先判断输入归属。
- 禁止无边界自由漂移（非禁止主线内多轮交互）。
- 防呆逻辑前置，在进入业务执行、消耗 Token 之前触发拦截/纠偏。

**输出结论**：**【防呆兜底机制校验通过 / 不通过 + 缺失分支说明】**

### 校验7：使用救助与受限观测机制校验

**可量化校验项**（四大子目标须全部配置）：
1. 是否存在结构化 FAQ 库、支持关键词唤起、覆盖全链路预判卡点。
2. 是否设置卡点识别规则（含强弱触发分级）、绑定对应节点定向帮助、救助后可回原链路、保留进度。
3. 穷尽救助后是否给出基于平台隔离的兜底声明（无人工客服、附重置/退出），严禁虚构人工通道。
4. 救助相关埋点是否配置齐全（触发次数/QA查阅/回归比例/退出重置比例/卡点位置），可支撑平台数据受限下的离线复盘。
5. **形态适配**：交互式技能四子目标全过；定时自动化技能仅校验子目标4埋点配置。

**输出结论**：**【使用救助与受限观测机制校验通过 / 不通过 + 缺失子目标说明】**

### 校验8：路由节点编码、静态素材预绑定、定向索引调度校验

**可量化校验项**（七大子目标须全部配置）：
1. 是否存在全局唯一节点编码 + 独立索引总表（编码、触发条件、目标动作、绑定模板/素材编号、下一跳、兜底编码）。
2. 标准化固定回复是否全部预封装为编号模板，主干链路不含大段待现场组装文本；模板与节点一一绑定。
3. 素材是否分配独立 ID、建立复用关系表；节点命中后按需定向加载，不批量加载全部附件。
4. 寻址逻辑是否为定向索引加载（仅加载当前节点绑定资源），禁止全分支全素材扫描检索。
5. 相似分支是否增加差异化前置判定条件并隔离（编码、索引表分开），防止 B/C 混淆误命中。
6. 是否存在锁止规则：命中节点后强制使用绑定模板，禁止模型自主创作、自由发挥。
7. 三级兜底（路由异常/卡点救助/越界提问）是否均为预封装编号模板；兜底后是否配置主线回拉路由（回原始节点、保留进度）。

**输出结论**：**【路由编码与定向调度校验通过 / 不通过 + 缺失子目标说明】**

### 校验9：Skill技能搭建专家本体校验（适用于Skill技能搭建专家型技能；普通技能经合规专家产出即可，不重复校验本项）

**可量化校验项**（六大子目标须全部配置）：
1. 专家是否内置全套标准锁，禁止生产过程私自改动规范（标准库只读）。
2. 需求拆解是否固定顺序流水线（隔离构思层 → 提取能力层 → 提取辅助层 → 编码 → 索引表 → 模板 → 素材表 → 测试用例）。
3. 是否自动产出全套标准化物料（索引/编码/模板/素材/兜底回拉/测试用例），模块边界清晰、不夹带构思层。
4. 生产完成后是否内置逐项自检引擎，输出结构化偏差报告（达标/违规/风险/偏差位置）。
5. 偏差是否自动修正并二次复检，直至核心校验项通过；历史偏差是否沉淀复用。
6. 是否支持版本快照、片段复用，实现 1 到 N 批量生产；标准升级时存量快照不被强制改动。
7. 专家自身是否带兜底询问（需求信息不足时主动收集、补齐后回拉生产主线）。

**输出结论**：**【Skill技能搭建专家本体校验通过 / 不通过 + 缺失子目标说明】**

---

### 校验10：技能质量标准五维出厂质检闸门校验（出厂前硬闸，独立于立项前置9项）

**可量化校验项**（五维须全部达标，递进一票否决）：
1. 流水线出厂默认开启 `auto_quality_check`；打包前自动执行技能质量标准核验。
2. 评测只扫描产物实际内容，不读自报通过标记；探针用例选自固定版本钉死用例库。
3. 严格按 五维递进 顺序核验，前序不达标即终止。
4. 评测结果生成签名报告（包哈希+标准哈希+逐维结论+时间戳），不可静默重生成。
5. 技能质量标准任一维不达标 → 专家默认拦截，不产出成品技能Skill。

**输出结论**：**【技能质量标准出厂质检通过 / 不通过 + 未过维度与原因】**

### 校验11：生产体系自监管与失效兜底校验（防自我放水·防规则失效）

**可量化校验项**（五层护栏须全部配置）：
1. 标准锁哈希启动校验：哈希不符/缺失 → 拒绝启动（起点 fail-closed）。
2. 评测与生产隔离：skill_quality_check 不读自报通过标记；探针用例库生产不可编辑。
3. 步骤不可跳过：9 步拆解每步中间资产可探测，缺则中断。
4. 全节点埋点：编码命中/兜底触发/流程回拉三类事件齐备，零埋点告警。
5. 外部独立复检路径可用：manual_quality_check 独立入口存在，支持外部/陌生账号复跑。
6. 规则失效总兜底：任一闸门 fail/error/未运行 → 默认拦截；每次拦截产出负面清单。

**输出结论**：**【自监管与失效兜底校验通过 / 不通过 + 缺失护栏说明】**

## 6. 第二部分：价值比对评估（4项）

> 前置校验全部通过后，才进入价值比对。比对维度：成本、时间效率、稳定确定性、鲁棒容错兜底。

### 比对维度1：成本比对

计算公式：

```text
用户净收益 = 原有方案成本 − Skill 刚性 Token 成本
```

准入硬性阈值：**净收益 > 0**

判定规则：
1. 净收益趋近于 0，即使流程跑通，判定无开发价值，终止立项。
2. 净收益差额越大，价值优势越强。

**【净收益复核】** 立项阶段用**预估净收益**做初筛；上线首月须以**实测数据**复核，若实测净收益 ≤ 0，启动迭代或下线，不以立项估算值长期背书。

**输出**：原有方案成本、单次 Token 成本（预估/实测）、净收益数值、**【成本比对合格 / 不合格】**。

### 比对维度2：时间效率比对

对比原有方案的时间消耗：包含用户配置时间、学习摸索时间、操作步骤、等待反馈时长。

判定规则：
- 合格：相比原有方案，减少用户总时间投入，引导清晰、反馈快速。
- 不合格：刚性成本很低，但配置繁琐、学习成本极高、等待周期长，用户切换意愿弱。

**输出**：**【效率比对合格 / 不合格 + 时间差说明】**

### 比对维度3：稳定确定性比对

按交付类型分开判定：
- TYPE-A 过程交付：动作可复现、定时触发稳定、无随机失效。
- TYPE-B 结果交付：相同输入，输出质量波动可控，交付标准稳定。

判定规则：今日正常、明日报错、交付波动大 → 稳定性不合格，用户不敢长期使用。

**【量化基线（估算，可按平台调整）】**
- 过程交付型：任务成功率 ≥ 99%，定时触发丢失率 < 1%。
- 结果交付型：相同输入交付一致性 ≥ 95%。
- 低于基线须说明原因并列入整改。

**输出**：**【稳定性比对合格 / 不合格 + 风险描述】**

### 比对维度4：鲁棒容错兜底校验

稳定性=正常场景；容错=外部异常场景，二者独立校验。

校验项：
1. 外部接口超时、限流、返回失败时，有合理重试策略（有上限，无无限重试爆 Token）。
2. 失败后主动通知用户，说明失败原因，而不是静默卡死。
3. 异常场景下，自动停止后续任务，避免持续消耗 Token。

**输出**：**【容错兜底校验通过 / 不通过 + 缺失兜底逻辑说明】**

### 综合比对结论规则

> 成本、效率、稳定确定性、鲁棒容错 **四项全部合格 → 价值比对通过**。  

> 任意一项不合格 → 价值比对不通过，终止立项或重新优化方案。

## 7. 第三部分：开发、测试、上线标准化流程

### 阶段1：方案设计

**输出物**：
- 交互流程图
- 分步引导话术
- 确认节点清单
- 风险告知文案
- 退出撤销入口
- 异常兜底逻辑
- 防呆路由分支话术库
- **高危清单（按领域定义）**
- **数据隐私与版权处理说明**
- **跨平台适配降级说明**

**强制要求**：
- 高风险节点必须植入用户确认交互（仅交互式形态）。
- 概率类结果前置风险提示。
- 三类防呆场景（跑偏纠偏、越界拒绝、高危拦截）全部写进状态机路由。

### 阶段2：开发实现

- 严格按照前面判定的交付类型、比对指标、边界规则配置 Skill 状态机。
- 控制 Token 消耗，精简上下文，持续压低刚性成本。
- 埋点设计：可观测指标埋点。

**【埋点分级】** 在支持埋点的平台（如运行宿主本地技能）启用全量埋点；分发到 Agent 平台（能力受限环境）时，以平台后台数据 + 测试报告 + 用户反馈替代细粒度埋点（防呆触发次数、取消率等），不强制跨平台统一全量埋点。

**埋点采集指标（支持平台全量，不支持平台降级）**：
- 单次任务 Token 消耗
- 任务成功率
- 用户平均操作时长
- 失败类型
- 用户取消率
- 防呆触发次数（纠偏 / 越界拒绝 / 高危拦截）

### 阶段3：开发者全量测试（强制）

**测试覆盖范围**：
- 正向流程
- 分支流程
- 异常输入
- 超时
- 失败重试
- 边界场景
- 用户取消/撤销场景
- 防呆三类输入测试用例

**【付费技能实测】** 付费/计费类技能，上线前须以**未绑定付费账户的陌生环境**实测完整计费链路：下单 → 扣费 → 交付 → 退款/取消，验证金额、交付、对账一致。

**测试输出**：测试报告，记录每一条链路是否畅通、兜底逻辑、防呆路由是否生效。  

**硬性规则**：测试不通过，禁止进入上线评审。

### 阶段4：上线评审

复核全部前置校验 + 比对指标 + 测试报告 + 埋点方案 + 防呆路由；全部达标，允许上线。

### 阶段5：上线后持续迭代监控

**持续监控指标**：
- Token 消耗成本
- 用户操作耗时
- 交付故障率
- 异常失败率
- 防呆触发频次
- 救助触发频次、救助成功率、救助后退出/重置比例

**【版本管理】** 每次上线标注版本号；变更须回归测试；保留历史版本可回滚；多壳/多平台分发须基线一致（如三壳版本对账）。

**规则**：指标偏移低于阈值，启动迭代优化。Agent 输出周期复盘报告，对比立项时比对基线，判断是否继续维护、下线、优化。

## 9. 第五部分：核心总纲与常见错误

### 9.1 核心总纲（Agent 全局记忆锚点）

1. Skill 本质是优化/替代用户已经存在的原有方案，不是凭空创造需求。
2. 先守边界、匹配人群、分清交付类型、做好风险告知、配套用户退出权、搭建防呆意图路由；再做成本、效率、稳定、容错四维比对。
3. 拿到动作/产出结果 ≠ 具备价值；正向净收益、更高效率、稳定交付、异常兜底，四者缺一不可。
4. 分工基线：链路通畅、兜底逻辑、防呆路由由开发者侧落实；高风险决策权保留给用户，由用户确认后执行。
5. 防呆是前置风控：区分“引导回归主线”、“超出能力友好拒绝”、“高危请求强制拦截”，避免对话漂移、无效耗 Token、越界执行。
6. 全程可观测、可复盘，上线后持续比对立项基线，指标退化则迭代或下线。
7. 所有指标可量化、流程串行、条件刚性，不接受主观模糊判定。
8. **开发者与评审者隔离**：同一 Agent 既开发又评审时，须加载独立标准并引入外部复核/陌生实测，防止宽松放行。
9. **平台强制规则优先**：本手册与平台官方强制规则冲突时，以平台规则为准。
10. **数据隐私与版权是第四重红线**：用户内容归属用户、不外传、脱敏、版权清晰。

### 9.2 常见错误清单

| 常见错误 | 正确做法 |
|---|---|
| 把外部接口超时写成防呆 | 归入鲁棒容错，配置重试、通知、止损 |
| TYPE-A 承诺“100%成功” | 必须告知概率收益与外部不可控因素 |
| 高风险节点由 Agent 自动确认 | 必须用户手动确认（仅交互式）；定时自动化须规避 |
| 缺少高危请求拦截 | 必须配置场景C，直接拦截终止并停止后续消耗 |
| 防呆只做跑偏引导 | 必须覆盖跑偏、越界、高危三类 |
| 成本未量化就评审 | 标记缺失资料，暂停评审 |
| 测试不通过仍上线 | 硬性禁止，必须整改后重测 |
| 埋点不含防呆触发统计 | 支持平台须包含；不支持平台以测试+反馈替代 |
| **把估算净收益当长期事实** | 立项初筛用预估，首月实测复核，≤0 则迭代/下线 |
| **定时任务要求手动确认** | 定时自动化禁止含手动确认高风险节点，或拆两段 |
| **忽视用户数据隐私版权** | 第四重边界：归属用户、不外传、脱敏、版权清晰 |
| **同体自审宽松放行** | 开发者≠评审者，同体须外部复核/陌生实测 |
