# 素材版本风险防控与对比评审协商机制（并入标准守门自检体系）

> 定位：本文件是 Skill技能搭建专家「标准守门自检模块」的素材关口专册，覆盖 **事前预防、事中对比评审协商与确认、事后挽救溯源** 三段，专门解决：**高相似度改版材料（大纲/标题一致、核心规则/解法已变更）被浅层判定重复、直接跳过解析、回一句"有了"、新材料完全不入库** 的致命隐患。

> 本册与 REF-QC-020（守门自检模块）、REF-LST-022（上架测试验收）配套使用，三者同一条流水线，互不重复。

## 底层公理（优先级最高，不可突破）

**文本高重合 ≠ 业务等效。** 用户每次独立上传的文件、提交的修改意见、他人提交的评测修改方案，都是独立输入实体；**禁止以标题、章节大纲、全文文本重合度、主题名称作为是否解析、是否接收的判断条件。**

---

## 一、事前预防机制（material_parse 节点前置，根源风控）

### 规则 1：废除相似度拦截逻辑（硬性禁令）

1. 禁止以标题、章节大纲、全文文本重合度、主题名称，作为是否解析、是否接收文件的判断条件；
2. 无论新上传文件和已有素材相似度 99% 还是 1%，只要是用户单独上传的文件，**强制进入完整解析链路，不跳过、不丢弃、不直接回复"有了"**；
3. 相似度比对结果仅用于生成 **【差异摘要提示】**，供用户对照查看，**不参与任何拦截、拒收判断**。

### 规则 2：素材元数据强制登记（机器可读，四标签缺一不可）

每一份素材入库，自动生成以下四项：

- `material_id`：全局唯一素材编号；
- `version_tag`：版本标记（由用户标注，如 2023 教材 / 2026 改版教材 / V2 修订版 / 他人评测修改方案）；
- `status` 三态枚举（互斥）：
  - `active`：当前生效基准。同一技能同一时刻最多仅 1 份 active 基准，是生成、推理、质检的核心采信源；
  - `supplement`：补充素材，仅辅助，不能推翻 active 基准内的规则、流程、解法、判定口径；
  - `archive`：归档封存，**永久移出推理检索池，禁止被调取用于生成回答**，仅用于日志留存、复盘比对、溯源；
- `upload_meta`：上传时间、上传人、文件摘要、差异比对快照、评审结论快照、用户确认记录。

### 规则 3：上传材料自动分类引导

文件解析完成后，先询问用户定性材料类型，二选一：

- **A 类【改版替代型｜高风险】**：本文件废止旧版本核心规则、解法、判定标准，旧版本不再具备使用效力（新版教材、法规修订、平台政策改版、考核标准更新、全新替代方案）；
- **B 类【补充拓展型｜低风险】**：原有基准规则不变，本文件仅增加案例、场景、细节，不推翻原有口径。

> 用户选定 A / B 之后，系统才进入后续处置分支。A 类默认高亮提醒：新旧版本存在核心逻辑变更，混用会造成错误。

## 二、事中对比评审协商机制（核心闭环，阻断认知错位）

> 触发时机：文件解析完成之后，**在进入 draft_build 初稿生成之前，强制暂停流转，等待用户确认，无确认不往下走**。

> 禁止：解析完成自动合并、自动替换、自动归档。素材处置决策权归属用户。

### 2.1 比对评审逻辑（同名同结构也必须执行）

解析完成后，和当前 active 基准素材做深度比对，区分变更类型：**升维迭代 / 降维修改 / 内容补充 / 规则更新 / 局部修正 / 方案替换**。

输出评审结论，明确拆分：

- ✅ **建议纳入基准的内容**：写明纳入理由；
- ❌ **建议不纳入基准的内容**：写明不纳入理由（冲突、逻辑矛盾、与原有核心规则相悖、适用场景不一致等）。

> 即使本次输入与现有基准同名、同结构，也必须走完整比对，并向用户讲清"差在哪里、为什么纳入/不纳入"。用户不认可 Agent 的判断，可提出修改意见，重新进入比对评审循环，直到用户确认方案。

### 2.2 材料分类引导（解析 + 评审完成后，先定性）

展示给用户二选一（同规则 3）：A 类改版替代型 / B 类补充拓展型。用户选定后才进入处置方案选择；A 类自动高亮风险提示。

### 2.3 增强版固定回执模板（强制使用，禁止简化为"有了/收到"）

```
✅ 已完成 **【{文件名称 / 修改方案}】** 全量解析与对比评审，material_id：{material_id}
📑 当前技能生效基准素材：**【{文件名}，version_tag：{version_tag}，material_id：{material_id}】**
📊 对比评审结论：本次输入与现有基准对比，属于 **【升维迭代 / 内容补充 / 规则更新 / 降维修改】**
👉 建议纳入基准内容：
{逐条列出 + 纳入理由}
👉 建议不纳入基准内容：
{逐条列出 + 不纳入理由}
请确认本次素材处置方案：
① 替换基准：以本次评审后方案作为新 active 基准；原有 active 素材自动标记 archive 归档隔离，不再参与推理
② 补充并入：本次文件标记 supplement，原有 active 基准保持不变，仅作为辅助素材
③ 仅备份存档：本次文件 / 方案仅入库归档，本次技能构建完全不采信
若不认可本次评审结论，可直接回复你的修改意见，本工具重新比对评审。
```

### 2.4 用户选择后执行动作

- 选 ①：更新 status，新版 → active，旧版 → archive，写入日志，放行进入 draft_build；
- 选 ②：新版 → supplement，active 不变，写入日志，放行进入 draft_build；
- 选 ③：新版 → archive，active 不变，写入日志，放行进入 draft_build；
- 用户提出异议、要求重新评审：回到比对环节，重新输出评审结论；
- 用户不回复、不确认：停留在 material_parse，不向下流转。

## 三、质检环节·素材采信专项校验（守门模块兜底关卡）

并入 REF-QC-020 标准守门自检清单，作为强制校验项：

- ✅ **校验项 1**：本次构建所采信素材清单，必须和用户最终确认的处置方案一致；用户选择 ① 替换基准，则采信池必须为新版 material_id；
- ✅ **校验项 2**：检索技能输出内容，排查是否调用 status=archive 归档素材内被变更的规则、解法、条款、标准；
- ✅ **校验项 3**：A 类改版替代素材，禁止新旧基准素材同时作为推理依据；
- ✅ **校验项 4**：supplement 补充素材内容，不得覆盖、改写 active 基准里面的核心规则。

> 校验不通过判定 **【严重违规】**，直接阻断交付，输出告警：素材采信异常，存在调用旧版失效规则风险，退回整改。

## 四、全链路日志规范（事实凭证，不可篡改）

每次上传、比对评审、用户异议重审、用户确认、素材状态变更，强制记录以下字段：

1. 上传时间、文件名称、material_id；
2. 新旧素材差异摘要快照、评审结论快照（纳入 / 不纳入清单 + 理由）；
3. 用户选定材料类型（A / B）；
4. 用户选择的处置方案（① / ② / ③）、用户异议记录、二次评审记录；
5. 变更前后 active 素材编号；
6. 操作人员、用户确认原文。

> 日志随构建产物归档，字段固定、不可篡改，用于事故溯源、事实回溯。日志落点见 REF-QC-020 持久化自检报告（`logs/QUALITY_<build>_<时间戳>`）。

## 五、事后挽救与应急处置机制（已出错后的补救闭环）

触发条件：技能对外交付使用后，收到反馈，输出内容和新版基准不符。

### 步骤 1：紧急熔断

1. 立刻下架该技能Skill，暂停对外分发、调用；
2. 锁定当前生效素材清单，导出本次构建全链路日志、素材比对评审记录，快速定位根因：
   - 情形 1：用户当时选择方案 ③ 仅存档，用户自身遗忘；
   - 情形 2：流程故障，未执行替换基准，新版素材未进入采信池；
   - 情形 3：质检漏检，调取归档旧素材内容；
   - 情形 4：用户上架前未充分测试，直接对外投放。

### 步骤 2：纠错修复

1. 核对用户历史上传文件，确认用户真实意图；
2. 重新执行标准确认流程：重新向用户展示新旧差异、再次确认是否替换基准；
3. 用户确认替换后，更新素材 status，旧素材归档，重新跑完整构建 + 质检流水线；
4. 重新交付新版本技能Skill，同步告知之前使用者版本更新内容、历史错误范围。

### 步骤 3：复盘归档

1. 记录故障事件、故障类型、损失范围、触发原因；
2. 若是流程漏洞，同步更新禁令、质检规则、状态机逻辑，同类情形纳入回归测试用例；
3. 形成事件档案，留存备查。

## 七、时效排查三问（素材解析环节前置问询）
素材会随行业规则更新而失效；用户通常不知道要标注版本，若不主动问，失效素材将混入交付并在后续被采信。素材解析完成回执中固定附本时效排查三问问询：
1. 你所属的行业与具体业务是什么？（不同行业随时间变化的内容完全不同：法条法规、会计制度、行业规范、教材课件、诊疗标准、施工规范等）；
2. 你行业里哪些规则、制度、标准或文档会随时间更新？
3. 大致的更新周期是多久？（公司标准、流程、制度等是否在持续更新也一并说明）

处置规矩：
1. 用户答复后按答复对素材标注时效风险，与既有素材采信校验（第三节）衔接；
2. 用户未答复不阻断主链路，相关素材记入待确认清单，交付前二次问询；
3. 拿不准是否仍然有效的资料，一律按「可能失效」处理——宁可标注后慎用，不可不标误用。
