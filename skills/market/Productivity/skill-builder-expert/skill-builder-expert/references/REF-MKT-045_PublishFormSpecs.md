# REF-MKT-045 出包形态规范（基准形态 / 双语两级形态）

> 用途：同一个母版，面向不同上架目标输出两种出包形态。本册只写技术规格，**全程零市场名称**——市场识别只发生在会话层（由用户自己说出市场名），任何市场名、任何"别家市场如何"的表述不进本册、不进对话产物、不进交付物。

> 铁律：无论哪种形态，交付产物内任何分发平台名称零命中（出包闸门 `scripts/deliverable_competitor_scan.py` 独立执行）；本册约束出包结构层，与竞品名闸门两层独立、同时执行。

> 机检：`scripts/publish_form_scan.py`（fail-closed，支持 `--self-test` 阳/阴用例自测）。

## 一、形态判定（会话层执行，产物层零市场名）

1. **基准形态（默认）**：用户未提出特殊上架要求，或选定专用模式（自用版 / 私域版）→ 直接按基准形态出包，零适配、零追加追问。绝大多数场景走这一条，链路一步不增。
2. **双语两级形态（形态B）**：用户明说要上架的目标市场具备以下任一特征时启用——
   - frontmatter 必须含**英文展示名、英文简介、作者**三个字段；
   - 压缩包仅支持「根目录 / 一级子目录 / 文件」，且 **SKILL.md 必须位于压缩包根目录**（不得有外层总文件夹包裹）；
   - **压缩包体积上限更严**：该市场上限以官方要求为准（其余市场以官方要求为准，一切以官方最新公告为准）。
3. **判定依据优先级**：用户提交的该市场官方上架规范文档 ＞ 用户对两项特征问询的口头确认 ＞ 运行环境对主流市场的通行认知。拿不准时问两句（不提任何市场名）：
   - 「你要上架的市场，是否要求包内必填英文展示名和英文简介？」
   - 「是否要求说明文件放在压缩包第一层、子目录只能有一层？」
   - 「该市场对压缩包体积是否有更严上限（比如 3MB）？」

   用户答「是」→ 走形态B；答「否 / 不清楚」→ 默认基准形态，并提示可提交官方文档再校准。
4. **文档校准可选，永不卡死**：用户拿得到官方规范文档则提交核对，有差异以文档为准、出差异清单；拿不到则给通用指引（该市场开发者中心 / 上架规范页可查），**不得因缺文档阻断出包**——先按已判形态出包，文档后到再核对补差，走既有迭代升级路径。

## 二、形态B出包变换（程序化四步，母版一字不动）

1. **去外层包裹**：SKILL.md 与全部一级内容直接置于压缩包根目录，消除外层总文件夹；
2. **拍平二级子目录**：templates/ 下的分档子目录取消，模板文件带档位后缀平铺（如 `SKILL-template-heavy.md`），并同步改写包内全部文本中的对应路径串；
3. **字段补齐**：frontmatter 英文展示名 / 英文简介 / 作者三字段齐备且非空（基准形态已具备的沿用，缺失的先补后出）；
4. **重打包并跑自检闸**，全过才出 zip。

## 三、出包自检闸（基准形态查①②⑤⑥⑦⑧⑨⑩⑪⑫⑬⑭，形态B加查③④⑧）

> **危害分级原则（分级定处置强度，分级依据为真实审核周期）**：上架卡点分两级——

> **甲类·解析期拦截**：提交时机器解析即报错（如 name 命名不合纪律、目录层级超限），用户当场看到、当场可改，不占用审核周期，代价低；

> **乙类·审核期驳回**：解析通过后进入人工审核（常见三到七天一轮）才被驳回，整改后再审又是三到七天，一个技能从首次提交到上线可能拖到十几天——**乙类必须零容忍前置消灭**，绝不允许依赖「驳回后整改」兜底。

> 本闸十四查中，①②③④⑤⑧⑨⑩⑫⑬⑭属甲类防线（结构层、体量层、描述层与检索适配层，解析期暴露），**⑥⑦⑪属乙类防线**（清单字段中性化、宿主工作区路径零落盘、名称写法不一致——此类残留只在人工审核中被发现，一旦漏出即浪费整轮审核周期）。乙类防线执行标准：出包前必过、不过必阻断、阻断即修复，禁止带病出包。

1. **命名纪律**：技能标识 name / slug 仅允许小写字母、数字、连字符、下划线，且必须以字母或数字开头和结尾；**分市场差异化**——同一技能上架多个市场时，name 按目标市场要求差异化（定稿依据 2026-11-04 实测：同一生态的两个市场各自独立审 name，撞名无法过审；基准 name 主站通用；同生态宿主开放市场专用 name 由形态B变换自动改写，专用 name 字面只在变换逻辑与分市场包内存在、基准包内零落盘，中文名称不受影响，能力不变，其他生态开放市场可同名）；**名称全包一致**——英文名与中文名在包内所有文件（frontmatter、元数据、清单、文档、脚本、示例）只允许一种写法：英文名全包唯一不得两名交叉残留（完整名与词根级同查），中文名一律全称（六字核心前恰为大写 Skill 前缀，禁空格变体、禁缺前缀写法）；**英文名称字段逐词对应**——display_name_en 规范化后必须等于 name，category／tags／标签词根跟随本包英文名；**压缩包文件名一致**——压缩包文件名必须以包内英文 name 开头（后接版本/批次标识），由出包脚本自动生成与校验，禁止手取他名；
2. **基线字段**：frontmatter 基线字段（name / display_name / description / description_zh / version）齐备非空；
3. **根位检查**（形态B）：SKILL.md 位于压缩包根目录，无外层总文件夹；
4. **层级检查**（形态B）：任意文件路径中目录层数 ≤1，禁止任何二级子目录嵌套；
5. **英文三字段**（形态B）：display_name_en / description_en / author 齐备非空；
6. **清单字段中性化**（全形态）：tools.json 等一切清单/配置文件的 package、name、display 类字段零「市场名+版」自我发行标注、零站外获取指引——宿主注入残留曾致人工审核驳回（定稿依据），细则见 REF-DLV-029 宿主残留防治；
7. **宿主工作区路径零落盘**（全形态）：全部文本文件（含注释）零「点 + 宿主记忆目录名」路径形态；打包排除工作区记忆目录、日志目录与宿主隐藏配置目录；
8. **出包体积上限**（全形态）：两级目录市场压缩包 ≤3MB，其余市场 ≤10MB（各市场上架要求实测，定稿依据；规则变化时以官方最新公告为准更新本条）；自检按**未压缩总量保守校验**——实际 zip 因压缩只会更小，宁严勿漏；基准形态按出包口径（排除内部机件）统计未压缩总量，形态B按变换后 staging 总量与实际 zip 双查。
9. **描述长度校验**（分市场）：各市场中文描述（description / description_zh）按其官方要求核验（目录市场上传解析实测硬校验，定稿依据 2026-11-04：超限直接「解析失败」拒绝入库），英文描述 ≤1000 字符；**无限制市场（基准形态）** 实测无字数限制（在架竞品实测 1004 字描述过审），基准上限设 2000 字防呆；描述是检索与转化的门面——两市场两套打法：无限制市场铺「检索用词」全量段（见第14条），有限制市场用高密度正文（词即句子，功能全保留、语义不缩水，触发词表优先保留），机检第⑨查按形态取档。
10. **版本纪律**（全形态）：整包版本声明必须一致——SKILL.md frontmatter version、_meta.json version、LISTING.md 版本行三处同值；**平台上架版本字段必须纯 SemVer 2.0.0 三段数字**（如 1.0.0，禁一切前缀——定稿依据 2026-11-04 平台解析实测截图：带 V 前缀即报「版本号格式不合法，请使用 SemVer 2.0.0 格式」，甲类·解析期拦截）；版本号**只升不降**（例：当前 1.2.0 时下一版取 1.2.1 或 2.0.0 合规，取 1.1.x 这类更小号则无法上架）；**两轨并行**——产品语义版本号（大写V前缀口径，起始 V1.0.0，定稿见 REF-BSE-047 §九第4条）保留为内部与组件层命名，与平台上架字段按剥前缀换算对照；机检第⑩查核纯 SemVer 格式＋一致性，单调性对照内部机件 `_build_seq.json` 的 `released_version`（随发布回填，永不入包）。
11. **名称全包一致性**（全形态）：英文名与中文名全包唯一——基准包内零分市场专用 name 完整字面与词根、形态B包内经全文归一后零基准 name 完整字面与词根（完整名与词根级双向核验：frontmatter、元数据、清单、安装说明、权属文档、状态机、随包脚本与示例均同查；**衍生英文标识同查**——display_name_en、category、tags/标签的词根必须跟随本包英文名，name 改了标识字段还挂旧词根同样驳回）；中文名称凡出现必须全称（六字核心前恰为大写 Skill 前缀，禁空格变体、禁缺前缀写法）；**display_name_en 与 name 逐词对应**（规范化后必须相等，英文名称字段与包内英文名不一致直接驳回）；压缩包文件名必须以包内英文 name 开头（出包闸自动校验，缺省自动按 name 命名）；机检第⑪查双向核验，fail-closed。

任一项不过 → **阻断出包**，输出不合格项清单，禁止带病出包。

## 四、机检与构建入口

- `python scripts/publish_form_scan.py <包目录>`：基准形态自检（命名纪律＋基线字段＋描述长度＋宿主残留防治＋名称全包一致性＋体积上限）；
- `python scripts/publish_form_scan.py <包目录> --form b --out <zip路径>`：执行形态B变换＋全项自检＋出包；
- `python scripts/publish_form_scan.py --self-test`：阳/阴用例自测。
- `python scripts/base_block_scan.py <成品包目录或SKILL.md路径>`：标准化交付底座锚点块完整性块内五查（锚点/身份基线/九节/十项自检/质检把关项五维）＋真源文件级收尾边界（真源 REF-BSE-047 定稿入库版），代建封装与存量改造挂载后必跑。
- 解析背书：基准形态包与形态B包均已通过目标市场解析进入审核；形态B两条结构红线（外层包裹、二级子目录嵌套）为另一市场解析失败报错原文反推，已程序化治理。

## 五、已知上架卡点处置清单（标准修法，修复链路唯一对照表）

> **定位**：用户回传上架驳回意见或报错原文时，技能优化调整链路**先对照本清单**——命中已知卡点按标准修法执行，未命中按通用排查处理，处置完成后**必须重跑本册 §三自检闸全部查项**再重新出包。新卡点处置经验按下表格式增补，处置知识持续沉淀，不依赖个人记忆。

**处置总流程**：回传驳回原文 → 对照映射 → 按标准修法修改 → 重跑自检闸（全查项）→ 重新出包交付。

| 条目 | 卡点现象 | 危害级别 | 标准修法 | 修后验证 |
|---|---|---|---|---|
| P1 | 提交即报「技能标识命名不合纪律」（name 仅允许小写字母/数字/连字符/下划线且首尾为字母或数字） | 甲类·解析期 | 修改 frontmatter name 与 slug 为合规形态；全包该标识出现处同步改名 | 重跑自检闸命名查项 |
| P2 | 提交即报「目录层级超限 / 仅支持两级目录结构」 | 甲类·解析期 | 去外层总文件夹包裹；拍平二级子目录（references/scripts/templates 下禁止再建子目录）；同步改写 SKILL.md 内全部路径指向 | `publish_form_scan.py --form b` 全项自检 |
| P3 | 人工审核驳回「清单字段自我发行标注，将用户引至站外平台」（tools.json 等清单的 package/name/display 字段出现「某市场名+版」形态） | 乙类·审核期 | 字段值一律中性化；删除全部「市场名+版」标注与站外获取指引表述；描述类字段同步检查 | 重跑自检闸第⑥查（清单字段中性化） |
| P4 | 人工审核驳回「打包脚本中使用宿主平台工作区路径」（脚本文档含注释出现「点+宿主记忆目录名」路径形态） | 乙类·审核期 | 删除该路径字面；需要定位用户环境时改参数传入或标准相对路径；**注释同查**；打包脚本写死排除宿主记忆目录 | 重跑自检闸第⑦查（宿主路径零落盘）＋竞品名出包闸 |

| P6 | 上传解析报「Skill 中文描述超限 / 英文描述超限」（按目标市场官方口径核验；样例超限条目 / 2989 字符被拒） | 甲类·解析期 | 三处描述字段（description / description_zh / description_en）压缩重写至限内：功能点全保留、语义不缩水，触发词表优先保留；一处真相全形态共用，不搞两套描述 | 重跑自检闸第⑨查（描述长度，按形态取档） |
| P7 | 提交报「版本号低于已有版本」「整包版本不一致」，或解析报「版本号格式不合法，请使用 SemVer 2.0.0 格式」（定稿依据 2026-11-04 实测：V 前缀被平台解析拒绝） | 甲类·解析期 | 全包版本声明统一为一个值且高于历史已发布版本（只升不降），格式纯 SemVer 2.0.0 三段数字（如 1.0.0，禁 V 前缀）；SKILL.md frontmatter version、_meta.json version、LISTING.md 版本行三处同步同值 | 重跑自检闸第⑩查（版本纪律：纯 SemVer 格式＋一致＋单调） |

> **增补纪律**：每次真实驳回处置完成后，把新条目按上表五列格式增补进本清单并写入维护备案；同一卡点第二次出现视为前置防线失效，回查 §三对应查项为何没拦住并修闸。

12. **描述四段一致性**（全形态，观察项2修复）：SKILL.md frontmatter 四段描述（summary / description / description_zh / description_en）与 _meta.json 必须逐字同文——多数平台读 frontmatter，若某平台改读 _meta.json，缺段或不同文会导致多语言与预览摘要降级。出包时自动从 SKILL.md 反向同步四段到 _meta.json（内存层，源文件不动）；机检第⑫查 fail-closed（缺段或不同文即拒绝出包），源文件侧须同步修平。SKILL.md 缺某段则跳过该段（通用性）。
13. **质检留痕时序**（观察项1修复，定稿依据同上）：出包自动留痕（质量编排全闸报告）前置到打包之前执行——报告反映本次出包内容，且此刻内部构建计数器仍在源目录，报告可携带真实构建号归档；质量编排读不到构建计数器时（质检方在解压包上跑的场景）兜底取 version 字段作归档键（报告文件名自带时间戳，两者联合可定位），不再恒为空值。

14. **检索适配**（⑭）：tags 与 description 按目标市场要求逐项核验，超限按工程规则拦截出包，fail-closed。
## 六、改名规程（任何包改名/重命名，一律机器执行，禁止手工逐处改）

> **为什么必须有本规程（定稿依据 2026-11-04 两次工程教训）**：改名从来不是改一个 name 字段——一个技能的名称是一个「名称族」。只改族内一个成员、其余成员还挂旧值，平台按「名称写法不一致」直接驳回；每被驳回一轮就是三到七天审核周期，用户为同一个名字改十次二十次，时间与信任成本不可承受。故固化：**改名动作只允许走机器全族改写＋复检，人不手工逐处改。**

1. **名称族清单（改名=全族同步，缺一即驳回）**：name / slug（frontmatter 与 _meta.json 双处）；display_name 与 displayName 双写（必须同值）；display_name_en（与 name 逐词对应）；category（skill- 前缀形态时词根必须与本包英文名同族）；keywords / tags 中与本包英文名同族的词条；LISTING 清单 name/slug 行；包内顶层目录名（与 name 同名时同步改名）；压缩包文件名（= 包内英文 name + 批次标识，出包闸自动校验）。
2. **派生规则（新值全部由新英文名机器生成，人不填字段）**：display_name_en = 新英文名各词首字母大写、空格连接；category（skill- 前缀形态）= skill- + 新英文名中间词根；同族词根词条 = 旧词根形态替换为新词根形态。
3. **执行链路**：`python scripts/rename_skill.py <包目录> --new-name <新英文名> [--new-display <新中文名>]`；先 `--dry-run` 预览改写计划，确认后实改；脚本自动完成全族改写＋包内目录改名＋复检（旧名完整字面与旧词根裸字面零残留、标识字段同族、双写同值），复检不过即 FAIL 禁止出包。
4. **复检衔接**：改完必跑自检闸第⑪查（名称族一致性）＋全套机检，再重新出包（压缩包文件名自动按新 name 生成）。
5. **版本纪律**：改名也是迭代，版本号必须递增（⑩查），三处声明同步。
6. **触发口径**：用户任何「改名 / 重命名 / 换英文名 / 换中文名 / 名称不一致整改」诉求，一律路由到本规程执行，禁止在会话中手工逐处改文档字段。
