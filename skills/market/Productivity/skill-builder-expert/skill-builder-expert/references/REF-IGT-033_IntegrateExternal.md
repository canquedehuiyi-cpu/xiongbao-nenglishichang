# REF-IGT-033_IntegrateExternal ｜用户自有素材技能重构规范（闭环4③）

> 适用状态：`role_4_integrate`（状态机 REF-SM-004）。定位：接收用户提供的技能包（用户自有开发 / 第三方获取 / 各类样例素材），按用户提出的业务规则做整合改造，产出属于用户自己的标准化技能包。

> 朴素原则：**业务诉求、业务规则全部由用户定义提出；本工具负责工程落地执行。** 禁止代定业务目标、禁止脑补业务规则。

## 一、接收校验（输入合法性）

1. 待整合技能包：压缩包或文件夹均可，先做完整性与结构校验（能否解包、目录结构可读、关键文件存在）；校验失败走 `illegal_input` 兜底，给明确引导，不凭空编造业务内容。
2. 业务规则：必须收到用户显式提出的整合规则（改哪些、留哪些、达到什么结构目标）；规则未确认前不启动解析改造（状态机 `integrate_rules_confirmed` 门槛）。
3. 咨询类需求无强制文件输入；整合类需求两样输入缺一不可。

## 二、整合原则（工程层四条）

1. **外来包只做工程层处理**：结构分析、组件抽取、逻辑合并、标准对齐（内核四卡 / 统一输出基线 / 交互闭环铁则全量套用）；知识产权与版权风险由用户自行确认负责（见 REF-HON-017 第五节）。
2. **外来包内容当素材走统一关口**：解析结果进 `material_parse_gate` 做 A/B 分类（纳入 / 不纳入清单及理由），与用户既有基准深度比对，禁止静默替换。
3. **产物零豁免**：整合改造产出的技能包与代建产物同标准——六查机检、代码安全第七闸、技能质量标准五维、验收证据四件套全部跑齐，任一不过不得交付。
4. **溯源标注纪律**：产物文档不得出现外来项目名、原始平台名等第三方专有名词（平台无关化改写）；用户业务内容不可改，格式结构必须对齐标准底座。

## 三、交互与流转约束

1. 进入方式仅两条：用户直接点名整合改造诉求（`intent == role_integrate`），或评测完成后用户显式确认（`user_confirm_integrate`）；禁止自动流转。
2. 流转路径与角色3一致：`integrate_rules_confirmed → material_parse_gate → select_config → run_business_logic → deliver_preview → finish_return_menu`。
3. 交付口径：整合改造产物附带变更清单（吸收了什么、放弃了什么、为什么）+ 全套质检报告 + 自测指引。

## 四、出厂必查

- 状态机 `role_4_integrate` 节点存在、模板绑定 **【重构需求确认模板】** 有效、连通至终态（回归引擎自动核）；
- 本规范册在 SKILL.md §15 索引登记；
- 整合产物交付前：禁词 0、红线 0、第六章机检全绿。
