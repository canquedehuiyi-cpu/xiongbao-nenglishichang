# REF-HON-017_HonestBoundary

> 本规范专治"假承诺分数"——明确力气该往哪儿使、到哪儿收手。是链路4 评测输出的口径约束。

## 一、飞轮闭环（判据 E-06 / G-08）
```
能力闭环（给确定性）
   ↓  用户用完真拿到东西
用户留下来（留客）
   ↓  调用量／使用量在涨
平台给推荐位
   ↓  更多人被看见
更多人用上 ────↺ 回到起点，转得更快
```
- 平台愿意推你，是因为你的技能给用户带来了确定性和稳定性；用户在同一个需求上反复用、每次都拿到差不多的结果 ⇒ 平台用户体验数据在涨 ⇒ 平台得利。
- 你和平台是利益共同体，不是甲乙方；把能力做扎实并给出一致结果，平台的推荐是自然回报，不是赏赐。
- 这解释了为什么"抬站内数据"是主攻：它不是刷数据，是把能力兑现成使用量。

## 二、三重大山（判据 K-18 / G-09）
排在最前面的三类本工具动不了：
| | 谁 | 是什么 |
|---|---|---|
| 第一座 | 平台自己做的技能 | 同一个平台自家的技能排在前面——没办法 |
| 第二座 | 行业大厂技能 | 综合类大厂一般也排在前面——没办法 |
| 第三座 | 垂直头部专业工具 | 专门做一件事的那种——没办法 |

本工具属第四类，跟成千上万对手一起被检索。**唯一能赌的只有一件：用户带着他的问题来搜时，本工具能出现在结果里。**

## 三、可控 / 不可控两栏（不承诺、不追、不当验收指标）
| 可控（本工具的活，做到位） | 不可控（平台的决定，认了） |
|---|---|
| 能力是否闭环 · 三维词铺没铺满 · 长尾够不够长 · 两套词齐不齐 | 排第几位 · 要不要被推荐 · 他选不选本工具 |

- 态度：把能做的做到位，其余明确交给平台——无能为力的事不耗力气。
- 反过来也成立：别把不可控的当可控去追（团队会被耗在改不动的数字上），也别把可控的混在不可控里一起放弃（那真正该做的也没做了）。

## 四、对评测输出的约束
- 评测报告只承诺"达不达标"（技能质量标准 最低准入），不承诺排名、推荐、转化。
- 凡涉及"付费意愿 / 转化率 / 市场规模"等不可控项，在 L3 陌生号真付跑通前一律标"推断，待验证"，不得当结论输出。

## 五、用户自有素材技能重构的权属边界（闭环4③）
- 本工具对外来技能包（用户自有 / 第三方获取 / 各类样例素材）只做**工程层面的分析、抽取与改造落地**，不代做权利审查。
- 外来素材的知识产权、授权范围、能否商用改造，由用户自行确认负责；用户发起整合改造请求即视为其已确认对相应素材的处置权利。
- 改造产物按平台无关化纪律清洗第三方专有名词（详见 REF-IGT-033），但清洗不改变素材权利归属，不构成权利担保。
- 交付时随附版权边界提示一行，不渲染风险、不隐瞒边界。

## 六、两条不可动摇边界（整合稿定稿 · 全链路最高边界，README 对外说明同步）
> 两条边界高于本包任何单册条款，冲突时以本节为准。

1. ✅ **我方必须做到（边界一 · 最低硬性底线）**：基于用户提交的素材，严格执行本工具全部标准，交付标准化、安全、可检验的技能工程产物。**这是最低硬性底线**——无论自用、团队企业内部不公开使用，还是对外开源，无论版本类型、部署形态、分发访问模式如何选择，一律不降。
2. ⚠️ **我方无法承诺（边界二 · 用户侧掌握）**：**不保证最终业务效果。** 用户原始素材质量、真实业务逻辑、实际运行应用场景，由用户侧掌握，不在本工具可控范围。

使用规则：
- 两条边界写入 README 对外说明，并作为系统约束生效；
- 任何交付话术、评测报告、修复方案、整合改造方案，不得与两条边界冲突；
- 与第三节「可控 / 不可控两栏」配套理解：边界一是承诺的下限，边界二是不承诺的上限；
- 与用户沟通时按 REF-STD-032 表达层规则自然讲清，不渲染风险、不隐瞒边界。
