# 生产体系自监管与失效兜底规范（防自我放水 · 防规则失效）

> **问题根源（三线合一）**：本体系里，**立法**（写标准）、**生产**（产技能）、**评测**（按技能质量标准判达标）由同一套专家完成。没有任何外部制衡时，存在两类结构性风险：

> ① **自我放水**：自己写规则、自己产、自己评，体系可能悄悄把评测尺子放宽松，让不过关的包"轻松过去"；

> ② **规则失效**：哪怕主观想守规矩，规则也可能在运行时没生效、被绕过、被瞎执行——而本工具以为它执行了。

> 本规范是应对这两类的**全局护栏**，必须随标准一同落地，不可省略。

## 一、五层护栏（L1–L5）

- **L1 · 标准锁不可篡改**：标准（标准手册 + 技能质量标准）作为只读锁。专家启动先算锁文件哈希，哈希不符或缺失 → **起点 fail-closed，拒绝启动**。技能质量标准阈值固化在基线文档，生产运行无权改阈值；想"过"只能改产物，不能改尺子。
- **L2 · 评测与生产物理隔离**：`skill_quality_check` 只扫描**产物包的实际文件内容**（frontmatter、路由索引、FALLBACK 模板、测试用例实跑输出），**不读专家自报的"我通过了"标记**。评测探针用例选自固定、版本钉死、生产运行不可编辑的探针用例库，不是专家为某个技能现编的。评测结果生成**签名报告**（包哈希 + 标准哈希 + 逐维结论 + 时间戳），报告不可被生产静默重生成"通过版"。
- **L3 · 步骤不可跳过 + 偏离即拦**：9 步拆解每步产出可探测中间资产（索引表/编码/模板/素材表），下一步开始前校验上一步资产存在，缺则中断。自检引擎对实际产物 vs 标准期望结构做偏离度检测，超阈值进修正闭环，不静默放行。
- **L4 · 全节点可观测埋点**：每个节点埋"编码命中 / 兜底触发 / 流程回拉"三类事件。应触发却零埋点 = 专家脱稿信号，触发即告警，不触发视为异常。
- **L5 · 外部独立复检（自我放水的终极防线，必要非充分）**：诚实承认——三线合一的体系，内部 技能质量标准防的是无意识偏差，防不住有意的自我放水。真正确认"没自我放水"只能靠体系外的人/账号：`manual_quality_check` 模式让不同人 / 独立 Agent 跑同一 `skill_quality_check`；最终由包属方用陌生账号真跑一次做第三方终验。架构任务：把 `skill_quality_check` 做成独立、可签名、可外部复跑的工具，让外部验证成本低、可信度高。

## 二、规则失效总兜底

- 任一闸门（标准锁哈希 / 步骤校验 / 技能质量标准核验 / 签名）返回 **fail OR error OR 未运行** → 一律视为不通过，专家**默认拦截，不产出 zip**。
- 增设"体系健康自检"：专家每次运行先自检五道闸门脚本是否齐全、可运行；脚本缺失即停。
- 每次拦截必须产出可读的**拒绝原因清单（负面清单）**，不许静默；拒绝原因随包归档，供包属方复核。
- 质量姿态：专家按平台评测要求内置工程措施（前置约束 + 三级兜底 + 主线回拉 + 出厂技能质量标准核验）以压低异常概率，并明确区分「工程可控」与「平台评分不可控」；最终评分权在平台，本专家不作任何评分或评级承诺。

## 三、自动化落点

- 标准锁哈希启动校验：`scripts/` 内闸门脚本在打包前先校验标准锁文件存在与可读。
- 评测隔离 + 签名：`scripts/skill_quality_check.py`（不读自报标记，结果签名留痕）。
- 步骤不可跳过：专家拆解引擎每步产出可探测中间资产（见 SKILL.md §四）。
- 外部复检入口：`manual_quality_check=true` 时，`skill_quality_check.py <任意包目录>` 可被任何独立 Agent / 陌生账号调用。
