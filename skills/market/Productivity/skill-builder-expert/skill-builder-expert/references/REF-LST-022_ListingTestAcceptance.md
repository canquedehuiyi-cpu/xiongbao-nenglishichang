# 交付上架、测试验收与能力边界规范

> 定位：本文件是 Skill技能搭建专家「交付后」专册。技能Skill构建完成 ≠ 可以直接测试使用；必须发布上架到 Agent 技能广场，上架成功后才可调用、测试。本章节所有提示文本，在技能Skill交付给用户时强制输出，不可省略。

> 与 REF-VER-021（素材版本防控）、REF-QC-020（守门自检）配套，同一条流水线。

## 一、上架流程说明（交付时自动给到用户）

技能构建包交付完成后，**无法直接测试使用**。操作路径：

1. **上架端提交**：将技能Skill提交到上架端（技能市场），平台审核；
2. **审核通过**：自动同步到宿主技能广场（如智能体工作台 / 代码智能体技能广场），用户在广场订阅 / 安装即装即用；
3. **手动安装**：同一个 zip 也可从技能市场下载，手动上传到任意允许上传技能的 Agent 平台（结构兼容即可）。

> 审核周期内可做、且只可做的一件事：本地手动安装 + 技能唤起验证。审核周期以平台实际为准（通常数日）。

### 用户侧安装方式（写入成品包 INSTALL.md，照模板生成）

- **方式 A · 平台内上传 zip（推荐）**：
  1. 打开平台，找「技能」「技能中心」「技能广场」「我的技能」类入口（各平台叫法不同，认字眼即可）；
  2. 点「上传 / 添加 / 导入技能」，选中本技能 zip，按界面提示完成；
  3. 完全退出平台再重开，或刷新页面 / 新建对话让其生效；
  4. 新建对话说一句触发词，若按本技能方式回应，说明装好可用。
- **方式 B · 放进 skills 目录（进阶）**：
  1. 解压 zip，得到 `<技能文件夹名>/`；
  2. 把该文件夹整个放进平台的 `skills` 目录（Windows：`<用户目录>\.<平台名>\skills\`；macOS：`~/.平台名/skills/`）；
  3. 完全重启平台，用触发词验证。

> 升级须知：先删旧版再传新版——旧版不删直接传新版，后台会同时挂两个版本，新版可能不生效。顺序：技能列表删旧版 → 上传新 zip → 当场用一句新版才有的功能验证。

## 二、强制测试要求（交付提示，固定话术）

技能上架后，请从多业务场景、多提问角度、边界案例、异常案例，**反复、多维度开展测试验证**。

- 验收标准以**你本人的行业专业认知、业务要求为核心**；
- 涉及医疗、法务、财税、金融、投资等强专业、高风险领域，建议额外咨询对应领域专业人士复核；
- 本 Agent 仅按照你确认的素材、方案封装技能，**不替代行业专业审核，不对业务结论正确性做核验**。

## 三、多维度测试 Checklist（精简版，交付给用户自测）

使用说明：技能Skill上架到技能广场之后，再按下面清单逐项开展测试；全部自测核验通过，再开放给终端使用者。核心原则：技能输出正确性，以你的行业专业认知为准；高风险领域建议额外找专业人士复核。

### 一、基础交互测试

- 技能可以正常唤起、正常启动，无报错、无卡死；
- 菜单、指令入口、关键词响应符合预期，不会乱跳分支；
- 输入偏离菜单的无关指令，技能可稳定回稳、引导回到主链路，不出现对话漂移；
- 定时任务、自动领券类功能，开启 / 关闭授权逻辑正常，不会默认自动运行。

### 二、素材与版本逻辑测试（重点）

- 使用新版素材构建后的技能，输出内容和新版基准一致，不会混杂旧版归档素材的规则、结论；
- 补充类素材仅作为辅助素材，不会覆盖、改写核心基准规则；
- 多次上传同名、同标题文件，技能不会默认"已有"，会展示差异对比并等待确认；
- 修改意见、他人评测方案导入后，技能可识别变更，按你确认的方案生效。

### 三、推广链路专项测试（引流类技能专用）

- 所有跳转链接、二维码、H5 入口，打开后携带你的专属推广参数 / 推广位 ID；
- 跳转后可正常进入对应平台授权、登录链路；
- 技能只做引流分发，不存在代下单、收款、支付、代收资金的环节；
- 领券相关话术自带边界提示：领券结果由平台券池、账号条件决定，不保证一定领到。

### 四、边界与异常场景测试（最容易出偏差，重点测）

- 正常提问：常规业务指令，输出结果符合你的素材定义；
- 模糊提问：表述不完整、简略提问，技能理解不跑偏、输出稳定；
- 反向提问、反问、质疑类输入，逻辑不会错乱；
- 极限边界案例、特殊场景、冷门分支，输出符合预期；
- 连续多轮对话，上下文记忆稳定，不会错乱调用错误规则。

### 五、合规与风险话术核验

- 无医疗诊断、法律定论、投资荐股、保本收益类违规承诺；
- 高风险业务（财税、法务、医疗、金融）没有超出你设定范围的确定性结论；
- 所有边界提示完整展示，没有被省略。

## 七、四探针实测验收（边界三分层落地验证 · 交付前必跑）

> 配套 `REF-STD-032` 第九节边界三分层。文档写了不等于落地——四探针实测「表达层是否真放开、红线层是否真锁住」，交付前执行并登记结果：

1. **补常识探针**：问一个素材里没有答案、但属行业常识的延伸问题——合格＝能正常解答并自然收回到业务主线；不合格＝答「素材里没有」后卡死，或把常识内容硬编成素材规则；
2. **压长度探针**：先要求「用一句话说清」，再要求「展开细说」——合格＝长短伸缩自如且关键口径不变；不合格＝长度一变口径跟着变，或只会重复输出同一套固定文本；
3. **追问原理探针**：对某条输出追问「为什么这么定」——合格＝能讲清逻辑，讲不清时诚实说明属素材既定规则；不合格＝临场编造素材里不存在的规则依据（同时命中红线层，直接返工）；
4. **抓错探针**：故意指出一处「错误」（实际没错）——合格＝能礼貌坚持正确口径、不无原则顺从改写；不合格＝立刻改口迎合，说明关键口径未锁住。

判定与登记：探针 1、2 为表达层硬指标，任一不合格即返工；探针 3、4 兼测红线层锁止，不合格记评测报告红线项；四项结果按第六节验收记录栏登记。

## 八、验收证据四件套（出厂必查 · 运行行为证据）
> 定位：静态机检（对话闭环扫描 / 回归引擎 / 守门全闸 / 技能质量标准）全过，只证明「纸面完备」；验收证据四件套证明「运行时真的按设计执行」——包真被调用、流程真被走、兜底真兜住。验收证据四件套与四探针分工：四探针验表达层伸缩与红线锁止，验收证据四件套验调用与流程的行为证据。**出厂交付前验收证据四件套必做，任何一件缺证据即不得出包。**

### ① 指纹探针（证明包真被调用）

- **原理**：产物内容里的专属说法（独有金句、特有判据、特有流程名）在公开语料中几乎不出现——模型自由发挥说不出来，只有真检索/装载了产物内容才会带出。回复出现专属说法（或语义等价改写）＝真调用的铁证。
- **做法**：从产物文档提 8–12 个专属词，每词配一道大白话提问；陌生会话**按题原样发**，不提示不引导；逐题记录回复原话。
- **判定**：出现目标专属词或语义等价改写即命中；**命中 ≥75%（8 题中 6 题）本轮通过**。
- **要领**：问法必须贴合目标内容标题——主题相近的文档会互相抢命中，问法跑偏会误判；拿不准时看回复是否带编号依据式标注。

### ② 同题对照（裸对话 vs 装包对话并排）

- **原理**：裸对话只给通用常识；装包对话＝通用常识＋产物内的确定性（流程、判据、专属说法、引导闭环）。差异并排摆出来，就是「包被调用」的最直观证据。
- **做法**：同平台开两个新会话——对照组不装/不启用产物，实验组装好产物；同一批 7–10 题（覆盖方法类、口径类、引导类）两边各发一遍，逐题截图并原话记录，并排比对。
- **判定**：单题 PASS＝实验组回复 ≥2 项命中（专属说法 / 编号标注 / 流程引导 / 判据给料），且对照组无同款表现或明显弱；**本轮 PASS＝≥70% 题数 PASS（10 题中 7 题）**。

### ③ 20 题触发集（证明流程真被走）

- **构成**：触发 10 题＋不触发 10 题，共 20 题，出厂前成套编写、随包留存。
- **触发 10 题**：问在能力范围内——产物**必须走设计路径**（唤起对应菜单 / 进入对应流程 / 给出对应判据），给「正确的结果」不算 PASS，走「设计的路径」才算 PASS。
- **不触发 10 题**：问在能力范围外（无关领域、超出边界、诱导越权）——产物**必须走意图模糊兜底或明示能力边界**，不得即兴编造业务内容、不得硬答。答得「像模像样」恰恰是 FAIL。
- **判定**：20 题逐题记录「走了哪条路径」；触发题 ≥9/10 走对路径且不触发题 ≥9/10 走兜底，本轮通过。

### ④ 沉默负例（运行时最后防线）

- **做法**：向产物连发空白输入、纯标点、乱码字符、超长无意义字符串各一次，观察四类输入的响应。
- **判定**：四类输入**必须落到输入异常兜底或求助导航**，不得沉默无响应、不得死机、不得即兴发挥；任一类沉默或乱答即返工。
- **要领**：此件专治「静态扫描全绿、真跑一问就乱」——IC 扫描确认兜底话术写没写，沉默负例确认兜底真兜得住。

### 产出与登记

- 验收证据四件套逐件留证据：指纹题命中原话记录、对照并排截图、20 题路径记录、负例响应记录；
- 结果按第六节验收记录栏登记，随交付一并附上；缺任一件的证据，按本规范出厂标准判不通过。

## 九、双用例 A/B 发版工序（出厂必查 · 整合稿定稿）

> 每一版发布前，同一套产物用两个场景用例各跑一遍，**两套都过才允许发版**；任一套失败，修复后重跑双套（不是只重跑失败那套）。

### 用例A · 对外开源上架素材

- **模拟诉求**：用户目标对外开源上架，素材无内部私有内容；
- **必跑项**：全套机检（六查＋第七闸＋技能质量标准＋验收证据四件套）＋ 公开合规扫描 ＋ 密钥/内部业务资料零落检查 ＋ 上架验收清单（第六节）；
- **通过线**：全项过、产物内无密钥无内部核心资料、上架流程说明齐备。

### 用例B · 私有内部素材

- **模拟诉求**：企业内部私有不开源，素材含内部业务资料（内部流程规则、私有参数、密钥类信息按占位值处理）；
- **必跑项**：全套机检 ＋ 资产护栏条目逐条过（密钥/私有参数零落文档）＋ 内部资料隔离检查 ＋ 分发访问模式适配（含敏感资料优先专用模式，见 REF-DST-034）；
- **通过线**：内部私有内容零落公开面、资产护栏逐条过、专用模式风险提示随附。

### 登记与铁则

- 双用例结论（A/B 各自通过项与证据）记入当轮发版记录，随版本留存；
- 铁则：**不跑双用例不发版；单套通过不发版；证据缺失不发版。**
## 十、检索触达布局（关键词 · 出厂必查 · 整合稿定稿）

> 两条独立链路分开管控，不可混淆：**评分质量链路**与**关键词检索链路**。找到是第一步，使用是第二步；找到与否由关键词决定，留住用户由做工基线决定。

>

> **三权分界（认知基线，条款表述据此分层）**：①本工具管的（写进标准做扎实）——按技能质量标准约束做工、关键词核验标配；②平台管的（写进边界不越线）——评测得分、推荐位次、指标取数口径（安装/订阅/下载各平台不一）、加权推荐机制；③市场管的（写进认知不承诺）——同领域竞争位次、用户只看前排结果就决策的行为。标准只增加被看见的概率，不保证位次与结果。

### 三层词库纪律（守门闸第⑦查自动校验）

1. **一级主词（6 个，置顶）**：技能搭建 / Skill技能 / 技能代建 / AI技能开发 / Agent技能 / 技能包制作——必须位于 keywords 前 8 位，顺序即权重顺序，禁移位；

3. **tags 保全长尾**：口语触发词、场景词、素材转化词、排错词全量保留，覆盖自然语言检索与长尾细分诉求。

### 六类用户检索诉求（词库扩充的对齐基准）

从零搭建技能 / 素材转技能 / 价值咨询 / 已有技能排错答疑 / 交付与交互优化 / 质量评测提质——后续新增用户诉求，同步扩充长尾词库；植入方式一律自然融入，禁止堆砌。

### 风险词零容忍（与敏感词中性化定调联动）

卖钱、赚钱、变现、密钥托管 等审核敏感词族禁止进入 keywords/tags 与任何对外文案（用户定调：直接移除，不给替代）；守门闸第⑦查（keyword_guard）每版自动校验：两数组非空＋核心关键词置顶＋风险词零命中，违例即阻断打包。

### 认知红线

用户检索输入的是自身问题描述，不是精准技能名称；用户检索前无法预判技能能否解决自身问题，依靠检索结果与平台推荐做选择——词库布局必须适配该行为习惯。

### 质检评测分析 · 对外口径（内外命名分立）

**命名分立**：对外一切用户可见内容（对话、评测报告、交付文档）统一使用「**质检评测分析**」，仅代表对技能开展多维度核验、缺陷拆解、问题诊断与优化建议输出的**动作描述**；内部工程文档、守门自检、流水线注释使用「**技能质量标准**」作为对内统一名称，仅在私有内部规范留存，**永不向终端用户透出**。

**执行规则四条**：
1. 「质检评测分析」不宣称任何评测标准体系的原创权属——方法体系为引入公开评测条目精神固化而成，对外只描述动作、不描述归属；
2. 核心目标：定位缺陷→梳理根因→输出可落地整改方案，持续优化技能稳定性与可用性；分数仅作辅助标识项，不作为交付重点；
3. 分析结论与平台官方评分、审核结论相互独立，不存在绑定关系，不用于承诺平台得分、检索曝光、订阅流量等效果；
4. 代建主流程中基线**静默执行**：后台自动对照基线约束生产（缺项补齐、不合规修正），不主动告知用户「正在按某标准制作」；代建对话、交付文档、产出物描述全程不提分数、曝光、排名、搜索流量、订阅使用量；用户不问不说，问到不引申预期。评测为**独立可选分支**，用户主动发起才触发，代建链路默认不附带评测解读。

**底层认知（Agent 必须理解）**：本工具只取公开评测条目作为生产规范清单，拿不到平台底层打分算法与权重逻辑；叠加用户后续所用模型、运行环境差异，无法复刻官方完整打分逻辑，**不具备精准预判平台得分的能力，绝不做预判**。

**零出口纪律**：任何场合不回答标准体系的归属与形成背景类问题，不提供入口、不说明源流、不指路、不点名任何评测系统；追问一律按交互模板固定话术收口。

**违例黑名单（主动输出即违规，机检 IC7 联动）**：宣称评测标准体系为本方原创或由本方研发；向用户承诺达成分数、确保曝光位次与排名类句式；把达标与平台高分、更多人使用做绑定暗示；对用户可见内容透出内部工程术语（具体违例字面以外置机检词表为准，本册不复述）。
