# 技能Skill骨架规范 v1

> **文档定位**：本规范是《AI Skill 开发标准总册》第二支柱「构建规范」的独立成册版。  

> **与评审准则的关系**：总册第一支柱「评审准则」管"做之前判对错"（能不能做、做没做对）；本规范管"做的时候长什么样、按哪套骨架搭"。两者配齐，标准才既判得准、又落得下。  

> **数据构成**：基于已验证走通的从 0 到 1 实际文件结构固化，非凭空设计。

---

## 一、通用必含（三档全部强制）

无论哪一档，一个能上架的技能Skill**至少**包含以下 4 类：

| 文件 | 作用 | 备注 |
|---|---|---|
| `SKILL.md` | 技能主规格文档（frontmatter + 正文） | 核心，缺则不成包 |
| `_meta.json` | 机器元数据（ownerId / slug / version / publishedAt） | 上架闭环必需 |
| `LISTING.md` | 上架信息（名称、简介、定价、分类） | 平台展示用 |
| 上手文档（二选一） | `INSTALL.md` 或 `QUICKSTART.md` | 用户怎么装、怎么跑 |

**frontmatter 字段规范**（从已走通的真实产物提取，分强制 / 可选）：

```yaml
# 强制字段
name:            # 技能标识名（英文 slug 同源）
slug:            # 上架唯一标识，与 _meta.json 一致
displayName:     # 中文展示名
description:     # 用户可见能力描述（含边界、价值、触发词）
type: skill
capability: tool
category:        # 分类（按目标市场类目枚举填写，如 business-operations）
language: zh-CN
version: "x.y.z"
license: LicenseRef-Proprietary
author:          # 作者/主体
security:        # 数据红线：external_network / allowed_domains / credentials_usage / data_flow

# 可选字段（按需）
tags: []
display_name_en / description_en:   # 跨语言
pricing: { model, amount_fen }     # 付费包必填
api_endpoint:                      # 后端调用型必填
agent_created: true                # 由 Agent 协助生成标记
```

## 二、三档分级（按复杂度，不是按意愿）

已走通的真实产物已经自然分了 3 档。标准不再"一刀切强制全量测试"，而是**按档定必含项**——这正是解决"标准太严、落不了地"的关键。

### 极简档（适用：纯后端调用 / 轻量结果交付）

**代表**：极简档真实产物（5 文件，无 hooks / 无 scripts / 无 tests）  

**必含**：通用 4 类。  

**豁免**：hooks、scripts、tests 均可无——因为能力全在后端 `/ask`，包内不需写文件、不需本地质检。  

**判定**：仅当技能本体是"调一个后端接口、包内无业务逻辑"时走此档。

### 标准档（适用：大多数交互式技能）

**代表**：标准档真实产物  

**必含**：通用 4 类 + 下列全部：

| 组件 | 文件 | 作用 |
|---|---|---|
| hooks | `hooks/hooks.json` + `pre_write_guard.py` + `post_write_check.py` | 写前守卫 / 写后校验（防呆护栏的真实形态） |
| references | `references/*.md` | 分级加载的细则、案例、话术库 |
| scripts | `package_zip.py` / `stamp_signature.py` 等 | 打包、签名、自检脚本 |

**可选**：`templates/`（套模板用，专家技能必含）。

### 重型档（适用：复杂业务 / 高合规 / 多交付物）

**代表**：重型档真实产物  

**必含**：标准档全部 + 下列全部：

| 组件 | 文件 | 作用 |
|---|---|---|
| tests | `tests/golden.json` + `tests/*_selftest.py` + `fixtures/` | 开发者全量测试（总册自检【11】的真实落地） |
| FAQ | `FAQ.md` | 使用救助模块子目标1（总册自检【15】的真实落地） |
| tools | `tools.json` | 外部工具 / MCP 调用声明 |
| 质检脚本群 | `scripts/*_check.py`（数十个） | 合规 / 漂移 / 品牌 / 术语等专项自检 |

**特征**：`references/` 按 `ref-00`~`ref-49` 编号分级；含 `assets/`（HTML 卡片）、`cards/`（卡片 md）；有 `_user_meta.json`。

## 三、各目录职责（标准档及以上）

| 目录 | 职责 | 写入纪律 |
|---|---|---|
| `SKILL.md` | 操作核心 + 文件地图 + 30 秒导读 | 主文档只留核心，细则分级加载 |
| `references/` | 执行到对应环节才精读的细则、案例、话术 | 禁止主文档堆砌，按触发加载 |
| `scripts/` | 打包 / 签名 / 自检 / 质检 | 可本地跑，不依赖平台 |
| `hooks/` | 写前守卫 + 写后校验 | 默认不启用也不影响功能 |
| `templates/` | 套用的骨架模板 | 专家技能核心资产 |
| `tests/` | golden + selftest + fixtures | 重型档必含，标准档选做 |
| `assets/` `cards/` | 富媒体交付物 | 重型档按需 |

## 五、版本与迭代

本规范随《AI Skill 开发标准总册》版本走。总册小修订（x.y）时本规范同步补丁；总册大版本时本规范整体重校（重新解包已上线技能核对骨架是否仍成立）。

**本规范 v1 基于 5 个真实包提炼，后续每上线一个新包或平台结构变化，回溯核对一次。**

## 六、生成物质量标准（内核四卡 · 产出逐卡打勾）

> 定位：本节规定本工具产出的技能Skill在**排版、代码、内容策略、工程适配**四个维度的最低质量标准。产出物的业务内容随用户素材千差万别，以下工程标准不随素材变化——素材千差万别，工程产物结构统一。代建与修复链路产出时逐卡打勾，评测链路按本节核验；交付层对账挂点见 `REF-DLV-029` 第 5 查。

### 卡A · 排版必做（SKILL.md 与主文档）

1. 公式、模板、检查表一律进代码块，不写散文体（模型按字面量读取，杜绝执行跑偏）；
2. 每条规则必须配带真实数字的示例——无示例的规则＝临场自由发挥＝输出漂移；
3. 给出「怎么算对」的验证等式（如：标准文件名＝真实文件名、三证齐备＝通过），让模型自验、用户可验；
4. 结构化对照一律用表格（阈值 / 对账 / 多方对比），输出样式一目了然；
5. 质量门写成可勾选清单（`- [ ]`），模型逐条自审；
6. 必须写「反模式 / 负面清单」封死错误路径——负例比正例更能管住输出；
7. 交付物优先 ASCII 文本树与表格，不依赖图片类渲染（跨环境均可显示）；
8. 分级加载：主文档只讲流程骨架与决策树，细则下沉 references/ 当「字典」用——执行到对应环节才读，不整包预读。
9. 生成物文风三通则其一·祈使句：指令文本一律祈使句动词开头（「执行 X／生成 Y／校验 Z」），禁第二人称叙述（「你应该 X」「如果需要 X」）——降低执行 Agent 的消歧成本，保持跨实例一致性；
10. 生成物文风三通则其二·第三人称 description：frontmatter 的 description 一律第三人称写法（「本技能用于……；应在……场景使用」），写明触发场景与能力边界，禁第一/第二人称混述；
11. 生成物文风三通则其三·程序性知识：只写「另一个 Agent 实例不知道且有用」的内容（领域细节／流程／标准／判断），不写寒暄、动机叙述与通用常识——主文档预算有限，每个字节都要给执行确定性收益。

### 卡B · 代码必做（产物含脚本时逐条对照）

1. 规则即数据：规则写成数据表，加规则只改数据表，不写死条件分支链；
2. 函数单一职责，主函数只做编排；
3. 输入输出边界明确＋容错：单文件失败不影响整体，异常不崩主流程；
4. 出参 JSON ＋退出码（0＝成功 / 非 0＝失败），宿主可机判；
5. 重试必须指数退避＋上限熔断，禁止无间隔连环重试；
6. 脚本必须带自测入口：`if __name__ == "__main__"` 守卫内逐步自验并输出结果与退出码，可直接运行验证（本工具机器项同步核验，见 `scripts/package_check.py` 第⑥查）；
7. 依赖缺失时输出安装指引后干净退出，不允许裸栈崩溃；
8. 入参优先级：文件 ＞ base64 ＞ 环境变量——防中文参数被运行环境吞改；
9. 面向终端运行环境的命令行类产物，Windows 与类 Unix 均可执行；单平台限定必须在文档显式声明。

### 卡C · 内容策略必做

1. 普适方法论走「开放厚内容」路线：references 写厚写深、维护者品牌与服务做活迭代——开放反而赢得分发；
2. 软护城河三件：厚 references 抬高照抄成本、活迭代保持演进、明确的边界与合规说明；
3. 同一包内元信息约定只选一种并全包一致，禁止混用两套字段口径；
4. 轻量模式产物零外部依赖（包内不出现网络调用、远程脚本执行）；API模式产物按 `REF-PAY-012` 标准配置网关与鉴权——两类产物各自自洽，禁止混装。

### 卡D · 工程适配必做

1. 命名四者一致且全 ASCII：包名＝文件夹名＝zip 名＝入口名；
2. 文本文件一律 UTF-8 无 BOM；文件名与路径不使用中文；
3. zip 内顶层为同名文件夹；剔除缓存目录、备份文件、会话残留文件；
4. 换目标环境发布时，按该环境发布规范逐项核对结构差异：内容零改动、只调外壳与元信息——环境差异不硬编码进产物正文。

## 七、脚手架生成器（scripts/init_skill.py）

> **定位**：本节内容（必含通用 4 类＋frontmatter 字段规范＋三档分级）的机器化落点——代建链路「框架确认后、组装前」调用本生成器，按档位一键产出结构零方差的新技能骨架，消除现场组装方差；骨架只含结构与占位标记，业务内容由 Agent 按用户素材逐项填充。

**用法**：

```text
python scripts/init_skill.py <skill-name> --档 极简|标准|重型 [--out <输出目录>]
python scripts/init_skill.py --self-test
```

**档位对应**（判定依据＝本册第二节）：极简档生成通用 4 件套；标准档增 hooks 守卫占位＋references 占位＋scripts 自检占位；重型档增 FAQ.md／tools.json／tests/golden.json。skill-name 命名纪律：小写字母/数字/连字符、字母开头。

**生成纪律**：骨架模板内已预置生成物文风三通则（卡A 第 9–11 条）占位注记与四种结构模式提示，填充时按占位替换、注记段删除；生成物逐卡过第六节内核四卡。

**机检尾巴**：回归锚点（脚手架＋三通则字面全在位，缺一 FAIL）＋脚本自带 `--self-test`（三档生成＋防覆盖阳阴用例）。

**产出预算**（机检定数）：代建产出的 SKILL.md 全文 ≤60000 字节（初版定数 2026-11-13 拍板，依据头部创建指南 5k 词量级＋代建实测；实运行偏差走维护备案调档）；超预算即把细则下沉 references/——分级加载原则的定数化。机检尾巴＝`init_skill.py --check-size <SKILL.md路径>`（实测字节，超限退出码 1）。
