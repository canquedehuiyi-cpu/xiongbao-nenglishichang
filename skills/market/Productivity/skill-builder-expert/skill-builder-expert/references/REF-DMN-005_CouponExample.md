# REF-DMN-005_CouponExample（机制验证样本 · 非落地组件）

> 本文件是《REF-DMN-019_DomainComponentBoundary》在「优惠 / 领券类」业务上的**验证样本**，用于演示机制如何把一个喧嚣、低质、部分踩线的领域，安全收敛为通用能力 + 红线清单。**本域不作为「已落地组件」入库**，仅作方法演示。

> 数据基础：用户一手提供的 18 个历史案例目录（只读，未改动任何本体），经分类评估。

## 一、评估结论（先行）

18 个历史案例经逐条判定：高度重叠、质量参差、部分触碰合规红线，**不能整包吸收为领域组件**。但本域恰好验证了专家机制的价值——它把「该不该做、能复用什么、必须排除什么」一次说清，而非盲目照搬。

## 二、按三类入库边界的判定

### 类别一 · 可复用通用类（已提炼入机制，不入本域私有组件）
- 领域组件库机制本身（见 `references/REF-DMN-019_DomainComponentBoundary.md`）。
- 概率性结果前置告知：能否领取 / 归因由对应平台库存与账号规则决定，技能不承诺成功率。
- 仅做入口、不控平台侧策略：技能只提供携带参数的跳转入口。
- 禁后台静默批量请求、禁自动化抓取：仅做用户主动触发的分发。
- 上述已属通用合规原则，跨领域复用，不专属优惠券。

### 类别二 · 仅体验类（记录交互形态，不复用业务逻辑）
- 部分案例的菜单化交互编排：首屏分类入口、回数字直达模块。
- 分层文档结构：能力说明 / 局限说明 / FAQ 分区清晰。
- 卡点救助话术：领取失败时的友好引导。
- 处理：仅记形态要点，供其他领域交互设计对照；不复制其领券业务逻辑。

### 类别三 · 禁止复用私有资产类（红线清单，仅作禁区记录）
- 自动领券 / 定时静默批量领取：属后台静默批量请求，禁用。
- 自动化抓取平台券池：属爬虫式采集，禁用。
- 携带推广参数的归因链接、佣金结算逻辑：属私有资产与平台违规，禁用、不入库。
- 平台账号密钥、用户隐私字段：零落包、不进任何产物。
- 处理：登记进反面红线清单，供后续识别拦截；绝不进入技能产出物。

## 三、机制验证结论

优惠券域经本机制处理后产出三样东西，而非一个低质技能：
1. 一组**通用能力**（已进标准库，跨域复用）；
2. 一份**交互形态说明**（仅体验，不复制业务）；
3. 一张**红线清单**（明确禁区，防再犯）。

这证明专家的「机制通用化 + 插件化」能把任意外部领域安全吸收为「能力 + 红线」，不产出伪能力、不污染标准。

## 四、若未来要做优惠券域组件的最小骨架（模板占位，不含真实业务）

```
components/coupon-domain/
  SKILL.md        # 组件卡：能力边界（仅入口）+ 红线（禁静默/禁抓取）+ 适用场景
  references/     # 领域专用判据（如需）
  templates/      # 入口模板（仅跳转，不控平台）
```

组件卡必须含：概率性结果前置告知、仅做入口声明、禁静默批量请求与自动化抓取红线、最小权限与零密钥声明。其余业务逻辑以通用机制为准，不重复造轮子。
