# REF-SNP-051 用户业务快照档案规范（单套定稿 · 2026-11-06 下发全文收录）

> 定位：本册是快照档案能力的唯一设计依据，八节定稿逐字收录（仅章节编号适配）。快照是可选增强能力，不是底座核心依赖；底座四大闭环（代建／整改／评测／答疑）在快照功能不可用时完整可用。

## 一、定位总纲
本档案不属于对话记忆，不和 Agent 平台原生会话记忆、平台记忆并行，规避信息冲突、意图打架。

档案仅承载本技能域结构化工程配置、进度现场与索引快照，不存储聊天原文、原始业务资料、用户私密业务素材；所有加载、切换、清空、继承动作，必须经过用户显式确认，无任何自动静默读取、自动推断偏好逻辑。

目标：实现「越用越好用」，本质是复用用户已经确认过的交付基线与进度现场，而不是模型记住对话。

称呼规矩（全包统一）：正式名「业务快照档案」，首次出现用全称，行文其余处统一简写「快照档案」；「基线档案」仅用于口令组名（保存至我的基线档案／加载我的基线档案），不作叙述用名。

## 二、档案存储内容（白名单，仅下面这些，禁止扩列）
一份用户快照档案包含：
1. 基线配置：用户锁定的术语词库、交付排版模板、输出渲染规范、自检质检清单；
2. 偏好索引：默认部署模式（轻量 / API）、默认版本类型（免费 / 收费）、默认分发方式；
3. 历史索引：历史产出技能包编号、版本快照编号、上次整改记录摘要（仅记录问题标签，不存完整包、不存原文）；
4. 高频提醒标记：该用户反复出现的提示标签（例如：API模式备案提醒、收费版资质提醒）；
5. 个人模板池：用户确认归档、允许复用的自用参考案例；
6. 进度现场：用户确认过的业务框架概要全文、已确认结论摘要、当前环节与下一步待办（依 4.6 在关键节点自动写入，跨窗口续作与断点重建的唯一现场依据）。

> 黑名单严禁存入：对话记录、用户上传的原始文档、业务一手素材、身份证、收款信息、密钥、服务器凭证。

## 三、触发口令（中频，归入答疑链路档案管理子菜单）
「加载我的基线档案」「新建交付基线」「清空我的档案」「查看历史技能包」「继承上一份基线」「保存至我的基线档案」——全部路由档案管理子菜单；文本口令大小写不敏感。

## 四、交互流程（强制流程，Agent 必须按顺序执行）
### 4.1 进入会话检测逻辑
会话启动时仅做轻量标记检测，不自动加载档案。固定问询话术：

「检测到您存在一份业务快照档案，档案仅包含您过往确认的交付基线、模板与历史索引。是否加载这份基线用于本次技能搭建？**【是 / 否】**」

选择「否」：本次会话使用底座默认标准，不读取档案；选择「是」：载入基线，同时输出摘要告知用户本次生效的配置项，用户仍可以在开工前逐项修改覆盖。
### 4.2 新建基线
用户触发「新建交付基线」：引导用户确认一套全新术语、排版、质检、默认部署配置，确认后生成一份独立快照，可命名区分（例如：私域自用基线、对外上架基线），支持多份档案并存。
### 4.3 继承基线（整改 / 迭代场景）
当用户进入「整改技能、技能升级」链路，在用户上传旧技能包之后，弹出选项：

「是否继承该技能包原有基线标准？继承后术语、排版、自检规则沿用原有版本，您可以单独修改其中条目。**【是 / 否】**」
### 4.4 清空档案
触发「清空我的档案」，做二次确认，防止误操作：

「确认清空当前这份业务快照档案？清空后基线、模板、历史索引全部清除，该操作不可恢复。**【确认清空 / 取消】**」

确认后：档案标记为已清空，不再读取；平台侧原有会话记忆不受影响。
### 4.5 查看历史技能包
仅返回索引清单：编号、版本、创建时间、部署模式，不自动打开、不自动加载；用户选中某一条，才弹出「加载对应基线」选项。
### 4.6 进度现场自动写入（关键节点自动固化，用户零操作）
在下面四个关键节点，系统自动把进度现场（框架概要全文、已确认结论摘要、当前环节与下一步待办）写入当前档案，无需用户回复口令、不依赖用户记得：

① 素材解析完成；② 业务框架获用户确认后；③ 每轮迭代修改完成；④ 成品交付完成。

平台不支持持久存储时整套静默降级，不阻断主链路；降级时在四个节点改用一句话提醒，并主动输出阶段性草稿交用户本地留存——草稿固定四段：当前梳理进度、业务背景、已萃取要点、待续事项；用户重进会话时粘贴草稿即接续，无需从头再来。

## 五、边界约束（强制写入规约）
1. 跨账号、跨 Agent 平台、跨设备：档案不自动同步；档案绑定当前 Agent 账号环境；
2. 平台记忆隔离：平台模型记住的对话上下文，不会写入快照档案；快照档案内容也不会自动注入平台长期记忆；二者独立；
3. 只读边界：档案仅提供基线复用，不会替用户做业务判断、不会自动修改技能逻辑；
4. 权限边界：本技能不导出、不上传、不外发快照档案；
5. 失效规则：若底座主版本号向前跳升（Major 级升级），档案标记为待校验，加载前强制提示用户复核基线兼容性。

## 六、兜底逻辑
1. 档案损坏、格式异常、索引丢失：静默降级，自动切换到底座默认交付标准，告知用户：「读取快照档案异常，本次将使用底座默认基线，您可以选择新建档案」；
2. 用户选择不加载档案：全程使用底座原生默认标准；
3. 用户在会话中途修改基线：改动仅在本次会话生效；只有用户主动执行「保存至我的基线档案」，变更才写入快照；
4. 如果当前 Agent 平台不支持持久存储：整套快照功能直接静默关闭，不报错、不弹窗，回退为纯默认交付模式，不阻断四大主业务链路。

## 七、FAQ 配套条目（E11）
问：这个技能会不会记住我们聊天内容？会不会自动记住我的所有需求？

答：本技能没有独立对话记忆，不会自动留存聊天内容。仅在您主动确认后，可以加载业务快照档案，复用您之前确认的术语、排版、质检基线与历史技能索引；档案只存工程配置索引，不保存原始业务材料。Agent 平台自带的会话记忆由平台管控，和这份档案互相独立，互不干扰。

## 八、文档备注（内部）
快照属于可选增强能力，不是底座核心依赖；底座四大闭环在快照功能不可用时，完整可用。快照只做「复用标准」，不新增任何自主决策逻辑，不扩大责任边界，符合「只管控自身技能框架」的底层原则。

## 九、工程落地适配（Agent 执行补充）
- 存储：沿用现有本地偏好文件（单文件多档案结构，档案数组＋当前指针），路径仅限本地相对文件名（沿用偏好守卫 P3）；
- 守卫：偏好守卫升级档案守卫——白名单字段校验（超列即拦）＋黑名单字段名零容忍＋不入包＋仅本地；
- 检测时机：首响轮零工具调用（极速响应优先，不检测不追加）；自第二条消息起，轻量检测复用该轮唯一允许的一次本地文件读取（读不到＝无档案＝首次流程，读到档案标记＝该轮回复尾附加载问询）；
- 与交互模板同源：四屏话术在 REF-TMP-003 与 SKILL.md 内联区同源维护，改动两处同改过回归机检。
