# 行业模板库（四套成品骨架 · 可直接选）

> 定位：本文件是工厂的"纵深资产层"——四套按行业场景预制的技能骨架，每套都带完整的接料口、流程、输出卡与自验证设计。代建开工时若用户业务与某套模板匹配，**以模板为底改内容**，比从零起草更快、更稳、更不容易漏件。

> 用途：这是造技能动作的加速器；行业里沉淀的成品骨架只有这里有。

## 一、四套模板一览

| 模板 | 适用场景 | 核心交付物 |
|---|---|---|
| 老板决策陪练 | 中小老板的经营判断：定价、扩不扩、招不招人、砍不砍业务、大额支出把关 | 决策清单卡 + 复盘记录 |
| 团队操作手册 | 门店／团队的 SOP 问答与新人带教 | 按问即答的操作卡 |
| 手艺经验库 | 维修、安装、工艺等手艺活的口述经验沉淀 | 排查决策树 + 判定卡 |
| 内容生产流水线 | 公众号／短视频等内容的选题到成稿 | 成稿 + 选题备档 |

## 二、选用规则

1. **先听后选**：用户讲完业务，对照上表判断是否命中某套模板；命中→说明"你的场景有现成骨架，我按它给你起底子"，**经用户点头后再用**；不命中→走从零起草，不硬套。
2. **只换内容不改骨架**：模板里的接料触发表、输出卡、自验证三问、分页铁律是**结构件**，保留；替换的只有行业知识、话术、示例。
3. **骨架不允许降级**：交付前对照模板尾部的"出厂自检"逐条过，缺一件 = 不出包。
4. **改完必做全包自查**：逐文件核对成品包内容与关联完整性。

## 三、改编四步

1. 复制模板目录内文件到新建包目录，目录名改成新技能的 slug（name ＝ slug ＝ 目录名，三处一致）。
2. 替换 frontmatter 的 name／description（description 按"用户会怎么开口"写满触发场景）。
3. 按"改编位"标记逐处替换行业内容——模板内所有 `**【改编位：…】**` 标记都要清零。
4. 跑出厂自检 + 本包检查脚本，全绿才交付。

## 四、出厂自检（每套模板尾部同款，交付前逐条勾）

- [ ] 装得上：frontmatter 完整，name ＝ slug ＝ 目录名
- [ ] 唤得起：description 含至少 5 个真实触发说法
- [ ] 答得对：核心流程 + 输出卡齐全，接料触发表覆盖至少 3 种开口方式
- [ ] 说得清：自验证三问在交付前真实跑过，证据随交付给出
- [ ] 分页合规：知识体量超 50KB 必装行号索引，禁整文件读取
- [ ] 安全声明：frontmatter 四项齐（联网／域名／凭证／数据流向）
- [ ] 改编位清零：全文检索 `【改编位` 无残留

# 老板决策陪练（模板 · 改编后删除本行）

> 骨架基准：本工具行业模板库。改编完成后本注释与全部 `**【改编位】**` 标记必须清零。

## 一、能力定位（一句话）
**【改编位：一句话说清这套决策陪练帮谁、算什么账。示例口径：你开口讲 situation，我给一张能直接照着做的决策清单卡——算什么、看哪几个数、什么情况选哪条路、定下来之后过多久回头看什么。】**

**立场铁律**：只帮把账算清、把选项摆全，**决定永远是老板自己拍板**；不替用户做决定，不预测生意之外的市场走势，不碰资金盘、借贷、投资类话题——命中即停，说明边界并回到经营本身。

## 二、接料触发表（处境信号 → 动作）
| 用户怎么开口 | 实际要什么 | 本技能做什么 |
|---|---|---|
| 「帮我算算这笔账」 | 一笔具体支出的取舍 | 走流程 A，出决策清单卡 |
| 「最近单子多了忙不过来」 | 扩不扩、招不招人的判断 | 走流程 A，先补三个关键数 |
| 「这个月怎么又白干了」 | 经营复盘 | 走流程 B，出复盘记录 |
| 「隔壁店降价了」 | 应对定价 | 走流程 A，跟价前先算成本线 |

**接料纪律**：用户讲不清时**最多问一个问题**，且问的是「哪个数」而不是「你再讲讲」；三个关键数（成本线、客流/单量、现金流可撑月数）缺哪个先要哪个。

## 三、核心流程
- **流程 A · 一次决策**：① 复述决定本身（一句话）→ ② 列出这次要看的 3–5 个数 **【改编位：按行业定，如餐饮＝翻台率/损耗率/租金占比】** → ③ 数从哪来问清楚，**没有的数标「待补」不许编** → ④ 给三条路（做 / 不做 / 缩小了做）各配一句代价 → ⑤ 出决策清单卡。
- **流程 B · 复盘**：① 当时清单卡上写的是什么 → ② 实际发生了什么 → ③ 差在哪一格 → ④ 把新判断写回决策规则里。

## 四、输出卡（交付物格式）
**决策清单卡**：① 要决定的事（一句话）② 看哪几个数（实数或「待补」）③ 三条路 × 各自代价 ④ 底线数字（低于多少就停）⑤ 回头看的时点（如「两周后看单量」）。

**复盘记录**：编号 + 日期 + 当时判断 + 实际结果 + 差因一句 + 写回规则的新条目。

## 五、自验证（交付前必跑自验证三问）
1. 卡上每个数，是用户给的还是我编的？——编的清零重来。
2. 三条路是不是都有代价？只写好处的卡不出。
3. 底线数字和回头看时点有没有？缺一件不算交付。

## 六、出厂自检
装得上（name＝slug＝目录名）｜唤得起（description ≥5 个触发说法）｜答得对（触发表 ≥3 种开口）｜说得清（自验证三问跑过、证据随交付）｜改编位清零。

# 团队操作手册（模板 · 改编后删除本行）

> 骨架基准：本工具行业模板库。改编完成后本注释与全部 `**【改编位】**` 标记必须清零。

## 一、能力定位（一句话）
**【改编位：一句话说清这本手册覆盖哪个店／哪条业务线、给谁用。示例口径：员工开口问「XX 怎么办」，我给一步不停顿的操作卡——先做什么、再做什么、什么情况上报给谁。】**

**立场铁律**：答「怎么按规矩办」，不答「规矩该不该改」；遇到手册没写的情况，**明说「这条手册没覆盖」并给上报路径**，不现场发明流程。

## 二、接料触发表（处境信号 → 动作）
| 用户怎么开口 | 实际要什么 | 本技能做什么 |
|---|---|---|
| 「XX 怎么操作」 | 单个步骤 | 出单条操作卡 |
| 「新人第一天该学什么」 | 带教清单 | 出带教顺序单（从高频操作开始） |
| 「这单客户闹起来了」 | 应急处理 | 出应急卡 + 上报路径 |
| 「这个流程好像不对」 | 修手册 | 进修订模式：先记差异，经确认再改正文 |

## 三、核心流程
- **建库**：老板口述／丢资料 → 按场景分册 **【改编位：按业务定分册，如收银册/售后册/交接册】** → 每条操作写成「步骤 ≤7 步 + 判断点 ≤3 个 + 上报线 1 条」→ 编号入库。
- **答问**：定位编号 → 按行号精读对应条目 → 出操作卡（原文口径，不改写不改序）。
- **修订**：用户说实际做法变了 → 记差异条目（编号 + 变了什么 + 谁确认的）→ 确认后改正文并在该条立「修订标记 + 日期」，防止改回去。

## 四、输出卡（交付物格式）
**操作卡**：① 编号 ② 适用情形一句 ③ 步骤列表 ④ 判断点（满足什么走 A、否则走 B）⑤ 上报线（什么情况找谁）。

**带教顺序单**：第一周每天 2–3 条编号，从最高频操作排起。

## 五、自验证（交付前必跑自验证三问）
1. 每张卡的步骤，是用户口述的原口径还是我想当然的？——想当然的清零重来。
2. 判断点有没有写「否则怎么办」？只写正常路的卡不出。
3. 手册没覆盖的问题，有没有明说没覆盖 + 给上报路径？

## 六、出厂自检
装得上（name＝slug＝目录名）｜唤得起（description ≥5 个触发说法）｜答得对（触发表 ≥3 种开口）｜说得清（自验证三问跑过、证据随交付）｜分页合规（条目超 50KB 装行号索引）｜改编位清零。

# 手艺经验库（模板 · 改编后删除本行）

> 骨架基准：本工具行业模板库。改编完成后本注释与全部 `**【改编位】**` 标记必须清零。

> 本模板专为「手艺在脑子里、从没写成文档」的老师傅设计：**口述即可建库，不需要先整理任何文档**。

## 一、能力定位（一句话）
**【改编位：一句话说清覆盖哪门手艺、给谁用。示例口径：学徒描述现象，我按师傅的排查路数给「先查什么、再查什么、查到什么程度换判定」的决策树——师傅的顺序就是本库的顺序。】**

**立场铁律**：只出师傅验证过的路数；师傅没讲过的排查分支**标「待师傅补」**，不凭常识现编；涉及断电、拆机、高压等安全动作，**安全步骤永远排在最前面**，一步不省。

## 二、接料触发表（处境信号 → 动作）
| 用户怎么开口 | 实际要什么 | 本技能做什么 |
|---|---|---|
| 「XX 不亮 / 不响 / 不动了」 | 排查起点 | 出排查决策树（从现象起的第一分叉） |
| 「拆到这里下一步呢」 | 排查中途定位 | 问清当前现象 → 给下一分叉 |
| 「这个件怎么判断好坏」 | 判定标准 | 出判定卡（测什么、读多少算好、多少算换） |
| 「师傅你上回那个怪毛病…」 | 经验回流 | 进录账模式：现象 + 处理 + 结果，编号入库 |

## 三、核心流程
- **建库（口述直录）**：师傅讲一段 → 拆成「现象分叉 + 判定动作 + 判定读数」三件套 → 编号入库 **【改编位：按手艺定分册，如不开机册/异响册/更换件册】** → 每条必带「安全动作」栏。
- **带徒**：学徒给现象 → 决策树定位 → 出排查卡（一步一卡，做完这步再给下一步，防跳步）。
- **录账回流**：现场遇到库里没有的现象 → 处理完回来补录 → 补录条目经师傅确认后升级为正式条目（含「确认人 + 日期」）。

## 四、输出卡（交付物格式）
**排查卡**：① 现象复述 ② 这一步做什么检查 ③ 读到什么数／看到什么现象算哪条路 ④ 安全提醒 ⑤ 下一分叉预告。

**判定卡**：① 件名 ② 测量方法 ③ 好的读数区间 ④ 必换的读数区间 ⑤ 常见误判（看着像坏了其实是别的问题的情形）。

## 五、自验证（交付前必跑自验证三问）
1. 每个排查分支，师傅口述过还是我推理的？——推理的标「待师傅补」，不许混进正式条目。
2. 安全动作排最前了吗？拆机／断电类条目缺安全栏不出。
3. 判定卡有没有具体读数？「量一下看看」这种不算判定标准。

## 六、出厂自检
装得上（name＝slug＝目录名）｜唤得起（description ≥5 个触发说法）｜答得对（触发表 ≥3 种开口）｜说得清（自验证三问跑过、证据随交付）｜分页合规（条目超 50KB 装行号索引）｜改编位清零。

# 内容生产流水线（模板 · 改编后删除本行）

> 骨架基准：本工具行业模板库。改编完成后本注释与全部 `**【改编位】**` 标记必须清零。

## 一、能力定位（一句话）
**【改编位：一句话说清给谁写、写什么、按谁的口气。示例口径：你给主题或丢素材，我按你定下的口径出成稿——结论前置、场景开场、金句可摘；每一稿都有编号，改过什么都能对账。】**

**立场铁律**：数字必须源于用户给的素材，**算不清的数不上稿**；转述别人的话须注明是谁说的；口径（结论先定还是先出三版选）按用户拍板执行，写完不改口径。

## 二、接料触发表（处境信号 → 动作）
| 用户怎么开口 | 实际要什么 | 本技能做什么 |
|---|---|---|
| 「最近没东西可写」 | 选题 | 出选题单（每条带一句「写给谁、戳什么场景」） |
| 「这篇帮我改改」 | 改稿 | 先问改哪层（开头／结构／口径），按层动刀 |
| 「开头不够抓人」 | 开头重写 | 出三版不同切法，标注各版路数 |
| 「照这个口气写」 | 定风格 | 先出 200 字风格样张，确认后成稿 |
| 「上个月好像写过」 | 查重复用 | 按编号检索旧稿，给复用建议 |

## 三、核心流程
- **选题**：素材库 + 用户近况 → 选题单（一次至多 5 条，每条带场景句）→ 用户勾选才开工。
- **成稿**：确认口径 → 初稿（结论前置／场景开场／金句加粗／移动端短段落 **【改编位：按发布平台定版式规则】**）→ 交付带编号。
- **改稿**：按层改，不动没让动的部分；改完在稿尾列「本稿改动两三处」。
- **留档**：成稿编号入库（编号／日期／主题／用过的素材／数据表现留空待回填）。

## 四、输出卡（交付物格式）
**成稿**：编号 + 标题 + 正文（版式按改编位规则）+ 稿尾「本稿依据的素材清单」。

**选题单**：编号 + 题目 + 一句场景 + 建议形式（长文／短文／脚本）。

## 五、自验证（交付前必跑自验证三问）
1. 稿里每个数字都能指到素材里的原始位置吗？指不出的删掉或标「待补数据」。
2. 口气跟样张一致吗？拿样张并排对一遍再交。
3. 稿尾素材清单列了吗？没列不算交付。

## 六、出厂自检
装得上（name＝slug＝目录名）｜唤得起（description ≥5 个触发说法）｜答得对（触发表 ≥3 种开口）｜说得清（自验证三问跑过、证据随交付）｜分页合规（旧稿库超 50KB 装行号索引）｜改编位清零。
