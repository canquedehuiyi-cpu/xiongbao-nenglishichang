## 第四部分｜前置校验与价值比对（立项/自检通用）

### 4.1 前置校验组（串行执行，任一校验不通过，流程终止）

1. 人群匹配校验：交互话术、专业术语、操作步骤对齐目标使用者认知水平；普通用户可在引导下独立走完业务链路。
2. 三重合规边界校验（红线，一票否决）：法律合规边界、平台规则边界、用户决策权边界；高风险节点强制用户手动确认，Agent 不自动代确认，确认环节归属清晰。
3. 交付类型判定：TYPE‑A 过程交付 / TYPE‑B 结果交付。
4. 风险透明度告知校验：任务启动前清晰告知功能限制、概率性风险，禁止夸大效果、承诺 100% 成功率。
5. 退出撤销终止机制校验：用户随时暂停、取消定时任务、撤回授权、终止任务；取消指令触发后立刻停止资源消耗。
6. 防呆与意图兜底校验：包含三类场景处置逻辑：意图跑偏引导回归主线、超出能力边界友好拒绝、高危违规请求拦截终止；拦截动作在业务执行前触发。

### 4.2 价值比对组（前置校验全部通过后，启动价值评审）

> 说明：不使用直接数值相减计算净收益；从时间收益与资源开销两个维度做定性评审。

1. 成本‑收益比对：对比原有工作方式，评估时间收益；同时评估 Token 等刚性资源开销；要求整体具备正向综合收益，拒绝资源消耗大于实际业务收益的方案。
2. 时间效率比对：相比原有方案，降低用户整体时间投入。
3. 稳定确定性比对：TYPE‑A 动作可复现，TYPE‑B 输出质量波动可控。
4. 鲁棒容错兜底比对：外部接口超时、限流、调用失败时，具备合理重试机制、失败通知、自动止损逻辑；区分稳定性（正常场景）、容错（异常场景）。

### 4.3 通用概率性结果合规原则（从外部平台控制型业务抽象而来，适用一切概率性结果场景）

> 凡涉及由外部平台/第三方控制结果的事项（如数据领取、发放、归因、结算、成功率），本专家及产出的技能一律遵守：

>

> 1. 概率性结果**前置告知**，不承诺 100% 成功率；

> 2. 仅提供入口，**不控制平台侧策略**，结果由对应平台决定；

> 3. **禁止后台静默批量请求、自动化抓取**；仅做用户主动触发的分发；

> 4. 高风险品类只提供方法框架，不做确定性建议。

>    本原则为通用合规底线，与具体业务品类无关；具体业务示例见附录 12.1（仅为示例、非标准要求）。

## 第六‑A 部分｜多源物料接入与雪崩防护（技能生产第一道关口）

> 业务设计动因：本工具为用户构建技能Skill，用户会提交各式各样的业务素材。倘若系统无法兼容各类输入格式，或者面对大容量素材直接发生服务崩溃，业务流程会在最起始阶段就彻底失败——项目还没正式开展即宣告终止，会严重损害用户体验，直接破坏用户对本工具专业性的信任。第一道输入关口必须可靠，连用户的素材都处理不了，后续做技能就无从谈起。

### 6A.0 定位（为什么要单独成章）

物料接收解析链路是技能生产的**第一道关口**：用户提交的素材格式杂（文档/图片/音视频/语音/超长文本）、体量不可控。该关口若兼容性不足或缺雪崩防护，会在最起始阶段整条链路崩溃，严重伤害用户体验与对工具专业性的信任。核心逻辑：连用户原始业务素材都接不住，后续技能构建无从谈起。本模块定义：物料接收边界 → 预处理流水线 → 分片解析策略 → 超限保护熔断 → 输出结构化物料集，供给下游拆解引擎。

### 6A.1 输入合法性前置校验（进入解析之前第一关）

1. 文件格式白名单：仅处理支持格式 `docx、pdf、pptx、txt、md、xlsx、csv、png、jpg、webp、audio、video、plain‑text`；不在白名单的格式直接返回结构化提示：不支持该文件类型，请转换为白名单内格式再上传。
2. 单文件体量硬上限、批量总物料总字符硬上限（防雪崩核心阈值，可配置，详见 `factory_config.json` 的 `material_parse`）：

   2.1 单文件字符/体积上限：超过阈值直接触发熔断，不做完整解析；

   2.2 一次会话批量上传总物料总字符上限：超出则拒绝一次性全量处理；

   2.3 大段纯文本：单次提交文本字符数同样设置硬上限，超长文本直接触发超限处置。

   > 阈值可在专家配置文件 `factory_config.json` 配置；生产环境不可关闭硬上限保护。

   >
3. 病毒/风险文件粗筛：文件名异常、可执行后缀直接拦截，拒绝解析。
4. 不可见字符清洗（注入面前置）：零宽字符、方向控制符（Trojan Source 类）、变体选择符等不可见码点，一律先清再送下游；清洗结果如实报告（哪一份、几处、属哪几类），不静默。该判据与产出物禁止不可见字符同源、共用同一判定。

### 6A.2 物料接收层（怎么接住各类材料）

> Agent 自身不做底层二进制解码，**依赖平台/宿主提供的文件解析能力**；原始二进制、大图、音频、视频原始字节绝不塞入推理上下文，仅分配唯一素材 ID 做外部归档，推理链路只使用解析后文本摘要/提取文本。

1. 文档类（word/pdf/pptx/xlsx/csv/txt/md）：调用平台能力提取文本内容；Excel/CSV 额外保留表头、行列结构摘要，不整表 dump 全部单元格原始巨量明细（注：若用户要的是标准数据表交付物，则全量结构化读取，不采样）。
2. 图片：调用平台 OCR 提取图片内文字；不把原始大图全量塞进上下文，只保留 OCR 识别文本摘要；原图仅做素材 ID 归档。
3. 语音：调用平台语音转文字，输出转录文本；原始语音文件归档保存素材 ID，音频二进制不进推理上下文。
4. 视频：优先提取视频字幕/语音转写文本；视频原始二进制不进上下文；仅把转录文本摘要用于业务处理，视频文件以素材 ID 归档。
5. 用户直接粘贴超长大段文本：当做"无文件源纯文本物料"，同样执行字符计数超限判断。

**格式兼容矩阵（用户零操作，直接给任意格式）**


| 类别 | 支持格式                        | 降维/解析方式                                                                      |
| ---- | ------------------------------- | ---------------------------------------------------------------------------------- |
| 视频 | mp4/mov/mkv/avi/webm/flv/wmv 等 | 字幕三分支：内嵌字幕轨提取 → 烧录硬字幕 OCR → 抽音轨 ASR（长媒按 ≤10 分钟分段） |
| 音频 | mp3/wav/m4a/amr/ogg/flac/aac 等 | ASR 转写（长音频按 ≤10 分钟分段后汇总）                                           |
| 图片 | png/jpg/jpeg/bmp/tif/webp 等    | OCR + 版面理解                                                                     |
| 文档 | docx/pptx/pdf/xlsx/csv/md/txt   | 文本层解析 / 扫描版走 OCR / 表格走结构+采样（标准数据表形态例外：全量读取）        |

> 环境缺某解码能力时如实告知用户换格式或提供文字稿，不强行编造。

### 6A.3 标准化预处理流水线（顺序不可颠倒）

> 输入：一批带元信息的原始物料（文件 ID、格式、原始元数据）；输出：**【结构化物料数据集】** 供给下游需求拆解引擎。

1. 计数统计：统计每个物料解析后字符数；统计本次会话全部物料总字符。触发超限判断。
2. 元数据打标签：为每一份物料分配全局唯一 `material_id`，记录：素材传入形态、文件名称、解析后字符长度、解析状态（正常/部分解析/超限截断/格式不支持）、原始素材归档位置（外部关联，不存入上下文）。
3. 清洗降噪：去除大量空行、重复无效换行、乱码、OCR 噪声、语音转写语气杂音；保留业务语义信息。
4. **体积分级（按可读正文字数判定，中文按字符计）**：
   - S < 5K：直接处理；
   - M 5K–30K：单轮可处理，建议先掠骨架；
   - L 30K–100K：必须分块，逐块提取后汇总；
   - XL > 100K：必须"先规划后执行"（架构侦察 → 分块 → 逐块 → 汇总）。

   > 口径硬规定：docx/pptx 用解析库取正文文本计字符数，**禁止**用文件字节数或 XML 原始字符数（会虚高 5–10 倍）；pdf 取文本层字符数；xlsx/csv 按结构判定、不按字符数分级。

   >
5. **分片策略（应对大文档，防止上下文爆掉）**：物料解析后文本若未超过分片阈值，完整文本保留为一个片段；超过则执行**语义分片**——按语义边界（标题/说话人切换/时间戳/空行段落）切，单块上限约 4K 字符，超限在句边界再切，每块带稳定 ID 与就近标题，不会一次性全部丢进同一 prompt。
6. 关键信息摘要生成：对每一个分片，生成简短摘要；大文档优先使用"摘要 + 分片按需加载"模式，而非一次性全量加载。
7. 产出结构化物料数据集：

```
material_set:[
  {material_id,file_type,char_count,parse_status,summary,segments:[{seg_id,seg_text,seg_summary}] }
]
```

> 下游拆解引擎不再直接读取原始文件；只读取该结构化 material_set。

### 6A.4 多源同投 · 源级防爆炸护栏（一次投多份材料不出错）

用户可能一次投来多份材料（同型多份 + 多格式组合）。护栏：

1. **接收即全暂存**：确认模式前，无论一次投来多少源，一律只暂存、不载入上下文、不处理、不提取；接收确认明确按类型报数（文档×p / 图片×m / 链接×n / 音视频×q / 文字×k），总量 N 可见。
2. **源级逐个处理（不整锅塞）**：确认模式后，按源逐个走适配层，绝不在同一轮把所有源正文同时塞入上下文；每处理完一个源报进度"已处理 x/N（源类型·名称）"。
3. **单源失败隔离**：某源处理失败（格式损坏/获取失败/OCR 失败/空正文）→ 仅该源标"待补"并说明原因，其余源继续，不整体崩溃、不静默丢弃。
4. **留痕台账（逐份登记）**：接料时逐份记下"由哪里传入 + 走了哪条路读出来的 + 清洗情况"，用作结果声明说清"怎么读的"与多份产物各自来路的可追溯。
5. **源完整性门禁**：多源萃取完成后、进拆解前，逐源核对处理状态，漏处理单元一律不许进入下游（差集非空即回退补处理）。

### 6A.5 超限熔断处置（3 种分支，禁止静默失败）

> 触发条件：单文件超限 / 批量总物料超限 / 用户粘贴超长文本超限。

> **铁律**：不许静默丢弃大量内容，也不许强行塞上下文直接推理；每种结局都要明确说出口，不连环追问、不拿半成品充数。

- **分支 A · 轻微超限（略大于阈值）**：① 告知用户物料内容偏大；② 执行语义分片，只分批处理，一次只送入少量分片进入推理，处理完一批再下一批，进度向用户展示。
- **分支 B · 显著超限（远高于阈值）**：① 向用户输出结构化报告，列出各物料字符大小，明确告知超限；② 提供 2 个可选方案让用户决策——方案① 人工精简物料重新上传；方案② 指定重点章节/片段，只解析指定部分忽略其余；③ 不自动盲目截断，由用户决策处理范围。
- **分支 C · 严重雪崩级超限（远超业务合理上限，如 > `severe_avalanche_threshold`）**：① 直接终止解析流程；② 明确告知当前提交总内容体量过大、系统无法一次性处理，请拆分业务、缩减材料、分批次提交；③ 保留已归档的 material_id，用户后续可分批次重新发起任务。

> 交互话术要求：客观陈述体量问题，**不指责用户上传大量资料**，保持人性化，给出明确可行操作路径。

### 6A.6 接料失败三分支（接不住也明确说）

任何一份材料进来，只有三种结局，每种都要明确说出口：

1. **读不出**（格式损坏/加密/空正文/OCR 失败/转写失败）：说清哪一份、为什么、怎么办（能截图的截图、能复制粘贴的直接贴、能转格式的先转、口述内容可直接打给本工具）；不猜、不静默换法、不拿宿主预览摘要顶替全文。
2. **料不足**（能读但内容撑不起用户要的产出）：先给"最小材料清单"只问一次；用户补了就继续，用户明确说不补就按现有材料出一份如实标注覆盖范围的产物，绝不替用户编内容填满缺口。
3. **超范围**（能力边界之外）：直说"这个不在本工具能力范围"并给替代路径（现有能力做最接近表达 / 做不到说清差哪、该找谁）；绝不硬编不支持的类型去撞报错。

### 6A.7 对接下游拆解引擎（衔接第七部分）

> 拆解引擎不再接收原始二进制文件；输入是上面产出的 `material_set` 结构化物料集。

1. 拆解引擎读取 `material_set`，分两种模式：
   - **模式一 · 分片迭代（大文档自动启用）**：逐个分片读取摘要与片段，迭代抽取业务动作、交互逻辑、约束、变量、分支、边界；每处理完一个分片把抽取结果追加汇总，不把全部原始文本常驻上下文。
   - **模式二 · 完整读取（小物料未触发分片）**：直接读取完整 seg_text 做信息抽取。
2. 抽取产出物：从多源物料提取业务主干、交互分支、约束、风险、变量、需求要点。
3. 将抽取出的业务要点，送入 **【需求‑结构化拆解引擎】**（第七部分 7.1 九步 SOP），继续执行：隔离构思层 → 提取能力层主干 → 分配编码 → 生成路由索引总表……（完全复用本规范整套生产流水线）。

> 已验证落地范例：本专家方法论产出的 `蒸馏成技能Skill`（平台评分 4.9、使用最多，免费版本）即具备完整的多模态降维（视频/音频/图片 OCR+ASR）、体积分级（S/M/L/XL）、语义分块、多源同投防爆炸、接料失败三分支等能力，上述 6A 各节均已在实际产物中验证落地。其平台评分由平台评定，本章仅作方法佐证，不作任何评分承诺。

## 第六‑B 部分｜素材版本风险防控与对比评审协商（强制关口）

## 第六‑B 部分｜素材版本风险防控与对比评审协商（强制关口）

> 完整细则见 `references/REF-VER-021_MaterialVersionRisk.md`（事前预防 / 事中对比评审协商 / 事后挽救复盘，配套 REF-QC-020 守门自检、REF-LST-022 上架测试验收）。本部分为本技能第一道关口的延伸，解决"高相似度改版材料被浅层判定重复、回一句'有了'、新材料不入库"的致命隐患——本工具自身先过硬，才能替用户守住这道关。

### 6B.1 底层公理

文本高重合 ≠ 业务等效。用户每次独立上传的文件、提交的修改意见、他人提交的评测修改方案，都是独立输入实体；禁止以标题、章节大纲、全文文本重合度、主题名称作为是否解析、是否接收的判断条件。

### 6B.2 "有 / 没有"界定（本项目的最高判定口径）

- **没有**：用户上传一份独立文件，但该文件未进入完整解析链路；或解析后未生成 material_id / version_tag / status；或未向用户展示差异摘要并获得确认；或确认后未写入采信池、未留日志；或仅凭标题 / 大纲 / 相似度被判定"已有"而跳过 → 一律算**没有**。特别锁死一条：**"以为有了、实际没载入" = 没有**。
- **有**：每次独立上传强制全量解析 → 生成 material_id＋version_tag＋status → 解析后向用户展示差异摘要 → 用户选定 A/B 与处置①替换 / ②补充 / ③仅存档 → status 正确变更且旧 active 按规则归档隔离 → 该 material_id 进入采信池 → 全链路日志落档（含差异快照、用户确认原文）→ 质检采信专项校验通过。全链满足才叫**有**。

### 6B.3 同名同结构也必须比对（核心纪律）

比对评审完整逻辑（同名同结构完整比对、写明纳入与不纳入理由、用户驳回重评循环、禁止仅凭相似度回"有了 / 已经做了 / 做好了"）唯一执行源：`references/REF-VER-021_MaterialVersionRisk.md` §2.1；多源同投触发时先读该节再动手。

### 6B.4 事中确认（material_parse 后、draft_build 前强制暂停）

解析完成、对比评审后，向用户展示差异摘要与三选一处置方案，**无用户确认不进入初稿生成**；标准回执模板与素材采信专项校验 4 项见 REF-VER-021。

## 第七部分｜Skill技能搭建专家本体（标准化搭建引擎）

> 定位：专家本身是一套严格遵循全部规范的技能，解决「静态标准文档无法自动落地、从 0 到 1 完成后规模化复用困难」的痛点。

1. 六大子目标

   1.1 内置标准锁：固化全套规范（三层隔离、节点编码、索引格式、模板绑定、素材复用、寻址定向、路由优先级、三级兜底+回拉、防自创）；专家无权私自修改、简化、遗忘标准。

### 7.1 拆解引擎九步 SOP（需求转产出的固定顺序）

> 收到新技能需求后，**严格按以下顺序执行**，不跳步、不夹带构思层进入运行逻辑。

- 步骤 ① 隔离构思层：把用户的口头思路、草稿、发散想法记入归档（仅归档，不写入产出技能的运行包）。运行包只放能力层＋辅助层。
- 步骤 ② 提取能力层：梳理主干业务动作、交互分支、触发条件、输出交付物。
- 步骤 ③ 提取辅助层：列出防呆（跑偏／越界／高危三类）、使用救助（FAQ＋卡点救助）、鲁棒容错、退出撤销、兜底、埋点。
- 步骤 ④ 分配节点编码：给每个节点、输出模板、素材分配全局唯一编码（示例：`MAIN-01`、`BRANCH-01-01`、`FALLBACK-01`）；所有交付用户的输出内容绑定对应编码与路径。
- 步骤 ⑤ 生成路由索引总表：字段＝编码、触发条件、目标动作、绑定模板编号、绑定素材编号、下一跳编码、对应兜底编码（对齐 SKILL.md 第五部分 2.1）。
- 步骤 ⑥ 生成静态模板清单：把固定句式、固定回复、标准文案预封装为编号模板，与节点一一绑定；仅动态变量（用户输入、第三方实时数据）允许注入占位符，其余文字不得由模型现场生成。
- 步骤 ⑦ 生成素材关联表：所有外部素材（文档／图片／文件）分配独立素材 ID，记录「可被哪些节点编码调用」，支持一对多复用。
- 步骤 ⑧ 选骨架档位并产出全套物料：依据 `references/REF-SKL-007_SkillSkeleton_v1.md` 选档（极简／标准／重型）并套用对应档位骨架，填入上述物料＋立项表单（见 `references/REF-INT-015_InitForm_V32.md` 历史存档，新立项用本规范第四/六/七部分）+ 测试用例；同时按 `references/REF-NAM-006_NamingDiscovery.md` 完成命名与可发现性布词、按第二/三部分套用版本与形态规范；封装出包前按 `references/REF-BSE-047_DeliveryBaseComponent.md` 将 REF-BSE-047 挂载块（标准化技能交付框架）内联产物说明文件正文最前（业务内容后置），并跑 `scripts/base_block_scan.py` 校验通过方可出包。立项定位与布词取舍按 `references/REF-POS-063_PositionKeywordStandard.md` 执行（立项三问定位刻度＋布词「去重不去钩」）。
- 步骤 ⑨ 跑评审自检：对照本规范全部校验项（第九部分 30 项）逐项打分（或调用 `scripts/selfcheck_factory.py` 做结构机检），输出偏差报告，进入第八部分评测与第十一部分出厂闸。

## 第八部分｜五维评测基线（内置通用质检标准 · 技能质量标准）

## 第八部分｜五维评测基线（内置通用质检标准 · 技能质量标准）

> 本评测模块为专家**内置的技能质量自检基线（生产方内部工程核验，非平台评级）**，五维核验为定性达标判定，不打分、不评级；结论不映射、不承诺任何平台评分或评级结果。

> 两种执行模式：

> ① 流水线自动检测模式：嵌入技能生产流水线，**可信任度维度安全基线不通过直接阻断技能Skill产出**；其余维度不达标，标记风险、给出整改建议，可选择放行测试。

> ② 用户手动调用评测模式：仅输出五维评测报告+安全检测结论，不阻断任何产出，由开发者自行决定是否整改。

> 触发方式：流水线出厂默认自动检测；同时支持开发者手动调用评测模块。

1. 五维定义（校验顺序严格递进：可信任度→可靠性→适用性→规范性→有效性，前序不通过直接终止评审，一票否决；五维核验细则＝核验检查项＋开发要求＋评测要求成对条款，统一见 `references/REF-SPC-001_AISkillManual_V32.md` §3.4.1a）

   1.1 可信任度（前置红线项，绑定安全基线）

   > 安全基线准入（必须全部通过，否则本维度不达标；由 `scripts/skill_quality_check.py` 实扫产物内容核验，不读自报通过标记）

   >

   - 供应链风险：无不可控第三方依赖、无恶意依赖包；
   - 命令执行风险：无危险系统命令、子进程调用；
   - 网络请求与数据外传：仅调用业务必需链接，不私自采集、外传用户隐私、手机号、账号标识等敏感信息；
   - 文件操作与敏感路径访问：不读取系统敏感凭证、不越权访问本地敏感文件；
   - 注入防护：内置注入过滤，隔离用户输入与系统提示词；
   - 远程脚本下载执行：禁止自动拉取远端脚本执行；
   - 可疑编码/混淆：无加密逃逸、无恶意混淆代码；
   - 其他安全风险：无隐藏埋点、无隐性违规逻辑。

   > 业务评分项：合规边界清晰、权限最小化、敏感信息保护、风险前置告知、中文交互友好、针对目标生态适配优化；高风险品类只提供方法框架，不做确定性建议。

   >

   1.2 可靠性

   相同输入输出稳定一致；边界异常输入友好处置；接口超时、限流、网络波动场景内置重试、超时止损、失败通知机制；不静默崩溃、不空白输出；故障时明确告知用户卡点，不无限等待。

   > 比对短板补强：补齐自动重试、异常降级机制，不单纯依赖用户补充信息。

   >

   1.3 适用性

   适用场景清晰、能力边界明确、前置门槛说明清楚；同时兼顾小白用户和进阶使用者；提供入门引导、菜单化交互，降低上手成本；明确标注能力盲区、功能限制（例如外部数据结果受第三方平台库存、账号规则影响，不承诺 100% 达成）。

   > 比对短板补强：降低小白门槛，菜单引导，前置说明限制。

   >

   1.4 规范性

   文件目录结构标准化、元数据文件完整；文档分级编排、主次分明；配套独立 FAQ 快速答疑区；节点编码、路由规则长期稳定；入参、出参、模板、素材索引文档齐全；交付物自带溯源与结果边界说明。

   > 比对短板补强：文档分级、独立 FAQ，避免文档冗长杂乱。

   >

   1.5 有效性

   业务目标明确、链路闭环；交付物可直接落地使用，不需要大量二次改造；覆盖标注的业务场景；输出结果精准、格式结构化。

   > 业务核心指标（中性）：交付物稳定、可复现地提供其声明的能力入口与完整链路，结果可追溯、可核验。

   >
2. 运行规则

   2.1 校验顺序严格固定：可信任度→可靠性→适用性→规范性→有效性；

   2.2 前序维度不达标，直接终止评审，不进入下一维度；

   2.3 评测报告交付时，同步正向肯定用户的开发成果，客观说明问题，不否定用户全部投入；

   2.4 内部自检定性结论（仅用于生产方工程核验，非平台评级，不构成对最终平台评分的任何承诺）：内部核验仅区分「达标 / 待优化」两档，驱动内部整改优先级，**不设分数、不设分级区间**；对外评测报告（模板B）不出现任何分值与评级（本包铁规），最终上架评分以平台为准。

## 第十部分｜全局路由调度规则（Agent 执行判断逻辑）

## 第十二部分｜出厂质检闸门与生产自监管护栏（运行层 · 本专家独有）

### 12.1 双闸门定位（消除冗余观感）

- **第一道闸 · 立项前置（第四部分 前置校验组）**：动手做之前，判定"想法该不该做"。
- **第二道闸 · 出厂质检（第八部分 技能质量标准五维＋安全基线八维）**：做完了要出包时，判定"成品达不达标"，最低准入红线，不达标一律拦截。
- 两者阶段不同、对象不同，不重复不漏检。

### 12.2 技能质量标准五维出厂质检（最低准入，fail-closed）

- 技能质量标准 是本项目内置五维自检基线（T/R/A/C/E 五维定义与递进一票否决规则唯一真源＝第八部分 §1），仅作开发者自查，不代表任何平台审核结论；T 维绑定安全基线八维实扫；最低准入而非最高要求：达标只是入场券、不承诺满分，标准、产物、评测三者同源同尺，否则测不住。


- 自动执行：流水线打包前默认跑（见 12.4 装配闸门 + `scripts/skill_quality_check.py`），同时开放独立接口供手动评测任意包。
- 评测只扫产物实际内容、不读自报通过标记，结果签名留痕，不可静默重生成。

### 12.3 自监管五层护栏（防尺度失守 · 防规则失效）

立法（写标准）、生产（产技能）、评测（技能质量标准）三线合一，无外部制衡时存在两类风险：① 尺度失守（尺子被放宽松）；② 规则失效（运行没生效/被绕过/被瞎执行）。护栏：

- **L1 标准锁不可篡改**：标准作只读锁，启动哈希校验，不符/缺失 → 起点 fail-closed 拒绝启动。
- **L2 评测与生产隔离**：skill_quality_check 只扫实际产物，不读自报通过标记；探针用例库版本钉死、生产不可编辑；评测结果签名留痕。
- **L3 步骤不可跳过 + 偏离即拦**：9 步每步中间资产可探测，缺则中断；偏离超阈值进修正闭环。
- **L4 全节点埋点**：编码命中/兜底触发/流程回拉三类事件埋点，零埋点即告警。
- **L5 外部独立复检**：manual_quality_check 让不同人/独立 Agent/陌生账号跑同一 skill_quality_check，作为尺度失守的终极防线（必要非充分）。

### 12.4 双开关与装配闸门（出厂质检默认配置）

双开关配置（`auto_quality_check` / `manual_quality_check`，落点 `factory_config.json`）与装配交付闸门六步（目录 name＝slug＝目录名一致 → package_check → stamp_signature → skill_quality_check → package_zip 自动复检未过退出码 5 拦截 → 任一闸门 FAIL 禁止交付、回到第七部分修正引擎）——完整细则唯一执行源：`references/REF-QC-020_QualityGateModule.md`「十、出厂双开关与装配闸门」；出包流水线触发时先读该章再动手。

### 12.5 自检留痕与漂移回溯（持久化自检报告）

每次构建必须产出并归档一份结构化自检报告，落点 `logs/QUALITY_<构建号>_<时间戳>.json` 与 `.md`（logs 为内部私有区域，永不入对外交付包），字段固定：构建编号、校验时间、逐分类逐项的通过/不通过、命中违规项（位置/条目/整改指引）、素材采信快照（material_id / version_tag / status / 用户确认方案）、整改次数（retry_count）、最终结果（pass / fuse_abort）、签名摘要（包哈希＋标准哈希＋逐维结论＋时间戳）。出现漂移时可精准定位是哪一条规则、哪一轮出问题，用于复盘迭代。完整细则见 `references/REF-QC-020_QualityGateModule.md`。

> **检查失效显性化（自检降级）**：质检节点或机检脚本失效（无法运行／结果为空壳／环境不支持）时禁止静默继续：① 显性输出「本轮检查未能执行，结果不可采信」；② 交付物标注「未经完整机检」；③ 恢复后补检并更新报告。

### 12.6 修正闭环：重试上限与熔断

定向整改采用有界重试：`retry_count` 每次进入修复前 +1，任务结束自动清零；`max_retry` 固定等于 3，不可修改。校验失败且 `retry_count < 3`：回传违规清单定向修复、仅改违规项、其余保留、修复完自动复检；校验失败且 `retry_count >= 3`：触发全局熔断、终止任务、输出告警、不再继续生成。质检节点系统约束见 REF-QC-020：「你仅执行扫描比对、标记违规项、输出结构化报告；禁止修改内容、禁止放宽规则、禁止自主放行；不做内容创作。」

> **同族普查纪律（整改必经两步）**：① 动一处前先普查同族全部调用点（同句式／同锚点／同清单成员／同映射）逐一同步——修一处不改同族＝没改完；② 修好当轮故障注入验证：故意触发一次原故障，确认闸真能拦才算收口

### 12.9 代建交付收口工作流（成品真正交付闭环）

## 第十三部分｜REF-NAM-006_NamingDiscovery

> 本规范回答"技能如何被搜到、上架前怎么核"，是链路1 构建的前置必过项。完整判据见 `references/REF-NAM-006_NamingDiscovery.md`。

1. 名字点题、关键词指路（判据 K-16）：名称只做总览（平台硬上限通常 12–18 字），简介＋关键词是详细说明；名字点题、关键词指路，不指望名称承担全部检索职责。

3. 四维递进模型（3.4b，用户按什么搜到本工具）：动作 → 动作+对象 → 对象+动作 → +结果，四层递进落点。三维管"写什么词"、四维管"怎么连成整串"，两条都过才算布词完成。
4. 落词纪律（判据 K-13~K-17）：关键词必须是"用户此刻真实处境"的组合；生活化词与行业术语两套都要；长尾要够长（按"独立问题说法覆盖数"报数，不按词条个数）。
