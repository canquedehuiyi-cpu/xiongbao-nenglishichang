# REF-DMN-019_DomainComponentBoundary（机制通用化 · 插件化）

> 本机制是Skill技能搭建专家的「领域能力插件化」扩展能力，使专家除产出标准技能Skill外，还能安全、可复用地沉淀「领域组件」——即与具体业务解耦、可跨技能复用的通用方法论、模板、判据模块。

> 本文件为**标准层**通用机制，不绑定任何具体业务品类；具体领域（如优惠领取类）仅作方法演示，见 `references/REF-DMN-005_CouponExample.md`。

## 一、核心思想

1. **机制通用化**：把「如何产出可复用组件」「如何安全地吸收外部领域经验」固化为通用流程，与具体业务解耦。
2. **插件化**：每个领域作为独立插件接入组件库，目录隔离、互不污染；新领域接入不改专家主干，只挂新插件。
3. **安全吸收**：外部领域的经验不是照单全收，而是经「三类入库边界」逐条判定后，分流入库、沿用、或红线排除，杜绝把低质/踩线资产混进标准。

## 二、领域组件库结构

领域组件以独立目录挂载，建议形态：

```
components/<domain>/
  SKILL.md            # 组件卡：能力边界、适用场景、调用方式、红线
  references/         # 该领域专用判据（可选）
  templates/          # 该领域模板（可选）
```

组件库本身不进用户产出物（遵循分层隔离铁律：标准层不打包进交付）；仅当某组件被某次生产实际调用时，才按需求摘取进入该技能Skill的运行层。

## 三、三类入库边界（关键纪律，防污染）

任何外部领域经验入库前，必须逐条判定归属，三选一：

### 类别一 · 可复用通用类（准入标准库）
- 特征：与具体业务解耦、跨领域可复用的方法论 / 模板 / 判据 / 通用合规原则。
- 处理：提炼为通用机制，写入专家 `references/` 标准库，成为基座能力，被后续生产直接复用。
- 示例：领域组件库机制本身、概率性结果前置告知、仅做入口不控平台侧、禁静默批量请求、最小权限等通用原则。

### 类别二 · 仅体验类（对照形态，不入库）
- 特征：某领域优秀的**交互体验、话术、流程编排思路**，但其业务逻辑不可直接复用。
- 处理：仅作「体验说明」，记录交互形态要点；不复制其业务逻辑，不进标准库，不进用户产出物。
- 示例：菜单化交互编排、分层文档结构、FAQ 唤起方式等形态经验。

### 类别三 · 禁止复用私有资产类（红线排除，仅作反面清单）
- 特征：含密钥 / 推广参数 / 佣金归因 / 用户隐私 / 平台违规操作（后台静默批量请求、自动化抓取、自动领取等）的资产。
- 处理：**一律禁止入库**；仅列入「反面红线清单」作为禁区记录，供后续识别与拦截，绝不进入任何技能产出物。
- 示例：平台账号密钥、携带推广 ID 的归因链接、自动领券脚本、爬虫式采集逻辑。

## 四、入库流程 SOP（固定顺序）

1. **采样**：收集该领域已有资料 / 历史案例 / 同类产物。
2. **逐条判定**：对每条经验按三类边界归类，不模糊、不混装。
3. **通用提炼**：类别一经验抽象为与业务无关的机制，写入标准库。
4. **形态摘记**：类别二经验仅记交互形态要点，标注「仅作说明」。
5. **红线归档**：类别三经验登记进反面清单，明确禁止。
6. **挂载插件**：若形成可复用领域组件，按第二节结构挂入 `components/<domain>/`。
7. **自检**：对组件卡跑 技能质量标准五维（五维递进）+ 安全基线八维，未过不入。

## 五、与现有专家能力的衔接

- **拆解引擎九步**（第七部分 7.1）可扩展产出「领域组件」：在步骤⑧选骨架时，组件卡按轻量档骨架产出。
- **自检引擎 / 技能质量标准 评测**：领域组件同样适用第九部分 30 项与第八部分五维，标准自洽、不双标。
- **分层隔离**：组件库属标准层；仅被实际调用时，相关片段进入目标技能运行层，构思层与私有资产永不进交付。
- **三类边界与 REF-FOP-065 第四部分 4.3 通用概率性结果合规原则、SKILL.md 第八部分 13 同源**：凡概率性结果一律前置告知、仅做入口、禁静默抓取，本机制不另立标准。

> 本机制的价值不在「多存了多少案例」，而在「把喧嚣、低质、踩线的领域，安全地收敛为通用能力 + 红线清单，不产出伪能力」。
