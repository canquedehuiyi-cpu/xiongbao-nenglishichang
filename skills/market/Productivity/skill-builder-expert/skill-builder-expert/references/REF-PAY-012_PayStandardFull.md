# REF-PAY-012_PayStandardFull（上架合规与支付接入标准）

> 本文件是专家"收费版本"的支付接入与计费配置唯一事实源。免费版本不得含任何收款环节。

> 凡涉及计费与支付，**陌生环境实跑是终极标准**；AI 无法替代用户的真实支付实测。

## 零、成本账四步法（收费决策测算层 · 前置必答）

> 定位：本章回答「该不该收费、值不值得配」，一至十五章回答「怎么收、怎么接」——顺序不可倒，先算账后动手，算错科目，越优化越亏。本章数字只给方法与量级示例（量级核对日期：2026-09；模型价目随厂商变动频繁，一律以官方定价页当期为准），不预填具体厂商价目。

### 第一步 · 成本归属先分清（三层）

| 层 | 内容 | 花钱配生成力能解决吗 |
|---|---|---|
| 用户侧 | 终端用户用什么平台、什么模型 | 不归本工具管，也不需要管 |
| 逻辑层 | 流程、门禁、校验、兜底、内容库 | **完全不能**——这是代码与规则的活 |
| 生成力层 | 把素材加工成成品的最后一步 | **能**——这是花钱唯一买到的东西 |

判定铁律：实测遇到的失效先归类——属逻辑层的失效（流程卡死、空壳产出、边界识别失效），配生成力一个都治不了；**能用逻辑层（代码规则）解决的，不许用生成层（花钱调模型）解决**。

### 第二步 · 单次成本实测（两本账）

- **钱的账**：以真实调用链的完整输入为样本实测字符量（不拍脑袋估算），按厂商定价页当期价目折算单次成本；**输出侧是大头**——推理/思考类输出的量常为普通输出的数倍，账单翻倍就翻在这。再按目标用户量 × 人均调用次数折算月/年成本，与拟售价对比得出成本占比；按次收费场景，毛利 =（售价 − 单次成本）÷ 售价。
- **复杂度的账**：为省钱而新增的防护、降级、观测、维护——单价是时间与精力。实测经验：**钱的成本接近 0，复杂度成本占比接近 100%**。先算清成本长在哪一项再动手；为省小钱引入大复杂度，是这类账里唯一确定亏本的地方。

### 第三步 · 效果盲评（不承诺更好，只验证更好）

- **原则**：引入付费生成力 ≠ 效果必然更好——上限更高、下限更低是常态；配套防护兜的是下限，不拉上限。「配了就更好」这句话不允许说，也不允许写进任何交付物。
- **方法**：取 10 条真实素材，新旧两条生成路径各跑一遍；打乱顺序盲评，四维各 1–5 分（结果可辨识度 / 结构拆分度 / 隐含信息挖掘度 / 表达可读性）；由包属方或独立方打分，产出方不参与。
- **判定**：新路径平均分不明显高出（低于 15%）就**不引入**——省下整套复杂度。

### 第四步 · 三档路线（先借后买）

| 档 | 做法 | 成本 | 适用 |
|---|---|---|---|
| **A 借力档（默认）** | 只出结构化规格与模板，成品文字由宿主平台自带的模型生成 | 零 | 默认路线，先验证 |
| **B 兜底档** | 自配轻量模型，仅在宿主写不出来时补位 | 极低（单次约分钱量级，以当期价目为准） | A 档验证不足时 |
| **C 转嫁档** | 按次收费把生成成本计入售价 | 已覆盖 | 商业化阶段 |

- **顺序铁律**：先 A 后 B，B 只做兜底不做主力；宿主平台本身就有生成力，**能借的力先借，借不动再自己买**。
- **与本文件其余章节的关系**：三档路线选定 C 才进入一至十五章的收费接入流程；A / B 档不涉及收款环节。

### 减法闸（新增能力配额纪律）

1. 任何新能力，先证明「不加它不行」才允许加；
2. 每个新增组件必须对应一个**已实证的失败**（有日志 / 截图 / 复现步骤），不接受「为了更稳」「以防万一」；
3. 每个新增组件必须同时给出**退出条件**：什么情况下把它删掉；
4. 成本科目先分清：**钱的成本 vs 复杂度的成本**，后者单价是创作者的时间。

## 一、两档 slug 并存策略
- 同产品免费档 + 付费档用**不同标识**、互不覆盖（示例：免费档标识 `your-skill-free` 与付费档标识 `your-skill-paid` 须区分，不得混用同一标识）。
- 免费档不得含收款环节；付费档不得出现"免费/不收费"等误导词（免费话术 0 命中）。

## 二、计费骨架五处一字不动
金额计算 / 幂等 / 对账 / 异常表 / 防造码——只填参数，不重造逻辑。改动计费骨架属于高危，须经八步闸门（见六）与陌生账号实测双重确认。

## 三、SkillPay（支付宝）/ X402（微信）商户接入
- 凭 `merchant_id` / `product_id` 接入；`api_endpoint` 走自有备案域名反代（如 `api.sizhushou.com` 443 反代到内网 8080），公网直连非标准端口口子默认关闭。
- 密钥服务端持有、包内零落密钥；`allowed_domains` 白名单仅放支付域名。
- 口令/私钥只存在于服务端 `.env`，任何文档与交付包一律占位符，绝不落明文；会外传的三处必须 0 密钥。

## 四、付费能力判据纪律（防自我预言式拦截，基于本体系付费能力判据）
1. 能力判定优先"实试"，不靠"预判"；涉及计费与支付，陌生环境实跑是终极标准。
2. 判据只许拦"能确定判死"的项（如接口不可达）；不足以判死的项（如"宿主工具列表里没看到某前缀"）不得停。
3. 按结果分流出三态：走通 / 走不完（给可执行替代）/ 压根发不出去（重试或异常收口）；不许写成二选一。
4. 降级方案永远是最后兜底，不是第一反应；一遇不确定就降级为免费引导，等于把可能的成交直接送掉。
5. 承载端不决定能不能付费——同一平台上架的技能在多个宿主端调用时报的是承载平台头，要用平台头去核，不要用端去猜。

## 五、防黑洞五步（每个平台壳部署完必做）
黑洞 = 壳没弹支付、直接用平台自带模型把答案答了。
| 步 | 操作 | 正常 | 黑洞 |
|---|---|---|---|
| 1 | 像真实用户问"知识库怎么搭建" | 弹支付（或 402） | 直接给答案 |
| 2 | 扫码付 | 付完返回文档（带边界说明 + 联系方式） | 付不了／答的是编的 |
| 3 | 同会话再问 | 仍弹 402 再收一次 | 直接免费答了 |
| 4 | 问垃圾话 | 仍弹 402（不留白嫖口子） | 直接免费答了 |
| 5 | 看付完的回答 | 带会员引导／边界说明 | 什么都没有 |

## 六、出包八步闸门（paid-version-bump）
红线扫描 → selfcheck → check_links → 计费口径＋免费话术 0 命中 → 出包 → MD5 比对 → `.md5` 锁 → **陌生账号实付实测（铁律，AI 做不了，交用户，不过禁分发）**。

- 付费包正文不得出现"免费/不收费"等误导词（purity_scan 正则扫）。
- 红线扫描同时扫绝对路径与违规词，上线前必过（与全局可移植约束同源）。

## 八、版本六处同步 + MD5 锁
SKILL.md `version` / `_meta.json` / INSTALL / LISTING / README / zip 文件名 六处一致；出包后 MD5 比对落锁。构建可复现是上架交付硬属性：同源、同脚本、独立跑两次，zip 的 MD5 必须相同（打包脚本不能把"打包时刻"写进 zip）。

## 九、三层验证（收钱链路分级判据）
| 层 | 测什么 | 判据 | 状态 |
|---|---|---|---|
| L1 直连链路 | 门本身能不能收钱 | 人工 curl → 真弹 402 → 真扫码扣费 → 真返内容 | 已实测 |
| L2 Agent 撞门 | 平台内 Agent 会不会主动 POST | 统计出现该平台 | 待验证 |
| L3 陌生号真付 | 端到端 | 统计出现 且 付费>0 | 待验证（必须陌生号，自己+自己的号测不出白嫖行为） |

L1 通了只说明"门能用"，L3 通了才叫"这门能收钱"，中间隔着一整个平台。

## 十之二、收费路线五：独立积分制（选型备选）

> 定位：一至四章四条路线均为「平台代收」（平台托管支付与结算）；路线五是「自建账户计量」——预充值积分、按次扣减、余额不足才拉起充值。自建负担重、适用面窄，**仅作选型备选项，默认不作为首选**；选定前应先过零章成本账四步法。

### 5.1 模式定义

- 用户先充值换积分（积分与现金换算比率固定且置顶公示），每次消耗型调用按积分扣减；
- 余额充足时静默扣费，不足时才发起充值支付；
- 余额与消耗记录对用户可查。

### 5.2 适用边界（三条同时满足才考虑）

1. **消耗可计量**：每次调用成本能折算成固定积分档位——查询 / 生成类单次边际成本近零的产品形态最合适；
2. **后端具备账户能力**：积分账户、扣费流水、余额查询、幂等去重全部自建或托管，缺任何一项即不具备条件；
3. **赠送额度不得触碰核心交付物**：赠送类额度只能送「边际成本近零的次数」，不得送核心交付物本身——免费收料 / 引导 / 梳理部分本身已是获客漏斗的产品，不再叠送付费产品次数（自断营收）。

### 5.3 与四条平台代收路线对照

| 维度 | 平台代收（路线一~四） | 独立积分制（路线五） |
|---|---|---|
| 支付与结算 | 平台托管，资质门槛低~中 | 全部自建，资质与合规自查 |
| 用户理解成本 | 单次付费一眼懂 | 换算比率必须置顶公示（充值金额=积分、每次消耗=积分），否则弃用率高 |
| 资金流 | 平台结算提现 | 先充值后消耗，属预收资金 |
| 防套取 | 依赖平台机制 | 积分与交付绑定，账户体系天然隔离 |
| 建设成本 | 低（接入既有插件） | 高（账户 / 流水 / 对账 / 退款全链路自建） |

### 5.4 三硬线（充值 / 扣费 / 退款）

1. **充值**：换算比率固定唯一、置顶公示；每笔充值唯一单号、幂等去重、进对账流水；促销类「多送积分」不得与基础换算比率混淆展示；
2. **扣费**：余额充足才执行；「先扣后履约」或「先履约后扣」二选一并写死在产物规则里；扣费失败不得部分交付；消耗记录逐笔可查（时间 / 积分变动 / 对应服务）；重试复用同一单号，防重复扣；
3. **退款**：未消耗积分可退，规则与入口在上架前公示；已消耗部分不退；退款走原路；平台隔离（无人工通道）场景下，退款规则必须写成产物内置话术，不得引导用户向人工渠道寻求处理。

### 5.5 出厂纪律

- 路线五产物除走本文件全部通用闸门外，**额外实测三件**：①余额不足时弹充值引导而非报错；②重复请求不重复扣（幂等实测）；③退款规则话术在产物内可检索到；
- 陌生账号实测铁律照常适用：充值 → 消耗 → 余额查询 → 退款申请，全流程真跑一遍才算验收。

## 十一、通用范式六条（详细落地，对应 SKILL.md §2.5）
1. **402 支付握手**：用户请求受限内容 → 技能返回 `402 Payment Required` ＋ 支付要求（含商品标识/金额）→ 宿主拉起支付 → 用户付款 → 用户携支付凭证（如 `payment_code` / `WeixinPay-Required` 回执）重试原请求 → 技能校验凭证有效后履约。未付款前不交付受限内容。
2. **两套密钥区分**：测试密钥 / 生产密钥严格分离；包内一律写占位符（如 `{{MERCHANT_PRIVATE_KEY}}`），绝不落明文；密钥仅存在于服务端 `.env`；轮换 SOP 仅更新服务端两处 `.env`，文档与交付包保持占位符。
3. **幂等**：每笔交易生成唯一 `out_trade_no`；重试、网络抖动必须复用同一单号，防重复扣款；服务端对 `out_trade_no` 做去重。
4. **云端保护 / 原文隔离**：订阅制防套取——核心业务逻辑、数据、模型留在服务端；技能Skill内仅放调用入口、授权校验与轻量编排，不随包交付完整业务实现；用户订阅期内按凭证放行，退订即停。
5. **价格三处一致**：付费包公示价格（LISTING / 介绍页）、SKILL.md 计费说明、实际支付参数下的金额、计费口径、币种三者必须一致；改价须三处同步，否则触发出包闸门拦截。
6. **计费矩阵**：按「平台 × 形态」列出计费方式、费率/分成、结算周期、结算前提，作为选型与验收对照基线（见 §十三）。

## 十二、云端保护 / 原文隔离（订阅制防套取）
> 设计动因：若把完整业务逻辑、提示词、数据随技能Skill整体交付，付费订阅将失去意义——用户一次购买即可无限复制、脱离平台使用。故采用云端保护 + 原文隔离。

- **做法**：技能Skill = 轻量壳（入口 + 授权校验 + 调用编排）；重逻辑在服务端受控运行；用户凭有效订阅凭证调用，服务端按凭证鉴权后返回结果。
- **凭证形态**：订阅令牌 / 支付回执 / `payment_code`，由平台或支付网关签发，技能Skill不持有签发密钥。
- **反例（禁止）**：把核心提示词、私域数据、模型权重打进交付包；把服务端私钥写进文档或包内。
- **边界**：免费版本/轻量模式不涉及收费，按 §3.1 全内置；收费版本才启用云端保护分支。

## 十三、计费矩阵与价格三处一致校验
**计费矩阵（估算，以各平台官方规则为准）**

| 平台 | 计费方式 | 费率/分成（估算） | 结算周期（估算） | 结算前提 |
|---|---|---|---|---|
| 自有宿主开放市场 | 买断 / 订阅 / 内测费 | 平台规则（如约 1% 内测费或平台分成） | 按平台 | 开发者认证 + 技能过审 |
| 微信 X402 企业版 | 按次 / 订阅 | 微信支付费率 | T+1 | 企业商户号 + SkillPay 入驻 |
| 支付宝个人版 | 按次 / 订阅 | 支付宝费率 | T+1 | 个人签约 SkillPay + 沙箱转生产 |
| 其他生态 SkillPay | 试用 → 购买 → 订阅 | 平台/支付宝分成 | 按平台 | 对应生态开发者入驻 + Alipay 签约 |

**价格三处一致校验（出包前必过）**：
1. 取 SKILL.md 计费说明中的金额/币种/计费口径；
2. 取 LISTING / 介绍页公示价格；
3. 取实际支付参数（如 `product_id` 对应单价）；
4. 三者逐项比对，任一处不一致 → 拦截出包，回到修正引擎。

> 工具仅校验「三处是否一致」，不校验、不保证「价格是否合理」「资金能否实际结算到用户账户」——后者取决于平台与用户自身资质。

## 十五、交付物竞品名零命中纪律与中性支付配置模板

### 15.1 为什么必须零命中
分发平台官方审核不接纳竞品分发平台名称；交付物出现任一目标分发市场名称字面即卡审核、无法上架。市场身份在会话层由用户口述绑定，插件匹配只依赖创作者类型与收款路径，包内与交付物一律零市场名称字面（见 SKILL.md §2.7 与 REF-DLV-029 宿主残留防治细则）。

### 15.2 支付通道（中性，可留）vs 分发平台名（竞品，必删）
- **可留（支付事实）**：微信支付 / 支付宝支付 / AI 专属卡 / AI 付 / 402 / Payment Required（口径定稿 2026-11-06 维持；对外表述建议在同段附「接入事实描述，非官方背书」小注，防误读；`external_wording_scan --strict-pay` 为可选严格开关，默认关）。
- **必删（竞品标识）**：任一目标分发市场名称字面（含各市场开放平台表述与「某市场名+版」自我标注形态）。

### 15.3 中性支付配置交付模板（交付物套用，竞品名零命中）
以下为交付物收费配置片段示例，仅声明支付通道与握手，不含任何分发平台名；创作者后台据目标平台 ＋ 类型匹配 channel，构建时注入占位符。
```yaml
# 本技能收费配置（中性声明，无竞品平台名）
payment:
  enabled: true
  channel: wechat_pay        # 微信支付·AI 专属卡；或 alipay（支付宝支付·AI 付）
  handshake: "402 Payment Required"
  entitlement_checkpoint: "{{ENTITLEMENT_CHECKPOINT}}"
  price:
    amount: "{{PRICE_AMOUNT}}"
    currency: "{{PRICE_CURRENCY}}"
  keys: "{{...占位符，零明文...}}"   # 真实密钥仅服务端 .env
# 价格三处一致：本文件 / LISTING / 实际支付参数 金额币种须一致
```

### 15.4 出包闸门
交付物出包前必须运行 `scripts/deliverable_competitor_scan.py <交付物目录>`，对公开文件扫竞品名；命中即 fail-closed（exit 1），回到修正、清掉所有分发平台名后重扫，直至 0 命中才准分发。本闸门只针对「交付物」，不针对本工厂自身 references（工具大脑允许含平台名）。
