# REF-RPT-031 确认节点报告固定格式标准

> 用途：SKILL.md 第六部分 6.2 确认节点铁律的配套物料标准。凡确认节点前必须出具的报告，一律按本标准固定字段模板输出；字段为最小集，**可增列、不可减列**。目的：报告形态不随轮次、不随执行者漂移，用户每次看到的确认依据结构一致，确认成本最低。

> 关系说明：本标准只管「给用户看的确认前报告」的格式；内部机检自检报告字段见 REF-QC-020 第六节，交付回执 A/B 两套见 REF-DLV-029 第四节，素材解析确认回执见 REF-VER-021 第 2.3 节——四者并行，互不替代。

> 报告编号规则：`REP-<构建号>-<当日序号>`（例：REP-16-01），写入报告头部，供后续修复变更清单与回执对账。

## 一、模板 R1：技能质量评测报告（评测转修复确认前，强制使用）

```text
**【技能质量评测报告 REP-<构建号>-<序号>】**

▎1. 基础信息（表格）

| 技能名称 | 版本标识 | 部署形态 | 分发访问模式 | 平台审核标记 | 评测时间 | 依据标准基线 | 报告编号 |

| （用户技能名） | （version/标记） | 轻量内置 / API | 公开模式 / 专用模式‑自用版 / 专用模式‑私域版 | 需平台完整广场审核 / 仅Agent安全校验 / 不涉及 | （时间） | 五维技能质量标准＋八维安全 | REP-xx-xx |

▎2. 优势亮点（五维层面逐条客观列明，写明亮点价值，不夸大吹捧）

| 维度 | 亮点结论（定性一句话） |

| 可信任度 / 可靠性 / 适用性 / 规范性 / 有效性 逐行 | （含八维安全基线判定；不打分、不评级，只写定性结论） |

▎3. 逐项核验明细（表格）

| 编号 | 核验项 | 结论（通过/不通过） | 校验依据 | 位置 |

| P-01 起顺序编号 | | | （写明所依据的规则条款） | （文件/章节/字段级定位） |

▎4. 可提升方向清单（按 6.2 分两类，各自成组；每条固定四段式，缺一不可，禁止只写问题不给依据、影响与方案）

▎4.1 基线红线项（平台规范、安全规则，通用硬性标准）

| 编号 | 位置 | 现状事实（客观描述，不带主观贬义） | 对照规范条目要求 | 维持现状的潜在影响 | 可选优化方案及收益 |

| R-01 起编号 | | | （写明所依据规则条款） | | |

▎4.2 业务可选优化项（不违反规范，改不改取决于用户业务场景）

| 编号 | 位置 | 现状事实 | 对照规范条目要求 | 维持现状的潜在影响 | 可选优化方案及收益 |

| O-01 起编号 | | | | | |

▎5. 强制尾注（6.3 第 4 条原文全文追加，一字不改）

▎6. 决策征询收尾（固定话术一字不改）：以上为本次质检评测分析全部内容。相关参考方案仅供你结合自身业务场景、使用需求综合判断。你可以选择确认调整、部分调整或暂不处理；请告知你的决定，我将按照你的指令执行。（选择分支见 6.4：① 暂不处理→记录评测档案，流程终止，不反复提醒；② 确认/部分确认调整范围→基于本报告开展优化调整，仅处理用户确认条目。）
```

约束：第 3、4 节无问题时输出「本项无不通过记录」，不允许整节约省略；两类可提升项不允许混写在同一组；全报告不出现分值与评级，不出现图示评分类元素与外部标准体系命名元素（违例字面以外置机检词表为准）；每条可提升项四段式缺一不可；评价用词遵照 REF-TMP-003 中性措辞库。

## 二、模板 R2：调整方案确认单（调整执行前，强制使用）

```text
**【调整方案确认单 REP-<构建号>-<序号>】**

▎1. 方案明细（表格，对应报告编号必填）

| 编号 | 对应报告 | 问题点 | 修改思路 | 修改范围（改哪里） | 修改后影响 | 是否纳入本次修复 |

| F-01 起编号 | REP-xx-xx / 用户口述 | | | （文件/章节/字段级） | | □纳入 □跳过 |

▎2. 影响面汇总：本次纳入 N 项、跳过 M 项；新增版本号预分配；不影响区域说明。

▎3. 客观边界提示（6.2 同一套原文，仅信息告知，非确认门槛）。

▎4. 用户确认栏：「请告知修改范围：全部纳入 / 仅纳入编号 ____ / 取消修复。」用户未明确回复前，禁止生成新版本技能Skill。
```

约束：用户口述的新问题（无对应报告）同样入表，「对应报告」列填「用户口述＋现象描述」；「是否纳入」列初始全部留空，由用户回复填充，Agent 禁止代勾。

## 三、模板 R3：修复变更清单（修复交付时，强制随包附带）

```text
**【修复变更清单 REP-<构建号>-<序号>】**

▎1. 变更明细（表格）

| 编号 | 对应确认单编号 | 变更位置 | 变更前摘要 | 变更后摘要 | 影响面 |

| C-01 起编号 | F-xx | | | | |

▎2. 版本凭据：新版本标识、工厂基线版本（factory_base_version）、构建编号、包校验摘要。

▎3. 复测建议：本次改动涉及区域对应的建议实测点清单（逐条列出，不复述通用提醒）。

▎4. 强制尾注与统一收尾话术（6.3 第 4 条 ＋ 6.2 第 4 条，原文追加）。
```

约束：变更清单必须与确认单逐行对账——确认单内「纳入」项每项在清单有对应行，「跳过」项不得出现在清单；出现对不上的行即为违规，须返工。

## 四、执行铁律

1. 三个模板为固定最小字段集：允许按业务补充列与附录，不允许删减既有字段或改用自由散文体替代表格。
2. R1 基础信息表须完整回显四项配置留痕：**版本类型、部署形态、分发访问模式、平台审核标记**（分发模式细则见 REF-DST-034）；用户未确认分发模式时该项标「未确认」，禁止代填默认值。
3. R1 基础信息表须回显**关键词核验计数**一行
4. 评测报告输出重心固定顺序：**缺陷清单 → 根因说明 → 可落地整改方案**；分数仅作辅助标识，不置于报告核心位置、不与曝光/被搜到/订阅量做绑定描述（质检评测分析对外口径全文见 REF-LST-022 第十节）；报告头部固定短句一字不改：「本次为技能质检评测分析，梳理技能优势亮点、识别待优化方向并提供整改建议方案；分析结论仅作技能迭代依据。所有优化方案由你自主评估，是否调整、如何调整由你决定。」
5. 评测报告与全部对外交付文案禁用权属宣称与预期承诺（黑名单见 REF-TMP-003 禁说清单），机检 IC7 联动校验。：keywords 数量＋核心关键词是否置顶＋风险词扫描结果（守门闸第⑦查结论，见 REF-LST-022 第十节）；关键词守卫未过时报告禁止出具。
3. 「版本类型」回显值写法锁定为二选一：**免费版本 / 收费版本**（与选型菜单选项值一字不差）；禁止在报告里写成其他变体写法。
4. 报告一律使用结构化表格/列表输出（与标准总则第 5 条输出产物约束一致），禁止无结构大段文字。
3. R1→R2→R3 编号必须形成对账链：R1 问题编号（R-xx/O-xx）→ R2 方案编号（F-xx，带对应报告编号）→ R3 变更编号（C-xx，带对应 F 编号）；断链视为未按标准执行。
4. 报告编号 REP- 规则与构建编号对账：同一 构建号 内序号递增，跨轮不重号。
5. 本标准不改变 6.2 的确认口径：用户仅确认业务修改范围；风险类信息只展示知悉，不作为执行开关。
