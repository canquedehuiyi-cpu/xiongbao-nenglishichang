# REF-PLA-061 · 跨平台交付章程（标准件三：跨平台交付经验标准化，2026-11-11 备案 125）

> **定位**：本文件是「当前宿主以外 Agent 平台」交付经验的**唯一真源**。触发条件：用户明确要在当前宿主以外的 Agent 平台上架/使用技能、或帮用户做面向其他平台的技能、或目标平台实测出现渲染异常。落点为分册按需读取——不进首响读取路径，不占交互窗口。**平台名单纪律：本包 raw 形态零平台品牌字面，具体平台以机检词表 `scripts/competitor_lexicon.json` 为准（码点转义存储，扫描器解码加载）。**

> **一句话铁则**：目标平台渲染器普遍执行标准 Markdown 严格模式；一切屏面写法以「严格模式实测白名单」为准，生成时一次写对，不留待反复修。

## 一、渲染铁则（四条，逐条带机检尾巴）

1. **侧翼规则**：加粗收符 `**` 前是全角标点（」/】）时，其后必须跟空格/标点/行尾才能闭合；跟文字或符号时整个失配、星号原样露出。** 写法**：失配侧翼补一个空格（宽松渲染器对空格无感，双平台同形）。机检：适配器侧翼复检 100% 焊死（工作区级工具，不随包分发）。
2. **括号加粗**：凡【…】一律写成 **【…】**（括号与括号内文字整体加粗），禁止裸【】。机检：出包闸全包清零复检。
3. **段落独立**：标准 Markdown 单个换行＝软换行合并成段——屏面的 ▸/①/（A）/👉/💡 标记行必须行间空行独立成段，否则塌行。机检：适配器段落化＋visual_layer_scan.py R 系闸。
4. **围栏同塌**：```text 围栏内的单换行同样塌行（模型照抄围栏内容输出）——围栏内屏面同样段落化；```json / ```yaml / ```bash / ```thresholds 为代码配置，豁免不动。

## 二、屏面语法白名单／黑名单（按渲染器行为描述）

| 形态 | 判定 | 说明 |
| --- | --- | --- |
| **【口令】** | ✓ 白名单 | 严格模式实测稳定加粗 |
| **「口令」** 后跟标点/行尾 | ✓ 白名单 | 侧翼闭合成立 |
| **「口令」** 后紧跟文字 | ✗ 黑名单 | 收符失配露星号 |
| 裸【…】 | ✗ 黑名单 | 违反括号加粗纪律，教坏模型复述 |

## 三、出包适配流程（确定性投影，不做第四条独立包线）

1. 基准包过全套门禁（唯一语义源）；2. 渲染适配器（工作区级工具）做确定性投影：只做渲染层变换（侧翼补格＋段落化），零语义改动，自验星号零残留＋版本/名称断言；3. 四线核验器核版本一致（基准/自用/宿主形态/目标平台投影），缺线禁分发。更新目标平台版本＝跑一次适配器，禁止手工改投影包。

## 四、跨平台交付清单（五项，逐项过再交付）

1. 屏面写法生成时即按第二节白名单（不要事后修）；2. 交付前跑侧翼＋段落化机检；3. 提醒用户**必须实测**：不同账号、不同模型、不同平台多维测试（见交付完成屏测试纪律）；4. 问清目标平台：不说默认按当前交付标准执行，上其他平台回炉适配；5. 交付后留存平台适配备忘（哪平台哪规则），版本更新时逐线同步。
