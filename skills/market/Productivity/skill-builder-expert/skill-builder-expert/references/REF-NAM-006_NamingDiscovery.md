# REF-NAM-006_NamingDiscovery

> 本规范回答"技能如何被搜到、上架前怎么核"。是链路1 构建的前置必过项，与品类无关、任何技能都适用。

> 唯一事实源判定以本文件 + `REF-SPC-001_AISkillManual_V32.md` 为准；正文不再写死判据条数，避免口径漂移。

## 一、因果链顺序（不可颠倒）
| 环节 | 是什么 | 关系 |
|---|---|---|
| ① 能力是第一要务 | 真能解决问题、能构建闭环 | 兜底 |
| ② 被看见 | 能力再强，没被看见等于不存在 | 前提 |
| ③ 被看见的前提是能被搜到 | 用户不逛市场，他只搜 | 前提 |
| ④ 能否被搜到 | 取决于三个维度的词有没有铺满 | 落点 |

硬判据：在讨论曝光、排名、关键词之前，先回答"这件事这个技能真能办成吗"（判据 E-05）。能力不闭环，做得再好也只是被看见过一次，然后没有第二次。

## 二、三维度提问面（判据 K-10/11/12）
用户开口问的是三句话，缺一个就永远接不住这类提问：

| 维 | 用户脑子里的那句话 | 内容 | 最易漏点 |
|---|---|---|---|
| 维度一 | 我为什么需要它？ | 使用时机、想解决的具体麻烦、想达成的目的 | 在四维递进里没有独立位置，必须单独成清单，不许并进能力维（K-11） |
| 维度二 | 它能帮我做什么？ | 对什么原料下手、会做什么动作 | 落在四维递进第①②③维 |
| 维度三 | 我能拿到什么？ | 把现有东西变成他想要的那个东西 | 落在四维递进第④维 |

- 三维与四维是正交的两件事：三维管"写什么词"，四维管"怎么连成整串"，不许互相替代（K-12）。两条都过，才叫布词完成。
- 查某个包铺没铺满，只问三个问题：他什么情况下会想起这个技能？他会拿什么东西来试？他拿到的是什么？三个都能具体答上来才算铺满。

## 三、四维递进模型（3.4b，用户按什么搜到本工具）
动作 → 动作+对象 → 对象+动作 → +结果，四层递进落点。只报三维齐全会漏掉需求场景维；只做连法会只剩零件。本模型已取代旧"三维检索穷举表"，二者不并存。

## 四、命名层（判据 K-16 / 145 / 158~161）
- **名字点题，关键词指路**：名称只做总览（平台硬上限通常 12–18 字，过长则记不住、无辨识度）；简介 + 关键词是详细说明，逐条指明每个方向与位置，正是长尾容身之处。
- **主词判定三问**（都过才当主词）：是人话吗（用户会不会这么说话）／有没有别的更强势含义／用户会不会主动打这个词。例：`代建` 主词判定三问全否 → 主词应是「技能」而非「代建」。
- **「技能」是搜索词不是命名词**：头部表达"能装的包"用的是 助手 / 分析 / 器 / 专家；要在名字里用「技能」附近必须有中文锚定词（如"技能Skill"）把语义钉死。
- **英文形态后缀 `skill` 是形态标记**（像 app／插件），不负责被搜到；命名层给人眼，检索层给中文整串。

## 五、落词纪律（判据 K-13~K-17）
1. 关键词必须是"用户此刻真实处境"的组合；把每个词还原成一句用户真实处境，还原不出来的功能名一律删（K-13）。
2. 生活化词与行业术语两套都要，分别验命中；只埋一套等于漏掉一半人（K-14）。
3. 长尾要够长：用户问题千变万化，只有铺到足够细的长尾才有足够多入口（K-15）。
4. 报数口径：数"独立问题说法的覆盖数"，不数词条个数（K-15）。
5. 列问题按"Agent 拿结果要去解决的活儿"列（文件／音视频／会议／写作／查询／转换…），不是按人在聊天框里会打什么短问句（K-17）。

## 六、前 50 字落词（基于实测台账）
- `description` 前 50 字必须含检索词且无红线词；这是平台抓取与用户第一眼决策的关键区。
- 落词后做"是否出现其他在售包名""有无旧口径串""api_endpoint 是否指向新付"三查，任一项命中即回修。

## 七、可沉淀判定模型（A/B/C 要素加权）
判定一段经验或做法值不值得封装成技能，按三个要素加权评估：
- **A（经验依附于人，高权重）**：换个人执行效果明显下降，新人难以接手；只有少数人掌握，全凭手感或脑子记；本人说不清做法但实际做得好；
- **B（重复且结果波动，高权重）**：长期重复执行同类事务；结果时好时坏、不同人执行差异明显；每次执行都要重新琢磨，同类问题反复出现；
- **C（复用与传递诉求，中权重）**：想固定下来长期复用；想提升效率或降低执行波动；想传递给团队其他成员。

判定规矩：
1. A、B 同时命中 → 判定成立，进入封装评估；
2. 仅命中其中一项 → 弱信号，先向用户复述对齐确认，不直接下结论；
3. 单次事故复盘、临时向外求方案、纯情绪表达 → 判定不成立，不引导封装；
4. 行业或表述无法完全识别，但 A、B 命中 → 判定成立，按通用流程承接。

本模型用于三处统一口径：接料阶段的价值判定、命名发现的前置评估、边界类答疑（什么适合做成技能）。

## 八、承接诊断四类与第五态（按原料与目标性分流）
用户表达沉淀意愿时，按其拥有什么、目标是否明确分四类，另设一种暂无产出条件的第五态：
1. **底稿与经验兼备**（教案、案例、图纸、提示词等资料与个人经验都有）→ 定位整理者，直接结构化承接，难度低；
2. **仅流程标准**（流程、规范、步骤、量化资料齐备，个人经验占比低）→ 定位规范化承接，资料输入即成型，难度低；
3. **仅经验可口述**（全在脑中，无底稿无资料）→ 定位口述提取，走代建快通道逐段承接，难度高但价值最大；
4. **仅零散收藏**（无体系无产出，见好就存）→ 先引导明确用途与目标，再判断是否有沉淀价值，避免无目的堆积；
5. **第五态·暂无可沉淀条件** → 引导自查挖掘：每日每周重复做的事、固定做法与流程、判断标准、踩过的问题与修正方法。

分类作用：预判承接路径与工作量、向用户如实说明难度与产出形态，不夸大、不劝退。

## 九、口语表达解析口径（先剥离噪音，再判定）
真实用户的表达普遍存在六类特征：不用专业术语、诉求碎片化、使用行业黑话、夹杂情绪表达、叙述随意跳题、使用省略背景的熟语式表达。

解析规矩：**先剥离噪音，再判定诉求**——抓用户要解决的内在问题要素，禁止按预设例句做字面死配；语义与字面不一致时以内在诉求为准，拿不准先复述确认。本口径是自由语义触发（两车道一轨道）的解析前置层。
