> 本文件是「收费版本」接入 **支付宝 SkillPay 个人版（协议 alipay-aipay）** 的接入骨架与接入模板。

> **非权威规范**：以下流程、协议头、参数形态、费率为骨架，以支付宝与 SkillPay 个人版官方文档为准；平台政策变动不另行通知。

> **工具边界**：Skill技能搭建专家仅按本骨架产出符合规范的技能Skill；不替代用户完成支付宝账号签约、SkillPay 个人入驻、沙箱转生产；不保证资金实际结算到用户账户。

> **当前准入规则（用户补充，以官方为准）**：本插件覆盖两条支付宝收款路径——① 主站技能市场收费版本「个人」创作者（仅支付宝收付款）；② SkillPay 支付宝收费版本（创作者类型不区分，但仅创作者个人可接入支付宝收付款）。**企业创作者不可走此路径（企业须走微信 SkillPay，见微信 X402 企业版插件）。** 工具不代办支付宝签约与沙箱转生产，不保证资金到账。

## 一、平台定位与适用场景
- 支付宝生态内付费技能：个人开发者经 SkillPay 个人版签约后，以 `alipay-aipay` 协议拉起支付宝付款。
- 适合：已有支付宝账号、无企业商户资质、希望以个人身份上架收费技能的开发者。
- 认证强度：中（个人实名 + SkillPay 个人签约 + 沙箱转生产）。

## 二、前置条件（用户自行完成，工具不代办）
1. 实名支付宝账号，完成 SkillPay 个人版签约。
2. 走通沙箱环境（`Payment-Needed` 返回、扫码付、回执校验），再切生产。
3. 取得 `app_id`、用户侧 `serviceId`（商品服务标识，不由工具生成）。
4. 准备服务端私钥（签名）、支付宝公钥（验签），仅落服务端。

## 三、接入流程骨架（步骤）
1. 选型确认：用户明确收费版本且具备支付宝个人资质 → §2.0 落位。
2. 构建技能Skill：按标准产出，支付相关仅放占位符。
3. 注入支付触发点：受限内容返回处按协议返回 `402` ＋ `Payment-Needed` 头，附 `serviceId`。
4. 服务端承接：用户付款后，宿主携支付回执重试，服务端校验 `serviceId` 与回执后履约。
5. 沙箱 → 生产：先在沙箱实测全链路，再切换生产参数（严禁把沙箱密钥当生产用）。
6. 实测：陌生账号真付实测（L3，AI 做不了，交用户）。

## 四、402 握手 / 凭证形态（文字描述，非可复制命令）
- 用户请求受限内容 → 技能/服务端返回 `402 Payment Required` ＋ 头 `Payment-Needed: <serviceId>`。
- 宿主拉起支付宝 → 用户扫码/确认付款。
- 付款成功后，用户携支付回执重试原请求。
- 服务端校验回执有效性与 `out_trade_no` 幂等 → 履约返回内容。

## 五、密钥与占位符
- 应用私钥：仅服务端 `.env`，占位符 `{{ALIPAY_APP_PRIVATE_KEY}}`。
- 支付宝公钥：验签用，占位符 `{{ALIPAY_PLATFORM_PUBLIC_KEY}}`。
- 用户参数占位符：`{{APP_ID}}`、`{{SERVICE_ID}}`、`{{PAYMENT_ENDPOINT}}`。
- 会外传的三处（SKILL.md / LISTING / README）必须 0 密钥，全部占位符。

## 六、结算与限制（工具不保证）
- 结算：支付宝按 T+1 结算至用户绑定的收款账户（以支付宝规则为准）。
- 费率：支付宝标准费率（以官方为准）。
- 资金是否实际到账、到账时效、税务处理，取决于用户是否满足全部前置条件；**本工具不保证、不承诺资金结算结果**。

## 七、与通用范式六条对应关系
1. 402 握手：`402` ＋ `Payment-Needed` 头。
2. 两套密钥：应用私钥 / 支付宝公钥分离，包内零落密钥。
3. 幂等：`out_trade_no` 唯一去重。
4. 云端保护 / 原文隔离：核心逻辑服务端化，包内仅放入口与鉴权。
5. 价格三处一致：SKILL.md / LISTING / 支付参数金额一致。
6. 计费矩阵：见 §十三 支付宝个人版行。
