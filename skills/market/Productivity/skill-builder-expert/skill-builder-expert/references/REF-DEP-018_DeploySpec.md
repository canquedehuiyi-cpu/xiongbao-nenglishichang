# REF-DEP-018_DeploySpec

> 本文件是专家"轻量模式 / API模式"两种部署形态的唯一事实源。链路1 构建时按 §七 选定形态，本文件给出两种形态的独立配置流程与校验规则。

## 一、轻量模式（默认主推）
- 全部逻辑、模板、规则、评测能力**内置在技能Skill内部**，无需外部接口调用。
- 独立配置清单：frontmatter 必填字段、security 块（`external_network: none`）、三档骨架档位、静态模板与素材绑定。
- 独立检查规则：跑 `selfcheck_factory.py` + `skill_quality_check.py` + `package_check.py` 三项机检全过即可出包。
- 适用：绝大多数无外部依赖的技能。

## 二、API模式（依赖外部网关）
- 依赖外部接口网关、鉴权、参数传递；含独立接口配置项、连通性检查、入参出参校验、异常回调规则。
- **唯一对外域名反代**：外部调用走自有备案域名 443 反代到内网服务端口；公网直连非标准端口口子默认关闭（直连 `:8080` 不通不代表服务挂了，要打域名）。
- **接口契约判定**：以"接口契约有没有变"判定要不要动壳，不是看版本号；壳是静态文件，上传后平台不自动拉新，改了必须逐个平台重传。
- **密钥零落包**：口令/私钥只存在于服务端 `.env`；文档与交付包一律占位符；会外传的三处必须 0 密钥；口令轮换 SOP：新口令只写进两处 `.env`，文档里一律占位符。
- **连通性校验**：验收时打 `/ask`（只有 `/ask` 计入客户端 IP 与付费），打 `/health`/`/stats` 不计数；外网探测走域名 + `--noproxy '*'`（本机可能被注入失效代理）。
- **API模式额外评测项**（链路4）：接口连通性、参数、权限校验；判据只看"服务器有没有收到请求"，不看"回答得像不像"。

## 三、打包纪律（交付前缺一不可，本体系固化）
1. 内容 + 时间戳双维度验证：只比对内容哈希会漏"内容新、时间戳旧"的倒挂；打包后断言 zip 内条目时间戳 == 今天。
2. 顶层平铺，不带中文目录（避免 `cd` 对不上）。
3. 交付到 Linux 的文件名一律 ASCII（内容可中文，文件名不要）。
4. 绝不把 `.env` / 密钥打进包（显式断言 `'.env' not in namelist`）。
5. README 永不写死自身交付物的 MD5（只写上游固定物 MD5，避免自指失效）。
6. 构建中间产物写到包目录之外；排除清单必须含 `.log` 等中间文件。

## 四、三段验收（T1/T2/T3，本体系固化）
| 段 | 验什么 | 需要 key |
|---|---|---|
| T1 启动 | 跑的是不是母版（md5/revision）、进程健康、内容装载量、支付模式 | 否 |
| T2 数据 | 真实业务全链路 + 每个动作是否写进数据盘（埋点增量断言） | 否 |
| T3 对账 | JSON ⇄ CSV ⇄ 报告三方对账 → 清空干跑 → 真清 → 清零后迷你 E2E | 是 |

- 写断言前先读服务端源码确认真实行为，不凭猜（例：卡片质检可能记 `qa_fail` 而非 `qa_pass`，断言应写三键合计 ≥1）。
- `pay_mode` 分支：`mock`（密钥未配齐）完整跑通支付履约；`live`（真密钥）只到 402 即止，绝不真付钱，履约标 SKIP 留真机验证。
- 本地实测必须覆盖两条路径：用户手动设了环境变量 / 用户没设走默认配置文件（含 CRLF、行内中文注释等脏数据）。

## 五、形态切换校验
构建、修复、评测链路必须匹配选定部署形态的校验规则，不混用两套模式标准（见 §7.3）。
