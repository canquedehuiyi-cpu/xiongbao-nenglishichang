# 标准守门自检模块（内嵌质检基线 · 分层扫描 · 有界重试熔断 · 持久留痕）

> 定位：本文件是 Skill技能搭建专家的内部质检基线专册，与 REF-VER-021（素材版本防控）、REF-LST-022（上架测试验收）配套。质检为流水线内置强制环节，初稿产出后自动流转质检分支，无旁路跳过通道。

> 全部规则为硬基线，无酌情放宽、灵活变通权限。

## 一、权责隔离与基线固化

1. **权责隔离**：生成引擎只负责产出内容；守门自检模块独立负责审核，禁止自生成自审。生成模块无权放宽、变通、跳过任何一条基线规则，审核权完全交给守门模块。
2. **基线固化**：所有规则拆成可逐条核验的检查项，分为 **【静态文本扫描项】【元数据 / 配置校验项】【业务逻辑校验项】【版权与署名规范项】【版本分支约束项】【物料接入熔断项】**。基线定稿后锁定，修改基线必须走单独的基线版本管理流程，禁止在单次对话内临时松绑。
3. **两套场景共用同一套基线**：① 迭代、更新本技能本体；② 为用户定制开发技能Skill。两场景 100% 调用同一套守门规则、同一套校验逻辑，无双重标准。

## 二、流水线强制顺序（不可调换、不可跳过）

1. 生成引擎输出初稿产物；
2. 送入守门自检模块全量校验；
3. 输出校验报告，标记通过 / 不通过、违规位置、违规条目、整改指引；
   - 通过：放行，交付最终产物；
   - 不通过：直接拦截，不允许流出；自动回传生成引擎定向整改，只针对违规项修复，其余内容原样保留；
   - 连续 3 轮整改仍失败：触发任务熔断，终止本次构建，输出告警报告。

## 三、分层扫描执行（先快检、后深度核验）

- **第一层 · 结构化配置校验**：违规描述、格式、yaml 字段、元数据、状态机、参数、免费 / 收费版本约束、上架前置条件，优先拦截高危风险；
- **第二层 · 代码安全供应链检查**：产出物含脚本时强制执行（见分类七），高危命中直接阻断出包；
- **第三层 · 业务逻辑一致性校验**：路由、分片、物料接入、熔断逻辑、版本分支约束（含 REF-VER-021 素材采信专项校验）。

## 四、完整检查清单（机器逐条执行）

### 分类一：版权与署名规范（最高优先级，先扫）

- 成果归属如实表述：本体系为开发者自主沉淀成果，权属信息以 SKILL.md「🔒 版权声明」与 `references/REF-OWN-046_OwnershipCharter.md` 为准；
- 全文不出现任何别家技能名称、别家体系备注、跨体系文档标注；
- 质检评测方法体系为引入公开评测条目精神固化，对外一律表述为「质检评测分析」动作，不宣称方法体系原创归属。

### 分类二：物料接入与雪崩防护

- 文件白名单校验：仅支持 docx、pdf、pptx、txt、md、xlsx、csv、png、jpg、webp、audio、video、纯文本；
- 字符容量阈值校验：单文件、批量总字符不超限，超限触发分片策略；
- 分片逻辑校验：大文档按语义分割，分片摘要完整，分片之间无关键信息丢失；
- 归档标记：素材唯一 material_id 归档，原始素材二进制不注入上下文（详见 REF-VER-021）。

### 分类三：版本分支约束（免费 / 收费版本）

- 无用户主动明确申请收费版本，不得生成收费版本相关配置、逻辑、话术；
- 收费版本分支启用前置校验：是否确认用户已知悉需自行准备支付参数、平台资质、自行完成平台入驻流程；
- 收费版本文案不承诺资金结算、收款到账效果；
- 默认分支固定为免费版本，未确认版本选择时，不会混入收费版本逻辑。

### 分类四：元数据与工程配置

- displayName、display_name_en、name、slug、tags 字段匹配规范，标识符不冲突；
- yaml 格式、json 结构语法合法，无缺字段、非法符号；
- 状态机 state、路由 key 命名统一，不存在路由漂移、死分支；
- 触发词、菜单路由和状态机一一对应，不存在无效跳转。

### 分类五：业务交付规范

- 交互确认节点齐全：版本选型确认、收费版本前置条件告知、风险告知；
- 熔断逻辑完整：素材超限、参数缺失、多次校验失败都有对应终止逻辑；
- 交互话术无歧义、用词严谨，不存在容易被平台误判的模糊描述；
- 输出产物附带自检报告，报告清晰可读。

### 分类六：本体自检专属加固项（构建本技能自身时强制启用）

- 本体迭代时，强制开启全部校验项，不设置任何豁免通道；
- 本体每一次更新，必须输出完整自检报告，不允许直接覆盖旧版本；
- 本体基线一旦发现持续漂移，暂停对外交付，优先修复本体规则引擎。

### 分类七：代码安全供应链检查（第七闸 · 产出物含脚本时强制执行）

> 执行工具：`scripts/code_security_scan.py`（fail-closed，支持 `--self-test` 阳/阴用例自测，自测不过其结论无效）。

> 与 技能质量标准 安全基线八维互补分工：八维只扫交付内容（排除 scripts 机件）做粗筛一刀切；第七闸扫**全部脚本（含机件自身）** 做精细分级——高危（HIGH）命中即阻断出包，薄弱点（WARN）记录进报告不阻断。两套扫描共存，缺一不可。

- S1 危险执行函数（HIGH）：动态求值、动态执行、shell 命令直通、不安全反序列化、子进程 shell 直通、动态导入执行；
- S2 硬编码密钥（HIGH）：密钥类变量赋长字面量、已知格式密钥字面、私钥块；文档示意用的占位值（明显非真实凭据）豁免；
- S3 隐私静默外传（HIGH）：同一文件内「本机信息采集」与「网络发送」并存即组合信号，判高危待复核；
- S4 远程代码动态加载（HIGH）：网络获取与动态执行并存、脚本管道直接执行远端内容；本地指向的文件跟随扫描，深度封顶 2 层；
- S5 输入边界薄弱点（WARN）：外部参数直转整数等未捕获转换，记录报告不阻断；
- S6 声明与行为一致性（HIGH）：SKILL.md / README.md 声明不依赖网络、仅本地运行，而任何脚本存在网络行为，即不一致，阻断。
- S7 Prompt 注入特征（HIGH，提示词层）：md/txt/yaml 文本出现指令覆盖/无视/设定篡改句式（与平台安全实验室检测面对齐，依据 REF-SEC-048）；
- S8 混淆/编码逃逸（HIGH，提示词层）：md/txt/yaml 文本出现长 base64 块或超长十六进制块（与平台检测面对齐）。

执行约束：

- 产出物只要包含脚本文件（py/js/ts/mjs/cjs/sh/bash/ps1/bat），本闸强制执行，无旁路；
- 包内无脚本文件的纯文档产物：S1–S5 自动豁免放行（报告注明），S6 一致性核验照常执行；
- 目录内无任何可读文件：一律 FAIL（fail-closed），不得放行；
- 本体迭代时，第七闸对本技能包自身 scripts 同样全量执行（自我适用，无豁免），每版双跑：阳性样例必须被拦、阴性样例必须放行（防死门）。

## 五、有界重试与熔断（retry_count）

- `retry_count`：本次构建整改重试次数，每次进入定向修复前 +1；任务结束自动清零；
- `max_retry`：固定等于 3，不可修改；
- 校验失败且 `retry_count < 3`：回传违规清单，定向修复，仅修改违规项，其余保留，修复完成自动复检；
- 校验失败且 `retry_count >= 3`：触发全局熔断，终止任务，输出告警报告，不再继续生成。

## 六、持久化自检报告（全链路留痕，不可篡改）

每一次构建，永久保存自检报告，落点 `logs/QUALITY_<构建号>_<时间戳>.json` 与 `.md`，字段固定：

1. 构建编号、校验时间；
2. 校验条目清单（逐分类逐项的通过 / 不通过）；
3. 命中违规项（位置、条目、整改指引）；
4. 素材采信快照（material_id、version_tag、status、用户确认方案，详见 REF-VER-021）；
5. 整改次数（retry_count）、最终结果（pass / fuse_abort）；
6. 签名摘要（包哈希 + 标准哈希 + 逐维结论 + 时间戳）。

> 出现漂移时可精准定位是哪一条规则、在哪一轮出问题，用于复盘迭代规则库。

## 七、质检节点系统约束

质检节点系统提示词固定：**你仅执行扫描比对，标记违规项，输出结构化质检报告；禁止修改内容、禁止放宽规则、禁止自主放行；不做内容创作。** 规则库为静态只读锁定，单次对话内不允许删减、修改基线。

## 十、出厂双开关与装配闸门（出厂质检默认配置）

- `auto_quality_check = true`：打包默认自动质检（出厂硬闸，见下）。
- `manual_quality_check = true`：开放独立接口，用户手动跑评测（见 `factory_config.json`）。
- 专家产出的每个技能Skill，其 `_meta.json` 会被盖戳写入 `auto_quality_check: true`，使其再次打包时自动过闸。

#### 装配与交付闸门（六步，缺一不可）

1. 产出目录 name＝slug＝目录名三者一致。
2. 跑 `python scripts/package_check.py <目录>`（禁词／CRLF／隐形字符／zip 时间戳）。
3. 跑 `python scripts/stamp_signature.py <目录>`（自动盖戳代建署名，生成 `_meta.json`；并盖戳写入 `auto_quality_check: true`；构建编号仅内部留痕，打包入对外交付物时自动剥离）。
4. 跑 `python scripts/skill_quality_check.py <目录>`（技能质量标准五维＋安全基线八维出厂质检，fail-closed，签名留痕；任一维/安全项不达标即拦截）。
5. 跑 `python scripts/package_zip.py <目录> -o <输出.zip> --mtime fixed`（UTF-8 文件名、统一时间戳、排除非业务文件、CRLF 拦截）；因 `_meta.json` 含 `auto_quality_check=true`，打包前会自动再跑一次 技能质量标准 硬闸，未过则退出码 5 拦截出包。
6. 任一闸门 FAIL，禁止交付，回到第七部分修正引擎。
