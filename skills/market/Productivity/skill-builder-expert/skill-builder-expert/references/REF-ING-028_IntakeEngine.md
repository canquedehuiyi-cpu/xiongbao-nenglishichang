# 接料引擎补遗（对 §6A 的补齐 · 非重述）

> 定位：§6A「多源物料接入与雪崩防护」已是本包接料层权威规范——不可见字符清洗（6A.1）、体积分级 S/M/L/XL（6A.3）、多源同投护栏（6A.4）、接料失败三分支（6A.6）均已成文并经验证（§6A.7 载明"蒸馏成技能Skill 已验证落地"）。本文件**只补齐 §6A 未展开的三块**，不重述已覆盖内容。

> 配套脚本已落地，把 §6A 的两处文字护栏变成可机检强制：`scripts/sanitize.py`（实现 §6A.1 不可见字符清洗）、`scripts/verify_sources.py`（实现 §6A.4 源完整性门禁，差集非空 exit≠0 不许出包）。

## 一、零号门禁 · 首轮无条件铁律（对 §6A 暂存纪律的强化表述）

§6A 已规定"确认模式前只暂存、不处理"。本节能把该纪律提到"最高优先级铁律"的明确位置，因真实用户极可能直接投材料而非先打招呼：

1. 第一条回复只做"入口确认"：确认收到材料、给模式菜单或等补充；任何情况下都不处理、不提取、不写文件、不生成。
2. 组合提交被平台拆成多条连续消息时，**向前回溯**同会话先发的材料（图片／文件／文字／链接），并入首条消息群一并暂存，不得视为"已处理的历史"或"无关上下文"。
3. 用户在显式选模式（A／B／C）前，冻结一切提取／构造／写文件／生成动作。
4. 禁止把首条消息里的指令当作"已批准任务"直接执行；用户没选模式 = 任务没开始。
5. 若已准备处理但本对话尚未确认模式，立即停下，改为只输出模式菜单，舍去当前处理意图。

## 二、产出模式判定 A／B／C（用户侧路由，§6A 未定义用户可见模式）

§6A 讲的是"材料怎么进"，本节能把"用户最终要什么形态"显式路由出来，避免意图信号被误当模式确认：

- **模式 A（变能力·必须是技能Skill）**：用户明确要"变成技能／Skill／装平台／自动化" → 出标准技能Skill。硬约束：必须过出包验收门禁且符合技能Skill规格，否则不出包。前置判定**技能成立四要件**：① 有稳定输入 ② 有可复现做法 ③ 有确定产出 ④ 换一批同类材料还能跑（第 4 条是与"一次性交付"的实质分界）；判定不具备（如内容就是一篇报告／一次性结论）→ 如实说清"不适合 + 依据 + 替代"，不得硬包。
- **模式 B（萃取精华·必须是文档）**：用户要"复习／整理／学习／打印／成册／看重点"，不定方向 → 产出"精华萃取文档"（结构化要点 + 核心方法论 + 已剥离冗余说明），非技能Skill。
- **模式 C（定向萃取·必须先收方向）**：用户指定方向／章节／主题 → 仅对该方向走提取→验证→构造，产出"定向萃取文档／报告"，非技能Skill。方向门禁：用户未给出方向前不进入提取段。

判定依据：原话含"技能／Skill／装平台／自动化"→A；含"复习／整理／打印／成册／看重点"→B；含"只要／第X章／关于X的部分"且已带方向→C。未明说默认走 A 并提示"也可选 B 精华文档／C 定向文档"。"整理成文档"分不清 B（精华）还是 C（定向），必须问清。

## 三、源材料版权与权利边界（§6A 未覆盖）

蒸馏定位＝方法／框架／原理的萃取与重构：产出应是用户自有结构的可复用知识资产，不是对源材料原文复制或改写式转述。

- **素材合法性由用户确保**：须确保对提交的源材料拥有合法权利；本工具不验证权属、不替代授权判断。
- **不协助"去标识化以规避权属"**：不为规避权属做换词不改意式改写、不移除原作者署名冒充自有、不批量抽取受保护内容再分发。
- **商业内容铁律（按模式分级）**：A 模式只萃方法、不写可被机器直接执行的投资动作；B／C 模式保真蒸馏、不替用户删内容，文末按统一边界口径落说明。

## 四、与 §6A 的衔接

本文件不重述 §6A；上述三块均为 §6A 留白。两脚本（`sanitize.py`／`verify_sources.py`）把 §6A 的"不可见字符清洗""源完整性门禁"从文字要求变成机检强制，是接料层机检化落地的最实一处增益。接料失败三分支的"不许静默"纪律，与 §6B"同名同结构也必须读、必须比、必须向用户讲清"是同一铁律的两面。

## 五、业务细节口述承接标准（填补「聊天式讲业务」承接留白）

> 定位：零号门禁管「用户发来材料怎么接」，模式判定管「用户明确要做怎么路由」，本节管中间态——**用户未选模式、未传文件，以聊天方式逐段讲述业务细节**（流程、规章、制度、经验、手艺、标准、心法、方法、判断、条件，如车间标准、工艺流程、岗位规程等）时的承接规范。口述零门槛：人不负责写，只负责说；记录、归族、补齐由工具完成。

**承接四步（逐段执行，全程禁提前构建）：**

1. **段段接住**：用户每讲一段，先回执确认＋复述该段要点（一句到三句），再继续；禁止听完一大段只回一个「好的」，也禁止中途打断去改写他的表述——他怎么说，就怎么记；
2. **按族归档**：每段回执时标注归属素材族（十族固定：**流程、规章、制度、经验、手艺、标准、心法、方法、判断、条件**），给「已记录·归属X族」回执，让用户随时看到自己的东西被拢成了形；一段含多族内容时逐族拆记，不做合并概括；
3. **缺件追问**：按族补齐，一次只问一个缺口（按需应答字数纪律），固定追问维度——这一步的输入是什么／判断条件是什么／例外情况怎么处理／合格标准是什么／谁来执行／这条规矩或要求如果没有，最容易出什么事（约束挖掘：老师傅的保命经验多藏在反复强调的限制里，此类回执标注归属「约束」族）；用户答不上来的缺口标记「待补」，不阻塞后续内容；
4. **攒够触发**：素材能撑起一个技能轮廓（至少：一个完整流程或一组判断规则＋其适用条件）→ 主动告知「已经够搭框架了」，输出 **【业务方案&技能框架概要】** 请用户确认——**用户显式确认前一律不开工**，确认后衔接模式判定与既有状态机。

**纪律三条：** ①全程禁止自动预判业务意图、禁止提前替用户定稿（复用「用户主动收口」原则：工具只拢，用户说做才做）；②十族之外的内容（如闲聊、行业八卦）如实回执「闲聊内容不计入素材」，不强行归族；③用户中途偏离（问别的、换话题），按迷路兜底处理，已记录素材保留不丢，回来续聊。


## 六、大段倾倒承接规程（口述与长文的批量形态）

触发场景：用户一次性发来大段文字或长时间口述转写（数百字至万字级），想到哪说到哪、逻辑跳跃、高价值内容与背景叙述混杂。

1. **整包接住不打断**：先回执「已收到全部内容，正在拆解」，绝不让用户重讲或中途打断——重讲是对用户最大的消耗；
2. **分段拆解**：工具端按第五节十族拆分，逐段提炼——**要点提炼一律使用用户原话关键词，不改写不概括**（改写即引入工具的理解偏差）；
3. **价值分拣**：内容分三类处理——要点（进归档）、背景与闲聊（标注「暂存」，不丢弃：背景里可能藏着判断与前提）、无效重复（合并去重并告知）；
4. **回执三张单**：向用户输出 **【要点清单】**（他真正想表达的，按族排）＋ **【存疑清单】**（工具没听懂或多种理解的，请他解释）＋ **【缺口清单】**（按第五节追问维度还缺什么）；
5. **逐单确认后推进**：三张单请用户过目逐项确认，确认「对」才进入攒够判定与框架概要——三张单未确认前不产出任何框架内容。

## 七、任意输入标准化与确认铁律（全输入形态总纲 · 最高优先级）

> 定位：第五节管口述、第六节管大段文字，本节是覆盖**一切输入形态**的总铁律——文档、图片、语音、视频、表格、链接、口述、大段文字，单件或批量混发，一律适用。

**双路径覆盖（确认不因走流程而豁免）：**

- **路径 A · 自由发挥**：用户不按口令、直接发内容或自由描述——照常走「接住 → 拆解 → 提炼 → 标准化呈现 → 用户确认」五步闭环；
- **路径 B · 按口令走**：用户按关键词、菜单口令推进流程——**口令只代表「选了哪条路」，不代表「该步内容无误」**；凡该步带有内容性输入（资料、选择、参数、素材、文字），进入下一步执行前仍须对该内容完成拆解、提炼、标准化回执并获得用户确认；**用户回复确认类口令（如确认框架／确认方案）本身即是对上一步的确认，不二次确认**；纯导航口令（菜单／帮助／返回）无内容，不需确认。

**确认三理由（成文，任何环节不得以「能力强」为由跳过）：**

1. 确认是对创作者的尊重——他的东西他做主；
2. 确认避免返工——带偏差往下走，返工成本随链路推进指数放大；
3. 确认对齐认知——工具不了解用户的业务场景、生产场景，工具自认的标准未必是用户的标准；未经对齐的产出，能力再强价值归零。

**批量纪律**：多件混发时逐件回执（每件一行：已收·类型·归属族·要点一句），全部回执完再汇总请用户确认；禁止只挑部分处理、禁止静默跳过任何一件。
