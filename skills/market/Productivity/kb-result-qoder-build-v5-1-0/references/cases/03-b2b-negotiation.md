# 案例三（真实样本）：老板把 B2B 供货谈判心法变成技能

> 💡 本案例沉淀为可复用能力资产：把高频重复的专业应答经验，封装成可调用、可传承的数字员工与 AI 助手。

## 背景

一位做水/奶/饮料/啤酒批发的老板，把多年跑门店、谈超市/便利店/夫妻店铺货促单结账的实战心法口述出来。目标：把"该谈不该谈、怎么谈、怎么逼单"固化成可复用技能，装上即用、断网也能跑，不靠临场发挥。本例由用户亲手按本标准形态产出，是验证"标准能产出好东西"的活证据。

## 进料（用户给的）

- 场景：零售"批发→零售"供货谈判（超市/便利店/夫妻店铺货、促单、结账）
- 步骤（头尾闭环）：察言观色四关筛查 → 显性/隐性需求判定 → 知己知彼问价 → 阶梯报价逼量 → 差异化 → 账期闭环 → 价格+服务终审成交
- 准则：不替老板下最终业务决策（如是否放账）；特殊场景提示人工复核
- 标准：四关是成交前提，首次合作不许跳过；成交硬标准是"价格优势 AND 服务优势"双有
- 资料：老板亲授口述 + 两个带真实数字的实战场景（超市补货 / 收银软件）

## 代建产出（技能长什么样）

- 文件：`SKILL.md`（L1-L5 闭环）+ 参考 `negotiation-gates.md`（四关决策矩阵）+ `worked-examples.md`（带数字实战）+ `INSTALL.md` / `README.md` / `_meta.json`
- 触发词：`帮我分析这个客户` / `怎么谈这单` / `客户说考虑一下怎么办` / `按我的谈判方法出方案` / `这个客户值不值得谈`
- 用户眼前只三步：给料 → 对齐（装哪 / 边界确认）→ 收包
- 边界声明：明确适用范围（零售供货）+ 认知边界（不套陌生行业）+ 灵活原则（是标准不是死模板）

## 验收判据

- 真机用"超市牛奶啤酒补货"跑一遍：AI 先四关筛查 → 需求判定 → 知己知彼 → 阶梯报价 → 终审，结构齐全、没编数字、双有才推成交 → 通过。
- 特殊场景提示：涉及是否放账等最终业务决策，技能只做策略设计、不给业务结论。

## 给代建的提醒（本样本暴露的真问题）

- 该成品 `INSTALL.md` 里曾写"另有某生态外平台的适配版"——这**违反了本包"生态外平台变体一律不出"的硬约束**。代建时凡是生态外平台的适配念头，直接掐掉，不在任何文档里留口子、不写任何生态外平台名。
- 这正说明一件事：**标准写给人看，人（哪怕是我们自己）也会漂**。只有交付前的自动校验能卡住每一个出去的包——这也是"标准变用户标准"路上最该先补的坎。
