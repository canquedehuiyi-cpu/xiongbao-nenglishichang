# 成品包 · INSTALL.md 标准模板

> **给谁用**：给「你（Agent）」。这不是给用户看的文件，是你**生成成品包时照抄的模板**。
> **什么时候用**：走完 ⑦ 真机验证、进入 ⑧ 交付引导时，照本模板为**那个具体的技能**生成一份 `INSTALL.md`，放进成品包再交给用户。
> **铁律**：成品包缺 `INSTALL.md` = 交付未完成。用户不会自己猜"去哪上传"，你得写给用户看。
> **同步铁律（按主语拆开看）**：
> - **「适用边界」口径**：必须与本包 `INSTALL.md` 保持一致（同一份边界声明，两处不能有两种说法）。
> - **平台覆盖**：**本模板讲的是"成品包能装到哪"**，本包自己的 `INSTALL.md` 讲的是"**本包自身的服务范围**（Qoder 系一个生态：平台内「上传技能」即装即用）" —— **两件事，不要求一致，也不能互相统一**。改了任一处的**边界五条**，回来同步即可。
> - 本模板滞后于 `INSTALL.md` 的**边界口径**时，下次代建会退回旧版，这次的成果就丢了 —— 要防的是这个。

---

## 为什么必须有它（根因）

用户不是技术出身。你只给一个 zip，用户不知道：

- 在平台的**哪个按钮**上传
- 上传的是 **zip 还是解压后的文件夹**
- 怎么知道**装上没装上**

结果：技能做完了，躺在硬盘里永远用不上——**等于没做**。

**合格判据**：一个从没用过 AI 技能平台的人，照着这份 `INSTALL.md`，能不能独立完成安装并唤起技能？能 = 合格。

## 使用说明（你生成时看这段）

1. 复制下面「模板正文」整段。
2. 把 `【】` 里的内容替换成**这个技能的真实信息**（技能名、zip 名、文件夹名、触发词）。
3. 平台表格**照抄整张** —— 这张表讲的是**成品包能装到哪**，列全（WorkBuddy / CodeBuddy / Qoder / 扣子 · 豆包 · IMA / Cloud Agent / 其他 / 进阶）；用户可能装的平台不止一个，少一行用户就找不到自己那一节。
4. 「适用边界」一节：把成品包 `README.md` 的边界声明**五条原样搬过来**，并在小节开头加一句「与 `README.md` 的边界声明同源，这里便于随手查阅」——让用户知道两处是一致的，不是两份说法。
5. 平台入口名称**不要编造**——各平台界面叫法可能不同，模板已写"以平台实际界面为准"，你照抄即可。**遇到不确定的平台，宁可不写，也不硬编码一个可能错的路径。**
6. 存成 `INSTALL.md`，放进成品包根目录（与 `SKILL.md`、`README.md` 同级）。
7. 「装好后先验一验」这一节**原样保留**：三道题的位置要留着，让用户**自己出题**（你不代用户出题、也不许删掉这一节）——这是"用户能自己验对错"的落点。有它，用户装完才知道成没成、准不准。

## 模板正文（复制这段，替换【】）

````markdown
# 怎么把「【技能名】」装到您的 AI 平台

> 这个技能包已经做好了，装上去就能用。下面按您用的平台对着做，不用懂技术。
> 各平台界面叫法可能略有不同，认准「技能」「上传技能」这类字眼即可。

---

## 一、先确认您要装到哪

| 您用的平台 | 用哪种方式 | 看哪一节 |
|---|---|---|
| WorkBuddy / WorkBuddy APP | 平台内「上传技能」 | **方式 A** |
| CodeBuddy / CodeBuddy APP | 平台内「上传技能」 | **方式 A** |
| Qoder（CN / APP / IDE / CLI / QoderWake） | 平台内「上传技能」 | **方式 A** |
| 扣子 / 豆包 / IMA | 平台内「上传技能 / 添加技能」 | **方式 A** |
| Cloud Agent | 平台内「上传技能」 | **方式 A** |
| 其他能在界面里上传技能包的 Agent 平台 | 平台内「上传技能」 | **方式 A** |
| 会把文件放进目录的平台（进阶用户） | 放进 `skills/` 目录 | **方式 B** |

> 不确定用哪种？先试方式 A，不行再看方式 B。
> 没列到您用的平台也没关系：只要它能"在界面里上传技能包"或"能放 `skills/` 目录"，照方式 A / 方式 B 做就行。

---

## 二、方式 A：在平台里上传（推荐，最省事）

**第 1 步 · 找到「技能」入口**
- 打开平台，在平台里找「技能」「技能中心」「技能广场」「我的技能」这类**入口**（位置各平台不同，认字眼就行）
- 找不到就在平台内搜"技能"，或看平台的帮助中心

**第 2 步 · 点「上传 / 添加 / 导入技能」**
- 在技能页找「上传技能」「添加技能」「导入技能」按钮
- 选中这个文件：`【zip 文件名】`
- 按界面提示完成

**第 3 步 · 让它生效**
- 完全退出平台再重开，或刷新页面 / 新建一个对话

**第 4 步 · 验证装上没（重要，别跳过）**
- 新建一个对话，直接说一句：
  > 【触发词示例】
- 如果它按「【技能名】」的方式回应您，就说明装好了、能用了

---

## 三、方式 B：放进 skills 目录（进阶）

适合熟悉电脑文件位置的用户：

1. 解压 `【zip 文件名】`，得到 `【技能文件夹名】/` 文件夹
2. 把这个文件夹整个放进平台的 `skills` 目录，常见位置：
   - Windows：`C:\Users\你的用户名\.【平台名]\skills\`
   - macOS：`~/.【平台名】/skills/`
3. 完全重启平台
4. 用上面「第 4 步」的方法验证

> 目录不存在就自己新建一个 `skills` 文件夹。

---

## 四、怎么用这个技能

**唤起它**——说下面任一句就会触发：

```
【触发词1】/【触发词2】/【触发词3】
```

**怎么用**——把您要处理的事情描述给它，它会按「【技能名】」的方法给您结果。

**长期用**——遇到新情况、或发现哪句答复不对，把您的修正告诉它，它就越用越准。

**装好后先验一验**——拿几道真题测测它（题自己出，最贴近您的真实场景）：

1. 【您最常碰到的那种客户 / 情况】，它给的判断合理吗？
2. 【您最头疼的那种反馈 / 问题】，它的应对方式对吗？
3. 【您最近成功的一单 / 一次】，它的分析跟您的做法对得上吗？

跑完这几题，您就知道它是不是真懂您的方法了。

## 五、常见问题

**Q：传进去了没反应？**
A：① 确认传的是 zip **原文件**，不是解压后散落的文件夹；② 完全重启平台；③ 确认唤起时说的话对得上触发词。

**Q：能装到别的平台吗？**
A：能，技能内容不变，只是装法不一样——都是"打开平台 → 找技能入口 → 上传 zip → 说触发词验证"。上面表里列的平台都适用。

**Q：这个技能能干什么？**
A：见技能包里的 `README.md`。
````

## 各平台"入口"参考（给你判断用，别当成硬编码的路径）

> ⚠️ **下面只是"通常长什么样"的参考，不是你照抄进 `INSTALL.md` 的路径。** 平台界面会改版，入口名称可能不同。写 `INSTALL.md` 时一律用"找『技能』类入口"这种**稳妥说法**，别硬编码按钮位置。

| 平台 | 通常的安装方式 | 写进 INSTALL.md 时的稳妥说法 |
|---|---|---|
| WorkBuddy / CodeBuddy | 平台内技能入口上传，或放本地 `skills/` 目录 | "在平台里找『技能』入口 → 上传技能 → 选 zip" |
| Qoder 系（CN / APP / IDE / CLI / QoderWake） | 传 zip 安装，或放 `skills/` 目录 | "在平台里找『技能』入口 → 导入 zip" |
| 扣子 / 豆包 / IMA | 界面里添加 / 导入技能包 | "在平台里找『技能』入口 → 添加 / 导入" |
| Cloud Agent | 平台内技能入口上传 | "在平台里找『技能』入口 → 上传技能" |
| 其他兼容 Agent 平台 | 结构兼容即可 | "按该平台『技能』入口操作；找不到就看平台帮助" |

**通用原则**：说"**在哪类入口找**"，不说"点某个具体坐标"；说"**以平台实际界面为准**"，不把未验证的路径写成硬性规定。
