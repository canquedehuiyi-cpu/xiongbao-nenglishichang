# 可沉淀内容清单

> 🔒 **本文件：Agent 参考（可沉淀内容索引）**
> **什么时候读**：用户问「我有什么能沉淀的」「这个算不算」「清单」「我该给你什么格式」时。
> **怎么用**：标【可照讲】的部分可以直接讲给用户听；标【内部】的只用来帮你判断归类，**不逐字念**。
> 本文件**不限定行业与岗位**：只要手里有反复在做、别人却很难做到同等效果的事，都可以沉淀。第五节按「事」举的例子**只是举例**，不构成适用范围。
> 核心能力：把**经验、手艺、技巧、技术、标准、流程、心法、策略、方法论、规则、制度**等分散、碎片化的业务素材，完成系统化梳理、规整重构、体系化整合，最终输出标准化、结构化的专业 AI 技能。

---

## 一、核心判别依据【可照讲】

**「这件事我反复处理多次，但换其他人来做，很难做到同等效果」—— 这就是适合沉淀为技能的内容。**

满足下面三项特征，就具备封装价值：

- **高频重复**：不属于一次性偶发工作，需要周期性、反复处理；
- **依赖个体经验**：您处理起来得心应手，其他人照搬却很难达到同等结果；
- **隐性化，不易言说**：实操可以完成，但很难完整讲清底层逻辑，常依靠直觉与经验判断。

## 一之二、给料十二类（与开场白同源 · 可照讲）

> 开场白里给用户看的是**短定义**；这里是**完整定义**——用户回「清单」时，照这十二类逐条举例子讲给您听。

- ① **经验**：实操沉淀的行业认知、实战复盘与经验门道
- ② **方法**：经过验证的业务处理思路、固定打法以及可跨场景复用的成套分析思考框架
- ③ **流程**：业务从接收到交付的完整执行链路，含分支、回退逻辑
- ④ **准则**：业务对错与推进与否的判断边界
- ⑤ **标准**：成果合格、可交付的验收标尺
- ⑥ **规则**：业务不可突破的红线与约束
- ⑦ **手艺**：熟手独有的实操体感与现场判断能力
- ⑧ **技术**：专属参数、配比、操作顺序等实操诀窍
- ⑨ **技巧**：特定场景提效的实操手段
- ⑩ **策略**：多场景下的风险取舍与应对方案
- ⑪ **心法**：底层决策逻辑与价值取舍
- ⑫ **制度**：组织内权责、管理、奖惩相关规范约束

> **与下面两节的对照**：本节是全套类目名，以本节为准。第二、三节的类目是归类用的细分说法——"实战经验/工作方法/业务流程/判断准则/交付标准/底线规则/实操手艺/技术诀窍/应对策略/管理制度/作业规范/表单记录"分别归入上面十二类；用户说的行话仍按第四节映射表归位，**不要纠正您的用词**。

## 二、个人可沉淀资产（自身实操积累）【可照讲】

|类目|简要说明|参考示例|
|---|---|---|
|实战经验|业务过程中积累的风险认知、复盘总结与行业门道|"该型号设备不可强行拆解""客户提出这类表述，大概率存在压价意向"|
|工作方法|处理一类事务的固定思考框架与处理范式|承接业务优先确认的 3 个关键问题；业务研判固定观察维度与顺序|
|业务流程|从业务接收到交付闭环完整执行链路|业务接收 → 需求研判 → 报价核算 → 实施执行 → 验收闭环|
|判断准则|区分业务对错、边界的判定逻辑|哪些场景可以继续推进，哪些情形需要拒绝客户需求|
|交付标准|判定结果合格、可交付的标尺|交付前必须完成的核对项；触发返工的判定条件|
|底线规则|业务红线与不可突破的约束|不予承接的业务类型、需要规避的客户情形、必须消除的潜在风险|
|实操手艺|熟手才具备的实操判断与处理能力|通过运行声音即可定位设备故障点；实操层面的手感、判断|
|技术诀窍|专属实操参数、配比、执行先后顺序等关键要点|关键参数阈值、物料配比、不可颠倒的操作顺序|
|应对策略|不同业务场景对应的处置思路|客户压价如何沟通、紧急订单如何做资源排期|

## 三、团队可沉淀资产（制度与已落地资料）【可照讲】

|类目|简要说明|参考示例|
|---|---|---|
|管理制度|团队分工、权责划分、管理约束规则|绩效考核、排班机制、安全规范、问题追责机制|
|作业规范 / 章程|岗位职责、标准化作业指导文件|岗位权责划分；各环节需要遵循的作业文档|

## 五、常见「一件事」参考示例【可照讲 · 举例时优先照这个写法】

> **举例时用这一节的写法，不要用类目名。** 「通过运行声音就能定位故障点」比「实操手艺」好懂得多。
> **按「事」分节，不按行业分节**：一件事谁都在做，行当不同、事是同一件——**照事对号，不照身份对号**。

#### ① 把一件事讲给对方听懂、教会他上手

- 经验：不同基础的人常见误区、相关方高频诉求与风险点；
- 技巧：现场把控、把复杂内容讲成大白话；
- 心法：分层讲解的底层思考；
- 流程：摸底 → 备料 → 讲透 → 检查掌握 → 复盘反馈完整链路；
- 标准：讲解输出标准、掌握程度评判标准；
- 策略：不同性格对象的沟通应对策略；
- 制度：日常管理规范、对外沟通制度。

#### ② 判一件事该不该接、风险在哪

- 经验：同类事项的常见风险点、对方常见反驳思路；
- 方法论：事项研判分析框架；
- 流程：受理 → 事实梳理 → 材料整理 → 文书起草 → 沟通协调；
- 规则：承接红线、禁止受理情形；
- 标准：文书撰写质量标准、材料梳理核对清单；
- 策略：谈判、协调、不同情形下的处置策略；
- 制度：归档、内部审批、对外沟通规范。

#### ③ 把需求做成一份能交出去的东西

- 经验：需求方高频关注点、不同类型需求的偏好特征；
- 手艺：审美判断、细节把控、落地取舍；
- 技巧：快速出方案、修改迭代技巧；
- 技术：参数、色彩规范、版式约束、输出文件规范；
- 心法：方案背后的取舍逻辑；
- 流程：需求沟通 → 调研 → 初稿 → 迭代修改 → 定稿交付；
- 标准：交付物验收标准；
- 策略：需求变更的沟通应对策略；
- 制度：项目归档、版本管理规范。

#### ④ 把钱和账对齐、按周期报准

- 经验：账务常见漏洞、风险识别经验；
- 技巧：对账快速排查问题的实操技巧；
- 流程：票据收集 → 账务处理 → 申报 → 复盘校验全流程；
- 标准：账务处理标准、凭证审核核对标准；
- 规则：账务处理红线、哪些情形需要预警；
- 方法论：账务风险自查框架；
- 策略：不同主体情况的应对思路；
- 制度：报销制度、票据管理、审批流程。

#### ⑤ 把一件跨人来回的事办完

- 经验：事务高频问题、跨部门协作常见卡点；
- 流程：采购、会务、资产、人事异动完整办事流程；
- 标准：会务筹备标准、资产盘点核对标准；
- 策略：跨部门沟通协调策略；
- 制度：办公用品管理、会务制度、资产管理制度。

#### ⑥ 让一套系统或设备稳定跑着

- 经验：故障常见诱因、线上问题排查经验；
- 技巧：快速定位问题、快速排障实操技巧；
- 技术：配置参数、部署顺序、排查步骤；
- 方法论：故障分析框架、项目风险研判框架；
- 流程：需求评审 → 开发 → 测试 → 上线 → 运维 → 故障处置；
- 标准：代码规范、上线检查清单、运维验收标准；
- 规则：上线红线、禁止操作项；
- 策略：故障降级、应急处置策略；
- 制度：发布流程制度、权限管理制度。

## 六、用户没头绪时，定向提问顺序【内部 · 单次只问 1 条，不批量抛出】

1. 「在您所处行业，哪些业务环节最容易出现失误？一旦出错会带来哪些影响？」→ 引导梳理**实战经验 / 判断准则**

2. 「同一项工作，新手和您处理完成，核心差距体现在哪里？」→ 引导梳理**实操手艺 / 技术诀窍**

3. 「在带新人、做内部交底时，您反复强调的核心要点有哪些？」→ 引导梳理**工作方法 / 应对策略**

4. 「您所在团队是否有在用的业务表单、台账或者内部规矩？」→ 引导梳理**表单记录 / 管理制度 / 业务流程**

5. 「当一项业务完成度达到什么状态，您会判定可以收尾交付？」→ 引导梳理**交付标准 / 判断准则**

## 七、资料发送方式【可照讲 · 格式无硬性约束，降低用户负担】

|用户现有资料情况|可直接发送的形式|
|---|---|
|可口头表述|文字口述、语音消息均可直接提供|
|已有成型文档|Word / PDF / PPT / Excel / TXT / MD，直接上传发送|
|仅有零散素材|手机照片、截图、手写笔记，全部可以接收|
|尚未整理归档|碎片化片段也可接收，您想到哪里讲到哪里，缺失信息我们会逐步向您确认补齐|

> 补充提示（仅当用户提供不属于自身权属资料时提醒）：请提供您本人拥有或具备合法使用权限的业务资料，涉及第三方版权内容建议替换为占位描述，规避权属风险。

## 八、引导交互三条纪律【内部 · 硬约束】

1. **单次只推进一个问题**，禁止一次抛出多个**提问**；类目清单只作对照参考，不作提问使用——堆砌提问只会提升用户门槛，而非提供引导。

2. **多用实例，少讲抽象定义**；具象业务案例更容易让专业用户产生共鸣，纯名词概念容易造成理解障碍。

3. 用户连续两条问题均无法给出有效信息，则切换交互方式：给出最小业务示例做参照，引导用户对照示例进行调整补充：「我给您举一个参考示例，您看看是否贴合您的业务场景？」

> **口径边界（防与包内规则打架）**：本节第六组「定向提问」用的都是开放式问句。这与包内「引导层」那条"永远不用开放式问题逼用户动脑"**不冲突**——那条禁的是**让用户替我们做决策**（❌"您想做什么？"）；这里问的是**帮用户回忆自己手上有什么**。本组正是「你怎么对人」第 3 步"给开放式反问让用户接着说"在"收料"环节的具体落地：**抉择权在我们，确认权在您。**

## 九、沉淀价值【可照讲】

把原本存于大脑、聊天记录、零散文档、实操经验中的各类素材，消除碎片化与口头化，补齐业务分支与边界，整理成一套结构化、可被 AI 读取、可反复调用的专业技能资产。

- **个人**：隐性能力转为可复用资产，输出不再受个人状态、记忆的影响；
- **团队**：专家经验沉淀为公共资产，新人可直接复用，降低人员流动带来的能力流失风险。
