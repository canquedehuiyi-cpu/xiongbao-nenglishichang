# 行业模板库 · 使用说明（给「壳 / 模型」与代建用户）

> 本目录是**成品骨架资产库**：四套按行业场景预制的技能骨架，每套都带着完整的接料口、流程、输出卡与自验证设计。
> 用途：代建开工时，若用户业务与某套模板匹配，**以模板为底改内容**，比从零起草更快、更稳、更不容易漏件。
> 这是本包的纵深资产层——建技能的动作谁都能做，**行业里沉淀的成品骨架只有这里有**。

## 一、四套模板一览

| 模板 | 目录 | 适用场景 | 核心交付物 |
|---|---|---|---|
| 老板决策陪练 | `boss-decision/` | 中小老板的经营判断：定价、扩不扩、招不招人、要不要砍 | 决策清单卡 + 复盘记录 |
| 团队操作手册 | `operation-manual/` | 门店 / 团队的 SOP 问答与新人带教 | 按问即答的操作卡 |
| 手艺经验库 | `repair-craft/` | 维修、安装、工艺等手艺活的口述经验沉淀 | 排查决策树 + 判定卡 |
| 内容生产流水线 | `content-workflow/` | 公众号 / 短视频等内容的选题到成稿 | 成稿 + 选题备档 |

## 二、选用规则（给「壳 / 模型」）

1. **先听后选**：用户讲完业务，对照上表判断是否命中某套模板；命中→说明「您的场景有现成骨架，我按它给您起底子」，**经用户点头后再用**；不命中→走从零起草，不硬套。
2. **只换内容不改骨架**：模板里的接料触发表、输出卡、自验证三问、分页铁律是**结构件**，保留；替换的只有行业知识、话术、示例。
3. **骨架不允许降级**：交付前对照模板尾部的「出厂自检」逐条过，缺一件 = 不出包。
4. **改完必做全包自查**：逐文件核对成品包内容与引用完整性。

## 三、改编四步

1. 复制模板目录内文件到新建包目录，目录名改成新技能的 slug（name ＝ slug ＝ 目录名，三处一致）。
2. 替换 frontmatter 的 name / description（description 按「用户会怎么开口」写满触发场景）。
3. 按「改编位」标记逐处替换行业内容——模板内所有 `【改编位：…】` 标记都要清零。
4. 跑出厂自检 + 本包检查脚本，全绿才交付。

## 四、出厂自检（每套模板尾部同款，交付前逐条勾）

- [ ] 装得上：frontmatter 完整，name ＝ slug ＝ 目录名
- [ ] 唤得起：description 含至少 5 个真实触发说法
- [ ] 答得对：核心流程 + 输出卡齐全，接料触发表覆盖至少 3 种开口方式
- [ ] 说得清：自验证三问在交付前真实跑过，证据随交付给出
- [ ] 分页合规：知识体量超 50KB 必装行号索引，禁整文件读取
- [ ] 安全声明：frontmatter 四项齐（联网 / 域名 / 凭证 / 数据流向）
- [ ] 改编位清零：全文检索 `【改编位` 无残留
