# 可选增强：写前 / 写后自动检查（默认关闭）

> **本目录不是技能运行的必要部分。不启用它，技能的一切功能照常，交付结果不受任何影响。**

---

## 一、这一组是干什么的

给"写入文件"这个动作加两道自动检查：

| 时机 | 脚本 | 检查什么 | 会不会拦住你 |
|:--|:--|:--|:--|
| 写之前 | `pre_write_guard.py` | 内容里有没有"问题框架词族"；有没有岗位 / 行业限定词 | 词族命中会**拦下**；限定词只**提示** |
| 写之后 | `post_write_check.py` | 刚写的 markdown 里，本地链接有没有指向不存在的文件 | **只提示**，从不拦 |

两道检查都**只读**：不联网、不调用任何外部接口、不修改你的任何文件。

---

## 二、默认是关的

本包**不自动注册**这两个检查，也不会去改你的任何配置文件。原因很实在：

1. 让一个技能包去改你机器上的配置，本身就需要你给出很高的权限；
2. 高权限会带来一连串确认弹窗，反而把简单的事变复杂。

所以这里只**提供能力**，开不开由你定。

---

## 三、想开的话，怎么开

**第 1 步 · 生成你自己的配置**

在本目录执行（先预览，不落盘）：

```
python install_hooks.py
```

确认输出没问题后，真正落盘：

```
python install_hooks.py --write
```

会生成 `hooks.installed.json`——里面的路径已替换成你机器上的真实路径。

**第 2 步 · 接入你的运行时**

把 `hooks.installed.json` 的内容，接入你所使用运行时的 hooks 配置入口（不同运行时入口不一样，照着它的说明放即可）。

**第 3 步 · 重启后生效**

---

## 四、开了之后你会遇到什么（先说清楚）

- 平台可能会就"执行命令"询问你**一次**：允许即可。
- 如果它反复询问，说明运行时的权限档位偏保守；把该目录加入信任，或切到更宽松的权限档位即可。
- **不想被打扰，就把它关掉**——本包的核心功能不依赖它。

---

## 五、跨工具说明

配置里的匹配规则已取并集（`write_to_file|replace_in_file|Write|Edit`），可同时覆盖多个工具家族的写法，一套配置通用。脚本本身只用 Python 标准库（3.8+），不需要装任何第三方包。
