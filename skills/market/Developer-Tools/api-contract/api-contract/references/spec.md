# 前端联调接口契约规范（自包含快照）

> 本文件是 salt-data-web 仓库 `docs/api-contract-for-backend.md` 的同步快照，随规范更新而更新，供无仓库环境的后端同学使用。两者如有出入，以仓库规范为准并提醒维护者同步。
> 面向对象：salt 后端 / 网关负责人。
> 目的：约定接口契约的**生成流程**与**内容格式**，保证前端（salt-data-web，Umi + antd）可以按契约直接对接，减少来回确认。
> v2 修订依据：U02 批次查询模块实际交付明细（`U02 批次查询接口前后端对接明细.md`）——凡后端已实践且效果好于原约定的，已吸收为正式规范；凡实测暴露的缺口，已补为强制要求。
> 与前端现状对齐的硬约定用【前端现状】标注，后端必须遵守或提前提出变更。

---

## 1. 契约生成流程与纪律（先读这一节）

契约文档按以下三步生成，**顺序不可颠倒**：

1. **后端先交付接口清单总表**（§3 格式）：编号 + 方法 + 路径 + 所属模块 + 状态。
   总表是契约范围的**唯一来源**——契约正文只覆盖总表内的接口。
2. **逐条生成单接口契约**（§4 格式），内容**以后端实际代码为准**：
   字段名、类型、必填性、枚举值、默认值、校验规则，均从后端 Controller / DTO / 枚举类 / 校验注解中扫描确认，不凭记忆或口头描述。
3. **交叉核对**：契约中引用的外部 ID / fileIds / 状态机，其来源接口和依赖关系必须在总表中闭环（见 §3 要求）。

**防扩散规则**（适用于人工编写及 AI 辅助生成，违反即文档无效）：

- 【禁止】生成总表之外的接口——即使"前端页面看起来需要"，也必须先让后端补入总表。
- 【禁止】推测字段、枚举值、错误码：内容必须能对应到后端代码，或经后端明确确认；不确定的一律标注 `【待确认】` 并留空，不得脑补。
- 【禁止】"例如 / 如 B1_MISSING、B2_EXPIRED" 式的不完全枚举——枚举值必须列全量；确实动态的（如 reasonCode 后续扩展），写明"当前全量值 + 扩展方式"。
- 【必须】后端尚未实现的接口只出现在总表中（状态=开发中），不提前生成契约正文。
- 【必须】前端不消费的字段也照实写入（以代码为准），可标注"前端暂不使用"。

## 2. 全局约定

### 2.1 环境与网关

| 项目 | 要求 |
|---|---|
| Base Path | 【前端现状】前端统一前缀 `/salt/api/v1`（`SALT_API`）。契约中 path 写法二选一并全文档统一：① 完整路径含 `/api/v1`（如 U02 明细的写法，baseUrl 指到 `/salt`）；② 相对 Base Path。**推荐 ①**，并给出 `{{baseUrl}}` 各环境取值表（如联调 `http://192.168.2.24/salt`） |
| 环境域名 | 联调 / 测试 / pre / 生产各环境 `{{baseUrl}}` 一并给出 |
| CORS | 如前端直连（非同域网关），列出允许的 origin、methods、headers（含 Authorization） |
| 网关行为 | 限流阈值、超时时间（建议 30s，长任务另说明）、是否透传自定义 header |

### 2.2 请求头约定

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 登录后接口必填 | 【前端现状】`Bearer {token}`；租户与企业身份**由 token 解析确定，前端不另传 tenantId/enterpriseId**（U02 已按此实现，全模块沿用）。如某接口例外必须显式标注 |
| `Content-Type` | — | `application/json`（文件上传用 `multipart/form-data`） |
| `Idempotency-Key` | 写操作按接口标注 | 【前端现状·新增】U02 已要求"本次提交唯一键；同一内容重试复用，同一键不能用于不同请求内容"。需要幂等的写接口必须逐个声明此 header 及键的生成规则、重复提交时返回什么（复用上次结果还是报错） |

### 2.3 响应 envelope（统一包裹）——✅ 2026-09-17 已定稿为 ApiResponse

【2026-09-17 定稿】后端确认全模块（认证 / 数据 / 文件服务）统一返回 `ApiResponse<T>`，前端已适配：

| 项 | 定稿结论 |
|---|---|
| 成功 | `{ "success": true, "data": T, "error": null, "traceId": "...", "timestamp": "ISO8601" }` |
| 失败 | `{ "success": false, "data": null, "error": { "code", "message", "details" }, "traceId", "timestamp" }` |
| HTTP 状态码 | 语义化返回：200/201 成功，400/401/403/404/409/422/500 按语义，不固定 200 |
| 204 No Content | 无响应体，仅限无返回值的接口；前端不按 ApiResponse 解析 |
| 前端判定 | 用 `success` 与 `error.code` 分支，禁止依赖 message 文案；`details` 为字段级错误明细 |

前端适配现状：`src/services/http.ts` 解包 `data`；`src/utils/request-helpers.ts` 拦截器做双 envelope
判定（salt `success` 风格 / mock `code:'00000'` 风格），业务错误 reject 的 `e.payload` 即 `error` 对象
（`error.code` 分支写法见 `services/supplier.ts` 的 `getIdentityStatus`）；blob 响应（文件下载）的
4xx JSON 错误体已支持解析。mock 接口不受此定稿约束，仍用 `{code:'00000', message, data}`。

- `timestamp`、`traceId`：前端不消费，但契约中保留说明（traceId 用于问题排查，报障时前端会附带原文）。

共同要求：

- `data`：成功时为 payload；失败时允许 `null` 但**字段必须存在**（不允许返回空 body 的 200）。
- 列表接口无数据时 `data.list` 返回 `[]` 而非 `null`（U02 已符合，全模块沿用）。

【前端现状·例外】HTTP 401：登录态失效时后端直接返回 **HTTP 401 且响应体为空**，前端走刷新-重放链路；`code === 'A0230'`（token 过期）与 401 同链路处理（mock 用）。

### 2.4 错误码

后端必须提供**全量错误码表**，格式：

| 错误码（`error.code`，语义化字符串） | HTTP 状态 | 含义 | 前端处理建议 | 是否可重试 |
|---|---|---|---|---|
| `VALIDATION_FAILED` | 400 | 参数校验失败 | 展示 message / details 字段级错误 | 否 |
| `UNAUTHORIZED` | 401 | 登录态失效 | 静默刷新重放 | 刷新后自动重试 |
| `ENTERPRISE_NOT_FOUND` | 404 | 资源不存在 | 展示 message | 否 |
| （按模块分段定义，如 `CONFLICT` 类） | 409 | 状态冲突 | 展示 message | 视场景 |

要求：

- 错误码**分模块分段**（前缀按模块，如 `AUTH_` 用户认证、`AGREEMENT_` 协议/合同、`BATCH_` 数据批次…），避免全业务共用一个码。
- mock 体系保留码（**仅限 mock，salt 真实接口不使用**）：`code:'00000'` 成功风格、`A0230`（token 过期）、`A0203`。salt 真实接口错误码一律为 `error.code` 语义化字符串。新增语义冲突需同步前端。
- 每个接口的契约正文列出该接口可能返回的所有非成功码（见 §4）。
- success 包裹模块（定稿）：错误码为语义化字符串置于 `error.code`（如 `VALIDATION_FAILED`、`ENTERPRISE_NOT_FOUND`），HTTP 状态语义化；全量错误码表由后端按本表格式补入。

### 2.5 字段与数据类型约定

以下每条均要求**全表一致**，且与后端代码实际序列化行为一致：

| 类型 | 约定 |
|---|---|
| ID | 【前端现状·按 U02 确认】雪花 ID 等超出 JS 安全整数的 ID **一律 string**（如批次 `id: "1890000000000000001"`），并在注释中写明"按字符串保存，避免数值精度丢失"。contract 中 ID 字段类型写 String 而非 Long/number |
| 时间 | 明确选择其一并全站统一：`yyyy-MM-dd HH:mm:ss`（Asia/Shanghai）或 ISO 8601；**日期与日期时间区分声明**——查询入参用日期 `yyyy-MM-dd`（含当天边界语义，如"包含当天零点 / 包含完整结束日"），展示字段用日期时间。禁止时间戳秒/毫秒与字符串混用 |
| 金额 | 【前端现状·按 U02 确认】**string 类型、保留两位小数**（如 `"80.00"`），避免浮点精度丢失；含冲正/净额等口径在注释中写明。"未计价"与 `0.00` 必须可区分（U02 用"字段可能省略"表达，见下行可空语义） |
| 枚举/状态码 | 每个状态字段给出**全量枚举值→含义**对照（`processingStatus: RECEIVED 已接收、PROCESSING 处理中、SUCCEEDED 成功、FAILED 失败、UNKNOWN 未知`）。存在兼容别名的必须显式声明（如 `settlementStatus` 兼容 `PENDING` = `PENDING_SETTLEMENT`），并说明弃用计划 |
| 可空语义 | 【必须逐模块声明】可空字段是 **`null`** 还是**整个键省略**——U02 采用"空值可能省略"，前端两种都会兼容，但同一接口内必须一致；且"省略 ≠ 0 / ≠ 空串"要有独立语义（如 `estimatedAmount` 省略 = 未计价 ≠ 0 元）。前端序列化/TS 类型将按此声明定义 |
| 布尔 | 用 true/false，禁止 0/1 |
| 分页 | 【前端现状】入参 `pageNum`（从 1 开始）+ `pageSize`；出参 `{ list, total, pageNum, pageSize }`。**非法值处理必须写明**（如 pageNum<1 按 1、pageSize 仅允许 10/50/100 其余按默认处理——静默纠正 vs 报错，二选一并统一）。写接口若分页参数语义不同（如 B05 的 total 是"原因分组数"）必须在注释中说明 |
| 防混淆注记 | 【借鉴 U02】易混淆字段必须在注释中写"不是什么"：如 `batchId` 来自 `list[].id` **不是 batchNo**；`parentId` 是文件关系 ID **不是 fileId**；`fileIds` 取通用上传接口的 fileId **不是控件 uid / OSS URL**。这是实测中最能有效减少联调误会的做法，全模块执行 |

| 编号 | 接口名称 | 方法 | 完整路径 | 所属模块/页面用途 | 依赖接口 | 状态(已就绪/开发中) | 联调优先级 | 负责人 |
|---|---|---|---|---|---|---|---|---|
| U02 | 用已上传文件创建批次 | POST | /api/v1/data/supply/batches | 已上传数据/提交批次 | 通用文件上传(待补编号) | 已就绪 | P0 | — |
| B01 | 分页查询已上传批次 | GET | /api/v1/data/supply/batches | 已上传数据/列表 | — | 已就绪 | P0 | — |
| B10 | 获取质量报告下载链接 | GET | /api/v1/data/supply/batches/{batchId}/quality-report/download-link | 已上传数据/报告下载 | — | 已就绪 | P1 | — |

要求：

- **编号制度**（借鉴 U02）：每接口一个稳定编号（U=写/上传、B=浏览查询…），后续契约正文、排期、问题提报均以编号指代，避免只写路径产生歧义。
- **依赖闭环**：接口 A 的入参若引用接口 B 的出参（如 U02 的 `fileIds` 取自通用上传接口），B 必须在总表中且标注编号。**实测缺口示例：U02 依赖"通用文件上传接口"，但 U02 交付清单未包含该接口——此类遗漏必须在总表阶段补齐，不允许到联调时才发现。**
- 覆盖前端所有页面用到的接口，包括易遗漏的：字典/枚举下拉数据源、文件上传、文件下载链接、当前用户信息、消息通知等。
- 清单确定后新增/删除接口走变更流程（见附），契约正文不做清单外扩展。

## 4. 单接口契约模板（每个接口一份，缺项视为未完成）

````markdown
### {编号} {接口中文名}

- **接口路径**：`POST /api/v1/data/supply/batches`（含 Base Path 的完整路径写法）
- **所属模块**：已上传数据
- **调用时机**：前端在「提交批次」弹窗点击确定时调用（前端补充，后端可留空）
- **鉴权**：是（Bearer token）；租户/企业由 token 解析，前端不另传
- **幂等**：是——`Idempotency-Key` header，重复提交返回首次结果 / 否
- **HTTP 状态**：成功 200 / 201（创建类）；失败语义化（400/404/409/422…），见错误码表

#### 请求示例（完整可复制 HTTP 报文）

```http
POST {{baseUrl}}/api/v1/data/supply/batches
Authorization: Bearer {{token}}
Content-Type: application/json
Idempotency-Key: astra-upload-20260917-001

{ "fileIds": ["6c0faec9-..."], "description": "入库数据" }
```

#### 请求字段

| 位置(Header/Path/Query/Body) | 字段 | 类型 | 必填 | 含义（含枚举全量、默认值、校验规则、防混淆注记） |
|---|---|---|---|---|
| Body | fileIds | String[] | 是 | 非空，取通用上传接口返回的 fileId；不是控件 uid、OSS URL 或本地路径 |

#### 响应示例（完整 envelope，成功与失败各一份）

```json
{ "success": true, "data": { "id": "1890000000000000002" }, "error": null, "traceId": "...", "timestamp": "2026-09-17T10:00:00+08:00" }
```

失败（HTTP 404 等语义化状态）：

```json
{ "success": false, "data": null, "error": { "code": "BATCH_NOT_FOUND", "message": "批次不存在", "details": null }, "traceId": "...", "timestamp": "2026-09-17T10:00:00+08:00" }
```

#### 响应字段

| 字段 | 类型 | 可空性(null/省略) | 中文注释（含枚举全量、语义边界、防混淆注记） |
|---|---|---|---|
| data.id | String | 否 | 批次雪花 ID，前端按字符串保存，避免数值精度丢失 |
| data.estimatedAmount | String | 省略 | 预估收益两位小数；省略=未计价，不等同于 0 元 |

#### 错误码

| error.code | HTTP 状态 | message 示例 | 场景 | 可重试 |
|---|---|---|---|---|
| BATCH_NOT_FOUND | 404 | 批次不存在 | batchId 无效 | 否 |
| BATCH_FILE_INVALID | 400 | 文件不存在或已删除 | fileIds 含无效 fileId | 否 |

#### 备注

- 异步任务说明（如有）：创建后 processingStatus 从 RECEIVED → PROCESSING → SUCCEEDED/FAILED，
  前端轮询哪个接口、建议间隔、终态枚举、是否有回调。
- 状态机/字段联动约束（如「仅 processingStatus=SUCCEEDED 可调本接口」）。
- 上线时间/灰度计划。
````


## 6. 联调交付物 Checklist

后端在进入联调前须交付（缺项请提前声明补齐时间）：

- [ ] 接口清单总表（§3，含编号、依赖闭环、易遗漏接口）
- [ ] **成功/失败响应示例**（§2.3 ApiResponse 定稿形态；后端实际实现与定稿不一致处必须显式标注）
- [ ] 全量错误码表（§2.4）
- [ ] 全部枚举值对照表（全量值 + 兼容别名 + 前端展示文案）
- [ ] 可空语义声明（null vs 键省略，§2.5）
- [ ] 单接口契约文档（§4 模板），建议提供 Apifox/Swagger 在线地址 + 可导入 JSON
- [ ] 鉴权全链路说明（token 生命周期、401 行为、多端登录互踢）
- [ ] 联调环境 `{{baseUrl}}` 各环境取值 + 测试账号（供应方/客户方/运营方至少各 1，含不同权限级别）
- [ ] 测试数据：预置可查列表数据、可走通的批次/协议/企业认证流程数据、短信验证码联调获取方式（固定码或后门）
- [ ] 第三方对接说明：e签宝签署回跳 URL、状态查询接口、异步任务终态
- [ ] 变更通知机制：契约变更通过什么渠道同步（接口文档评论/群公告），变更后前端缓冲时间
- [ ] 联调排期：按接口编号的就绪时间表

## 附：双方联调协作约定

1. 前端按契约先行 mock 开发（envelope/分页/错误码按 §2 模拟），后端就绪一个接口切换一个；mock 与真实接口禁止同 URL 并存。
2. 契约一旦确认，**后端单方面变更字段名/类型/枚举值/可空语义视为联调阻塞**，须回退或走变更流程。
3. 契约内容与后端代码不一致时**以代码为准**，但后端需主动通知差异并更新契约文档。
4. 联调期问题按「接口编号 + 接口路径 + 请求/响应原文（含 traceId）+ 时间」格式提报，后端当日响应。
