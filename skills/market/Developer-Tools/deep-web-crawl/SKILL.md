# 深度网站抓取工作流 (Deep Web Crawl)

面向企业官网、机构网站的全网深度抓取工作流。核心流程：搜索定位 → 首页探测 → 子页面并行抓取 → 多源交叉补充 → 结构化报告编译。

---

## 前置检查：crawl4ai-skill 可用性

在执行任何抓取前，先检测 crawl4ai-skill 是否可用：

```bash
crawl4ai-skill --version 2>&1 || python -m crawl4ai_skill --version 2>&1
```

- **可用** → 优先使用 `crawl4ai-skill crawl` 和 `crawl4ai-skill crawl-site` 抓取页面
- **不可用**（命令不存在 / Playwright 未安装 / 超时） → 全部回退到内置 **WebFetch** 工具

> **关键原则：** crawl4ai-skill 不可用时绝不能卡住，必须立即切换到 WebFetch 继续执行。

---

## 工作流步骤

### Step 1：搜索定位

使用 **WebSearch** 工具搜索目标，收集所有相关信息源 URL：

```
WebSearch: "{目标名称} 官网"
WebSearch: "{目标名称} site"（若第一轮未找到官网）
```

从搜索结果中识别并分类 URL：
- **官网 URL** — 目标自身网站（优先级最高）
- **第三方信息源** — 百科、企查平台、招聘站、行业目录等

将收集到的 URL 按来源分类记录，供后续步骤使用。

### Step 2：首页探测与导航提取

抓取目标官网首页，核心目标是获取**站点导航结构**：

**crawl4ai 可用时：**
```bash
crawl4ai-skill crawl {官网URL} --format fit_markdown
```

**crawl4ai 不可用时（fallback）：**
```
WebFetch: url={官网URL}, prompt="提取全部导航链接和页面内容，包括所有子页面的完整URL路径"
```

从首页内容中提取：
- 主导航菜单项及其链接（关于我们、产品中心、新闻、联系我们等）
- 子导航/二级菜单链接
- 页面中出现的其他重要链接

构建子页面 URL 列表，为 Step 3 的并行抓取做准备。

### Step 3：子页面并行抓取

使用 **Task 子 agent** 并行抓取 Step 2 提取到的各子页面。每个子 agent 负责抓取 1-2 个子页面。

**并行策略：**
- 将所有子页面按主题分组（关于/产品/新闻/联系等）
- 每组启动一个 Task 子 agent
- 每个 agent 使用 WebFetch 抓取对应子页面并提取结构化内容

**Agent prompt 模板：**
```
抓取以下页面并提取结构化内容：
- URL: {子页面URL}
- 提取目标: {具体提取要求，如"所有产品分类和产品列表，包含名称、描述、规格"}
使用 WebFetch 工具抓取，将结果以结构化文本返回。
```

**常见子页面及提取重点：**

| 页面类型 | 提取重点 |
|---------|---------|
| 关于我们 | 公司简介、成立时间、注册资本、发展历程、企业文化、荣誉资质 |
| 产品中心 | 所有产品分类、产品列表、规格参数、功能特点 |
| 产业优势/技术实力 | 专利、认证、研发团队、制造能力 |
| 新闻动态 | 新闻标题、日期、摘要 |
| 联系我们 | 地址、电话、邮箱、各分支机构信息 |
| 人力资源 | 招聘岗位（侧面反映公司规模和业务方向） |

### Step 4：多源交叉补充

抓取 Step 1 收集到的第三方信息源，补充官网未覆盖的信息：

| 信息源类型 | 典型网站 | 提取内容 |
|-----------|---------|---------|
| 百科类 | 百度百科、维基百科 | 公司概况、历史沿革 |
| 企查平台 | 爱企查、天眼查、企查查 | 注册资本、法人、股东、经营范围 |
| 招聘平台 | 猎聘、智联、前程无忧 | 公司规模、行业分类、在招岗位 |
| 行业目录 | 买购网、行业协会站 | 品牌排名、行业地位 |

**注意：** 第三方源经常遇到反爬问题，参考下方 Fallback 策略处理。

### Step 5：结构化报告编译

将所有抓取结果合并为一份 Markdown 报告，使用下方报告模板输出。

## Fallback 策略

抓取过程中各类异常的应对方案：

| 异常场景 | 典型表现 | 应对策略 |
|---------|---------|---------|
| crawl4ai 不可用 | 命令不存在 / Playwright 未装 | 全部切换为 WebFetch |
| 百科反爬 | 百度百科返回验证码/空白 | 跳过，尝试维基百科或其他百科 |
| 企查平台 JS 渲染 | 爱企查/天眼查返回空内容 | 标记"JS渲染受限"，尝试招聘平台或行业目录补充 |
| 重定向过多 | 招聘站等超过10次重定向 | 跳过该源，标注失败原因 |
| 域名不可达 | DNS解析失败 / 连接超时 | 标注"网站不可访问"，继续其他源 |
| 403/401 拒绝 | 返回权限错误 | 跳过，标记"需要登录/授权" |
| 页面内容为空 | 抓取结果无实质内容 | 尝试 raw_markdown 格式或换用 WebFetch |

> **核心原则：** 单个源失败不影响整体流程，标注失败原因后继续执行其他源的抓取。

## 报告模板

输出文件为 Markdown 格式，结构如下：

```markdown
## {目标名称} 全网抓取报告

> 抓取时间: {YYYY-MM-DD}
> 数据来源: {来源列表}

---

### 一、公司概况

| 项目 | 信息 |
|------|------|
| 全称 | ... |
| 官网 | ... |
| 成立时间 | ... |
| 注册资本 | ... |
| 地址 | ... |
| 定位/行业 | ... |

{公司简介正文}

---

### 二、产品/业务

{按分类列出所有产品/业务线}

---

### 三、技术实力与资质

{专利、认证、荣誉、研发能力等}

---

### 四、新闻动态

{最近的新闻标题、日期、摘要}

---

### 五、联系方式

{总部及各分支机构的地址、电话、邮箱}

---

### 六、关联企业信息（如有）

{母公司、子公司、关联企业}

---

### 抓取受限说明

{列出本次抓取中遇到失败的源及原因}
```

> 报告末尾必须列出"抓取受限说明"，标注所有未能成功抓取的源及原因，让用户了解信息覆盖范围。

## 常见陷阱

1. **不要死等 crawl4ai** — Playwright 浏览器安装可能耗时数分钟甚至失败，必须在检测失败后立即切换 WebFetch
2. **百科类网站反爬严格** — 百度百科、爱企查等经常返回验证页面，不要反复重试，直接跳过换源
3. **并行优于串行** — 子页面抓取应使用 Task 子 agent 并行执行，显著减少总耗时
4. **导航链接需拼接域名** — 从首页提取的导航链接可能是相对路径，需拼接为完整 URL
5. **第三方源作为补充** — 官网信息优先，第三方平台信息用于交叉验证和补充
6. **报告要标注信息时效** — 抓取时间必须写入报告头部，方便用户判断信息新鲜度
7. **关联企业信息容易被忽略** — 搜索时注意识别同一集团下的多家子公司/品牌
