> 2. 六、注意事项与七、回滚方案来自团队经验而非提交记录，须由用户补充确认，不得自行编造；
> 3. 实际生成发布说明时，以当次提交记录的真实业务细节为准（具体型号/设备名、表名与 ALTER 原文、缺陷对象与根因等），禁止把提交内容改写成样板中的通用措辞；本文件为公开素材，也不得写入真实业务内容。

## 期望输出样板（虚构）

以一款通用移动应用为例（虚构），某版本发布包含账号体系与数据看板优化，整合后的发布说明如下：

一、新增功能
    1.新增数据看板：支持首页自定义展示核心指标，减少逐页查看成本；
    2.新增第三方账号登录：支持微信、钉钉快捷登录。
二、功能优化
    1.优化列表加载策略：弱网环境下首屏展示速度明显提升。
三、缺陷修复
    1.修复深色模式下部分页面文字对比度不足的问题。
四、配置变更
    无
五、数据库变更
    1.用户表新增最近登录时间字段；
      ALTER TABLE `t_user` ADD COLUMN `last_login_time` datetime DEFAULT NULL COMMENT '最近登录时间'；
    2.新增消息模板枚举：站内信与推送通知模板统一管理。
六、注意事项
    1.本次升级涉及登录态刷新，升级后首次启动需重新授权消息推送。
七、回滚方案
    1.通过发布平台的历史版本记录一键回滚至上一版本。

## 消息结构说明（末尾不附提交日志）

发布说明末尾**不附加独立的【提交日志】段落**，区间内提交内容全部糅合进七段式对应段落，保证消息简洁无重复：

- 提交归类映射：新增/上线/支持类 → 一、新增功能；优化/调整/重构类 → 二、功能优化；修复类 → 三、缺陷修复；无对应内容的段落写"无"。
- 每条提交合并归纳后成为对应段落中的一个条目（一行一句，合并同类），不在末尾重复罗列提交要点。
