# 迭代轨道（阶段 B）详细规则

## 1 为什么是"阶段"而不是"第 10 步"

9 步法描述"从无到有"的一次性串行；迭代是"在基线上反复改进"的循环。若把迭代编成第 10、11、12 步，"第几步"会失去含义，还暗示存在终点。因此：**第几步只描述建项目，第几轮只描述演进。**

## 2 进入、完成与放弃

- 进入：阶段 A 第 9 步过关，基线写入 `0_迭代总览`（日期、提交号、测试结论）。
- 完成：I1–I5 全绿，状态改"已完成"并写一句结论。
- 放弃：允许，但必须在总览留"放弃原因 + 已产生的影响 + 是否已回滚"，不许静默消失。
- 一轮只解决一个可验收目标。发现目标过大就地拆成两轮，不许一轮并行两个目标。

## 3 `0_迭代总览` 字段

| 字段 | 说明 |
|---|---|
| 编号 | I1、I2……连续，不复用 |
| 目标 | 一句话、可验收；禁止"优化体验""完善功能" |
| 来源 | 债务台账 / 第 2 步"不做什么" / 新需求 / 缺陷 |
| 涉及模块 | 引用第 6 步的模块名，不新造 |
| 变更级别 | L1 / L2 / L3，取最高者 |
| 状态 | 待立项 / 进行中 / 待验收 / 已完成 / 已放弃 |
| 基线提交 | 本轮起点的提交号 |
| 结论 | 一句话：达成什么、留下什么 |

表头之外固定两行指针："当前迭代"与"最近基线"。

## 4 `1_债务台账` 字段

| 字段 | 说明 |
|---|---|
| 编号 | D1、D2…… |
| 位置 | 文件:函数 / 表:列，必须可定位 |
| 类别 | 设计 / 实现 / 文档 / 测试 / 契约 |
| 触发条件 | 什么情况下会出问题 |
| 影响 | 出错后果与影响面 |
| 发现于 | 建项目第几步或哪一轮 |
| 建议处理 | 一句话方向 |
| 状态 | 未处理 / 已登记待排 / 处理中 / 已关闭（注明关闭轮次） |

规则：当场发现当场登记，不许只在对话里说。债务是本流程唯一的跨轮记忆，不登记等于不存在。

## 5 四份文档的写作模板

### 01_功能说明

- 目标：一句可验收的话
- 范围·进：本轮做什么
- 范围·不进：**必写**，是硬约束不是备忘
- 用户可见变化：界面、行为、数据上的可感知差异
- 验收口径：可判定句（跑哪条流程、看哪个状态）
- 依据：引用的债务编号 / PRD 段落 / 缺陷复现步骤

### 02_涉及模块

- 表格：模块 | 文件 | 动作（新增/修改/删除/仅读）| 必须改的理由
- 不改清单：看起来相关但不改的文件 + 理由，防执行时扩散
- 变更级别：判定结果与理由
- 替代方案：至少 1 个被放弃的方案 + 代价
- 待决策点：需要决策者拍板的具体问题，逐条列

### 03_改动指南

按执行顺序编号，每步六段：位置 / 现状 / 目标 / 数据结构 / 影响面 / 验证。

另附四张表：常量与规则表、分支真值表、契约与生成物、迁移与回滚。

测试点：新增用例 + 必须保持通过的既有用例。

### 04_验收记录

实际改动清单 / DoD 五项结果 / 与指南的偏差及原因 / 回顾（定量 + 定性，改进项不超过 2 条）/ 遗留项（转入债务台账）

## 6 DoD 五项（少一项不算完成）

1. 功能验收：01 的验收口径逐条跑通
2. 测试：新增用例通过，既有用例无回归
3. 迁移与回滚：迁移执行过、回滚验证过、存量数据校验过
4. 文档回写：按下节映射逐条完成
5. 无半成品：无临时开关、无旧逻辑残留、无 TODO 占位

## 7 不合格样例（一眼可判）

- 目标写成"优化""完善""提升体验"
- 只有"进"没有"不进"
- 指南出现"适当调整""视情况""合理优化""参考实现"
- 只写改哪个文件，不写改哪个函数、输入什么状态、输出什么状态
- 有迁移无回滚，有回填无校验
- 04 写"已自测通过"却不写跑了哪条流程、哪个失败态

## 8 回写映射（强制）

| 改动类型 | 必须回写 |
|---|---|
| 界面与交互 | `doc/2_原型图/` 对应端的串联原型（含新增或变化后的跳转关系） |
| 前后端共享数据结构 | 第 6 步模块文档的数据类 + 契约生成物 |
| 失败降级与状态归属 | 第 6 步模块文档的调用关系与失败降级段 |
| 表、字段、约束 | `sql`（DDL）+ 数据字典 + ER |
| 新依赖与版本 | 第 4 步技术栈（不可逆项写原因） |
| 运行、部署、测试步骤 | 第 9 步开发部署手册 |
| 流程节点变化 | 第 2 步最简流程 |
| 每轮实际提示词 | `prompt.md` 追加主题节 |

## 9 反模式

假迭代（每轮都不可交付）／大爆炸（一轮改数十文件）／重构运动（想一轮改完，留下更糟的中间态）／范围蔓延（轮内加需求）／无留痕 hack／只加功能不还债／文档漂移／一轮多目标／用"下轮再迁"逃避迁移。

## 10 与"阶段 A 不许敏捷化"的关系

阶段 A 禁敏捷化，是因为设计未定型时切片的返工代价高于串行做完；阶段 B 必须是迭代，是因为基线已可运行，改动收益只能靠短周期验证。两者不矛盾：**禁的是"设计期偷跑"，不是"交付后演进"。**
