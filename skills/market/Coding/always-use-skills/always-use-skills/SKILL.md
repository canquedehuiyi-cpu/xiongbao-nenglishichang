# Always Use Skills — 技能优先执行协议

## 触发时机

出现以下任一情形时，先审阅可用技能列表再动手：

- 新任务（新功能、新问题、新文件、新项目）
- 错误 / 异常需要排查
- 进入此前未涉及的领域（部署、图表、支付、设计等）
- 会话开始后的第一条实质性消息

无需审阅、直接回复的情形（不浪费上下文）：

- 纯确认 / 闲聊（"好的"、"继续"、"谢谢"）
- 对上一步输出的小修正（追加说明、改措辞）
- 本任务内已审阅过且技能列表未变

## 三级判定

| 级别 | 特征 | 动作 |
|------|------|------|
| 强匹配 | 技能名称 / 描述与任务关键词直接命中 | 立即调用，遵循其指令 |
| 疑似 | 领域有交集 / 直觉可能有帮助 / 你在犹豫 | 调用并快速评估：相关则遵循，明显跑偏则说明后跳过 |
| 无关 | 与任何技能领域无交集 | 跳过 |

犹豫 = 调用。宁可多调一次，不可错过一个本该用的技能。

## 禁止的跳过理由

| 想法 | 为什么错 |
|------|----------|
| "这只是个简单问题" | 简单问题也可能有对应技能 |
| "我已经很熟悉了" | 技能可能有你忽略的细节 |
| "我先看看代码再说" | 技能会指导你如何看代码 |
| "可能不适用" | 不确定 = 调用确认 |
| "太慢了" | 跳过导致返工更慢 |

## 调用方式

通过当前环境的技能调用机制加载技能（不是用 Read 把 SKILL.md 当普通文档读）：

- TRAE：`Skill` 工具，参数为技能名
- Qoder：按系统提示中给出的技能加载方式调用

加载后必须把技能指令当作本次任务的执行准则。

## 优先级

多个技能同时适用时：

1. 流程类技能优先（约束工作流的：头脑风暴、写计划、TDD 等）
2. 领域类技能其次（针对特定技术栈 / 场景的）
3. 通用工具类最后（截图、视觉识别等）

## 失败降级

技能调用失败（不存在、加载出错）时：记录原因、跳过、继续正常完成任务，不重试、不阻塞。
