# Mura 检测项目案例（单项目经验，不是通用阈值）

来源会话：`70930b8d-13e1-4d41-95ad-e597ea1dd475`（2026-10-15 至 2026-10-19）。

## 数据与任务

- 工业 Mura 缺陷检测，2 类：black、white。
- 数据集 `dataset_0728_semi_v3`：948 train / 94 val。
- 模型起点：YOLO12n 预训练权重。
- 硬件：RTX 4080 16GB。
- 环境：Ultralytics 8.4.90。

验证集只有 94 张，指标波动较大；以下数值只用于说明方向和量级，不应直接作为新数据集的阈值。

## 已验证结果

| 实验 | mAP50 | mAP50-95 | 说明 |
|---|---:|---:|---|
| baseline，lr0=0.001 | 0.8304 | 0.4791 | 200 epochs 基线 |
| copy_paste=0.5 | 0.8368 | 0.4436 | mAP50 小幅提升，mAP50-95 下降 |
| mixup=0.3 + copy_paste=0.3 | 0.8330 | 0.4491 | 提升有限 |
| lr0=0.005，200 epochs | 0.9161–0.9162 | 0.6462 | 本项目最大单项改进 |
| lr0=0.005，400 epochs | 0.9627 | 0.7504 | 继续提升 |
| lr0=0.005，500 epochs | 0.9713 | 0.7537 | 继续提升 |
| lr0=0.005，500 epochs 复现 | 0.9774 | 0.7681 | 本项目最高记录 |
| lr0=0.005，180 epochs 重训 | 0.8873 | — | 低于 200 epochs，说明减少 epoch 不一定改善 |

| YOLO12m | 0.8083 | 0.4330 | 比 nano 差 |

## 失败与纠正

### 1. 自定义 `best_mAP50.pt` 无法加载

在 `on_fit_epoch_end` 中手写 checkpoint 字典，加载时报：

```text
TypeError: ERROR ... references types outside the supported Ultralytics checkpoint format
```

最终只能使用 `best.pt`。正确方向是复制官方 `last.pt`，见 `references/ultralytics-pitfalls.md`。

### 2. `erasing` / `auto_augment` 实验完全相同

用户发现两个实验曲线完全一样。排查确认：

- `erasing` 和 `auto_augment` 只用于分类任务；
- 检测任务的 `v8_transforms` 不使用它们；
- 两个实验实际使用相同的检测增强配置。

### 3. 180 epochs 反而更差

用户希望减少 epochs 缓解过拟合，但 180 epochs 重训 mAP50=0.8873，低于 200 epochs 的 0.9161。说明单次训练波动可能大于“减少 epoch”的收益；后续把 400/500 epochs 作为独立实验对比，而不是直接替换原最佳。

### 4. 更大模型与 P2 层

在该小数据集上，YOLO12s/m 与额外 P2 检测层均未超过 YOLO12n 基线。不要把这些结论泛化到所有数据集；它们只支持“小数据集先不要盲目增加容量”的假设。

## 可复用的教训

1. **先固定基线，再单变量实验**；否则无法判断提升来自哪里。
2. **最大收益可能来自学习率和训练量**，增强的收益可能很小；不要只堆增强。
3. **同时保存两个 best**：默认 `best.pt` 是 mAP50-95 最优，mAP50 峰值可能出现在另一个 epoch。
4. **拟合状态要看 train/val loss 与 mAP 的组合趋势**，不能只看 mAP50 峰值。
5. **验证集小时必须复现**；单次峰值可能是噪声。
6. **自定义 checkpoint 风险高**；复制官方 `last.pt` 并做加载烟雾测试。
7. **无效增强会静默浪费算力**；批量运行前先用 `--dry-run` 和相同曲线检查拦截。
