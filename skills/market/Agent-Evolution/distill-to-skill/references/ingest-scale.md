# ingest-scale（自主件移出的细则册）

> **本册由主件 `SKILL.md` 按需加载。** 主件保留操作核心与一行指针；本册是细则全集，执行到对应环节时读取，不需要时不必预读（省时间与成本）。内容与主件同源。

### A0 规模适配层（大内容预处理·防崩溃第一关）

投料先过本层再进 A1 路由。无论文档、报告、书籍、视频转写、会议纪要、英文、杂志、学术刊，体量都可能极大——本层负责“不整段塞入上下文、不漏失段落、不崩溃”。

体积分级（按「可读正文字数」判定，中文按字符计、含标点空白换行）：
- 口径硬规定（消除歧义·防误判 XL）：
  - 纯文本 / md / txt：直接统计文件解码后的字符数。
  - docx / pptx：用解析库取正文文本（段落 + 文本框 + 表格内文字）后计字符数；**禁止**用文件字节数、资源管理器"大小"、压缩包体积、或 docx 内部 XML 原始字符数（XML 原始字符数含大量格式标记，会虚高 5–10 倍，须用解析库取正文文本计字符数）。
  - pdf：取文本层字符数（扫描版走 OCR 后再计）；无文本层不得按文件大小估。
  - xlsx / csv：按结构判定（见 O3 大表规则），不按字符数分级。**但用户要 Excel 标准数据表时，表格是交付对象 → 全量结构化读取，不走采样**（边界见 O3 大表规则条）。
- S < 5K：直接进四段式（A3），单轮可处理。
- M 5K–30K：单轮可处理，建议先掠骨架。
- L 30K–100K：必须分块（A0.1），逐块提取后汇总。
- XL > 100K：必须"先规划后执行"（A0.2），架构侦察 → 分块 → 逐块 → 汇总。

A0.0 多模态归一（视频/语音/图片先降维再分块·防性能崩溃）：投料含媒体（O4）时，先按方法标准把媒体降维为锚定文本（转写 / OCR），再走文本适配层——用户零操作，直接给任意格式媒体即可。格式口径、视频字幕形态三分支判定、字幕带预探测与 OCR 健壮性、质量护栏、锚定文本缺失兜底、链路与误差标注等细则见 `references/multimodal-ingest.md`（仅 O4 媒体出现时加载，A 模式常规文本蒸馏不进本文件）。

A0.1 语义分块（确定性，由 `scripts/ingest_chunk.py` 执行）：
- 按语义边界切：标题（#/##/第X章/节/回）、说话人切换、时间戳、空行段落；不按固定字符硬切。
- 单块上限 4K 字符，超限在句边界再切，防单块过大。
- 每块带稳定 ID 与就近标题，产出可独立验证、可溯源、可回退。
- 输出：分块清单（JSON）+ 执行计划（先骨架后细节）。

A0.2 先规划后执行（架构优先）：
适用：XL（>100K）强制启用；长语音 / 长视频转写稿（单一连贯方法论素材）即便落在 L 级（30K–100K）也建议启用——源为单一连贯结构，架构侦察 + 三遍扫描价值大，避免逐块漏失整体骨架。
- 架构侦察：先扫目录/大纲/标题/首尾段，产出“架构骨架假设”（章节树/流程节点/核心判定），不先抠细节。
- 逐块提取：每块按所属适配层（A4.1 路由）走四段式最小闭环，产出“可复用单元 + 挂接架构位置”。
- 汇总架构：把所有块单元挂到骨架上，去重、归并、识别“核心架构层 vs 附属叙述层”。
- 架构优先提取（三遍扫描）：①骨架（章节/标题/流程节点）②核心单元（判定/规则/参数/步骤/阈值，即底层逻辑、方法论、技巧）③剥离附着物（举例/情绪/重复/闲笔/广告）。附着物不进包，仅记“已剥离冗余 N 处”。

A0.3 防崩溃护栏（L/XL 强制）：
- 整段超限保护：超过 L 阈值不整段进上下文，强制分块。
- 块级隔离：单块失败只回退该块重提，不整体崩溃；失败块标"待补"不强行编造。
- 汇总幂等：重跑不产生重复单元；已处理块可断点续跑（记录进度状态）。
- 块覆盖完整性门禁（汇总前必过·机器校验）：A0.1 / A0.2 逐块提取时，每处理完一块将其 ID 追加写入状态文件 `runs/<任务>/.work/processed_ids.txt`（一行一 ID）；汇总架构前必须实跑 `scripts/verify_chunks.py --plan <分块清单.json> --processed <processed_ids.txt>`——该脚本输出差集（分块清单有、processed 无的块 ID）；**差集非空则回退重提差集块，脚本 exit≠0 一律不许出包**，从机器级杜绝「漏蒸数万字 / 整块丢失」。
- 媒体长链防崩（与文字同源）：音视频降维走 `scripts/media_ingest.py`，长媒体（>10 分钟）**代码级真分段**——ffmpeg 按 ≤10 分钟切段 → 逐段 whisper → 带时间戳拼回，绝不整段喂模型（避免超大显存 / OOM / 超时崩溃）；单段失败隔离标「待用户确认」不整体崩。图片 / 音视频**批量投来**走同一脚本 `--files/--dir` 批量入口，逐文件隔离处理、写 `media_plan.json`+`media_processed.json`，蒸馏前实跑 `scripts/verify_sources.py --plan media_plan.json --processed media_processed.json` 做源完整性门禁（漏单元不出包），与文字 verify_chunks 同构。
- 多形态/多语言：英文/杂志/学术/视频转写/会议纪要，统一先降为文本块（OCR/转写），本层只认文本块；非中文同处理。
- 完整正文获取：文档类（docx 等）须取完整正文再分块；若宿主预览接口只回摘要或截断正文，改走本地解析文档内部结构取全文，不靠预览摘要，避免漏失正文。文档类（docx）摄取统一走 `scripts/docx_ingest.py`（纯标准库解 zip+xml，UTF-8 解码，绝不裸读 xml、不猜编码）；失败明确告知用户，不静默换法、不靠宿主预览摘要。
- 容量边界：单块 ≤4K 字符，远小于上下文窗口，不整段塞上下文；33K 字 / 71KB 书籍级长文可分块后逐块提取汇总出标准包；>100K（XL）必须"先规划后执行"（A0.2）。纯文本直接粘贴进对话超 30K 字时，引导用户上传文件而非粘贴，避免单次输入截断。
- 表格 / 大表专用规则（O3 结构化资料）：表格不是线性文本，不按字符数分级而按结构分级。**适用边界（必读）**：本规则管「表格作为**素材**、被萃取进您读文档 / 技能包」的情形——提取只用"页签名 + 表头 + 关键列 + 聚合值 + 抽样行"，绝不全量 dump 整表进上下文；单表行数 >5 万走分块采样（按页签 / 按列族分块），避免一次吃整表导致慢 / 崩。**例外（形态变了，规则就变）**：用户要 **Excel 标准数据表**时，**表格本身就是交付对象**，必须**全量结构化读取（全部行全部列）**、不得采样——采样会直接导致产出缺行缺列（详见 `references/bc-output-standards.md`「标准数据表默认语义」节）。

### A0.3+ 多源同投·源级防爆炸护栏（一次投多份材料不出错）

用户可能一次投来多份材料：同型多份（链接×20 / 文档×10 / 图片×50）+ 多格式组合（图+文 / PPT+文 / 音视频+文）同投。本护栏保证「接得住、不崩、整理得开」。

- **统一接料入口（确定性落地·`scripts/intake.py`）**：以上「全暂存 / 逐个处理 / 单源失败隔离 / 源完整性门禁」由本脚本在工程层落地。它一次接收【任意 N 的】链接（`--url` 可重复）、本地文档（`--file` 支持 glob）、文件夹（`--dir` 递归）、直接文本（`--text`，`'-'` 走 stdin）、预写清单（`--manifest spec.json`），按类型路由到 `web_ingest` / `docx_ingest` / `pdf_ingest` / `pptx_ingest` / `xlsx_ingest` / 媒体 `media_ingest`（subprocess 委派）；链接、文档、大文本、媒体任意 N 路组合全部并入【同一份】 `materials_plan.json`（含失败单元）+ `materials_processed.json`（成功单元）+ `corpus.txt`（拼接正文供 `ingest_chunk.py` 分块）。工程铁律：①每种形态永远按多份处理，绝不假设单一；②任意 N 路组合并入同一 plan，不拆、不相互污染；③单单元失败隔离（失败记 `status=error` 不进 processed，`verify_sources.py` 会钉死漏单元→exit≠0 不许出包）；④大文本整文件读后交分块，不整段塞上下文。投料阶段 Agent 只需调一次 `intake.py` 即可把「多链接+多文档+大文本+媒体」的混合轰炸归一成下游可对账的统一单元集。
- **接料两问（缺一不可）**：① **这份材料能不能读**（抽得出正文）；② **这份材料干不干净**（有没有夹带不可见字符）。不可见字符是**注入攻击面**（零宽 / 方向控制符〔Trojan Source，CVE-2021-42574〕/ 不可见字母 / 变体选择符〔不含 U+FE0F·Emoji 呈现选择符〕/ 标签块）——人看着是正常内容，模型读到的却是被注入的指令。由 `scripts/sanitize.py` **一律先清再送下游**，清到就**如实报告**（哪一份、几处、属哪几类），不静默。与 A6#10「我们的产物不许含不可见字符」是同一条规矩的两面：**清别人的、不许自己注**，两边**共用同一判据**（`is_invisible_codepoint()`，不许漂移）。
- **来源台账（`sources.json`·逐份留痕）**：接料时逐份记下**来源 + 走了哪条路读出来的**（文本直读 / Word 文档层 / PDF 文本层 / 幻灯片文字层 / 表格单元格 / 网页正文提取 / 图片识别 / 音频转写 / 视频转写）+ **清洗情况**。两个用途：① **结果声明说清「怎么读的」**（哪一份是估的、哪一份降级了、哪一份没抽到正文）；② **多来源产物页脚出「来源总览」**（见 A0.5 交付段第 6 条）。

- **接收即全暂存**：确认模式前，无论一次投来多少源，一律只暂存、不载入上下文、不处理、不提取、不写文件。接收确认明确按类型报数（文档×p / 图片×m / 链接×n / 音视频×q / 文字×k），总量 N 可见。
- **源级逐个处理（不整锅塞）**：确认模式后，按源逐个走适配层，绝不在同一轮把所有源正文同时塞入上下文；每处理完一个源报进度「已处理 x/N（源类型·名称）」，用户随时知道进行到哪。
- **单源失败隔离**：某源处理失败（格式损坏 / 获取失败 / OCR 失败 / 空正文 / 转写段失败）→ 仅该源标「待补」并说明原因，其余源继续，不整体崩溃、不静默丢弃。
- **媒体批量不崩编排**：图片 / 音视频大量同投时，走 `scripts/media_ingest.py --files <a.png;b.mp3;…>` 或 `--dir <文件夹>` 批量入口——逐文件隔离处理（单文件异常不影响其余），返回汇总（total/ok/failed/失败单元+原因）；失败单元明确回用户「X 成功 / Y 失败（列单元与原因），失败的请补文字稿 / 字幕」。⚠️ 批量必须带 `--out-dir <目录>`——否则不写 `media_plan.json`/`media_processed.json`，下游 `verify_sources.py` 会因门禁文件缺失 fail-closed 拦下出包（宁可误停不可漏放）。
- **源完整性门禁（蒸馏前必过·跨材质 uniform）**：多源萃取完成后、进蒸馏前，必须按材质跑对应门禁——文字走 `verify_chunks.py`、链接走 web_ingest 批量汇总、媒体走 `verify_sources.py --plan media_plan.json --processed media_processed.json`；**三者任一差集非空（漏处理单元）一律不许出包**，回退补处理差集单元。把「漏 8 万字 / 漏几张图 / 漏几段音频」从流程级钉死成机器级。
- **多源超大→先规划**：多源合计远超单源阈值（如合计 >100K 字符，或源数 >5）时，先架构侦察（扫所有源骨架 / 标题 / 首尾段）→ 逐源逐块提取 → 汇总去重归并，不整锅塞入、不漏失。
- **组合源走 O10 混合适配层**归并，各源按自身形态路由（图文 / 音视频+文 等），不混处理、不相互污染。
- **产出形态由用户定**：多源萃取后，用户可要「整批萃取成一份」（默认），或「逐源各出一份」（逐源分别走 A/B/C）；前者一次产出、后者逐源迭代产出，均不出半成品。

### A0.3++ 接料失败三分支（接不住也明确说 · 不许静默失败）

接料不是"能读就读、读不了拉倒"。任何一份材料进来，只有三种结局，**每种都要明确说出口**——用户不许在"不知道发生了什么"里干等。三支守同一条底线：**不许静默失败、不许连环追问、不许拿半成品充数**。

- **分支一 · 读不出**（格式损坏 / 加密 / 空正文 / OCR 失败 / 转写失败）：说清**哪一份、为什么、怎么办**——① 点名到具体单元（文件名 / 链接）；② 一句人话说明卡在哪（打不开 / 是扫描件没有文字层 / 里面是空的）；③ **给替代提供方式**（能截图的截图、能复制粘贴的直接贴、能转成 txt 或 pdf 的先转格式、口述内容可以直接打给我们）。**不猜、不静默换法、不拿宿主预览摘要顶替全文**（取不到完整正文就照实说，同 A0.3「完整正文获取」）。
- **分支二 · 料不足**（能读，但内容撑不起用户要的产出）：**先给「最小材料清单」，只问一次**——说清"要出 <用户要的形态>，至少还需要 X"，X 尽量具体（哪几章 / 哪几个字段 / 哪一段时间范围）。**一次问完，不许连环追问**；用户补了就继续；用户明确说不补 → 就按现有材料出一份**如实标注覆盖范围的产物**（如"仅覆盖已提供的 N 段"）并说清缺哪块，**绝不替用户编内容把缺口填满**。
- **分支三 · 超范围**（能力边界之外）：**直说"这个我们不做"，并给替代路径**——顺序 ① 先用现有能力做出**最接近的表达**；② 做不到就说清差在哪、差的那部分该找谁（另一个工具 / 人工 / 平台自带功能）；③ **绝不硬编不支持的类型去撞报错**——报错是"我们给错了"，不是"用户用错了"。（与「能力边界必须与能力同时写明」同源：**支持什么 / 不支持什么 / 不支持的怎么替代**，三件一起说。）
- **汇报口径**：三分支的结论一律出现在**对话里**（用户看得见的地方），不藏进内部日志；**说清了再往下走，没说清不许往下走**。

三、形态 → 适配层映射

| 材料形态 | 适配处理 |
|---|---|
| 文本 / 文档 | 直接分块，结构识别 |
| 链接（支持批量） | 多条链接走批量：`scripts/web_ingest.py --urls <链接清单.txt>`（每行一链接，或重复 `--url u1 --url u2 …`），逐条获取正文产 `body_N.txt` 再统一走 ingest_chunk.py 分块；单条亦可用 `--url <链接> [--out body.txt]`。批量返回汇总（成功数 / 失败数 / 失败链接 + 原因），部分失败须明确回用户「X 条成功 / Y 条失败（列出失败链接与原因），失败的请复制正文或传 PDF / 截图」。⚠️ 网页 / 链接常取回空正文或验证页，属正常降级，不引入浏览器引擎，请用户复制正文或传 PDF。 |
| 录音 / 语音（单人口播，如 mp3 录音） | 转写为文本即可，无需说话人分离；多方访谈 / 会议才需分离 + 议题切分。**长录音（>10 分钟）由 media_ingest.py 代码级真分段（≤10min 逐段 whisper 带时间戳拼回），不整段喂模型防崩**。大量同投走 `scripts/media_ingest.py --files a.mp3;b.mp3` 或 `--dir ./audio` 批量（逐文件隔离、失败单元隔离）。 |
| 会议录音 / 视频 | 转写 + 说话人分离 + 议题切分；走 media_ingest.py 视频/音频分支，长媒体同样真分段防崩。 |
| 短视频 | 走 A0.0 字幕三分支：有内嵌字幕轨→直接提取；无轨但有烧录硬字幕→字幕带 OCR（保真高于 ASR，采样 ≤1s 防漏抽，空结果三级重试）；无字幕→抽音轨 ASR；画面关键文字另做关键帧 OCR。批量同投走 `media_ingest.py --files/--dir`。 |
| 长视频 | 走 A0.0 字幕三分支：有轨直接提取；无轨有烧录硬字幕→先字幕带预探测、再 1fps OCR（保真高于 ASR，空结果三级重试）；无字幕无硬字幕→**由 media_ingest.py 按 ≤10 分钟真分段抽音轨 ASR 后带时间戳拼回（代码已落地，非仅注释）**。批量同投走 `media_ingest.py --files/--dir`。 |
| 图片 | OCR + 版面理解；关键信息请用户确认。**大量图片同投走 `scripts/media_ingest.py --files img1.png;img2.png;…` 或 `--dir ./imgs` 批量入口**——逐图隔离 OCR、返回汇总（成功/失败/失败图+原因），失败图请补图内文字稿；蒸馏前实跑 `verify_sources.py --plan media_plan.json --processed media_processed.json` 门禁（漏图不出包）。 |
| 口述 | 实时转写 → 确认关键点 → 进入蒸馏 |
