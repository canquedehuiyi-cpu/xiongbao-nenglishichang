# 模式 B / C 引导（用户选 B 或 C 后输出 · 逐级分步 · 全程决策 ≤3）

> 本稿在用户显式回复 B 或 C 之后由 Agent 输出，由 SKILL.md A0.5 指针引用。
>
> **决策不过三（本轮铁规 · 最高优先）**：从选模式到开工，用户在菜单上做的选择**最多 3 次**。本链固定为 **① 产出模式 → ② 交付格式 → ③ 萃取方向（仅 C）**，最深也就是 3 级。**内容深度 / 视觉观感 / 用途文体一律不上菜单** —— 它们都有默认值，用户口头一句话即可切换；这是「不制造选择困难」，**不是「能力下线」**。
>
> **呈现铁规**：每一级都**优先调用当前平台的选择组件弹出**，让用户点选；平台不支持时才回落为本稿的文本编码菜单。两条路径的**编码、文案、顺序、默认值必须完全一致**。
> **分页铁规**：宿主弹窗单题最多 4 个选项 —— 选项超过 4 个时**必须分页**（每页 ≤4），编码全局连续（第 1 页 1–4、第 2 页 5–7），**不得删项、不得重排、不得静默截断**（「不重排」指同一次呈现 / 同一会话内；跨版本要重排时五处必须同版同步，见 SKILL.md A0.5 交付回执编号条）；回落文本时一屏列全，编码与弹窗逐字一致。
> **分步铁律**：逐级输出，前一级确认后才给下一级；禁止一屏倒全。

**顺序**：**交付格式（B / C 都走）→ 萃取方向（仅 C 走）**。模式那一级在前，见 `references/opening-script.md`。

## 第 1 级 · 交付格式（可多选 · 分 2 页 · 不选即 Word）

**标题**：请选交付格式（可多选 · 不选默认 Word）。

> **顺序与编码**：按「先给最通用的可编辑源头、再给派生形态」排——**Word → PPT → Excel 图表 → PDF → Markdown → TXT → Excel 标准表**。Word 排第 1，既是默认值也是平台会标「推荐」的首项，两点一致。

第 1 页（4 项）：

| 编码 | 选项 | 一眼懂 |
|---|---|---|
| 1 | Word 正式文档（默认） | 人人能开、能改，可批注修订，适合存档 / 跨部门传阅 |
| 2 | PPT 演示文稿 | 分页图文，适合会议 / 提案 / 内训 / 分享 |
| 3 | Excel 图表分析报告 | 数据表 + 图表同页，适合数据分析汇报 |
| 4 | PDF 定稿文件 | 版式固定，适合对外交付 / 打印 |

第 2 页（3 项）：

| 编码 | 选项 | 一眼懂 |
|---|---|---|
| 5 | Markdown 文稿 | 轻量，适合持续迭代 / 跨平台迁移 |
| 6 | TXT 纯文本 | 通用兼容，适合快速存稿 |
| 7 | Excel 标准数据表 | 标准报表（**默认全量搬运 + 规整**，要按方向汇总说一声），适合结构化数据留存 |

**其他补充（本级出口 · 规格类 · 首屏可见）**：直接写您要的格式，或说规格 / 感觉（「要能打印的」「横版」「字大一点」）—— **不满意菜单里给的，就自己说一句，我们按您说的来。** 出口与选项**同屏**，不藏在分页末页。

**怎么回**：回数字即可，可多选——**不回就默认出 Word 正式文档（1）**；回 `2` 出 PPT；回 `2,5` 出 PPT + Markdown；也可说「全都要」。**不用打字解释。**

> **默认只出一份**：用户不选即按 **Word（1）** 产出，不强制多出——多格式是「主动勾选加项」的能力，不是默认义务。
> **跟随真实需要**：用户话里已带格式诉求（如「给我份 PPT」「要打印」）的，以用户为准，不走默认，**也不再弹这一级**（他一句话已经答了）。
> **成本可见**：每多勾一种格式就是多一道产出、多一份文件——不替用户多产出，也不替用户省。

> 分两页是宿主弹窗 4 项上限所致，**不得为省一页而删掉 5-7 项**；回落文本时一屏列全 7 项。
> 跨页多选合并：第 2 页弹窗标题注明「已选：1,3（还可补充 5-7）」，两次提交**追加合并**（回执如 `1,3,5,7`），不覆盖前页。

→ **B 模式到这里就开工**（无第 2 级；**开工前先用一句话对齐理解、不等确认**）；**C 模式继续第 2 级**（**收到方向后同样先对齐、再开工**）。对齐口径见 `references/agent-behavior.md` 第五节第 4 条。

> **选了 Excel 图表分析报告（编码 3）之后**：Agent 在整理数据前先做**接料前置三步**——读表结构 → 一句话回执并给推荐图型 → 用户一句话可覆盖（如「换饼图」「横过来」「就看占比」）。图型按 `references/bc-output-standards.md`「Excel 图表选型与边界」的选型规则自动定（**规则拿不准时兜底柱形图**），**不为图型再开一级弹窗**（守 A0.5 第 12 条「不制造选择困难」）。用户要「树状图 / 关系图」时，如实说明当前只支持柱形图 / 条形图 / 饼图 / 折线图四种，并给三步替代（首选「条形图 + 缩进层级标签」）。若同时勾了编码 3 与编码 7，3 出图表分析报告、7 出标准数据表，两者不冲突。
>
> **选了 Excel 标准数据表（编码 7）之后**：默认**全量搬运 + 规整**（源表全部行全部列进产出，只做表头统一 / 数字格式按列 / 冻结表头 / 清空空行空列，**不预设汇总维度**）。交付时附一句「如需按某维度汇总（按人 / 按地区 / 按月 / 按产品…），说一声即可」——**一次重出、不重复问**；**永不自行选汇总维度**（维度是用户的业务视角，我们推不出来）。详见 `references/bc-output-standards.md`「标准数据表默认语义」节。

## 第 2 级 · 萃取方向（**仅 C 模式**走这一步）

C 是定向萃取，先有方向才动得了手。**候选方向由 Agent 从材料内容动态生成**（不可写死），最多 4 项：

**标题**：您想按什么方向萃取？（可直接在「其他」里写您自己的关键词 / 问题 / 提示词）

| 编码 | 候选 | 来源定位（取自材料哪一处） | 一句话用途（选它得到什么） |
|---|---|---|---|
| 1 | 候选方向一 | 材料主体议题 —— 写明摘自哪一节（如「摘自第 2 章」） | 抓最核心的那条主线 |
| 2 | 候选方向二 | 材料次要议题 —— 写明摘自哪一节（如「摘自第 5 节」） | 抓主线之外的次重点 |
| 3 | 候选方向三 | 材料的行业 / 对象特征 —— 写明依据（如「取自主标题」） | 按材料的对象特征收口 |
| 4 | 通用要闻速览 | 兜底项，不指向某一处 | 不分方向，全篇要点速读 |

**其他补充（本级出口 · 方向 / 主题类 · 首屏可见）**：直接写关键词 / 主题 / 问题 / 提示词 —— 菜单里没有您要的方向，**自己写一句就是**，我们按您写的抽。出口与选项**同屏**。

> 生成硬规：候选必须**来自材料本身**（标题、章节、高频主题），每项 ≤12 字、一眼懂；**每项附「来源定位」（取自哪一节）与「一句话用途」（选它得到什么）**；拿不准就把「通用要闻速览」作为兜底项保留。**清单只列「候选 + 来源定位 + 一句话用途」这一种形态、不解释落选者** —— 候选清单要保持一眼看完的长度，不给「为什么没选它」这类解释。
> **这一级是「必需输入」**（不选就不知道该抽什么）——故**不设默认值**，改用「兜底项 + 其他补充」兜住空白，保证用户永远有得选、也永远能自己写。

## 不上菜单的三级（都有默认值 · 口头一句话即可切）

| 维度 | 默认 | 用户口头怎么说 | 说明 |
|---|---|---|---|
| **内容处理深度** | **D1 完整原生**（B / C 同） | 「改写成我的话」→ D2；「只留骨架 / 只要框架」→ D3 | 原为 C 的强制门禁；按「决策不过三」降为**默认值 + 口头出口**。深度只改**内容保留力度**，不改文件格式。 |
| **视觉观感（风格 / 版本）** | **标准商务**（`biz` + 标准商务版式） | 「要红黑硬核」「用课件版」「数据简报那种」「典雅一点」 | 原为 PPT 专属两级；现**全部格式**默认标准商务。生成器**同样接受**配色 / 字体 / 字号规格 / 序号参数，Agent 按映射表调参重出即可。 |
| **用途文体** | **通用正文**（`plain`） | 「要能照着讲」→ 讲稿体；「做成口播稿」→ 口播体；「做知识卡片」→ 卡片体 | 只改文风与分段，不改文件格式。**讲稿体 / 口播体的正文写进 `paragraphs`（成段的话）；卡片体写进 `points`（一卡一要点）** —— 两个容器不可互替，折错了排版救不回来。 |

> **这是「不上菜单」、不是「能力下线」**：以上三项**能力都在、生成器参数都在**，只是不再占用用户的决策次数。**用户说了就照做**，不得以「本轮没问这一级」为由拒答。
> **默认为什么是这三个**（过四问：① 用户打不打得开 ② 交付形态完不完整 ③ 成本是不是最低必要 ④ 下游好不好转）：D1 保真不减内核、标准商务人人看得惯、通用正文哪都能用 —— 三项都站「低成本 · 高通用」那一端，差异化由用户按需口头加。

## 维度 × 格式适用矩阵（不适用就不弹、也不套用）

| 维度 | Word | PPT | Excel 标准表 | Excel 图表 | PDF | MD | TXT |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 交付格式 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 萃取方向（仅 C） | ✓ | ✓ | – | ✓ | ✓ | ✓ | ✓ |
| 内容深度 | ✓ | ✓ | – | – | ✓ | ✓ | ✓ |
| 观感（风格 / 版本） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 用途文体 | ✓ | ✓ | – | – | ✓ | ✓ | ✓ |
| 图表类型（自动定，不弹） | – | – | – | ✓ | – | – | – |

> **表格类不做「深度 / 文体」** —— 表格是数据、不是行文：拿一张表问「要不要改成口语体」是错的。**格式决定哪些维度适用**，不适用就**不问、也不套用** —— 这正是「格式与真实需求匹配」在引导链上的落地。

## 决策计数与接管（口径写死）

- **怎么数**：用户在**菜单上**做出的选择才算一次。最坏路径 = 模式（1）+ 交付格式（1）+ 萃取方向（1，仅 C）= **3 次**。
- **用户自述 = 直接接管、不额外计次**：用户若用自己的话说了要求（「我要 PPT 和 Word」「只留骨架」「按华东看」），**该级直接按他说的办、不再弹该级菜单**，并回执「已按您的说法办」。他一句话说了算。**自定义优先级三层写死：用户自述 > 菜单预设 > 默认值**（其余出口条文见下节「自主出口」）。
- **没走到该级不提前抛选项**；一级只问一件事。
- **超出 3 次即属违规**：若实现上又冒出第 4 级选择，**先想它的默认值**——想不出默认值的可选择维度，就是不该上菜单的维度。

## 自主出口（各级通用 · 用户自述 > 菜单预设 > 默认值）

> **默认值管「不选也能走」，出口管「想自己定也有地方去」** —— 两条合一才不把用户框死。预设本是为了让**不会用的人快速拿到结果**；但对**有自己方法论的人，框死＝他觉得这是机械式产品、发挥不了、不愿用**。同一个菜单，对前者是**梯子**，对后者若插不上话就是**墙**。

- **① 每级出口分型（写死）**：
  - **方向 / 主题类**（C 萃取方向）→ 出口写「**自己写关键词 / 主题 / 问题**」；
  - **规格类**（交付格式 / 内容深度 / 观感 / 文体）→ 出口写「**不满意就自己说 —— 想要什么格式、什么感觉、什么规格，按您说的来**」。
- **② 自定义优先级三层顺序（写死）**：**用户自述 > 菜单预设 > 默认值**。用户说了什么就按什么办；菜单里有的按菜单；都没说才用默认值。**不得以「菜单里没有这一项」为由拒绝** —— 要么照做，要么如实说清能力边界 + 给替代路径。
- **③ 活口第一屏可见**：出口（「其他补充 / 自定义」）必须**出现在首屏、与选项同屏**；藏在分页末页或折叠里 ＝ 墙上的小门，不算敞开。
- **④ 接管即静默**：用户一自述要求，**该级不再弹菜单**，直接按他说的办，并回执「已按您的说法办」（见上节「决策计数与接管」）。
- **⑤ 事后自我完善（交付后同样有效）**：交付后用户改口 / 加要求 / 换口径，**一律以他为准、直接重出**；不辩解、不说「刚才您没提」。需要时回执「已按您新说的重出」。
- **⑥ 出口是随时可用的兜底、不是必答项**：加了出口 ≠ 加负担 —— **一路默认到底仍须完整可交付**；用户想加我们没预设过的维度，也要接住。
- **⑦ 禁止让用户先声明层级**：**不问**「您是新手还是专家 / 要不要自定义」。正解＝**默认高兜底 + 处处可接管**，由行为自然分层，不由用户声明分层。

> **判据一句话**：**用户对给出的标准全都不满意时，能不能自己说一句话就拿到想要的？** 不能 → 用户被按进预设里了。

## 交付之后（回钩 + 结果声明 + 交付回执 · 必做）

1. **结果声明**：交付说明里紧跟一句大白话——"这一趟您拿到了什么"（如"您现在有了一份新人照着就能上手的维修判断流程"），**不写成"这是 XX 文件"**。口径＝**数量 + 单位 + 后果**，并说清**每一份材料是怎么读出来的**（"这份 PDF 是扫描页、没文本层"），**有缺口或降级必须主动讲**；逐份来源与读取方式取自接料台账 `sources.json`，不许凭印象说。
2. **回钩句（固定留）**：
   > 「无论您做的是 A、B 还是 C，随时想更新、迭代、优化、完善，**直接回到这里提要求就行**——我帮您接着处理，您只管说要改什么，不用重新传材料、不用重开会话。」
   只陈述事实，**不推销、不夸大**；用户回来提修改 → 走迭代修改流程（不重选模式、复用上下文、形态锁定）。
3. **交付回执（用户→我方的口）**：产物末行已自带「交付回执」（由 `constants.receipt_line()` 生成，紧随免责之后）；交付说明里把**做法标签**（材料类型 / 模式 / 格式 / 深度）一并给用户，并说明"贴回评论区就行"。**回执里只有做法标签、零用户内容**——不承诺、不索取、不夹带。
