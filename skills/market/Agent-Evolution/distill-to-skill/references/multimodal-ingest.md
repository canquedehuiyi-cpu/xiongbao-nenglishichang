# 多模态降维细则（A0.0 / O4 对应·按需加载）

本文件仅在投料含视频 / 音频 / 图片（O4 媒体）时加载。A 模式常规文本蒸馏不进本文件，避免无关注释占用上下文。

## 一、投料格式口径

- 音频 mp3 / wav / m4a / amr / ogg / flac / aac 等；视频 mp4 / mov / mkv / avi / webm / flv 等常见格式均支持：平台按原格式解码降维，本技能不限定格式、只认降维后的锚定文本块。用户零操作，直接给任意格式媒体即可。
- 文档投料格式（docx / pptx / pdf / xlsx / csv / md / txt 均支持）：①文本层文档（docx / pptx / md / txt / pdf 文本层）直接解析取完整正文；②扫描版 / 图片 PDF 走 OCR 降维（同本节）；③表格类（xlsx / csv）走结构 + 采样提取（见 O3 大表规则），不整表 dump —— **此条仅适用「表格作素材被萃取」的情形；若用户要 Excel 标准数据表（表格即交付对象），必须全量结构化读取全部行全部列、不得采样**（见 `references/bc-output-standards.md`「标准数据表默认语义」）。平台按原格式解析，本技能不限定格式、只认解析后的文本块 / 结构块。
- 投料为视频 / 音频 / 图片时，先按方法标准把媒体降维为锚定文本（转写 / OCR），再走文本适配层。用户零操作，直接给视频 / 音频 / 图片即可。

### 格式兼容矩阵（用户零操作，直接给任意格式）

| 类别 | 支持格式 | 降维方式 |
|---|---|---|
| 视频 | mp4 / mov / mkv / avi / webm / flv / wmv / m4v / ts | 字幕三分支（见下） |
| 音频 | mp3 / wav / m4a / amr / ogg / flac / aac / wma / aiff | ASR（≤10 分钟分段） |
| 图片 | png / jpg / jpeg / bmp / tif / tiff / webp | OCR |
| 文档 | docx / pptx / pdf / xlsx / csv / md / txt | 文本层解析 / 扫描版走 OCR / 表格走结构采样（**标准数据表形态例外：全量结构化读取**） |

包不限定格式，只认降维后的锚定文本块；环境缺某解码器时如实告知用户换格式或提供文字稿。

## 二、视频字幕形态三分支（判定顺序固定）

### 双形态自动判定（视频/音频常见两态）

- **有字幕有声音**：优先走字幕（内嵌轨提取 > 烧录硬字幕 OCR），声音仅作校验/补字幕空档；字幕与声音并存时以字幕为准（保真）。
- **只有声音无字幕**：直接抽音轨 ASR；长媒体按 ≤10 分钟分段后汇总，不一次吃整段。

判定由 `scripts/media_ingest.py` 自动完成（ffprobe 探流 → 路由），用户无需手动选路径。

1. 有内嵌字幕轨 → 直接提取字幕（最保真、最快）。
2. 无内嵌字幕轨但画面有烧录硬字幕（底部白字黑边等）→ 字幕带 OCR（保真高于 ASR，优先于 ASR）。
3. 无字幕轨且无硬字幕 → 抽音轨 ASR；长视频 / 长音频按时间分段（每段 ≤10 分钟）转写后汇总。

- 长视频（>10 分钟）若走 OCR，按 1fps 顺序抽帧 + 字幕带预探测；若走 ASR，按 ≤10 分钟分段；不一次吃整段大媒体。

## 三、字幕带预探测（长视频 OCR 前必做）

从视频头 / 中 / 尾均匀抽 20–30 帧，OCR 后聚类文字块 Y 坐标，识别主字幕带与次要文字带（含双行字幕漂移范围、插图说明文字带），输出字幕带 Y 范围掩膜参数；后续 OCR 只认主字幕带 + 漂移带，不把插图标签误当字幕。

## 四、字幕带 OCR 健壮性（空结果自动重试，全程内部进行、不向用户交付任何中间报告）

首轮 1fps 顺序 OCR → 对空结果帧自动 2x 放大重抽 → 仍空则按预探测字幕带裁剪后 3x–4x 放大 + 灰度 / 对比度增强重抽 → 仍空则标记「真空白」或「待用户确认」；所有重试轮次与找回行数内部留存，保真核对须基于最终补齐稿而非首轮稿。

## 五、质量护栏（所有路径生效）

- 字幕带 OCR 须顺序解码禁随机寻址防时间轴漂移、环形缓冲流式防内存溢出、密集采样间隔 ≤1s 快于字幕变更频率防漏抽。
- 大媒体（数 GB 长视频 / 长音频）按时间分段流式处理、不整文件载入内存，单段 ≤10 分钟，确保提取质量且不崩。
- 大文档（docx / xlsx / pdf 数 MB 以上）同样不整文件作为单一 blob 载入上下文，按结构 / 分块流式解析，避免一次吃整份大文档导致慢 / 崩。

## 六、锚定文本缺失兜底

当无法拿到媒体锚定文本（无论何种原因）时，如实告知用户：「当前材料未能转为可处理文本，请提供字幕文件（.srt / .vtt / txt）或文字稿」，并明确告知给什么、怎么给（粘贴屏幕字幕 / 导出 .srt / 上传 txt 转录稿），不得含糊说「请提供文字稿」。

## 七、链路与误差标注

- 转写文本落本地后，整个材料回归「文本」口径，继续走 A0.1 语义分块（L/XL 强制先规划后执行）。链路：媒体 → 分段转写 → 文本块 → 四段式，绝不「视频帧直接蒸馏」。
- 转写误差标注：转写稿标「转写稿（可能失真）」，低质音频 / 口音重部分在提取段标「待用户确认」，不强行编造。
- 图片：先 OCR / 语义提取为锚定文本，再走对应文本适配层；仅用公开可采素材，不下载受保护内容。
- 多语言：转写 / OCR 由宿主按原语种产出；需互译在转写阶段完成，本层只认文本块。深度双语风格保真走通用兜底并标精度（见 A9）。

## 八、包体轻量与运行依赖

本技能包安装轻量、不捆绑第三方库 / GB 级二进制；但**真实运行在联网的 agent 平台下**，媒体降维（ffmpeg / whisper / tesseract 等）由运行环境提供——agent 平台联网环境天然具备，或用户按需安装。`scripts/media_ingest.py` 只写路由判定与调用约定，二进制缺失时优雅降级（标记「待用户确认」，复用第六节兜底），不强行编造。包内核心文本蒸馏纯标准库、零第三方依赖、装上即跑；本包运行于需联网通电的 Agent 平台；媒体降维依赖运行环境工具属正常。
