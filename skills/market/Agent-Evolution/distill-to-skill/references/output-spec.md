# output-spec（自主件移出的细则册）

> **本册由主件 `SKILL.md` 按需加载。** 主件保留操作核心与一行指针；本册是细则全集，执行到对应环节时读取，不需要时不必预读（省时间与成本）。内容与主件同源。

### A7 标准件输出规格（跨平台·轻量）

产物结构：

```
<技能名>/
  SKILL.md        # 触发 + 步骤 + 判定 + 输出（能力层 + 辅助层）
  README.md       # 成品说明 + 溯源落款 + 「怎么用这份技能」三步（A6#19 盖戳落点，必含）
  usage-notes.md  # 使用日志空白表（用户回填口，必含）
  references/     # 参考素材（已脱敏、已拍平），可选
  scripts/        # 必要脚本，可选
  hooks/          # 写时护栏，可选，默认不启用
```

质检报告处置（A/B/C 全模式硬规·一律不交付）：本技能内部仍跑质量门禁（A5 L1–L4 / A6）确保产物达标，但**不向用户交付任何质检报告 / 质量证明文档**——质量门禁是内部生产标准（产物不达标就回退修补、不出包），干净产物本身即质量证明。对话内只输出「简短清单（文件名 + 一句话用途）+ 交付入口」，不贴正文、不交付报告。

起底骨架：蒸馏产出先套 `templates/distill-output-skeleton.md`（含 `【改编位】` 标记，填完清零），保证能力层+辅助层齐全、跨平台技能包规范合规、出厂自检可逐条勾。**同模板内另附 README 与 `usage-notes.md` 两份骨架**——README 必含「怎么用这份技能」三步（上传 → 平台识别 → 触发词唤起）；`usage-notes.md` 必为空白四列表（日期 / 我碰到的情况 / 它当时怎么答 / 我希望它怎么答），只给表头与一句用法，不给用户预制任何内容。

安装包交付（必产）：标准件文件夹产出后，须同时产出同名可安装压缩包（zip，无顶层目录、UTF-8 文件名、mtime 统一），与文件夹并列交付；**A 模式装配【必须】走 `scripts/assemble_skill.py`**（禁人工 / 平台手搓 zip），从脚本层保证每份产出的安装包结构一致、可重复。用户直接上传 zip 即可安装到支持技能上传的 Agent 平台，无需自行打包（用户通常不具备打包条件，不产 zip 则无法上平台）。

跨平台规则：

- 遵循通用技能包规范，不写死平台名、平台专有路径、平台专有接口、平台专有权限；依赖最小化，平台差异走适配层或条件判断，不污染核心能力层。
- 产出标准件，用户上传任意支持技能上传的平台即可安装运行。标准包跨平台可装。
- 本技能不做跨平台代装（无平台连接点，无法在他平台代为安装）。
- 若某平台拒绝安装，用户回传，本技能调整；或宿主 Agent 平台自身辅助发现与修正问题。

交付硬门禁（A/B/C 全模式通用·产出 Agent 完成前必逐条过，任一项 FAIL 禁止交付）：
- 【适用范围·先读】下列与 frontmatter 相关的 A 模式条款（`displayName` 纯 ASCII、schema 锁定、`credentials_usage` / `data_flow` 须为顶层）**管的是本技能产出的用户技能包**（标准写法见 `templates/distill-output-skeleton.md`）；本技能自身是平台侧技能包，其 frontmatter 字段与嵌套层级按所在平台 schema 约定，不套用上述「纯 ASCII / 顶层」两条。
- 【全模式·零号门禁联动·产出前终检】在生成 / 写出任何文件或内容之前，先确认本对话已显式选定模式（A/B/C）。未确认 → 立即中止当前生成，改为输出模式选择菜单（A0.5 一），不产出、不写文件。此检先于一切其他交付门禁。
- 【A 模式】文件集齐全：SKILL.md / README.md / usage-notes.md 必备；references / scripts 可选（均不强制）。不向用户交付任何质检报告——质量门禁（A5 L1–L4 / A6）内部跑通即交付干净产物，交付物本身即是质量证明（详见「交付硬门禁·质检报告处置」）
- 【A 模式】已产同名 zip：无顶层目录、UTF-8 文件名、mtime 统一；zip 名＝slug（由 `scripts/assemble_skill.py` 装配，禁手搓）
- 【A 模式】三同名一致：文件夹名＝frontmatter name＝slug
- 【A 模式】displayName 纯 ASCII：仅含英文 / 数字 / 空格 / 连字符，不含中文字符（中文标题放 README 首行或正文 H1，不进 frontmatter 名称字段）
- 【A 模式】frontmatter 合法：YAML 可解析；credentials_usage / data_flow 为顶层字段（不可嵌套于 security 下）
- 【A 模式】schema 锁定：仅允许骨架列出字段，禁增 tech_source / build_no 等非标字段（溯源统一走 README 落款，见 A6#19，本脚本不碰 frontmatter）
- 【A 模式】可调用达标：description 含 ≥5 真实触发说法；能力层含 触发 / 步骤 / 判定 / 输出 四要素；产出是技能包非分析报告
- 【B/C 模式】内容处理深度已定档（默认 D1 · 口头可切 · 不再询问）：深度**不上菜单**（守 A0.5 第 13 条「决策不过三」）——B / C **一律按默认 D1 执行**，并在交付说明里一句话告知「默认按完整原生出，要改写 / 只要骨架说一声」；用户口头说 D2 / D3（「改写成我的话」「只留骨架」）即照做。**本门禁判的是"深度档位已定"（默认或用户指定），不是"必须问过用户"** —— 不得因"没弹窗确认过深度"判不合格（那会与 A0.5 第 13 条正面打架）。**唯一禁止**：用户已明确说了某一档、产出却按另一档走（三层的第 1 层「用户自述」不许被覆盖）。
- 【B/C 模式】格式正确：产出为用户指定格式（PPT / PDF / Word / MD / TXT / Excel（XLSX）），必须调用包内对应生成器（`build_ppt_standard.py` / `build_pdf_standard.py` / `build_docx_standard.py` / `build_md_standard.py` / `build_txt_standard.py` / `build_xlsx_standard.py` / `build_xlsx_chart_standard.py`），严禁 Agent 手搓 XML / Markdown / 文本自由生成；版式符该格式固定模板（见 A0.4）
- 【B/C 模式】溯源落款：产出含统一落款「由 蒸馏成技能Skill 蒸馏产出」，轻量不侵入。B/C 产物若缺此落款、或落款被挤到不可见位置、或被平台生成器覆盖，视为不合格，必须回退重做；严禁 Agent 跳过包内生成器手搓格式。
- 【B/C 模式】中文与数字格式门禁：Excel（XLSX）工作表名、标题、表头必须中文，禁止英文表名/标题/标签；金额列固定 `¥#,##0.00`、百分比列固定 `0.00%`、整数列固定 `#,##0`，禁止浮点裸奔；PPT 目录页禁止出现英文 `CONTENTS` 等外来标识；任一项 FAIL 回退重做。
- 【B/C 模式】交付回执（用户→我方的反馈口）：产物末行必须带统一交付回执——前缀「交付回执：」+ 零内容边界（`constants.receipt_line()` 单一事实源），紧随免责声明之后（落款 → 免责 → 回执，三句三处、不合并）。**回执只含做法标签、零用户内容**（不承诺、不索取、不夹带）。缺回执即不合格。（机器判据：`scripts/verify_contract.py` 断言七格式全覆盖。）
- 【B/C 模式】八标准门禁：B/C 您读产物必须同时满足八标准——严谨 / 准确 / 清晰 / 有温度 / 有框架 / 有层次 / 有逻辑 / 专业（逐条「为什么」见 `references/bc-output-standards.md` 零节）。其中「有逻辑」硬规：凡并列 ≥2 点，必须编号——大标题 1/2/3、中标题 1.1/1.2、小标题 1.1.1…，层级编号让您一眼抓重点；**大于两点不编号 = 不交付**。任一项 FAIL 回退重做。
- 【B/C 模式】同源强制 + 一致性门禁：蒸馏完成只产一份 canonical outline，立即 `scripts/distill_skeleton.save_outline` 落盘；多格式产出【必须】经 `scripts/distill_skeleton.render_formats(outline, formats, out_dir)` 从同一 outline 渲染，禁止为每个格式单独重撰 outline（从结构上消灭某格式内容跑偏）；**讲稿体/口播体的成段正文写进 `paragraphs`、短要点写进 `points`**（两个容器不可互替）；交付前实跑 `scripts/verify_multiformat.py --outline outline.json --files <产物…>` 做跨格式一致性门禁，模块标题集合/数量不等、或成段正文缺失，exit≠0 不许交付。
- 【全模式】内部过程不外显：禁止向用户打印提取命令（如「我用 Python 提取」）、编码报错、「Let me…」/「我先…」式自言自语、「重新读取」等中间过程；只输出进度结论（如「已读取 N 份文档，开始蒸馏」）。工具/脚本执行细节属内部生产标准，不进对话。
- 【全模式】交付路径脱敏：交付只给文件名（或相对/沙箱路径如 `runs/<任务>/<成品文件名>`），绝不输出含用户名的绝对路径（如 `C:\Users\Administrator\…` / `/home/xxx/…`）。
- 【B/C 模式】输出文件命名硬规：文件名一律 `<材料名主干>_<动作后缀>.<扩展名>`——名干取源文件名（去扩展名、去平台前后缀与 `(1)` 类标记）；后缀跟「要什么」走：全量搬运规整 `_数据表` / 按方向汇总 `_汇总分析` / 图表分析 `_图表分析` / 通用精华文档 `_精华萃取` / 定向萃取 `_定向萃取`（技能包用 slug）。**禁**包标签名（「Excel 标准数据表」）、平台自拟名、`输出.xlsx` 类无关联名、含用户名 / 绝对路径。同批多格式同「名干」。详见 `references/bc-output-standards.md`「输出文件命名硬规」节。
- 【全模式】交付目录卫生（硬规）：**常量单一来源**——中间件根与成品后缀白名单定义在 `scripts/constants.py`（`RUNS_ROOT` / `WORK_DIR` / `DELIVERY_EXTS`，路径拼接走 `work_dir()`），各脚本一律引常量、不得各写一版路径字面；交付根卫生由 `selfcheck <交付目录> --product --delivery-root` 机器校验（外层只允许白名单后缀的成品 + `.work/`，出现散落中间件即 FAIL）。产物落盘分两层——**成品在最外层、中间件归隐藏子目录 `runs/<任务>/.work/`**。① **成品**（用户要拿走的文件：`.docx` / `.pptx` / `.pdf` / `.xlsx` / `.md` / `.txt` / A 模式技能包 zip / **媒体裁剪成品〔音频 / 视频 / 图片，如 `.mp3` / `.mp4` / `.png`〕**）落 `runs/<任务>/` 根，用户打开目录第一眼看到的就是成品；② **中间件**（`source.txt` 原始材料、`chunks_plan.json` 分块清单、`processed_ids.txt` 状态文件、`outline.json` canonical 大纲、`intake` / `media` 中间产物（含媒体分段中转件 `xxx_seg001.wav` —— 与音频成品同后缀、靠本条归位）、临时渲染脚本、日志）一律落 `runs/<任务>/.work/`，不外露；③ **不留垃圾**：0 字节的错误输出文件（如 `ingest_err.txt`）跑完删除；宿主编辑器产生的 `~$xxx.docx` 是编辑器锁文件、非技能产物，提示用户先关掉该文件即可，**不主动删用户正在编辑的文件**。中间件与成品混放，用户打开文件夹看到一堆看不懂的文件会误以为出错；分两层后用户只见成品、溯源材料仍在 `.work/` 可查。
- 【全模式】红线 0 命中：红线词表（8 词及单字红线）均 0 命中
- 【A 模式】内容铁律门：产出是 Agent 可调用的技能包、会被机器自动执行，故涉及投资 / 医疗 / 法律等强监管题材时只留方法 / 框架 / 决策尺子，严禁「买什么 / 什么时候买 / 能赚多少 / 具体买入条件 / 选股指标 / 持有 / 卖出纪律」式可被机器直接执行的动作建议；发现即回退重构，否则不出文件
- 【全模式】通用型标准件原则：用户给的任一具体投料只是「通用场景的一个点」，引擎必须产出通用标准件而非对该投料定制——差异化的个性化需求由 agent 在对话中按需解决，标准件只守共性底线（八标准 + 固定版式 + 固定生成器 + 固定判定逻辑）。用户拿到即精品 / 至少标准品，不依赖对单个投料的特殊适配；默认所有用户都需要共性的、通用型的产出。
- 【全模式】服务结果中心与稳定性铁律（优化边界）：一切优化以「服务结果」为中心——任何改动不得降低 agent 交付的稳定性与确定性，不得为追求形式完美（如过度隐藏方法、强行结构重组、迁移深层方法文件、重构生成器）而触动运行时逻辑或生成器，导致产物版式 / 内容 / 格式漂移。稳定可预期的交付优先于理论上的更优；结构性大改须先评估对交付稳定性的影响，确认无回退风险方可实施，否则保持现状。
- 【B/C 模式】保真蒸馏门：产出是您读文档，忠实保留源材料内容、不替用户删内容、不替用户决策；三条硬约束（不注水 / 标来源 / 留声明）按题材触发的声明口径见 A0.6 商业内容铁律。
- 【全模式】脱敏零痕迹（A6 #14–16）；A 模式另须【改编位】全文清零
- 【全模式】媒体产出口径门（默认不产同源媒体·详见 A0.4 媒体投料产出口径）：投料为音频 / 视频 / 图片时，默认产出精华文本 / 技能包；不主动引导、不承诺、不做档二重生成（TTS / AI 视频 / AI 图）；仅当用户明确要求同源裁剪 / 选择且宿主环境具备 ffmpeg / opencv / Pillow 时，可调 `scripts/media_output.py` 按需可裁。
- 【全模式】交付呈现克制：zip 产出后，对话内仅输出「简短清单（文件名 + 一句话用途）+ zip 交付入口」，**不逐文件复述全文、不把 README/SKILL.md 等正文贴进对话、不交付任何质检报告**、**B/C 交付物（PPT/Word/PDF 等）绝不把生成脚本/代码贴进对话**——用户看不懂代码、无法审阅，贴代码既越界又制造困扰；用户开包即得产物，复述/贴码既浪费又冗余（落款/指纹等溯源信息由内部校验，不在对话展示；质量门禁内部跑通即代表达标，达标不靠"报告"说话）
