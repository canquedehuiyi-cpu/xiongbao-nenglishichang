# B/C 模式标准件规格（按需加载）

本文件仅在用户选定 B（萃取精华文档）或 C（定向萃取文档）模式时加载。A 模式产出技能包不进本文件，避免文档版式细节占用 A 模式上下文。

## 零、八标准总纲（B/C 您读产物硬门禁·含"为什么"）

B/C 产物是「您看的」——用户自己看、交付公司看、商用看。八条标准不是装饰，每条都对应「您看时的真实需求」，必须同时满足，不许为省事砍任一条：

1. **严谨**：做事有规矩、有边界、不越位。您看到严谨，才放心把材料交给我们。
2. **准确**：表达准确，不模糊、不臆造、不张冠李戴。您看到准确，才信得过内容。
3. **清晰**：看上去一目了然，不凌乱、不堆砌。您看到清晰，才愿意往下读。
4. **有温度**：考虑您的感受，让您看着舒服，不冷冰冰机械腔。您看到温度，才愿意用、愿意传。
5. **有框架**：内容有骨架、有条理。面对密密麻麻的大量信息，您容易视觉混乱、大脑空白；有框架才能接住。
6. **有层次**：大中小分级清楚。配合编号，您一眼知道「这块讲什么、那块讲什么」。
7. **有逻辑（编号硬规）**：凡并列 ≥2 点，必须编号——大标题 1/2/3、中标题 1.1/1.2、小标题 1.1.1…。**大于两点不编号 = 不交付**。编号让您一眼抓重点、直白高效，不绕。
8. **专业**：匹配场景、像专业人士做出来的。您一看就觉得「对味、靠谱」。

八标准交集 = 通用标准件底线：任何用户材料，产出都必须同时满足这八条，全格式（PPT/PDF/Word/MD/TXT/Excel）生效。

各格式标准版（提前规划，Agent 不临场发挥版式；合格线 = 结构完整 + 内容可用 + 版式规范 + 不溢出）：

- MD：调用包内 `scripts/build_md_standard.py`（纯标准库、零第三方依赖）生成，禁手搓。锁死：顶部一行溯源落款 + 层级标题（#/##/###）+ 每节「一句话核心」+ 要点列表 + 标准 Markdown 表格 + 文末落款；不堆大段原文、不套复杂版式；可进知识库。
- TXT：调包内 `scripts/build_txt_standard.py`（纯标准库、零第三方依赖）生成，禁手搓。锁死：UTF-8 无 BOM、顶部一行溯源落款、层级标题、每节「一句话核心」、要点化正文、文末来源说明；纯文本、可进知识库 / 轻量搬运。
- Word（DOCX）：调用包内 `scripts/build_docx_standard.py`（纯标准库、零第三方依赖）生成，禁手搓 docx XML。锁死项：A4 页面（11906×16838）+ 四边 1″ 页边距；固定样式（标题1 / 标题2 / 正文 / 要点列表 / 表格）；字体与配色来自设计令牌库（biz 默认 微软雅黑 + 琥珀金蓝，可选 7 配色族 / 4 字体族 / 3 字号规格，见「全格式设计令牌库前置」一节）；顶部一行溯源落款 + 文末落款段；表格表头深蓝底白字、正文深灰、细边框；**严禁逐段落 / 逐标题插分页符（防失控分页）**——仅在用户明确要求「每节起新页」时，才在相应一级标题前插分页，默认内容连续流排；图表用原生形状不贴图。各平台 Agent 照调生成器、只整理大纲数据，不写 docx 渲染代码（手搓必出失控产物：逐段 / 逐标题插分页、内容复制、字号乱）。
- PDF：调包内 `scripts/build_pdf_standard.py`（纯标准库、零第三方依赖、内嵌中文子集）生成，禁手搓 PDF 渲染或平台「自由生成」PDF。锁死：A4 + 20mm 页边距、单一 CJK 字体（biz 默认 SimHei，可选 hei/song/kai/deng 四族，绝不混排西文字体如 Helvetica）、层级标题用主色、每节一句话核心用强调色、表格表头深蓝底白字/数据行白底深灰/细边框、自动分页不漂移、页码、封面信息行 + 落款页；Identity-H 编码 + ToUnicode，跨设备不乱码。**严禁平台自由生成 PDF**——自由生成版式 / 字重不可控，且可能失控分页。
- Excel（XLSX）：分两种子形态，均必须调用包内对应生成器，禁手搓 xlsx XML：
  - **标准数据表**：调 `scripts/build_xlsx_standard.py`（纯标准库、零第三方依赖）。锁死：A4 逻辑，标题带（强调色填充）+ 表头主色填充白字、冻结表头行、自适应列宽、顶部溯源落款 + **末行免责声明**；多工作表（每张表一个主题）；适合各类报表 / 结构化数据导出。**默认语义＝全量搬运 + 规整（见下方「标准数据表默认语义」节）**。
    - **可见结构固定**（五行序，不重排）：`落款行 → 标题行 → 口径说明行 → 表头行 → 数据行… →（末）免责行`；**冻结表头行**（冻结覆盖落款＋标题＋口径＋表头，滚动时表头与口径不丢）。
    - **自动筛选范围 = 表实际列数**（`庚-13`）：`autoFilter` 必须从表头行覆盖到**末数据行的末一列**，不许漏列（漏列 = 用户按最后一列筛不到）。
    - **数字格式按列**（`庚-3 / 庚-6`）：金额 `¥#,##0.00` / 百分比 `0.00%` / 整数 `#,##0` / 一般数值 `#,##0.00` / 日期 `yyyy-mm-dd`；未给 `col_fmts` 时由 `_detect_col_fmts()` 按列头与首个样本自动识别（判据只看真数值，字符串绝不折算，防「00123」类编号丢前导零）。
    - **日期写真日期**（`庚-7`）：日期列写 **Excel 序列值 + `yyyy-mm-dd`**（显示与源一致，但可排序 / 可透视 / 可算间隔）；不像日期的串一律退回文本，**绝不硬转**。
    - **口径说明行不许空着**（`庚-11`）：交付时该行必须有「数据周期 / 口径」内容；材料里推得出就填，推不出**留空但不编造**（宁可留白，不可编数）。
  - **图表分析报告**：调 `scripts/build_xlsx_chart_standard.py`（纯标准库、零第三方依赖）。锁死：①页面结构固定 = 大标题行 + 副标题/数据周期行 + 核心 KPI 卡片区（首页，6 项以内）+ 小标题 + 左侧数据表 + 右侧图表 + 底部落款；②数据表与图表在同一工作表合理布局（数据居左、图表居右），绝不把图表挂到空 Sheet 上；③图表类型限 column / bar / pie / line，颜色循环使用设计令牌（#16335B / #E0A33E / #2E6E9E 等）；④工作表名、标题、表头必须中文，禁止英文表名/标题/标签；⑤数字格式按列固定——金额 `¥#,##0.00`、百分比 `0.00%`、整数 `#,##0`、一般数值 `#,##0.00`、日期 `yyyy-mm-dd`（日期写序列值），禁止浮点裸奔；⑥表头主色填充白字、冻结表头、自适应列宽、底部落款 + **末行免责声明**。
    - **标题带与标准表同一房式**（`庚-10`）：大标题行＝**强调色填充 + 白字**，两版 Excel 观感必须一致，禁一版有带一版无带。
    - **饼图逐扇区上色**（`庚-5`）：饼图按扇区数逐点（`dPt`）分配令牌色板，**强调色 / 辅助色必须真的用上**；折线 / 柱 / 条按令牌主色。
    - **图表引用按实际数据行**（`庚-8`）：`cat` / `val` 引用按**实际行数**生成区间（禁写死到 `$X100`），并写入 `strCache` / `numCache`（防第三方预览器显示空白图）。
    - **排行截断必须在标题层声明**（`庚-9`）：某页只列前 N 条时，小标题 / 副标题须写明「共 X 条 · 本页列前 N」，口径透明、不许悄悄截断。
    - **落款 / 免责缺一即不合格**（`庚-1 / 庚-2`）：xlsx 两版均须有可见溯源落款与末行免责声明，与其余格式**同一份文案**（单一事实源）。
  - 用户仅说「Excel / xlsx / 报表」时默认走**标准数据表**；用户明确要求「图表 / 可视化 / 分析图」时才走**图表分析报告**。

### Excel 两版共用硬约束（跨平台一致性 · 癸组）

两版 Excel（标准数据表 / 图表分析报告）**必须在同一套机器判据下产出**，任一版偏离即不合格。**同一份规范、同一份材料、换个平台就不一样 = 不合格** —— 差异不能出在"各自发挥"上：

| # | 硬约束 | 判据（可机检） |
|---|---|---|
| 癸-1 | **必须调用包内生成器**，禁止手写 xlsx 渲染（openpyxl / 自写 generate_excel.py 等） | 产物结构指纹命中包内生成器（自定义 `numFmtId` 164–168 + 固定 cellXfs 布局）；不命中即视作手搓 |
| 癸-2 | 设计令牌**显式写进 XML**，不走主题默认色 | 图表/表头 XML 出现显式 `<a:srgbClr>` = 令牌值 |
| 癸-3 | **每份产物落款 ≥1、免责 ≥1**（xlsx 两版各 1 处） | 扫全部产物：落款 / 免责逐份计数 > 0 |
| 癸-4 | **冻结行 = 表头所在行**（覆盖落款 / 标题 / KPI / 小标题 / 表头） | `ySplit` == 表头行号、`topLeftCell` == 表头下一行 |
| 癸-5 | **每列数字格式显式**（金额 / 整数 / 百分比 / 数值 / 日期） | `numFmts` 含 164–168，且列样式命中对应 numFmt |
| 癸-6 | 命名 = `<材料名主干>_<动作后缀>.<扩展名>`（见「输出文件命名硬规」；**不跟包标签走**） | 文件名与命名公式一致 |
| 癸-7 | 文档属性**只写品牌落款**，绝不写工具指纹（openpyxl / python-pptx / xlwt / pandas 等） | 扫 `docProps/core.xml` 无工具名 |
| 癸-8 | 选型规则**做进生成器**（`recommend_chart_type()`），不靠 Agent 凭记忆 | 未给类型时生成器自动定；给冲突类型以用户为准 |
| 癸-12 | **命名门禁**：产物文件名 / 目录名逐份比对命名公式 | 命名不符即 FAIL |

> 判据一句话：**规则写在文档里 ≠ 落在产物里** —— 文档是提醒，**生成器与门禁才是保证**。

### 标准数据表默认语义（唯一口径 · 与汇总的分界）

**标准数据表不做判断、只做规整**——默认把源表原样搬进来，要什么口径由用户说：

① **默认 = 全量搬运 + 规整**：源表**全部行、全部列**进入产出，只做表头统一 / 数字格式按列正确 / 冻结表头 / 清空行空列 / 工作表名中文化，**不减行、不换列、不预设维度**。
② **按方向汇总 = 用户明确给出方向后才执行**：用户说「按X汇总 / 只看X / 给我X的合计」即按用户方向做；**未给方向不得自行选维度**（规范里永远不得出现「默认按区域汇总」这类写法）。
③ **出口常开**：交付时附一句「如需按某维度汇总（按人 / 按地区 / 按月 / 按产品…），说一声即可」，一次重出不重复问。

**为什么默认是全量**（三条硬理由）：① 「按哪个维度汇总」**无法从材料推出**（取决于用户站在哪个岗位看数）→ 推不出来就绝不替他定；② 汇总＝做减法＋选视角，**视角选错，用户拿去汇报会被当场指出来源表里有的数据没了**；③ **全量是唯一可再加工的形态**——全量表用户自己会筛会透视，汇总表给错维度则原始信息被砍掉、**不可逆**。

**与图表报告的边界**：图表分析报告**必须选一个维度才画得出图**（形态必需输入，能从材料推出就推、推不出问一次），与标准表的「默认全量」不冲突——**两种形态，两套默认，不混用**。

## Excel 图表选型与边界（接料前置规划）

用户导入表格后常想「给我出个图表」。本节把「接料怎么问、图型怎么定、边界在哪」写死，让 Agent 有据可依、让用户提前知道能出什么 —— 图型由选型规则定，不临场自定，也不挑生成器不支持的类型。

### 一、接料前置三步（在整理 outline 之前做；不新增弹窗级）

1. **先读表结构**：调 `scripts/xlsx_ingest.py`（或 `scripts/intake.py` 的 xlsx 分支）读到工作表名 / 列头 / 行数 / 每列已识别格式——`_detect_col_fmts()` 会自动认金额 / 百分比 / 整数 / 一般数值，这一步不花用户任何操作。
2. **一句话回执并给出推荐图型**：把读到的结构用一句大白话回给用户，同时**依下方选型规则给一个推荐图型**（规则拿不准时兜底柱形图）。示例：「这份表 2 列 36 行，『月份』是时间列、『销售额』是金额列，我按**折线图**给您出走势；想换柱形 / 条形 / 饼图，说一句就行。」
3. **用户一句话可覆盖**：用户说「换饼图」「横过来」「就看占比」→ Agent 只改 `chart.type` 重出，**不加一级菜单、不弹窗**。

### 二、选型规则（数据形态 → 推荐图型）

| 数据形态（看列怎么组合） | 推荐图型 | 一句话判据 |
|---|---|---|
| 时间 / 序号列 + 数值列（按月、按天、按季推进） | 折线图 `line` | 看**走势**用折线 |
| 分类列 + 数值列，类别多或名称长（横向排得开） | 条形图 `bar` | 名称长 / 类别多 → 横过来 |
| 分类列 + 数值列，类别少（≤8，纵向比大小） | 柱形图 `column` | 比大小、最通用 |
| 分类列 + 数值列，看构成或份额（类别 ≤7） | 饼图 `pie` | 看**占比**用饼图 |
| 形态不明显 / 拿不准 | 柱形图 `column`（**默认兜底**） | 默认柱形，最不易出错 |

> 用户可见文本只写中文图名（折线图 / 条形图 / 柱形图 / 饼图），**不写 `line` / `bar` / `column` / `pie` 这些内部令牌**（同 A0.5 第 11 条英文零容忍）。

### 三、能力边界（如实告知，不含糊）

1. **支持四种**：柱形图 / 条形图 / 饼图 / 折线图——仅此四种（`build_xlsx_chart_standard.py` 对其它类型 `raise ValueError`，是硬边界）。
2. **不支持**：树状图、雷达图、散点图、气泡图、桑基图、关系网络图，以及同一张图里画两个以上数据系列的叠加图——当前一律出不了。
3. **用户要「树状」时怎么答（三步替代，按推荐顺序给，绝不硬编不支持的类型去撞报错）**：
   - ① **条形图 + 缩进层级标签**（首选替代）：层级名用缩进表示从属（「总部 /　华东 /　　上海」），条形长度表数值——一屏内最接近树状结构的表达，本包 `bar` 直接能出。
   - ② **改出 Word / PPT**：层级或结构关系改用缩进列表（Word）或对比页 / 流程页（PPT 页型库）表达，本包能出，且往往比树状图更清楚。
   - ③ **要真·树状图**：本包先出 **Excel 标准数据表**（`build_xlsx_standard.py`），用户在 Excel / BI 工具里自行插入树状图（那是工具自身能力）；或告知用户另投支持该图形的平台。
4. **绝不**为了满足「树状」而给生成器传一个它不支持的类型——那会直接报错中止。

**一句话判据**：用户说「出图表」→ 按选型规则**自动定图型给默认**、一句话可改；用户说「出树状 / 关系图」→ **如实讲边界 + 给三步替代**，既不装作能做、也不硬编。

## 全格式设计令牌库前置（字体 / 配色 / 字号规格 / 序号 / 模板模式）

**硬规**：各格式生成器不再各自 hardcode「单一字体 + 单一配色 + 单一规格」，而是把字体库 / 配色族 / 字号规格 / 序号系统 / 模板模式**统一前置为 `scripts/design_tokens.py` 单一事实源**，五个段落型生成器（MD / TXT / Word / PDF / PPT）与两个 Excel 生成器均已参数化接入；Agent 按场景任选模式或自由组合，产出有层次、有逻辑、有差异。**不前置、不可选 = 不交付**。

**前置令牌库组成（详情见 `scripts/design_tokens.py`）**：
- **字体库（4 族·跨平台）**：`hei` 黑体/微软雅黑（现代商务·默认）、`song` 宋体（报告/书籍/学术感）、`kai` 楷体（金句/引文/温暖人文感）、`deng` 等线（轻商务简净）。PDF 给候选字体文件名列表按系统探测，Office 给字体名由宿主按本机回退。
- **配色族（7 族·均非 Office 默认蓝·贯穿全篇主导 2–3 色）**：`amber` 琥珀金蓝（默认·商用正式）、`red` 红黑（营销/硬核/行动号召）、`sky` 天蓝科技（数据/互联网）、`teal` 欧美 teal（咨询/可持续）、`warm` 暖橙（财富/商业温暖交付感）、`ink` 墨绿（报告/研究严肃）、`violet` 紫灰（创意/文化高级）。
- **字号规格（3 套·层级自动分层）**：`standard` 标准商务（默认）、`compact` 极简紧凑（留白多·长文/知识卡片）、`report` 学术报告（正文略大·行距宽松）。每套含 封面主标题 / 一级 / 二级 / 三级 / 正文 / 核心句 / 注释 / 页码 不同字号——大标题最大、逐级递减、正文清晰可读，视觉才有层次。
- **序号系统（4 套·标题层级编号）**：`arabic` 1. / 1.1. / 1.1.1.、`cn` 一、/（一）/ 1）、`circle` ①②③、`none` 无前缀极简。生成器按所选系统在章节标题前自动加前缀（并先剥离原标题里旧前缀，确保重跑幂等）；不指定则保留原标题（向后兼容·不回归）。
- **模板模式（8 种预设·一键连贯）**：`biz`(amber+hei+standard+arabic) / `lean`(ink+hei+compact+cn) / `report`(ink+song+report+arabic) / `warm`(warm+kai+standard+circle) / `red`(red+hei+standard+arabic) / `sky`(sky+hei+standard+arabic) / `teal`(teal+hei+standard+arabic) / `violet`(violet+deng+standard+cn)。选一个模式即拿到连贯的「配色+字体+字号规格+序号」整套（高级/内部分发用）。
- **版本族（7 种·PPT 菜单可点选的模板版本·全中性命名·不挂任何厂商标识·中文名统一 4 字）**：`standard` 标准商务(amber+hei+standard+arabic+平衡版式) / `minimal` 简约商务(sky+hei+compact+cn+通透版式) / `classic` 经典商务(ink+song+report+arabic+端正版式) / `premium` 高级商务(violet+deng+standard+cn+雅致版式) / `summary` 总结汇报(warm+kai+report+circle+平衡版式) / `course` 课件讲义(teal+hei+standard+arabic+通透版式) / `data` 数据简报(red+hei+compact+arabic+平衡版式)。每个版本 = 连贯的「配色+字体+字号规格+序号+版式风格」整套，用户生成时直接点版本即得一致观感；Agent 也可在版本之上自由组合 palette / font / scale / number / layout 做微调。
- **文体层（4 种·MD / Word / TXT 承载·只改文风与分段、不改文件格式）**：`plain` 通用正文（默认·常规书面体）／`speech` 讲稿文体（**能照着上台讲**：完整句、口语连接词、每段一个落点、关键处标停顿与重读；适合演讲稿 / 发言稿 / 培训讲义）／`oral` 口播文体（**能照着念录**：短句、口语、无书面嵌套、每 2–3 句一个气口；适合口播稿 / 直播稿 / 短视频底稿）／`card` 卡片文体（**一卡一要点**：每卡一句结论 + ≤3 条支撑，卡间独立可单读；适合速览 / 复习 / 转发）。**文体与版本正交互补：版本管「好不好看」，文体管「拿来怎么用」**——同一格式 × 任一文体的组合都成立；用户不选即 `plain`，不影响原有产出。用户侧编码 1–4 见 `references/mode-bc-guide.md` Step 4。
  - **落料容器（写死，写错容器不得靠排版补救）**：canonical outline 每节有两个正文容器——`points`（短要点，渲染为项目符号列表）与 `paragraphs`（成段的话，渲染为不加符号的独立段落），两者可同节并存、顺序固定为 核心句 → `paragraphs` → `points`。**讲稿体 / 口播体是「成段的话」，正文必须写进 `paragraphs`**（「每段一个落点」这个要求本身就只在段落容器里成立）；**卡片体写进 `points`**。把 `paragraphs` 折进 `points`，产出的是一串项目符号，念出来是一串短横——排版层救不回来。三个承载格式都读 `paragraphs`：MD / TXT / PDF 直接读，Word 经适配层映射为 `paras`。

**调用方式（Agent 整理大纲后传参，禁手搓）**：
- MD / TXT：`build_md(outline, out, mode=, palette=, font=, scale=, number=)` / `build_txt(outline, out, mode=, palette=, font=, scale=, number=)`
- Word：`render_outline(outline, out, mode=, palette=, font=, scale=, number=)`
- PDF：`build_pdf(outline, out, mode=, palette=, font=, scale=, number=)`
- PPT：`render_outline(o, out, mode=, palette=, font=, scale=)`（PPT 幻灯用 `chapters` 显式 `num` 编排，配色/字体/规格按模式套）
- Excel：`build_xlsx(outline, out, mode=, palette=, font=, scale=)` / `build_xlsx_chart(outline, out, mode=, palette=, font=, scale=)`

**各格式可选模式一览（确认格式后一并确认模式/序号）**：
- MD / TXT / Word / PDF：八模式全可选 + 自由组合 配色/字体/字号规格/序号 四维度。
- PPT：八模式全可选（页型库 + 导航 + 令牌三层不变，仅配色/字体/规格随模式切换）；序号由 `chapters` 的 `num` 显式编排。
- Excel（数据表/图表）：八模式全可选（配色用于标题带/表头/图表色循环，字体用于中英文回退）。

⚠️ **稳定性铁律**：默认 `biz` 模式（amber+hei+standard+arabic）与既有默认值完全一致——选 `biz` 即既有行为，不回归稳定交付；选其他模式才产生差异化成品。任何优化不得降低交付稳定性。

## 交付目录卫生（B/C 全格式通用）

中间件若与成品同落 `runs/<任务>/`，用户打开交付目录会看到 `source.txt`、`chunks_plan.json`、`outline.json`、`processed_ids.txt`、临时渲染脚本、0 字节的 `ingest_err.txt`，会误以为「配置错误」——产物本身没问题，只是目录乱了。

**硬规（两层落盘）**：
- **成品在最外层**：用户要拿走的文件落 `runs/<任务>/` 根，用户打开目录第一眼看到的就是成品 —— 文档类（`.docx` / `.pptx` / `.pdf` / `.xlsx` / `.md` / `.txt`）与**媒体类**（裁剪出的音频 / 视频 / 图片，如 `.mp3` / `.mp4` / `.png`）一律落交付根最外层。
- **中间件归隐藏子目录**：`source.txt`（原始材料）、`chunks_plan.json`（分块清单）、`processed_ids.txt`（状态文件）、`outline.json`（canonical 大纲）、`intake/` `media/`（接料与媒体中间产物）、临时渲染脚本、日志——一律落 `runs/<任务>/.work/`，不外露。
- **不留垃圾**：0 字节的错误输出文件（如 `ingest_err.txt`）跑完删除；宿主编辑器产生的 `~$xxx.docx` 是编辑器锁文件、非技能产物，提示用户关掉文件即可，**不主动删用户正在编辑的文件**。
- **媒体成品与媒体中间件分开落**：档一裁剪 / 选出的**片段与选图是成品**，落 `runs/<任务>/` 根；**只有**分段中转件（`xxx_seg001.wav` 之类）、转写稿中间件、`media_plan.json` / `media_processed.json` 归 `runs/<任务>/.work/media/`。判据一句话：**交付根里看到 `xxx_seg001.wav`，就是没按本节做**（分段件是过程、不是成品）。

**一句话判据**：用户打开 `runs/<任务>/`，看到的应该只有成品文件（和 `.work/` 这个隐藏夹）；**若看到中间件，就是没按本节做**。

## 免责声明单一标准（全格式通用 · 紧邻落款）

**落款 ≠ 免责，两句两处，不得搅成一句**：落款管溯源（谁做的），免责管合规（您能拿它做什么）。此前 Word 曾把落款当免责用（实际没有免责）、两种 Excel 形态则完全没有——本节的唯一目的，就是**把它立成一份标准、六格式落齐**。

**唯一句式 = 一句固定主句 + 一个题材槽**：

```
固定主句（全格式、全题材，一字不改）：
    本产物为对源材料的个人蒸馏整理，仅供学习参考

题材槽（按材料题材自动挂一句，比主句多这一句）：
    · 投资 / 理财 / 股票 / 基金 / 房产增值类  →  ，不构成任何投资建议
    · 商业 / 管理 / 思维 / 学习方法类          →  ，不代表对任何商业行为的建议
    · 其他题材                                →   只留主句，不加槽
```

**为什么留题材槽（不能一刀切）**：投资类**必须**留「不构成任何投资建议」（合规红线，省不得）；商业类**不能套**投资声明——一本管理书写着「不构成投资建议」，用户一眼就看出是模板没改（这正是「格式与真实需求匹配」在文案层的同一把尺）。

**六格式落点（一处不少，任一缺即 FAIL）**：

| 格式 | 落点 |
|---|---|
| MD | 文末最后一行 |
| TXT | 文末最后一行 |
| Word | 文末落款段**下方紧邻**（两句并存、上下相邻，不合并） |
| PDF | 第 2 页页脚注位置 |
| PPT | 末页（结尾页）落款下方 |
| Excel 标准表 | **末行**（最后一张表下方） |
| Excel 图表报告 | 底部落款下方 |

**纪律**：① 六格式生成器统一读同一处文案常量，不各写一版（单一事实源）；② 免责声明**不能替代内容重构**（A 模式原铁律保留不动）。

## 交付回执硬规（B/C 全格式通用 · 紧随免责）

产物末尾除「落款 + 免责」外，**再挂一行「交付回执」**——这是**用户→我方**的唯一反馈口（此前全包只有"我方→用户"的回执）。

- **落点**：紧随免责声明之后（**落款 → 免责 → 回执**，三句三处、互不合并）。六格式落点同免责节：MD / TXT 文末最后一行、Word 文末落款段下方、PDF 落款页脚注处、PPT 末页、Excel 标准表末行、Excel 图表报告底部。
- **生成**：一律由 `scripts/constants.py` 的 `receipt_line()` 单一事实源产出，七个生成器统一调用，**不各写一版**。
- **带做法标签**：Agent 传 `outline["receipt_tags"]`（材料类型 / 模式 / 格式 / 深度），回执即带「做法标签」；不传则只出反馈口与零内容边界，**不留占位符、不留空壳**。
- **★ 零内容边界（IP 铁律）**：回执里**只有做法标签、零用户内容**——不承诺、不索取、不夹带。这句边界本身就写在回执里（"这一行不含您的任何内容"），**用户看得见才敢贴**。
- **不做承诺**：回执只陈述本产物事实（这是一扇反馈口），**不写任何我方兑现不了的承诺**（平台在数据通路上，我方控不住的事一个字不写）。

## 来源总览硬规（B/C 全格式通用 · 紧贴落款）

产物页脚除「落款 + 免责 + 回执」外，**多份材料时再挂一行「来源总览」**——让用户一眼看清这份产物由哪些材料来的、各走了哪条路读出来的。

- **口径**：**单份只报份数（不列条目）、多份列全每一份、无来源不出这行**（用户直接给正文时不出现，避免空壳）。
- **落点**：**紧贴溯源落款**（**落款 → 来源总览 → 免责 → 回执**，四处四句、互不合并）。六格式落点同落款节：MD / TXT 文末、Word 文末落款段下、PDF 落款页脚注处、PPT 末页、Excel 标准表末段首行、Excel 图表报告底部。
- **生成**：一律由 `scripts/constants.py` 的 `sources_overview()` 单一事实源产出，七个生成器统一调用，**不各写一版**。
- **数据来源**：接料台账 `runs/<任务>/.work/intake/sources.json`（逐份来源 + 读取方式），**不许凭印象编**。
- **★ 正文保持干净**：来源信息**集中在页脚一处**，**正文不逐条插页码 / 出处**（用户要的是能读的内容，不是标注满页的稿子）。
- **★ 聚合不丢 per-item**：多份合并时逐份属性原样带着走，绝不从合并后的全文重新推导 —— 否则「某一份有没有目录 / 页数 / 读取方式」这类属性会随输入顺序翻转。

## 结果声明（交付说明必出 · 不是产物文件）

交付说明（对话内）里紧跟一句**结果声明**——用大白话说清"这一趟您拿到了什么"（如"您现在有了一份新人照着就能上手的维修判断流程"），**不写成"这是 XX 文件"**。

- **口径**：**数量 + 单位 + 后果**，并说清**每一份材料是怎么读出来的**（"这份 PPT 是文字层读的，图中的字没读到""这份 PDF 是扫描页、没文本层"）——**哪里有缺口或降级必须主动讲**，不许只报好消息。逐份来源与读取方式取自接料台账 `sources.json`，**不许凭印象说**。
- 判据：**用户读完这一句，知不知道"我手上多了什么能力"？** 不知道 → 没写到位。
- 与回执分工：**结果声明管"用户知道拿到了什么"（我方→用户）；交付回执管"我们能收到一句真话"（用户→我方）**。一出一进，两处不混。

## 输出文件命名硬规（全格式通用）

**公式**：`<材料名主干>_<动作后缀>.<扩展名>`

① **材料名主干**：有源文件 → 原文件名去扩展名，再去掉平台加的前后缀、`(1)(2)` 重名标记、临时数字；口述 / 链接 / 多源 → 取用户那句话的主题词（没有就用材料首标题）；多源合成 → 取用户给的主题词。
② **动作后缀（跟「要什么」走，不跟「格式」走）**：全量搬运规整（表格默认）`_数据表`；按方向汇总（表格·用户要分析）`_汇总分析`；图表分析报告 `_图表分析`；通用精华文档（Word / PDF / MD / TXT）`_精华萃取`；定向萃取文档 `_定向萃取`；技能包 → 直接用 slug（既有规则）。
③ **同批多格式同名干**：`<名干>.docx` / `<名干>.pptx` / `<名干>.pdf` —— 一眼看出是同一批。

**明令禁止**：包标签名（把内部形态名当文件名，如「Excel 标准数据表」）· 平台自拟名 · 无关联通用名（`输出.xlsx` / `demo_标准版.xlsx`）· 含用户身份信息（绝对路径 / 用户名，与交付脱敏条一致）。

**怎么验**：文件名须含源文件去扩展名的连续子串；后缀须属上表枚举；连接符一律半角下划线 `_`（不混用 `-` / 空格）；同批多格式名干必须完全相同。

## PPT 标准版规格（B 模式 PPT 产出硬标准）

- **商用交付原则（硬标准）**：PPT 产出按商用交付物标准生产——结构完整、版式规范、可直接用于汇报 / 培训 / 商用，用户拿到即能用、能交付，无需从零重做。版式不绑定任何特定来源。
- **底层架构 = 页型库 + 导航系统 + 设计令牌**（合格 PPT 的根本，非配色好看）。三层须同时锁死，缺一不可。
- **页型库（10 标准页型，产出时按内容选页型，不临场发明版式）**：①封面页（全幅色块 / 图 + 主标题 + 副标题 + 落款，无要点）②目录页（编号模块列表 ≤6，每模块一行）③章节分隔页（大编号 01/02 + 章名 + 一句导语，全幅主色块；带全局路线图 running header）④要点页（标题 + 3–5 要点，每点 ≤2 行 ≤25 字，色块 / 图标区隔）⑤图文页（左文 60% / 右图 40% 或反之，图来自源材料 / OCR / 用户给，不空白占位）⑥数据页（KPI 卡 ×3–4 或大数字 + 一句解读，禁文字墙）⑦对比页（2–3 列并排，列头色块区分）⑧流程页（步骤横向 1→2→3→4 箭头连接）⑨金句页（大字居中 + 出处，主色块底）⑩结尾页（总结 / 致谢 + 落款）。每内容页只讲一个子观点（一页一意），不把多观点塞一页。
- **导航系统（专业 PPT 标志，缺此层则像流水稿）**：①全局路线图——章节分隔页顶部 / 侧边展示「1 章名 · 2 章名 · 3 章名 …」当前章高亮；②每内容页页眉回显当前章名；③每页页脚固定「页码 + 溯源落款」。让用户随时知道「我在哪、全篇怎么走」。
- **设计令牌（必须显式建立「主导应用配色」，防回退 Office 默认蓝）**：专业感来自「贯穿全篇、反复出现的主导 2–3 色 + 黑字（#000000）+ 白 / 灰底」的应用配色；没建立主导配色、只零星用默认强调色的产物会显得业余。故引擎须显式指定并贯穿全篇：内置默认「琥珀金蓝」主 #16335B / 强调 #E0A33E / 辅助 #2E6E9E / 浅底 #F4F6F9 / 正文 #1F2733 / 注释 #6B7480 / 边框 #D8DEE6；另备已验证商用配色族（均非 Office 默认蓝，按需选用）：红黑（主 C00000 / 黑 000000）、天蓝科技蓝（主 04AEDA / 辅 00B0F0）、欧美 teal 蓝（主 45C1A4 / 辅 0E7FB7）；用户给参考模板则按 `extract_template_tokens.py` 抽其主导色对齐。字体 中文微软雅黑（思源黑体 / Noto Sans SC 备选）、英文数字 Arial；字号 封面主标题 36–40pt 粗、章节大编号 54–60pt、要点页标题 24pt、正文 14–16pt、注释 11pt；网格 16:9、安全边距 0.5″、留白 ≥20% 页面面积、三级字号、对齐到网格。配色 ≤3 主色，不溢出不重叠。
- **结构骨架（必含，顺序固定）**：封面页 → 导读 / 课程地图页（全局结构一览，呼应路线图）→ 章节分隔页（每章一页）→ 要点页 / 图文页 / 数据页 / 对比页 / 流程页（按内容选页型）→ 清单页（可落地行动 / 复习清单）→ 结尾页。框架 / 模型 / 流程 / 对比一律图形化呈现（页型库 ⑥⑦⑧），非文字墙。图表组件化：数据 / 对比 / 流程页优先复用专业图表组件（KPI 卡 / 矩阵 / 流程箭头 / 关系图，参考图表库素材），不堆文字墙。
- **内容密度**：单页正文 ≤120 字；要点每条 ≤25 字；金句放大突出；定义 / 要点保留（完整原生不抽骨）；禁止大段原文直接搬运、禁止一页塞满。
- **可执行生成器（禁手搓·硬规·内容无关）**：B 模式 PPT 一律调用包内 `scripts/build_ppt_standard.py`（纯标准库、零第三方依赖）生成。入口函数 `render_outline(outline, out_path)` 由「结构化大纲」驱动——`outline` 只列章节与每节的小标题 + 要点，**与具体题材无关**：任何用户材料只要整理成大纲，引擎即产出标准版 PPT，不绑定某一份文档。生成器内置通用版式原语（标题带 + 强调横 / 编号徽章 / 卡片模块 / 图标圈 / 分隔大编号 / 对比双栏 / 步骤横排 / 金句块），按 section.type 自动选版式，并已锁死页型库 / 导航 / 令牌 / 层级 / 行距 / 一页一意。**严禁 Agent 自己手搓 pptx 渲染代码**——手搓极易出格式错误（导航重叠、章节编号字号不一、金句比正文小、一页一意破、卡片正文被逐字符拆分）。各平台 Agent 照调生成器、只整理大纲数据，不写渲染代码。
- **易错点锁死（必须规避）**：①导航不重叠——内容页只放一行全局路线图（当前章高亮），**不重复**再放 running header，否则两行字叠在一起；②章节大编号统一——分隔页固定 96pt（水印式），目录页固定 22pt 编号徽章（二者是不同页型，不混用）；③金句 / 核心洞察字号必须 > 正文（金句 22pt / 卡片标题 17pt / 正文 13pt），金句要放大突出，不能比正文小；④行距固定 1.2、留白 ≥20%；⑤一页一意——章节分隔页独立成页，不与内容同页；⑥导航字 ≥11pt，卡片正文 ≥13pt，避免看不清；⑦卡片要点必须是「字符串列表」`[...]`，**绝不可传裸字符串**——传裸字符串会被按字符迭代、每个字前误加「· 」、PPT 中每个字符前被误加前缀、呈字符级散列。
- **参考模板机制（可执行）**：用户给「参考模板 / 风格样本」（自有 PPT）→ 运行 `scripts/extract_template_tokens.py <用户模板.pptx>` 提取 {主色 / 辅色 / 字体 / 页型清单 / 版式提示} JSON，引擎对齐其版式 / 配色 / 字体产出标准版；用户未给则走上方内置设计令牌与页型库。模板仅作版式参考，不把模板内文当源材料（提取脚本只取设计特征、不取文字内容）。
- **分工边界**：引擎交付「标准底稿」（页型正确、导航齐全、令牌达标、内容可用），用户在 Agent 平台用 PPT 插件做视觉精修——合理分工，但底稿必须达标，不能交付「不达标底稿」让用户从零重做。生成方式：优先用运行环境 PPT 生成能力 / 平台 PPT 插件，按本令牌 + 页型库产出；环境若有 python-pptx 可直接生成标准 .pptx（脚本不依赖 python-pptx，仅指南）。
- **内部四查（不交付报告）**：产出后按 结构完整（页型库齐 + 导航全）/ 内容可用（一页一意 + 密度达标）/ 版式规范（令牌达标 + 不溢出）/ 不溢出 四查，任一不达标回退重做；四查为内部生产标准，不在对话交付质检报告（见「质检报告处置」）。
- **B 模式长视频（>10 分钟）档位确认**：开工前先向用户确认档位并给 ETA——「快速大纲版」：按章节卡 + 关键画面 + 骨架字幕，约 10–15 分钟出 PPT；「逐句保真版」：1fps OCR + 全文校准，时长随视频长度增长（约 1.5–2 倍视频时长）；用户不选则默认建议「快速大纲版」。长任务（>10 分钟）每 10 分钟输出一次进度摘要（已完成 XX%、当前处理阶段、预计剩余 XX 分钟），不让用户干等；转写稿收敛后可先展示"转写稿 + 课程骨架"供用户确认，再进 PPT 制作。

## B/C 模式内容边界（按作用对象分级，不替用户删内容）

- 判据：B/C 产出是「您读的文档」（PPT / Word / PDF / MD），作用对象是用户本人看 / 学 / 参考，本质是源材料的浓缩书摘。本工具只做蒸馏，不替用户决策、不替用户删源材料内容——**完整原生**，源材料里有什么就凝什么，否则用户看不懂、等于没做；浓缩篇幅可以，抽掉定义 / 要点 / 实质内容不行（即「省篇幅不抽骨」）。
- 保真蒸馏：投资经典里的具体观点、指标、操作思路，一律忠实保留（学习、研究、自用参考都是正当用途）。
- 三条硬约束（守的是「不越位」，不是「替他删」）：
  ① 不注水：只凝源材料本身讲的方法，不跨书泛化、不补源材料没有的「通用投资指标 / 买卖信号」（如源材料没讲 ROE / 市盈率，不可自行补入）。
  ② 标来源观点：投资类内容明确标注「以下为源材料 / 本书观点」，不摆出「本引擎的方法」姿态，不替源材料背书。
  ③ 留免责声明：文末固定挂「免责声明单一标准」节的主句 + 题材槽（投资类即「本产物为对源材料的个人蒸馏整理，仅供学习参考，不构成任何投资建议」）——既保护产品合规边界也保护用户，且不可被内容重构替代。
- 用户对外发布责任：若用户打算将 B/C 产物对外发布 / 商用，属用户自身内容合规责任；引擎在产物内保留来源标注与免责声明即尽到提醒义务，不越位替用户删内容。
- 与 A 模式区别：A 模式产出是 Agent 可调用的技能包，会被机器自动执行，故必须只留「方法 / 框架 / 检查表」，不得含可被 Agent 直接执行的买卖动作（见 A7 / A9 的 A 模式口径）；B/C 模式产出作用于人，故保真优先。
