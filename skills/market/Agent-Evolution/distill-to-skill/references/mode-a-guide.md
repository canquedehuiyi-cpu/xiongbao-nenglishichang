# 模式 A 引导（用户选 A 后输出）

> 本稿在用户显式回复 A 之后由 Agent 输出，由 SKILL.md A0.5 指针引用。
> 核心：A 直接产出「技能包」，不是给您读的文档，因此**没有 PPT / Word 那套格式与模板**，跳过格式 / 模板确认环节。
> 口径对账：A 的载体**天然是 MD 结构**（SKILL.md / references 本身就是 markdown）——所以 A **没有「格式」这个选择项，载体天然就是 MD、且是唯一形态**（不存在"默认出一个格式"这回事）；**B / C 才是有格式可挑、默认 Word**。

---

您选了 **A｜封装可安装技能（Skill）**。

A 模式产出的是「技能包」——一种能导入 Agent 平台、被反复调用执行的文件，不是给您逐页读的文档，所以**不用选交付格式、也不用选视觉风格**，这步直接跳过（因此本模式下没有需要点选的弹窗）。

**先做一件事：判定这套内容够不够格做成技能**（四要件，缺一不成立）：

1. **有稳定输入** —— 说得清「每次来料是什么形态」（一类材料 / 一种场景），不是只有一个孤例；
2. **有可复现的做法** —— 内容是**可重复执行的做法 / 步骤 / 判据 / 规则**，不是一次性结论；
3. **有确定产出** —— 产出形态与结构固定（出什么、长什么样说得清）；
4. **换一批同类材料还能跑** —— 这是「技能」与「一次性交付」的**实质分界**。

**判据一句话**：**这份内容「换一批材料还能不能用」？** 能 → 具备技能条件，往下走；**不能（只服务这一次 —— 比如就是一篇报告、一次结论）→ 我们如实告诉您「这套不适合做成技能」，并给替代**（它本身就是完整交付，直接给您文档就行）—— **不硬包**。

> 依据：做成技能要付**封装 / 维护 / 安装 / 调试 / 学习五种成本**，而它只能用一次就是净浪费 —— **所以不是什么东西都值得做成技能，我们不会为了出包而出包**。

---

**接下来两步**：

1. 跟我说说这个技能包要干什么——给谁用、解决什么重复活、希望每次产出什么样。**一句话场景也行**，不确定我帮您理。
2. 我据此启动蒸馏，提炼「核心逻辑 + 执行框架 + 核查清单」，产出可直接上传导入的技能包。

**您最终拿到**：一个能装进 Agent 平台、反复调用、产出稳定的技能包。包里自带一份「怎么用」说明（上传 → 装好 → 唤起 三步）和一张使用日志空白表——用着有哪里不对，把当时的话照原样记一行就行。注意——机器只留方法、不替您做决策；强监管题材（投资 / 医疗 / 法律等）只萃方法、不输出结论与建议。

您说完需求，我先用一句话把「我理解您要做什么」讲给您听（要干什么 / 解决什么重复活 / 希望每次产出什么样），**讲完就开工、不用您再点头**；要是理解偏了，您当场说一声，我马上改口径重做。

---

**交付之后（回钩 · 三种模式通用）**：产物出来后，结尾固定留一句回钩——

> 「无论您做的是 A、B 还是 C，随时想更新、迭代、优化、完善，**直接回到这里提要求就行**——我帮您接着处理，您只管说要改什么，不用重新传材料、不用重开会话。」

钩子只陈述「可随时继续在此迭代」这一事实，**不推销、不夸大**。A 模式交付时另加一句**结果声明**：用大白话说清"这一趟您拿到了什么"（如"您现在有了一个装进平台就能反复调用的技能"），不写成"这是 XX 文件"；并点明包内两份附件各自的用处（「怎么用」说明 ＋ 使用日志空白表），只陈述它们是什么，不推销、不夸大。
