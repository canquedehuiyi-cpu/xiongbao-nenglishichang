# 中文结构示例

以下示例用于展示输出结构、范围判断和证据要求。生成实际任务时必须替换为用户的真实目标，不得复制本示例的 CSV 场景。

# 任务

- 类型：Bugfix
- 目标：修复 Windows 下导出 CSV 后中文在 Excel 中显示乱码的问题，同时保持其他平台和现有导出字段不变。
- 假设：目标仓库已经存在 CSV 导出入口；具体文件、编码库和测试命令由第一阶段探测确认。

# 范围与边界

必须完成：复现乱码；定位编码或文件头根因；实施最小修复；补充 Windows Excel 可验证的回归覆盖。

不做：不重写整个导出模块；不新增导出格式；不调整无关界面和字段。

约束：保持现有字段、顺序和非 Windows 行为；先识别真实构建与测试命令；新增依赖必须说明必要性；任何外部发布或生产写入须另行授权。

# 阶段

1. 复现与基线：只读检查导出链路、现有测试和真实命令，用最小中文样例复现并记录原始字节与 Excel 表现。
2. 最小修复：只修改根因涉及的文件，保持公开接口和字段契约；完成后立即运行聚焦验证。
3. 回归与证据：运行项目已有测试、构建和导出冒烟；验证中文、英文、空值和现有平台路径，失败则定位、修复并重跑。

每阶段遵循：计划 → 实现 → 验证 → 修复 → 证据 → 决策。

# 验证与证据报告

- 记录修改文件、实际执行命令、退出状态和关键结果。
- 保存修复前后的同一确定性样例及字节级差异。
- 提供 Windows Excel 中的可见验证，不能只以单元测试代替。
- 区分已完成项、未完成项、风险和仍需人工确认的事项。

# 验收

- [ ] Windows Excel 正确显示中文，字段和顺序保持不变
- [ ] 英文、空值及原有导出路径无回归
- [ ] 适用测试和真实运行验证均通过
- [ ] 没有无关修改、虚构命令或证据
- [ ] 最终报告包含完整证据和剩余风险
