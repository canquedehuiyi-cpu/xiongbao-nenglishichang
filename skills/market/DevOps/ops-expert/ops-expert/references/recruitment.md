# 运维招聘与面试（从 SKILL.md §四 展开）

本文件提供可直接复用的运维招聘与面试资产：分级能力模型、JD 模板、分层面试题库、结构化评分表与面试 SOP。
目标：让"招到对的运维"可标准化、可复现，减少凭感觉面试。

## 1. 分级能力模型

| 级别 | 定位 | 核心要求 |  autonomy |
|------|------|----------|-----------|
| **初级（1-3 年）** | 执行型 | 能在指导下完成部署、监控、排障；熟悉 Linux 常用命令与基础网络 | 需带教 |
| **中级（3-5 年）** | 独当一面 | 独立负责模块运维；能定位常见故障根因；会写自动化脚本；懂一门配置/编排 | 独立 |
| **高级（5+ 年）** | 架构与体系 | 设计运维体系（监控/发布/容灾）；主导复杂故障；推动 SRE 文化；带人 | 主导 |
| **SRE / 专家** | 稳定性与效能 | SLO/错误预算、容量规划、混沌/压测、可观测性体系、降本增效 | 体系 owner |

## 2. JD 模板（按级别套用）

### 2.1 高级 Linux 运维工程师（示例）

**岗位职责**
- 负责核心业务系统的日常运维、发布与稳定性保障，达成可用性 SLO。
- 建设并完善监控告警、日志采集、自动化运维体系。
- 主导疑难故障的根因分析与复盘，输出改进项并跟踪闭环。
- 制定运维规范、Runbook 与应急预案，推动 On-Call 机制落地。
- 参与容量规划与性能优化，保障大促/峰值稳定。

**任职要求**
- 本科及以上，5 年以上 Linux 生产运维经验；精通 Shell/Python 至少一种。
- 深入掌握 Linux 内核与调优（CPU/内存/IO/网络）、网络协议（TCP/IP、HTTP、DNS）。
- 熟练至少一种编排/配置体系（Kubernetes / Ansible / Terraform 之一）。
- 熟练至少一种中间件与数据库运维（MySQL/Redis/Kafka/Nginx 等）。
- 有 Prometheus/Grafana 监控体系或 CI/CD 落地经验者优先。
- 具备故障复盘、变更管理、跨团队协同能力。

**加分项**：CNCF 生态认证、SRE 实践、大规模集群（千节点级）、Go/可观测性开发能力。

> 初级/中级/高级/SRE 的差异点：初级强调"照做+理解"，中级强调"独立+脚本化"，高级强调"体系+复盘"，SRE 强调"稳定性量化+效能"。

## 3. 分层面试题库

每题标注 **考察点** 与 **参考答案要点**。建议按比例组合：基础 30% / 网络 20% / 脚本 15% / 中间件 DB 15% / 故障场景 20%。

### 3.1 Linux 基础
- Q：一台机器 `df -h` 显示磁盘满了，但 `du` 统计不到占用，可能原因与排查？
  - 考察：已删除但仍被进程占用的文件（`lsof | grep deleted`）、挂载点覆盖、inode 耗尽。
  - 要点：查 `lsof +L1`；重启持有句柄的进程或清空；`df -i` 看 inode。
- Q：`top` 里 CPU 的 us/sy/wa 分别代表什么？wa 高怎么查？
  - 考察：CPU 时间拆解。wa=IO 等待；wa 高查磁盘（`iostat -x`）、慢查询、swap 颠簸。
- Q：如何查看与修改一个进程可打开的文件描述符上限？
  - 考察：`/proc/<pid>/limits`、`ulimit -n`、systemd `LimitNOFILE`、`/etc/security/limits.conf`。

### 3.2 网络
- Q：TCP 三次握手与 TIME_WAIT 的作用？高并发短连接下 TIME_WAIT 过多怎么治？
  - 考察：连接状态机；`net.ipv4.tcp_tw_reuse=1`、`tcp_max_tw_buckets`、连接复用/长连接。
- Q：服务器 ping 得通但端口 telnet 不通，如何分层排查？
  - 考察：iptables/firewalld、安全组、服务是否监听 0.0.0.0、selinux、路由/源地址。
- Q：DNS 解析慢或偶尔失败，如何定位？
  - 考察：`dig +trace`、`nscd`/systemd-resolved 缓存、`/etc/resolv.conf`、DNS 服务器健康。

### 3.3 脚本与自动化
- Q：写一个脚本：监控某端口，连续 3 次不通则重启服务并记录。
  - 考察点：循环、退出码、幂等、日志。要点：用 `nc`/`curl` 探活；重启前判断进程状态；避免频繁重启（退避）。
- Q：如何用 Ansible/Shell 批量在 100 台机器改一个 sysctl 并校验？
  - 考察：幂等、批量、校验、失败处理。要点：先备份、并行度、结果收集、差异比对。

### 3.4 数据库与中间件
- Q：MySQL 主从延迟变大，常见原因与处理？
  - 考察：大事务、从库性能/参数、网络、单线程回放（并行复制）、磁盘 IO。
- Q：Redis 内存暴涨的可能原因？
  - 考察：大 key、热 key、过期策略（lazy/主动）、内存碎片、未设 maxmemory 与淘汰策略。

### 3.5 故障场景（必出一道）
- 场景：线上 API P99 延迟从 80ms 突增到 2s，CPU 与内存正常，QPS 未变。
  - 期望思路：先止血（扩容/限流/回滚最近变更）→ 分层取证：网络（重传/丢包）、依赖（DB/缓存慢查询、
    外部调用）、GC/锁、连接池耗尽、TIME_WAIT、DNS。要求给出具体命令与止血动作。
  - 评分关键：是否"先恢复后根因"、是否用证据说话、是否考虑影响面。

## 4. 结构化评分表（满分 5）

| 维度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 基础知识 | 概念模糊 | 正确但浅 | 准确+能延伸原理 |
| 排查思路 | 无方法 | 有方向但乱 | 分层+止血优先+证据 |
| 脚本/自动化 | 不会 | 能写但粗糙 | 幂等+可复用+有校验 |
| 生产意识 | 忽视风险 | 知道要谨慎 | 主动提回滚/灰度/授权 |
| 沟通协作 | 表达不清 | 尚可 | 结构化、能对齐目标 |

> 录用建议：核心维度（排查思路、生产意识）≥4 分；任一项 1 分需谨慎；总分与级别对齐。

## 5. 面试 SOP

1. **开场（5min）**：介绍团队与岗位，确认候选人级别预期。
2. **基础与网络（20min）**：按题库 3.1/3.2，关注原理而非死记。
3. **脚本实战（15min）**：现场或共享文档写一段脚本（3.3），看工程素养。
4. **故障场景（20min）**：3.5 或真实案例，重点看"止血优先 + 分层 + 证据"。
5. **中间件/DB（10min）**：按岗位需求抽 3.4。
6. **反向提问（10min）**：候选人问团队/技术栈/值班，顺势评估文化匹配。
7. **评分与对齐（内部）**：按 §4 打分，写出"录用/待定/不录用 + 关键依据"。

## 6. 避坑

- 不唯证书、不唯年限；看"是否真动手过生产"。
- 故障题重点不在答案对错，在**思维过程与安全生产意识**。
- 初级可放宽体系经验，但必须有过硬的执行与学习能力；高级必须能"建体系+带复盘"。
