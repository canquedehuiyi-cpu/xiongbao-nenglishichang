# 生产环境部署与更新（从 SKILL.md §四 展开）

本文件覆盖发布策略选型、上线检查清单、配置与数据库变更、回滚预案与发布门禁。配套
`scripts/pre_deploy_check.sh`（上线前自动校验）。**铁律：任何发布先有回滚，先灰度后全量。**

## 1. 发布策略选型

| 策略 | 原理 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **滚动更新** | 逐批替换旧实例 | 资源省、零额外集群 | 新旧混跑、回滚慢、流量可能打到旧 | 无状态服务常规发布 |
| **蓝绿部署** | 新环境全量起好，切流量 | 秒级回滚(切回)、风险低 | 双倍资源、数据兼容要求高 | 关键服务/大版本 |
| **金丝雀(Canary)** | 小比例放量观察再扩 | 真实流量验证、爆炸半径小 | 实现复杂、需流量路由 | 高风险/新功能 |
| **灰度(按维度)** | 按用户/地域/比例放量 | 可控、易观测 | 需网关/标签路由 | 渐进式发布 |

**选型建议**：
- 常规无状态小版本 → 滚动更新。
- 关键业务/数据库 schema 变更 → 蓝绿或金丝雀。
- 新功能且影响面大 → 金丝雀 + 按用户灰度。

## 2. 上线检查清单（pre_deploy_check）

运行 `scripts/pre_deploy_check.sh` 自动校验以下项，人工确认其余：

### 2.1 前置（必过）
- [ ] **备份/快照完成且可恢复验证**（DB 备份、配置备份、磁盘快照）。
- [ ] **回滚方案明确**：上一版本镜像/包可用，回滚命令已备。
- [ ] **监控与告警就位**：本次变更相关指标面板已开，告警能触达 On-Call。
- [ ] **变更窗口**：在批准窗口内，相关方知情。

### 2.2 系统健康（脚本校验）
- [ ] 磁盘使用率 < 阈值（默认 85%）。
- [ ] 内存 available 充足（非 swap 颠簸）。
- [ ] 关键端口/依赖可达（探活通过）。
- [ ] 负载未处于异常峰值。

### 2.3 发布中
- [ ] 先灰度 1~5% 或单节点，观察 5~15min 无异常再放量。
- [ ] 每批放量后核对错误率/延迟/饱和度（RED 信号）。
- [ ] 保留旧版本直至全量稳定一个周期。

### 2.4 发布后
- [ ] 冒烟测试通过（核心接口/页面）。
- [ ] 监控无新增告警、错误预算未异常消耗。
- [ ] 旧版本下线（蓝绿切流后回收旧环境）。

## 3. 配置管理变更
- 配置与代码分离（配置中心/环境变量/挂载），禁止把密钥写进镜像。
- 配置变更视同发布：走同一门禁、可回滚、灰度。
- 动态配置下发需有"下发失败回退到上次正确值"的机制。

## 4. 数据库变更（高风险）
- **向后兼容优先**：加列/加表优于改列/删列；删列先标记废弃一个版本。
- **大表 DDL**：用在线 DDL（gh-ost / pt-osc）避免锁表；低峰执行。
- **数据迁移**：双写/补偿/校验，可回滚（保留旧列或备份）。
- **变更前**：全量备份 + 预估影响行数 + 审批。

## 5. 回滚预案（模板）
```markdown
# 回滚预案: <服务/版本>
## 触发条件
<错误率> / <延迟> / <资损> / <人工判定>
## 回滚手段
- 镜像/包: 回退到 <上一版本 tag>
- 配置: 恢复 <备份文件/配置中心版本>
- 数据: 不可用则 <快照恢复 / 反向迁移脚本>
## 回滚命令
1. <命令>  # 验证:<预期>
## 回滚验证
<健康检查/冒烟/监控>
## 回滚时限
<目标 X 分钟内完成>
```

## 6. 发布门禁（不可绕过）
1. 备份可恢复 ✔
2. 回滚预演过 ✔
3. 监控/告警就位 ✔
4. 灰度计划明确 ✔
5. On-Call 知情且在岗 ✔
6. 紧急联系(研发 owner)可达 ✔

> 违反任一项 → 暂停发布，升级负责人决策。

## 7. 避坑
- 不在业务高峰做重大发布。
- 不"发布完就走"：留观一个周期再下线旧版本。
- 不要相信"只是小改动"：小改动也能打挂依赖链，门禁不跳。
- 回滚不是失败：快速回滚是专业素养，优于硬扛。
