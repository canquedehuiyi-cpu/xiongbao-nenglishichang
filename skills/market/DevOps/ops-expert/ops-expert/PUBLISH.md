## 四、详细描述（市场页正文）

### 4.1 解决什么问题

多数运维失败不在"不会敲命令"，而在**流程缺失与安全意识薄弱**：生产操作无回滚、故障先查根因再止血导致资损扩大、监控只有 CPU 没有错误率与饱和度、发布不灰度直接全量、招人凭感觉面试。本技能把这些做成**硬门禁与可复用资产**，而不是建议。

### 4.3 可复用脚本

| 脚本 | 用途 | 安全特性 |
|------|------|----------|
| `server_init.sh` | 新服务器标准化初始化基线 | 幂等、改前备份、关键项确认 |
| `health_check.sh` | 系统健康巡检（只读，输出报告） | 无副作用，可定时跑 |
| `trace_diag.sh` | 故障信息按层收集打包 | 只读，便于事后分析 |
| `kernel_tune.sh` | 应用常见性能内核参数 | 备份原值、可回滚、需确认 |
| `pre_deploy_check.sh` | 上线前检查（磁盘/内存/端口/探活/备份） | 只读校验，失败非零退出 |
| `gen_alert_rules.py` | 生成 Prometheus 规则与 Grafana 面板 | 仅标准库，确定性输出 |
| `validate_mermaid.cjs` | 校验文档内 mermaid 语法（目标 mermaid@8.8.3） | 复用自 p8-full-stack，需 `npm install mermaid@8.8.3 jsdom` |
| `vuln_report_parse.py` | 解析漏洞扫描 Word(.docx) 报告，抽取严重度统计/CVE 清单/资产清单/按严重度排序的候选漏洞条目 | 仅标准库（zip+xml），确定性输出，供制定修复方案 |

### 4.4 工作方式

运维闭环：**评估 → 方案 → 执行 → 验证 → 复盘**，按任务规模裁剪为轻量/常规/复杂三档，禁跳过验证与复盘。
故障场景强制 **止血 > 恢复 > 根因** 顺序；生产变更强制 **方案 + 回滚路径 + 显式授权** 安全闸门。

### 4.5 与通用助手的差异

- 生产操作不是"想做就做"，而是**安全闸门**：方案+回滚+授权三件套，缺一项不执行。
- 故障处理不是"先查清楚"，而是**先恢复业务**再查根因。
- 所有结论不是"应该是"，而是**带证据**（命令+输出 / 指标前后对比 / 退出码）。
- 告警不是"越多越好"，而是**可行动、低噪音、带 Runbook 链接**，并按 SLO 多窗口多燃尽降噪。

## 五、使用提示词（市场页示例，复制即用）

### 5.1 招聘：生成高级运维 JD
```
用运维专家帮我写一份「高级 Linux 运维工程师」JD，包含岗位职责、任职要求、加分项，
按 references/recruitment.md 的分级能力模型对齐，输出可直接发的版本。
```

### 5.2 面试：出一套中级运维面试题
```
用运维专家出一份中级运维面试卷：覆盖 Linux 基础、网络、Shell/Python 脚本、MySQL、Nginx、
一个故障排查场景题，每题附考察点与参考答案要点，并给结构化评分表。
```

### 5.3 工作安排：搭建 On-Call 与 SLO
```
用运维专家为我团队设计 On-Call 轮值机制（含升级链路与疲劳保护）和一个核心接口的 SLO
（成功率/延迟/可用性），给出错误预算计算与告警阈值初值，引用 references/work-planning.md。
```

### 5.4 环境初始化：新服务器基线
```
用运维专家给一台新 Ubuntu 22.04 服务器做标准化初始化：时区/NTP、SSH 加固、防火墙、
普通用户+sudo、基线工具、内核基础参数。先给清单与回滚点，再运行 scripts/server_init.sh
（需我确认后执行）。
```

### 5.5 故障排查：CPU 飙高根因
```
用运维专家排查：一台 8C 生产机 CPU 突然 100%，但 QPS 没涨。先给分层排查路径与取证命令，
定位到根因后再给修复，改完给前后证据，不要只给猜测。
```

### 5.6 系统优化：高并发网络调优
```
用运维专家对一台高并发网关做网络栈优化：文件描述符、TIME_WAIT、net.core/net.ipv4 关键
sysctl，先备份当前值，用 scripts/kernel_tune.sh 应用并说明每项作用与回滚方式，给出优化前后基准对比。
```

### 5.7 部署发布：灰度上线方案
```
用运维专家为一个 Java 服务设计灰度发布方案：滚动/蓝绿/金丝雀选型与理由，上线检查清单
（含 scripts/pre_deploy_check.sh），回滚预案与触发条件。
```

### 5.8 监控告警：搭建 Prometheus 告警
```
用运维专家为我的主机与 Nginx 搭建 Prometheus 监控：需要采集哪些指标、写一组告警规则，
用 scripts/gen_alert_rules.py 生成可直接加载的 rules.yml，并设计 2 个 Grafana 面板。
```

### 5.9 巡检：生成健康报告
```
用运维专家跑 scripts/health_check.sh 对我管理的多台服务器采集关键指标，输出健康报告，
标出需关注项与建议。
```

### 5.10 上线文档：产出运维资料包
```
用运维专家为刚上线的「订单服务」产出一套运维资料：架构部署拓扑（含依赖与端口）、运维手册
Runbook（启停/日志/应急流程图）、监控告警说明（指标+告警规则+面板）、发布回滚文档、容量应急预案、
值班升级与 SLA/SLO、交接知识库。所有结构图用 mermaid（≤8.8.3，带 classDef），写完后用
scripts/validate_mermaid.cjs 校验至无 PARSE-ERROR。
```

### 5.11 漏洞修复：漏扫报告转修复方案
```
用运维专家处理这份漏洞扫描报告：先运行 scripts/vuln_report_parse.py --in 漏扫报告.docx
--out findings.md --raw raw.txt 解析出漏洞清单，再按 references/vuln-remediation.md 流程，
对每条漏洞给出「影响面 → 修复动作 → 回滚路径 → 验证方式 → 业务窗口」，按严重度/可利用性/
资产重要性/合规四维排序，涉及升级重启的走生产安全闸门（方案+回滚+授权），最后用复扫验证闭环。
```
