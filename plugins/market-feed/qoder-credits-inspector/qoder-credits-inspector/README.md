# Ocean's Credits Inspector

> 📄 官方展示页可能只渲染前半部分，**完整说明请打开插件目录内的 `README.md`**（或项目仓库）查看。

Qoder CN 桌面端插件：把**当前会话烧了多少 token / credits、都花在哪**，变成一张自动刷新的图形报告。

- 计费输入总量、实时上下文占用、重发放大倍数、Credits 一目了然。
- 按类别 / 工具 / 文件的占比，定位「哪个文件、哪类内容最烧 token」。
- Agent 每次结束响应自动刷新，无需手动操作。

长会话里同一批上下文会被反复重发，实际消耗远高于「净上下文」。本插件用平台计费口径还原真实消耗，并告诉你钱花在哪儿。

> 📋 想快速看全插件能为你做什么，见同目录 `FEATURES.md`（功能一览）。本 README 侧重「怎么装、怎么用」。

## 怎么用

### 第一步：让报告有数据

**① 官方模型（默认）—— 开箱即用**，什么都不用做。报告自动落在项目根的 `.qoder-credits/`。

**② 自定义模型 / 自带 Key（BYOK）—— 配一次本地代理**
千问、通义、DeepSeek 等 OpenAI 兼容端点不经 Qoder 计费。插件自带本地记录代理：透明转发、记下每次请求实测 token，报告即可显示**供应商实测输入 / 输出 token**（credits 仍「—」）。

报告里的 token 数按你所用模型的真实上下文窗口来算，这个窗口一般能自动认出；万一认不出，报告顶部会提示此时用的是回退默认窗口、绝对值只能看个大概，并指引你手工锁定（见下方“使用须知”）。

**推荐：在对话框里让 Agent 帮你配** —— 用斜杠命令 `/credits-inspector`，或直接说「帮我配 BYOK 代理，地址是 xxx」「查代理状态」「停用代理」。Agent 在后台代跑配置 / 自检 / 停用，把可粘贴的 Base URL 转给你；**不用装 Node、不用敲命令、不用手改 JSON**，且**当场拉起代理、无需再开会话**。（`@` 是给对话加上下文用的，跑插件能力靠这种技能调用。）

**或手动改 JSON** —— 编辑 `~/.qoder-credits-proxy/config.json`（Windows：`C:\Users\你的用户名\.qoder-credits-proxy\config.json`）：

1. `upstream` 填供应商根地址 = 你在 Qoder 里那个 Base URL **去掉结尾 `/v1`**（例：`…/compatible-mode/v1` → 填 `…/compatible-mode`）。
2. Qoder 里该模型 Base URL 改成 `http://127.0.0.1:49787/v1`（API Key、Model ID 不变；端口以 config.json 的 `port` 为准，默认 49787）。
3. **再新开一个会话**对话即可。新增自定义模型时记得勾选思考能力、对话时切到该自定义模型一栏。

> 代理在**新建会话那一刻**才检查配置并拉起（不是发首句话触发），首次冷启动需几秒。手动改 JSON 时，首次开会话 `upstream` 还是空的，**要再开一次会话**才生效；想免这一步就用上面的对话路径。装好插件、重启 Qoder 后首次开会话会自动生成带中文说明的 config.json 模板。

停用：config.json 里 `enabled` 改 `false`（不改也行，代理空跑不影响官方模型出数）。

**被停用后如何确保代理重新启动** —— `--stop-proxy` 或手改 `enabled:false` 之后，SessionStart 钩子会因 `enabled=false` 跳过拉起，必须手动恢复其一：
- **方式一（推荐，立即生效）**：`<插件目录>\bin\credits-inspector.cmd cli --setup-proxy --upstream <地址>` —— 写回 `enabled:true` 并当场拉起，无需再开会话。
- **方式二（手改 JSON，需新开会话）**：把 `~/.qoder-credits-proxy/config.json` 里的 `enabled` 改回 `true`，**再新开一个会话**。代理只在 SessionStart 那一刻检查并拉起，当前已开的会话不会补触发。

使用者一侧只有三个动作，都能让 Agent 代跑（**无需安装 Node.js**，插件自带入口会找到 Qoder 运行时；`<插件目录>` 换成你的安装路径）：

| 要做什么 | 命令 |
|---|---|
| 配代理并拉起 | `<插件目录>\bin\credits-inspector.cmd cli --setup-proxy --upstream <地址>` |
| 看链路通不通 | `<插件目录>\bin\credits-inspector.cmd cli --check-proxy` |
| 停用（改回官方模型） | `<插件目录>\bin\credits-inspector.cmd cli --stop-proxy` |

对话或上下文压缩不对劲时，直接对 Agent 说一句「检查一下代理」——它会代跑逐笔请求诊断，分清是代理、供应商还是客户端，你不用碰任何参数。

### 第二步：看报告

- **看图**：Canvas 预览面板打开 `.qoder-credits/` 里本次会话的报告（文件名含会话标题）——饼图、条形图、文件榜（含「单次读取」代价）、逐请求明细、压缩单笔成本、当前上下文占用该不该压的结论、自动压缩不会触发的醒目告警、链路健康度。
- **直接问**：「这个会话花了多少 token？」「哪个文件最耗 token？」「现在该压一下上下文吗？」Agent 读报告给你文字速览。
- **一条“该不该压”的结论 + 一条醒目告警**：报告头条是“当前上下文占用”，按**你设的压缩阈值**给出该不该压的结论（段内上下文只增不减，最新占用就是自上次压缩以来的峰值，不再单列冗余的“峰值”）；同一处附“对模型物理窗口”的占比（= IDE 底部进度条口径）。**当模型窗口很大（如 1M）而你设的阈值（如 200K）远小于窗口时，报告会单独弹一块醒目告警**：Qoder 的自动压缩按窗口 ~85%（≈850K）才触发，你设的 200K 永远不会自动压——必须照“对压缩阈值”那条自己手动压。注意 IDE 底部进度条按模型真实窗口算，自定义模型下会显得“还很空”，具有迷惑性；判断该不该压、会不会自动压，一律以报告为准。真实上下文已超你设的阈值时，拖到很满再手动压可能被供应商拒掉而报错，要趁早压。

产物：`.qoder-credits/report.json`（结构化数据）；`.qoder-credits/<会话标题>__<会话id前8位>.canvas.tsx`（每会话一份可视化报告，互不覆盖）。

## 数字准不准

| 指标 | 精度 |
|------|------|
| 计费输入总量 / Credits | 真值，精确 |
| Credits 的覆盖范围 | 混合链路下只覆盖部分往返，报告会标明是几笔、占多少输入量 |
| 当前上下文占用 | 精确（段内只增不减，= 自最近一次压缩起的峰值）；报告据此给“该不该压”的结论，并在你的阈值远小于模型窗口时单独告警“自动压缩不会触发” |
| 模型上下文窗口 | 一般能自动识别；识别不到时回退默认值、报告顶部告警，可手工锁定 |
| 重发放大倍数 | 由真值派生 |
| 按类别 / 工具 / 文件占比 | 总量精确，内部拆分为按比例估算 |
| 输出 token / 缓存命中 | 真值，仅配了代理的自定义模型会话有 |
| 压缩单笔成本 | 客户端自估；能在代理日志里唯一对上时换成供应商实测，报告里用「口径」列标明是哪一种 |

一句话：**总量、占比可信；单个文件的绝对 token 是估算值，用来看相对高低，别当精确账单。**

## 使用须知

- **平台**：Windows + Qoder CN 桌面端。
- **首次安装或更新后请重启一次 Qoder CN**，自动刷新与代理拉起才生效。
- **数字有无取决于会话在哪端**：仅 **Qoder CN 桌面端**会话有完整 token / credits；**IDE / JetBrains 插件端**用固定内置端点、本地读不到计费数据，token / credits 显示「—」（数据源限制，非故障）。工具调用 / 文件读取 / 对话轮数两端都准。
- **BYOK**：仅桌面端可配，配好即有供应商实测 token（credits 仍「—」）。
- **压缩阈值需你手动告知（重要）**：报告里「你真实的上下文占用」用的那把尺（`userContextLimit`），**插件无法自动读取你在 Qoder「模型管理」里设的上限**；未告知时一律按内置默认 **200000** 算（报告里标「・默认」，并在旁边提示你如何改）。想让它反映你的真实阈值，二选一：
  - **全局**：在 `~/.qoder-credits-proxy/config.json` 填 `"userContextLimit": <你的上限>`（对所有会话生效）。
  - **单场**：在项目根 `.qoder-credits/overrides/<会话id>.json` 填同名字段（手工优先级最高，只影响该会话）。
  - 填完重跑报告即生效。模型窗口（`contextWindow`）一般能自动识别，识别不到时也可在 overrides 里一并手工锁定（如 `1000000`）。
