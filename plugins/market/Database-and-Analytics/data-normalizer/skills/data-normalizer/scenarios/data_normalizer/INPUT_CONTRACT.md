# 输入契约 —— 数据标准化（固定前置功能）

> 目的：把「标准化动作」的输入边界定死——只吃文本层、只做格式清洗、不臆造值。
> 各企业真实数据格式各异（列名/版式/单位写法都不同），本功能用 80-20 方式把
> 关键数据按**列名别名识别 + 值清洗 + 模板回填**统一成目标场景的标准键值行，
> 是判定场景的第一步/第二步，不跑它后续判定无法进行。

## 0. 输入形态总览

| 输入字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source-file` | 文件 | ✅ | 用户真实数据文件：Excel/CSV 表格优先；文本/PDF/Word 走文本层 |
| `scenario` | 选择 | ✅ | 目标场景键集（产物喂给哪个判定场景） |

`scenario` 可选值（CHOICE）：

| 值 | 判定场景 |
|---|---|
| supplier_identity_vet | 供应商核验 |
| shipping_doc_crosscheck | 单证交叉核对 |
| material_kitting_check | 物料齐套核对 |
| external_statement_reconcile | 外部对账 |
| bid_deviation_crosscheck | 偏离核对 |
| bid_disqualification_terms | 投标要件核对 |

## 1. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| Excel（xlsx/xlsm） | ✅（推荐） | 自动按列名别名识别表与列，转标准键值行 |
| CSV（utf-8-sig/GBK） | ✅ | 同上，按单元格读，格值含逗号不错列 |
| UTF-8 TXT / MD | ✅ | 按文本行原样清洗输出（交由目标场景解析） |
| 文本层 PDF / DOCX | ✅ | 读到的是文字，非图像 |
| 扫描件 / 图片 / 截图（jpg/png/tif） | ❌ | **拒绝**；格值命中扫描件特征时整行拒出转人工 |
| 图片版 PDF（无文本层） | ❌ | 同上 |

> 例外：若只能拿到扫描件，宿主须在喂入前完成 OCR/手打转文本层；转不出的
> 单元格以「扫描件占位」标记，由引擎整行转人工清单，**不产出伪数据**。

## 2. 表格输入：列名别名识别（80-20）

引擎内置每个目标场景的**标准列头 + 常见列名别名库**（中文为主、英文为辅）。
表头做全半角/大小写/空白/下划线归一后匹配，命中率+专属命中选表；对不上的列
如实进「未识别列」清单转人工，**绝不按位置硬填**。

例（外部对账，企业列名与标准全不同）：

```
输入列：交易时间 | 户名 | 发生额 | 凭证号 | 借贷 | 摘要
标准键：日期     客户    金额     单号     类型   摘要
产出行：流水:日期=2026-09-01 客户=深圳市蓝天科技有限公司 金额=1,000.00 …
```

## 3. 扫描件拒识与转人工

- 单元格值命中扫描件特征（图片/截图/扫描/拍照/照片/ocr/image/png/jpg 等）→
  **整行拒出**，不输出该行的键值行，计入清洗报告「转人工」清单。
- 表头列名无法识别且场景无原文表兜底 → 报错 FAILED，提示改用模板或文本输入。
- 文本输入：清洗（全半角/首尾空白）后原样输出，原文行语义不变。

## 4. 输出（产物三件套）

| 产物 | 内容 |
|---|---|
| `〈snake〉-normalized.txt` | 标准键值行（与目标场景文本契约同构，可直接喂判定） |
| `〈snake〉-normalized.xlsx` | 回填模板（表名/表头与目标场景 `template_reader` 一致，可回喂） |
| `normalize-report-〈date〉.md` | 清洗报告：列映射 / 未识别列 / 转人工清单 / 行数 |

- `outputs.verdict`：`DONE`（全部识别并产出）/ `REVIEW`（有未识别列或扫描件
  占位转人工）/ `FAILED`（输入为空或表头无法识别且无兜底）。
- `outputs.explain`：目标场景、输入类型、标准化行数、识别表、列映射、未识别列、
  转人工清单（清洗依据，逐条可查）。
- 供应商核验（supplier_identity_vet）特殊：键值行按字段逐行输出
  （`台账:名称=X` / `台账:法定代表人=Y` …），与「两侧对照」模板同构。

## 5. 通用模板回填（与判定场景模板对齐）

回填 xlsx 的表名/表头与目标场景 `template/` 模板**完全一致**：
- 命中表填数据行；原文表回填文本行；未命中表留空仅表头；
- 物料齐套场景附空「口径声明」表供用户后补；
- 供应商核验场景按「两侧对照」纵向结构转换（每行一个字段 × 台账侧/证照侧）。
产物可被目标场景 `template_reader` 原样回读成同构键值行，**判定结果与直接喂
文本完全一致**（键集一致性由 tests 锁定，防双份声明漂移）。
