# 影响分级决策

## L0：核心（必须 sign off）

**判定条件（任一）**：
- 财务 / 计费 / 对账类下游
- 涉及外部客户的报表 / API
- CEO / VP 关注的看板
- 有明确业务 SLA 承诺
- 最近 7 天被消费 ≥ 100 次

**处理**：
- 提前 ≥ 1 周通知（团队 SLA 以 `change_sla_l0` 为准）
- 必须业务方 + 技术方双 sign off
- 配双写 / 兼容期
- 上线后专人监控 1 周

## L1：业务运营核心

**判定条件**：
- 业务运营每日决策依赖的看板
- 团队主管以上角色查看
- 最近 7 天被消费 ≥ 30 次

**处理**：
- 提前 ≥ 3 天通知
- 需技术 owner 确认修改方案
- 上线日有人值守

## L2：一般分析任务

**判定条件**：
- 普通分析师任务
- 数据科学家探索任务
- 内部 PM 关注的辅助看板

**处理**：
- 提前 ≥ 1 天通知
- 自动通知 owner，不强求确认

## L3：低优 / 疑似废弃

**判定条件**：
- 最近 30 天无访问
- 个人临时任务
- 已知 owner 离职

**处理**：
- 通知 owner（如有）
- 无 owner 直接归档

## 处理矩阵

| 级别 | 通知 SLA | sign off | 改动方 | 监控 |
|------|---------|----------|--------|------|
| L0 | ≥ 1 周 | ✓ | 通常下游自改 | 1 周专人 |
| L1 | ≥ 3 天 | △ | 通知 owner | 上线日值守 |
| L2 | ≥ 1 天 | ✗ | 通知 owner | 无 |
| L3 | 当日 | ✗ | 不强求 | 无 |
