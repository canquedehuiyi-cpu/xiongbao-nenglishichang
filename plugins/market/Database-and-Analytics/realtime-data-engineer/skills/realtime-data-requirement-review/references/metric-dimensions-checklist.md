# 5 维度拆解决策因子清单

## Dim 1：指标定义

| 问题 | 必答 | 反模式 |
|------|------|--------|
| 业务名是什么？技术名是什么？ | ✓ | "用户活跃度"——业务说法和 DAU/MAU/PV/UV 不对齐 |
| 是核心指标还是派生指标？派生公式是？ | ✓ | "GMV" 没给公式，下游算的可能不一样 |
| 单位是什么？百分比 0-1 还是 0-100？ | ✓ | "转化率 5"——是 5% 还是 500%？ |
| 数值精度（小数位、四舍五入规则）？ | △ | 客户金额场景必须问 |

## Dim 2：计算逻辑

| 问题 | 必答 | 典型分歧 |
|------|------|---------|
| 聚合方式（count / sum / distinct / avg / 自定义）？ | ✓ | "用户数"是 count 还是 distinct count |
| 去重维度（user_id / device_id / 复合 key）？ | ✓ | 一个 user 多设备如何处理 |
| 过滤条件（测试账号 / 内部员工 / 黑名单）？ | ✓ | 大促数据被压测流量污染 |
| 是否包含退款 / 撤销 / 取消？ | △ | 交易类指标必问 |

## Dim 3：时间口径

| 问题 | 必答 | 影响 |
|------|------|------|
| 事件时间还是处理时间？ | ✓ | 跨天数据归属 |
| 时间字段（业务时间 / 创建时间 / 入库时间）？ | ✓ | 多个时间字段时极易踩错 |
| 时间窗（自然日 / 滚动 24h / 业务日 04:00 切）？ | ✓ | "今日 GMV"和零点切换 |
| 时区（UTC / 北京 / 用户当地）？ | ✓ | 跨境业务必问 |

## Dim 4：边界 case

| 场景 | 引导问句 |
|------|---------|
| 跨天事件 | 订单 23:59 下单，00:01 支付，归哪天？ |
| null 值 | user_id 为 null 的记录算不算？ |
| 历史回刷 | 数据迟到 7 天后到了，要不要回刷历史指标？ |
| 异常流量 | 大促被刷单 / 压测流量，要不要过滤？ |
| 退款/撤销 | T 日下单 T+3 退款，T 日 GMV 要不要回滚？ |
| 维度变更 | 用户 city 字段昨天是北京今天是上海，按哪天算？ |

## Dim 5：字段映射 + 数据源

输出表（必填）：

| 业务字段 | 物理字段 | 表/topic | 数据类型 | 是否可空 | 特殊取值 |
|---------|---------|---------|---------|---------|---------|
| 用户ID | user_id | dwd_user_log | string | N | -1 表示游客 |
| 下单金额 | order_amount | order_realtime_topic | decimal(18,2) | N | 0 表示赠品 |

## 业务 sign off 流程

口径文档生成后，**必须**：
1. 列 3-5 个测试 case（含正常 + 边界）
2. 给具体数值预期（业务方要 yes/no 而非自由发挥）
3. 业务方回邮件/钉钉 sign off 才算定稿
4. 文档归档到 `metric_doc_storage`（QODERWORK.md 配置）

## 反模式

- ❌ 把"约定俗成"当共识——同公司不同部门"DAU"定义经常不一样
- ❌ 不写时区——跨时区业务全错
- ❌ 不列边界 case——开发完才发现退款没处理
- ❌ 没业务 sign off——上线被打回
