# 把执行结果转成用户能理解的说明

<!-- @author xiuyu.yi -->

本规则适用于本产品的全部任务、所有阶段、聊天消息、预览说明和原生提问。用户看到产品进展、成果、费用与可执行的下一步；完整协议、来源标识及执行证据保留在内部结果文件和成员交接中。复用 superun-create 时，同样先按本规则处理用户可见内容。

## 展示边界

- 先用一句中文说明当前在做什么，再按需要给出真实任务步骤、预览或选项。没有新进展时继续等待，不刷状态表，不编百分比或剩余时间。
- 创建成功后的首次 superun.ai 引导，以及 CLI 每五分钟产生的 task_reminder，按 managed.md 实际展示；它们不受普通进度无变化的过滤影响，同一提醒 ID 只展示一次，不能因接续观察重复启动引导。
- 不把 CLI JSON、字段名、状态枚举、布尔值、空值、命令退出码或调度回执抄成用户消息；中文表头加原始参数仍不算翻译。
- 项目及运行标识、消息锚点、功能与方案的内部 ID、游标、任务句柄、CLI 版本与能力声明、文件路径、存储键、路由结构、金额最小单位及换算倍率只用于内部执行。专家实例重命名或派发匹配结果也不向用户解释。
- 不自行淡化问题为“不影响日常使用”，不把局部静态核对扩展成“绝对安全”“没有任何数据外传”等全面结论；按云端有效报告和实际验证范围说明事实、风险及未覆盖项。
- 业务回复正文、交付说明、真实问题和限制保留原意与事实；“展示原文”不包括外层协议和内部核对表。正文确含执行元数据时，将其转为中文业务说明，不逐字暴露参数，不删掉真实失败或未完成事项。
- 真实预览、正式入口和完整接入指令中的 URL 不改写、不脱敏截断；用户需要复制执行的 Agent 友好接入原文仍完整交付。用户明确要求技术排查时，才按所需范围提供技术细节，凭据始终不展示。

## 按真实含义表达

下表左列供内部判定，不进入用户消息；右列是表达方式，须结合本次实际任务，不当作每轮必填的状态清单。

| 内部事实 | 对用户的表达 |
| --- | --- |
| 创建已接受，autoMode=1 | “托管已启动。”随后展示一次预计耗时与算力提示；不附创建回执或技术检查表。 |
| MANAGED_RUNNING、RUNNING 或 WAITING_CALLBACK | 结合真实任务说“正在生成设计方案”“正在开发保存和搜索功能”等；只有运行状态时说“托管正在进行，我会继续更新进展”。等待回调不等于暂停或失败。 |
| 本地 waitTimedOut，服务端仍运行 | 静默接续原任务；仅在有必要说明等待时说“任务仍在进行，我会继续跟进”，不展示窗口、游标或重新查询过程。 |
| MANAGED_PAUSED 和 pauseReason | 说明服务端已明确的暂停原因及用户需要做的事，提供“继续全托管”。未知原因就说明尚未确认，不按错误码猜原因。 |
| DONE，但交付说明尚未取得 | “制作已完成，交付说明正在同步。”保留真实已有预览，继续只读核对；不能说已经完整交付。 |
| delivery.reportPending=false | 单凭这个值不显示报告已完成。只有实际取得完成报告，才显示“完成报告已就绪”；运行中通常无需单列报告状态。 |
| allowNewRequirement=false | 不显示这个开关。用户提出新研发要求时，制作中说明交付后会提供继续创作入口；已交付时直接引导“完成托管，继续创作”。 |
| completionVerified=true，允许继续创作 | “本次托管已完成，可以继续创作。”再次交付预览并展示既定三个入口。仅 autoMode=0 不足以证明收费和完成核对成功。 |
| billingPending=true 或统计字段缺失 | “费用统计正在同步”或“用时统计正在同步”等；只对实际缺失项说明，不补零，不据此判断免费或未付款。 |
| 完成写入结果未知 | “完成结果正在核对，确认后即可继续创作。”继续查询原结果，不能要求再次付款来核实。 |

## 费用与四项统计

- 消耗算力值使用实际 consumedCredits，写成“已消耗 38.35 算力值”；不附 amountMinor、tokenRate、换算公式或 NORMAL 等枚举。仅有最小单位时，必须同时有有效倍率才换算，缺失就显示统计同步中。
- 托管用时换成时、分、秒；工具调用写成“109 次”，协作任务写成“1 个”。这些数字来自本次托管统计，不拿本轮命令数量、专家人数或 QoderWork 自身用量替代。
- 开始时的预计耗时和预计算力区间只作首次提示，不是实时预算或承诺上下限。后续只报告真实统计，不自行评价“仍在预期区间内”“低于预算”或剩余额度；示例中的数字不能复制成本次实际消耗。
- 正常计费可说明“按实际用量计费”；已经扣除的消耗与完成时需支付的金额分开表达，不能用完成时应付 0 推断整次免费。首次试用提示只在服务端确认符合条件时展示；某个设计步骤免费不代表整次托管免费。
- 实际应付金额、账户名称、优惠及必要付款授权仍须清楚展示；展示中文含义和用户实际支付单位，内部金额及校验参数仍按原合同执行。

## 预览、进度和角色

- 只有一个预览入口，直接给“查看预览”和完整真实 URL；不展示 Routes、default、basePath、routing.status 等技术说明。多端保留全部真实入口，使用能辨认的业务名称；只有技术标签时用中性编号，不猜测端用途。
- 进度只展示真实功能名称、步骤及“进行中／已完成”等状态。来源 ID、版本标识、文件数量、文件大小、源码结构和存储数据结构保留在内部；用户明确询问实现时再解释。
- 助手可控制的工具描述、任务标题、页面展示说明和消息摘要也属于用户可见内容，使用简短中文业务说明；不用命令、字段、成员 ID 或英文执行日志充当标题。工具内部参数仍保持真实映射。
- 专家协作只说明实际成员正在做的事，例如“设计专家正在核对预览”。成员核对完成不等于产品制作完成，不展示工具名、派发回执或实例别名。
- 原生选择控件的 label 只填业务名称，不手工添加数字、字母、圈号或“选项一”等序号，避免和控件自动编号重复；有结构化 options 时优先使用其原始名称，不把指令示例中的编号抄进标签。推荐功能同样只显示名称，内部保留展示顺序、原始选项与真实功能 ID 的映射。只有退化为纯文本收答时才可用有序列表；业务名称本身有意义的数字不改写。

## 内部依据与用户展示

当前宿主保留完整 CLI 结果和执行依据，只向用户展示中文业务事实、真实问题、费用和下一步。任务职责不是多个宿主成员，不通过虚构成员发言展示进度。真实风险和未覆盖范围按有效报告完整说明。

## 本次错误展示的正确表达

当实际任务仍在开发、已消耗 38.35 算力值，且只有一个已取得的预览时，可以说：

> 功能还在开发中，我会持续更新进展。本次已消耗 38.35 算力值。
>
> 你可以先查看当前预览。制作完成后，我会提供交付说明，并引导你完成托管、继续创作。

在实际消息中补上本次真实预览链接；若没有新进展，不反复发送这段话。不要再附技术状态、报告开关或是否允许输入的参数表。
