# 当前任务的职责划分

<!-- @author xiuyu.yi -->

| 成员 | 承接任务 | 内部交接必须保留的事实 |
| --- | --- | --- |
| 项目经理 lead | 用户对接、统一执行、统一观察句柄、收答与展示、正常收费和结束托管、跨角色交接 | 当前 sessionId/runId、授权、准备结果、来源锚点 |
| 产品 product | 首次原始需求与材料、范围与自动决策、结束后真实功能推荐 | 原话和附件、平台需求结论、真实功能 ID |
| 设计 design | 方案、演示、视觉与交互进展；结束后的页面调整或高级设计师 | 本轮真实成果与预览、用户具体调整要求 |
| 开发 development | 研发进度、功能实现、缺陷处理、结束后新增或修改功能 | 当前主线、本轮结果、预览和实际问题 |
| QA qa | 完整性、自动测试、代码审查、安全扫描、报告后续修复和验证 | 报告来源与问题编号、范围、修复及复验状态 |
| 运营 operations | 正式交付、上线、介绍材料、项目使用与业务运营 | 目标版本、正式入口、实际数据或操作回执 |

安全工作归 QA，不新建安全角色。所有业务执行通过 superun，宿主不另外编写一套产品、代码、SQL 或审计结论。

全托管进行中，各角色只解读真实阶段结果、核对交付数据和已有云端报告。QA 不在宿主重新下载全部源码或构建包另做一套审计，不因承担核对角色而额外启动测试、代码审查或安全扫描。已有结论未覆盖的范围如实说明，不编写本地复核脚本代替云端已有能力；完成托管后，用户选择的检查仍通过既有 superun CLI 执行。不得自行增加依赖清理、代码优化等任务，或承诺托管完成后自动执行它们；模型自己创建的任务清单不代表用户授权。

同一次全托管只保留一个观察任务。当前宿主沿本次项目和运行，按上表职责处理阶段结果、收答、预览和必要核对；职责划分不代表已经创建宿主成员，不模拟团队讨论或协作次数。云端报告与协作统计只采用本次真实回执。任何后续业务写入先经收费和完成状态检查。

当前宿主直接调用原生提问和页面工具，保存真实用户答案与完整链接。预选、取消、超时和内部任务记录均不代表用户已经回答或成果已经展示。
