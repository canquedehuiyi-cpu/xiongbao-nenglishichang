# 交付、正常收费并完成托管

<!-- @author xiuyu.yi -->

## 完成时的固定顺序

先读取本次真实结果：

```text
superun-ai chat auto-mode report <sessionId> --run-id <runId>
```

1. 展示 delivery.report 中原始交付说明：做成了什么、怎么使用、需要完善的事项及已知限制。全文可在“查看完成报告”展开，不另造结论。
2. **给出本次真实 id--预览链接**，使用 delivery.previewUrl/routing；单端直接给“查看预览”，多端完整展示各端名称和 entryUrl，正文写出完整真实 URL，并调用当前页面工具。不能改用项目工作台或正式发布域名替代，也不由宿主拼 URL。
3. 展示四项统计：**消耗算力值、托管用时、工具调用、协作任务**。取 metrics 的本 run 数据，按 [中文展示规则](presentation.md) 使用算力值、时分秒、次和个；不附原字段、金额最小单位或换算倍率。同步中显示“同步中”或“—”，不补零，不拿末轮次数或专家人数顶替。
4. 读取 quote，准备当前完成入口的真实费用信息，不自动购买：

```text
superun-ai chat auto-mode quote <sessionId> --run-id <runId>
```

5. 用原生单选同时展示且仅展示三个入口：**完成托管，继续创作／查看完成报告／创作历程**。实际应付金额、`completionQuote.chargeAccount.label` 和当前优惠放在现有完成选项的说明中；用户不需要选择计费模式，不再增加“是否开始”或同一意图的重复确认。

交付文档或费用信息尚未就绪时，保留真实已取得成果并只读补查，不声称全部已交付。预览保持只读，不能由此开放未结束托管的新研发输入。

## 报告和历程之后

“查看完成报告”读取并展示原始报告；“创作历程”读取本次 run 的真实范围：

```text
superun-ai chat auto-mode history <sessionId> --run-id <runId> --started-at <scope.startedAt> --completed-at <scope.completedAt>
```

时间使用本次回执值；没有结束时间时省略。查看后都 **直接引导“完成托管，继续创作”**，不额外加推荐待办或解释可以继续修改的步骤。外部页面打开时同次聊天也保留这个入口，不假装知道用户已读完。

这里没有“直接输入新需求”第四个选项，没有“是否已有具体需求”判断。宿主外层仍收到新研发文本时，先引导用户完成托管，不提交研发，也不把文本当作未知金额付款授权。

## 自动调用既有完成接口

用户明确选择“完成托管，继续创作”后，执行 quote 结果中的 COMPLETE_AUTO_MODE.command，保持本次 runId 和有效金额：

- NORMAL：核对实际已收账单，调用现有正常解锁，不另做购买。
- FREE_TRIAL：按当前真实 quote.purchaseTokenAmount、tokenRate 和平台现有付款授权执行原购买接口。`--acknowledge-purchase` 仅在费用已展示且用户明确选择付款动作后传入。
- 预计 200–800 算力不是实际应收金额或任意扣款授权。费用变化或优惠跨期先重新读取并更新当前入口说明，不能自动接受更高价格。
- 写结果未知只查询，不能重发扣款。成功回执、同一 run 和 autoMode=0 都核对后才开放后续创作；不能在本地改状态。

正常收费不能漏收、也不能重复收。完整保存本次成功结果或未知结果的原始任务文件；状态接口解锁后缺少旧统计时继续使用本次真实回执，不再次购买来“重建”数据。

收费和完成托管成功后，**再次交付当前真实 id--预览与全部端入口**，然后直接展示：

- 推荐更多功能
- 手动输入需求
- 上线运营

原生选项的 label 只使用上述名称，不添加数字、字母或其他人工序号；顺序由选项数组保留，编号交给控件自动显示。

这时才开放新需求。后续每次业务写入通过本包 guarded 脚本先核对同一运行的完成状态，不能仅依赖历史按钮或提示词。
