# 继续使用同一项目

<!-- @author xiuyu.yi -->

收费并完成托管、再次展示预览后，固定提供 **推荐更多功能／手动输入需求／上线运营**。后续沿用当前项目与任务，不重新新建。

## 三个入口

- 推荐更多功能：产品角色读取当前真实推荐；需要新推荐时将用户诉求原话转交同一项目。原生选项只展示真实功能名称，序号由控件生成，内部保留展示顺序到真实 ID 的映射，用户选择后再交给对应角色，不默认全选或自动开发推荐。
- 手动输入需求：此时收取具体内容；后续已经提供原话时不重复询问。项目经理按任务指派产品、设计、开发、QA 或运营。
- 上线运营：运营角色查询当前目标版本，已经上线的同一版本不重复部署；有待发布改动时沿当前发布能力执行，成功后交付全部正式入口。

业务命令使用同包 superun-create 的云端执行与对应方法；状态检查通过后才能执行，不重走新建流程。云端数据、代码和交付结果来自 superun，不在宿主另造。

## 强制前置检查的执行方式

每次执行既有业务命令，用当前 Skill 根目录的 `references/methods/superun-create/scripts/run-cli.mjs` 记录任务结果；被执行程序换成本包的 guarded 脚本。CLI 实际路径和 Node 路径使用 READY 回执，不写死用户名或全局安装位置。

```text
<nodePath> <当前Skill根>/references/methods/superun-create/scripts/run-cli.mjs --out-dir <本次新结果目录> -- <nodePath> <当前Skill根>/references/methods/superun-autopilot/scripts/run-guarded.mjs --session-id <sessionId> --run-id <runId> -- <nodePath> <CLI实际path> chat send --input <需求JSON文件> --no-wait -- <sessionId>
```

CLI 位置参数统一放在其 `--` 之后，第一个必须是同一 sessionId。后续按原任务句柄和 nextActions 继续；guarded 核对同一运行的收费和完成状态，检查通过后再执行本次业务。读取托管、quote、complete、history 等接口不使用这个业务脚本，以免错误阻挡完成处理。

Agent 友好所选接入指令中的目标应用 CLI 安装和查询，是用户选择接入后的独立能力；按所选完整原文及其权限约定执行，不将这些目标应用命令当成 superun-ai 创作命令塞入 guarded，也不把接入指令发回项目聊天。

## 每轮完成后的实际引导

| 结果 | 用户后续动作 |
| --- | --- |
| 研发或修改完成 | 展示原始成果、真实 id--预览和各端入口；提供代码审查、自动测试、安全扫描、继续创作、上线运营等当前允许动作 |
| 代码审查或自动测试 | 按同包质量检查方法展示当前报告、范围和真实修复结果；剩余问题按原 sourceMessageId 跟进，不能全部结束都套成功菜单 |
| 仍有未修复问题、缺资料或本次范围未完成 | 先引导处理对应问题／补齐剩余检查，不把任务结束解释为通过 |
| 已修复但尚未复验 | 明确事实，提供对应复验入口；已有明确授权可衔接，否则等待真实选择 |
| 安全扫描结束 | 依据真实报告展示风险、处理与未覆盖范围，按实际允许动作给继续创作、自动测试、上线运营 |
| 当前目标版本成功上线并满足公开条件 | 展示实际变更及全部正式入口，给继续创作、Agent 友好和实际返回的高级设计师 |
| 高级设计师 | 没有具体要求时收取要调整的页面及具体要求；已有要求调用原 chat design。重新设计不回风格候选，完成后再给预览；用户要求时才重新上线 |
| Agent 友好 | 能力就绪后选择技能／连接器，完整展示所选接入原文，再给接入当前会话／新会话／其他 AI 应用，最后用真实只读查询验证 |
| 内容、活动和业务数据运营 | 转交同一项目真实诉求与授权，展示实际结果，不把每次运营查询都强塞研发和发布菜单 |

当前阶段所有可选动作按原 nextActions.when 筛选，使用宿主真实原生选择能力收答；已有选择不重复弹框。后续检查、修复和设计有可展示成果时重新提供真实预览，不能用旧页面或正式网址冒充本轮预览。
