# Java 格式与注释规范

修改或生成 Java 代码（含文档及技能中的示例）时读取。只整理本次修改范围，保留历史作者和日期。

## Java 代码格式

- 新增、生成及本次修改的 Java 代码应符合 IntelliJ IDEA 格式化后的整洁排版，并明确采用以下规则；文档和技能生成的 Java 示例同样适用。
- **左花括号同行**：类、接口、枚举、record、构造方法、普通方法及控制语句的左花括号必须放在声明或条件末尾，与前面的内容用一个空格隔开，不允许左花括号独占下一行。例如类声明使用 `public class ExampleController {`；`else`、`catch`、`finally` 与前一个右花括号同行。声明因长度换行时，左花括号跟随声明的最后一行。
- **缩进与空白**：使用 4 个空格缩进，不使用 Tab；运算符两侧、逗号后及控制关键字与括号之间保留规范空格。方法之间适当留空行，长参数列表和链式调用按 IDEA 风格换行缩进，不把多个声明或语句挤在一行。
- **格式化范围**：新文件整体检查格式；历史文件只整理本次修改范围及相关声明，不批量重排无关代码。交付前检查缩进、括号、空行、导入和注释排版，不能把存在的旧式换行花括号作为新代码的参考格式。

## 注释适用范围

- **新增代码**：接口、类、枚举须有中文类注释；新增方法（含构造、静态、抽象、私有方法）须有中文方法注释；新增属性和常量须有中文用途说明。在历史类中新增成员也适用。
- **修改历史代码**：只更新与本次行为变化有关的说明，并在关键逻辑处补充必要注释；不为已有类、方法批量补作者、日期或其他模板信息，不改写历史作者和日期。
- **方法内部**：对业务规则、复杂分支、计算口径及关键步骤添加说明，可使用编号行注释或多行注释。简单取值、赋值或委托调用无需重复翻译代码；抽象方法无方法体，不要求内部注释。
- 未改动的代码不补注释、不调整风格。文档和技能产出的 Java 代码示例遵守同样约定。

## 注释格式

所有新增或修改的 Javadoc 必须使用标准多行格式：起始 `/**` 和结束 `*/` 各自独占一行，中间每行以对齐的 `*` 开头；即使只有一句描述也不得压缩成单行 Javadoc。说明正文与 `@param`、`@return`、`@author`、`@since` 等标签块之间留一个空注释行。方法内的普通步骤说明仍可使用 `//` 行注释。

新增类和方法的 `@author` 使用当前仓库 `git config user.name` 的结果，未配置时询问用户，不猜测作者；`@since` 使用创建当天日期，格式 `yyyy-MM-dd`。描述为中文，参数和返回值按实际签名填写，无参数或 `void` 时省略相应标签；相关引用使用 `@see`，无引用时省略。

类、接口、枚举：

```java
/**
 * 中文功能说明
 *
 * @author <git config user.name 的结果>
 * @since <yyyy-MM-dd>
 */
```

方法（按实际情况填写或省略 `@param`、`@return`）：

```java
/**
 * 中文功能说明
 *
 * @param 参数名 中文参数说明
 * @return 中文返回值说明
 * @author <git config user.name 的结果>
 * @since <yyyy-MM-dd>
 */
```

属性和常量同样使用多行 Javadoc：

```java
/**
 * 中文用途说明
 */
```

关键步骤可使用 `// 1. 校验源类型与目标类型` 这样的编号注释。模板中的占位符必须替换为实际值。
