# 接口与 OpenAPI 规范

新增或修改 HTTP 接口及关联请求/响应模型时读取。

- **适用条件**：项目已接入 Swagger / OpenAPI，或相关历史接口已有文档注解时，新增、生成或修改 Controller 接口必须同步维护在线 API 文档及关联请求/响应模型。先核对实际生效的依赖、注解版本和扫描配置及目标项目实际支持的注解体系，不混用 Swagger 2 与 OpenAPI 3，不为补文档升级或更换依赖。
- **接口描述**：使用实际注解体系说明业务分组和接口中文摘要；OpenAPI 3 项目可使用 `@Tag`、`@Operation`，包含本次涉及的权限、状态约束和行为变化。文档中的路径、HTTP 方法和媒体类型必须与实际路由映射一致。
- **请求参数**：路径、查询、请求头、表单及请求体参数均应在文档中正确展示位置、名称、类型、必填性和说明；使用当前文档框架支持的参数和模型注解，查询对象按实际支持方式展开。DTO 及嵌套对象的字段须说明用途、枚举、单位、范围、默认值和空值语义，与校验注解及实际行为一致。普通 Java 注释不能代替在线文档注解；文档注解也不能代替运行时参数校验。
- **返回参数**：保留具体响应类型及泛型，完整展示响应包装、业务对象、数组元素、分页字段和嵌套 VO 的结构与中文字段说明；避免因使用原始包装类或泛化为 `Object` 导致响应模型丢失。按当前版本支持的方式补充成功及主要错误响应；区分 HTTP 状态码和业务错误码，文件下载按实际媒体类型描述。
- **请求与返回示例**：为本次接口提供可供联调参考的请求示例和成功响应示例，必要时补充空结果及主要错误示例。使用当前版本支持的字段和完整请求/响应示例注解；无请求体时提供对应参数示例，文件流不伪造 JSON 响应。示例须符合真实序列化类型、必填条件、枚举和时间格式，且不含真实凭证或敏感数据。
- **同步范围**：同步修改本次接口关联的 DTO / VO、枚举说明、示例及前端联调文档，核查共享模型对其他接口的影响。不得为了改善文档展示擅自改变运行时返回结构、校验规则或序列化行为；也不批量迁移无关历史接口。
- **展示验证**：在已获授权且可用的运行或测试环境中，检查实际生成的 OpenAPI 描述及项目实际使用的文档页面，确认接口可见、参数和嵌套模型完整、示例可读；存在自定义地址或分组时以项目配置为准。未完成运行验证时明确说明，不仅凭注解存在就声称页面展示正常。
