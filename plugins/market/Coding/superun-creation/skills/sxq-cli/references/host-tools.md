# 当前宿主工具

## 用户提问

### Qoder 提问方式

使用当前真实问题和完整选项，不省略影响选择的费用信息。问题来源由当前执行模式决定。

需要用户补充答案或选择时，按以下优先级调用当前可用且用途匹配的工具：
- `AskUserQuestion`；允许模式：以当前会话声明为准；收答方式：synchronous。


遵守当前工具的 schema、题数、选项数及单/多选限制；不为提问擅自切换模式。工具不可用或无法完整表达题目时，用完整文本收答。异步返回、推荐和控件预选不等于真实用户答案；未收齐必需答案时保持当前交互。

questions 每题使用 question、header、multiSelect、options；options 每项包含 label、description。单选 multiSelect=false，多选 true，自由输入使用控件提供的入口。保留问题、选项和 ID 映射；返回为问题到答案文本的映射，不按逗号盲拆多选答案。按当前 schema 的题数和选项数限制分页，不能表达时完整文本收答。



## 成果展示

### Qoder 页面展示方式

以下页面工具仅用于业务成果预览。superun 登录/PAT 授权链接必须按认证用法由 CLI 拉起系统默认浏览器，不使用宿主内置浏览器、WebView 或 `present_files` 打开。

每个阶段产生当前可查看的真实预览时，主动调用页面展示工具，不等待用户另说“打开看看”。使用下方已配置的工具，并遵守本端的正文交付顺序；工具支持链接卡时先交付可点击预览卡，不把它说成自动打开。根据实际动作报告“链接已提供”或“页面已打开”。按以下顺序使用当前可用的能力：
- webview：调用 `mcp_call`，参数结构参考 `{"toolName":"mcp__browser-use__navigate_page","arguments":{"url":"<本轮工具返回的真实业务URL>"}}`，将 URL 槽位替换为当前真实地址。
- link：在对话中提供可点击的真实链接。


先在助手正文展示状态文案和 Markdown 链接，再调用内置浏览器导航；工具失败时说明原因并保留链接，不能只把 URL 放进问答控件。

只使用当前阶段允许展示的真实 URL。工具不可用或打开失败时按顺序降级并说明结果；工具回执只证明其实际完成的展示动作；链接卡回执只证明卡片已交付，浏览器回执才证明已打开，不证明关键功能已验收。不伪造控件，不把抓取网页内容当成已向用户打开页面。

### 正文中的 Markdown 链接

每次交付样式、预览或发布结果，都先在助手正文中写出状态文案和 Markdown 链接，再询问下一步或结束本轮。这里使用 Markdown 的“链接名称 + URL” 的形式，不只写裸地址，不放进反引号。

链接不能只出现在 AskUserQuestion 的 question/description、工具输出或附件中。即使稍后问题里重复提到链接，正文也必须先展示。

文案格式如下；示例地址替换为本轮工具返回的真实 URL：

```markdown
**方案 A 已生成**：[查看方案 A](https://example.invalid/style-a)
**本轮预览已就绪**：[查看预览](https://example.invalid/preview)
**发布已完成**：[访问网站](https://example.invalid/published)
```

- 样式：每个成功候选就绪即在正文展示，保留原编号，再收集样式选择。
- 预览：每轮研发、修改或修复后展示本轮入口；新轮次即使 URL 没变，也重新交付。
- 发布：只有本次发布成功且已公开才使用“发布已完成”；仍部署中、失败或未公开时说明实际状态。多个端逐项写出端名和入口，不能只给默认端。
- 没有本轮有效 URL 时说明缺口，不生成示例地址或用旧结果冒充。提供链接只表示“链接已提供”；用户点击后的浏览器位置由客户端设置决定。

### 在侧边栏打开网页

正文链接展示后，用 browser-use 的 navigate_page 打开同一个真实业务 URL，然后再询问样式选择、功能或下一步。该入口用于内置浏览器，既可导航本地地址，也可导航可访问的云端 HTTPS 地址，不把 localhost 作为使用条件。

通过 MCP 懒加载调用时，首次先用 mcp_list / mcp_get 获取当前工具 schema，再调用：

```json
{
  "toolName": "mcp__browser-use__navigate_page",
  "arguments": { "url": "<本轮工具返回的真实业务URL>" }
}
```

已获取的工具说明直接复用；若当前会话直接暴露导航工具，则按其实际名称和 schema 调用。不要把 MCP 包装参数传给直接导航工具。

- 导航成功后说明实际结果；需要检查页面内容时可调用 take_snapshot 或 take_screenshot，截图不是导航或正文链接的前置条件。
- 工具缺失、导航失败、页面不可见或加载异常时说明具体情况，保留正文链接，不把请求已发送当成页面已打开。
- 返回网络或权限限制时停止该导航，不通过代理、本地包装页或其他方式绕过限制。
- 多个候选或多个端的正文链接完整保留，不因侧边栏当前只展示一个页面而省略其余入口。
- 此处仅用于样式、预览与已发布页面；CLI 登录/PAT 授权链接仍由 CLI 使用系统浏览器处理。

本地文件确认存在后用绝对路径 Markdown 链接交付。



## 后台进程

### Qoder 后台进程

通过 `Bash` 启动长命令；将本次实际命令填入 command、操作说明填入 description，附加参数为 `{"run_in_background":true}`。保存工具返回的原任务标识和输出位置。


结果工具为 `Read`，使用 `{"file_path":"<原输出文件绝对路径>"}`，附加参数为 `{}`。完成通知的 task-id、output-file、status 须匹配原调用。Read 只读取文件，不等待完成；文件存在或部分内容不是终态，不能传 task_id 或 TaskOutput 的 block/timeout 参数。

后台 Bash 返回任务 ID 和输出文件；task-notification 的 task-id、output-file、status 须匹配原调用。收到完成通知后使用 Read(file_path) 读取原输出文件。会话恢复或通知未到时核对原任务结果，不重新提交写命令。

有限时命令收到真实终态后保存 stdout、stderr 和退出状态。持续运行的开发服务器以启动日志和实际页面响应确认就绪，读取状态而不等待退出；交付后保留原进程和句柄供后续使用。未完成或结果不明时保留原句柄，不重新提交写操作；已消费的结果不重复取。命令输出的业务含义由对应模式解释，不能从进程退出成功推断业务验收通过。仅在实际支持的原生能力上续接；普通长命令不另外创建 Agent、定时任务，也不通过 &、nohup 或循环 tail 模拟后台。用户取消后不自动重启；停止本地进程不等于取消远端业务。
