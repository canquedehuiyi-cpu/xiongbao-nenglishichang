# 选择执行模式

在以下情况介绍模式：用户询问收费、反馈消耗高、明确要求切换；或新项目提交样式选择后，superun 已返回待开发功能清单且用户尚未勾选功能。

首次自动提示按项目只进行一次。先展示 superun 的真实清单，再用当前原生提问工具提供两个选项：

- **云端生成（superun-ai）**：由 superun AI 开发，消耗 superun 生成 token。
- **本地开发（sxq-cli）**：由当前客户端开发并通过 sxq 同步，不消耗 superun 生成 token；客户端模型和云资源费用另计。

| 用户决定 | 下一步 |
|---|---|
| 云端生成 | 收集功能选择，按原 interactionId 与 answerSchema 提交 |
| 本地开发 | 保留清单作为需求材料，交 sxq-cli 关联、拉取、启动本地 dev 并展示预览，再回复接管结果；不提交云端功能答案 |
| 已有明确选择 | 复用决定，不重复追问 |
| 未回答、取消或超时 | 不写模式、不切换，也不抢先提交生成请求；用户明确要求按当前模式继续时沿用原模式 |

按 [项目记忆](project-memory.md) 保存明确选择和“样式选择后已介绍执行模式”记录。费用咨询与首次提示重合时只问一次；用户再次主动询问费用时正常解释。模式问题是本地选择，不生成 CLI interactionId 或向云端 reply 提交。

规划仍在生成、只收到命令受理/后台通知或失败时，不触发首次提示。样式选择前用户主动询问或选择本地时可保存意向，但接管须等待实际关联条件满足；不自动调用云端生成补齐条件，也不承诺已发生的费用能撤回。

提问工具见 [宿主工具](host-tools.md)，执行者交接见 [模式切换与恢复](handoff.md)。
