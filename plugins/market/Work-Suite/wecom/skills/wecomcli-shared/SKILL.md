# 企业微信连接与公共检查

本技能随 Qoder 企业微信插件安装。先完成安装与授权检查，再回到用户请求对应的业务技能。仅请求连接时，验证授权成功即完成，不发送消息或创建业务数据。

## 1. 检查运行环境与 CLI

插件的 `bin/` 由 Qoder 加入 Agent Bash 的 PATH。首次执行：

```bash
node --version
wecom-cli-runtime-check
```

- Node.js 缺失或低于 18：提示用户安装 Node.js 18+（包含 npm），重启 Qoder 后再试。
- 运行时存在：执行 `wecom-cli --version`，版本不低于 `1.2.1` 则继续授权检查。
- 运行时缺失或版本低于 `1.2.1`：说明将安装公开版 `@wecom/cli` 到用户目录，然后运行下方安装入口。用户已请求安装、连接或使用企业微信时，按该请求完成必要安装；遵守宿主实际的工具审批要求。

```bash
wecom-cli-install
wecom-cli-runtime-check
wecom-cli --version
```

安装器将 CLI 固定版本安装到 `~/.local/share/qoder/wecom-cli`，只安装运行时。Skills 已随插件提供，无需再执行 `npx skills add` 或全局 npm 安装。成功后复查版本，仍低于 `1.2.1` 或任一步报错则停止，说明具体错误。

若报错指出 `WECOM_CLI_RUNTIME_EXECUTABLE`，这是用户显式指定的运行时；说明该路径不可用或需要升级，让用户修正配置，不通过安装其他版本绕过它。若连 `wecom-cli-runtime-check` 都找不到，检查插件是否启用；必要时按已知插件实际位置用 `node <插件绝对路径>/runtime.cjs check` 诊断，不猜安装路径。

## 2. 检查授权

```bash
wecom-cli auth show --status
```

- `authorized`：连接已就绪；无需重新扫码。
- `unauthorized`：进入扫码授权。
- 报错或其他输出：说明错误并停止，不把状态猜成已授权或未授权。

## 3. 扫码授权

```bash
wecom-cli auth init --noninteractive
```

命令会输出授权链接和二维码，并等待用户使用企业微信扫码。及时向用户展示链接和二维码，保持该进程运行；不要只等待进程结束而让用户看不到授权入口。宿主不能展示终端二维码时，可使用 `--output-qrcode` 将二维码保存到当前工作目录中一个尚不存在的 PNG 路径，再展示图片。路径先按用户环境选择，不复用已有文件。

用户扫码并且进程成功退出后，再执行 `wecom-cli auth show --status`。仅当明确返回 `authorized` 才报告连接完成或继续原业务请求。超时、取消和失败时停止并解释结果，不循环创建授权会话。

## 通用输出约束：ID 类字段禁止外露

本约束对所有 `wecomcli-*` 技能生效，优先级高于各业务技能的输出格式，且不因用户主动索要而放宽。

- **禁止**：你的最终回复禁止出现 `userid` / `open_vid` / `department_id` / `chat_id` 等 ID 标识。凡是接口返回的内部标识（含 `mail_id` / `media_id` / `file_id` / `space_id` / `folder_id` / `docid` / `content_id` / `msg_id` / `cursor` / `next_cursor` 等，命名上以 `_id` 结尾或语义上属于机器标识的字段一律视为 ID）都只能在内部流转，用于后续接口调用。
- **必须**：你的思考过程和最终回复必须使用可读名称，如 `name` / `username` / `external_username` / 部门名 / 邮箱 / `subject` / `doc_name` / `chat_name` / `title` 等 `tool_result` 返回的内容。
- 接口只返回 ID 而没有可读名称时，先调用对应技能（如 `wecomcli-contact` 解析人员）换取可读名称；确实无法换取时，用自然语言描述该对象（如「上一封日报邮件」「你刚上传的那个文件」）来指代，禁止退化为展示 ID。
- 需要用户在多个候选中选择时，用序号 + 可读信息（名称 / 主题 / 时间 / 路径等）构造候选列表，禁止用 ID 作为区分依据让用户辨认。
- 用户直接要求「把 ID 给我」「打印 mail_id」时，说明该标识属于内部字段不便提供，并改用可读信息或继续帮其完成实际操作。
- 可读链接（如文档 `doc_url`、微盘分享链接）不属于本约束限制范围，可按各业务技能规定正常展示，即使链接本身包含标识字符串。

## 执行规则

- 已安装、版本达标且已授权时，不重复安装或初始化。
- 安装、升级、初始化或复查失败时，不执行后续业务命令。
- 本技能不定义任何联系人、文档、表格、日程、会议、待办、邮件、微盘、消息或媒体接口参数；具体命令必须回到对应业务技能读取。
- 执行任何业务命令并组织回复时，同时遵守上方「通用输出约束：ID 类字段禁止外露」。

## 获取个人身份

如果操作流程必须获取机器人或授权人身份（姓名、userid等），需要调用 `wecom-cli identity whoami` 获取。
