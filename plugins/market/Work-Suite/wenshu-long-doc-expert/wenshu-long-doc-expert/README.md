# 文枢（wenshu-long-doc-expert）

> 企业级长文档生成专家 · 4 位专业角色 / 6 段成书流程 / 规范可溯

**花名释义**：「文枢」取「文章枢纽」之意，契合以规范为骨、以长文档为成的核心能力。

由 **1 位总编辑 + 3 位专业成员** 组成的文档工坊，按「定向 → 采撷 → 织辞 → 校雠 → 合卷 → 付梓」六段流程成书，产出施工图设计说明、技术方案、招投标文件、维修手册、API/系统文档等企业级长文档。

---

## 一、角色构成

| 角色            | Agent ID            | 定位    | 拿手的事                     |
| ------------- | ------------------- | ----- | ------------------------ |
| 宗秉衡（Zong，字持钧） | `wenshu-team-lead`  | 总编辑   | 定向、派工、仲裁、合卷、交付           |
| 殷溯典（Yin，字辑古）  | `wenshu-researcher` | 文献检索员 | 采撷规范条文、同类实践、参数区间，产出可引用凭据 |
| 谢敷文（Xie，字摛之）  | `wenshu-drafter`    | 内容生成员 | 把凭据织成正文，控详略、去重、统体例       |
| 邢绳谬（Xing，字纠之） | `wenshu-corrector`  | 质量审核员 | 六则校雠，给出放行/须改结论与必改清单      |

**质量门禁**：每篇必须走完「采撷 → 织辞 → 校雠」闭环，校雠判「须改」即退回重写（最多退回两轮，第三轮强制放行并加「校勘未竟」标注）。

---

## 二、适用场景

- 建筑装饰：装修施工图设计说明、方案设计说明
- 工程与 IT：技术方案、API 文档、系统运维手册
- 招投标：投标文件、技术规格书
- 通用：需求规格说明书、标准化作业程序（SOP）

**不适用**：营销文案、创意脚本、纯代码实现等轻量内容。

## 三、推荐提问方式

| 场景     | 提示语                   |
| ------ | --------------------- |
| 新建文档   | 帮我生成一份装修施工图设计说明       |
| 基于规范撰写 | 基于行业规范写一份技术方案         |
| 独立审核   | 帮我审一下这篇文档的规范符合性与跨篇一致性 |

**建议在首轮补充**：文档用途、篇幅要求、行业领域、需遵循的具体规范、已有模板或参考资料。这会显著提升首稿可用度。

## 七、设计说明

本插件由项丰开发，主要构成如下：

- **流程**：「定向 → 采撷 → 织辞 → 校雠 → 合卷 → 付梓」六段，参考传统编纂工序设计
- **角色**：四位成员命名取自典籍——宗秉衡（秉钧持衡）、殷溯典（溯流穷源）、谢敷文（铺采摛文）、邢绳谬（绳愆纠谬）
- **审核维度**：义理一贯 / 规制合度 / 参量允当 / 义蕴完备 / 体例齐整 / 跨篇呼应
- **视觉**：深海军蓝底 + 金色主体，512x512 透明底 PNG
- **依赖**：仅使用平台内置工具，无外部服务
