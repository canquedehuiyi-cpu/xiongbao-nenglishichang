# 资产清单与交付状态

## 资产清单

跨物料生产开始前建立资产清单，每行一个可独立交付的资产：

| 字段 | 要求 |
| --- | --- |
| `asset_id` | 项目内唯一且稳定 |
| 名称 | 面向用户的资产名称 |
| 分类 | character、scene、prop、ui、animation、vfx 或 promo |
| 用途 | 出现的玩法、界面或宣传位置 |
| 实际像素尺寸 | 最终宽高；未知时写「待确认」 |
| 格式 | PNG、JPEG、GIF、MP4 或 JSON |
| 透明要求 | 是否需要 Alpha |
| 优先级 | P0、P1 或 P2 |
| 状态 | draft、reviewed、engine-tested 或 final |
| 版本 | 从 v1 递增，旧版保留 |
| 阻塞项 | 缺失时受影响的体验或交付 |
| 派生来源 | 使用的锚点和源资产相对路径 |
| 人工工作 | 待人工处理和确认的事项 |

## 优先级

- **P0**：缺失会阻塞核心体验或当前验收目标。
- **P1**：缺失不阻塞运行，但明显影响产品完整性。
- **P2**：装饰、扩展或宣传加分项。

先完成 P0 清单和少量基准资产。风格、角色或 UI 锚点未确认时，不批量展开 P1/P2。

## 状态

- **draft**：已经生成或处理，尚未通过完整文件检查和人工视觉复核。
- **reviewed**：文件检查通过，且人工确认内容、风格和完整性符合当前需求。
- **engine-tested**：在明确的引擎、版本、导入设置和目标环境中完成验证。
- **final**：精修、内容合规与工程验证全部完成。

自动工具只能输出检查证据，不能独立把资产升级到 `reviewed`。MeituHub 生产与本地自动流程不得设置 `engine-tested` 或 `final`。

## 证据

状态变化需要保留对应证据：

- `draft → reviewed`：检查报告、人工视觉复核结果、锚点与规格确认。
- `reviewed → engine-tested`：引擎名称和版本、导入设置、目标平台与实机验证结果。
- `engine-tested → final`：精修、内容合规、版本冻结和最终交付确认。

## 动画交付

角色动画使用 `${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/scripts/asset_tool.py` 生成规则图集、动画 JSON、预览 GIF 和交叉校验报告。自动检查只覆盖文件结构、像素、帧序、时长与锚点；角色身份、姿态、手型、动作合理性和风格一致性仍需人工视觉复核。
