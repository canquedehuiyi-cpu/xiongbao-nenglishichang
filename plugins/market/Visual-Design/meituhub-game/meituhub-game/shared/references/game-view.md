# 游戏视角原则

游戏素材不是插画。同一张图放在画廊里好看，放进引擎里可能不可用。生成前先回答三个问题：它在游戏里怎么出现、占多少屏幕、被谁挡住。

## 一、镜头由玩法决定，不由画面好看决定

| 玩法 | 镜头 | 画幅 | 后果 |
| --- | --- | --- | --- |
| 横版动作、平台跳跃、跑酷 | 正侧视、平视或轻微俯视 | 16:9 | 角色只能左右移动，场景要横向延展 |
| 等距经营、SLG、暗黑类 | 45 度等距俯视、正交 | 1:1 或 4:3 | 建筑与地块必须落在网格上 |
| 俯视射击、战棋、沙盒 | 正俯视、正交 | 1:1 | 只看到顶面，垂直面几乎不可见 |
| 竖版手游、卡牌、休闲 | 竖构图 | 9:16 | 上下要留 UI 区，主体居中偏上 |

镜头一旦确定，整批素材不允许换。俯角差 10 度，两张场景就拼不到一起。

## 二、按实机像素评审，不按原图评审

- 出图是高分辨率，但评审要缩到**游戏内实际显示尺寸**再看一遍。角色在实际屏幕上是 64px 高，就在 64px 下看它的表情还在不在。
- 缩到实际尺寸后糊掉的细节，属于无效细节，不要为此加预算。
- 同一批素材至少抽出三张，缩到实机尺寸横向对比，看是否像同一套。

## 三、分层是为引擎服务的，不是为好看

- 背景按远 / 中 / 近分层，是为了做视差与遮挡，不是为了方便修改。
- **可通行区域不能被前景层盖住**，否则玩家看不见自己站的位置。
- 分层图之间的元素不能重复：同一栋建筑不能同时出现在远景和中景。
- 每层单独输出、背景纯色或透明，方便引擎叠加。

## 四、给 UI 留位

- 场景构图先扣掉 HUD 区：常见的上 10–15% 与下 10–15% 不放关键信息。
- 竖版项目上 1/4、下 1/5 默认视为 UI 安全区。
- 关键视觉元素（宝箱、入口、Boss）不要压在安全区边缘，会被按钮盖住。

## 五、网格与对齐

- 等距与俯视项目必须先定网格：单格边长按项目逻辑像素（常见 16 / 32 / 48 / 64），整批素材按同一网格出。
- 瓦片与建筑要能落在格子上，边缘对齐；接缝仍需人工修，但错位属于返工。
- 同一场景的所有单体共用同一地平线高度与光源方向。

## 六、道具按游戏内尺寸出，不按原画尺寸出

- 先定它在游戏里的显示尺寸，再决定出图尺寸。图标化的道具与场景里的大件，是两种不同的素材，不能一张图两用。
- 道具要有明确锚点：拾取点、握持点、落地接触点，交付时说明。
- 同一批道具共用同一视角与光位，混排时才不跳。

## 评审三问

1. 这张图在游戏里出现在哪、多大？
2. 缩到实际尺寸后，要传达的信息还在吗？
3. 它和同批素材能拼在一起吗？

三问答不上来，就不要进入量产。
