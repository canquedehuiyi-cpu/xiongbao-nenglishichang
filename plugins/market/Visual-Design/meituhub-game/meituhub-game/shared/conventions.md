# 规格约定

本文件是全部 game-* skill 的规格基准。各 skill 的 SKILL.md 内联关键值，完整版本在此；两者不一致时以本文件为准。

资产清单字段、P0/P1/P2 优先级和 `draft / reviewed / engine-tested / final` 状态统一见 `references/asset-delivery.md`，其他文件不得另建一套定义。

## CLI 入口（唯一写法）

唯一接入为包内 `skills/meitu-ai-game/SKILL.md` 的操作系统启动器。下方 meitu 是启动器简写，不是全局 CLI：

```bash
meitu <command> <arguments> --json --download-dir ./output
```

- 首次按接入技能检查配置、运行时和真实会话；未登录按 `meitu-ai-game` 的流程授权。
- 登录失效、余额不足、错误码、充值链接，一律沿用 `meitu-ai-game` 的规则，不在 game-* 里重复实现。
- 执行前必须用 `<command> --help` 确认当前版本参数。

## 输出目录与命名

- 产物统一落 `./output/game/<物料单元>/`。
- 文件名：`<单元>_<类型>_<视角>_<风格>_v1`，多版本递增。
- 每个物料单元一个目录，不混放。

## 画幅与尺寸

| 物料类型 | 画幅 | 尺寸 | 备注 |
| --- | --- | --- | --- |
| 风格锚点 / 气氛图 | 16:9 或 3:4 | 2K | 单张，不分层 |
| 角色设定卡 | 3:4 | 2K | 正面全身、A-pose、纯色背景 |
| 角色三视图 | 3:1（1×3 宫格） | 2K | 正 / 侧 / 背，拆成单张 |
| 角色立绘 | 3:4 | 2K | 半身或全身，纯色背景 |
| 角色表情组 | 1:1（2×3 宫格） | 2K | 六表情 |
| 4 方向转面 | 1:1（2×2 宫格） | 2K | 拆分后剔除多余格 |
| 8 方向转面 | 1:1（3×3 宫格） | 2K | 中心格留空或放正面 |
| 道具单体 | 1:1 | 2K | 白底，再抠图 |
| 场景概念图 | 16:9 或 1:1 | 2K | 按视角定 |
| 分层背景 | 16:9 | 2K | 远/中/近三层分别生成 |
| 地图与瓦片表 | 1:1（4×4 宫格） | 2K | 每格一个地块 |
| UI 图标 | 1:1 | 1K | 单个出，不塞宫格 |
| UI 按钮 / 面板 | 3:1 或 1:1 | 2K | 预留文字区 |
| UI 套装 | 1:1（2×3 / 3×3） | 2K | 按钮四态用 2×2 |
| 卡牌插画 | 3:4 | 2K | 下方预留文字区 |
| 卡牌成卡 | 3:4 | 2K | 文字原样保留 |
| 动画序列帧 | 等分网格 | 按单帧尺寸拼装 | 帧数由全帧筛选结果决定，格子需容纳腾空与武器范围 |
| 技能特效序列帧 | 3:2（2×3 宫格） | 2K | 无角色 |
| 海报 / 商店封面 | 2:3 或按商店要求 | 2K | 多尺寸各出一版 |
| 宣传视频 | 16:9 | — | 时长按需求 |

`--ratio` 的取值不会被严格校验：传入列表外的比例（如 7:5）仍会出图且不报错。生成前自行确认比例属于目标平台规格，不要依赖 CLI 拦截。

## 锚点规则

- **风格锚点**：客户有可用素材就直接用，不另生成；没有才生成一张并确认。同一项目只用一个。
- **角色锚点**：凡同一角色出多张图，必先出正面全身设定卡并确认，之后作唯一参考。
- 同一项目内不换锚点；换风格或换角色时重新生成，并明确告知旧素材不再匹配。
- `text-to-image` 的 `--image_list` 与 `--ratio` 互斥：既要锁画幅又要参考锚点时，必须走 `image-edit`。

## 动作命名（与 animation-breakdown 一致）

- 行走四姿态：Contact（接触）、Down（下沉）、Passing（过渡）、Up（上升）。
- 帧数：先解码全部视频帧，再按动作阶段、姿态信息增量和时间节奏自适应选择；动作目录中的范围只用于规划与成本估算，不是硬约束。
- 帧时长分阶段：预备 120–200 ms、动作 30–60 ms、跟随 80–150 ms、回待机 60–100 ms。

## 验收格式

每个 skill 的验收清单用 checkbox 列表，末尾统一附这三条通用项：

- [ ] 产物落在 `./output/game/<物料单元>/`，命名符合约定
- [ ] 与项目锚点一致，未擅自换风格或换角色
- [ ] 已说明哪些环节需人工二次处理

## 能力边界（统一表述，各 skill 只写与本模块相关的部分）

- **3D 相关不做**：不产出 `.fbx` / `.obj` / `.gltf` / `.blend`，不做建模、UV、PBR 材质、骨骼绑定。「等距 2.5D」「低多边形」「体素」「黏土」都是 2D 画面观感。
- **真 inpainting 不做**：没有 mask 与局部重绘参数，`image-edit` 改局部也会重绘整图。
- **原生低分辨率像素画布不做**：不输出 16/32/64 像素画布，不锁色板；输出高分辨率图，需美术降采样与修边。
- **无缝平铺不保证**：只能生成并扩图，接缝需人工校验。
- **引擎工程文件不输出**：角色动画的规则图集、预览 GIF、JSON 与锚点对齐由 `game-character/scripts/asset_tool.py` 完成；不输出引擎项目、状态机或导入配置。
- **非游戏物料不承接**：电商、通用营销、真人写真、投放素材交给 `meitu-ai-game`。
- **不暴露底层模型**：普通交付不堆砌模型或供应商信息；用户询问技术来源时按实际调用如实说明，未知则说明未知，不编造路由。
