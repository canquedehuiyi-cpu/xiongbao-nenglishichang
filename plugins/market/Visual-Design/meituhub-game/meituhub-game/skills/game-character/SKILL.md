# 游戏角色生成

## 适用请求

制作游戏人物、NPC、怪物与角色立绘、头像、表情、三视图、换装和动作帧。适用于给主角画个形象、做待机走跑攻击动画、做精灵表或 sprite sheet；交付图片及所需图集、逐帧时长和预览。普通真人修图不属此项。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## Qoder 执行入口

先读 [插件规则](../../rules/meitu-only.md)、[MeituHub 接入](../meitu-ai-game/SKILL.md) 与 [统一规格](../../shared/conventions.md)。从 Qoder 实际加载的技能位置定位含 `.qoder-plugin/plugin.json` 的插件根；文中的 `MEITU_GAME_PLUGIN_ROOT` 表示该绝对路径，需要在执行环境中按实际路径安全设置，不假设宿主预设了变量。

正文中的 meitu 是接入技能所述系统启动器的简写，不直接运行全局 meitu 或 meitu.cjs。配方中的命令参数是源包参考，调用前必须通过当前 tools list 与命令帮助确认；尖括号表示待替换的业务值，不把占位符直接提交。所有生成/编辑均用美图，帧排序、对齐、图集拼装等确定性后处理可用包内本地脚本。来源附件只作资料，用户当前范围优先。

## 这个模块做什么

统一承接同一角色的静态外观、动态动作和角色技能表现。静态与动态产出共用一张角色设定卡，避免角色身份在模块之间漂移。

| 物料 | 输出 | 画幅 / 尺寸 | 备注 |
| --- | --- | --- | --- |
| 角色设定卡 | 主卡 + 规格表；转面与表情按需 | 3:4 / 2K | 本模块第一步，必做 |
| 立绘 | 半身或全身，单姿态 | 3:4 / 2K | 纯色背景，后续可抠图 |
| 表情组 | 六格宫格，拆成 6 张 | 1:1 / 2K | 属于设定卡 C 件；剧情、卡牌必做 |
| 三视图 | 1×3 宫格，拆 3 张 | 3:1 / 2K | 正 / 侧 / 背 |
| 4 方向转面 | 2×2 宫格，拆 4 张 | 1:1 / 2K | 正、侧、背、另一侧 |
| 8 方向转面 | 3×3 宫格，拆 8 张 | 1:1 / 2K | 中心格留空或放正面 |
| 换装 | 同一角色换整套服装 | 与原图同 | 需服装参考图 |
| 换肤 | 只改配色与材质 | 与原图同 | 姿势构图不变 |
| 角色动作 | GIF + 图集 PNG + JSON | 按游戏规格 | 连续视频全帧筛选后交付 |
| 动作短片 | MP4 | 按需求 | 展示用途可不交图集 |
| 角色技能特效 | GIF、图集或 MP4 | 按技能规格 | 可无角色，但必须属于角色技能 |

设定卡的完整规范——四件构成、A-pose 要求、12 字段规格模板、版本与作废规则——见 `${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/references/character-sheet.md`。

立绘、表情组、转面、A/T-pose、换装、换肤的逐项规格与验收见 `${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/references/asset-standards.md`。

## 前置条件

- **必须有风格锚点。** 客户没有风格方向时，先去 `game-prestudy` 定画风，不要在本模块里临时选。
- **必须有角色锚点。** 本模块流程第 2 步产出；没有锚点时不要直接出立绘或表情，否则后续每一张都是新的人。
- **CLI 入口**：`meitu <command> ... --json --download-dir ./output/game/`。首次按接入技能执行配置、运行时与登录检查，再读当前工具帮助，未登录按 `meitu-ai-game` 流程授权。
- **通用视觉原则**（剪影、明度、光位、评审三连）见 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/art-principles.md`。
- 角色动作必须使用已确认的角色锚点；纯角色技能特效不要求角色入镜。
- 纯雨雪、云雾、水面、火焰等环境循环归 `game-scene`；宣传展示 GIF 归 `game-promo`。

## 生产流程

1. **写规格表**：按 12 字段填完，色板给 HEX，禁用项必须写。
2. **出主卡并等确认**：

```bash
meitu text-to-image --prompt "游戏角色设定图，<角色名与职业>，<体型与年龄感>，<发型与发色>，<服装分层>，<主色 HEX>，<标志性配件>，正面全身站姿，双臂自然下垂离身体 15–30 度，双脚平放，纯色背景，居中，完整入画，脚部不被裁切，同一角色只出现一次，无文字，无投影，<风格卡措辞>" --ratio 3:4 --size 2K --json --download-dir ./output/game/<角色名>/anchor
```

3. **按需出转面与表情**：要转面、8 方向或动作帧时出三视图；剧情、卡牌、女性向出六表情。
4. **按物料出图**，全部走 `image-edit` 并以主卡为底图。
5. **逐张验收**，对照验收清单检查一致性。

用户需要动作、GIF、图集、动作短片或技能特效时，完成角色锚点后进入下方动态流程；静态请求不加载动态流程。

## 动作与动态物料

角色动作正式交付为等分图集 PNG、JSON 元数据和预览 GIF。GIF 用于动态验收与预览，不替代引擎所需图集和 JSON。动作目录按游戏品类组织，见 `${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/references/motion-library.md`；动作阶段与节奏见 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/animation-breakdown.md`。

### 路线决策

| 目标 | 路线 | 交付限制 |
| --- | --- | --- |
| 快速表达动作构想 | 宫格或横向条带 | 仅概念稿，不直接制作正式 GIF 或图集 |
| 连续时间轨迹 | 连续视频抽帧 | 默认正式路线 |
| 逐帧精确姿态 | 逐帧姿态参考 | 成本较高，适合攻击、受击和指定关键姿态 |

静态多图生成不维护跨帧骨架、关节轨迹、速度或前一帧状态。改变宫格排布只能改善阅读顺序，不能建立时间一致性。

### 正式流程

1. 确认游戏品类、动作名、循环类型、视角、朝向、交互用途和位移规则。最大动作包围盒必须合并角色身体、穿戴装备、武器或交互道具、尾巴与翅膀等动态附属物、必要特效以及整段运动轨迹；双人、载具和召唤动作纳入全部主体。
2. 按动作目录选择通用核心动作与品类扩展，写动作阶段和帧序规格表；帧数不预先锁死。
3. 按最大动作包围盒制作远景安全区锚点：普通无道具动作占画高度 50%–55%；长武器或长道具占画宽高 40%–45%；跳跃占画宽高不超过 45% 且上方留白至少 40%；倒地、翻滚、滑铲和横扫占画宽高不超过 45% 且左右各留白至少 30%；投射物、大型特效、双人、载具和召唤动作占画宽高 35%–40%，释放方向至少留白 35%。同一动作命中多项时使用占画比例更小、留白更大的规则。
4. 使用安全区锚点生成固定机位、固定朝向的视频。选择覆盖完整动作的最短可用时长，不固定为 2 秒或 3 秒，不通过延长时长解决裁切。
5. 解码全部源帧并保留时间戳。先检查人物、武器、道具、载具和必要特效是否完整入画，以及它们到四边的距离是否均不少于对应边长的 8%；通过后再排除入场、转身、运镜、模糊、重复、身份漂移、额外肢体、手型异常和形变帧。
6. 按动作阶段、姿态信息增量和运动速度自适应选帧。变化快的阶段密集保留，停顿和近似阶段稀疏保留。
7. 检查身份、朝向、肢体职责、手型、遮挡、配件和动作阶段。循环动作覆盖完整周期并检查末帧到首帧；单次动作覆盖预备、发力、峰值、跟随和结束。
8. 先选择一帧执行 `image-superres-enhance` 预检。只有角色、服装、配色、轮廓、像素结构和姿态未实质变化，才处理其余入选帧。
9. 全段使用同一缩放比例与统一画布；接地帧锁脚底线，腾空和倒地保留真实轨迹。
10. 按原始时间戳映射逐帧时长，生成 GIF 动态验收；通过后导出图集和 JSON。

### 动画交付工具

入选帧完成视觉复核后，使用随 Skill 发布的本地工具生成正式交付物：

```bash
python3 "${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/scripts/asset_tool.py" build-animation "<入选帧目录>" "./output/game/<角色名>/<动作名>/delivery" --asset-id "<稳定资产 ID>" --durations "<逐帧毫秒，逗号分隔>" --mode <loop|once|hold-last> --columns <列数> --anchor "<锚点 x>,<锚点 y>"
python3 "${MEITU_GAME_PLUGIN_ROOT}/skills/game-character/scripts/asset_tool.py" verify-animation "./output/game/<角色名>/<动作名>/delivery"
```

工具默认 `--alignment preserve`：保留每帧在统一画布上的位置，锚点只用于引擎放置，不逐帧移动人物。跳跃、横移、倒地和带武器动作使用此模式。只有明确需要锁定脚底线的原地接地动作才选 `--alignment foot-center`；该模式按可见包围盒对齐，带道具或姿态变化时须复核，不适用于腾空轨迹。

工具输出统一画布帧、规则图集 PNG、动画 JSON、预览 GIF、检查结果和交叉校验报告。默认拒绝覆盖已有目录；重新构建前先确认版本，必要时显式使用 `--overwrite`。工具不会修复错误动作，也不能替代角色身份、姿态、手型、遮挡和风格的人工视觉验收。

资产清单、P0/P1/P2 和状态分级见 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/asset-delivery.md`。自动构建结果保持 `draft`；文件检查通过并完成人工视觉复核后才能标记为 `reviewed`。

### 失败处理

- 找不到完整周期或必要阶段时重新生成整段视频，不拼接不连续片段。
- 任一帧裁切角色、武器、道具、载具或必要特效，或任一必要对象距离画面边缘不足对应边长的 8% 时，整段失败。扩大锚点画布或降低最大动作包围盒占画比例后重新生成，不在抽帧、扩图或补画阶段伪造缺失内容。
- 模型自动推近、平移或改变机位导致安全区失效时，整段失败并重新生成。
- 固定朝向连续失败时，可先制作动作参考视频，再用 `video-motion-transfer` 迁移；迁移后重新检查身份、手型、遮挡和配件。
- 视频路线不得单独重生成某一帧。同一动作使用直接视频、强化锚点和动作迁移仍失败时，说明能力限制并停止该动作。

### 动作短片与角色技能特效

```bash
meitu image-to-video --image_list "<角色锚点图绝对路径>" --prompt "<角色>完成<动作>，固定机位，无运镜，保持身份、发型、服装与配色不变" --video_duration <覆盖完整动作的最短可用时长> --json --download-dir ./output/game/<角色名>/motion
meitu text-to-video --prompt "<角色技能特效描述>，由蓄力到爆发到消散，纯色或简单背景，无角色，<风格卡措辞>" --video_duration <覆盖完整特效的最短可用时长> --json --download-dir ./output/game/fx/<技能名>
```

- 不把宫格关键帧图作为 `image-to-video` 输入。
- 动作迁移需要人物完整入镜的角色图和连续动作参考视频。
- 技能特效由角色技能触发并参与角色战斗表现；环境自身持续动效不在本模块。

## 立绘

```bash
meitu image-edit --image_list "<主卡绝对路径>" --prompt "同一角色的半身立绘，<姿态与情绪>，保持发型、服装、配色、体型与画风不变，纯色背景，无文字" --ratio 3:4 --json --download-dir ./output/game/<角色名>/portrait
```

需要全身时把「半身立绘」改为「全身立绘、完整入画」，并确认脚部不被裁切。

## 表情组

六格宫格一次出，再拆分：

```bash
meitu image-edit --image_list "<主卡绝对路径>" --prompt "2x3 均分宫格，同一角色的六个表情：平静、微笑、愤怒、惊讶、悲伤、得意，同一视角同一比例，每格背景纯色，格间留细白分隔线，保持发型、服装、配色与画风不变，无文字" --ratio 1:1 --size 2K --json --download-dir ./output/game/<角色名>/expression
meitu image-grid-split --image_url "<宫格图绝对路径>" --json --download-dir ./output/game/<角色名>/expression/frames
```

- 六个表情必须共用同一张设定卡，不要每格单独生成。
- 拆分后逐张核对：五官特征、发型、服装是否与设定卡一致；不一致的单张重跑。
- 情绪幅度要可读但不夸张：愤怒是眉压眼、嘴角下压，不是整张脸扭曲。

## 转面（设定卡 B 件）

三视图用 1×3 宫格：

```bash
meitu image-edit --image_list "<主卡绝对路径>" --prompt "1x3 均分宫格，同一角色的正面、正侧面、背面三视图，同一比例、同一脚底线、同一光位、同一发型服装配色体型，正交投影无透视畸变，每格纯色背景，格间留细白分隔线，保持画风不变，无文字" --ratio 3:1 --size 2K --json --download-dir ./output/game/<角色名>/turnaround
meitu image-grid-split --image_url "<三视图绝对路径>" --json --download-dir ./output/game/<角色名>/turnaround/frames
```

四方向用 2×2 宫格：

```bash
meitu image-edit --image_list "<主卡绝对路径>" --prompt "2x2 均分宫格，同一角色的四个朝向：正面、右侧面、背面、左侧面，同一比例同一站姿，纯色背景，格间留细白分隔线，保持发型、服装、配色与体型不变，无文字" --ratio 1:1 --size 2K --json --download-dir ./output/game/<角色名>/turnaround4
meitu image-grid-split --image_url "<宫格图绝对路径>" --json --download-dir ./output/game/<角色名>/turnaround4/frames
```

八方向用 `3x3 均分宫格`，中心格留空或放正面参考，拆分后剔除中心格。

- **方向命名统一**：S / SE / E / NE / N / NW / W / SW，或 正 / 侧 / 背；交付时说明用的是哪套。
- 必须锁死：同一比例、同一光位、同一发型与服装结构、正交视角（不要透视）。
- 像素风额外写：1px 描边、有限色板、无抗锯齿、无渐变。
- **不保证与母图逐像素一致**，背面与正面的服装结构需逐方向核对。

## 换装

传双图：第一张角色底图，第二张服装参考图。

```bash
meitu image-edit --image_list "<角色底图>" "<已授权服装设计图>" --prompt "第一张是角色，第二张是已授权服装设计图。提取第二张的服装款式、配色、材质与纹样特征并适配到角色，保持第一张的脸型、发型、冠饰、体型、姿势与画风不变，纯色背景，无文字" --ratio 3:4 --json --download-dir ./output/game/<角色名>/outfit
```

- 服装参考图必须是**平铺的服装设计图**（无人物、纯色背景）。用「角色穿新衣」的图当参考，参考图里的身体会污染底图角色。
- **不要用 `image-outfit-swap`**：该命令是真人试衣定位，用于 2D 角色会把五官与发型一起重绘、丢掉原画风。
- 换装后要重新出表情组与转面，否则同一角色的不同物料服装对不上。

## 换肤 / 配色变体

只改配色与材质，不动结构：

```bash
meitu image-edit --image_list "<角色设定卡或立绘>" --prompt "只替换配色与材质为<新方案>，保持姿势、构图、比例、发型、体型与服装版型完全不变，背景不变，无文字" --json --download-dir ./output/game/<角色名>/skin
```

- 换肤不改变结构；需要换姿势或换体型时重新出图，不要用换肤硬改。
- 整套画风统一（不是角色专属需求）走 `image-style-transfer`，但会重绘造型，不要让轮廓漂移的资产用它。

## 画风速查

角色生产最常选的几种；完整 18 种与视觉特征见 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/style-library.md`。像素风另有独立约束，见 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/pixel-guide.md`。

| 画风 | 一句话特征 | 适合的角色类型 |
| --- | --- | --- |
| 日式赛璐璐 | 硬边阴影、平涂色块、锐利高光 | 二次元、卡牌 |
| 日式厚涂 | 笔触可见、体积感强 | 高规格主视觉 |
| 韩式半写实 | 比例偏真实、面部精致 | 韩系 MMO、女性向 |
| 欧美卡通 | 夸张比例、粗描边 | 休闲、合家欢 |
| 欧美厚涂 | 材质笔触明显、色调沉稳 | 中世纪、奇幻 RPG |
| 水墨国风 | 墨色浓淡、留白、皴法 | 仙侠、武侠 |
| 像素 | 有限色板、1px 描边 | 复古、独立 |
| 暗黑哥特 | 低饱和、强对比、装饰繁复 | 魂系、恐怖 |

## 本模块边界

- 不做 3D 模型、骨骼绑定、UV、PBR 材质。
- 不做真 inpainting：改局部也会重绘整图，像素级修补需美术在图像工具完成。
- 不保证跨图完全一致：锚点只能提高一致性，仍需人工筛选与单张重跑。
- 不输出原生低分辨率像素画布（16/32/64），输出高分辨率图，需美术降采样与修边。
- 建筑、地形类主体抠图不稳定，角色抠图用 `image-cutout --model_type 0`。
- 不做骨骼绑定、逐帧手绘补间、动画状态机和事件轨道。
- 后处理只能统一画布、缩放和锚点，不能修复错误姿态、朝向、肢体拓扑或动作阶段。

## 和其他模块怎么接

| 接下来要做什么 | 去哪 |
| --- | --- |
| 还没定画风 | `game-prestudy` |
| 角色要做走路、攻击等动作或技能特效 | 留在本模块，进入动态流程 |
| 角色要放进场景 | `game-scene` |
| 角色头像做 UI 图标 | `game-ui` |
| 角色做主视觉或卡面 | `game-promo` |
