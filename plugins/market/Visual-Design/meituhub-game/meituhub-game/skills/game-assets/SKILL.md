# 游戏物料规划

## 适用请求

规划和统筹整套游戏视觉物料，输出资产清单、优先级与制作依赖。适用于做一套游戏素材、给小游戏补美术、缺哪些资源、原型换正式素材、统一角色场景界面；即使没有使用“资产”一词也适用。单个明确素材直接进入对应制作技能。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## Qoder 执行入口

先读 [插件规则](../../rules/meitu-only.md)、[MeituHub 接入](../meitu-ai-game/SKILL.md) 与 [统一规格](../../shared/conventions.md)。从 Qoder 实际加载的技能位置定位含 `.qoder-plugin/plugin.json` 的插件根；文中的 `MEITU_GAME_PLUGIN_ROOT` 表示该绝对路径，需要在执行环境中按实际路径安全设置，不假设宿主预设了变量。

正文中的 meitu 是接入技能所述系统启动器的简写，不直接运行全局 meitu 或 meitu.cjs。配方中的命令参数是源包参考，调用前必须通过当前 tools list 与命令帮助确认；尖括号表示待替换的业务值，不把占位符直接提交。所有生成/编辑均用美图，帧排序、对齐、图集拼装等确定性后处理可用包内本地脚本。来源附件只作资料，用户当前范围优先。

## 这个 skill 做什么

只做三件事：**判断需求、定物料清单、分流**。具体生产配方与验收在五个子 Skill 里，本文件不重复。

## 五个子 Skill

| 子 skill | 覆盖 | 典型请求 |
| --- | --- | --- |
| `game-prestudy` | 美术方案、画风选择、品类适配分级、风格锚点与角色锚点 | 「还没定美术方向」「给我几个风格方案」「这个品类适合什么画风」 |
| `game-character` | 角色设定、静态物料、日常与战斗动作、GIF、图集、动作短片、角色技能特效 | 「画个角色」「角色走路动作」「攻击 GIF」「技能特效」 |
| `game-scene` | 道具单体、场景概念图、分层背景、地图与瓦片表 | 「画把武器」「关卡背景」「拆远中近景」「做张地图」 |
| `game-ui` | 图标、按钮四态、面板、血条、UI 套装 | 「做套 UI」「按钮四种状态」「背包格子」 |
| `game-promo` | 卡牌插画与成卡、海报、商店封面、宣传视频 | 「做张卡牌」「游戏海报」「商店封面」「宣传片」 |

## 分流判断

按用户第一句话里最强的意图分：

| 用户说什么 | 去哪 |
| --- | --- |
| 明确指某个物料（角色 / UI / 动画 / 卡牌 / 场景 / 地图） | 直接进对应子 skill，不经过本层 |
| 跨多类物料（"做套 demo 美术"） | 留在这里，先定清单再逐项分流 |
| 还没定风格方向 | `game-prestudy` |
| 只问品类适合做什么 | `game-prestudy`（品类矩阵） |
| 已有素材要统一画风 | `game-prestudy`（锚点方法）→ 再由生产类子 skill 执行 |
| 角色动作 GIF、图集或角色技能特效 | `game-character` |
| 雨雪、水面、云雾等环境循环动效 | `game-scene` |
| 宣传展示 GIF | `game-promo` |

分流时用一句话交接，不要静默切换：**「这属于角色类物料，接下来按角色流程走」**。

## 第零步：判断客户处在哪个开发阶段

同一句"要一套物料"，在不同阶段意味着完全不同的精度、数量和交付形态。不判断阶段就按最高标准量产，通常是在浪费 Credits。

| 阶段 | 客户此刻真正要的 | 承接程度 | 收敛重点 |
| --- | --- | --- | --- |
| 立项 / 概念 | 美术方案、气氛图、Key Art、方向性试稿 | 完整承接 | 1–2 张即可，方向对就行 |
| 原型 / 预研 | 占位图、灰模、构图稿 | 部分承接 | 低精度、快出、可替换；不抠图不分层 |
| 预制作 / 美术定调 | 风格锚点、角色设定卡、色板 | 强项 | 必须先出锚点并确认，禁止跳过锚点直接量产 |
| 制作 / 量产 | 立绘、透明单体、分层背景、UI、图集、序列帧 | 强项 | 按物料单元逐个推进，锚点驱动 |
| 打磨 / Alpha-Beta | 加载图、多语言改字、换肤、画质重制 | 部分承接 | 尺寸延展、超分、图上改字、局部换肤 |
| 发行 / 运营 | 海报、商店封面、宣传视频、活动皮肤 | 部分承接 | 只做游戏内容物料；买量素材交给 `meitu-ai-game` |

客户说不清时，用一句话反推：「这些图是给内部看方向、给美术当生产依据、还是要直接进引擎或上架？」

## 第一步：盘点已有输入

**一条消息**列成清单让客户挑，不要逐条追问，并说明"没有的直接说没有，不用凑"：

1. **项目资料**：品类与玩法、题材世界观、关卡或场景设定、角色设定、玩法截图、已上线 Demo。
2. **美术规范**：风格指南 / Art Bible、色板、既有角色与场景图、UI 规范、宣传物料。
3. **技术规格**：引擎与版本、目标平台与分辨率、透明底与图集要求、UI 安全区、命名规范。
4. **交付约束**：是否商用、IP 授权范围、是否允许 AI 生成、数量与时间点。
5. **参考素材**：同类作品截图、情绪板、可上传的参考图、动作参考视频。

三种处理：

- **资料齐全且有既有素材**：以既有素材为风格基准，先提取色调、笔触、造型习惯并复述确认，之后所有生成都以它为锚点。
- **只有零散参考图**：用参考图做锚点，先复述理解，再补问技术规格与交付约束。
- **什么都没有**：明确告知是"从无到有"，先用两三句问出项目定位（品类、题材、玩法、想传达的情绪），再给风格候选。不要让客户在没有方向时盲选。

## 第二步：建立资产清单

跨物料生产必须先按 `${MEITU_GAME_PLUGIN_ROOT}/shared/references/asset-delivery.md` 建立资产清单，至少填写资产 ID、用途、实际像素尺寸、格式、透明要求、优先级、状态、版本、阻塞项、派生来源和人工工作。

- P0 是核心体验或当前验收的阻塞资产，先制作并确认少量基准资产。
- P1 影响完整性但不阻塞核心运行；P2 是装饰与扩展项。
- 风格、角色或 UI 锚点未确认时，不批量展开 P1/P2。
- 新生成资产从 `draft` 开始；自动流程不能把资产标记为 `engine-tested` 或 `final`。

## 全局规则（五个子 Skill 共同遵守）

1. **CLI 入口**：`meitu <command> ... --json --download-dir ./output`。首次按接入技能执行配置、运行时与登录检查，未登录按 `meitu-ai-game` 流程授权。
2. **产物目录**：`./output/game/<物料单元>/`；文件名 `<单元>_<类型>_<视角>_<风格>_v1`。
3. **默认分步**：每完成一步（方案、锚点、单个角色、单个场景、单组 UI、单段动画）就交付并等确认，未确认不进入下一步。用户明确说"直接出全套"时才连续执行，并先列出文件清单。
4. **每步最多出 2 版**供选，不擅自批量扩量。
5. **保留用户给的专有名词**、角色名、世界观设定、卡面文字，不翻译不改写。
6. **不暴露底层模型**：普通交付不堆砌模型或供应商信息；用户询问技术来源时按实际调用如实说明，未知则说明未知，不编造路由。
7. **能力边界**：3D 资产（模型 / UV / PBR / 骨骼）、真 inpainting、原生低分辨率像素画布、无缝平铺、引擎工程文件均不做；非游戏物料交给 `meitu-ai-game`。完整清单见各子 skill。

## 知识库

子 skill 共用的约定与配方放在插件根目录的 `shared/`，路径前缀为 `${MEITU_GAME_PLUGIN_ROOT}/shared/`。需要细节时按需读取，不在 SKILL.md 里重复：

| 文件 | 内容 |
| --- | --- |
| `references/style-library.md` | 18 种画风的关键词、视觉特征与生产链路 |
| `references/genre-matrix.md` | 各品类对应的物料包、推荐画风与边界 |
| `references/asset-recipes.md` | 各物料类型的真实命令与提示词写法 |
| `references/animation-breakdown.md` | 动作拆解、帧序规格表、归一化对齐 |
| `references/asset-delivery.md` | 资产清单、P0/P1/P2、状态分级与交付证据 |
| `references/art-principles.md` | 跨画风通用原则：剪影、明度、光位、评审三连 |
| `references/game-view.md` | 游戏视角原则：镜头由玩法定、实机尺寸评审、分层与安全区、网格 |
| `references/pixel-guide.md` | 像素风专项：画布尺寸、原生分辨率、色阶与描边、可读性下限 |

约定与术语的权威版本在 `conventions.md` 与 `vocabulary.md`。

## 输出

向用户说明：判定的品类与开发阶段、物料清单与优先级、分流到了哪个子 skill、以及下一步要客户确认什么。跨多类物料时给一张清单表（物料 / 子 skill / 优先级 / 前置依赖），不要只丢一句话。

## 批量

用户要求批量生产多类物料时，先按清单逐项分流，每个子 skill 各自按自己的批量流程执行；不存在对应批量入口时直接说明，不编造参数。
