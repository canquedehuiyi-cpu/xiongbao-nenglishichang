# 给可玩的游戏接入爱给素材

从玩家的操作和能看到、听到的反馈入手。已有项目先找运行入口、资源目录和现有事件，沿用其引擎、音频管理和启动方式。新原型按用户给定的平台、操作方式和胜负条件实现。选材需要已授权的爱给 MCP，接入和试玩还需要可写的项目及对应运行环境。

## 按事件选材

1. 列出需要素材的事件与场景，例如进入关卡播放配乐、实际起跳时触发短音效、星星首次拾取时发出提示音、落坑时播放失败音。区分一次性反馈和循环播放。按玩家动作频率判断哪些事件需要独立声音，按角色、道具、背景列出画面需求。
2. 用 `audio-search` 的 `cat=sound` 搜事件音效，用 `cat=music` 搜配乐。例如拾取音可先试 `{"keyword":"像素 拾取 提示音","cat":"sound","pageNumber":1}`。从 `fileList` 核对具体版本的时长和格式，优先选择连续触发也有辨识度的短音，以及适合关卡节奏的配乐。用 `image-search` 的 `imageElement` 搜角色或道具，用 `imageBg` 搜背景，比较分辨率、主体大小、透明信息和像素风格。候选不足时自主调整关键词或分类。
3. 已有结果足够时直接推荐。需要按已知 `itemId` 查询当前信息时才用 `audio-detail` 或 `image-detail`。按文件编号与规格区分同扩展名的不同版本。说明推荐依据来自素材描述、文件规格、小图、实际试听或试玩中的哪一项。
4. 给候选编号，列出对应事件或场景、素材标题、所选 `fileList` 版本及 `fileId`。有 `prevImageList[].prevMiniUrl` 时，在表格外用 Markdown 图片展示真实小图。保留签名与查询串，客户端无法内嵌时提供该预览原链接。缺少小图时注明，未试听的音频用返回的名称、时长和拟用事件供初选。用户说“拾取音短一点，背景音乐留着”时，只重选拾取音。用户只想压低音量时可直接调整项目混音，复用已经保存的文件。

## 获取、接入与试玩

- 游戏制作需求和风格偏好只用于选材。说明所选版本、对应事件、此次用途和适用条件后，由用户明确指定要获取的清单行。试听需要获取所选音频文件，用户确认试听后才用该版本的 `fileId` 调用 `audio-download`。查看较大图片预览时，确认预览记录及尺寸档后，用对应的 `fileId`、`imageSize` 调用 `image-preview-download`。
- 正式接入时，用户可一次点名多项，逐项用所选正式版本的 `fileId` 调用 `audio-download` 或 `image-download`。已保存且获选的同一文件可直接复用。更换版本或适用条件有重要变化时，更新该项清单并重新确认。服务返回表明获取某个文件会改变账号状态时，先说明该文件对账号的具体影响；涉及数值时，列出服务返回的实际数值和单位，用户明确同意该影响后才执行。影响或适用条件未明时，暂停该项并保留已选清单供用户决定。发生异常时只报告受影响条目的操作状态和服务实际返回的 `requestId`，不自动重试。
- 原样使用限时链接，将成功获取的文件保存到项目，运行时从项目文件加载。链接失效后只按用户明确要求重新获取。把图像接到实际角色或关卡，把音效接到状态变化，给背景音乐设置单一播放实例。浏览器原型在玩家首次点击或按键后启动声音。
- 用正常入口试玩，检查操作响应、连续拾取、胜负判定和重开。确认声音在对应动作发生时触发、配乐重开后只播一份、画面无缺图且高频音效不会盖过关键反馈。交付可运行入口、启动与操作说明，以及“事件或场景 → 项目文件 → 素材标题及编号”清单，注明所用版本与使用状态。按具体素材的许可核对用户拟定的用途。
- 若只能选材，交付事件表、候选和接入位置。若已接入但缺少运行环境，交付项目并指出哪些操作尚未试玩。用户暂缓获取的声音或画面标明待补。

## 可复现示例 · 屋顶摘星

> 做一个用浏览器玩的像素跳跃游戏《屋顶摘星》。玩家按空格从一个屋顶跳到下一个，沿途收齐 5 颗星星获胜，掉进屋顶之间的空隙就失败，按 R 可以重开。给起跳、摘星和坠落各选一种声音，配一段轻快音乐。城市天际线背景、角色、星星和所有声音都从爱给选。

先列出七项候选，展示图片缩略图，标明每段声音的用途和试听状态。起跳选短促上扬的声音，拾取音要能和它区分，失败音给重开前留出停顿。背景和星星应有足够对比。确认具体文件并接入后，从开始画面按空格启动，实际跳过一道屋顶间隙、连续摘星，分别走通落坑和集齐五颗星星的结局，重开检查分数归零及音乐单实例播放。交付项目入口和上述事件的素材来源。
