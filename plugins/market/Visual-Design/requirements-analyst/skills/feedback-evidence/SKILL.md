# 反馈证据归组

交付保留来源的证据组及待核实问题，服务后续需求决策。不是会议纪要、客户跟进台账或全市场统计。

## 工作流程

1. 读取指定反馈，沿用已有反馈编号；无编号时为原始片段分配 F01 等局部编号，记录文件/段落、已知角色、版本与时间范围。身份未知保持未知，不从语气猜客户群体。
2. 读取 [证据归组方法](references/evidence-method.md)。逐条区分用户场景、想完成的任务、遇到的障碍、用户提议的方案；保留关键原话，分析解释另行标记。
3. 识别同一原话的转发与重复记录，保留关系，不把同一客户多次追问算成多名用户。只有输入明确且可复算时汇总本批记录数，并说明口径；没有样本基数不计算客户占比。
4. 围绕任务与障碍归组，角色、权限或目标冲突时拆开子组。不同人的同一术语不必然指同一需求，功能名称相似也不强并。
5. 对每组提供证据编号、问题解释、现有约束、替代解释及需要补问的具体问题。无依据的根因保持假设；资料不足不靠多写内容来补齐。
6. 保存证据材料或交付完整正文，保留原始片段与分析之间的引用，方便 requirement-brief 承接。不能把草案自动写入外部工单或向客户发送。

## 验收

抽一组能回到实际原话，抽一条原话能找到归组及未归组理由。清楚说明这是一批指定材料的分析，不代表全部用户。对于冲突与未知记录，交出可执行的下一步补问，不虚构调查结论。
