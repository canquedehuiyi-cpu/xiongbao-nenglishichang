# 需求变化与决定

使用简短记录承接变化：来源/决定人及日期（若提供）、受影响需求、旧行为、新行为、理由、关联验收条件、状态。用户没提供决定人或日期时注明未提供，不编造签字。

## 小例子

旧 R01 讨论“上传 CSV 或粘贴多条”，验收 A03 的部分成功策略未定。新增材料 D01 是用户明确决定：“首版只支持粘贴多条；仅管理员；允许合格条目成功，失败条目逐项返回；不在首版做 CSV。”另有 F05 普通成员再次要求自助添加。

应当交付：

- R01 方案正文改为粘贴多条，CSV 记录为本版不做而非静默删除讨论历史。
- A01 使用已确认输入方式；A02 继续保持管理员权限；A03 明确部分成功及逐条结果。
- F05 加入权限需求证据或待决策清单，但不覆盖 D01，不自动放权。
- 格式细节与容量若未决定继续保留待定；不从“多条”推导固定上限。
- 状态标为“范围按 D01 收敛、实现及排期待确认”；不能写成“功能已发布”。

旧稿丢失时可基于 D01 写当前范围说明，但交付中明确无法验证所有旧验收项是否已同步。
