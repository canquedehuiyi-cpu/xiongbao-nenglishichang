# HTML制作

## 适用请求

把演示资料制作成可翻页、有动效和播放控制的 HTML 幻灯片。适用于网页 PPT、在线课件、浏览器放映、动态汇报、把 PPT 做成 HTML；交付可打开的页面及素材。可点击产品操作原型优先按网页演示场景处理。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**演示对象/用途、内容范围、风格与讲述方式、是否确实需要HTML**。

可按缺口这样问（不是固定问卷）：“这份是你手动讲解，还是发给别人自己阅读？有想参考的视觉风格吗？”

确认大纲和方向后做代表页；反馈后再扩全稿，已明确委托的沿用委托。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-ppt/SKILL.md)，再按本技能执行。所有路径相对当前技能或插件根目录解析。开始前读取输入并确认范围；生成后打开真实结果检查，不能凭任务成功判断质量。只在实际完成时标 completed；缺素材、服务或预览环境时注明 partial/blocked 和影响项。


1. 按 [演示需求确认](../../references/ppt-intake.md) 先落实受众、内容重点、风格和讲述方式；用户要求 PPTX 时不擅自改交 HTML。大纲和方向未明确前只盘点/提建议，不开生成任务。
2. 读 [逐页设计](../../references/ppt-design.md)、[图片处理](../../references/ppt-images.md) 和 [数据展示](../../references/ppt-data.md)。论点与证据先行，图表由真实数据和可修改代码绘制，不用生图代替精确图表。
3. 做封面与代表正文，有数据必须含数据页；图片按内容做美图生成/编辑、抠图或扩图，不只填一张背景。至少接入一张有效核心配图，五页及以上至少两张内容不同的核心配图；用户明确纯数据/局部修改等限制时遵守，不为次数插入无关图。交样稿看反馈，除已有明确跳过或全权委托外，等待后再扩整稿。
4. 文字、图表、标注和控制保持代码对象。按阅读顺序入场，默认手动翻页，提供前后页、方向键、目录、页码。连续播放提供开始/暂停，真实业务操作不自动点击。
5. 实际运行，检查桌面与手机、重进/快切/首末页、键盘焦点、后台恢复、减少动态与打印状态。动态图表不改变数据口径；静态状态仍能读完。
6. 输出 HTML 与本地素材；单文件离线需内嵌依赖并断网验证。只在实际实现并验证时称有 PPTX 导出、可视化编辑或持久保存。画面不加生成标签；实际播放未测就不称动效通过。
