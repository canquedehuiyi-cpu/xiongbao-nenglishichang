# PPT生成

## 适用请求

将资料制作成可编辑 PPTX 演示文稿，含大纲、版式、配图与原生图表。适用于做 PPT、汇报、述职、答辩、路演、产品介绍、培训课件或提案；未说“PPT”但明确要求逐页展示或演示文件也适用。只写讲稿或提纲时按该范围处理。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**演示对象与用途、内容重点和不可更改事实、风格参考及大致时长/页数**。

可按缺口这样问（不是固定问卷）：“这份主要给谁看、希望对方记住什么？现有资料哪些必须讲？视觉更偏克制商务、产品画册，还是数据报告？”

按演示专项流程，先确认内容与方向，再看包含正文和数据的代表页。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-ppt/SKILL.md)，再按本技能执行。所有路径相对当前技能或插件根目录解析。开始前读取输入并确认范围；生成后打开真实结果检查，不能凭任务成功判断质量。只在实际完成时标 completed；缺素材、服务或预览环境时注明 partial/blocked 和影响项。


1. 先读 [演示需求确认](../../references/ppt-intake.md)。读取资料和真实数据，补齐受众、内容重点、风格等关键缺口并等待答案；不能把“做整份 PPT”解释为风格、内容都已委托。
2. 按页整理结论、证据与来源，给出大纲，等内容确认或沿用已有明确大纲/委托。按 [内容组织逻辑](../../references/ppt-story.md) 决定叙事顺序，再提出适合内容的视觉方向；用户没有模板也能从零设计。
3. 必须读 [逐页设计](../../references/ppt-design.md)、[图片处理](../../references/ppt-images.md)、[数据展示](../../references/ppt-data.md) 和 [交付检查](../../references/ppt-delivery.md)。按关系设计构图，不批量套相同卡片。
4. 按逐页图片作用调用 `meituhub-ppt-visuals`，使用本次实际美图结果。需要抠图、扩图、参考编辑或超清时执行相应处理；至少一张有效核心素材进入代表页，后续按内容需要继续处理全部槽位，不把“一张图”当全稿完成标准。数据页优先原生图表，不加无关装饰。
5. 用真实内容做 2–3 张代表页，必须含正文，有数据时含原生数据图表页，不能只有封面/目录/章节。自检实际 PPTX 后给用户看，反馈未到不扩全稿；明确委托直接完成或跳过样稿时沿用授权，但仍内部检查代表页。
6. 按确认结果完成整稿。标题、正文、标签、表格、流程、数据图表保持原生；图表附可核对工作簿。真实产品、人物、数据不凭空补造。复杂材质仅局部图片化。
7. 保存实际 PPTX，运行可用的内容/图片/数据/排版检查，并检查真实渲染及编辑性。修复后复查受影响页，交付文件和必要预览。成品不添加生成标签；内部素材记录无需逐条讲给用户。

## 完成条件
内容、图片与数据均服务于本页结论；素材确实进入成品；数值口径、工作簿和图表一致；无漏页、乱码、遮挡、拉伸或关键主体误裁。没有目标软件时明确文件显示/编辑仍待验证，不能声称仅凭脚本已通过视觉验收。
