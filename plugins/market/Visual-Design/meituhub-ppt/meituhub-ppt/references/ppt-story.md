# 从内容到页面的逻辑

先理解观众需要作出的判断，再组织材料。先有论点和证据，后有图片、图表和构图；页数与风格为内容服务。

## 1. 整份稿要解决哪一个问题

从已确认的受众和用途，写一句内部目标：谁看完以后，应理解什么、认可什么或能完成什么。目标不一定是销售，也可能是解释研究、复盘结果或教会操作。不能从文件名猜用户想说服谁。

材料逐条分清：事实、数据、案例、观点、建议、未知。事实保留来源；建议不能写成已经发生，未知不能补成结果。找出与目标有关的内容和缺失的关键证据。读者已知道的背景压缩，影响决策的差异讲透；旧稿未授权删改则只调整层次，先提出内容修改建议。

## 2. 顺序由问题决定

以下是组织思路，不是强制章节模板：

| 任务 | 观众通常要理解的链条 |
| --- | --- |
| 经营复盘 | 结果与目标的差异 → 哪些变化有证据 → 哪些原因已验证/仍待验证 → 下一步 |
| 产品介绍 | 用户情境与问题 → 产品如何解决 → 真实功能/使用证据 → 适用范围或行动 |
| 项目提案 | 要解决的问题 → 可选办法与取舍 → 推荐理由 → 落地条件和请求的决定 |
| 教学 | 学习目标 → 已知与难点 → 解释/示例 → 应用/练习 → 核对理解 |
| 研究汇报 | 问题 → 方法与条件 → 结果 → 解释及局限；顺序可按听众背景调整 |

没有验证原因的数据，只讲观察和待验证假设；没有报价不编商业方案。内容不适合这些链条时自行重组，不能为了章节齐全凑内容。用户已给结构时优先遵循，发现逻辑问题先指出具体位置。

## 3. 每页是一段完整表达

一页确定一个主要问题，并写出数据或事实能支持的回答。标题尽量表达判断，正文负责证据，不把“现状分析”“数据展示”当所有页的结论。探索性内容还没有结论时如实用问题标题。

内部记录：本页回答什么、结论、证据来源、信息关系、哪些内容必须保留、读者看完如何接下一页。它不需要出现在成品里。

- 同一观点的多条证据，围绕同一焦点组织，别随意分成等宽卡片。
- 并列方案用一致维度比较；先后过程用方向与顺序；因果关系必须有依据。
- 一个页面有多个互不相关的结论，优先在允许的篇幅内拆开；不允许改页数时调整层次并说明具体限制。
- 密集数据先确定要回答的问题，再挑主图，完整细节按约定保留在同页或附页。
- 每张图片要承担对象、证据、细节、关系解释或主题情境；没有作用就不放。

## 4. 把逻辑转成可见的设计

先确定一个主要视觉焦点，再安排阅读路径与支撑信息。比较需要对齐与同尺度，趋势需要连续轴，层级需要有意义的分组/连线，产品需要可辨认主体与细节。版式由这些关系产生，不由已有槽位决定。

图片处理按 [图片流程](ppt-images.md)，数据表达按 [数据流程](ppt-data.md)，字体、颜色、材质与整稿节奏按 [设计方法](ppt-design.md)。图像和数据不能各自好看却不支撑同一个论点。

## 5. 用代表页检验而不是假设成立

选真实正文与数据页验证：不读讲稿能否理解主结论？证据是否足够？图片有没有误导？数值口径能否核对？页面是否一眼有焦点？只改颜色会不会仍然难懂？

哪项不成立就回到对应环节：内容缺口补证据，关系不清改组织，图片不匹配重做素材，数据不可读换图形，布局失衡再改构图。不能把所有问题都归因于模板或配色。
