# PPTX 制作与交付检查

## 按最终文件制作

先检查 Qoder 当前可用的文件、代码和预览能力，不假设内置 PPT 编译器存在。可用原生 PPTX 能力或现有的 PptxGenJS、python-pptx、OOXML 工具时，按本项目逐页设计构建；不把仅演示基本文本卡片的通用生成器当正式设计。依赖缺失按项目与宿主权限处理，不静默安装办公软件、系统依赖或字体。

新建文本、表格、节点和图表保持原生对象，图表附数据工作簿；图片为独立可替换对象。复杂效果可局部栅格化，不能整页截图冒充可编辑 PPT。PDF 和 HTML 是预览或另行要求的格式，不能代替用户要的 PPTX。

旧稿另存新版本，原件只读。优先保留原 OOXML；使用只支持部分对象的库整稿重存可能丢失动画、音视频、备注与复杂形状。先检查再选择局部编辑方式；无法保留时指出具体对象与替代办法，不能静默丢弃。

## 内容和结构检查

在插件根目录按需执行（路径替换为真实路径，作为独立参数传入）：

```sh
python3 scripts/inspect_pptx.py input.pptx ledger.json
python3 scripts/check-pptx-layout.py output.pptx --out layout-check.json
python3 scripts/audit-pptx-images.py output.pptx
python3 scripts/audit-pptx-data.py output.pptx
```

内容脚本只读提取实际页序、文字、备注、图表缓存、关系和媒体。美化前后比对保护内容；数据脚本检查原生图表及其工作簿关联，能核对简单引用值，不理解业务口径。图片脚本检查栅格图实际像素、裁切和显示比例；SVG、复杂分组等列为待检查，不能默认为通过。排版脚本报告越界和文字框重叠候选；框内溢出、继承字体、实际字形与有意层叠必须看真实页面。

检查退出码为零仅代表未发现该脚本能检测的错误，不代表视觉质量、图表语义或最终交付通过。当前环境无脚本依赖时继续做可做的检查，准确记录缺项，不虚构已检结果。

## 真实渲染与编辑性

打开最终保存的 PPTX，用一个当前可用的预览入口或已有演示软件，不批量唤醒不同应用。先看缩略图的整稿节奏，再逐页检查：

- 结论与证据是否对应；正文和数字是否被简化丢失。
- 中文缺字、断词、孤字、溢出、压字、图层遮挡、字号缩小后不可读。
- 图片比例、关键主体、透明边缘、留白与文字关系；不能以独立原图效果代替回填检查。
- 图表口径、轴、标签、图例、单位与来源，真实工作簿的值是否一致。
- 音视频、超链接、动画的实际行为；没有放映不称播放通过。

在副本中修改一处文字和一个数据值并保存，确认图表随之更新；最后交付原始正确数值。没有目标软件环境时，注明未验证的具体行为，交付待验收稿，不把 XML 检查或 HTML 渲染当作 PPTX 播放验证。

## 修复与交付

发现错误按原因修复：主体裁掉改槽位/扩图，图片拉伸改几何，数据错误回源表，正文太挤改分组/行宽而非全页缩字。修复后检查受影响页；全局字体、主题或布局改动后复查整稿。

优先交付 PPTX 与可打开的预览、必要素材。项目内部保留素材任务、源数据、内容差异、逐页问题与复核结果；用户没有要求时不把这些记录逐条讲解，也不加工具署名或生成页脚。只说明影响使用的未验证项。样稿反馈、视觉自检、文件检查、目标软件编辑各自记录，不能相互代替。
