# 逐页设计与整稿节奏

按 [需求确认](ppt-intake.md) 确定内容和方向后再设计。先读 [内容组织逻辑](ppt-story.md)，再按信息关系组织页面。本包不依赖模板库，不把内容塞进固定的“标题+三个卡片”。

## 先画信息关系

内部逐页写下：本页结论、支撑证据、信息关系、主要焦点、构图理由、图片作用、可编辑范围。比较至少两个可能构图，选更适合内容的一个，无需让用户决定所有版式细节。

| 内容关系 | 页面可采用的形式 | 避免 |
| --- | --- | --- |
| 一个判断与证据 | 结论标题 + 大图/图表 + 简短解释 | 每页把长段落拆成三个相同卡片 |
| 前后/方案比较 | 同尺度并排、参数对照、差异高亮 | 不同维度比较、图片大小误导 |
| 时间变化 | 折线、阶段轨迹、时间轴 | 把无时序的并列内容套时间线 |
| 构成/层级 | 堆积、分层架构、树图、带语义连线 | 真实层级变成互不关联的盒子 |
| 产品与服务 | 抠图主体 + 细节放大 + 使用情境 | 只有小贴图、主体没有视觉分量 |
| 教学/技术 | 现象、变量、过程、推导和标注 | 抽象插画代替知识关系 |
| 数据复盘 | 结论 + 主图 + 关键差异 + 口径来源 | 大数字没有基准、单位或趋势 |

封面建立主题，正文给证据，章节控制节奏，结尾给真实的结论或行动。连续三页构图完全相同时检查是否只是换字；需要一致的步骤或连续比较可以保持同构。不要为变化破坏比较尺度。

## 字体、颜色与画面层级

先定画幅、安全边距、标题/正文/辅助信息字阶，背景、正文、次级信息与强调色。品牌色用于层级，不把每个数据系列涂成高饱和彩虹。演讲稿正文一般从 18–24 pt 起按真实显示调整，阅读稿按密度单独处理。长文先重建分组和行宽；删改、拆页需要在内容授权范围内，不能全页缩字掩盖拥挤。

核对当前环境已有字体和实际中文显示。源文件声明字体不等于用户电脑也有；不用正文图片化掩盖缺字。投屏检查颜色对比，浅灰细字在白底不因看上去干净就合格。

## 图片有处理、有层次、有作用

必读 [图片处理与构图](ppt-images.md)。根据内容采用真实主体抠图、前后景分层、细节放大、带标注的证据照片或整幅情境图；不能仅下载一张图塞进右侧矩形就算视觉设计。背景本身有事实意义时保留背景，不强行抠图。

复杂光线、金属、纸张、玻璃等由美图生成/编辑为独立素材，普通文字与数据保持原生。优先原生对象，其次可编辑 SVG 或独立局部高清图片；禁止为方便把整页做成一张底图，再声称可编辑。不要因导出能力有限把好的构图和材质全部降级成纯色卡片；改实现或明确局部编辑边界。

## 图表承担论点

必读 [数据展示](ppt-data.md)。数据决定图形形式与轴尺度；标题说数据能支持的判断。无数据页不硬造图表，有数据页不只把表格截图贴上去。数据图表用原生对象及实际工作簿，图像生成不得绘制精确数字。

## 内部记录与实际检查

项目内部保留逐页设计、素材处理与检查结果，用于复查而非增加成品说明。按 [交付检查](ppt-delivery.md) 看真实 PPTX：先缩略图看整稿节奏，再逐页检查。技术通过、视觉自检、目标软件编辑和用户反馈是四种不同证据。
