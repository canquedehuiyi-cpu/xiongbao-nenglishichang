# 网页设计与验收

保存简明 BRIEF（受众/用途/内容来源/风格/范围）、ASSETS（原图/美图任务/文件/槽位）、QA（实际查看与交互检查）。记录服务本次工程，不额外制作技能介绍站。

## 视觉
先检查整体主题与访客路径，再看字阶、网格、图文比例和留白。设计不是在每个段落上加卡片、渐变和光晕。颜色有角色，图片有用途，标题清楚，正文易读；品牌配色和真实内容优先。缺事实不能用虚构销量、客户 Logo、地址或评价补齐。

实际查看用户图、生成图和接入后的页面。主体误裁、透明白边、字压在复杂背景上、图文不相关要修复。等比裁切，按手机与桌面焦点分别布局；背景与前景不要互相抢占注意力。

## 技术与交互
使用现有工程栈和依赖管理；构建通过后打开页面检查。覆盖宽屏与手机（例如 1440 与 390 像素宽），正文无横向溢出，导航、返回、锚点、主要按钮和表单按承诺工作。检查键盘焦点、可读对比、图片替代文本、加载和错误状态。

微交互服务反馈，叙事动画服务顺序。减少动态时内容完整；自动播放失败有静态替代。请求视频导出时检查实际文件时长、画面及音频，不把预览链接称导出。

## 事实与交付
原型/本地运行/部署上线分开描述。没有真实服务就不写“发送成功”或“支付完成”。技术检查、视觉自评、用户认可分别记录。既有项目仅改受影响范围；网页迁移到小程序还要在目标工具中验收，浏览器不能代替真机。
