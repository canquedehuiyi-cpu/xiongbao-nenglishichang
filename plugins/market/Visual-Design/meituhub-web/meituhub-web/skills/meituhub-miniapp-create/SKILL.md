# 小程序生成

## 适用请求

从零制作小程序页面、导航和视觉素材，交付目标平台源码与手机框可点击预览。适用于做个小程序、作品展示、商品目录、预约页面原型；目标平台和真实接口范围需明确，已有网站迁移优先走互转技能。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**目标平台、主要用途/页面、内容资产与风格、必要交互**。

可按缺口这样问（不是固定问卷）：“小程序主要让用户做哪件事？首版需要哪些页面，有现成内容和风格参考吗？”

确认流程与视觉后做代表页面，再扩原生工程和可点预览。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-web/SKILL.md)，再按本技能执行。所有路径相对当前技能或插件根目录解析。开始前读取输入并确认范围；生成后打开真实结果检查，不能凭任务成功判断质量。只在实际完成时标 completed；缺素材、服务或预览环境时注明 partial/blocked 和影响项。


1. 确认目标小程序平台、页面范围、用户路径、数据来源与是否已有 AppID/工程；不把普通移动网页称作原生小程序。
2. 复用宿主可用工具与目标平台现有项目规范，读取真实配置文件，不猜平台 API 或编造 AppID。缺后端时明确原型范围。
3. 新建必须通过 `meituhub-web-assets` 生成或处理至少一项有实际用途的图片，在页面中接入；保留用户产品与品牌。实现导航、返回、表单状态与必要空态。
4. 检查目标端布局、包体与资源限制。浏览器预览只证明预览层；未在目标开发者工具、模拟器或真机运行就标未验证。
5. 交付源码、素材、导入方法与实际测试记录；不宣称已审核、已发布或后端已经接通。

同时交付标准手机框内可点击效果预览，覆盖已约定页面、导航与返回；模拟接口显式标注。此预览与原生工程分别检查，不把浏览器中的手机框称为小程序真机运行。
