# 网站与小程序互转

## 适用请求

将已有网站、H5 或小程序的页面和交互迁移到另一端，交付目标工程、差异说明与可点击预览。适用于网页改小程序、小程序做网页版、已有 H5 搬到小程序；平台 API、登录支付与发布另行核对，不承诺直接上线。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**迁移方向与目标平台、原工程/范围、需保留的页面交互及是否改风格**。

可按缺口这样问（不是固定问卷）：“要从哪一端迁到哪一端？先迁哪些页面，外观是否保持现状？”

保真迁移沿用现有风格，不强加重设计确认；平台能力差异先核对。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-web/SKILL.md)。所有影像生成、编辑和图片理解必须通过包内启动器使用美图能力，不调用全局 CLI 或其它生成服务。执行前发现当前能力并阅读帮助；已有 task_id 先等待，不重复提交。

实际读取输入，按用户已明确的范围执行；关键方向缺失才补问。生成后打开真实结果复核，原件不覆盖；服务或检查未完成就列明缺口，不假称全部通过。

1. 明确迁移方向：网站到小程序，或小程序到网站；读取源工程、目标平台、页面范围、业务逻辑、数据接口与素材。不把“互转”写成只有单向迁移。
2. 建立路由、组件、样式、事件、媒体、存储和请求的逐项映射。网站转小程序需核对目标平台配置、包体、安全区和真实 AppID；小程序转网站需替换小程序生命周期、导航和平台 API，保留内容与可实现行为。
3. web-view 只有在用户接受且目标平台、域名权限真实可用时才采用，不拿嵌一个页面冒充原生转换。平台专属登录、支付、订阅通知等不伪造；列出缺口和待接服务。
4. 原资产保真复用；缺图、扩图或内容编辑必须走 `meituhub-web-assets` / `meituhub-image-adapt` 的美图链路。纯迁移不为调用重画原件，不把页面变成截图集。
5. 制作标准手机框内可点击预览，覆盖约定首页与详情、导航返回和状态变化。预览明确标识模拟行为；它不等于目标平台或真机验收。能运行目标工具时再验证真实工程。
6. 交付目标源码、素材、运行/导入说明、功能映射、迁移差异与实际验证记录。没有部署或审核记录时不称上线；原工程保留。
