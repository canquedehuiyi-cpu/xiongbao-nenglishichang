# 整体网站设计

## 适用请求

设计和实现响应式网站、官网、落地页、活动页、产品展示页与作品集，交付源码、配图和可用交互。适用于做个网站、搭个页面、把资料放到网页上展示、给项目做首页；也承接开发任务中的完整视觉页面。纯后端或无视觉需求的代码修复不适用。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**网站用途/目标访客、真实内容与主要页面、风格参考与核心交互**。

可按缺口这样问（不是固定问卷）：“访客看完首页最希望做什么？有现成文案、作品或产品图吗？更偏作品画册还是产品介绍？”

先确认首页方向与关键内容，再做代表首屏和正文；不先编造整站业务。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-web/SKILL.md)，再按本技能执行。所有路径相对当前技能或插件根目录解析。开始前读取输入并确认范围；生成后打开真实结果检查，不能凭任务成功判断质量。只在实际完成时标 completed；缺素材、服务或预览环境时注明 partial/blocked 和影响项。


1. 明确真实主体、目标访客、主要行动、内容来源、视觉方向与范围。宽泛的“做个艺术网站”不能据此编展览名、城市或履历；用户明确做虚构概念站时才可在授权范围内设定。
2. 读 [网页设计与验收](../../references/web-design.md)，规划最小完整访客路径，复用现有技术栈。不得擅加后台、登录、支付或营销数字。
3. 盘点实际图片，规划每个槽位。新建/完整重构必须通过 `meituhub-web-assets` 实际生成或处理至少一项与内容相关的视觉素材，落盘并可见接入页面；数量由内容决定，不用无关小图凑数。
4. 如需美图生成代码，先从工具目录发现 text-code 并查帮助；不可用时宿主仍可实现 HTML/CSS/JS 和本地工程，但影像步骤依然必须走包内 meitu-ai。不能把代码截图当网站。
5. 实现约定页面和可用交互；表单无后端时明确展示原型状态，不虚构发送成功。检查桌面/手机、导航、键盘、空态和资源加载。
6. 交付工程、实际入口、启动方法、本地素材和验收记录。未经上线任务授权不发布，不将本地可运行描述成已上线。
