# 整站风格转换

## 适用请求

调整已有网站的视觉风格，保留内容与功能，统一版式、字体、配色和图片。适用于页面太素、网站不好看、改高级一点、参考这种风格、重做首页视觉、手机端也统一；单纯修功能或改一行字不需要整站重做。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**原站范围、要保留的内容和功能、新风格参考**。

可按缺口这样问（不是固定问卷）：“这次只调整视觉，还是也改信息布局？有喜欢的参考网站吗？”

先展示代表页面变化，用户确认或明确委托后再扩整站。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-web/SKILL.md)，再按本技能执行。所有路径相对当前技能或插件根目录解析。开始前读取输入并确认范围；生成后打开真实结果检查，不能凭任务成功判断质量。只在实际完成时标 completed；缺素材、服务或预览环境时注明 partial/blocked 和影响项。


1. 先运行或读取现有项目，记录路由、页面结构、功能、品牌资产和用户保留项。区分完整视觉改版与局部字体/间距修改。
2. 风格未定时提出可比较的方向，并说明改动幅度；已给参考或委托就继续。读取 [网页设计与验收](../../references/web-design.md)。
3. 完整改版必须通过 `meituhub-web-assets` 生成/编辑至少一项适合新方向的素材并真实替换。仅改字、颜色、间距或用户要求图片不动时复用原图，不为凑调用扩大范围。
4. 在原工程内保留业务行为、真实文案、已埋事件与可用数据源。检查响应式布局和交互回归；不通过重建整个工程掩盖功能丢失。
5. 交付代码与前后差异，列明实际检查的页面和未验证的服务。无后端验收不声称业务链路通过。
