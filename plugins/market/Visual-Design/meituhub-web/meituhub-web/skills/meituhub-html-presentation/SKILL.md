# HTML演示

## 适用请求

制作网页翻页演示、产品操作演示和可点击流程原型。适用于做个 demo、演示注册下单流程、给客户看交互效果、把资料做成动态网页讲解；有演示意图时匹配，普通程序函数 demo 不适用。PPT 语境的浏览器放映可由 PPT 插件处理。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**翻页演示或可点击产品演示、受众/内容重点、风格与范围**。

可按缺口这样问（不是固定问卷）：“是逐页讲解资料，还是让客户点击体验产品流程？哪条流程最重要？”

先确认结构与视觉方向，再看一组代表页面；演示按钮不伪造真实业务成功。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-web/SKILL.md)。所有影像生成、编辑和图片理解必须通过包内启动器使用美图能力，不调用全局 CLI 或其它生成服务。执行前发现当前能力并阅读帮助；已有 task_id 先等待，不重复提交。

实际读取输入，按用户已明确的范围执行；关键方向缺失才补问。生成后打开真实结果复核，原件不覆盖；服务或检查未完成就列明缺口，不假称全部通过。

1. 读取资料，明确受众、用途、风格、素材保留项和讲述/自主阅读/操作演示方式。已明确的要求不重复询问，不从文档标题编用途。
2. 先组织页面结论和观看顺序。新建/完整重做至少生成并接入 1 张美图核心配图，5 页及以上至少 2 张不同内容的核心配图；图标、同图派生和隐藏背景不计。调用 `meituhub-web-assets`，保留真实证据和数据。
3. 标题、正文、图表与控件保持代码对象。进入页面自动按阅读次序入场；默认手动切页，提供方向键、前后页、目录和页码。连续播放有开始/暂停，操作演示不能替用户自动点击业务按钮。
4. 兼顾桌面舞台与手机阅读。实现减少动态与打印；检查快速切页、重进、首末页、焦点、后台恢复和资源加载。动画要实际播放检查，静态截图不能代表通过。
5. 交付 HTML、源码与素材；单文件离线需内嵌全部依赖并断网验证。只实际实现才宣称可视化编辑、保存或导出。PPTX 不是本入口默认产物，不将 HTML 冒充 PPTX。

此技能在网页项目内制作演示；PPT 插件中的“HTML制作”服务演示文稿任务。按用户当前选择的插件执行，不交叉要求安装另一包。
