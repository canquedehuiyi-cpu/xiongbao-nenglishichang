## 场景进入与任务范围

用户不必说出插件名、Skill ID 或“使用美图”。当请求需要本插件能完成的结果，或一个明确子任务需要该结果时，可选择相应业务技能；先按目标产物、输入类型和当前任务语境判断。

description 用于发现技能；本文件用于选中后的分工，不假定尚未加载的正文能代替发现。不要把只解释概念、改一个字或修纯逻辑 bug 的请求扩成素材生产。

复合任务选一个主流程，按实际缺口调用必要辅助技能，同一素材复用已有有效任务记录。同类能力同时可用时按当前语境选择一个实现，不让多个插件重复生产或重复计费。缺少影响制作的关键信息才补问，不要求用户先学会技能术语。

影像生成、编辑与图片理解仍通过包内 meitu-ai。技能命中只决定采用哪套流程，不等于已经登录、已经提交生成或允许超出用户要求上传文件。继续遵守原有权限、额度、失败取回和原件保护规则。

## 相邻能力怎样分工

- PPT / 汇报 / 课件语境的配图与网页演示由演示流程承接；产品页面、操作原型和界面资源由网页流程承接。没有语境但两者均可做的 HTML 演示，只选择一个可用入口。
- 游戏人物、场景、UI 与宣发素材按游戏资产流程；普通界面图标与无真人参考的插件职业头像按网站配图流程；用本人照片保持身份生成新写真按写真流程。
- 已有人像要求综合光色后期走人像精修；单人皮肤美化走人像美颜；多方向调色或需要 XMP 走调色方向；旧照损坏走老照片修复。
- 照片只需更高像素或专项清晰度走超清；噪点、暗光、压缩等综合问题走画质修复；尺寸与构图适配不等同于超清。
- 大批照片挑选走批量选片；用户已经明确选中的文件只需归档时，按清单处理，不再上传重选。

以上是场景分工，不构成安装其他插件的依赖；当前插件可独立完成自身已声明的任务。只有实际可用且确有必要时才使用其他已安装技能。

## 本插件常见说法与处理补充

### 批量选片

常见请求：“旅行拍了好多重复照片，帮我挑一组发相册。”；“这组猫咪连拍留哪几张？别删原片。”。

非人像照片按主体标准选片，先读扩展场景；只有文件整理或用户已选清单时不重新视觉筛选。

### 写真生成

常见请求：“用我的这张照片做一组自然光职业形象照。”；“给我家狗狗做一套生日主题写真。”。

身份参考与风格参考明确区分；同一人物多张输出先确认一张方向再扩展，艺术化处理不冒充真实拍摄记录。

### 超清

常见请求：“这张小图放大后太糊，帮我做清晰一些。”；“商品图要更高分辨率，包装字别变。”。

印刷或大屏诉求先确认目标像素，记录真实输出尺寸；字标、人脸、纹理变动单独复核，几何放大不当作超分结果。

### 画质修复

常见请求：“夜景照片太暗，噪点也多，帮我改善一下。”；“这张室内照片压缩得很差，修复画质。”。

噪点、暗光和压缩问题分步处理，先小样检查细节损失；仅需放大像素时走超清，缺失内容无法可靠恢复则说明。
