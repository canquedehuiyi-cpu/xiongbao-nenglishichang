# 画质修复

## 适用请求

修复已有照片的噪点、暗光、曝光不足、压缩痕迹与综合模糊，按诊断选择必要处理。适用于夜景太暗、颗粒多、照片画质差、压缩后糊了、帮这张图修清楚；无人照片也适用，不自动美颜、换背景或重做内容。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**主要画质问题、用途及是否只修画质保留原外观**。

可按缺口这样问（不是固定问卷）：“主要想改善模糊、噪点还是暗部？颜色和人物外观保持原样可以吗？”

明确单项修复直接按该项执行；复杂或批量先样片，不连做无关处理。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-culling/SKILL.md)。所有影像生成、编辑和图片理解必须通过包内启动器使用美图能力，不调用全局 CLI 或其它生成服务。执行前发现当前能力并阅读帮助；已有 task_id 先等待，不重复提交。

实际读取输入，按用户已明确的范围执行；关键方向缺失才补问。生成后打开真实结果复核，原件不覆盖；服务或检查未完成就列明缺口，不假称全部通过。

1. 实际查看照片并结合用户要求，只记录可见问题：低分辨率/模糊、噪点/杂色、曝光不足、压缩痕迹或局部损伤。不存在的问题不自动加进处理链。
2. 按当前工具目录和帮助选能力：清晰度用 image-superres-enhance，噪点用 image-denoise-enhance，暗光用 image-lowlight-enhance；其它修复仅在 image-edit 或专用能力确实适用时执行。上述名称是待发现的能力候选，不保证每个账号都有全部工具。
3. 根据原图安排最少必要步骤，不一律“先超清再磨皮”。多步串联使用上一步真实结果，保存中间产物与来源；必要步骤失败就保留未完成状态，不静默跳过并称综合修复成功。
4. 默认只修画质，保留人物身份、商品细节、字标、构图与场景。去物体、改字、换背景、磨皮或重塑五官须来自用户明确要求，不能由“画质差”推导出来。
5. 每步检查细节、边缘、颜色和亮度；暗部不盲目拉灰，高光不过曝，降噪不涂掉纹理。单纯超清转“超清”，从参考创作新照片转“写真生成”；历史照片的年代保真处理由老照片修复承接。
6. 批量按问题分组，逐张留成功、失败、等待状态；任务超时等原任务，积分不足停止新提交。交付修复图、实际处理项、对照和剩余问题，原片不变。
