# 批量选片

## 适用请求

批量比较写真、婚礼、活动、旅行、宠物或商品连拍，挑选焦点、表情、构图与时刻更好的照片，输出精选、理由和待复核清单。适用于帮我选几张、挑最好看的、相似照片留哪张、连拍去重、整理拍摄成片；复制精选，原片不删除。

按 [场景识别与分工](../../references/intent-routing.md) 处理常见说法和相邻任务。用户无需点名插件；选择后仍按下面的实际流程、输入要求与失败处理执行。

## 开工前先确认

必须先读 [需求确认](../../references/need-confirmation.md)。复用已有材料与决定，只补问缺失且影响结果的事项：**用途、目标张数或比例、选片侧重点、不能遗漏的人物/时刻**。

可按缺口这样问（不是固定问卷）：“这组用于交付、发社交平台还是留档？想留大约多少张，有必须保留的人或时刻吗？”

先确认筛选标准；大批量先一小组示例及理由，反馈后扩展；不删除原片。 没有收到关键回答时，只做只读盘点和方案建议，不先提交生成/编辑或开始依赖该决定的制作。已明确的信息与已委托的选择不重复询问。

## 执行约定

先读 [插件规则](../../rules/meitu-only.md) 和 [MeituHub 接入](../meitu-ai-culling/SKILL.md)。所有影像生成、编辑和图片理解必须通过包内启动器使用美图能力，不调用全局 CLI 或其它生成服务。执行前发现当前能力并阅读帮助；已有 task_id 先等待，不重复提交。

实际读取输入，按用户已明确的范围执行；关键方向缺失才补问。生成后打开真实结果复核，原件不覆盖；服务或检查未完成就列明缺口，不假称全部通过。

1. 先读 [美图选片流程](../../references/culling-process.md)，盘点数量、格式和来源，明确精华精选或完整交付范围；按时间、场景与相似动作分组。无法解码的 RAW 标待复核。
2. 旅行、宠物、商品连拍先读 [非人像选片](../../references/culling-general.md)。按照片类型读取对应规则：[写真与连拍](../../references/culling-portrait.md)、[婚礼](../../references/culling-wedding.md)、[活动与合影](../../references/culling-event.md)。人物表情优先，但艺术闭眼、动作模糊和唯一纪实瞬间按用途判断。
3. 通过包内 meitu-ai 对真实照片取得逐图可核对的判断。先发现当前图片理解工具/工作流；text-generate 仅在实际支持图片输入和视觉判断时作为候选。若无法逐图分析则标阻塞，不把本地-only 选片或修图调用充当选片能力。
4. 宿主复核候选与淘汰理由；缩略图看不清的面部补看单图细节。每个输入对应 selected/rejected/review、理由、相似组和真实证据；失败或不确定不自动归淘汰。
5. 按 [精选归档](../../references/culling-delivery.md) 使用 [本地复制脚本](scripts/cull_files.py)，把选中照片复制到源目录外的新目录，保留相对路径并核对哈希。同名不覆盖，RAW/JPEG 配对要明确，原件不改不移不删。
6. 输出 selected_files.txt、manifest.json、选片理由、待复核项与后期建议。星级写回仅在用户明确要求时执行；只归档用户已确定的清单不需重新提交图片分析，必须说明只是归档。
