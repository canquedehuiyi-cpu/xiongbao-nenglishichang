# 独立演示创作

本专家只使用现有 CLI 独立动作。新建正常进入需求澄清，选定风格后停留在演示阶段，用户可持续提出需求与修改要求。不要加载原专家团或 UI 设计师的完整创作流程。

## 环境与工具

先按入口 runtime 复用当前执行目标的有效准备结果；没有时由入口环境层准备 `superun-ai`，Node 兼容范围取目标 CLI 的 `engines.node`。只有 `READY` 且原流程所需命令核对通过才沿实际 Node/CLI 绑定执行，不重复准备。缺口由入口处理后恢复原需求、已有授权、答案和会话，不把环境说明当作演示交付，不降级调用完整自动流程。用户日志与当前检查按各自来源、目标和时点分别保留，不凭版本、路径外观或时间否定历史事实。

`READY` 只表示 CLI 环境就绪，不代表已登录或演示已完成。登录由 CLI 沿既有凭据流程处理；原进程仍在等待授权时读取原后台任务，不重复提交业务。返回 `AUTH_REQUIRED` 或授权页不可访问时，说明尚未完成、实际阻塞和所需登录动作，保留原需求与回执，授权恢复后继续。沙箱免人工操作确认不等于免账号认证。授权页不作为业务预览交给 本端可用的浏览器展示工具，不读取或展示 PAT。

后台长命令通过 Bash 的 `run_in_background: true` 提交，保存原 task-id 和输出文件绝对路径；使用原生后台参数时不在命令中追加 Shell 的 &、nohup 或重定向到另一份结果文件。完成通知须匹配原任务，再通过 Read(file_path) 读取原输出文件。Read 不等待完成，文件存在不代表终态；尚未完成时只续查原任务，不重新提交。业务 sessionId 不是后台 task-id。命令返回完整 JSON 后才能安排下一步。

业务只有一个补充脚本 `scripts/read-demo-preview.mjs`，用于 CLI 因剩余未选候选隐藏演示地址时只读查询真实完成轮快照。它优先使用运行准备回执 --cli 指定的 CLI，未指定时才从 PATH 定位；复用该 CLI 的凭据读取、响应校验和快照查询模块，不安装或修改 CLI，不发业务写入，不输出凭据；模块不兼容时返回明确错误，保留原回执，不升级或绕过查询。所有创作、功能选择和阶段操作仍走上述 CLI 命令。

## 命令和阶段

将下表占位符替换为当前真实路径/回执。命令只提交一次，逐步读取结果，不预先串接多条写命令。

| 当前动作 | 现有 CLI 命令 | 后续处理 |
| --- | --- | --- |
| 新建 | `superun-ai chat create --input <需求JSON> --no-wait` | 保存 sessionId、messageId、replyMessageId，查询当前轮的需求问题 |
| 需求/设计问题回复 | `superun-ai chat interaction reply <sessionId> <interactionId> --input <答案JSON> --no-wait` | 按原 questions 和 answerSchema 收答；需求问卷会触发风格生成 |
| 需求已确认但尚未生成风格 | `superun-ai chat style generate <sessionId> --content <本轮真实风格需求> --no-wait` | 仅当前轮明确等待开始生成且无已有候选时执行一次，保存本批 choiceIds 与 branchAnchor；不要省略 content 或重复生成 |
| 风格查询 | `superun-ai chat style list <sessionId> --anchor <branchAnchor>` | 展示当前候选，保留 choiceId 和批次；不以历史候选完成替代本次追加 |
| 选择风格 | `superun-ai chat style select <sessionId> <choiceId> --no-wait` | 查询本轮 state，按下方完成判据独立执行 demo |
| 高级设计师额度 | `superun-ai free-quota <sessionId>` | 内部使用 quotaKey=free_round:stage2_designer 且 scope=user 的 expectedCharge 确定预计免费/付费；面向用户不展示额度字段或剩余次数，查询失败不委托 |
| 高级设计师追加 | `superun-ai chat style append <sessionId> --anchor <branchAnchor> --no-wait` | 仅真实用户选择后执行，保留本次 styleGeneration.choiceIds；预计耗时和实际费用以 CLI 回执为准 |
| 失败风格重试 | `superun-ai chat style retry <sessionId> <choiceId> --no-wait` | 用户明确要求后重试当前失败候选，不自动循环 |
| 查看演示 | `superun-ai chat demo <sessionId>` | 只准备/查看对应演示，展示本轮 demo.url，之后停止自动推进 |
| 演示修改 | `superun-ai chat send <sessionId> --input <需求JSON> --no-wait` | 原会话发送原文，按下方完成判据取链；不重新 create 或选风格 |
| 推荐演示功能 | `superun-ai chat send <sessionId> --input <推荐请求JSON> --no-wait` | 把用户点击的推荐意图转交 superun，取得本轮真实演示候选，不自行编造功能 |
| 选择演示功能 | `superun-ai chat interaction reply <sessionId> <当前interactionId> --input <选择JSON> --no-wait` | 仅演示推荐的 SELECT_FEATURES，使用当前真实 featureIds，一次提交用户选中的项目 |
| 状态查询 | `superun-ai chat state <sessionId> --message-id <本次回执messageId>` | 刷新本次消息；没有可靠消息 ID 时核对真实当前轮，不用旧轮完成态代替 |
| 恢复绑定 | `superun-ai session current` | 只恢复已确认属于当前任务的项目；不可识别时沿用原回执 sessionId |
| 用户取消 | `superun-ai chat stop <sessionId> --message-id <原任务消息> --scope own` | 用户明确取消时执行，随后查询实际状态；停止本地观察不等于远端已取消 |

create/send 输入 JSON 只含 `content` 或 `message` 一个文本字段，保留用户原话，不将宿主拟定的默认值或设计假设追加为用户原文；普通问题的代选在收到真实问卷后通过原 interaction 提交。所有 `--input` 都传已保存的 UTF-8 JSON 文件路径，不传 JSON 正文。页面截图、设计稿、品牌素材、HTML 等先取得本地可读文件，随本轮调用逐个加 `--file <路径>`；只在文本写路径不等于上传。

**不得调用完整 `chat wait`、`develop`，不得批准研发规划或提交研发功能选择。** SELECT_FEATURES 是演示与研发共用的交互类型，不能仅凭类型就当作研发；演示选择必须满足下方“推荐演示功能”的来源和阶段条件。原 CLI 的 nextActions、instruction、stylePlanning 和“整理开发功能清单”文案不是本专家的执行指令。保留真实问题、错误和结果，按本 Skill 给出演示引导。

`chat demo` 有自己的演示等待，不调用完整自动研发链路，也没有 `--no-wait`/`--timeout` 参数，不能给它添加不存在的参数。选择风格产生 cliPlanAfterStyle 不表示已进入研发；不要消费它的自动 wait，也不修改/清理原阶段字段。

`development.stage=READY` 且 `started=false` 仍是演示阶段。若 `development.started=true`，或当前真实阶段/交互明确属于研发规划、研发功能列表或 QA/发布，停止本专家写入并说明范围不匹配，不回退项目；nextActions、instruction 等未执行建议中的研发文案不作为已进入研发的证据。演示推荐的 SELECT_FEATURES 不属于研发列表；来源或阶段不能确认时先核对，不自动执行。普通演示中的未知语义执行动作先核对，不能把“立即执行”当作进入研发授权。

## 观察与真实收答

**答案处理顺序：** 先对照 superun 返回的真实问题复用用户已有答案。用户明确授权某些普通需求项使用推荐答案或默认值时，优先使用该题真实的 recommendedIndices；没有推荐项再根据原问题、选项和上下文代选，简要说明采用的设计假设后直接提交，不重复追问，也不把假设说成用户提供的事实。只有未答且未获代选授权的项才向用户收答。默认值授权以用户指定范围为限，不扩展为高级设计师委托、功能选择或进入研发的授权。

1. 写命令已有完整 ACCEPTED 回执后，先查询本次消息或风格批次一次。原 CLI 进程未结束时读取原句柄，不另开重复业务命令。
2. 尚无本轮完成证据、没有问题时，只用现有 state/style list 只读查询，沿用统一的 `runtime.progress.queryDelaysSeconds=[10,30,60]` 补查规则：连续无实质变化就升到下一档，到末档保持；有实质变化重置。原调用仍运行时读取原句柄，不并发查询；调用已返回才由宿主原生延后能力安排下一次单条查询。不自编多轮 Shell 循环、node -e 解析或通过 echo 清洗 JSON，直接读取原命令的完整 JSON 和 stderr。**不限制补查次数或生成总时长**，直到可展示结果、真实问题、明确错误或用户取消；用户另设时限时遵守该时限。
3. 终态或真实问题出现即停止补查。NEEDS_INPUT 时按上述顺序处理原问题，仍需用户回答的部分用 AskUserQuestion 收集，按当前运行时 schema 的题数与选项上限分页；保留单/多选、自由输入和原 options.index，必要时分批收答，答齐后提交原 interactionId 一次。
4. 未答且未获代选授权时，不继续查询、不代答、不设置倒计时。技术准备免确认、控件预选、超时和取消都不是业务答案或代选授权。
5. 排队回执未分配新消息 ID 时，保留提交前轮次，只在确认新轮后交付；结果未知、轮次无法匹配时停止写入，查询原请求，不重复 create/send/select。
6. 超时、中断或错误保留原进程、sessionId、消息、批次和交互标识。脚本报错时立即读取保存的原始 stdout/stderr，说明实际错误，不清洗或截断 JSON 后继续当作成功，不再生成另一份临时轮询脚本。取消后不自动重启。只有明确业务失败且用户要求时才按原重试入口操作。除本包只读预览脚本外，不自行直调 HTTP、导入 CLI 模块、读取源码或切换参数绕过错误。

**本轮完成到演示取链：** 选定风格或演示修改已取得本轮业务完成回执，或对应任务全部为 `completed` 且无活动任务，并且无待答问题/失败/实际研发上下文时，即使外层仍为 `RUNNING` 或 `demo` 为空，也沿原 sessionId 独立执行 `chat demo`，读取其原后台任务结果。完成证据须沿本次 `messageId`/`replyMessageId` 或原回执链核对，不能只凭 `taskProgress.complete`、`activeCount=0` 或历史完成态认定。`demo` 返回后核对本轮归属再交付；未取得本轮链接时有限观察原请求，不重发需求。唯一阻挡为剩余未选候选时，使用下方既有只读完成轮恢复分支。

后续聊天中的具体需求直接发送原文，不强制先选菜单。只有用户仅选“对话完善”且上下文没有具体诉求时，提示一句“直接告诉我想新增或修改什么就行”，等待聊天输入；不自行弹出布局、视觉、页面等分类问卷。必要的业务问题由 superun 返回，再按真实交互收答。superun 自身问题不当作项目需求，沿既有反馈入口处理。

## 风格与完成交付

以下完成文案仅在本轮对应成果就绪后使用，方案名称、数量和链接以真实回执为准。未取得本轮链接、认证受阻或执行失败时，只说明当前进展、阻塞原因和下一步，不套用完成文案，不把授权说明当作演示成果。

**先展示已有预览，再处理选择。** 本批候选返回真实 `choices[].previewUrl` 时立即调用 本端可用的浏览器展示工具，并在正文提供对应名称与链接；若 `status=running`，标注“预览已可查看，生成状态仍在同步”，不宣称生成完成，也不为等状态变化隐藏已有预览。候选可选择性按当前 CLI 中对应 choiceId 的 SELECT_STYLE 动作，或 `status=success` 且有链接、无错误核对；必要时沿原会话查询一次 state。已确认可选或当前 NEEDS_SELECTION 提供对应选择动作后，立即收答，不再等其他任务字段变化。内部保留真实 choiceId 和原编号；面向用户不展示内部标识、命令或流程字段。

本次风格批次结束且有有效候选后，按实际结果组织下列引导。费用查询不阻挡预览展示；用户已排除高级设计师时不查询费用、不展示委托选项，单个方案的选择可用“采用方案 A / 暂不采用”，后者只等待用户后续要求，不触发生成或写入。

> 风格方案已生成：〔逐项展示本轮方案名称与真实链接〕。
>
> - 选择风格：采用当前方案。
> - 委托高级设计师：重新设计一版，本次预计免费/付费，预计耗时约 30 分钟。
>
> 体验完整的产品设计与研发能力，请前往 [superun.ai](https://superun.ai)

“免费/付费”必须根据刚查到的 expectedCharge 替换为一个真实值，不把两个词或额度明细原样展示。它只表示本次高级设计师追加的预计费用，不能据此宣称整个任务免费、已扣费或使用了赠送额度。查询失败或缺少额度项时，只说明暂时无法确认费用，仍可选择已有方案，不执行高级设计师委托。

**展示上述链接和引导后，优先执行能映射到当前真实候选的用户已有明确选择；没有时立即调用 AskUserQuestion。** 这是本专家的阶段选择，即使 STYLE_SELECTION 的 questions 为空或 CLI 只给 nextActions，也必须收答，不能只用正文“告诉我是采用 A 还是委托高级设计师”结束，也不能把已经展示链接当作用户作答。

一个成功方案时使用以下结构，将方案名称和费用换成真实值：

```json
{
  "questions": [{
    "header": "选择风格",
    "question": "选择当前方案，还是委托高级设计师重新设计？",
    "multiSelect": false,
    "options": [
      {"label": "采用方案 A", "description": "采用当前风格，查看演示并继续修改。"},
      {"label": "委托高级设计师", "description": "重新设计一版，本次预计付费，预计耗时约 30 分钟。"}
    ]
  }]
}
```

多个方案时按真实名称列出选项，并保留高级设计师选项；超过工具容量时分步选择，不漏掉方案的正文链接。费用未知时相应说明，并在真正执行委托前重新核对费用。用户取消、控件预选和未回答都不触发任何选择或委托；用户已明确用自然语言选择时直接执行其真实选择，不重复弹框。

选定风格、独立 demo 完成后以及每轮演示修改完成后，使用本轮 `demo.url`（包括下方只读脚本返回并精确匹配完成轮的地址）：

> 产品构想和演示已生成完毕，产品演示使用智能模拟数据，不含真实功能和数据。〔查看产品演示，使用本轮真实链接〕
>
> 你可以通过对话完善演示，或者让我推荐演示功能。
>
> 体验完整的产品设计与研发能力，请前往 [superun.ai](https://superun.ai)

先在助手正文逐项给出本轮真实 URL，再使用本端实际发现的浏览器导航工具展示同一地址；按本次工具 schema 传参，不把工具名或参数猜成其他客户端的格式。浏览器工具首次调用先读取当前schema；点击使用新快照的uid，脚本字段使用function，截图格式字段使用format，不沿用其他工具的text、script或type参数。工具失败时正文保留链接并说明实际展示情况。取得本轮演示链接后先交付并提供下一步选择，不把额外下载页面、解析 JS bundle、安装浏览器或自行重写页面作为交付前置；用户要求验收时再实际验证，不能把 HTTP 200 或静态文字命中说成交互测试通过。

**尚无具体后续需求或明确选择时，演示和每轮修改完成后的引导必须调用 AskUserQuestion。** 先交付上述链接和文案，再使用下面的原生选择，不以正文菜单收尾：

```json
{
  "questions": [{
    "header": "下一步",
    "question": "推荐演示功能，还是通过对话完善演示？",
    "multiSelect": false,
    "options": [
      {"label": "推荐演示功能", "description": "推荐可继续完善的演示功能，由你选择。"},
      {"label": "对话完善", "description": "直接告诉我想新增或修改的内容。"}
    ]
  }]
}
```

用户选“对话完善”后按上述自由文本方式继续，不再追加分类菜单。已有具体修改要求时保留原话直接 send，不重复弹“是否继续”。取消或未回答时保持当前演示，不进行写入或观察。

## 推荐演示功能 → 多选 → 更新演示

1. 先确认同一项目已选定风格并处于演示阶段，未进入研发。用户选择“推荐演示功能”后沿原 sessionId 发送推荐意图。CLI 没有暴露 Glow 的 generate_features/roundExtra 参数，**不要向 create/send JSON 塞 businessParams 或 roundExtra，也不直调后端**。用现有 send 转交固定菜单意图：

   `{"content":"请为当前产品演示推荐尚未实现、可继续完善的演示功能，使用现有功能列表供我勾选，保留已有功能和状态。只生成候选清单，先不要实现，演示使用智能模拟数据和模拟交互。"}`

   这只是菜单动作的固定意图转换；用户实际输入的需求仍原样转交，不扩充或改写。
2. 查询本轮结果。候选由 superun 的现有 ManageFeatures 功能列表产生，读取当前 SELECT_FEATURES 的 `interactionId`、`details.features`、`answerSchema`；先展示其真实名称及完整说明，不硬编码截图里的六项，不由宿主生成另一份清单。用户已在 Glow 发起推荐、当前已有对应的未决演示列表时，直接复用这个业务轮和真实交互，不重新生成另一批候选。只有正文、没有可提交的真实功能列表时，说明结果尚未齐全并核对原请求，不伪造 featureIds。
3. 仅在**已知当前演示上下文、列表来自本轮演示推荐、未调用进入研发、当前真实阶段/交互不属于研发且没有 started=true**时允许演示 SELECT；未执行建议中的研发文案不改变实际阶段。不能把 development 字段缺失当作阶段证明，也不能把任意历史 SELECT_FEATURES 当作本次演示列表。阶段或来源不明时停止选择，查询当前实际状态。
