# 从产品事实到可用指南

## 写作决策

先选读者要完成的任务，例如“邀请一位同事加入”，而非按产品菜单罗列功能。角色、版本或前置状态改变结果时显式分支；步骤只有材料确实给出的动作，不补想象中的菜单。说明“发出邀请”与“对方成为成员”是两个状态，不能将前者直接写为成功。

将信息分成：已确认的产品事实、写作组织建议、缺失或冲突事实。组织建议可由编辑提出，事实要可回源。引用“来源 S01：产品规则第 2 段”即可；若来源只有一段贴文，直接用其标题，不编造页码。

## 成果结构

用具体任务做标题；开头说明谁在什么版本下使用，接着列必要前提、按顺序执行的操作及对应结果，再给已知分支和待确认项。若没有具体 UI 记录，标题或开头说明这是“流程说明，界面步骤待补”。不输出一堆未填写的空栏目作为成品。

## 完整小例子

输入 S01：只有管理员可发出成员邀请；对方接受后成为成员。S02：企业版支持 CSV 批量导入，免费版仅逐人邀请。未给按钮名称与邀请有效期。

可用的流程说明：

> 邀请同事加入（流程说明）
>
> 适用：管理员；免费版逐人邀请，企业版另有 CSV 批量方式。
> 1. 确认自己具有管理员角色。普通成员没有发出邀请的权限（S01）。
> 2. 使用产品的成员邀请功能发出邀请。当前资料没有页面路径，具体点击步骤待补。
> 3. 提醒同事接受邀请；接受后才成为成员（S01）。
> 批量处理：只有企业版在已给规则中支持 CSV 导入（S02）。
> 待确认：页面路径、按钮名、CSV 字段要求、邀请有效期。未进行实际界面验证。

错误写法：“点击设置→组织→一键导入，免费版也能用，邀请 24 小时内有效。”四项均无来源，不能作为可用教程。
