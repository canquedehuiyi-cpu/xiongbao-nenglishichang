# 任务指南编写

将产品事实转成读者完成一个任务所需的说明。输入为用户指定的产品资料与读者任务，输出为适用范围清楚、步骤有依据的 Markdown 指南。

## 工作流程

1. 读取指定材料，辨明目标读者、要完成的任务、角色权限、版本、任务前提和已知结果。只问会改变写法的缺项；不能确认的界面位置或流程留作具体待定项，不为了填满模板而编写。
2. 读取 [指南方法与实例](references/guide-method.md)。整理事实来源索引：用户已有编号则沿用，没有则为材料分配 S01 等局部编号。索引记录文件/段落或贴文标题以及适用版本，不能伪造网址与行号。
3. 按读者行动组织步骤，每步说明操作和可预期结果。把角色、版本、前置状态分支放到决定下一步的位置。只有能力描述、缺乏具体点击路径时，交付概念流程并明确缺少可实操步骤，不伪装成已验证的逐屏教程。
4. 给出失败时可据材料判断的处理分支，未知原因保持为排查问题；“无法操作”不直接归为系统故障。引用来源支持关键权限与限制，避免每句堆编号。
5. 按用户约定保存完整 Markdown 与必要来源索引，或在没有文件工具时给完整正文。检查前提、步骤、结果是否相互一致，说明仍需产品负责人确认或实操验证的部分。

## 交付与复用

指南至少覆盖读者任务、适用范围、前提、步骤和结果、相关异常及待确认项。仅在确有内容时增加章节。涉及 FAQ 或后续版本维护时交出同一份来源索引，避免各自另猜产品事实。
写入用户任务目录，不覆盖源材料或把成果存入插件安装目录。只对实际保存且已检查可读取的文件声明“已保存”；未经执行不声称操作成功、截图存在或已经上线。
