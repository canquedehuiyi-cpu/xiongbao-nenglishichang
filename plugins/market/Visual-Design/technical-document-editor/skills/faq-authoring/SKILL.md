# 答疑条目编写

用真实问题与产品证据写直接、可采用的答疑，不从营销猜测生成产品承诺。可单独处理一条问题，也可与同一产品的任务指南协作。

## 工作流程

1. 读取真实问题、适用用户与版本，以及用户指定的产品来源；有既有指南或 FAQ 时一起读取。资料范围不清且会影响答案时先明确该范围。
2. 读取 [答疑方法与实例](references/faq-method.md)。将问题按用户意图归组；只有问的是同一条件下的同一事情才合并，保留角色与版本导致的不同答案。
3. 每条先给直接回答，再说明适用条件、依据和下一步。区分产品不支持、当前角色无权、资料不足三种情况；没有故障证据时不归因为系统错误。
4. 找不到答案时交付具体的待确认问题，保留对原问题的承接，避免编造时限、价格、可用版本或客服承诺。已有材料相互冲突时标明冲突，给出能确认的范围。
5. 将已有指南的相关章节作为交叉指引，使用真实存在的文件或章节，不伪造链接。检查 FAQ 与指南对角色、版本和结果的说法是否一致。
6. 在用户任务目录保存约定的 Markdown，或完整交付正文并说明未落盘。交出问题来源与产品事实依据，便于后续维护。

## 输出要求

每条应有面向用户的问题、清晰回答、必要条件与操作指引；不为凑数量制造问题。能回答的部分先完成，缺事实部分单独列出。事实来源沿用用户编号或已有索引；没有编号时建立简短可回源索引。
不能自动向客户发送、修改帮助站点或宣称问题已解决。答疑稿的交付和用户实际完成操作分别说明。
