# 版本内容维护

读取用户指定的旧成果与新事实，维护同一产品的说明。需要明确新资料的适用版本或生效范围；缺少旧成果时可以编写新稿，但不能假报已完成全量同步。

## 工作流程

1. 读取旧指南、FAQ、来源索引及新变更材料，确认它们属于同一产品与版本范围。只处理指定范围；多份来源冲突时先保留冲突及可确定的部分。
2. 读取 [修订方法与实例](references/update-method.md)，列出每项新事实影响的章节、问题及条件。区分行为变化、文字澄清与待确认消息；草案不能覆盖已确认规则。
3. 修改受影响的实际正文和交叉引用；只改已证实的变化，不因新说明遗漏旧功能就推断它被取消。历史版资料如仍被用户保留，不悄悄改成新版本。
4. 给出变更说明，逐项包含新依据、受影响位置、修改内容以及仍未确认的范围。不把“需要负责人确认”写成“已批准”。
5. 读回新稿，核对指南与 FAQ 的版本、权限和术语一致。仅在实际读取并修订了全部指定文件后声明同步完成；文件不可访问时说明具体缺口。

## 保存和交付

默认将修订稿写到用户任务目录的新版文件中，保留旧稿；用户明确要求覆盖时按授权处理。无文件工具则交付完整修订正文并说明未落盘。
交付新稿、影响说明与待定问题。未运行软件的实际流程不宣称已经实操验证；不自动发布站点、不定时监控来源、不修改产品配置。
