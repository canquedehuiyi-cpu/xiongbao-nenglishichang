# 文档变更影响方法

逐项考虑权限、版本、输入要求、执行结果与异常。先形成简短映射“新事实→旧位置→应修改内容→依据”，再修改正文，避免只交付建议而未改文档。

用户给出的新材料并非天然权威：产品草案、会议讨论与已经发布的规则分别标记。用户没有指定优先级且存在冲突时，记录冲突并请求决定关键项，先完成不受影响部分。时间较新不自动意味着覆盖所有旧版本。

## 实例

旧版 V1：免费版仅逐人邀请，企业版支持 CSV。旧 guide.md 的“批量方式”和 faq.md 的“为什么不能批量邀请”均引用此规则。

新确认材料 S03：“V2 起所有版本支持 CSV；字段规范另行提供。”

预期交付：

- V2 指南将批量方式改成所有版本可用，标明 V2 与 S03；V1 历史稿保留原适用范围。
- V2 FAQ 回答 CSV 在当前版本可用；不继续让免费用户升级到企业版。
- CSV 字段仍待提供，不能补造字段列表；没有材料证明邀请有效期变化，保持原待定状态。
- 修订说明列出两个受影响位置与各自依据。未拿到旧文件的其他副本，不声称所有渠道均已更新。

可用的修订记录字段：事实/来源、适用范围、旧位置、实际修改、新稿位置、待确认事项。只为本次真实变化填写，避免空模板。
