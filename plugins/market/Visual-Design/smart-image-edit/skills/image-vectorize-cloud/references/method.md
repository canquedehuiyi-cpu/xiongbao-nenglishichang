# 图片矢量化：方法与案例

## 先评估适用性

标志、图标、色块清晰的扁平插画和线稿通常更适合转为路径。照片、细密纹理、复杂渐变和极小文字可能生成大量路径、改变细节或失去自然观感，先解释取舍，再建议是否转换。已有合格 SVG 不重复矢量化，先检查文件。

确认用途、是否保留原色、背景与细节要求。输入标志或图案应有使用权；矢量化不是移除他人权利的方式，也不能把转换称为原创设计。

## 选择处理路径

`vectorize_local` 是浏览器操作：通过 `canvas_get_editor` 打开对应图片与矢量化工具，由用户预览并调整当前界面提供的参数，再按网页报价确认应用与保存。不要把“本地”说成一定免费；入口没有执行副作用不等于应用转换没有费用。不能用 `canvas_run` 模拟浏览器描摹。

`vectorize_recraft` 是云端转换：核对原图字节、边长、像素上限及发布状态，参数当前为空，按真实报价确认并持续查询。不能传不存在的颜色数、路径数或保真百分比。默认不把两条路线都执行，不能静默缩小、裁图或减少颜色以绕过限制。

云端成功直接从 `canvas_get_result(task_id=...)` 领取真实 SVG 及可用预览。`canvas_export` 的格式当前为 png/jpg/psd，不支持 `svg`，不能为下载 SVG 创建额外导出任务。浏览器描摹的 SVG 应按实际网页能力保存或下载，不声称 MCP 已取得该文件。

## 验证真实文件

检查 SVG 根元素、viewBox与尺寸、路径/形状内容、是否只包了一张 raster `<image>`、是否存在外链、脚本或异常 `foreignObject`。安全解析文本，不执行 SVG 中脚本。包含预览 PNG 不代表 SVG 无效，但不能拿 PNG 当作矢量交付；单纯把文件扩展名改成 .svg 不算转换。

放大与缩小比较主体轮廓、负空间、孔洞、色块连接、边缘锯齿和细线。复杂文字常变为轮廓，不承诺仍可按字体编辑；转换结果也不是原始标志母版或 CAD 精确图纸。当前画布可作为整体图像继续调整，不能承诺逐个路径节点编辑器已开放。

文件过大、路径过密、颜色丢失或文字变形时如实说明；仅在用户确认新方法与报价后再尝试其他路径。远程文件检查无法完成时说清未验证项，不把一次成功状态当作全部视觉检查通过。

## 对话示例与异常处理

1. **双色标志转 SVG**：检查源图与授权，建议转换，确认报价后验证负空间、色块和真实路径，交付 SVG 与画布链接。
2. **扁平插画放大**：比较本地预览与云端方案，按用户选择的一条执行，保留主体轮廓与主要色彩。
3. **复杂人像照片**：解释矢量化会风格化，先讨论是否接受；只求清晰时推荐超分思路，不暗中跨工具执行。
4. **已有 SVG 检查**：仅安全读取结构和预览，若只是嵌入位图如实说明，不触发付费处理。
5. **临时 SVG 下载地址过期**：重新取得原任务结果链接，不重复矢量化或调用不支持的 SVG 导出。
