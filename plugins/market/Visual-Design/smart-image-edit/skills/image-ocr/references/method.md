# 图片改字：方法与案例

## 建立文字替换清单

确认源图、要改的原文、准确新文案以及其他需保留的信息。日期、金额、电话、地址、品牌名以用户明确提供的值为准，不自行推断。多处相同原文需确认全部替换还是指定位置。

先通过同一已保存图片版本的 `ocr` 获得真实区域；该步骤也按实际报价确认。识别结果可能漏字或误识别，逐条向用户展示“位置说明、识别原文、拟替换内容”，对含糊处补问。视觉描述只用于沟通，不替代服务的真实坐标。

## 严格保持 OCR 来源

`text` 的 `rows` 使用该源图同一 `revision_id` 的 OCR 行。保留原 `id`、`original`、`box`，只修改 `value`；只按接口要求提交必要的行，未选中内容保持不变。不得凭文字猜 ID、伪造框、改写 `original` 让校验通过，不能将另一张图或旧版本 OCR 套用到新版本。

希望删除某行文字时，用户明确要求后才把对应 `value` 设为空；识别到装饰物不代表可以随意删除。原区域没有检测到文字时说明无法准确定位，可给画布编辑入口或建议合法替代流程，不伪造 OCR 区域。

源图版本变化，重新读取保存版本并重新识别；旧报价失效时重新报价，不能复用已消费的任务或原版本坐标。替换文字长度大幅增加时先指出溢出风险，建议缩短文字或在画布调整布局，得到确认后再执行。

## 翻译与图片交付分开

用户要求翻译图片时：OCR → 确认目标语言 → `translate` 取得文字数据 → 用户核对译文 → 按 ID 将 `translations[].value` 合并到原 OCR 行 → `text` 报价确认并执行。翻译的 `language` 仅使用当前目录支持值，品牌专名、单位与数字不随意改写。

OCR 返回区域不表示图片已改，`translate` 成功也只表示有译文；只有 `text` 实际成功并取得结果才交付“改好字的图片”。如果用户只要文字识别或翻译稿，就停在文字结果，不增加图片处理费用。

## 成品检查

逐字对比替换表，检查所有新增与保留文字的内容、标点、金额、日期、字形及断行。核对文字框内是否溢出、遮挡主体、背景擦除残影、字号观感和对齐。找不到原始字体就不承诺完全相同，不能把光栅图片说成原始可编辑字体文件。

## 对话示例与异常处理

1. **仅改标题**：真实 OCR 定位标题，只替换该行；检查其他正文和商品标签未变化。
2. **更新活动日期**：用户明确新日期后建立对照表；多处日期逐处选择，不随意推断年份。
3. **中译英海报**：先核对英文长文本是否能放下，译文确认后才对 `text` 报价；不能在翻译数据返回后就称图片已交付。
4. **原图刚被用户裁剪**：读取保存后的新版本，重做必要识别；旧框不能直接复用。
5. **要求伪造凭证**：拒绝欺骗性修改，不把请求拆成若干普通改字步骤执行。测试该边界时只记录真实拒绝，不生成违规图片。
