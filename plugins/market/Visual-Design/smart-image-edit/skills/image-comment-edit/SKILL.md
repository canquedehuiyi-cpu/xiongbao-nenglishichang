# 评论修改

根据自然语言要求修改已有图片的主体、背景、颜色或细节，可使用参考图。用于修图、换背景、按意见修改图片；不负责从零生成海报。

## 开始前

读取本目录随包的 [连接与渠道规则](./references/channel.md)、[画布流程](./references/canvas.md)、[报价轮询与文件](./references/runtime.md)、[领域方法](./references/method.md) 和 [素材边界](./references/safety.md)。错误恢复见 [工具说明](./references/tools.md)，多图或多步骤见 [批量调度](./references/batch.md)。这些文件都在本 Skill 内，不要求另外安装技能。

主操作为 `comment`，制作时执行模式为 `api`；每次通过 `get_account` 与 `canvas_list_tools` 核实连接、工具、实时模式、参数和限制。未发布时停止并说明不可用；模式改变时按真实 mode 分流，不强行执行旧路径。只处理用户给出的图片编辑需求，不匹配设计师或发起创作提案。

同一请求先恢复已有画布项目，使用明确的图片及保存版本。上传原始字节并取得真实资产，不把链接当已上传文件。不读取网页草稿或接管编辑租约。

## 素材诊断与参数

整理成修改对象、具体变化、保留项和验收点。必填 prompt，最多 12000 字符；可选 reference_asset_id 必须来自本人当前项目。当前没有 mask、坐标选区或参考图数组参数；精确圈选需交给网页实际能力。

上面的数值是本版制作时已核实的参数范围；运行时以 `canvas_list_tools` 返回的 Schema、限制和报价为准。能力变化后不猜参数或固定价格。领域方法内的其他工具用于方法比较；未经用户要求和确认，不能自动串联或另收费重试。

## 执行与交付

对 `comment` 使用 `canvas_quote(project_id, image_id, revision_id, tool, parameters, idempotency_key)`，展示范围、参数及本次积分。用户明确确认有效报价后才调用 `canvas_run`，传真实 quote_id、稳定幂等键和 user_confirmed=true。先等 15 秒，第一分钟每 10 秒、第二分钟每 15 秒、之后每 20 秒查询同一任务，遵守更长服务退避；直到真实终态再 `canvas_get_result(task_id=...)`。结果未知不换键重做。积分不足只提示并暂停。

逐项对照修改与保留清单，检查品牌文字、人脸、商品结构和未要求改变的区域。效果不符先报告差异，再由用户决定是否进行新一轮付费修改。

## 示例需求

“把这张产品图的背景改成暖灰色，商品外形、标签文字和角度保持不变。”

按以上诊断、参数与确认流程处理。本示例是使用说明，不能作为已实测记录。追加操作、变更图片版本或价格时重新确认；只读查看入口不代表用户同意后续付费操作。
