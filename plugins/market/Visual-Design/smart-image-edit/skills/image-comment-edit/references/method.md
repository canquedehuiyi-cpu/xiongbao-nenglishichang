# 评论修改：方法与案例

## 把反馈写成清晰的编辑清单

读取图片，把意见拆成“目标对象—希望改变—必须保留—验收点”。例如“背景更干净”改成“减少背景杂物与高对比装饰；保留商品轮廓、标题原文和品牌主色”。用户已说清楚时直接整理给其核对，不让用户填写长问卷。

区分内容修改、风格调整和局部修复。多个意见相互冲突时先指出并补问关键一项；同一区域多条意见合并为一致要求。报价前把明确不改的文字、主体、脸部身份和布局写进去，但不能保证模型对保留区域零像素变化。

只想精准替换一行字时先解释 OCR 改字更合适，不能用自由修图假装能逐字保证。若本次确需转用其他画布工具，先说明并征得用户对新操作和报价的确认，不静默跳出专家职责。

## 参考图与标注

`comment` 接受 `prompt` 和可选当前项目 `reference_asset_id`。原图作为被修改图片，参考图说明仅用于颜色、氛围或构图哪一项，不能颠倒主次。参考图先上传并按实际项目回执核对归属；无法确认属于当前项目就停止引用，不直接使用其他项目资产 ID。

自然语言能唯一定位的对象可以文字描述。多个人物、多个相似商品或需要像素级局部蒙版时，先给画布 `comment` 定位入口，让用户点选、框选或画笔标注。MCP 当前没有这些标注的坐标参数；不凭看图虚构 `mask`、`region` 或笔迹传入服务。

网页完成标注与处理后请用户保存，读取结果版本。单纯打开标注入口不等于已提交修改。后续新的修改沿用用户选定的结果版本；对比两个版本只是检查，不自动发起第二次付费任务。

## 结果检查

逐条对照编辑清单：目标区域是否改变、修改强度是否合适、主体结构与数量是否一致、保留文案是否完整、其他区域是否出现额外物体或不自然接缝。检查人物手部、脸部和商品标签等易变部位；有原本不可辨认内容时不编造正确答案。

把已完成与需调整项分别说明，并附真实画布入口和作品。若结果有小瑕疵可提出下一步建议，只有用户要求继续修改并确认新报价才执行，不把质量检查自动变成付费循环。

## 对话示例与异常处理

1. **海报减噪**：保留标题、商品、品牌色，减少背景装饰；修改后先逐字核对原文，再看商品边缘和背景接缝。
2. **参考氛围**：图一是原图，图二只参考暖色灯光；核对资产归属后提交，不能把参考图中人物或文案移进来。
3. **“把这个去掉”但对象不明**：询问对象或打开原图标注入口，不任意猜测后执行。
4. **只点评新版本**：读取真实图片，对照原意见列差异，不上传、报价或运行新的修改。
5. **修改提交后断线**：恢复原任务与原版本，查出是否完成；不重建相同修改，也不从历史余额猜本次是否扣费。
