# 图片变清晰：方法与案例

## 判断问题与使用目标

先看原图真实尺寸、压缩痕迹、失焦、运动模糊、噪点、细小文字和透明通道。确认用于屏幕展示、进一步设计还是打印，目标尺寸不明确时按使用位置提出适当建议，不默认最高档。

超分提升像素和可感知细节，不是找回已丢失的真实信息。严重失焦、被遮挡文字和极低分辨率人脸无法保证准确恢复；不要把生成细节用于身份证明、证据还原或辨认未知人物。

## 选择规格

`upscale_tencent` 为倍率路径，`upscale_wavespeed` 为分辨率档位路径；面向用户说“倍率清晰化”和“高清档位”，展示当前目录公开规格即可，不输出内部模型路由。

读取 `capabilities.specs`、图片大小与长短边限制、透明支持以及报价。参数按实时 Schema：倍率使用 `scale`，档位使用 `resolution`。两条路线比较后只选一条，不串联两次超分、不擅自缩小再放大以绕过输入限制。存在尺寸或格式限制时先说明并取得处理决定。

透明输入遇到 `alpha=false` 时说明透明区域无法按该路径保留，用户决定是否接受明确的背景处理；不能偷偷铺白再称为透明交付。目录列出规格但未给出独立价格时以该规格实际报价或返回错误为准，不能推算。

输出实际宽高从结果文件核对，不把“4K”强行解释为固定 3840×2160 或改变原有比例。高分辨率原始结果按实际文件链接交付；超出合成导出尺寸限制时不要重复导出或宣称不存在的更大文件。

## 质量检查

先整图对比构图和比例，再在同等显示比例及局部放大下检查：商品细节、文字数字、皮肤与发丝、边缘锐化、重复纹理、噪点、色偏和条纹。区分“尺寸提高”和“细节确实改善”，过锐光晕或塑料皮肤都需说明。

有文字的图片逐字核对可辨认原文，不把错误补字当清晰化成功；极小文字仍不可辨认时如实记录。老照片重点保持身份和原有神情，避免承诺完全还原。

## 对话示例与异常处理

1. **商品网页大图**：看原尺寸和展示位置，推荐足够的规格，报价后只处理一次，核对商品标签和纹理。
2. **老照片**：明确这是清晰化预览，比较人脸和衣物细节；不擅自美颜、换脸或改年龄。
3. **含价格的海报**：核对金额、小数点、日期和标题，若生成伪字则指出，不把结果当可直接发布。
4. **透明 PNG**：先检查当前路径透明支持，不支持则告知限制并等待选择，不自动转换 JPG。
5. **用户只要求评估**：说明可期待改善与无法恢复的部分，推荐参数但不直接付费执行。
