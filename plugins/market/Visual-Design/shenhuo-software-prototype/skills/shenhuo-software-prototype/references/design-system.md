# 从采用图提取DESIGN.md

以用户已采用的实际图片为视觉来源。先核对 [总览页](design-board.md) 当前整组已明确确认、图片版本与哈希一致；基准页单独采用或整组仅生成成功都不算此条件。用户已明确提供全套批准稿时沿用真实依据。然后打开图片，创建简洁的 [DESIGN.md](../templates/DESIGN.md)，记录采用图路径、对应页与目标CSS视口，保障之后实现能追溯。

## 提取方法

| 观察 | 写入规范的可用内容 |
|---|---|
| 页面整体 | 明暗、信息密度、留白、视觉重心、各页共同特征 |
| 色彩 | 背景、表面、正文、次要文字、边框、主动作、状态色；HEX可估测并标记 |
| 文字 | 字体类别及可用替代、标题／正文／辅助字级、字重、行高，不假称识别出商业字体 |
| 布局 | 页边距、内容宽度、导航、栏数、列宽比例、列表密度、手机底栏和安全区 |
| 间距与形状 | 共同间距阶梯、按钮高度、圆角、分隔线、阴影强度 |
| 组件 | 导航、按钮、卡片、列表、表单、标签、弹窗和状态的真实样式 |
| 交互补缺 | hover、focus-visible、按下、禁用、错误、空态／加载，仅补本次核心流程需要的项 |
| 响应式 | 目标视口及相邻宽度的重排、文字换行、横向滚动、固定导航避让 |

从光栅图估计CSS值不是精确设计稿测量。可取相近值形成少量共享CSS变量，再在浏览器对比校正；对比结果和用户决定优先于估测。可读性、焦点和点击区域按通用UX原则补齐，但不借此替换整套风格。

## 冲突处理

用户最新明确视觉决定优先于旧图；各页采用图优先于通用风格推荐。跨页同类组件略有不一致时优先沿用代表页的共同规则，记录小差异；明显矛盾会改变观感时向用户指出具体组件并给建议，不默默重设计。若变更影响主要视觉，先返回神火生成新版并确认，再更新规范。

DESIGN.md应短且可执行，不写完整设计系统百科，不引入框架架构或组件库选型。色板与字体必须来自当前采用图，而不是从通用风格库随机选择。规范更新后同时更新受影响页面基线，浏览器验证记录也要重新对应当前文件。
