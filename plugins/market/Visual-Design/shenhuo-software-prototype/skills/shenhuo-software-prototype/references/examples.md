# 典型任务与预期行为

| 输入情境 | 应做的事 |
|---|---|
| “做一个宠物寄养预约App” | 简短问主要用户、核心预约流程；建议列表→详情→预约结果。手机代表页经神火生成后让用户看图，再扩展，不追问数据库和支付网关。 |
| “这是需求，要手机下单、PC店员管理” | 保留已有内容，给双端页面表；手机竖版与PC横版分开任务和报价，保持品牌语言一致。 |
| “第二页太挤，主按钮放底部，其他别改” | 读取第二页对应原图；同一设计师新建仅一页的参考改版任务，原话传递，新的有效报价确认后生成，保留旧稿。 |
| 基准页r02已采用，其余4页已生成 | 总览只展示基准r02和4个页面，每张标名称；用宿主预览工具在预览区打开HTML，不把r01作为第6页。等待整组确认。 |
| 新版生成成功，用户尚未评价 | 在同一总览替换该页为最新图、标待确认，保留历史采用记录，不直接覆盖DESIGN.md或功能性HTML基线。 |
| “统计和我的两页改一下，其他别动” | 只生成这两页；每张真实下载后更新对应卡片并刷新同一总览，未改页保持，整组通过状态重新待确认。 |
| 两页修改中有一页失败 | 总览更新成功页，失败页保留旧图并明确说明，查询原失败任务，不用占位图冒充新版。 |
| 账单和统计v2已下载，但总览还显示v1 | 本轮尚未完成：立即用真实v2清单update、check --expected，再刷新同一预览区入口并看到v2；不重新生图，也不先询问进入实现。 |
| 用户确认报价或说“这一页可以” | 只记录对应范围，继续总览审阅；不等同于认可当前整组并指示进入下一步。 |
| “这三张就用它，开始做HTML” | 对应三页记录真实整组确认；从图片提取规范、写DOM和跳转，检查后交付，无需再次逐页批准。 |
| “图已经确认，直接做HTML”，图片由用户提供 | 标记user来源、保存哈希，不伪造神火ID，不要求重新付费生图。 |
| “继续下载刚才的第三页” | 查询原生成任务／variant；领取新票据下载，不重新建项或生图。 |
| “登录后进入列表，详情可返回，提交后出现成功页” | 用模拟登录和表单状态实现全部跳转与返回，逐条实际点击；不接真实账号或后端。 |
| 需求讨论时连接器不可用 | 继续需求、页面表；图片阶段再恢复原连接，不以未授权阻断全部任务。 |
| 浏览器不可用，但文件已完成 | 说明预览未验证，交付启动方式；若交付脚本允许未验证包，保留not_run／partial记录，不能称通过。 |
| 最新HTML文件被修改，但验收记录来自旧版 | 重新检查受影响页面和流程并更新文件指纹，不复制旧passed状态。 |
| 用户只要求手机 | 不擅自增加PC页面、双端任务或额外收费。 |

这些是流程示例，不是已发生的神火出图或Qoder验收记录。
