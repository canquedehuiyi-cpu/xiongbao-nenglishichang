# 软件原型建项规格

先读取本次get_designer与工具Schema，核对用户需求、已采用风格及本轮终端。该技能编写时已确认以1.5K作为首选，手机通常9:16，PC通常16:9或16:10；这些是软件原型的默认建议，用户明确设备或比例要求优先，实际值必须被当前设计师与工具支持。

本技能在轻量需求阶段已选定的终端、比例与清晰度属于本次明确规格。不要因为用户这一句话没重提比例，就丢掉已有需求而省略image_spec；也不要把服务的auto默认套给已确定的手机或PC页面。尚未确定PC比例时可按当前页面内容提出16:9或16:10建议，沿用用户已认可的选择，不重复询问已确认结论。

当前image_spec只接收两个必填字符串：resolution与aspect_ratio。例：已确认手机1.5K、9:16时，传`{"resolution":"1.5K","aspect_ratio":"9:16"}`。不同终端或比例分开建项，不在一个冻结规格任务中混生成。

- 两项已在本次需求确定：同时传入，并核对实时支持值。
- 用户只改其中一项：保留另一项的当前需求值；如果确无当前需求值，才从本次get_designer默认补齐，将回执resolution_tier映射为输入resolution。
- 用户明确要求全部跟随设计师当前默认、且无相冲突的设备要求：可省略整个image_spec；不能传空对象或null。
- 必需默认字段缺失或规格不支持：重新查询；仍不明确则说明阻塞，不猜值或静默改变用户约束。

不把输出对象的resolution_tier、width、height或size直接作为建项输入字段。图片像素与HTML的CSS视口分别记录；自定义像素请求无法表达时先说明并核对受支持方式，不拉伸参考图冒充原尺寸。

只有明确返回未受理的参数校验错误，才修正字段后沿用原建项幂等键重试。网络超时或结果未知先查原操作，不能改参重放或换键重建；已受理任务改变规格属于独立新任务，重新报价确认。
