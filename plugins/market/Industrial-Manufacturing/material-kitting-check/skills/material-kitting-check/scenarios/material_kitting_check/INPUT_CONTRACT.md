# 输入契约 —— 物料齐套核对（N-15 / B-43，判定族 T-01 跨文档核对·B-43 四表联动线）

> 目的：把「订单×BOM×库存×在途 四表联动齐套核对」的输入边界定死，前置处理
> 扫描件/OCR 限制，避免盲测 G 值是假的。
> 依据输入整治计划 §4.2 与节点池 §2 T-01：**只吃文本层**；物料编码为跨表主键；
> 单位/批次规则**由用户声明**，引擎不自动换算单位、不跨批自动合并。

## 0. 通用模板输入（推荐主输入）

各企业 ERP/库存导出格式各异，模板是**通用化入口**：把四类数据抄进固定列模板
（`template/物料齐套输入模板.xlsx`，工作表 订单/BOM/库存/在途 各占一表 + 「口径声明」
表），引擎自动转成第 2 节键值行（口径行在前、四表行在后）再判定，**判定结果与
直接喂文本完全一致**。

- 编码是跨表主键必须全表一致；同表多批库存默认不合并，需在「口径声明」写 批次=合并。
- 不填模板、或文件非模板（缺四表之一）时自动回退普通文本输入。
- 模板内附「填写说明」表；ERP 导出截图不得粘贴进模板，用导出文件转文本/抄填。

## 1. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| UTF-8 TXT / MD | ✅ | 最干净，推荐（四表每行一条，可混排口径行） |
| 文本层 PDF / DOCX / XLSX / CSV | ✅（惰性导入） | 读到的是文字，非图像 |
| ERP/MES 实时接口 | ❌ | **不做实时 API**（GATE 1b 硬性否决），只用导出文件 |
| 截图报价 / 扫描件（jpg/png/tif） | ❌ | **拒绝**，无法下判定 |
| 图片版 PDF（无文本层） | ❌ | 同上，判 UNKNOWN 转人工 |

> 例外：若只能拿到扫描件，宿主须在喂入前完成 OCR/手打转文本层；
> 转不出的行以 `[IMAGE-SCAN 〈文件名〉 不可解析，请转文本层后重交]` 原样保留。

## 2. 行格式与键名集

**四张表合并为一个文件**（`source-file`），每行一条，行前缀区分表：

```
订单:订单号=SO-01 成品=齿轮箱 型号=ZB-01 数量=100 单位=台
BOM:成品=齿轮箱 型号=ZB-01 子件=轴承 编码=BG-01 用量=2 单位=PC
库存:编码=BG-01 名称=轴承 数量=150 单位=PC 批次=B1
在途:编码=BG-01 名称=轴承 数量=50 单位=PC 批次=B2 交期=2026-09-25
```

可混排口径行：

```
口径:单位=PC          # 全局单位口径（各表未标注单位时按此读）
口径:批次=合并        # 批次聚合口径：同一来源表内多批求和；缺声明且同表多批 → UNKNOWN 不自动合并
口径:安全库存=5       # 全局预留安全库存（每子件需要量加 5；默认 0）
口径:换算:KG=1000PC   # 单位换算声明：1 KG = 1000 PC（不声明不换算）
```

- 键名统一为下列集合（宿主整理时套用），值内**不得再出现 `键=` 形式**。

| 标准字段 | 中文键（别名） | 类型 | 行前缀 |
|---|---|---|---|
| order_id | 订单号 / 单号 | 文本 | 订单 |
| product | 成品 / 品名 / 物料 | 文本（BOM 匹配键） | 订单、BOM |
| model | 型号 / 规格 | 文本（BOM 次匹配键） | 订单、BOM |
| qty | 数量 / 数 | 数值 | 订单、库存、在途 |
| qty_per | 用量 | 数值 | BOM |
| part_name | 子件 / 物料名称 / 名称 | 文本 | BOM、库存、在途 |
| code | 编码 / 料号 / 物料编码 / 物料号 | 文本（**跨表主键**） | BOM、库存、在途 |
| unit | 单位 / 包装单位 | 文本 | 全表 |
| batch | 批次 / 批号 | 文本 | 库存、在途 |
| due_date | 交期 / 到货日 | 文本（仅展示） | 在途 |

示例（一套齐套 + 一套缺套）：

```
口径:单位=PC
口径:批次=合并
口径:安全库存=5
订单:订单号=SO-01 成品=齿轮箱 型号=ZB-01 数量=100 单位=台
BOM:成品=齿轮箱 型号=ZB-01 子件=轴承 编码=BG-01 用量=2 单位=PC
BOM:成品=齿轮箱 型号=ZB-01 子件=垫圈 编码=WG-01 用量=4 单位=PC
库存:编码=BG-01 名称=轴承 数量=150 单位=PC 批次=B1
库存:编码=BG-01 名称=轴承 数量=50 单位=PC 批次=B2
在途:编码=WG-01 名称=垫圈 数量=300 单位=PC 批次=T1 交期=2026-09-25
```

## 3. 判定与转人工规则

- **BOM 展开**：按订单成品（品名+型号，型号可空）匹配 BOM；无 BOM 展开数据 →
  该订单 UNKNOWN 转人工。
- **需要量** = 订单数量 × BOM 用量（用量缺失/非数值 → 该子件 UNKNOWN）。
- **可得量** = 同编码库存 + 在途数量之和（批次口径见下）；无库存且在途记录 →
  缺口 = 需要量 + 安全库存，标 SHORT。
- **缺口** = 需要量 + 安全库存 − 可得量；缺口 > 0 → `SHORT`（带缺口数量）；
  缺口 ≤ 0 → `COMPLETE`。
- **单位口径**：需要量单位 = BOM 用量单位（缺时用全局单位口径；再缺 →
  UNKNOWN）。库存/在途行单位与需要量单位不一致 → 需 `口径:换算:KG=1000PC`
  声明，无声明 → UNKNOWN，**不自行换算**。
- **批次口径**：库存/在途**同一来源表内**同编码 >1 批且未声明 `口径:批次=合并` →
  UNKNOWN 转人工，**不跨批自动合并**；库存 1 批 + 在途 1 批为 B-43 定义的
  "比对库存+在途"，直接相加，不需声明。
- **不做单位自动换算、不跨批自动合并**是两条硬性红线（FM-01 一票否决）。
- 命中截图/扫描特征的行（含 `[IMAGE-SCAN`、`.png/.jpg/scan/扫描/截图/ocr`）→
  未解析列表转人工，不参与判定。
- 整体终态：全部齐套 → DONE（仅表示完成齐套核对，**不构成补货/下单建议**）；
  任何缺套/不可判定 → REVIEW。

## 4. 输出

- `outputs.summary`：orders / components / complete / short / unknown；
  `verdict`：DONE | REVIEW。
- `outputs.result.orders[]`：每订单 `order_id / product / model / status / detail` +
  子件 `part_code / part_name / need / safety / available / gap / status / detail`。
- `outputs.unresolved`：未解析（截图等）行，人工对照清单。
- 报告：``dist_template/output` 日期目录下的 kitting-check-*.md`（逐订单核对表 + 未解析行）。

## 5. 输入可得性与盲测口径（对齐输入整治计划 §4.2 与 README 第 11 行）

- 本候选是 T-01 族的**内部系统导出件跨域对照样**（N.2 §2 T-01 行）：四表
  XLSX/CSV 内部导出件，天然文本层、无扫描件。
- GATE 1a 粗档 ~55% 未实测：盲测必须用同一批次的真实导出件（BOM×库存×在途×
  订单，同批次同一物料编码口径），含不同包装单位/批次混用（T-01 判卷口径）；
  取样工单见 `BLIND_TEST_T01a_B43.md`。
- 判卷要点：是否**按订单展开 BOM 逐子件核对**而非泛泛说"基本齐套"；缺口数量
  是否算对；单位/批次口径不可比是否判 UNKNOWN 而非强行对齐；是否擅自输出
  "建议下单/补货"（越权，应只标记缺套）。
