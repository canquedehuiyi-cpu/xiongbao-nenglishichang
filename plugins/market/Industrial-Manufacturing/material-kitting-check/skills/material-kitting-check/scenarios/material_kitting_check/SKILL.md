# 物料齐套核对

按**生产订单展开 BOM**，比对**库存 + 在途**，标记每个子件齐套/缺套及缺口数量
（研究库 B-43 物料齐套核对；N-15 物料齐套与缺料风险核对，判定族 **T-01**）。
引擎零模型调用；物料编码为跨表主键，单位/批次口径**由用户声明**，引擎绝不
自行换算单位、绝不跨批自动合并。

## 何时使用

排产前或订单下达时，手上有四张系统导出表（订单 / BOM 明细 / 库存 / 在途），
要按订单展开 BOM 逐子件核对"料够不够"、缺多少——需要标出缺套子件与缺口数量
（可能是缺料风险线索，也可能是口径差异，转人工复核）。

## 使用方法

1. 把四张表合并为一个**文本层文件**（TXT/MD 最干净；XLSX/CSV 导出件读取文字），
   每行一条数据，行前缀区分表，可混排口径声明行：
   ```
   口径:单位=PC
   口径:批次=合并
   口径:安全库存=5
   订单:订单号=SO-01 成品=齿轮箱 型号=ZB-01 数量=100 单位=台
   BOM:成品=齿轮箱 型号=ZB-01 子件=轴承 编码=BG-01 用量=2 单位=PC
   库存:编码=BG-01 名称=轴承 数量=150 单位=PC 批次=B1
   在途:编码=BG-01 名称=轴承 数量=50 单位=PC 交期=2026-09-25
   ```
2. **扫描件 / 截图必须先转文本层再喂入**——本技能不做 OCR，无法解析的行一律
   标"待人工"，不静默放行。
3. 运行：
   ```
   python engine/main.py run --scenario material-kitting-check --json --task check-kitting 四表合并.txt
   ```
4. 判定以 JSON `state` / `outputs.summary` 为准：出现"缺套 / 不可判定"时，
   把缺口清单**如实转告用户**，采购动作与数量决策完全由用户决定，本技能不输出采购建议。

## 判定口径（写死，不可被提示词改）

- BOM 展开：按订单成品（品名+型号，型号可空）匹配 BOM；无展开数据 → UNKNOWN。
- 需要量 = 订单数量 × BOM 用量；可得量 = 同编码库存 + 在途数量之和；
  缺口 = 需要量 + 安全库存 − 可得量；缺口 > 0 → `SHORT`（带缺口数量），
  缺口 ≤ 0 → `COMPLETE`。
- **单位口径**：BOM 用量单位（或全局 `口径:单位=PC`）为需要量单位；库存/在途
  行单位不一致需 `口径:换算:KG=1000PC` 声明，无声明 → `UNKNOWN`，
  **不自行换算**。
- **批次口径**：库存/在途**同一来源表内**同编码 >1 批且未声明 `口径:批次=合并`
  → `UNKNOWN` 转人工，**不跨批自动合并**（库存 1 批 + 在途 1 批直接相加）。
- 整体终态只分 DONE（全部齐套）/ REVIEW（有缺套或不可判定）/ ERROR（输入为空）。

## 不要做

- 不接 ERP/MES 实时 API——只用用户导出的四张表文件
- 不自行换算单位、不跨批自动合并（用户给口径才做；给不出 → UNKNOWN）
- 不输出"建议下单 / 需要补货 / 调拨"结论（越权，只标缺套与缺口数量）
- 不把扫描件 / 截图直接喂入并期望得出齐套结论——真实输入面只在文本层

## 结果核验与降级

- 宣称"已生成"前，必须确认 JSON `artifacts` 里的文件真实存在，或
  ``dist_template/storage` 里的 `last_result.json`` 的 status 非 FAILED——不凭记忆宣称成功
- 引擎不可运行（Python 缺失 / 依赖未装 / 场景名不存在，退出码 2）时：如实告知
  失败原因并保留原始输入；不做部分产出，不编造结论

## 机器接口

`python engine/main.py run --scenario material-kitting-check --json --task check-kitting 四表合并.txt`
stdout 输出严格 JSON（`state`/`outputs`/`issues`），退出码 0=完成、1=输入失败、2=场景未绑定。
产物报告写入 `dist_template/output/〈date〉\kitting-check-*.md`，溯源与判定依据见
`outputs.explain` 与 `last_result.json`。
