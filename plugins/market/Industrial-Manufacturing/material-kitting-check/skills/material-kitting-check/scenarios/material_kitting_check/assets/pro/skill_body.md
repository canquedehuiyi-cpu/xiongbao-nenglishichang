# 物料齐套核对

## 何时使用

当需要按生产订单展开 BOM、逐子件核对库存+在途是否齐套、标出缺口数量时使用。
典型场景：排产前齐套检查、订单下达前缺料风险预核——手上有订单/BOM/库存/在途
四张系统导出表，要标出缺套子件与缺口数量。

## 使用方法

1. 把四张表合并为一个文本层文件（TXT / MD 最干净），每行一条数据，行前缀
   区分表：`订单:订单号=… 成品=… 型号=… 数量=…`、`BOM:成品=… 子件=… 编码=… 用量=…`、
   `库存:编码=… 名称=… 数量=… 单位=… 批次=…`、`在途:编码=… 数量=… 交期=…`，
   可混排口径行 `口径:单位=PC`、`口径:批次=合并`、`口径:安全库存=5`、
   `口径:换算:KG=1000PC`
2. 扫描 / 截图件务必先转文本层——本技能不做 OCR，无法解析的行会全部标为
   「待人工」，不静默放行。
3. 运行：`python engine/main.py run --scenario material_kitting_check --json --task check-kitting 四表合并.txt`
4. 结果写入 ``dist_template/storage` 里的 `last_result.json``，报告在 `dist_template/output/` 目录；出现「缺套 /
   不可判定」提示时，把缺口清单如实转告用户，下单/补货等采购动作与数量决策完全由用户决定，本技能不输出采购建议。

## 不要做的事

- 不要接 ERP/MES 实时 API——只用用户导出的四张表文件
- 不要自行换算单位 / 跨批合并：用户给口径（如 `口径:批次=合并`、`口径:换算:KG=1000PC`）
  才做，给不出 → UNKNOWN
- 不要替引擎下结论：判定只认 `dist_template/output/*.md` 报告与 JSON `state`；
  不输出采购 / 补货 / 调拨建议性结论
