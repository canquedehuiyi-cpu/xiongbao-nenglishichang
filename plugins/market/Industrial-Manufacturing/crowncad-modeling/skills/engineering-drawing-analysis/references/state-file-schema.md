# 工程图分析记录约定

需要留存图纸分析依据时，在当前 runs 维护一份 `analysis/analysis_notes.md`。它保存图纸事实、必要判读和未解决问题，不维护 CAD 执行或验收状态。九阶段分析方法仍见本技能主入口。

## 按需记录的内容

```markdown
# 工程图分析记录

## 图纸来源与视图
<图号、页码/修订、原图的任务内路径；必要时说明视图对应关系>

## 关键结论及依据
<对象、结论、来源页/视图或裁剪图；区分图纸明确、推导、用户指定和未确定>

## 必要的判读和推导
<只解释影响建模且需要保留的理由、公式和前提，不复制完整参数表>

## 尚未解决的问题
<缺少什么、已经查过哪里、影响哪些结论；解决后更新原条目并注明依据>
```

按需要使用栏目，不填空表，不写逐阶段流水账，不要求给事实、视图、证据、对应组和问题另设 ID。复杂视图对应可以用简短表格；记录对象名称、各页/视图位置、对应依据、实际约束及缺失或冲突。

## 来源和确定程度

- 原图、裁剪图等位置用任务根目录相对路径文本，例如 `inputs/drawing.pdf`、`analysis/crops/port.png`；记录页码、视图和必要局部区域。README 提供实际文件的点击导航，避免嵌套记录中的链接指向错误位置。
- 图纸明确的信息保留原标注及对象归属；推导保留前提和必要公式。用户指定的值注明决定来源，不冒充图纸原标注。未知内容明确写未确定，不能用零、猜测或暂定解释替代。
- 视图对应必须有投影、中心线、尺寸或剖视等依据；各视图只提供其实际支持的约束，缺失信息和矛盾单独说明。
- 图纸记录解释来源和判读，操作图继续按原要求维护实际采用的设计。必要数值可用于说明依据，不复制整套设计参数或建模进度。

## 问题、人工决定和更新

未解决问题写明缺少的信息、已检查的视图/区域和影响。影响目标的关键问题解决前，暂停依赖该信息的结论，不宣称完整交接。

用户答复原话及时间、简化授权、保留项和影响保存在 README 的人工记录；notes 只注明采用结论和该记录位置。原问题解决后更新原条目，复核受影响结论，保留必要修正依据，避免一处已确认、另一处仍缺失。不同解释须经证据核查后采纳。

不维护阶段进度数组、“可交接”状态字段或另一份几何交接 JSON。仅在必需信息和相关一致性检查均通过后完整交接；图纸判读完成不等于 CAD 验收通过。
