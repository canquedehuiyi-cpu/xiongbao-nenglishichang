# 执行流程

本文件说明建模顺序和浏览器访问；检查工具及验收方法见[验证流程](verification-workflow.md)。工具选择和执行范围服从调用方已明确的授权与限制；本文不能授予额外权限。

## 1. 文档上下文、生成物及累计执行

先理解用户目标、尺寸和约束，按 [案例参考与保存](../../modeling-case-library/references/case-workflow.md#2-开始任务先看案例再决定方法) 查看相关案例，再确定本次方法。随后生成任务 UUID，按语义完整的设计部分划分操作图阶段，列清各零件要求、检查时机、必需特征和后续依赖。阶段不按命令数量拆分；执行前按草图参考核对平面、槽和轮廓。

完整提供 `documentId + versionId + docType` 时复用既有文档；只提供其中一部分时要求补齐；三项均未提供时采用新建模式。

**执行前消除可避免的返工。** 二维图先按实际需要放大关键局部，交叉核对各视图的尺寸端点、台阶厚度与剖切关系，并把明确/推导/待确认项记入已有操作图；不能把首次核读关键厚度留到依赖它的特征做好之后。阶段以完整结构及其检查依赖划分，可独立核验的同类操作在引用有效时合并，不为每个圆角或单条调用单独建阶段。确需新增阶段时更新原计划，不另建阶段管理文件。

新单文档零件任务先通过 `scripts/run_files.py init` 在 `generated/runs/<模型语义>__<任务UUID>/` 建立任务目录，再准备初步操作图和 README 草稿。同一单零件任务如果已在读图时初始化，进入建模时直接复用，不再次 init。初始化仅准备本地资料；适用范围与历史资料处理见下节。运行资料均写入该目录，不在工程根目录输出通用生成脚本。README 维护及正式归档按 [案例参考与保存](../../modeling-case-library/references/case-workflow.md) 执行。

文档创建与复用按第 2 节确认的上下文执行。首次按已确定的操作图构建，后续正常新增默认追加；仅在修改已有结构、执行失败或状态不一致时重新判断局部修改或必要的覆盖重建。目标变化时同步完整累计脚本，建模执行保存本次实际提交内容。

脚本、实际执行结果和修改说明保存在本任务 runs 内。公共程序更新固定用途文件，README 链接完整源码、当前状态与报告，不单独维护另一份通过状态。具体记录与保存要求见 [案例参考与保存](../../modeling-case-library/references/case-workflow.md)。

需要选面、选边或核验实际几何时，按 [拓扑规则](entity-modeling/details/topology-and-features.md) 查询当前模型；后续修改影响已有数据或验收证据时重新检查。执行失败按 [第 4 节](#4-失败未验证和恢复后的处理) 处理。

### 1.1 累计源脚本、阶段与修订

**CAD 执行、响应和验证入口的适用范围：新建的单文档零件任务。** 本地 `init` 和 `scope=input_analysis` 的图片保存也可用于建模前或纯图纸分析，不要求先有 CAD 文档、模型代码或操作图。`init` 不创建 CAD 文档、不接管现有目录；历史任务保留原阶段/修订资料，不自动迁移或清理，多文档及装配仍使用各自现有流程，不共用一套单文档执行状态。以下涉及 CAD 的公共保存示例仍限于单文档零件。资料格式由程序自动识别，不需要 Agent 选择格式编号或手写状态；入口提示格式不支持或状态损坏时，保留现场并报告，不能补标记、改状态或切换旧流程绕过检查。

每个文档维护一份 `model.crownscript.js` 当前完整源码，新增或修改时局部编辑；用注释标注结构、尺寸依据、方向和依赖，不混入失败尝试、旧尺寸、重复创建和易过期的通过声明。存在中途查询依赖时，标明“初始覆盖 → 查询当前引用 → 追加后续片段”的边界；重建时重新取得实际 ID，不能依赖旧拓扑或跨请求普通变量。

能连续完成且无需外部信息的操作合并；需要新引用、真实平面、关键检查或必要展示时保留阶段边界。修正属于当前阶段，不因文件保存或参数调整另起阶段，不改阶段名规避修正上限。

**按用途固定保存，不按执行次数建目录：**

| 文件 | 用途 |
|---|---|
| `model.crownscript.js` | AI 维护的完整设计，完整不等于重建已经实测 |
| `runtime/submitted.crownscript.js` | 本次实际提交：追加仅新增/已确认修改片段，覆盖才是完整重建内容 |
| `runtime/request.json`、`runtime/response.json` | 配套的实际文档、overwrite、代码指纹和安全响应 |
| `runtime/state.json` | 公共程序管理的当前执行、证据及检查状态 |
| `analysis/` | 一份精简的 `analysis_notes.md`、必要图纸裁剪及参考模型视图；notes 由 AI 编辑，运行状态仍由公共程序管理 |
| `evidence/` | 实际 CAD 拓扑、几何、必要子集、截图和证据包 |
| `reports/verification.json`、`reports/verification.md` | 同一份当前标准检查报告 |

没有用途就不生成。新流程不生成 `.work` 或同类中转目录；内容直接交给公共入口。不默认建 output、STEP、acceptance.md、final 副本、编号执行目录或任务专用 build.py/verify.py。复杂任务可保留一个纯计算/代码生成入口，但它不写执行和验收状态。

完整源码未按其边界实际重建并检查时，说明“完整源码已整理，重建未实测”；分段重建与单次完整执行分别表述。不能为补验证标记重复覆盖正确模型。覆盖已有模型前仍核对允许替换范围及未纳入源码的人工修改。

**公共模块由仓库提供，Agent 不现写文件管理员。** 保持任务工作区为当前目录，`<skill_dir>` 替换为执行器技能实际绝对路径，可用 `--help` 查看参数：

```text
python -B "<skill_dir>/scripts/run_files.py" init --workspace <工程目录> --name 支座
python -B "<skill_dir>/scripts/run_files.py" prepare --root <init返回的任务目录> --document-id <实际ID> --version-id <实际版本> --overwrite false --purpose holes --stdin
python -B "<skill_dir>/scripts/run_files.py" save-result --root <任务目录> --operation-id <prepare返回的编号> --outcome responded --stdin
```

prepare 示例为追加孔系；已确认空白文档的初始构建使用 true。Python API 直接接收内存对象；CLI 的 `--stdin` 接收一份 UTF-8 JSON，不先写输入文件，旧 `--*-file` 参数拒绝。源码字符串不裁剪、不改换行，正式目标由程序决定。prepare 成功后，Agent 才调用原 MCP `execute_program`，使用其返回路径中的同一份代码及固定参数，不临时另改代码。不把本地 operation_id 增加到 MCP 参数，不读凭据。

| 子命令 | 标准输入对象（只传输，不另存为文件） |
|---|---|
| prepare | `{"code": "本次实际提交代码"}` |
| save-result | `{"result": 实际MCP结果}`；无返回用 `null` |
| save-evidence | `{"data_base64": "原始字节的Base64", "source": 原来源对象}` |
| save-report | `{"report": 原报告对象, "source_fingerprint": 原来源指纹对象}` |
| resolve | `{"evidence_refs": 原回查路径与哈希对象}` |

宿主传输示例：`subprocess.run([sys.executable, "-B", str(run_files_path), "prepare", "--root", str(task_root), "--document-id", document_id, "--version-id", version_id, "--overwrite", "false", "--purpose", "holes", "--stdin"], input=json.dumps({"code": actual_increment}, ensure_ascii=False).encode("utf-8"), capture_output=True, check=True)`。`actual_increment` 仅是本次片段；累计完整源码仍单独维护。`init`、`clean` 不读标准输入。结果到达后立即保存，不另备份同内容返回；保存前宿主退出仍按 awaiting_result 回查，不能据此重发。

执行顺序：更新完整设计/参数/操作图 → prepare → 原 MCP → save-result → 必要回查 → save-evidence → 公共测量及 build_report → save-report → clean。程序不替调用方发网络请求，也不能阻止绕过入口的程序直接写磁盘。

取证前保存当时的 operation_id、document 和 input_fingerprint。`save_evidence` 的 source 例如：

```json
{
  "tool": "query_topology_geometry",
  "document": {"document_id": "实际ID", "version_id": "实际版本", "doc_type": "PartDocument"},
  "operation_id": "查询开始前取得的本地编号",
  "coverage": {"entities": [42], "fields": ["Curve", "Surface"]},
  "artifact": {"byteSize": 123, "sha256": "实际下载资料的64位SHA-256"}
}
```

`coverage` 按真实查询填写，不把示例 ID 当实际引用。当前模型 scope=current_model；必要过程展示 scope=required_process，按用途分别保存；裁剪/参考图 scope=input_analysis，source 带原始 source_sha256，裁剪再带 `[x,y,width,height]`。图片格式和尺寸由程序解码核对。主 topology/geometry 的 purpose=main；必要不同子集用 kind=query、各自 purpose；用途仅小写字母、数字、下划线、短横线，最长64字符。

`save-evidence` CLI 接收 `--kind --purpose --scope --stdin`；文档创建响应使用 kind=document、purpose=main、scope=required_process、source.tool=create_document。下载字节的 artifact 哈希与正式入库文件哈希可能不同：JSON 脱敏/格式化后，以实际入库文件哈希绑定报告。

报告 source_fingerprint 由取证前的 operation_id/input_fingerprint，加上**实际入库**证据相对路径到 SHA-256 的映射组成。`save-report --stdin` 固定写 reports，不能事后取新指纹给旧证据补身份。`clean` 默认只预览，`clean --apply` 才删除；证据或报告正式保存后也调用同一清理函数，不以报告 passed 为前提，不修改验收结论。仅清理同用途、同类别、同 scope 且已有当前有效替代物的 superseded/cleanup_failed 旧副本；stale 本身不是删除依据。执行未知、失败或等待返回时保留现场；原始输入、分析图、必需过程证据及报告/回查仍引用的旧文件不删，未知文件只报告。旧 `.work` 只读保留，不自动迁移或删除。单文件替换只短暂使用同目录 `run-files-*.tmp`，成功后消失，失败现场保留；清理失败不抹去正式保存成功。

超时、取消或返回丢失用 save-result 的 outcome=unknown，标准输入传 `{"result": null}`，不自动重发。先通过已授权只读查询回查：source 加 reconciliation=true，scope=required_process；取得实际文件后，用 `resolve --operation-id ... --reason ... --stdin` 及 evidence_refs 登记路径/正式哈希和判断。它只解除后续修正的阻塞，不把旧失败改成功；没有实际回查材料就停止依赖写入。state 损坏或多文件指纹不配套时报告现场，不手改成通过。

互不依赖的读取可合并；依赖新 ID、模型修改、未知写入状态或前一步判断的操作保持顺序。

### 1.2 操作图与阶段依赖

操作图在建模写入前建立。在已有图中提供公共 verification 可读的 `requirements` 对象列表，不另存一套检查期望；其余图结构不强加统一 schema，整个图参与输入指纹。至少记录：

- 草图、截面、路径和实体特征的类型、参数、唯一语义名称及输入依赖；基础实体或独立布尔仅在当前路线允许时列入。
- 输入用语义节点或已取得的实际引用表达，不能猜未来实体或拓扑 ID；结果实体是否供后续复用、工具实体的生命周期及最终结果对象必须明确。
- 尺寸到世界轴的映射、对象坐标范围、草图局部基准及关键空间关系；明确、推导和待确认参数分开记录。
- 草图尺寸目标使用已确认的 `Sketch.createDimension` 形式表达；平行、相切、相等等几何关系只使用[草图参考](sketch-modeling/sketch-modeling.md#517-几何关系约束sketchaddconstraint)中列出的图元与 `snapType` 组合。坐标定义图元的初始位置和方向，不替代明确的尺寸目标；没有设计依据的关系不额外添加。
- 关系约束记录目标不变量和语义图元。执行前核对约束类型、当前实际图元 ID、图元类型、`snapType` 及拾取点；执行后检查预期几何关系，证据不足则标为未验证。未列出的约束类型或组合视为当前技能不支持，不在建模中猜测或自行试验。`createFullyDefineSketch` 不作为默认收尾，只在用户明确要求草图完全约束时考虑，并检查自动增加约束是否改变目标。
- 圆角、倒角的输入对象、目标边的几何语义、尺寸和取当前拓扑的时机；执行时再绑定当前实际 ID。
- 每个完整阶段的必需要求、首次检查时机、受影响旧项及后续依赖。关键阶段检查通过后才继续依赖操作。
- 路线受限而采用备选命令时，记录已授权路线或已评估替代方案、不可用原因及依据。

已确认空白文档的初始构建使用 overwrite=true；后续正常新增默认以 overwrite=false 提交本次新增片段，不反复比较模式。沿用已确认状态和有效引用，仅补查本次缺少或失效的输入，不默认跨请求变量有效。修改已有结构只用已确认且适用的编辑能力，不为避免重建试探多种路线；没有可靠局部路线时，保留证据、核对人工修改并修正完整脚本后评估覆盖重建。任一成功几何修改均使受影响拓扑和检查证据失效；重建后重新绑定实际对象再继续追加。纯查询仍使用现有只读查询工具及其策略。

## 2. 浏览器直接访问与持续参考

1. **用允许的当前工具。** 按当前任务的授权边界选择专用浏览器入口；`mcp__cua_repl` 等 UI 自动化入口即使提供页面 API，也不得默认使用。没有允许的访问方式时如实报告阻塞，继续独立工作。按实际工具说明初始化，不猜调用签名，不要求安装、运行或检查 browser-use CLI，不先读取 CLI 专用技能或操作桌面。工具名、浏览器配置及登录方式不写入 Python 执行器。
2. **先复用已打开的目标。** 取得文档上下文后，先核对当前页面是否已经是目标文档及版本；一致时直接使用，不重复访问。尚未打开或需要切换文档、版本时，调用 `resolve_document_browser_url(document_id, version_id)`，将返回的 `browserUrl` 原样交给当前浏览器打开，若返回登录中转页 `/account/thirdlogin?initParam=…`，由浏览器完成登录及后续跳转，再核对最终页面标题、文档、版本和加载状态；不要自行拼接 workspace URL。已有 `documentId + versionId + docType` 时直接复用。需要新建文档时，先确定已确认的 `project_id` 和文档类型；MCP 没有项目列表工具，不得猜测项目 ID。若项目 ID 缺失且没有已确认的当前项目，询问用户使用哪个现有项目，或等待用户明确要求新建项目。仅在用户明确要求新建项目时调用 `create_crowncad_project`，再把实际返回的 `projectId` 传给 `create_document`。项目列表不能代替模型检查。
3. **区分模型文档页和项目列表页。** 同一个零件或装配文档内，模型内容会随修改自动更新；未切换文档或版本时，执行后直接重新查看当前页面，不例行刷新、不重复访问地址，也不无故新建标签页或浏览器会话。重新获取画面或截图不等于刷新网页，必须确认页面已展示本轮结果，不能复用旧截图冒充新证据。

   项目列表页不会自动更新；需要查看新增文档等列表变化时，重新访问列表页。已经取得目标文档地址时直接访问目标，不为更新列表绕行。

   同一零件或装配文档内，获取视觉证据直接查看当前页面并按需重新截图，尽量避免刷新或重新访问。暂时未看到变化时，先等待页面更新并再次查看，不把刷新作为获取最新画面的默认动作。确有加载失败或连接异常时，再按实际情况处理。
4. **按实际阻塞处理。** 跳到登录页或提示下线时才请用户登录，再回原目标；登录由用户完成，不读取或输出秘密。权限、页面或工具受阻则记录真实原因，视觉未验证，依赖未确认结构的工作先补证据或说明阻塞，独立工作可继续。CLI 不存在不等于没有浏览器能力，不自动安装 CLI 或改用桌面探测。

5. **限制 Computer Use。** 文档页面只通过当前任务允许的入口访问；UI 自动化须有覆盖具体动作的明确授权，浏览器 API 形式不构成授权，接口或截图失败不能自动授权切换入口。 允许范围内的纯视角操作不改变模型，但仍须遵守上述工具限制。

   创建或修改特征、输入建模命令、修改尺寸或配合、删除对象等改变模型或文档内容的动作，默认通过已确认的 CrownScript 和接口完成，不自行改用浏览器界面操作。确需通过界面完成时，先说明具体动作、原因和影响范围，取得用户明确授权后再执行；已有覆盖该动作的明确授权时沿用，不重复询问。

   测量、剖面等检查功能须确认其实际作用：仅改变观察或读取信息的，可用于检查；会创建特征或写入文档的，按上述界面修改规则处理。界面修改后仍须记录实际变化，并按现有建模及验证规则核对结果。

### 2.1 建模过程中的视角展示

视角展示用于让用户看清草图绘制和其余建模操作的变化。沿用已有操作图和阶段计划，补充本阶段要展示的部位、观察方向、选择依据及检查时机；不另建固定阶段表，不按每条命令拆分。调用前核对当前会话的工具定义和目标页面；工具未加载或实际调用失败时说明未验证，不能仅凭本地已有封装代码认定本次可用。

1. **解析真实工作平面。** 草图前通过 `resolve_sketch_plane` 确认当前真实 Plane 及局部坐标系；相机方向不能替代坐标核对。平面尚不存在时先完成合理的准备阶段，不能猜未来ID。
2. **按需调整相机。** 当前视角足够时保持。只有遮挡妨碍必要判断或用户明确要求时，才调用 MCP 工具 `transform_camera`；不在每阶段前后、平面切换或累计重放时例行调整。世界 +Y 向上。
3. **仅在必要时截图。** 取图前明确待判断问题；适用情形包括缺少视觉证据的关键结构、异常诊断、最终结果取证。已有有效证据足够时复用，不按命令、草图、阶段或相机调用固定截图，不用连续截图等待动画。尺寸、数量与连通关系优先用实际几何查询验证。
4. **展示服从结构依赖。** 草图会话不拆散，按有意义的结构及检查边界组织执行。需要观察阶段结果时可在完成后展示，再按当前状态追加后续内容；不因展示失败重放几何、不重复创建文档，也不绕过界面授权限制。
5. **有效性与恢复。** 相机下发不等于画面已确认。仅依赖视觉判断的工作需要相应观察，独立计算与几何查询可继续。实际截图按[证据保存](verification-workflow.md#41-视口截图与跨环境证据保存)下载、查看并关联当前状态。相机或截图失败不因此重放几何；不自动反复重发截图或相机请求。多窗口不随意选首个会话。
6. **遵守工具限制。** 沿用第2节的 Computer Use 限制，不因相机或截图故障自动转入界面操作。

## 3. 阶段执行与检查循环

```text
读图纸，列出每个零件的要求和阶段计划
    ↓
固定目标文档，打开浏览器持续参考
    ↓
解析当前真实工作平面坐标，保持合适视角；仅必要时调整
    ↓
正常新增提交追加片段；仅在首次构建或必要重建时提交完整脚本
    ↓
检查执行返回，确认浏览器显示最新模型
    ↓
核对视角是否保留、操作区域是否可见，必要时调整
    ↓
对照图纸查看整体和本阶段相关局部
    ↓
按本阶段检查需要，取得当前拓扑和元素几何详情
    ↓
结合图纸、画面和实际数据，确认要检查的对象
    ↓
读取实际尺寸、位置、方向等，与要求比较
    ↓
检查新增要求，以及本次操作影响的旧要求
    ↓
阅读差异和缺项，决定继续、修正或补证据
    ↓
零件完成后，用当前有效证据独立复查全部必需要求
    ↓
需要装配时，再进行装配过程检查与最终验收
```

这是理解和执行顺序，浏览器、查询和测量可围绕问题交替使用。关键阶段是一个完整设计部分做好、可核对要求的节点，例如基体、重要孔槽、圆角或关键连接；后续依赖它或可能改变重要结构时安排检查，不把全部检查推到最后，不按每条命令截图。

为每个实际需要新建的文档固定独立上下文，并在该文档的各阶段及修正重试中复用。单零件使用 `PartDocument`；装配结果使用 `AssemblyDocument`。装配中需要新建的零件各自使用 `PartDocument`，已有零件文档直接复用，再创建装配文档。调用 MCP `create_document(project_id, document_name, doc_type, task_id)`：`project_id` 必须来自用户提供或已确认的项目上下文，或来自用户明确要求创建项目后 `create_crowncad_project` 的实际响应；没有来源时先询问用户。`document_name` 只传模型语义名称，`task_id` 传本任务的 8 位十六进制 UUID；工具生成最终带 UUID 后缀的文档名。保存完整响应并从 `executionContext` 固定 `documentId`、`versionId`、`docType`。不向 MCP 工具传入旧 REST 创建体的 `docName`、`folderPath`、`folderCode` 或 `templateName`。

拓扑提供实体、面、边及关联；元素详情提供类型、圆心、半径、轴线和法向。它们既用于后续选边，也用于阶段及最终要求检查。需要时以同一上下文 REST GET 取得当前 ID，再追加只含所需元素的详情查询；详见[拓扑规则](entity-modeling/details/topology-and-features.md)。扫描来自草图路径或 3D 曲线、转换源草图已有有效 ID 等操作，不因命令本身强制采集实体拓扑。

AI 结合图纸、画面和实际数据确认对象，再调用已有测量与比较工具；不能凭期望尺寸排除做错的对象，也不能凭图片估计精确尺寸。检查新增及受影响旧项，读取报告差异、缺项和必要返回后决定行动；只写出报告不算完成检查。

单个零件完成后，无论是否装配，均按[独立验收](verification-workflow.md#5-单个零件最终验收)复查全部要求，另核对最终执行、必要返回和特征路线。报告 `scope=requirements_check` 只代表清单检查，不能单凭 passed 宣布任务完成。装配过程及最终验收见[装配参考](assembly-modeling/assembly-modeling.md#6-装配验收流程)。

## 4. 失败、未验证和恢复后的处理

- 几何或脚本失败：确认尚未提交写操作的本地参数错误直接修正，不查询 CAD 残留；可能已写入或结果未知时，才按需查实际完成项和残留。只对明确原因使用已确认能力修正，不要求穷尽局部方案；无法可靠修复时评估覆盖重建。当前状态无法确认时停止依赖写入，不能直接覆盖；已有查询已能支持决定时停止取证，没有新线索时不重复同一查询。最多自动修正 3 次是上限，不是必须试满，切换模式不重置次数；不重复相同失败代码或随机改参数。修正同步完整脚本，保存实际输入及响应；修正后重新检查新增和受影响旧项。

首次构建之外，确认没有可靠且适用的局部处理路线时，可以覆盖重建，不要求穷尽替代方案。在已有修订记录中简述原因即可。覆盖前保留必要证据，确认允许替换范围和未纳入脚本的人工修改，修正完整方案后再执行；覆盖后重新取得引用并检查受影响结构，再恢复追加。保存证据不等于已实现版本备份或自动回滚；没有已确认恢复接口时不得承诺自动还原。
- 未验证先说明原因并补证据；后续依赖时暂停或说明阻塞，可以继续独立工作但不能称该项通过。无法理解错误、缺少关键参数、外部阻塞或能力不足时停止依赖操作，反馈失败阶段、已知错误、已尝试修正次数和需要补充的内容。
- 恢复原脚本后同样核对有效返回及受影响结构。在问题闭环前保留必要修正现场、响应、回查及判断，闭环后由公共程序清理已登记且可靠替代的工作资料。不得补写历史阶段通过；同版本重建不保证证据有效，不能把旧结果改成 final 代替复查。
- 初始文档创建重试由工具内部处理：仅超时、连接或服务端错误最多尝试三次，保持任务 UUID，以 `_retry<n>` 区分可能留下的文档；权限或参数错误不重试，既有文档不执行创建重试。不泄露凭据。

网络重试由 MCP 工具内部处理，调用方不再叠加重试。只读 REST GET 使用 MCP 工具内的共享读取逻辑：SSL EOF、连接重置、超时及 HTTP 429/502/503/504 最多尝试 3 次（首次请求加 2 次重试），间隔 1、2 秒，成功即继续。网络重试不消耗几何修正次数；证书校验、权限、参数、JSON 解析及业务错误不重试。模型写入 POST 不能套用 GET 重试，先回查是否已执行，无法确认时停止。 只读元素详情查询是独立策略：工具按批处理，每批最多尝试 3 次，等待 5、10 秒；仅重试 HTTP 429/500/502/503/504、业务 429/502/503/504，或业务 501 且消息为“模型数据解析异常null”。不确定网络中断、认证、参数和脚本错误不自动重发。该策略不适用于建模写入。

调用 `collect_topology`、`query_topology_geometry`、`resolve_sketch_plane`、`collect_assembly_state` 或 `collect_assembly_transforms` 时不传本地路径。查询工具为每次调用创建独立服务端临时目录，返回业务数据及 artifacts 证据包。GET 脱敏日志、REST 原响应、查询脚本与响应、完整结果保留在包内；按第 5.1 节下载到调用端，不能将服务端路径当成本地文件。装配工具分别返回实例与配合、全部实例矩阵，其证据包包含本次查询的原响应、整理结果及日志。失败时尽量返回 failure-evidence.zip，保留 isError=true 和原始错误，不将证据包存在当作执行成功。

check_interference 同样直接返回，不传目录或日志路径，不自动保存文件。调用方按阶段保存完整返回到现有任务记录。该接口为单次 POST，不套用 GET 重试。

装配字段与矩阵用法统一见[装配结构查询](assembly-modeling/assembly-modeling.md#42-查询装配结构getassemblystruct)。

## 5. MCP 工具调用与资料保存

文档创建和程序执行通过 MCP 工具完成。创建文档后通过 save-evidence 的 document 角色保存真实 `create_document` 返回到 `runtime/document.json`，固定其中上下文。维护完整源码，并通过 prepare/save-result 保存实际提交及配套安全响应；不额外复制快照或另建修订目录。不要把凭据放入文件、MCP 参数、对话或日志。

新建文档、提交 CrownScript 和 STEP 导出默认调用插件已配置且当前已授权的 CrownCAD MCP 工具，身份来自宿主当前连接的 OAuth 授权，由 MCP 管理凭据；代理不查找或读取本地凭据文件，不传入凭据参数。未授权或授权失效时请用户通过宿主完成授权或重新授权，不自动退回本地凭据直连。除非用户明确要求本地直连，否则不要运行已迁入 MCP 的对应 Python 执行脚本。本地计算、几何分析、检查和案例管理仍可使用 Python。

拓扑和草图平面解析默认调用当前连接提供的 `collect_topology`、`query_topology_geometry` 和 `resolve_sketch_plane` 工具；参数及四层查询顺序见下节。用户未明确要求本地直连时，不运行对应 Python 执行脚本。

最终执行及代理校验通过后，按 [完成检查与保存决定](../../modeling-case-library/references/case-workflow.md#4-完成任务核对最终版本并询问保存) 交付当前模型，邀请用户补充人工经验或调整意见，并及时记录到 README。涉及模型修改时，更新实际受影响的建模资料，返回本文件的建模与检查循环，再次交付；用户认可当前效果后按保存授权归档。记录、确认及保存结果反馈统一见案例规范。 用户认可或同意保存不能代替必需验收。

### 5.1 跨机器文件交付与证据使用

1. 查询工具不接受 task_dir、request_log_path，STEP 工具不接受 output_path 或本地文件 overwrite 参数；服务端自行管理临时文件。collect_topology/query_topology_geometry 先检查返回的概况、覆盖状态和异常计数，再下载 dataFile 指定的业务 JSON；它们不直接返回完整业务数据。不为取得证据重复发起 CAD 操作。
2. 需要读取拓扑/几何业务 JSON、保存证据或分析 STEP 时，读取 artifacts 中的 name、downloadUrl、expiresAt、byteSize、sha256，在内存取得所需字节并校验。适用公共入口的资料直接经 save_evidence 写入固定用途槽；不同必要子集使用不同 purpose，不把局部查询覆盖主用途，不另写下载或来源信息副本。
3. 在有效期内下载，校验实际字节数与 SHA-256。ZIP 按需保留原件，仍校验路径、条目大小及 CRC，不落盘展开；source.extract 仅可省略或为空列表，非空明确拒绝。优先使用独立 dataFile，确需读取包内资料时仅在内存读取已校验条目，不执行包内代码。需要分析的 STEP 同样校验后再按其既有流程交给本地几何工具。
4. 校验后优先使用 `scripts/extract_topology.py` 按类别、对象、元素 ID 和顶层字段提取业务 JSON，具体调用见[分层查询](entity-modeling/details/topology-layer-design.md#本地业务数据提取)。已知目标时直接筛选，不固定先查概况；不整份打印到 AI 上下文。检查 missingIds、missingFields、unknownOwners、sourceIssues、recordIssues 和覆盖信息；空结果不能直接证明目标不存在。README、操作检查和报告引用下载后的调用端本地文件。包内服务端路径只描述来源；未下载的资料不能写成已保存在本地。
5. 下载链接凭随机标识访问单个文件，最长有效 10 分钟；重启会失效，禁止将完整链接写入 README、报告、公开日志或保存为案例。记录文件名、摘要、大小、时间及文档/版本/阶段关联即可。
6. 下载失败、校验失败或链接过期时保留未取得证据，不能假装本地文件存在。没有单独的链接续期工具：只读查询可在确认当前状态后重新采集，并标注新时间；模型已变不能回填旧阶段。STEP 或其他写入/导出 POST 不因下载失败而盲目重发，应保留 taskId 并说明需恢复下载能力；截图按验证流程处理。
7. 错误响应仍先检查 isError、errorType、message；存在 artifacts 时下载错误证据包，保持失败或未验证状态。证据发布失败不抹去已执行的 CAD 结果，不据此重新建模。

## 6. 按需拓扑查询入口

优先按[四层规则](entity-modeling/details/topology-layer-design.md)选择需要的信息，不默认全量。调用前先确定需要哪些对象、关系和测量字段：仅选边时先取 ID，再查询目标边及相邻面；不能为少量局部选边例行展开全量几何。`level="full"` 仅用于确需全模型关系、全局检查或局部证据不足的具体问题，理由在已有 README 或操作图中简记，不新增审批或诊断文件。同一几何状态已有有效证据时不重复获取；建模改变后按受影响范围重新取证。所有 ID 必须来自当前有效状态；每次调用返回独立证据包；按真实用途下载、校验并入库，替代资料可靠接班后由程序清理，必要过程包不能被当前查询覆盖。

第一层调用 `collect_topology`，显式传 `level="ids"`；可传 `kinds` 和 `entity_ids` 限定对象范围。需要完整兼容图时传 `level="full"`。第二至第四层调用 `query_topology_geometry`，分别传 `face_ids`、`edge_ids`/`curve_ids` 或 `vertex_ids`；`include_face_types`、`include_edges`、`include_vertices` 控制额外关系查询。

两种工具都要传同一文档的 `document_id`、`version_id` 和对应 `doc_type`；不传文件系统路径。artifacts 证据包按第 5.1 节下载。具体调用参数以当前 MCP 工具定义为准，文件下载和校验按第 5.1 节执行。
