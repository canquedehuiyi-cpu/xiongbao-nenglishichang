# 配合驱动的装配建模

## 职责与边界

依据已确认的零件、接口、尺寸和运动要求选择基准及配合，建立实际装配关系。图纸信息缺口使用[工程图解析技能](../engineering-drawing-analysis/SKILL.md)处理。

实际执行遵循 [crownscript-executor](../crownscript-executor/SKILL.md)和[装配接口参考](../crownscript-executor/references/assembly-modeling/assembly-modeling.md)。本技能不扩展接口能力；过程沿用任务已有操作图和阶段记录，必要字段见[装配记录约定](../crownscript-executor/references/assembly-modeling/assembly-records.md)。

## 1. 检查组件与修改范围

需要读取 STEP 或结合 topo 识别组件几何、接口和遮挡连接时，使用 [三维模型几何分析](../model-geometry-analysis/SKILL.md)。源零件视图不证明最终装配位置或无干涉；装配验收仍检查当前实际状态。

确认装配上下文、源零件版本、实例数量、实际接口、设计运动和允许修改范围。分析任务只形成方案，执行任务沿用已有授权。

处理已有装配时，先检查实例、配合及实际状态，区分正确、缺失、错误和未验证关系，再修正受影响部分。

## 2. 选择主基准

选择稳定主结构、安装基准或装配原点作为参照。按设计需要固定根参照或用基准配合定位，其余组件依靠有意义的几何关系约束。项目默认 +Y 向上，图纸基准须正确映射。

优先使用具有设计意义且稳定的面、轴线、孔系、止口和基准。距离与角度配合可表达图示定位尺寸。临时摆放仅用于插入或求解初始化，最终位置必须满足实际配合关系；避免逐件固定。

曲面连接先判断相切、相贯、间隙或其他接口形式。相切配合不自动保证全面贴合，应检查实际接触区域和穿透。

## 3. 选择配合与自由度

选择配合前，先确认连接的作用、实际定位部位、轴向和角向要求，以及允许的相对运动。按连接类型读取[机械连接分析参考](references/mechanical-connections.md)相关章节，结合图纸选择配合组合，并在操作图保留选择理由和依据。常见做法不能替代本任务尺寸、基准或运动要求，无法确定时记录具体待定问题。

确认每条配合的双方实例及真实元素、类型、方向、尺寸依据、依赖和预期自由度，根据具体接口选择组合：
- 固定连接：通过定位面、轴线、孔系或基准消除设计不允许的相对运动。
- 法兰和止口：核对同轴、轴向与必要角向定位；有垫片时按实际接触层次确定端面关系。
- 焊接结构：依据接触、焊缝位置和基准定位，表达焊接后的刚性关系；有复用或独立安装需要时建立子装配。
- 铰链和销轴：明确活动双方及销轴固定方式，选择同轴、轴向和必要防转关系，保留设计转动。
- 滑动和调节机构：约束导向及不允许的运动，保留所需移动或调节；行程与运动耦合须具有明确依据和已确认能力。

分析刚体和运动组的期望自由度，检查约束独立性。自由度不能简单按六减配合条数计算，闭环、冗余和奇异姿态须结合实际求解判断。

按几何依赖和求解稳定性选择配合顺序。轴类可先同轴再轴向和角向定位，其他结构采用适合其接口的顺序，逐步检查求解结果。

## 4. 组织层级与运动归属

根据功能、安装、复用和运动需求选择层级，允许简单组件直接处于总装。关系放在能正确引用双方且符合设计意图的最低合理共同层级，跨层引用先确认支持能力。

明确每个组件连接到谁、相对谁固定和相对谁运动。同属一个子装配不会自动形成刚性连接；附件随活动件运动时，须建立两者的刚性关系。

机构子装配进入父装配前，检查刚性或柔性表达及父级对内部自由度的支持。能力不足时评估在共同父级表达运动，或按用户需求建立明确的静态工作位置模型；静态结果不证明运动功能有效。

## 5. 按能力与依赖执行

调用 MCP 工具 `collect_assembly_state` 查询当前实例身份、来源、层级和配合；调用 `collect_assembly_transforms` 取得位置检查所需的实际实例变换。矩阵的几何用法见执行器装配参考。

调用 MCP 工具 `check_interference`，对当前实际实例进行静态干涉检查；检查方法见执行器装配参考。

`checkType=0` 不执行动态干涉，脚本模块不负责修改或删除已有配合；执行前仍须确认所需能力。

按依赖完成源零件和必要子装配；直接总装路线跳过不需要的中间层。插入后查询真实实例身份，结合拓扑和元素详情确认完整引用，再创建配合并检查返回与回查结果。

插入或重建后使用 collect_assembly_state 取得当前实例编号，结合来源、名称、层级和实际观察确认计划组件；按需重新查询部位并组织完整实例＋元素引用。把对应及选择依据写入已有阶段资料。计划配合编号关联本阶段脚本、必要返回和实际回查，不把历史 ID 当当前引用。查询函数不自动解决同一覆盖脚本内的引用衔接，仍使用已确认方式，不发明接口或改变执行规则。

配合失败时分析原因和影响，继续独立操作，暂停依赖操作。发现冲突或多余关系时，通过已确认能力修正；能力不足时明确阻塞，禁止随机更换元素、猜接口或擅自删除实例。

继续已授权且无阻塞的阶段。几何或装配修改遵循项目执行规则，引用受影响时重新查询实际实例与元素。

## 6. 检查实际装配

按[装配记录与独立检查](../crownscript-executor/references/assembly-modeling/assembly-records.md)先列要求及检查时机，阶段执行后取当前数据并逐项比较，实际观察后决定继续、修正或补证据，最后全面复查。独立 assembly_verification.py 只比较资料并输出报告，不自动执行、选面或决定阶段，零件仍独立验收。

按[装配验收流程](../crownscript-executor/references/assembly-modeling/assembly-modeling.md#6-装配验收流程)检查最新状态的实例、配合及求解、实际位置、实体干涉和视觉。机构另检查所需自由度与运动，静态截图不能证明行程内有效。

位置检查使用 collect_assembly_transforms，从 data.Instances 按 ID 找到实例，将所需局部几何转换后与要求比较。Matrix4Rows=null 时查看 processingIssues。具体矩阵用法及嵌套情况见[装配接口参考第 4.2.2 节](../crownscript-executor/references/assembly-modeling/assembly-modeling.md#422-全部实例矩阵collect_assembly_transforms)。

完成关键连接后按影响范围检查干涉，最终检查全部应检组件。Group 非空时先对应零件并分析设计要求，不随机移动零件消除干涉。确认不符合要求才修正，修正后重新查询实例和检测。静态结果不能证明运动全行程无碰撞。

检查预期来自设计依据，不能根据执行结果放宽目标。实际证据符合要求为通过，发现不符合要求为失败，能力不足或检查缺失为未验证。

任一必需项失败则验收不通过，存在必需未验证项则验收未完成，全部通过才能宣称完成。计划坐标、包围盒和名义尺寸不能替代实际几何与求解检查。后续配合、实例或源几何变化后，重新检查受影响结果。
