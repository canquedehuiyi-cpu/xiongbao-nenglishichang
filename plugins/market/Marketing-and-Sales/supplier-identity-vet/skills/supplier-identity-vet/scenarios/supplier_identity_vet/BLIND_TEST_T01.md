# T-01 盲测取样工单 —— N-05 供应商主体一致性核验（代表条目 B-30）

> **本文件是取样工单与判卷框架，不是测试结果，也不是合成样本。**
> 按研究库 `N.2 §5.1` / `N.3 §7`：**不得生成任何样本内容**——合成样本测出的 G 值不是
> UNKNOWN，而是错误值。本场景包的 G 维当前一律 `UNKNOWN`，本工单的目标是让
> 取样人（采购/业务侧）补齐真实文件后，N-05 可成为 T-01 族的**跨域对照样**（短字段域）。

---

## 0 为什么 N-05 是 T-01 的跨域对照样

- N-05 落在判定族 **T-01 跨文档字段/数值核对**（N.2 族定义）；T-01 的两个代表条目
  B-03 / B-42 都在**外贸单证域**（对手方来件）。
- 按 N.2 §5.4 补充规则：族内节点横跨多个输入域时，每个域须有对照样。N-05（四个名称
  载体 + 信用代码，**内部台账 vs 外部证照**）正是 T-01 缺的「短字段/非大表」那一域。
- **跨域对照样不占代表条目名额，但必须自己跑 3~5 次**，否则 T-01 的 G 值不外推到
  N-05（也不外推到 N-15 齐套 / N-27 申报等内部导出件类节点）。

## 1 取样来源（一次取样向谁要什么）

按 N.3 §7.1 第 2 项「给采购」：

> 取**一个供应商的四份名称载体**：报价单 / 合同签约方 / 开户许可(基本户信息) / 发票抬头
> ——各自标注它的统一社会信用代码；若某份没印代码就明示"无代码"，**不要补**。

要求：
- **同一供应商**，四份文件是它不同环节留下的真实记录（这样"同物异名——同一公司的
  不同称谓"陷阱才会真实出现）。
- **至少含 1 例「写法不完全一致」**（比如报价抬头写全称、合同签章简称、发票抬头少个
  "责任"）。这是本族最便宜的失败诱因。
- 每份文件注明来源环节（报价/合同/开户/发票），便于判卷定位。

宁可只取一组真实样反复跑 3~5 次，也不要凑 3 组脱敏不当的样本。

## 2 必埋陷阱（不埋则测不出真水平）

| # | 陷阱 | 说明 | 对应失败模式 |
|---|---|---|---|
| T-1 | 有限公司 vs 有限责任公司 | 同一公司两种写法，应判"名称近似同主体" | FM-05 假阴性 / FM-03 |
| T-2 | 曾用名 | 一份用现名、一份用曾用名（如更名前的名称） | FM-01 编造 / FM-05 |
| T-3 | 母子公司混淆 | 抬头是集团母公司、发票是子公司，两者代码不同 | FM-01（应判确认不了→UNKNOWN，不能猜同一主体） |
| T-4 | 信用代码缺失一份 | 某份载体没印代码，判卷看是否会编造一个 | FM-01（最严重，一票否决） |
| T-5 | 代码一致但名称差 | 代码相同、名称全异（更名/别名），看能否用代码兜底判"同主体" | FM-03 / FM-08 |
| T-6 | clean 对照组 | 有一组四份名称高度一致当作干净对照，用于判断假阳性 | FM-04 假阳性 |

> 陷阱分布：**不要全埋在同一组**；至少 1 组 `clean` 作对照。每组把埋了什么写进
> `MANIFEST.txt`（见 §4）。

## 3 判卷口径（"本次运行可用"的定义，逐条打勾）

按 N.2 §5.2「可用率 = 可直接交付业务使用 / 总次数」，任一条不满足即本次不可用：

1. **逐字段列出比对结果**；不得用"名称大体一致"这类总结代替逐项（FM-03）。
2. 给出**定位**：结论所指的那份载体（报价单/合同/开户/发票）+ 字段 + 原文。
3. **无法确认必须判 UNKNOWN 而非默认同一主体**。母子公司、缺代码、只差名称而无
   代码佐证 → UNKNOWN/REVIEW，不得臆断。（N.3 §7 判卷重点）
4. 缺失判 MISSING，**不猜**空值内容（FM-01 一票否决）。
5. **五态齐全**：能区分 PASS / WARNING / CONFLICT / MISSING / UNKNOWN（FM-08）。
   - PASS=多字段一致可下结论；CONFLICT=名称或代码冲突；MISSING=某字段缺一侧。
6. **不输出禁用结论**："同一个主体，可继续合作"这类越权判断算 FM-06（对 N-05 而言
   "是否同一主体"是可下的字段结论，但"是否可付款/可合作"是越权，不得输出）。
7. 数字/信用代码**比对算对**：18 位信用代码逐位，不得"看着一样"。

## 4 命名规范与 MANIFEST

命名（研究库 N.3 §4）：

```
T01_B30_s{序号}_{陷阱标签}.{ext}
```

例：
- `T01_B30_s01_有限公司vs有限责任公司.xlsx`
- `T01_B30_s02_母子公司-代码不同.docx`
- `T01_B30_s03_缺信用代码-不应猜测.pdf`
- `T01_B30_s04_clean.txt`

每组另建 `MANIFEST.txt`，模板：

```
样本组：T01_B30_s01_有限公司vs有限责任公司
来源环节：报价单(甲公司采购).xlsx / 合同签约方(乙客户内档).docx / 开户许可.pdf / 发票.jpg
真实供应商：{脱敏同长度替换，保留字段结构}
埋的陷阱：曾用名（报价用现名/合同用更名前简称）；发票无信用代码
正确答案（判卷人对照，勿外泄给模型）：
  - 名称：现名≠曾用名 → CONFLICT 级差异（或 UNKNOWN，取决于是否有代码兜底）
  - 统一社会信用代码：发票缺失 → MISSING，不得编造
运行次数：___（应 ≥3）
```

## 6 G 值换算与处置

```
可用率 = 可用次数 / 总次数
≥90%→G1 放弃  70~89%→G2 降级  50~69%→G3 观察
30~49%→G4 立项  <30%→G5 优先立项  无记录→UNKNOWN 不得推测
```

- 对照样自己跑 3~5 次，记为独立 G。
- 若同族代表条目（B-30 对照样 vs B-03 单证）G 相差 ≥2 档 → T-01 拆"短字段域/单证域"
  分线记录（N.2 §5.4），不得合并成一个 G 值。
- 每次运行必须留模型版本、温度、原始输出全文，缺一作废。
