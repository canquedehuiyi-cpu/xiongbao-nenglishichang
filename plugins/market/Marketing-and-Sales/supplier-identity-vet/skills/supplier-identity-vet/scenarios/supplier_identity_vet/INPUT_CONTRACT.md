# 输入契约 —— 供应商主体一致性核验（N-05）

> 目的：把「核验动作」的输入边界定死，前置处理扫描件/OCR 限制，避免盲测 G 值是假的。
> 依据研究库 N.1 §2 GATE 1c 与「扫描件/OCR 是最大杀手」结论：**只吃文本层**。

## 0. 通用模板输入（推荐主输入）

各企业台账/证照文件格式不一，模板是**通用化入口**：把两侧关键数据抄进固定列
模板（`template/供应商核验输入模板.xlsx`，工作表「两侧对照」），引擎自动转成与
第 2 节相同的 `侧:键=值` 行再判定，**判定结果与直接喂文本完全一致**。

- 模板每行一个字段，左列固定为 名称 / 法定代表人 / 开户行 / 统一社会信用代码；
  台账侧=我方台账值，证照侧=对方证照值，两侧都填才参与比对。
- 不填模板、或文件非模板（缺「两侧对照」表）时自动回退普通文本输入。
- 模板内附「填写说明」表；扫描件/截图不得粘贴进模板，先转文本再填。

## 1. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| UTF-8 TXT / MD | ✅ | 最干净，推荐 |
| 文本层 PDF / DOCX / XLSX / CSV | ✅（依赖 openpyxl/python-docx/pdfplumber 惰性导入） | 读到的是文字，非图像 |
| 扫描件 / 图片 / 截图（jpg/png/tif） | ❌ | **拒绝**，无法下判定 |
| 图片版 PDF（无文本层） | ❌ | 同上，判 UNKNOWN 转人工 |

> 例外：若只能拿到扫描件，宿主须在喂入前完成 OCR/手打转文本层，并保证与原件一致；
> 转不出文本的行以 `[IMAGE-SCAN 〈文件名〉 不可解析，请转文本层后重交]` 原样保留。

## 2. 行格式与两侧命名

每行一条 `侧:键=值`，一行一个字段。键对所有别名做归一化。

```
侧 ∈ 台账 | 我方 | a      ↔      证照 | 对方 | b
```

| 键 | 别名 |
|---|---|
| 名称 | 名称2（简称/对外名） |
| 法定代表人 | 法人 |
| 开户行 | 银行 |
| 统一社会信用代码 | 信用代码 / 代码 / 社会信用代码 |

示例：

```
台账:名称=深圳市蓝天科技有限公司
台账:法定代表人=张三
台账:开户行=招商银行深圳分行
台账:统一社会信用代码=91440300MA5G1X2Y3Z
证照:名称=深圳市蓝天科技有限公司
证照:法人=张三
证照:银行=招商银行深圳分行
证照:社会信用代码=91440300MA5G1X2Y3Z
```

## 3. 判定与转人工规则

- **只对两侧都出现、且都归一化出非空值的字段下 PASS/CONFLICT**。
- 单独一侧字段 → `MISSING_FIELD`，转人工。
- 两侧都无可用字段 → `UNKNOWN`，转人工。
- 命中扫描件/图片/无法解析的行（含任何 `[IMAGE-SCAN`、`.png/.jpg/scan/扫描/ocr` 等特征）→
  计入未解析列表，转人工，**不参与判定**。
- 多键指向同一归一化字段时，取第一个非空值比对（原始值永不覆盖）。

## 4. 输出

- `outputs.verdict`：`PASS / CONFLICT / UNKNOWN`（单侧则附加 `MISSING_FIELD` 提示）。
- `outputs.diffs`：逐条差异或判定说明。
- `outputs.judged_fields`：实际参与判定的字段（归一化 id）。
- `outputs.unresolved`：未解析（扫描件等）行，人工对照清单。
- 报告：``dist_template/output` 日期目录下的 supplier-vet-*.md`（含两侧字段覆盖与未解析行）。

## 5. 输入可得性与盲测口径（对齐研究库 N.1 §3 N-05 行）

- N-05 输入极小：四个实体字段即可，**GATE 1 全通、不依赖扫描件** —— 这是它成为
  第一个落地产物、可立即取盲测试样（T-01 族）的理由。
- 盲测 / 回归样例不得用扫描件原图：一律用「转好文本层后」的形态，保证 G 值可信。
- N-05 是 T-01 族的**跨域对照样**（短字段域）。取样工单、必埋陷阱、判卷口径与
  EVIDENCE 记录见同目录 `BLIND_TEST_T01.md`；空记录骨架见 `evidence/`。
