# HTML 默认交付

## 默认成果

完整交付以实际完成内容为准：项目 HTML、文案与物料清单、原始成功图片、ZIP。没有生图任务时 HTML 仍可交付选品或策划；pending/failed/planned/outdated 物料分别标识，不能用示例图片凑成品。研究依据带时间和市场；HTML 支持按市场筛选，公共商品资料始终可见。

1. 在当前任务工作目录保存真实资料 `project.json`，按 [数据格式](./project-format.md) 填写；参考 [合成格式示例](../assets/project.example.json)，替换全部示例内容。不要以示例代替真实调研。
2. 将已实际下载的成品放在输入 JSON 所在目录的子目录，用相对路径引用。脚本原样复制图片，不调用设计服务、不拉取远程图片。执行记录和原始回执放在另一个私有目录，不混入 project.json。
3. 用宿主命令能力运行以下命令，路径换成实际绝对路径；不要求额外安装 Python 包：

```sh
python3 /ABSOLUTE/SKILL/scripts/render_delivery.py --input /ABSOLUTE/project/project.json --output /ABSOLUTE/project/delivery-v1
```

4. 打开实际生成的 `index.html`，检查中文/外文、各市场筛选、表格、图片、待处理状态与下载入口；核对文件存在、图片内容和实际像素。输出目录必须是新目录，更新用 delivery-v2 等，不覆盖旧交付。脚本失败先修正具体资料或路径，再重试到新目录，不能把失败报成完成。
5. 聊天给简短成果摘要、必要图片预览和真实 HTML/ZIP/文案文件入口；有生图时按服务端回执分别报告实际费用和项目入口。不要让用户只拿到源 JSON。

检索 HTML 源码、检查模板标记与 ZIP 校验和只算静态检查，不能证明页面已经打开、图片显示正常或市场筛选可用。通过宿主实际可用的浏览器/HTML 预览打开文件并操作筛选后，才报告对应目视验收；未获得该能力时明确写「文件校验通过，页面交互尚未目视验证」，不能用静态检查替代此结论。

脚本的项目页模板随包提供，路径为 [delivery.html](../assets/delivery.html)。Python 3 不可用但宿主有文件能力时，可参照同一模板生成真实 HTML 和 ZIP，执行相同检查；不下载运行时或安装依赖。文件或浏览器能力均不足时说明实际完成程度，提供已有成果，不能宣称已生成或已目视检查文件。
