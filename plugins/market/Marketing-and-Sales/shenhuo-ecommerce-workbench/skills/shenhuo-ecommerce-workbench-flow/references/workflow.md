# 项目、阶段与市场

## 一次建立，持续复用

先识别用户要的是研究、方案还是实际成品。输入足够即开始，不要求用户选择内部模块。只有选品尚未决定、商品事实缺失、真实服务追问、设计师选择、付费报价或对外活动条件未确定等影响结果的节点，才补充相应确认。

平台、国家/地区、物料位置三项决定当前适配规则。国内和跨境可并行存在于同一项目，但逐市场执行，避免币种、单位、时间和商品版本串用。语言另设字段：美国与英国即使同为英语，也分别维护币种、尺码和活动条件；不能根据英文推定平台或站点。

常见路径：

- 没有商品：资源约束 → 分市场选品研究 → 用户选定 → 商品档案 → 文案/商品图 → 活动方案/海报 → 交付。
- 已有商品：直接核对资料 → 用户要求的文案、图片或活动 → 交付。
- 只要活动：已有商品与权益 → 分市场策划 → 确认需要制作的物料 → 设计 → 交付。
- 只要方案：保存真实方案和待制作清单，不为凑交付页生成图片。
- 继续旧项目：读取资料与原任务状态，补本次新增内容，不重新匹配、建项或生图已有成果。

## 两类记录

对外交付资料按 [项目数据格式](./project-format.md) 保存：

1. 共用商品档案：实物 SKU、品牌、原始素材编号、规格、材质、包含物、证据、确认状态。未确认的认证、功效、销量、评价、价格不补造。
2. 市场商品版本：平台/站点/语言、当地标题卖点、币种价格、单位尺码、电压接口、包装差异、相应依据。纯单位换算标明原值与规则，不把换汇当定价。
3. 市场活动版本：目标、人群、商品、实际权益、适用条件、当地时区起止、履约承诺、素材位置和评估指标。
4. 物料清单：市场、用途、准确文案、规格、真实文件、状态及依赖资料版本。原始素材、概念提案、已生成成品分开。

私有执行记录单独放在项目私有工作目录，不打进交付 ZIP：原始 Brief、素材上传回执、实际工具来源、设计师/匹配/设计/生成 ID、幂等键、报价有效期和实际结算回执。短期文件凭证只用于当前传输，不把 Token、签名 URL、账户明细或完整原始工具回执写入 HTML、public project.json。项目链接只使用服务返回的真实 project_url，可在聊天单独交付。

## 变更规则

每份商品事实、市场文案或活动条款使用独立 section id 与正整数 revision。每件物料的 depends_on 记录实际引用的 section id 和当时版本。保留旧交付目录，每次更新生成新目录。

- 某市场价格或期限变化：增加该市场对应 section 的 revision，只标记引用它的物料。
- 实物参数或品牌公共要求变化：增加共用 section 的 revision，检查所有依赖物料。
- 新市场：复用已核实共同资料，新增该市场的资料、文案、活动和物料；不覆盖已有市场。
- 用户未要求重新制作：指出受影响文件即可；不得自动生图扣费。重新制作完成后才更新依赖版本与交付状态。

交付脚本能检查版本依赖并标记待更新，但不会自行判断事实是否改变，不操作图片、业务系统或后台同步。完整性由真实资料维护和交付前检查共同保证。

## 结果复盘

只分析用户提供或已授权工具实际取得的曝光、点击、转化、订单、退款、费用等数据，注明时间窗、平台、币种和统计口径。不同市场分别分析；不把文案优化宣称为已提升销量。提出下一轮试验变量和验证指标，用户决定后进入相应环节。
