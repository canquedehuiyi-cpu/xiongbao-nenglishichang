# 输入契约 —— 多格式报价拉平预审（N-01 / E-11 / G-16，判定族 T-02 多来源报价拉平）

> 目的：把「拉平 + 横向偏离预审」的输入边界定死，前置处理扫描件/OCR 限制，避免盲测 G 值是假的。
> 依据输入整治计划 §4.1 与节点池 §2 T-02：**只吃文本层**；币种/单位/含税口径
> **由用户声明**，引擎不自行换算；截图件判 UNKNOWN 转人工。
> **v0.2 起主输入改为「标准报价模板 Excel」**（内部汇聚总表，采购按固定列填各家
> 报价，格式天然统一）——因真实异构报价文件采集困难，模板化是最通用的输入路径；
> 引擎不再试图解析任意异构格式，只负责数值归一与横向偏离（见 §1 与 §5 盲测口径变更）。

## 1. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| **标准报价模板 Excel（主输入）** | ✅ | `template/多格式报价拉平输入模板.xlsx`：含「报价明细」「口径声明」表 |
| UTF-8 TXT / MD（键值行文本） | ✅（兼容回退） | 每行一条报价 + 口径行混排（旧口径） |
| 文本层 PDF / DOCX / CSV | ✅（惰性导入） | 读到文字；但**建议抄填进模板再用**，保证口径统一 |
| 截图报价 / 扫描件（jpg/png/tif） | ❌ | **拒绝**：先转文字/抄填进模板，否则判 UNKNOWN 转人工 |
| 图片版 PDF（无文本层） | ❌ | 同上 |

> 例外：若只能拿到截图/扫描报价，宿主须先 OCR/手打转文本层、或抄进「报价明细」；
> 转不出的行以 `[IMAGE-SCAN 〈文件名〉 不可解析，请转文本层后重交]` 原样保留。

## 2a. 标准报价模板 Excel（推荐输入，v0.2+）

模板结构（`template/多格式报价拉平输入模板.xlsx`，可由
`tools/quote_template_gen.py` 重新生成）：

**「报价明细」表** —— 固定列表头，每行一家报价：

| 供应商 | 品名 | 型号 | 单价 | 数量 | 金额 | 币种 | 单位 | 含税 |
|---|---|---|---|---|---|---|---|---|
| 甲 | 齿轮箱 | ZB-01 | 500 | 100 | 50000 | CNY | PC | 是 |
| 乙 | 齿轮箱 | ZB-01 | 72 | 100 | 7200 | USD | PC | 是 |

**「口径声明」表** —— 两列 `键 | 值`，一行一个口径：

| 键 | 值 | 含义 |
|---|---|---|
| USD | 7.2 | 币种汇率：1 USD = 7.2 CNY（目标币种固定 CNY） |
| SET | 10PC | 单位换算：1 SET = 10 PC（归一单价 = SET 价 ÷ 10） |
| 含税 | 是 | 全局含税口径（各家未标注时按此口径读） |

规则：
- 列头为固定中文键（供应商/品名/型号/单价/数量/金额/币种/单位/含税），值内
  **不得再出现 `键=`**；空单元格自动忽略，不会整行丢弃。
- 单价必须是**纯数值**（`单价=10PC` 这类内联单位判不可比转人工）；单位写进「单位」列。
- 「填写说明」表内置填写指引与反例。

## 2b. 键值行文本（兼容回退，旧口径）

```
报价:供应商=甲 品名=齿轮箱 型号=ZB-01 单价=500 数量=100 金额=50000 币种=CNY 单位=PC 含税=是
报价:供应商=乙 品名=齿轮箱 型号=ZB-01 单价=72 数量=100 金额=7200 币种=USD 单位=PC 含税=是
口径:USD=7.2        # 币种汇率：1 USD = 7.2 CNY
口径:SET=10PC       # 单位换算：1 SET = 10 PC
口径:含税=是|否      # 全局含税口径
```

- 币种别名：USD/美元/$、CNY/RMB/人民币/¥/元、EUR/欧元。
- 单位别名：PC/件/个、SET/套、CTN/箱、KG/千克/公斤、LB/磅。
- 键名统一为下列集合（宿主整理时套用），值内**不得再出现 `键=` 形式**。

| 标准字段 | 中文键（别名） | 类型 |
|---|---|---|
| supplier | 供应商 / 供方 / 厂家 | 文本 |
| product | 品名 / 货名 / 物料 | 文本（分组主键） |
| model | 型号 / 规格 / SKU / 料号 | 文本（分组次键） |
| unit_price | 单价 / 价格 | 数值（**纯数值**，单位走 unit 键） |
| qty | 数量 / 数 | 数值 |
| amount | 金额 / 总价 | 数值（仅展示，不参与横向比较） |
| currency | 币种 | 枚举（别名归一） |
| unit | 单位 / 包装单位 | 枚举（别名归一） |
| tax | 含税 | 是 / 否 |

示例：

```
口径:USD=7.2
口径:SET=10PC
口径:含税=是
报价:供应商=甲 品名=齿轮箱 型号=ZB-01 单价=500 数量=100 币种=CNY 单位=PC 含税=是
报价:供应商=乙 品名=齿轮箱 型号=ZB-01 单价=72 数量=100 币种=USD 单位=PC 含税=是
报价:供应商=丙 品名=齿轮箱 型号=ZB-01 单价=800 数量=100 币种=CNY 单位=PC 含税=是
```

## 3. 判定与转人工规则

- **拉平**：数值代码算（千分位/尾零/全半角）；币种按声明汇率换算到 CNY；
  单位按声明换算归一到目标单位；含税按全局口径读。
- **无声明不换算**：币种不同且无汇率声明 → `UNKNOWN`；单位不同且无换算声明 →
  `UNKNOWN`；不猜汇率、不默认 1 SET = 1 PC。
- 行标注含税与全局口径冲突 → 该行不可比转人工。
- 单价带内联单位（`单价=10PC`）→ 该行不可比转人工（单价必须是纯数值）。
- **横向偏离**：同组（品名+型号）≥2 家才比较；基线 = 归一单价中位数；
  |偏离| > 20% → `DEVIATION`（带方向与百分比）；1 家 → `SKIPPED` 不下结论。
- 命中截图/扫描特征的行（含 `[IMAGE-SCAN`、`.png/.jpg/scan/扫描/截图/ocr`）→
  未解析列表转人工，不参与判定。
- 整体终态：全部无偏离 → DONE（仅表示完成拉平与偏离标记，**不构成选商结论**）；
  任何显著偏离/不可比 → REVIEW。

## 4. 输出

- `outputs.summary`：groups / quoted / normal / deviation / unknown / skipped；
  `verdict`：DONE | REVIEW。
- `outputs.result.groups[]`：每组 `product / model / median / status` +
  每家 `supplier / price_raw / price_norm / currency / unit / tax / status /
  deviation / detail`。
- `outputs.unresolved`：未解析（截图等）行，人工对照清单。
- 报告：``dist_template/output` 日期目录下的 quote-preview-*.md`（拉平表 + 偏离标记 + 未解析行）。

## 5. 输入可得性与盲测口径（对齐输入整治计划 §4.1 与 README 第 7 行）

- 本候选排第 7 的原因：文本层可行，但原文含"PDF 截图"→ 先限缩输入，截图报价
  判 UNKNOWN 转人工，**不以"以后接 OCR"放行**。
- GATE 1a 粗档 ~55% 未实测。**盲测取样口径（v0.2 起）= 按模板填内部汇聚总表**：
  取同一票询价的 3 家以上真实报价，采购把各家**抄填进「报价明细」**（每行一家），
  在「口径声明」如实填该票的汇率/单位换算/含税口径；**陷阱通过填表主动埋**
  （如币种不同但不填汇率、单位不同但不填换算、含税口径冲突、某家显著偏离、
  某品名只有一家报）——不再依赖采集格式互不相同的原始报价文件。取样工单与
  判卷口径见 `BLIND_TEST_T02.md`。
- **判卷预期（模板化后）**：输入格式已统一，通用 LLM 或简单引擎都能做拉平，
  本键 G 值预计显著偏高——盲测若 ≥90% 应判 G1（放弃建独立插件，无需开发）；
  这正是"输入整治为模板"的收益，不因其放弃而视为失败。
- 判卷要点：是否**对齐到可比口径**（单位换算、含税口径、币种）而非并排贴原文；
  换算是否算对；无法对齐的项是否判 UNKNOWN 而非强行对齐；是否擅自"推荐供应商"
  （越权，应只标记偏离）。
