# 输入契约 —— 投标应然要求存在性核对（双任务）

> 目的：把「存在性核对」两任务的输入边界定死，前置处理扫描件/OCR 限制。
> 依据研究库 N.1 §3 / 输入整治计划 §4.5-4.6：**只吃文本层**。
>
> 两任务共享同一宿主场景，输入彼此独立：
> - `check-completeness`（N-16/N-46，T-05）：应然清单 × 标书目录 → 文件完整度。
> - `check-terms`（N-18，T-07）：条款检查清单 × 招标文件 + 材料清单 → 条款/材料。

## 0. 双任务各自需要哪些输入文件

| 任务 | source-file（第一个 FILE） | --set 传参 |
|---|---|---|
| check-completeness | 标书目录/文件列表 | `required-file`=应然清单 |
| check-terms | 招标文件 | `checklist-file`=条款清单；`materials-file`=材料清单（可选） |

## 1. 通用模板输入（推荐主输入）

各企业招标文件/标书目录格式各异，模板是**通用化入口**：把招标文件正文、条款清单、
材料清单、应然清单抄进固定列模板（`template/投标要件核对输入模板.xlsx`，工作表
「招标文件」原文表 + 条款清单/材料清单/应然清单），引擎按输入字段读对应表
（source-file→招标文件、checklist-file→条款清单、materials-file→材料清单、
required-file→应然清单），自动转成第 2 节键值行再判定，**判定结果与直接喂文本
完全一致**。check-terms 与 check-completeness 双任务共用同一模板：完整度任务把
标书目录逐行贴进「招标文件」表、应然项贴进「应然清单」表。

- 不填模板、或文件非模板（缺对应表）时自动回退普通文本输入。
- 模板内附「填写说明」表；扫描件/截图不得粘贴进模板，先转文字再填。

## 2. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| UTF-8 TXT / MD / CSV | ✅ | 最干净，推荐 |
| 文本层 PDF / DOCX / XLSX | ✅（惰性导入） | 读到的是文字，非图像 |
| 扫描件 / 图片 / 截图（jpg/png/tif） | ❌ | **拒绝**，无法下判定 |
| 图片版 PDF（无文本层） | ❌ | 同上，转人工 |

> 例外：若只能拿到扫描件，宿主须在喂入前完成 OCR/手打转文本层；转不出的行以
> `[IMAGE-SCAN 〈文件名〉 不可解析，请转文本层后重交]` 原样保留。

## 3. 三个输入文件与行格式

- **招标文件**：`source-file`（第一个 FILE 字段）。几十页可全文检索，不需要分页。
- **条款检查清单**：`checklist-file`，用 `--set checklist-file=<清单>` 传入。
- **我方材料清单**：`materials-file`（可选），用 `--set materials-file=<材料>` 传入。

条款检查清单行格式（值允许含空格，不得含 `键=`）：

```
条款:名称=营业执照 关键词=营业执照,统一社会信用代码 材料=营业执照副本 类别=硬性资格
条款:名称=投标保证金 关键词=投标保证金 材料=保证金回单 类别=废标
```

| 键 | 别名 | 说明 |
|---|---|---|
| 名称 | 条款 | 必填，条款标识 |
| 关键词 | 关键字 | 逗号分隔；任一命中即定位（未填则回退到名称） |
| 材料 | 资料 | 逗号分隔；该条款要求我方的证明材料 |
| 类别 | 类型 | 废标 / 硬性资格（别名：否决→废标，资格/准入→硬性资格） |

我方材料清单行格式：

```
材料:名称=营业执照副本 关键词=营业执照
```

| 键 | 说明 |
|---|---|
| 名称 | 必填，材料标识 |
| 关键词 | 可选；用于与条款要求材料做子串互含匹配 |

## 3c. check-completeness（完整度任务）输入

- **标书目录/文件列表**：`source-file`（第一个 FILE 字段），每行一个目录条目或文件名。
- **应然清单**：`required-file`，用 `--set required-file=应然清单.txt` 传入。

应然清单行格式：

```
文件:名称=营业执照副本 关键词=营业执照 必须=是
文件:名称=业绩证明 关键词=业绩 必须=否
```

| 键 | 别名 | 说明 |
|---|---|---|
| 名称 | 文件/项目 | 必填，应提交项标识 |
| 关键词 | 关键字 | 逗号分隔；任一命中目录条目即算存在（未填则回退到名称） |
| 必须 | 必备/强制 | 是=>必备（缺失即 REVIEW）；否=>可缺（缺失仅提示不阻塞），默认是 |

判定（仅存在性）：命中 → `PRESENT`；必备未命中 → `MISSING`；可缺未命中 →
`OPTIONAL_MISSING`。整体任一缺失/无法判定 → `REVIEW`，全定位 → `DONE`。
**不核数字一致性/签章位置**；不输出任何结论性判词。

## 4. 判定与转人工规则

- **条款定位**：条款关键词（任一）在招标文件行中命中 → 定位（行号 + 原文摘录
  ≤120 字，最多 3 条）；未命中 → `NOT_FOUND` 转人工（表述可能不同，不猜）。
- **要件核对**：条款要求材料 vs 材料清单（名称/关键词归一化子串互含）；命中 →
  已提供；缺失 → `MISSING`；材料清单未提供 → `UNKNOWN` 转人工。
- **整体终态**：全部 `LOCATED` → `DONE`（仅核对完成，**不构成可投标判断**）；
  任何未定位/缺失/无法判定 → `REVIEW`。
- **红线**：不输出"会废标/不会废标/可投标"结论；不生成废标风险摘要；检查清单
  必须由用户提供，引擎不提炼条款。
- 命中扫描件/图片/无法解析的行（含 `[IMAGE-SCAN`、`.png/.jpg/scan/扫描/ocr`
  特征）→ 未解析列表转人工，不参与判定。

## 5. 输出

- `outputs.verdict`：`DONE` / `REVIEW`。
- `outputs.summary`：total / located / missing / not_found / unknown。
- `outputs.terms`：每条含 名称/类别/状态/hits(行号+摘录)/material_check。
- `outputs.unresolved`：未解析（扫描件等）行，人工对照清单。
- 报告：``dist_template/output` 日期目录下的 bid-terms-*.md`（条款定位与要件核对明细）。

## 6. 输入可得性与盲测口径（对齐研究库 README §一 第 6 行、输入整治计划 §4.6）

- 招标文件电子版（Word/文本 PDF）在场 → 本候选第一批立即可整治落地的主因。
- 盲测必须用真实招标文件 + 真实条款清单（T-07 取样工单，见
  `BLIND_TEST_T07.md` 待建）；不生成合成样本。
- N.2 §3：T-07 本族不得合并成一个 G 值——**条款定位与要件核对分线计**。
  本包只做限缩后的"定位+核对"；废标风险**摘要生成**不在本包范围。
