> **本文件是取样工单与判卷框架，不是测试结果，也不是合成样本。**
> 按研究库 `S2.2`、`N.2 §3`：**不得生成任何样本内容**。本场景包 G 维当前

## 0 为什么本包是 T-01a 跨文档线

- T-01 判定族拆两个子族（S2.2）：**T-01a 跨文档相符核对**（输入 2~5 份单证，
  失败模式是对齐失败）与 **T-01b 单文档内部自洽**（输入 1 份，失败模式是勾稽算错）。
- 本场景包只做 T-01a。T-01b 是脚本/另一子族，不在本包范围。
- 跨文档线对应条目：N-06（PI vs PO）、N-07（提单草单 vs 出货清单）、
  N-08（发票 vs 装箱单，跨单部分）。

## 1 取样来源（一次取样向谁要什么）

按 S2.2 工程含义与 输入整治计划 §4.3（本候选排第 6 的原因：**扫描件占比高，
须先与客户谈清输入口径**）：

> 取**同一票业务**的 2~3 组单证组，每组包含**至少两份可对照单证**：
> 1. 客户订单 PO（电子版优先；文本层 PDF 也可）
> 2. 形式发票 PI / 商业发票 INV
> 3. 装箱单 PL
> 4. 若可，附 提单草单 BL / 出货清单 SL

要求：
- 同一票的 PO/PI/INV/PL 是**同一批货**的真实记录（数量/单价/品名/毛重口径一致才真实）。
- 单证保留原样（含品名写法差异、单位写法差异、尾零差异），**不要清理**。
- 若某单证数字与另一份对不上（工厂改包装没改发票这类），保留原样（这是要测的矛盾）。
- **每份单证必须可定位**：文件名/页/行/字段原文摘录；无法定位的输入判卷时该次作废。

宁可只取一组真实票反复跑 3~5 次，也不要凑 3 组脱敏不当的样本。

## 2 必埋陷阱（不埋则测不出真水平；埋了才叫取样，不叫造假）

> 陷阱必须来自真实业务形态（真实存在的写法差异/单位混用/改单），不是人为制造数字。

| # | 陷阱 | 说明 | 对应失败模式 |
|---|---|---|---|
| T-1 | 数量尾零/千分位写法差异 | 100 = 100.0 = 100.00；1,000 = 1000，应判一致 | FM-08 误报（"看起像"不一致） |
| T-2 | 单价/金额不一致 | PO 500 vs PI 520，应报 CONFLICT 且带定位 | FM-05 漏检（直接对应拒付） |
| T-3 | 品名/型号文字变体 | "齿轮箱 ZB-01" vs "齿轮箱ZB-01"（空格/全半角），应判一致 | FM-08 误报 |
| T-4 | 单位混用（CTN vs PC） | 一张按箱、一张按件且无换算依据，应 UNKNOWN 转人工，**不得默认 1 CTN=1 PC** | FM-01 一票否决（编造换算） |
| T-5 | 毛重单位（KG vs LB） | 无换算依据，应 UNKNOWN 转人工 | FM-01 / FM-05 |
| T-6 | 收发货人/港名一个字之差 | 提单草单 vs 出货清单收发通错一个字，应 CONFLICT | FM-05 漏检（柜到港无人提） |
| T-7 | 某字段只在一份单证里 | 无对照，应跳过不下结论，不得编造对应关系 | FM-03 编造对应 |
| T-8 | 扫描件/图片混入 | 应整行转"待人工"，不参与判定、不得猜内容 | FM-02（把扫描件当文本） |

> 陷阱分布：至少 1 组含 T-1 纯 clean 对照（全部一致，验证不误报）；至少 1 组
> 同时含 T-2/T-4/T-7/T-8 验证会不会编造。每组把埋了什么写进 `MANIFEST.txt`（见 §4）。

## 3 判卷口径（"本次运行可用"的定义，逐条打勾）

1. **逐字段列出比对结果**（fid / status / present_in），不得用"整体没问题"总结代替明细（FM-03）。
2. 给出**定位**：不一致/不可比字段必须带 单证类型 + 行号 + 原文摘录（S2.2 硬性输出）。
3. **不一致必须显式报出**；不得自行消掉或"按某一份为准"静默通过（FM-01/FM-05）。
4. 数值归一化正确：尾零/千分位/全半角差异判一致，不误报（FM-08）。
5. **单位不同度量判 UNKNOWN 转人工**，不换算、不猜 1 CTN=1 PC（FM-01 一票否决）。
6. 只出现 1 份单证的字段跳过，不编造对应关系（FM-03）。
7. 扫描件/图片/无法解析行转"待人工"，不参与判定（FM-02）。
8. 不输出禁用结论："可通关 / 可放行 / 可结汇 / 没问题"这类越权判断算 FM-06。

## 4 命名规范与 MANIFEST

命名（研究库 N.3 §4）：

```
T01a_s{序号}_{陷阱标签}.{ext}     # 跨文档相符核对线
```

例：
- `T01a_s01_全部一致-尾零千分位.txt`
- `T01a_s02_数量单价冲突-带定位.txt`
- `T01a_s04_单位CTN-vs-PC-不得换算.txt`
- `T01a_s08_含扫描件-转人工.txt`

每组另建 `MANIFEST.txt`，模板：

```
样本组：T01a_s02_数量单价冲突-带定位
来源环节：客户订单PO(订单号2026-0701).pdf / 形式发票PI(2026-0701).pdf
真实客户：{脱敏同长度替换，保留字段结构}
埋的陷阱：PI 数量 120 vs PO 100、单价 520 vs 500；品名全半角差异应判一致
正确答案（判卷人对照，勿外泄给模型）：
  - qty: CONFLICT（PO 第2行 vs PI 第3行，定位带原文摘录）
  - unit_price: CONFLICT（同上）
  - product: MATCH（全半角归一）
  - 其余单侧字段：跳过不下结论
运行次数：___（应 ≥3）
```

## 6 G 值换算与处置

```
可用率 = 可用次数 / 总次数
≥90%→G1 放弃  70~89%→G2 降级  50~69%→G3 观察
30~49%→G4 立项  <30%→G5 优先立项  无记录→UNKNOWN 不得推测
```

- **T-01a 与 T-01b 分开计 G**，不得合并（S2.2 尾注）。
- 若 N-06 / N-07 / N-08 之间 G 相差 ≥2 档 → 在族内拆"PI/PO""提单/出货清单"
  "发票/箱单"分线记录。
- 每次运行必须留模型版本、温度、原始输出全文，缺一作废。
