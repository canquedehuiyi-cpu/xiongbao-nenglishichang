# 输入契约 —— 单证交叉核对（N-06 / N-07 / N-08，判定族 T-01a 跨文档相符核对子族）

> 目的：把「跨文档逐字段比对」的输入边界定死，前置处理扫描件/OCR 限制，避免盲测 G 值是假的。
> 依据研究库 S2.2 工程含义：**只吃文本层**；数值一律代码算；口径不可比必停。
> 本包**不做 T-01b**（单文档内部自洽：合计=分项和、箱号连续）——那是脚本/另一子族，
> 输入形态是 1 份、失败模式是勾稽算错，与跨文档比对同族外推会失真。

## 0. 通用模板输入（推荐主输入）

各企业单证格式（表格版式/字段名/单位写法）各异，模板是**通用化入口**：把每份
单证的关键字段抄进固定列模板（`template/单证核对输入模板.xlsx`，工作表「单证表」，
每行一份单证、列头即第 2 节键名），引擎自动转成 `单证:键=值` 行再判定，**判定
结果与直接喂文本完全一致**。

- 类型列填 PO/PI/INV/PL/BL/SL（或 订单/发票/装箱单/提单等，自动归一）；空类型行跳过。
- 不填模板、或文件非模板（缺「单证表」）时自动回退普通文本输入。
- 模板内附「填写说明」表；扫描件/截图不得粘贴进模板，先转文本再填。

## 1. 接受格式

| 格式 | 支持 | 说明 |
|---|---|---|
| UTF-8 TXT / MD | ✅ | 最干净，推荐（每行一条单证行） |
| 文本层 PDF / DOCX | ✅（惰性导入） | 读到的是文字，非图像 |
| 扫描件 / 图片 / 截图（jpg/png/tif） | ❌ | **拒绝**，无法下判定 |
| 图片版 PDF（无文本层） | ❌ | 同上，判 UNKNOWN 转人工 |

> 例外：若只能拿到扫描件，宿主须在喂入前完成 OCR/手打转文本层；转不出的行以
> `[IMAGE-SCAN 〈文件名〉 不可解析，请转文本层后重交]` 原样保留。

## 2. 单证行格式与键名集

**多份单证合并为一个文件**（`source-file`），每行一条单证行：

```
单证:类型=〈PO|PI|INV|PL|BL|SL〉 键=值 键=值 …
```

- 类型别名（宿主整理时归一）：`po/订单/采购订单/客户订单 → PO`；
  `pi/形式发票 → PI`；`inv/发票/商业发票 → INV`；`pl/装箱单/箱单 → PL`；
  `bl/提单/b/l/海运提单 → BL`；`sl/出货清单/发货清单 → SL`。
- 键名统一为下列集合（宿主整理时套用），值内**不得再出现 `键=` 形式**
  （解析以 `键=` 为分隔符）；值允许含空格。

| 标准字段 | 中文键（别名） | 类型 |
|---|---|---|
| qty | 数量 / 数 | 数值 |
| unit_price | 单价 / 价格 | 数值 |
| amount | 金额 / 总价 | 数值 |
| packages | 件数 | 数值 |
| cartons | 箱数 | 数值 |
| gross_weight | 毛重 | 数值 |
| net_weight | 净重 | 数值 |
| volume | 体积 / 方数 | 数值 |
| product | 品名 / 货名 | 文本 |
| model | 型号 / SKU / 料号 / 规格 | 文本 |
| currency | 币种 | 文本 |
| container_no | 柜号 / 货柜号 | 文本 |
| marks | 唛头 | 文本 |
| port_loading | 起运港 / 装货港 | 文本 |
| port_discharge | 目的港 / 卸货港 | 文本 |
| shipper / consignee | 发货人 / 收货人 | 文本 |
| payment_term | 付款节点 / 付款条件 | 文本 |
| ship_term | 海运条款 / 贸易条款 | 文本 |
| pack_req | 包装要求 | 文本 |

示例：

```
单证:类型=PO 品名=齿轮箱 数量=100 单价=500.00 币种=CNY 毛重=1500KG
单证:类型=PI 品名=齿轮箱 数量=100.0 单价=500 币种=CNY 毛重=1500 千克
单证:类型=INV 品名=齿轮箱 数量=120 单价=500.00 币种=CNY
单证:类型=PL 品名=齿轮箱 数量=1CTN 单价=500.00 币种=CNY
```

## 3. 判定与转人工规则

- **数值一律代码算**：千分位逗号 / 尾零 / 全半角先归一化再比（100 = 100.0 =
  100.00 = 1,000? 否——千分位是分组符，1,000=1000）。
- 单位同度量别名归一（KG=千克=公斤、CTN=箱、PC=件=个、USD=美元=$、CBM=立方米）；
  **不同度量不换算**（CTN vs PC、KG vs LB 无换算依据）→ `UNKNOWN` 转人工，
  不得默认 1 CTN = 1 PC。
- 只出现在 1 份单证中的字段：不参与交叉核对，不猜。
- 值无法解析（含非数字字符 / 残缺）→ `UNKNOWN` 转人工。
- 命中扫描件/图片/无法解析的行（含 `[IMAGE-SCAN`、`.png/.jpg/scan/扫描/ocr`
  特征）→ 未解析列表转人工，不参与判定。
- 整体终态：全部一致 → DONE（仅表示跨单证一致，**不构成通关/放行结论**）；
  任何不一致/不可比 → REVIEW。

## 4. 输出

- `outputs.summary`：total / match / conflict / unknown；`verdict`：DONE | REVIEW。
- `outputs.result.fields[]`：每字段 `fid / status / present_in / locations
  （单证+行号+原文摘录）/ values（原始值）/ detail`。
- `outputs.unresolved`：未解析（扫描件等）行，人工对照清单。
- 报告：``dist_template/output` 日期目录下的 doc-crosscheck-*.md`（逐字段核对结果 + 定位 + 未解析行）。

## 5. 输入可得性与盲测口径（对齐研究库 S2.2 与 输入整治计划 §4.3）

- 本候选排第 6 的原因：价值集中（PI/PO、发票/箱单、提单/出货清单全是相符核对）
  但**扫描件占比高**——真实单据大量是扫描件，**须先与客户谈清输入口径**再取样。
- 盲测必须用真实单证文件（T-01a 跨文档取样工单，见 `BLIND_TEST_T01a.md`），
  不生成合成样本。
- T-01a / T-01b 是两个不同子族，**分开计 G，不得合并**：本包只做跨文档比对
  （T-01a）；单文档内部自洽（T-01b）不在本包范围。
- 每份参与比对的单证必须可定位（文件名/行号/原文摘录）；无法定位的输入
  视为未达标，判卷时该次作废。
