# 更新日志

## 2.7.4

- 修复：2.7.3 的报表在「阈值为默认值」时可能无法渲染（Canvas 报错）。现已正常。

## 2.7.3

- 报告「上下文占用」一块**重排版**：头条只留「该不该压」的结论，其余对比信息（Qoder 界面显示、自动压缩实况、历史高点）改成一张清爽的三行小表，不再是一整段挤在一起、看不懂的小字。
- 说清那个 **200K 是怎么来的**：它是插件内置默认值，不是你在 Qoder 设的真实上限（插件读不到）。现在报告、README 都会明确提示：想按真实阈值算，在配置文件（全局）或会话 overrides（单场）里填 `userContextLimit` 即可。

## 2.7.2

- 报告头条改为**「你真实的上下文占用」**，按你实设的压缩阈值算，一眼看清真实占比。
- 新增一条对比提示：当模型物理窗口大于你实设的上限时，明确揭穿 **Qoder 界面进度条按物理窗口显示、百分比系统性偏低**（并给出真实是显示值的几倍），提醒别信界面那个数；两者一致时则标「无偏差」，不误报。

## 2.7.1

- 「自动压缩不会在你设的阈值触发」改为**单独一块醒目告警**：自定义模型窗口很大时（如 1M），你设的上限（如 200K）根本不会触发 Qoder 自动压缩，这条提醒不再被淹没在报告里。
- 新增《功能一览》（`FEATURES.md`）：一处看全插件能为你做什么。
- README 补充「代理被停用后如何确保它重新启动」。

## 2.7.0

- 报告头条改为**「当前上下文占用」**，直接按你设的压缩阈值说该不该压；不再并排印两个几乎相同的「峰值」。
- 自动识别 Qoder 实际的自动压缩触发点，并在你的阈值形同虚设（永远不会自动压）时明确告警。
- 压缩阈值支持多种来源，报告会标明当前用的是哪一个。

## 2.6.9

- 修复长对话 / 大压缩时自定义模型报「压缩异常」的归因：真凶是客户端首字节超时、不是代理；诊断不再让代理背锅。

## 2.6.8

- 修复自定义模型（BYOK）下 token 总量被静默缩小约 5 倍的问题，报告与供应商账单对齐。
- 自动反推真实模型窗口，无需手工录入；也可在报告指引下手工锁定窗口与压缩阈值。

## 2.6.7

- 「峰值占用」改为**压缩后重新起算**，压缩腾出的空间能在报告里看出来，结论不再一直停在压缩前那次高点。

## 2.6.6

- 修复 Credits 有时显示成「0（实测）」——本地没有这个数时应显示「—」。
- 「链路健康度」不再对与本会话无关的代理故障报警。

## 2.6.5

- 报告新增：缓存命中、每次压缩的单笔成本、峰值该不该压的结论、工具 / 文件榜的「单次」列、链路健康度一行、系统提示词可行动提示。
- 修复：陈旧的「代理启动失败」误报；报告里的命令改为可直接粘贴的完整路径。
- Credits 现在标明自己覆盖了多少笔往返，避免被当成全量单价。

## 2.6.4

- 插件命令不再依赖本机安装 Node.js，自动走 Qoder 内置运行时；自检输出的每条「下一步」都是可直接粘贴执行的完整命令。

## 2.6.3

- 新增逐请求诊断：对话或上下文压缩没反应时，看清每笔请求的成败与耗时，并给出「代理 / 供应商 / 客户端」三方归因。

## 2.6.2

- 修复供应商以压缩格式返回内容时对话失败、以及用量数据丢失的问题。

## 2.6.1

- 修复代理转发中断导致自定义模型统计不到 token 的问题。
- 插件更名为 `qoder-credits-inspector`。

## 2.6.0

- 新增本地记录代理：为不走 Qoder 计费的自定义模型恢复供应商实测的输入 / 输出 token。
- 一键配置、开会话自动拉起、免装 Node.js；改回官方模型时一键停用，停用与否都不影响官方模型出数。

## 2.4.0

- 首个版本：把当前会话的 token / credits 消耗做成自动刷新的图形报告——计费输入总量、上下文占用、重发放大倍数、按类别 / 工具 / 文件占比，以及逐请求明细。
