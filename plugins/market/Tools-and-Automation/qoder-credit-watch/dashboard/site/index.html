            使用指南

            这个看板是什么、不是什么

            用之前先看清楚

            • 它只读，不替你做事：插件只向用量查询接口发读取请求，不保存、不传输任何凭据，也不代领、不代下单、不改任何远端状态。
            • 「今日签到」只是提醒，不是代办：每天 100 Credits 的签到只能在 Qoder 桌面端右上角的签到浮窗点，网页里没有这个入口，看板也点不到。状态每天 0 点重置，当天没签不补；这一列只告诉你哪个号还没签。
            • 所有数字都是快照：页面显示的是上一次采集的结果，不会自己变新。要看最新值就点「刷新余量数据」；发布到云端的站点更是一份冻结快照，那里的按钮只能把命令交回给你。
            • 两种打开方式能力不同：经本机服务（bin/serve-dashboard.cmd）打开时按钮是真触发；直接双击 index.html 或打开已发布站点时只能浏览，操作按钮不会出现。
            • 本机服务的安全边界：只绑 127.0.0.1、启动带一次性令牌、写接口只认白名单字段，关掉进程就全部失效；不驻留、不开机自启。
            • 名单存在插件之外：~/.qoder-cn/credit-watch/accounts.json（配置）与 history.jsonl（采集历史）。升级重装不会覆盖它；每次保存前会先把上一份留成 accounts.json.bak。
            • 用量接口不是公开契约：字段可能随时变更。某天取不到数或数字异常，先怀疑这里，而不是账号真的用掉了这么多。

            数字是怎么算出来的

            • 当前总剩余：套餐剩余额度 + 资源包剩余额度，取每个号最近一次采集；几天没采的号沿用最后一次结果，所以这个数偏乐观。
            • 日均消耗：所选区间内的消耗之和 ÷ 有采集记录的天数；周期刷新回来的额度不算消耗。
            • 可支撑天数：当前总剩余 ÷ 近 7 日日均，不含周期刷新会回来的额度，只用来判断紧不紧。
            • 采集新鲜度：每个号最近一次采集是当天、几天前、还是压根没有记录。没有记录多半是那个号还没登录过。
            • 资源包分行：账号明细里每个号下面按资源包各列一行（来源 / 剩余 / 到期），各包到期不同、临近到期会标出来。旧数据没采到包明细时只显示聚合的“资源包到期”。
            • 今日签到：签到的奖励是一个「今天 + 30 天」到期的活动资源包，看到这种包就算已签。判据是到期日不是余额——包签来就会被用掉，余额早就不等于 100 了。上次采集不是今天的，只能报「无法判断」，不猜“没签”。
            • 不会串号：每个号用它自己已登录的窗口去查，结果按真实账号 ID 归档，不存在拿 A 号的登录态查出 B 号。

            加账号、改标签、改端口

            • 新增账号：进「设置」页，三步——开一个新号窗口 → 在窗口里本人登录那个号 → 读一下待登记的号，起个标签点「登记」。登记完会自动采一次验证。插件不代填凭据，也拿不到你的密码。
            • 改标签、改账号名称：「设置」页的表格里直接改，保存后自动重算。手工改过 accounts.json 的话，回来点一次「只重算数据」。
            • 改端口：「设置」页顶部的「默认启动端口」写进配置文件，只决定下次启动用哪个端口，保存后要重启服务才生效。

            常见状况

            • 趋势只有一根柱子：本机只采到一天的记录，区间会自动收口；多采几天就有形状了。
            • 某个号显示“无记录”：在它那一行点「登录窗口」，登进去一次，再刷新余量数据。
            • 「今日签到」一直是“无法判断”：多半是这个号今天还没采过。点一次「刷新余量数据」就能判。
            • 改了标签但页面没变：从「设置」页保存会自动重算；直接改配置文件则要再点一次「只重算数据」。
