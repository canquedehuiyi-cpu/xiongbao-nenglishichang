# Credit Start — 一键启动余量看板（唯一入口）

**这个入口只做一件事：把本地服务看板起起来。** 之后看余量、刷新、只重算、按号开登录窗、改标签、新增账号——**全在网页看板上点按钮**完成，不在这里做，也不用再回聊天敲指令。

- `<plugin_root>` 不用猜：本文件位于 `<plugin_root>/skills/credit-start/SKILL.md`，把路径砍掉结尾 `skills/credit-start/SKILL.md` 就是插件根目录。
- 配置一律在插件目录之外：`~/.qoder-cn/credit-watch/accounts.json`（含真实 `userId`，不随打包带出）。

## 启动

```bash
"<plugin_root>/bin/serve-dashboard.cmd"
```

- 起一个只监听 `127.0.0.1` 的本地服务、在浏览器打开看板，打印访问地址与一次性令牌；默认端口 49788。
- 要改启动端口：起服务时 `--port <端口>`，或在看板「设置」页改「默认启动端口」（写进 `accounts.json` 的 `port`，只决定下次启动、需重启生效）。
- **起服务时按现有 `history.jsonl` 自动重算一次** `credits.json`，所以打开就是最新。
- 关掉那个终端窗口服务即停；不驻留、不开机自启。

打开后若角标还显示"演示数据"，说明本机还没有名单/采集，见下。

## 首次（只在全新机器做一次）

1. 若还没有 `~/.qoder-cn/credit-watch/accounts.json`：把 `<plugin_root>/config/accounts.example.json` 复制一份过去（先建 `credit-watch/` 目录）——看板的写入也要求这份存在。
2. 在看板上用「新增账号三步向导」：开一个干净窗口 → **用户本人**登录 `qoder.com.cn` → 扫描并填标签登记。凭据始终留在用户浏览器里，插件不代填、不读取。
3. 要看真实余量就点看板上的「刷新余量数据」（服务端拉起采集），或先在有已登录 Profile 的机器上采过一次。

## 边界（红线）

- **只读**：只发 GET 查余量，不改任何远端状态；不接触密码/cookie/token，拒绝任何"存密码自动登录"。
  看板的「今日签到」列也只是**从已采到的资源包到期日反推的状态**：签到只能在 Qoder 桌面端完成。
- 本机服务是**唯一写入口**：只绑 `127.0.0.1`、默认端口 49788（`--port` 可改）+ 一次性令牌 + `Host` 校验；写盘只碰白名单字段且先备份（`accounts.json.bak`）。关掉进程即失效。
- `userId` 属个人信息，不打印进日志、不提交进仓库、不粘进插件目录。

> 操作细节、字段口径、无界面手动查询（`node scripts/probe.mjs`）等见 `README.md` 与 `CONNECTORS.md`；本入口不重复。
