# 智能创作（通用技能）

本技能聚焦两件事：**完成用户的任务**与**指导用户使用 IFS**。

- **完成用户的任务**：用户开口提需求 → §4 按路由进入模块 → §6 Chat 主循环执行到交付（发消息 → 盯进度 →
  呈现结果 → 迭代/落盘）；门禁、降级与异常处置按 §3/§5/§7。
- **指导用户使用**：用户问"怎么用/怎么写需求/怎么选模型/怎么改图/怎么计费"，或没思路要参考 →
  用户帮助模块（help.md 八问口径表 + 灵感案例），答完接力回 Chat 执行。

**本技能是插件的「通用技能」（多技能模式）**：插件采用多技能模式——1 个通用技能（本技能）+ N 个**专业技能**
（IFS 技能中心的图片/视频/音频/数字人专项，如商品套图、服饰试穿、数字人口播视频、语音合成等，各自是 `skills/` 下的独立技能，目录名带类型前缀 `<类型>-<技能名>`，如 `视频-商品图文视频`）。
通用技能负责**通用任务执行**与**专业技能的任务代理**：专业技能只准备专项业务规则与素材、并指定要带的 `skill` 参数值，
**具体任务提交与执行（发消息/轮询/中断答复/呈现/落盘/门禁/降级）一律转回本技能的 Chat 主循环**
（多技能架构、代理协议与专业技能索引 → [references/pro-skills.md](references/pro-skills.md)）。
命中专项任务时优先由对应专业技能承接准备、再回到本技能执行；纯通用或未命中专项的请求直接走本技能。

本技能是「if Studio AI 智能创作」插件的设计能力入口；连接层为 iconfont-ifs 连接器（MCP over HTTP + OAuth，
插件 mcp.json 注册的 IFS 平台远程 MCP 服务，方法面以会话内 tools/list 实时为准：发消息 / 轮询 / 上传 / 模型清单 /
画布授权链接 / 本地素材直传票据 + 探活）。官方 ifs CLI 内置同名 **MCP 直通**（`ifs mcp call <工具>`），降级期工具名、参数、返回结构
都与连接器一致（→ §5、references/connector.md §4.2）。
本文档只放路由、门禁与主流程速览；模块细则在 references/，**进入对应场景才读对应文件，不要一次读全部**。
阅读顺序：§0 技能匹配顺序（先专项后通用）→ §1 认识 IFS → §2 判断是否承接 → §3 守住原则 → §4 按执行路径路由到模块 → §6 Chat 主循环承接任务。

## 0. 技能匹配顺序（专项优先 · 硬门禁）

**收到请求的第一件事是判断「该由哪个技能承接」，不是直接开始做。** 插件是多技能模式：通用技能什么都能聊，
但专项技能的 SKILL.md 里才有该场景的**必收维度、素材门槛、确认节奏与边界转路**——**先专项、后通用**：

1. **先匹配专业技能**：拿用户的**最终交付物**对照下表，命中任一行 → 用宿主的 Skill 工具**激活该专业技能**（读它的 SKILL.md），
   按其业务规则收齐素材与必收维度（缺什么一次问清）。
2. **再回本技能执行**：专项技能只准备规则与素材，发消息 / 轮询 / 中断答复 / 呈现 / 落盘仍由本技能 Chat 主循环完成
   （代理协议 → [references/pro-skills.md](references/pro-skills.md) §2）。
3. **都没命中才由本技能直接承接**：纯通用生成 / 编辑 / 查询 / 咨询，或用户没提任何专项交付物。

**硬门禁**：本节判定必须在**任何 IFS 调用之前**完成——未完成判定不得 `ifs_ping`、不得查模型清单、不得发消息、不得先组织 prompt。
**即使本技能已经被激活，也要先做本判定**：命中专业技能就立即停下、转去用 Skill 工具激活该专业技能，不得因为「已经进了通用技能」就在本技能里继续出视频 / 出图——这正是最常见的错误路径。命中专项却走了通用路径 = 丢掉了该专项的业务规则（素材门槛、必收维度、确认与验收口径全部缺失），属于错误执行，**不是「差不多也能做」**。

**生图出口唯一（与专项判定并列，任何请求都适用）**：只要最终交付物是图 / 视频 / 音频，就必须经本技能 `ifs_canvas_create` 发到 IFS 生成——命中专项带专项 `skill`、命中垂直技能带垂直 `skill`、都不命中就不带 `skill` 走通用生图，出口只有一个。**不得用本地代码出图充当交付**（HTML / CSS / Canvas / SVG / 绘图库排版后截图、浏览器渲染等）。「数字不能错 / 排版要精确 / 参数要可控」都不是本地渲染的理由：用户给的文案与数字整段写进消息、生成后逐项核对即可。文本美化、数据长图、信息图、图表排版先看垂直技能「魔卡」，不命中再走通用生图（pro-skills.md §4/§5）。

  不代表不属于它，分镜规划正是它的职责。命中下表里的其他视频技能（换主体重拍、按时间点抽帧、商品与服饰类成品短片、

  摘要现成视频内容、给现成视频做本地剪辑都不算「生成」，不走本插件的生成技能）。

  进去后按它的「不适用」条款转路，比直接在通用技能里硬做更稳。
- **垂直技能不算专业技能**：技能中心另有一批没有独立 SKILL.md 的垂直技能（pro-skills.md §4），命中时由本技能
  直接在发消息时带对应 `skill` 名，不需要先激活专项技能。

## 1. IFS 是什么

- **平台**：IFS（if Studio）是 iconfont 出品的一站式 AI 智能设计平台，面向所有用户开放——自然语言
  描述需求 → 画布生成图片/视频 → 同画布多轮迭代，成套需求一次说清即可成套产出；
  成果沉淀资产库，算力积分计费。
- **品牌**：延续 iconfont 服务设计师的专业与审美积累，把完整的设计能力装进对话；对外介绍统一
  署名 iconfont 出品，只讲平台能力与场景，不承诺尚未提供的工具。
- **更多介绍口径**（一句话 / 电梯稿 / 能力清单五问五答、怎么用五步、应用场景、差异化话术、
  使用边界、对客材料、插件激活说明）→ [references/brand.md](references/brand.md)；
  本节只做平台与品牌要点速览，不重复维护。
- 平台地址：以平台配置为准（config/platform.json 的 platform.domain，经会话启动注入；留空 = 以连接器注册配置 mcp.json 的 url 为准——产品分对内/对外版、域名不同，不写死也不向用户提供具体域名）。hash 路由 SPA，实测路由 `#/` 首页 · `#/resources` 资产库 · `#/skills` 技能中心 · `#/canvas/<canvas_id>` 画布（路径结构与域名无关）。**画布深链统一在 `?` 后整串照抄标准后缀 `{canvas_link.query_suffix}`、不带 `sessionId`**（标准后缀由平台配置段注入；固定参数组取值以 config/platform.json 的 `canvas_link.fixed_params` 为准，本文档不逐参数写死字面值；面板参数组隐藏会话面板/左侧栏/顶栏、`top_actions` 与 `zawarudo_*` 画布交互开关的取值口径都见该配置；外挂屏里只剩画布本体；`title` 为平台口径的画布页标题参数——URL 参数，与 A2UI 的 `suggestions[].title` 无关，取值 = 平台配置 `canvas_link.title_url`（标题明文 `canvas_link.title` 的 URL 编码形态；明文字面值以配置文件为准、文档不抄写，**输出只用编码值、不拼带空格的明文**）；`from` 标明访问来自本宿主/插件，取值 = 平台配置 `canvas_link.from`；`title` 与 `from` 同源于 config/platform.json 的 `canvas_link` 段，改一处即全链生效、不写死；会话缺省即该画布最新会话，工具返回的 `canvas_url` 含 `sessionId` 要去掉；细则 → references/screen.md「4. 地址来源」）。**打开画布页前先取授权链接**：把整形后的画布地址交 `ifs_canvas_authorize` 换回 `login_url`，内置浏览器打开 `login_url`——已登录直接进画布，未登录先出登录页、登录一次即自动回跳该画布（`login_url` 只作导航目标、不进对话；取不到就直接开画布地址，不卡流程；细则 → references/screen.md「1. 唤起」）。
- **配置读取兜底**：平台配置（`config/platform.json`，插件目录内）与通道偏好（`~/.qoder/if-Studio-AI-Creation/preferences.json`，用户态）都以**文件为唯一来源**；hooks 的会话启动注入只是加速通道——注入缺失（hooks 未执行、hook 载体缺失（如 Windows 无 Git Bash）、宿主无 python3——后两者只跳过注入的对应段）时，agent **先自行读这两个文件**取同一组值再继续：不凭记忆写死、不因缺注入而中断，判定口径与注入一致（偏好细则 → connector.md §3）。

## 2. 使用场景（承接什么请求）

凡做图/做视频/做设计的请求都进本技能，按 §4 路由到 Chat 执行：

| 场景 | 典型请求 |
|------|---------|
| 平面 / 品牌 / 电商 / 户外 / 交互 / 游戏设计 | "做一张 618 主图" "设计个 Logo" "出 Banner" |
| 人像 / 数字人 / 头像 | "生成职业照头像" "做个数字人形象" |
| 图像处理 | 抠图、高清化、局部修改、尺寸调整 |
| 内容传播物料 | 教程步骤图、新媒体爆点图 |
| 视频生成 | 文生视频 / 图生视频 / 分镜成片 / 短视频与成片（先走「故事板生视频」专业技能，见 §0）；模型以 ifs_canvas_models 实时清单为准 |
| 迭代与批量 | 同一画布多轮修改、程序化批量套图 |

非生成请求（查历史画布/资产、查算力、品牌介绍、安装报错）同样承接，按 §4 模块路由；**使用指导**
（怎么用/怎么写需求/怎么选模型/怎么改图/怎么计费）与**灵感参考**（没思路、要案例）→ 用户帮助模块
（help.md 八问口径表 + 灵感案例，每条案例给全描述 + 示意图 + 画布地址），答完接力回 Chat 执行。

**专项需求分流（三分支，先判分支再执行；判定表与硬门禁见 §0）**：

1. **命中专业技能**（§0 判定表任一行命中，清单与识别信号以 §0 为准）→
   **先用 Skill 工具激活该专业技能**（只口头说「转给专项技能」、实际没激活不算命中），由其按业务规则收齐素材、指定 `skill` 参数后**转回本技能 Chat 主循环执行**（代理协议 → [references/pro-skills.md](references/pro-skills.md) §2-§3）。
2. **命中 IFS 技能中心垂直技能**（魔卡/服装搭配拆解图/模特带货图/
   商品概念创意广告/商品微故事广告/直播切片视频/
   营销文案/标题文案）→ 由本技能**直接**在发消息时带对应官方 `skill` 名
   （一字不改，触发场景与素材 → pro-skills.md §4），这些能力无独立 SKILL.md、不经专业技能。
3. **其余请求**（纯通用生成 / 编辑，未命中上两类）→ 由本技能直接承接：**同样发消息到 IFS 生成，只是不带 `skill` 参数**（画一张图、海报、头像、信息图、数据长图、文本美化排版都在此列）；**不是自己排版出图**——本地写 HTML / 画 Canvas / 截图渲染都不算交付。

所有专项任务的执行（发消息/轮询/呈现/落盘）都回到本技能 Chat 主循环，本技能不复制专项规则。

## 3. 核心原则（原则 4 类凭据/状态违规由插件 hooks 直接拦截；其余靠模块细则自查自纠）

1. **门禁先行（先确认方法面 → 再探活 → 连接器优先 → 未授权先唤起授权页 → 偏好分流 → 唯一一次询问 → 降级）**：每次会话首次 IFS 调用前先
   取方法名：懒加载会话（只有 `mcp_list` / `mcp_get` / `mcp_call`）先 `mcp_list` 列一遍，
   **列得出 ifs 方法 → 再调 `ifs_ping` 探活；整个 iconfont-ifs 都列不出 → 就是服务器没连上**（装/改后没重启宿主、或连接器没连），
   直接走下方不可用分流，不要先拿 `mcp_call` 去试（被前置门禁拒时只报一句 `No connected MCP server offers a tool named …`，
   容易误当参数错）。**直调形态同理**：会话里若已出现一等工具，也要先确认它在本会话工具表里已载入（多数会话并不预载），
   报 `Tool "…" not found` 就是没载入——回发现入口（`mcp_list` 或宿主工具搜索）取实时名再发，**不按同名重试**。**始终优先连接器，只有连接器不可用才降级**。`mcp_list` 查不到 ifs 方法或调用 401（未授权/授权过期/服务不可用；
   **懒加载宿主下 `ifs_*` 本就不在会话工具列表里，判定以 `mcp_list` 能否列出方法为准** → §8、connector.md §1）→
   **先用宿主的连接器管理工具主动唤起授权页**（会话里有就用，见 §5 ①：取 iconfont-ifs 的 `serverId` →
   `action=authorize` → 用户在浏览器里登录并同意 → `action=retry` + `ifs_ping` 复验，通过即继续、不弹框）；
   唤起不可用或仍未授权 → 再查**通道偏好**（`~/.qoder/if-Studio-AI-Creation/preferences.json`，经会话启动注入；未注入时自读该文件，§1）：
   偏好=CLI → **不弹框、不再唤起，直接降级**；偏好=连接器 → **不弹框，直接降级并如实说明**（唤起已试过；连接器暂不可用、
   可能授权过期；**降级≠改选择，不写偏好**）；**无偏好（从未做过通道选择）→ 唤起失败后再停下，不自行降级**：
   按 §5 弹出**三选一对话框**——**唯一一次「如何运行」询问**（推荐激活连接器，也支持先用 CLI 运行）；
   任一选择写入偏好后跨会话不再询问（「取消任务」=未作答，下次仍问一次）。降级 = **官方 `ifs` CLI 继续承接**
   （平台分发单二进制，经 Bash 调用，**首选 CLI 内置的 MCP 直通 `ifs mcp call <同名工具>`**——与连接器同工具面、
   同 snake_case 参数、同返回结构，主循环口径不变；`canvas run/poll` 等原生命令降为便利层；
   首次需 `ifs auth login --oauth --registry {cli.registry}/ --profile {cli.profile}` 一次（CLI 固定线上），登录页由用户本人操作，CLI 凭据独立于 Qoder 连接器；
   接入与调用细则 → references/connector.md §4）。
   降级期间仅当 CLI 无法完成任务而连接器可完成时，再提示用户恢复（重新授权）连接器（§5、connector.md §4.4）。
   严禁代点提交、代选身份、代输账号；**授权页可以代为唤起，但登录与同意永远由用户本人完成**。
2. **对话概念**：对 IFS 的一切生成都是「发消息/续聊」——不存在"提交任务/重试任务"；未完成只返回
   `in_progress`——不重发消息，继续 poll 原会话（CLI 原生命令便利层是 `timeout`，同样继续 poll），
   **一直等到完成或出错**，不提前收尾。**连续同参的 poll 会被宿主的重复调用保护掐断（第四次后硬拦），
   被掐不等于任务结束**——按 chat.md「轮询节奏」轮换 `timeout_seconds`、轮间夹一次不同调用，
   长任务改走一次 Bash 调用内的**终端等待循环**（只是换等待形态，主通道仍是连接器、不是降级，
   也不对此向用户播报——§6「通道术语不进对话」）。
3. **画布优先沿用（默认不新建）**：生成请求默认落在**当前画布**续聊，画布只从两处定位：① 用户本条消息给的画布链接 / ID；
   ② 本会话台账里最近一次 `create` 的 `canvas_id + session_id`；**两处都没有就直接新建画布**，不调 `ifs_canvas_list`
   去翻"最近一个画布"（它只在用户明确要回看 / 接着某个旧画布却没给链接或 ID 时才用，见 asset.md）。
   换主题、换产物类型（图生视频 / 视频转图）、"重新生成 / 重做 / 换一版 / 再做一个"都**不是**新建画布的理由；
   只有用户明确说"新建画布 / 新开一个画布 / 换个画布"才不传 `canvas_id` 新建，且新画布 prompt 必须完整自包含，
   禁止"继续/接着"这类依赖上下文的词。借旧画布续做时在交付首句点一句画布名，用户可随时纠正。
4. **安全红线**：不读取/外传 `~/.ifs/config.json`（内含访问令牌），查登录态只用 `ifs_ping`；
   不执行删除 `~/.ifs` 目录的命令；充值只提供平台入口，绝不代用户支付；**生成一律走 `ifs_canvas_create`，
   不在 IFS 页面点生成/发送按钮、不向提示词框 `fill`**。
5. **不绕行**：MCP 调用 -32603 → 原样重试一次；仍失败转 exception.md 排障表，不绕过连接器直调平台。
6. **消息即需求（忠实 → 准确）**：发给 IFS 的那条消息是服务端唯一能看到的需求——**用户提过的每一项都要
   原样在里面**（主体与数量、画幅/尺寸、时长、画面文字原文、指定的模型/垂直技能/风格、否定项，
   一条不丢、不改、不加戏；用户没要求翻译就不翻，中文需求按中文发），只补用户没说且生成必需的空白维度；
   **自己的推断不当作需求写进消息**（用户没提过的形式、版式、附加内容都不加）；
   **整段一次提交、不截断不摘要**，参数名以会话内实时 schema 为准（`model` 取 `ifs_canvas_models` 的 `name`、
   续聊定位用台账里的 `canvas_id` + `session_id`），create 返回受理态（`created` / `submitted`）才算发出去——
   需求有歧义先问不猜着发，失败原样重试同一条、不加发第二条重复消息。
   细则 → [references/chat.md](references/chat.md) 阶段 ①「需求忠实」「准确送达」。
7. **生图出口唯一**：正式成品图一律由 IFS 产出（发消息 → 轮询 → 交付产物）；未命中专业技能与垂直技能时也不得改为本地代码排版或截图出图（§0）。

### 4.3 协作约定（模块间衔接）

- **Chat 是中心模块**：所有生成/修改最终都回到主循环「发消息 → 轮询」（§6）；其余模块是 Chat 循环内按需触发的子能力（触发表见 chat.md）——**子模块只辅助，不接管主循环**。
- **外挂屏是公共服务（画布页呈现专用）**：Chat（created 打开画布页；结果由页面 WS 实时更新，**不 reload**）、资产管理（有画布 ID 时回看画布页）与用户帮助（用户挑定灵感案例后回看该案例画布页）的浏览器操作一律走 screen.md，不各自定义；平台管理页（资产库/灵感广场/技能中心/账单充值）不打开——管理查询一律经连接器查询，无对应方法如实提示功能尚未就绪。
- **模块间只传三样衔接参数**：`canvas_id` / `session_id`（资产管理 → Chat 续聊）、`asset_id`（资产管理导出）、产物本地路径（默认工作区 `outputs/`；连接器与降级 MCP 直通侧 = Bash 下载所得，CLI 原生命令便利层 = `downloaded[].local_path`）；已有 ID 直接用，不重复查询。
- **异常管理是唯一兜底**：处置完必须回原路径继续；异常处置中不改走其他路径。

## 5. 未授权与降级处理（§3 原则 1 触发时使用）

**处置顺序：主动唤起授权页 → 偏好分流 / 三选一 → 降级。**

### ① 主动唤起授权页（未授权第一动作，别一上来就让用户自己去设置里找）

会话工具表里有宿主自带的连接器管理工具时（Qoder 实测：工具 `mcp__qoder-settings__manage_app_mcp`、方法
`manage_app_mcp`，以会话内实时工具表与 schema 为准），未授权就**直接用它把授权页推到用户面前**：

1. **取 `serverId`**：iconfont-ifs 在宿主连接器列表 / `mcp_list` 返回条目里的 id（每套安装不同，**实时取**）；
   取不到就**不猜、不硬编 UUID**，转 ②。
2. **唤起**：调 `manage_app_mcp`，参数只有 `action=authorize` + `serverId=<上一步的值>`；返回
   `status=browser-opened` = 系统浏览器已打开 IFS 授权页。返回其它状态、报错、宿主拒绝该操作 = 唤起失败，转 ②。
3. **交给用户**：回复里说一句「授权页已经帮您打开，用 IFS 账号登录后点同意授权，完成后回我一句」——只这两句，
   **然后停下等用户**——浏览器里的登录与「同意授权」必须本人完成（落到登录页 / 身份选择页一律停手，不代点、不代选、不代输账号）。
   **不要紧跟着调 retry**：用户还没登录，重连必然失败，还会多弹一次宿主确认。
4. **复验切回**：用户说完成后 → 调 `action=retry` + 同一 `serverId` 让宿主重连 → `ifs_ping` 复验：通过 → 偏好
   更新为 connector，回原任务继续（**不弹三选一**）；仍不过 → 转 ②，且**同一任务不再反复唤起浏览器**。

**唤起红线**：只唤起、不代做——不代登录、不代同意、不代输账号，不探测用户身份；工具名、参数、`serverId`、
返回 JSON 都不进对话；宿主没有这个工具、或动作名/返回状态与上面不一致时按实时 schema 走实测过的动作，
**不猜动作名硬试**，仍不通就转 ②。

### ② 偏好分流与三选一（唤起不可用 / 唤起后仍未授权）

**先查通道偏好**（`~/.qoder/if-Studio-AI-Creation/preferences.json`，经会话启动注入，未注入时自读该文件（§1）；写入与格式细则 →
connector.md §3「通道偏好记忆」）：偏好=CLI（用户此前选过「暂不授权」）→ **不再唤起、跳过对话框，直接走下方降级承接**；
偏好=连接器 → **不弹框，直接走降级承接并如实说明**（唤起已试过；连接器暂不可用、可能授权过期；
降级≠改选择，不写偏好）；**偏好缺失（从未做过通道选择）→ 唤起失败后才走三选一对话框**（唯一一次「如何运行」
询问，推荐激活连接器、也支持先用 CLI 运行）。连接器可用时永远优先连接器（偏好不生效；若偏好=CLI 且 `ifs_ping`
复验通过，顺手更新为 connector 保持记录一致）。

**三选一对话框**（唯一一次「如何运行」询问——唤起授权页不可用且从未做过通道选择时的第一响应；推荐激活连接器、也支持先用 CLI 运行——先给具体执行步骤、再弹框由用户选择，不自行降级）：
门禁确认未授权（`mcp_list` 查不到 ifs 方法 / 401）且唤起失败后，先在回复里输出下方引导正文（**花括号 = 平台配置占位符**，
config/platform.json 单一来源、经会话启动注入，注入缺失时自读该文件（§1），输出给用户前替换为注入值），再用 Qoder 问卷式
提问交互（AskUserQuestion 一类宿主提问工具，与 A2UI 收集同一机制，细则 → references/connector.md §3）
弹出三选一对话框：

> IFS 连接器还没完成授权，接下来的两步需要您本人完成：
> 1. 打开 {host.name}「{host.connector_entry}」，找到 **iconfont-ifs**（if Studio 智能设计）条目，点「{host.authorize_button}」
>    ——浏览器会打开 IFS 授权页（授权页第 2 步已自动弹出，无需手动输地址——平台域名随对内/对外版本不同，不向用户提供具体地址）；
> 2. 用您的 IFS 平台账号登录，核对账号无误后点「**同意授权**」；完成后回来说一声，
>    或直接在下面的选择框里选「已完成连接器授权」，我立刻复验并接着做。

  持续报错/能力缺失）而连接器可完成时 → 停下说明卡点，提示用户恢复（重新授权）连接器（步骤同上方引导
  正文，但**不弹三选一对话框**）→ 授权后复验切回继续；拒绝 → 报阻塞结论 + 替代建议；
  同一任务至多提示一次（细则 → connector.md §4.4）。

## 6. Chat 中心模块主循环（生成请求的唯一执行通道）

> §2 全部生成场景由 Chat 承接执行；子模块（外挂屏/资产管理/用户信息/上传/连接器）只在循环内按需触发
> （触发表 → chat.md），只辅助、不接管主循环。可靠性机制见本节末「可靠性保障」表。
> **对外只呈现任务对话**：本节模块名与流程名仅内部使用、不进对话；探活/加载细则/确认参数等后台动作
> 直接做、不播报（话术 → chat.md「对话呈现」）。
>
> **调用形式（先于全流程）**：本文与模块里写的 `ifs_canvas_create` / `ifs_canvas_poll` 等是**方法名锚点**。
> 形态按**本次会话的工具表**判、**不预设**：只有 `mcp_list` / `mcp_get` / `mcp_call`（Qoder 懒加载实测常态）→ 先用 `mcp_list`
> 或宿主工具搜索**发现一次**、拿实时全限定名并在本会话复用，再经 `mcp_call` 传平级 `toolName` + `arguments`；会话里已经有一等工具
> `mcp__…__ifs_*` 才是**直调形态**，入参**就是业务参数本体**，直接摊平传：`{ media_type, media_url, prompt }`、`{ url }`、
> `{ session_id, canvas_id, timeout_seconds }`。直调的参数对象里**只有业务字段，永远不带 `arguments` 与 `toolName`
> 这两个键——连 `"arguments": null` 都算多余字段**，带了必被拒（`params must NOT have additional properties`）：
> 删掉该键、业务参数摊平、**原样重发同一次调用**即可。只有工具名本身是 `mcp_call` 的元工具才用
> `toolName` + `arguments` 平级的信封（此时报缺 `toolName` = 信封没拼对，补齐重发）。这类报错都在发出前、
> 请求没送达、不扣算力，**不算重复发消息**。全限定名**只取实时发现结果、不照本文或记忆拼**：前缀随插件名派生
> （形如 `mcp__plugin_<插件名>_iconfont-ifs__<方法>`；插件 `name` 是 `if-Studio-AI-Creation`，名字只随它派生），
> 名字不对或工具未载入都只报 `Tool "…" not found` / `No connected MCP server offers a tool named …`——遇到立刻回发现入口取实时名重发，
> **不按同名重试、不猜别名**。实测与分流 →
> [references/connector.md](references/connector.md) §1「先判调用形态」。
>
> **前置（技能匹配，先于发消息）**：进入本循环前必须已完成 §0 专项判定——命中专业技能就用 Skill 工具激活它、
> 按其业务规则收齐素材与必收维度，发消息时 `skill` 参数带该专项的官方名；没激活就发消息 = 丢掉专项规则（§0 硬门禁）。
> 一项都不命中时仍由本循环发消息生成，只是不带 `skill`；**不在本地自行排版出图**（§0「生图出口唯一」）。

**① 发消息**：`ifs_canvas_create { prompt, media_url?, media_type?, model?, skill? }` 立即返回
`canvas_url` / `canvas_id` / `session_id`（status=created）→ 存 ID → **️ 内置浏览器打开画布页（硬门禁，不可跳过、不可延后，每次 created 必执行）**（唤起外挂屏的标准动作，不是输出链接；地址去掉 `sessionId`、在 `?` 后整串照抄标准后缀 `{canvas_link.query_suffix}`（平台配置段注入，不逐参数重拼），再把该地址交 `ifs_canvas_authorize` 换回 `login_url`、浏览器打开 `login_url`——已登录直进画布，未登录登录一次自动回跳；取不到授权链接就直接开画布地址，不卡流程；浏览器工具不可用时走链接兜底；细则 → references/screen.md「1. 唤起」 + chat.md 阶段 ①「发送后立即动作」步骤 2）→ 回一句带关键要点的进度（如"画布已打开，正在按您说的出 3 张 16:9 主图"，让用户能当场确认理解没偏），**不展示地址、参数与 ID**（话术边界 → chat.md「对话呈现」）。
**消息内容 = 用户的意思（§3 原则 6）**：发送前先过两关自查——**需求忠实**（用户提的主体/数量/画幅/时长/
画面文字原文/指定模型与技能/否定项逐项原样进消息，不改写、不丢项、不加戏、不擅自换语言，只补缺失的必需维度）
与**准确送达**（参数名按实时 schema、整段文本一次传完整不截断、续聊定位用台账 ID、create 返回 `created`/`submitted`
且 ID 齐全才算送达）；细则 → references/chat.md 阶段 ①「需求忠实」「准确送达」。
**用户上传了本地图片/视频/音频 → 先上传取 URL 再发消息**：本地文件首选**票据直传链**
（`ifs_canvas_upload_ticket` 取一次性票据 → 本地执行返回的 `command`（curl）→ `data.upload_id` →
`ifs_canvas_upload` 换 URL，**文件字节全程不进对话**、单文件 ≤5MB）；已有远程地址用 `url` 转传，
`data_base64` 只作小图兜底。参考媒体只传上传返回的 URL，
**严禁把本地路径直接传给 create**（细则 → chat.md 阶段 ①「上传前置」）。
续聊加画布 ID（会话 ID 缺省取该画布最新会话）；**中断答复也走本工具**（A2UI=续聊发建议原文、
ask_user=回填文件随消息提交，见下方分支表）；续聊/新建规则见 §3 原则 3。

**② 等回复**：`ifs_canvas_poll { session_id, canvas_id?, timeout_seconds? }`（单次等待约 30 秒、上限 55；
未完成返回 `in_progress`——**继续调用而非靠调大等待收尾**，取值在 55/45/35 之间**轮换**防连续同参被拦，
细则 → chat.md「轮询节奏」），按 status 分支：

| status | 去向 |
|--------|------|
| `in_progress` | 生成中（附 `progress` / `message`）：**有新 `message` 先转述到对话框**（相同内容去重、不攒到 done），再**固定补一句短进度**（已等待约几分钟 / 当前百分比），继续轮询（继续调用、换个 `timeout_seconds` 取值，勿靠调大等待收尾）；**持续到终态、不设轮询上限**——不中途交还控制权、不问用户是否继续 |
| `done` | 先回显 `message` / 总结，再呈现结果：**本轮新生成的产物默认落盘到工作区 `outputs/`**（图片、视频、音频、文本素材、其他 `media[]` 一律保存，用户上传的原始素材 / 画布输入原图原视频不重复下；细则 → chat.md 阶段 ⑤ / asset.md）；画布页经 WS 实时呈现（**不 reload**，重载会重置缩放/视图）；**图片**用 `media[].url` 远程地址渲染（本地路径写图不渲染，落盘文件是交付物与兜底），**视频/音频不内嵌播放器**（对话渲染面板 CSP 禁媒体，挂了就是黑屏 0:00 / 静音）——**给落盘文件链接与所在目录**，并拉起系统播放器（macOS `open`；问"文件在哪"用 `open -R` 定位）；**文本素材**（笔记正文、文案、脚本等）直接在对话里展示全文 + 给落盘 `.md` 文件链接；复查/补落盘 = 短 timeout 重 poll 或外挂屏画布页回看 |
| `summary_feedback`（A2UI 中断） | **先在对话框转述 `planning_text` 要点 + `message`、列出建议编号**，再用 Qoder 问卷式提问交互收集选择（A2UI 落在 Qoder 对话内、不在外挂屏）→ `ifs_canvas_create` 续聊答复：发送所选 `suggestions[].title` **原文**（一字不改）→ 回②。**严禁重复轮询**；建议之外的意见直接发用户原话续聊 |
| `ask_user`（问题中断） | **先在对话框呈现表单 `title` / `description` 与字段**（让用户看到服务端在问什么），再用问卷收集 → 组装回填 `response_blocks` 数组（state 改 `submitted`、value 用 `options[].value`）→ `ifs_canvas_create` 携带该数组提交（降级 MCP 直通层把同一数组写进 args.json 一起 `ifs mcp call ifs_canvas_create --profile {cli.profile}`；CLI 原生命令便利层写 form.json 走 `--response-blocks-file`）→ 回② |
| 长任务久等无结果 | **未完成不是终态**：继续调用而非调大等待；CLI 原生命令便利层的 `timeout` 同样不是终态，继续 poll 原会话——一直等到 done / 出错 / 配额 / 取消，**不提前收尾、不问"要不要继续等/回一句继续"、不说"跟我说声『看下好了没』"**；连续同参 poll 会被宿主重复调用保护掐断（**被掐 ≠ 任务结束**）→ 轮换取值 / 轮间夹不同调用 / 长任务走一次 Bash 调用内的终端等待循环（chat.md「轮询节奏」；换的是等待形态，不是通道）；仍无进展（卡死/报错）才同对话续聊重发（最多 3 次，只约束重发、不约束持续轮询）。**「一直 in_progress」有判死口**：会话 ID 错时 poll 不报错、永远回 in_progress——连续 3 轮 message 一致且 progress 为空、或超经验上限（图 5 分 / 套图 8 分 / 视频 20 分）→ 停轮询、查 `ifs_assets` 核实产物，有产物就交付（chat.md 阶段 ②「轮询不会自己结束」） |
| `quota_exceeded` | **先 `ifs_balance` 查余额确认**（user.md「算力不足：先复核再决定」）：确实不够→ 转述提示 + 余额、给充值入口（`quota_info` 链接或告知自行前往）、不重发；余额够 → 说明情况后在原会话续聊继续；余额查不到 → 按 `quota_info` 原样转述 + 充值入口，不编造数字 |
| `canceled` | 呈现已取消，停止轮询 |

**叫停**：用户说"停掉/取消" → 本期无取消工具：立即停止轮询，引导用户到画布页手动停止（用户本人操作）；
用户没叫停就绝不擅自取消。

**可靠性保障（Chat 每轮执行强制）**：

| 机制 | 规则 |
|------|------|
| 单一骨架 | 发消息 → 轮询 →（中断答复 → 回轮询）→ 呈现；任何请求不走第二条执行路径 |
| ID 台账 | 返回 created 即存 `canvas_id` / `session_id` / `canvas_url`；续聊/回看只用台账与查询返回的 ID，不凭记忆编造 |
| 发送不失真（内容关） | 消息内容以用户原话为准：主体、数量、画幅/尺寸、时长、画面文字原文、指定模型/技能/风格、否定项**逐项核对、不丢不改不加戏**；用户没要求就不翻译、不改写、不摘成摘要，长文案整段提交；必需维度缺失才补合理默认值；需求有歧义先问再发（§3 原则 6、chat.md 阶段 ①「需求忠实」） |
| 发送不错位（传输关） | 参数名按会话内实时 schema（snake_case）、`model` 取 `ifs_canvas_models` 的 `name`、`skill` 取技能名（代理专业技能时 = 该专业技能名，一字不改，pro-skills.md §3 索引）、参考媒体只传上传返回的 URL；续聊与中断答复用台账 `canvas_id` + `session_id` 定位，一条消息只服务一个会话；create 返回 `created`/`submitted` + 完整 ID 才算送达；参数错就改参数重试**同一条**，**绝不加发第二条重复/冲突消息**（chat.md 阶段 ①「准确送达」） |

## 7. 能力与限制

**能力**：图像/视频生成（前沿 AI 模型，实时清单以 ifs_canvas_models 为准）、同画布多轮迭代、程序化批量、产物默认落盘到工作区 `outputs/`（图片/视频/音频/文本素材均保存；连接器与降级 MCP 直通侧 Bash 下载 media[].url 或写入文本 / CLI 原生命令便利层 --save-dir 指向该目录自动落盘）、画布页呈现与回看（外挂屏：created 打开，WS 实时更新不 reload）、品牌宣导材料。

| 限制 | 应对 |
|------|------|
| 算力积分计费，配额会耗尽 | 返回算力不足时**先 `ifs_balance` 复核余额**再决定（user.md）：不够 → 转述提示 + 充值引导（`quota_info` 链接或告知自行前往）；够 → 原会话续聊继续；绝不代付（§3 原则 4） |
| 管理查询类能力（画布历史 / 资产库 / 灵感 / 算力）以实时方法面为准 | tools/list 有对应方法 → 按各模块口径查询并呈现（灵感案例呈现四件套 → help.md §4）；没有 → 如实提示「功能尚未就绪」（asset.md / user.md / help.md），不打开平台管理页面代查、不编造数据 |
| 存量资产下载无工具代劳 | 如实提示功能尚未就绪，用户可自行前往平台下载；本会话产物默认落到工作区 `outputs/`（细则 → asset.md） |
| poll 对错的会话 ID **不报错**，只静默回 `in_progress` | `session_id` 只取本次 `create` 返回的原值（`l/I`、`0/O` 易抄错）；一直 in_progress 按判死条件停手并核实产物（chat.md 阶段 ②「轮询不会自己结束」） |
| 会话没绑定工作区 | 仍以 `pwd` 的会话目录为根落 `<该目录>/outputs/`（宿主为未绑定工作区的会话预建了临时目录，具体路径以宿主当次实际为准）；**不往家目录乱写、不自创别的位置**；交付时说明该目录不在用户项目里，并问要不要复制一份到指定目录（细则 → chat.md 阶段 ⑤ step 6） |

| 用户选「暂不授权」/ 授权异常 / 连接器不可用 | 降级到官方 `ifs` CLI：**首选内置 MCP 直通 `ifs mcp call <同名工具>`**——与连接器同工具面/同参数/同返回，直连平台真实执行（§5、references/connector.md §4.2），会话不中断；**降级与连接器同节奏**：先授权确认再执行（本表下一行）、`created` 后同样唤起画布页；任何通道选择记入偏好（~/.qoder/if-Studio-AI-Creation/preferences.json），跨会话不再询问 |
| 降级通道自身未登录（`ifs mcp call ifs_ping` 拿不到 `pong`） | 发起 `unset IFS_TOKEN` 后 `ifs auth login --oauth --registry {cli.registry}/ --profile {cli.profile}`（登录页本人操作，CLI 固定线上；**后台发起、提示用户并停下等其确认**，确认后 `ifs_ping` 复验通过才继续）；同一任务最多发起两次登录；**不拿机器上的 current profile 顶替、不改成它的 registry**；CLI 凭据与连接器 OAuth 相互独立 |
| 降级期原生命令报 401（OAuth profile 走的是旧 Token 端点） | **凭据分道，不是 CLI 失效**（connector.md §4.3 实测）→ 改用 MCP 直通继续任务，不反复让用户重新登录、不因此触发反向升级 |
| 外挂屏不是生成操作台 | 只呈现画布页/读取回看；禁区见 §3 原则 4，细则 screen.md |
| 连续同参 poll 会被宿主的重复调用保护拦停 | **被掐 ≠ 任务结束**：按 §6「等待不被掐断」换等待形态（`timeout_seconds` 轮换 + 轮间夹一次不同调用 + 长任务收进一次 Bash 调用内的**终端等待循环**），持续等到终态（细则 → chat.md 阶段 ②「轮询节奏」；只换节奏、主通道不变、不是降级、不向用户播报） |
| 视频产物不能在对话内播放 | 对话渲染面板 CSP 禁媒体 → 产物**默认已落盘到工作区 `outputs/`**，回复里给**文件链接 + 所在目录**（用户可定位）、并拉起系统播放器；画布页为主呈现通道；细则 → chat.md 阶段 ⑤ |

## 8. 连接器请求（iconfont-ifs，细则 → references/connector.md）

- 主通道形态：iconfont-ifs 连接器（MCP over HTTP + OAuth，插件 mcp.json 注册的 IFS 平台远程 MCP 服务），
  **方法面以会话内 tools/list 实时为准**（有 → 直接用，没有 → 如实提示功能尚未就绪）；本期主流程用到的锚点：
  `ifs_canvas_create`（发消息/续聊/中断答复）/ `ifs_canvas_poll`（等回复）/
  `ifs_canvas_upload`（上传：本地文件走票据直传）/ `ifs_canvas_upload_ticket`（本地素材直传票据）/ `ifs_canvas_models`（模型清单）/ `ifs_canvas_authorize`（画布授权链接：入参 `canvas_url`，返回 `login_url`）/ `ifs_ping`（探活，门禁豁免）/ `ifs_canvas_list`（画布历史：`keyword`/`limit`/`cursor`）/ `ifs_assets`（近 7 天资产：`file_type`/`source`/`limit`/`cursor`，**不收 `canvas_id`**）/ `ifs_inspirations`（灵感：`tag`/`agent_code`/`limit`/`cursor`）/ `ifs_balance`（余额，无入参）；
  调用前门禁：**先发现方法面（`mcp_list` / 宿主工具搜索，拿到实时全限定名）→ 再 `ifs_ping` 探活**（§3 原则 1）；跳过发现直接拿拼的名字直呼，只会白报一次 `Tool "…" not found`。
- 快约定：**调用先过形态关**——先看本次会话的工具表：只有 `mcp_list` / `mcp_get` / `mcp_call` = 懒加载，先 `mcp_list`（`keyword: "ifs"`）发现方法、`mcp_get` 查 schema，再用元工具把 `toolName`（`mcp_list` 实时全限定名）与
  `arguments`（业务参数）**平级**传，别把 `toolName` 写进 `arguments`、别写成 `tool_name`；
