# 专业技能代理模块 — 通用技能 × 专业技能（多技能模式）

> 定位：本插件采用**多技能模式**——1 个通用技能 + N 个专业技能。本文件是通用技能侧的「专业技能代理」总纲：
> 讲清两类技能的分工、专业技能如何转交通用技能执行、以及全部专业技能的索引与 `skill` 参数取值。
> 各专业技能的**业务规则与素材要求以其各自的 SKILL.md 为单一来源**，本文件只做索引与代理协议，不复制专项细则。

## 1. 多技能架构（通用技能 = 执行中枢 + 任务代理）

| 层 | 技能 | 职责 |
|----|------|------|
| 通用技能 | ifs-ai-design（name_zh「智能创作」） | 通用任务执行（Chat 主循环：门禁 / 降级 / 发消息 / 轮询 / 中断答复 / 呈现 / 落盘）+ **专业技能的任务代理**：接收专业技能准备好的专项需求与素材，带 `skill` 参数发出并跑完整条主循环 |
| 专业技能 | 见 §3 索引（IFS 技能中心的图片 / 视频 / 音频 / 数字人专项） | 在通用技能基础上，针对特殊类任务做**业务规则与素材专项优化**：明确该专项要什么输入、有哪些硬规则、`skill` 参数取什么值；**具体任务提交与执行一律转交通用技能** |

**分工红线**：专业技能不自己实现发消息 / 轮询 / 呈现 / 落盘，也不重复门禁与降级口径——那是通用技能的唯一职责
（SKILL.md §3 / §5 / §6、[chat.md](chat.md)、[connector.md](connector.md)）。专业技能只做两件事：
**把专项需求与素材准备到位** + **指定 `skill` 参数值**，然后交回通用技能 Chat 主循环执行。

## 2. 代理协议（专项优先：先激活，再执行）

**匹配顺序（硬门禁，判定表见通用技能 SKILL.md §0）**：收到请求先看**最终交付物**是否命中 §3 索引里的专业技能——
命中就必须**先用宿主的 Skill 工具激活该专业技能**，再按本协议走完；只口头说「转给专项技能」而实际没激活、
或跳过专项直接在通用技能里发消息，都等于丢掉该专项的业务规则（必收维度 / 素材门槛 / 确认与验收口径），属于错误执行。
只有一项都不命中（纯通用生成 / 编辑 / 查询 / 咨询）才由通用技能直接承接——**同样发消息到平台生成**（不带 `skill`），不在本地用代码排版或截图出图。

从激活开始，执行链固定为五步：

0. **激活专业技能**（宿主的 Skill 工具）：命中即激活并读它的 SKILL.md；拿不准时按最贴近的专项进入，
   由其「不适用 / 边界」条款转路，不在通用技能里硬做。
1. **专业技能准备**（读该技能 SKILL.md）：按其业务规则收齐素材与必需维度——缺素材 / 有歧义先向用户收齐
   （一次问卷式提问），不猜着发。
2. **素材上传**（通用技能 [chat.md](chat.md) 阶段 ①「上传前置」）：本地图片 / 视频 / 音频先上传取 URL
   （上传通道与单文件大小上限以 chat.md 为准），**严禁本地路径直传** create。
3. **转交执行**（通用技能 Chat 主循环）：过门禁（SKILL.md §3 原则 1）→ `ifs_canvas_create` 发消息，
   **`skill` 参数传该专业技能的官方技能名（§3 索引，一字不改）**，`prompt` 按「需求忠实」原样组织
   （chat.md 阶段 ①）→ **第一次 `created` 返回后立即打开内置浏览器画布页（硬门禁，不可跳过，
   chat.md 阶段 ①「发送后立即动作」步骤 2）** → 轮询 / 中断答复 / 呈现 / 落盘全部按通用技能口径（SKILL.md §6、chat.md）。
4. **降级同口径**：连接器不可用时按通用技能 §5 降级到官方 `ifs` CLI 的 MCP 直通，`skill` 参数照带
   （[connector.md](connector.md) §4.2）。

> 一句话：**专业技能决定「做什么、要什么素材、带哪个 skill 名」，通用技能决定「怎么发、怎么等、怎么呈现、怎么落盘、连不上怎么办」**。

## 3. 专业技能索引（`skill` 参数取值 = 技能名，一字不改）

| 分类 | 专业技能（= `skill` 参数值） |
|------|------|
| 视频 | 故事板生视频、视频深度重拍、视频抽帧、商品外观展示广告、商品图文视频、内容种草短视频、图片/视频转GIF工具、视频添加字幕、视频裁剪 |
| 图片 | 商品创意图、商品套图、商品图文笔记、服饰试穿、试穿戴、服饰套图、服饰图文笔记、矢量图标、图片编辑、服饰展示、SKU图 |
| 数字人 | 数字人形象生成、数字人口播视频、造型改造 |
| 音频 | 语音合成、音乐生成、语音ASR识别 |

> 本表即插件侧全部专业技能及其官方技能名。**触发场景看各技能 SKILL.md 的 description，素材与业务规则看其正文**——本表只做点名与分类，不复制专项规则；新增专业技能在 `skills/` 下加目录后，把技能名补进本表（见 §5）。

> **命名约定**：本表「专业技能」列为 IFS 官方技能名（= 发消息时的 `skill` 参数值）；其在 Qoder 侧的技能目录为 `<类型>-<官方技能名>`（类型取 视频 / 图片 / 数字人 / 音频，如官方名「商品套图」→ 目录为 `图片-商品套图`），frontmatter `name` 用 ASCII slug（小写字母 / 数字 / 连字符，符合 skill 规范，如 `ifs-product-image-suite`），中文显示名放 `name_zh`（如「商品套图」）。slug 只作用于插件技能标识，**不改变发给平台的 `skill` 参数值**（仍传官方中文名，一字不改）。通用技能同理：目录为 `智能创作`、`name` 为 `ifs-ai-design`、`name_zh` 为「ifs-智能创作」。

### 3.1 易被低估的能力与执行口径

有些能力容易被旧口径说窄，下列各处一律按对应技能 SKILL.md 执行：**不拿旧口径当能力上限告知用户，也不因旧口径拒绝用户**。

| 技能 | 容易被说窄的口径 | 实际口径（以 SKILL.md 为准） |
|------|------|------|
| 视频深度重拍 | 「一张参考图」 | 参考图**可多张**，需逐张说明用途与主次 |
| 商品图文笔记 | 「根据商品图片生成」 | 商品图**或**主题关键词二选一即可 |
| 图片编辑 | 「以光影编辑与商品换背景为核心」 | 除光影与换背景外还有多项专项编辑能力（含专项判定顺序，通用编辑兜底） |
| 语音合成 | 「系统自动匹配合适音色」 | 未指定音色时**先给候选等用户确认**，仅明确授权代选才自动选 |
| 数字人形象生成 | 四类形象图 | 能力多于官方文案（另有数字人多角度多景别图、通用编辑生成图） |
| 数字人口播视频 | 两种生成方式 | 生成方式多于官方文案（另有「参考音频音色 + 文案重新朗读」） |
| 服饰图文笔记 | 「自动匹配数字人模特形象」 | 模特形象除自动匹配外还支持用户上传、复用历史与文字描述，既给图又给描述时以图为准 |
| 语音ASR识别 | 「转化为文本」 | 完整转写文本 **+ 分句与逐句起止时间**（但不直接出字幕文件） |
| 矢量图标 | 「9 种经典风格」 | 风格档位数**以平台当次为准**；产物是**单色 SVG**、不支持其他格式，参考图**仅取内容不取风格** |
| 视频抽帧 | 「根据指定时间点提取」 | 属实，但**时间点必须来自用户或上游分析**；只说「关键帧」不直接出图 |
| 音乐生成 | 「输入曲风、情绪与场景时长」 | 属实，但时长**只有平台档位**，做不到精确秒数 |

## 4. 更多 IFS 技能中心垂直技能索引（未单独成技能，通用技能直接带 `skill` 参数路由）

> 与 §3 不同：以下能力**没有各自的 SKILL.md、不作为独立插件技能安装**，是 IFS 技能中心的垂直技能，由**通用技能直接**在发消息时带对应 `skill` 参数（下表「垂直技能」列 = 官方名 = `skill` 取值，一字不改）路由；参数 / 素材 / 确认 / 轮询链路同 §2 代理协议，只是少了「先激活专业技能」这一步。命中下列场景时按本表取 `skill` 名。

> 表中数量、时长与画幅为目录描述口径，具体以平台当次为准。

| 垂直技能（= `skill` 参数值） | 分类 | 触发场景（一句话） | 关键素材 / 输入 |
|------|------|------|------|
| 魔卡 | 图片 | 文本美化长图：按文案直接生成长图（数据长图 / 信息图 / 图文排版也走这里，不自己写 HTML 排版） | 文案（原文整段给，含要保留的数字与措辞） |
| 服装搭配拆解图 | 图片 | 1 张模特穿搭图 → 右侧模特 + 左侧商品平铺 + 文字排版的搭配拆解图（电商详情页） | 模特穿搭图（1 张） |
| 模特带货图 | 图片 | 商品图 + 输出类型 → 模特口播种草图或模特使用商品图，自动判模特形象与商品交互方式 | 商品图 + 输出类型（可选画面比例 / 自定义模特） |
| 商品概念创意广告 | 视频 | 概念 / 创意方向表达商品价值的视频广告（检索商品资料 + 可选人群策略选创意方案，完成故事 / 分镜 / 视频） | 商品图（可选人群策略） |
| 商品微故事广告 | 视频 | 用生活情境 / 人物行动 / 微故事表达商品价值的视频广告 | 商品图（可选人群策略） |
| 直播切片视频 | 视频 | 直播间口播带货视频 + 弹幕 + 视频比例 → 合成直播间切片视频 | 口播带货视频 + 弹幕 + 视频比例 |
| 营销文案 | 文案 | 按商品信息 + 需求生成高转化营销文案，支持多风格仿写（详情页 / 社交种草 / 直播） | 商品信息 + 需求 |
| 标题文案 | 文案 | 按商品信息 + 风格偏好生成高点击电商标题，支持多风格仿写 | 商品信息 + 风格偏好 |

> 说明：① 上表描述为触发场景摘要，**业务规则 / 素材细则以平台该技能实际为准**，本表只做路由索引；② 「商品概念创意广告」与「商品微故事广告」官方介绍文案高度重合（均以生活情境 / 微故事表达商品价值），此处按名称把前者归为「概念 / 创意方向」、后者归为「微故事方向」以便区分，平台若给出差异化定义以平台为准；③ 本表技能不占插件技能名额、无需单独 SKILL.md，若某能力日后要做深度业务规则 / 素材校验，再按 §5「新增专业技能」升级为独立专业技能；④ 上表一项都不命中时（画一张图 / 海报 / 头像 / 信息图 / 数据长图等），由通用技能**不带 `skill`** 发消息生成（生图出口见 §5），不在本地写代码排版出图。

## 5. 与既有口径的衔接

- **生图出口唯一**：不管命中的是专业技能、垂直技能还是都不命中，成品图都由通用技能发消息到平台生成；
  文本美化 / 数据长图 / 信息图优先带「魔卡」，其余走不带 `skill` 的通用生图。不得改成本地代码排版 /
  网页截图渲染当交付（判定与举例 → 通用技能 SKILL.md §0）。
- **[help.md](help.md) §1.3 垂直技能**：用户没命中具体专业技能、但点名了 IFS 技能中心的专项技能时，按 §3 专业技能索引 / §4 垂直技能索引取
  `skill` 名；索引外的技能名**不凭记忆编造**（用户给的官方名可照传）。连接器无技能目录工具时，平台技能清单查询
  仍**如实提示功能尚未就绪**——本索引是插件内置的已知专项集合，不替代平台实时目录。
- **触发竞争（专项优先）**：通用技能描述覆盖泛生成场景，专业技能描述覆盖各自专项——命中专项**一律先走专业技能**
  （专项带必收维度、素材门槛与确认节奏，跳过就漏规则），由专业技能准备到位后转回通用技能执行；
  **只有未命中任何专项**（纯通用生成 / 编辑 / 查询 / 咨询）才由通用技能直接承接。
  **即使通用技能已被激活也不例外**：进了 ifs-ai-design 后只要判定命中专业技能，就必须停下、转去用 Skill 工具激活该专业技能，
  不得因为「已经进了通用技能」就直接在通用技能里出视频 / 出图（判定表与硬门禁见通用技能 SKILL.md §0）。
  视频类特别注意：从创意 / 文字 / 脚本**从零生成一段新视频**一律先走「故事板生视频」，用户没提分镜或脚本也算命中；但分析 / 理解现成视频、按时间点抽帧、换主体重拍、商品与服饰成品短视频、裁剪 / 加字幕 / 转 GIF 都不属于「从零生成」，各走对应技能、不进故事板。
- **能力介绍与边界**：向用户介绍某项专项能做什么时，直接用该技能 SKILL.md 的 description 与 §1（带「典型如」示例更贴近用户问法）；
  用户转述的旧口径偏窄或偏旧时，**按 §3.1 回到对应技能 SKILL.md**，不拿旧口径当能力上限告知用户。
- **新增专业技能**：在 `skills/` 下加一个 `<类型>-<官方技能名>` 目录（类型取 `视频` / `图片` / `数字人` / `音频`，如 `视频-商品图文视频`；`SKILL.md` 的 `name` 用对应 ASCII slug、中文显示名放 `name_zh`、带 description / version，§4 转交文案里的 `skill` 参数传官方中文名），并同步四处：① 本文件 §3 技能清单（官方技能名，= `skill` 参数值）；② 通用技能 SKILL.md 的 description 与 §0 判定表（加一行识别信号）；③ 有 hooks 的宿主同步 hooks 注入文案；④ 宿主 plugin.json 的 `skills` 声明（数组写法必须逐项列出，目录通配写法可略）。
  version 由 `scripts/version.sh` 统一同步（勿手工只改一处，`build.sh` 打包前会校验全部 SKILL.md 版本一致）；上述同步面由 `scripts/audit-skill-docs.sh` 逐项校验。
