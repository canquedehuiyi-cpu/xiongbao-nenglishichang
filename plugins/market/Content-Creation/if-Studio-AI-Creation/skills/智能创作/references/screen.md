# 外挂屏模块 — 内置浏览器操作（唤起 / 激活 / 读取）

外挂屏 = 把 IFS **画布页**呈现在会话内置浏览器里（Chat 发消息 created 打开，
以及持有画布 ID 时的回看；用户挑定灵感案例后回看该案例页也算，见「4. 地址来源」案例地址条）。
**created 必打开（硬门禁）**：每次 `ifs_canvas_create` 返回 `created` 后都必须执行一次唤起（不可延后、不可跳过），
这是用户观察生成进度与产物的主通道；续聊返回 `submitted` 时画布已开，只聚焦已有标签页。
**硬门禁不分通道**：降级期同样每次 `created` 都打开一次（`ifs_canvas_authorize` 有就同名 `ifs mcp call`
换 `login_url`，没有就直接打开标准形态画布地址）——“降级”只换调用形式，不减少画布呈现。
**打开后不刷新**：画布页自带 WebSocket 实时更新，
生成进度与产物会在页面上自己出现。**平台管理页不在范围**：资产库、灵感广场列表页、技能中心、账单/充值等
管理查询类一律经连接器查询（工具以实时 schema 为准），连接器不可用或无对应方法时如实提示
「功能尚未就绪」——不打开页面代查、不编造数据。

- **本模块是内置浏览器操作的唯一入口**：其他模块只决定"打开哪个页面"，怎么打开、怎么聚焦、怎么核对落点、怎么读页面、撞墙怎么办一律按本文件。
- **打开 ≠ 输出链接**：只给一条地址链接不算完成外挂屏操作；链接仅在走不通时兜底（见 5）。
- **打开成功就不再额外输出链接（2026-11-03 用户定）**：落点正常（「3. 落点三判」第 1 行）即完成呈现——
  对话里不再附画布链接、也不单起「画布回看」这类入口行；链接只在「5. 链接兜底」那两种场景各给一次。
- **只呈现、不解释**：对用户的回复只讲"画布已打开 / 结果已更新"这类进展，**不解释地址参数、WebSocket、
  刷新与浏览器操作机制**（话术边界 → [chat.md](chat.md)「对话呈现」）。
- **画布地址有标准形态**：打开画布页或输出画布链接，一律在 `?` 后**整串照抄** `{canvas_link.query_suffix}`（画布链接标准后缀，上方平台配置段注入：平台口径固定参数组 + `title=<标题明文的 URL 编码值>` + `from=<流量归因来源>`，hook 拼装好注入，不逐参数重拼）、**不带 `sessionId`**
  （面板参数隐藏会话面板/左侧栏/顶栏，`top_actions` 为平台口径的顶栏操作参数，`zawarudo_*` 为平台口径的画布交互开关（开关个数与取值以 config/platform.json 的 `canvas_link.fixed_params` 为准，本文件不写死字面值），外挂屏里只剩画布本体；`title` 为平台口径的画布页标题参数（2026-10-27 用户定，链接里取 URL 编码值）；`from` 标明访问来自本宿主/插件；三者都由 hook 从平台配置 config/platform.json 的 `canvas_link` 段现场拼装注入；会话缺省就是该画布最新会话）；
  工具返回的 `canvas_url` 也要照此整形——形态与规则（含后缀取值来源）见「4. 地址来源」。
- **怎么 vs 何时**：本模块定义怎么打开；何时打开见 [chat.md](chat.md)（阶段 ① 打开；**打开后到任务结束都不 reload**——页面 WS 实时更新；**轮询期间也不动浏览器**，频次红线见「2. 激活与视图」末尾）。

**打开画布页要先取授权链接（2026-10-22 用户定）**：按「4. 地址来源」拿到标准形态的画布地址后，先用连接器
`ifs_canvas_authorize { "canvas_url": "<标准形态画布地址>" }` 换回 `login_url`，**内置浏览器打开的是 `login_url`**——
它是 iconfont 主站的登录直达链：用户已登录时打开**直接跳进画布**，未登录时先出登录页，登录成功后**自动回跳到该画布**
（省掉「落到登录页再让用户从头找画布」这一步）。`login_url` 只作浏览器导航目标，**不在对话里输出**（输出/兜底仍用标准形态画布链接，见 4、5）。
工具未挂载该能力、调用报错（重试一次仍失败）或降级期实时方法面没有该方法（`ifs mcp tools --json` 核对；有则同名
`ifs mcp call ifs_canvas_authorize`）时**不必卡住**：直接打开标准形态画布地址，落点按「3. 落点三判」处置。

> 工具来源：以下浏览器工具由会话的 browser-use 连接器（Qoder 内置浏览器）提供，运行时全名形如 `mcp__browser-use__list_pages` / `select_page` / `navigate_page`（`pageId` 是数字，不是字符串）。会话里没有这组工具 = 浏览器能力不可用，直接走「5. 链接兜底」。
>
> **通道唯一**：会话里可能同时存在 `user-browser-use`（扩展驱动用户日常浏览器）同名工具族——外挂屏**不使用**它，一律走内置浏览器；撞硬墙按「5. 链接兜底」，不改道到用户真实浏览器。

## 1. 唤起（打开页面）

1. 确定地址 —— 见「4. 地址来源」，拿到什么用什么（画布页按标准形态在 `?` 后整串补上标准后缀 `{canvas_link.query_suffix}`、去掉 `sessionId`）
2. `list_pages` 列出已开页面（取 `pageId` + URL）
3. 按 URL 判重（两级）：
   - URL 完全相同 → `select_page { "pageId": <id>, "bringToFront": true }` 聚焦，**到此结束**（不取授权链接、不 navigate、不 reload）
   - URL 不同但含同一关键 ID（如 canvas_id，判定见「4. 地址来源」）→ 算同一页面：先 select_page 聚焦，再走第 5 步在该标签页上换地址
4. **画布页先取授权链接**（只在确实要走第 5 步导航时取，一次导航取一次；命中已有标签页只聚焦 → 不取）：
   `ifs_canvas_authorize { "canvas_url": "<第 1 步整形好的标准形态地址>" }` → 用返回的 `login_url` 作为第 5 步的导航地址
   - 传入的是**整形后的地址**：实测 `login_url` 会把整条地址（当时含面板参数与 `from`）编进回跳链，登录成功后原样跳回——后补的 `top_actions`、`zawarudo_*`、`title` 同属整条地址的一部分，随同一机制带过去
   - 返回里的 `message` / `hint` 说明回跳行为（已登录直跳画布；未绑定万相账号先进绑定页再回跳；阿里域账号由主站引导到内网版）——**内部信息，不进对话**
   - `login_url` 的域名是**主站登录域**，与画布域不同且随对内/对外版本变化：**只用工具返回值，不拼不写死**
   - 该工具未挂载 / 调用失败（-32603 重试一次仍失败）/ 降级期 `ifs mcp tools --json` 里没有该方法 → 跳过本步，第 5 步直接用第 1 步的地址
5. 未命中 → `navigate_page { "type": "url", "url": "<login_url，取不到就用第 1 步地址>" }`（浏览器无页面时会自动新建）
6. 核对落点 —— 见「3. 落点三判」，通过才算打开成功

**一个 URL 只有一个标签页**：工具族没有新开标签页的能力，`navigate_page` 永远作用于当前选中页。

> 实测 2026-10-15：连续导航两个不同地址后 `list_pages` 仍只有 1 页（前一个地址被替换）；`evaluate_script` 里 `window.open` 被弹窗拦截返回 `blocked`。多标签只可能由页面在用户手势下自行弹出。

**副作用**：第 5 步会**覆盖当前选中页**。切去另一张画布前，先把当前 `canvas_url` 记在上下文，需要时再 navigate 回去——不要以为旧标签页还在。

## 2. 激活与视图（已开页面，不刷新）

- 激活聚焦：`select_page { "pageId": <id>, "bringToFront": true }`
- **结果不 reload（2026-10-19 用户定）**：IFS 画布页自带 **WebSocket 实时推送**，生成进度与产物在页面上自己更新——从 created 打开到 done，**全程不要 `reload`**。整页重载没有新内容收益，还会把用户的缩放/视图重置回平台保存值（实测：zoom 手动调整后 reload 会回到打开时的保存值，用户看到的"每次打开都是 5%"就来自这里）。
- **缩放异常只用视图控件修正**：若打开时画布缩放明显过小（如 5%），点一次「重置缩放」按钮即可回 100%（纯视图操作、不触发整页加载，算打开动作的收尾，**不破频次红线**，也不消耗算力）；**不要用 reload 修缩放**。确需 reload 排障的，先征得用户同意。
- 历史导航：`navigate_page { "type": "back" }` / `"forward"`——hash 路由的每次跳转都是真实历史条目，可逐级回退
- `select_page` 选定后，截图 / snapshot / reload / navigate / evaluate 都作用于该页；**换页面前先重新 select**，否则 navigate 会把当前页导航走

> **back / forward 的返回文案不可信**（实测 2026-10-15）：回退到首页、前进到技能中心，文案里写的却都是**操作前**的地址。落点一律用 `list_pages` 复核；`type:"url"` 的文案同样只算线索。
>
> `performance.getEntriesByType('navigation')[0].type` 只反映**整页文档加载**（reload / navigate），SPA 换路由不会更新它——可用它证明"确实 reload 过"，不能用它判断当前在哪个路由。

**刷新频次红线（防页面频繁闪动，2026-10-16 用户反馈实测；2026-10-19 收敛）**：一次生成任务内浏览器动作**至多一次且必须一次**——
发消息 created 打开（取授权链接后导航一次，或聚焦复用已有标签页）一次。「至多一次」约束的是上限（不得反复导航/聚焦），
不是可以零次（不得因任务复杂、多轮确认等理由跳过首次打开）。`in_progress` 轮询期间与 `done` 之后都**不再动浏览器**
（不 reload / 不 navigate / 不重复 `select_page` 聚焦）：进度与结果由页面 WS 实时呈现，
每次聚焦还会把浏览器窗口抢到前台，反复聚焦就是用户看到的"闪动"；reload 还会重置用户调整好的缩放与视图。
同页换地址优先 `select_page` 聚焦复用，不要 `navigate_page` 重导航同一地址。

> **授权链接不算浏览器动作**：`ifs_canvas_authorize` 是一次连接器调用（不消耗算力、不动页面），
> 只在"确实要新开/换地址"时取一次；命中已有同画布标签页只聚焦时**不必取**，轮询期间与 done 后也**不要**为同一页面重复取链再导航。

## 3. 落点三判（navigate 打开后必做；先判落点再动页面元素）

> 内置浏览器与用户日常浏览器的登录态不一定互通，所以落点可能是登录页；**按「1. 唤起」取授权链接后打开**，
> 这条路径已经从"意外落到登录页"变成"有设计的登录直达"——登录一次即自动回跳到目标画布，不需要用户从头找画布。
> 降级期同理：**CLI 的 OAuth 登录态与浏览器登录态也相互独立**，CLI 已授权仍可能落到登录页（正常分支，请用户本人登录一次，不因此重复发起 CLI 登录）。

**判定手段（按序降级，实测 2026-10-15）**：

1. `evaluate_script` 取 `{ location.href, document.title, 有无 input[type=password], 正文前 160 字 }`——一次调用即可定论，面板不可见时照样可用
2. `take_snapshot`——需要控件树 / uid 时用；大页面加 `{ "filePath": "/tmp/xxx.txt" }` 落盘再 Grep，别整页灌进上下文
3. `take_screenshot`——仅当浏览器面板对用户可见时才成功，否则报 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`（此时 `visible=true`、`attached=true`、viewport 也有值），**不能当唯一判据**

`list_pages` 的 URL / 标题只算线索、不能定论（跳转可能发生在渲染层）。

| 落点 | 判据 | 处置 |
|------|------|------|
| 正常渲染 IFS 页面 | URL 停在目标地址、标题是业务标题（`title` 参数生效后页签文案可能是配置的标题口径，**文案内容不作判据**）、无密码框、正文有业务内容 | 打开成功，继续业务动作（读页面见 6）；**无需再输出地址链接** |
| 登录页 / 身份选择页（控件可点） | 账号已预选只剩提交，或页面有密码框等登录控件 | **停手**，请用户"在内置浏览器窗口里点一次登录"；不点提交、不选身份、不输账号；**走授权链接打开时这是正常分支**——用户登录完成后页面自己跳回画布，无需再导航第二次；用户点过即持久，之后不再打断 |
| 绑定页 / 内网版引导 | 主站提示绑定万相账号，或阿里域账号被引导到内网版 | 同登录页处理：**用户本人完成**（绑定、切换都由其操作），完成后按工具 `hint` 自动回跳画布；助手不代点、不代填；回跳后按「落点三判」第 1 行复核 |
| 验证墙（控件禁用，用户本人也过不去） | 提示可信设备 / MFA 不可用，验证按钮 disabled | 硬墙：放弃浏览器路径 → 链接兜底（见 5） |

> 实测 2026-10-22（内置浏览器 + 连接器 `ifs_canvas_authorize`）：把标准形态画布地址传入，返回的 `login_url`
> 指向主站登录域，画布地址（含 `session_panel`/`left_panel`/`top_panel`/`top_actions`/`from`）被完整编进 `redirect` 链；
> 已有登录态时一次导航直接停在画布地址上（`document.title` 为业务标题、无密码框、左面板容器宽 16px、
> 正文为画布内容且缩放保持用户上次调整值 112%）——**回跳后参数照样生效，不需要再补一次导航**。

## 4. 地址来源（不改写、不臆造；画布页带隐藏面板参数与来源标注）

> IFS 是 hash 路由 SPA：画布 `/#/canvas/<canvas_id>` 只是一种形态，会话 / 项目 / 灵感 / 资产各有地址格式。

按优先级取地址：

1. 工具返回的 URL（如 `canvas_url`）→ **画布页按下方标准形态整形**：去掉 `sessionId`、在 `?` 后整串补齐标准后缀 `{canvas_link.query_suffix}`（固定参数组与
   `title`、`from` 都在其中，取值见下方标准形态说明）；其余键保持原值、不重复添加、不重排；非画布页原样使用，不拼接、不加参数
2. 用户给出的地址 → 原样使用（画布页只补缺失的固定参数与配置参数（`title`、`from`），**不动用户带的 `sessionId`**——他可能就是要看那条指定会话）
3. 只剩 `canvas_id` → 才构造深链，形态见下——花括号取会话注入的
   平台配置（config/platform.json）；domain 留空时优先复用本次已打开平台页面的域名（同源拼接），
   会话内还没开过平台页则以连接器注册配置（mcp.json 的 url）推断；不写死、不臆造
4. 其他形态 → 不臆造；改走**页面内导航**（见下），或如实说明并引导用户从平台首页进入

**灵感案例地址（`ifs_inspirations` 返回的 `canvas_url`，2026-10-23 实测）**：按第 1 条整形，但两种卡形态不同——

- `design`（图像设计）卡 → `/#/canvas/<canvas_id>`：画布页，整串补上标准后缀 `{canvas_link.query_suffix}`、去掉 `sessionId`（实测经授权链接回跳后
  左面板容器收窄 16px、页面标题 if Studio、`canvas` 元素在位正常渲染；案例节点画在画布上，DOM 里没有节点文字，
  **别用 innerText 判"页面空了"**）
- `video`（视频创作）卡 → `/#/video/<canvas_id>`：案例回放页，**原样使用返回地址、不加标准后缀**（实测该路由没有
  `LeftPanelPosition` 容器，正文直接是完整流程文本：用户输入 → 素材分析 / 创意框架 / 关键元素描述 / 视频创意方案 →
  分镜脚本，2786 个 DOM 节点）——`ifs_canvas_authorize` 对这类链接同样签发 `login_url` 并原样保留入参（实测），
  但既然参数在该路由无对应容器，对话里输出的地址就用返回值
- 域名沿用工具返回值（内含平台环境），**不改写、不拼接、不写死**

**画布深链标准形态**（打开画布页、输出画布链接一律用它）：

```
{platform.domain}/#/canvas/<canvas_id>?{canvas_link.query_suffix}
```

- **标准后缀 `{canvas_link.query_suffix}` 整串照抄，不逐参数重拼**：取上方平台配置段注入的「画布链接标准后缀 query_suffix=…」那一串，接在 `?` 后；它由 hook 从 config/platform.json 的 `canvas_link` 段现场拼装（`fixed_params` + `&title=<title 明文的 URL 编码值>` + `&from=<from>`），编码与拼接都是程序完成，**配置文件与文档都不存后缀/编码字面副本**（抄写必漂移）；改配置重启即全链生效。各组件含义：
  - **固定参数组**（`fixed_params`，取值与顺序整体以 config/platform.json 的 `canvas_link.fixed_params` 为准、本文档不逐参数写死）：三个面板参数（隐藏会话面板 / 左侧栏 / 顶栏）+ `top_actions`（平台给的顶栏操作参数口径，2026-10-20 用户定）+ `zawarudo_*` 画布交互开关（平台给的画布交互开关口径，2026-10-22 用户定）：
    外挂屏里只剩画布本体，呈现干净，也少一层误点平台控件的机会（禁区见「6. 页面内读取与操作」）
  - `title` = **画布页标题参数**（平台给的画布标题口径，2026-10-27 用户定）：后缀里已是标题明文的 URL 编码形态（裸空格/中文会让 Markdown 链接不解析、导航参数被截断）
  - `from` = **来源标注**（标明这次画布访问来自本宿主/插件，供平台侧流量归因）
- **注入缺失时兜底自拼**（SKILL.md §1「配置读取兜底」）：自读 config/platform.json 的 `canvas_link` 段，对 `title` 明文跑一行编码（方式见该段 note），再按 `fixed_params + &title=<编码值> + &from=<from>` 拼出同一串后缀——**不凭记忆写死、不臆造**
- **输出前自检**：链接里 `title=` 后必须是 URL 编码形态（`%XX` 串），出现裸空格、中文或缺后缀即错，回去重取注入值/重拼兜底后缀，不带着病灶输出
- **不带 `sessionId`**：画布页缺省就落到该画布最新会话，带上没有额外作用（实测见下）；
  工具返回的 `canvas_url` 含该键就去掉、缺标准后缀就整串补上。要定位/续接具体会话，用台账里的 `session_id` 走
  [chat.md](chat.md) 阶段 ① 续聊，不靠 URL 传会话
- 标准后缀只加在画布页；首页 / 资产库 / 技能中心等其他路由不加（管理页本就不打开，见开头）
- **整形后的地址就是授权链接的入参**：打开画布页前把它交给 `ifs_canvas_authorize` 换 `login_url`（见「1. 唤起」第 4 步）；
  `login_url` 只用作浏览器导航目标，**不作为对话里输出的地址**——对话与兜底链接一律用上方的标准形态画布地址

## 5. 链接兜底（仅两种场景）

画布页已打开且落点正常**不在此列**——不重复给链接、不单起「画布回看」入口（见文件开头「打开成功就不再额外输出链接」）。

浏览器路径走不通时才输出链接：

1. 会话没有内置浏览器工具族（`list_pages` / `navigate_page` 不可用）
2. 撞上用户本人也过不去的验证墙（落点三判第 3 行）

格式：显式 Markdown 链接、独占一行、行尾无标点、不进代码块、不输出裸 URL；文案按目标页面写；地址用「4. 地址来源」取到并整形的值，没有不编造。画布链接必在 `?` 后**整串照抄**标准后缀 `{canvas_link.query_suffix}`、**不带 `sessionId`**（`title` 在后缀里已是编码值，带空格/中文的明文会把 Markdown 链接截断）；输出前按「4. 地址来源」自检一遍（`title=` 后必须是 `%XX` 编码形态、无裸空格与中文）：

```markdown
[打开画布继续编辑]({platform.domain}/#/canvas/c_xxx?{canvas_link.query_suffix})
```

（域名与标准后缀都按平台配置注入值取、不写死；`c_xxx` 换成台账里的真实画布 ID；`canvas_url` 含 `sessionId` 就去掉、缺标准后缀就整串补上）

> 用户点了链接说"要我登录 / 打不开"时，本次任务若已取到 `login_url`，可把它作为替代链接再给一次（先登录再自动跳画布）；
> 没取到就按上方标准形态输出，**不编造授权地址**。

## 6. 页面内读取与操作（打开之后）

- **读内容**：`evaluate_script` 取 `document.body.innerText` 摘要最省上下文；要控件树用 `take_snapshot { "filePath": ... }` 落盘后 Grep 精确取 uid
- **点控件**：`click { uid }`，uid 必须来自**最近一次** snapshot；DOM 变了就重新 snapshot（常驻控件用旧 uid 仍可点）
- **等元素**：`wait_for { "text": [...] }` 会把**整页快照塞进返回**，上下文开销大——能用 `evaluate_script` 复查就别用它
- **看请求**：`list_network_requests { "resourceTypes": ["xhr","fetch"], "pageSize": 50 }` 只给摘要（reqid / 方法 / URL / 状态码 / mimeType），**没有 headers 与 body**；可用于判断接口是否 401/403（免登失效），读不到错误详情。`pageIdx` 从 0 起，最新请求在末页
- **禁区**：不点技能卡片、不点输入框旁的生成 / 发送按钮、不在提示词框里 `fill`——这些会真的发起生成、消耗用户算力。只点导航链接、分类筛选、Tab 这类纯浏览控件；要生成一律走 `ifs_canvas_create`
- 分类筛选 / Tab 切换是前端状态，**URL 不变**（实测点「视频制作」后仍停在 `#/skills?tab=official`），别用 URL 判断筛选是否生效
