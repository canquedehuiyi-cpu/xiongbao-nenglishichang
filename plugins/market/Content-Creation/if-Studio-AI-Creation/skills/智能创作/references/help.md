# 用户帮助模块 — 使用指导 · 灵感案例

> 定位：帮用户"会用"与"会选"。① 使用指导：回答怎么写需求、怎么选模型、怎么迭代、结果在哪等"怎么用"问题；
> ② 灵感案例：经连接器查询平台「灵感发现」官方案例，每条给全「描述 + 示意图 + 画布地址」（方法未挂载 → 如实提示功能尚未就绪）。
> 选定方向后走 Chat 模块执行（先过 SKILL.md §3 门禁）；本模块不直接发起生成。

## 1. 能力目录（先摸清弹药库）

1. **模型**：`ifs_canvas_models` → 实时模型清单（图像/视频），`name` 字段可直接用于发消息的 `model` 参数（支持模糊匹配）
2. **灵感广场**：经连接器查询官方案例卡（当前方法 `ifs_inspirations`，以 tools/list 实时为准）——
   每条案例呈现「描述 + 示意图 + 画布地址」四件套（细则 → §4）；方法未挂载时**如实提示「灵感案例功能尚未就绪」**，
   不打开平台页面、不编造案例
3. **垂直技能 / 专业技能**：发消息的 `skill` 参数。本插件采用**多技能模式**，已内置一批 IFS 技能中心专项
   **专业技能**（图片/视频/音频/数字人，如商品套图/服饰试穿/数字人口播视频/语音合成等），索引与 `skill` 取值
   → [pro-skills.md](pro-skills.md) §3：用户任务命中某专项时优先走对应专业技能（它准备业务规则与素材后转回通用技能 Chat 执行，`skill` 参数带专项技能名）。**未单独成技能**的更多 IFS 技能中心垂直技能（模特带货图 / 魔卡 / 营销文案 等，清单见 §4）由通用技能**直接带 `skill` 参数**路由 → [pro-skills.md](pro-skills.md) §4。
   用户点名了索引外的技能（来自平台页面/官方介绍）可按其给的名称传 `skill`，**不凭记忆编造技能名**；
   连接器无平台技能目录工具 → 平台实时技能清单查询**如实提示功能尚未就绪**（内置索引不替代平台实时目录）
4. **批量编排**：连接器无批量编排的目录工具与执行通道 → 成套需求按套图口径一条消息说清，
   要更多变体就拆成同画布多轮对话逐个执行，不承诺一键批量

向用户介绍按"模型管单次生成质量、垂直技能管场景化模板、灵感广场管从零起步"区分，不并列混谈。

## 2. 使用指导（用户问"怎么用"时）

| 用户问题 | 指导口径 |
|---------|---------|
| 需求怎么写 | 把要求一次说全：主体+风格+构图+画幅比例+数量（视频加时长），有参考图直接附上，画面要出现的文字给原文；**用户的话会原样进消息**——不做翻译、不改写、不摘成摘要，缺的必需维度才补默认值（chat.md 阶段 ①「需求忠实」）；新开对话禁止"继续/接着"类词 |
| 有哪些模型 | `ifs_canvas_models` 拉实时清单，报 `name` 字段（该方法无入参，参数传空对象 `{}`——直调形态不带 `arguments` 键，图像/视频在清单里自己筛）；拿不准就不传 model，底层自动选 |
| 怎么改图 | 默认就在当前画布改，直接说改哪就行（换主题、换产物类型也一样）；只有明确说"新建画布"才开新画布（SKILL.md §3 原则 3） |
| 卡在确认/表单怎么办 | A2UI 选建议（续聊发建议原文）或提意见（发原话续聊）、表单逐项选择——都是正常流程不是报错（chat.md 阶段 ③④） |
| 生成结果在哪 | 本会话产物**默认落到工作区 `outputs/`**（图片、视频一并下载，回复里会给出路径与目录）；**会话没绑定工作区时落到本次会话目录的 `outputs/`**（回复里会说明它不在你的项目里，并可按你的要求复制到你指定目录）；画布页永久可回看；历史资产查 `ifs_assets`、历史画布查 `ifs_canvas_list`（细则 → asset.md）；整理/移动到其他目录找资产管理模块（asset.md） |
| 花不花钱 | 算力积分制，生成/迭代都消耗；余额/充值口径见 user.md（`quota_info` 优先，无查询工具→提示未就绪，充值由用户本人操作） |
| 插件怎么装 / 连不上 | 激活步骤见 [brand.md](brand.md)「激活插件」；报错按 [exception.md](exception.md) 查表 |
| 能不能批量 | 一条消息说清整套需求，成套产出一次交付（套图规则 chat.md）；要更多变体就同画布多轮续聊逐个出 |

## 3. 灵感引导（用户说"帮我出个主意"时）

按四问收敛，一次问完（用户可跳答）：

1. **用途**：社交媒体 / 电商展示 / 品牌宣导 / 教程配图 / 个人创作
2. **主体**：想突出什么（产品/人物/场景/抽象概念）
3. **风格**：写实 / 插画 / 3D / 国风 / 赛博 / 极简……
4. **载体**：单图 / 套图 / 视频 / 批量物料

收敛后直接输出 2~3 个"可直接执行"的 prompt 草案（完整自包含：主体+风格+构图+画幅比例），
每个注明建议模型（来自 ifs_canvas_models）或垂直技能（skill 参数），让用户挑一个进 Chat 模块发消息；
若连接器提供灵感查询工具（实时为准），可先借同类官方案例的 prompt 思路改写。

## 4. 灵感案例（经连接器查询）

**查询**：灵感案例一律经连接器查询（方法以会话内实时 schema (tools/list) 为准，当前为 `ifs_inspirations`）；
**方法未挂载 → 如实提示「灵感案例功能尚未就绪」**——不打开平台页面、不编造案例；需要灵感时改走 §3 灵感引导。

参数按实时 schema 传：`tag` 分类过滤、`agent_code`（`design`=图像设计，默认 / `video`=视频创作）、
`limit`（默认 10，上限 50）、`cursor` 页码（翻页递增）。返回 `cards[]` + `total` / `has_more`。
平台口径（返回的 usage 说明）：命中较多时**不会一次取全**，本页按近期更新取样后在页内按推荐权重排序
（非全量推荐序），要更多案例用 `cursor` 翻页——不把"这页就是全部"告诉用户。

**分类口径**（`tag` 取值，与平台「灵感发现」tab 一致）：
`all` 全部 / `storyboard` 故事版视频 / `hh` Happy Horse 视频 / `brand` 品牌设计 / `illus` 内容创作 /
`create` 创意玩法 / `media` 社媒物料 / `product` 电商创意 / `clothes` 服饰设计 / `arch` 空间设计 / `other` 其他设计

**呈现——每条案例四件套一次给全，方便用户直接点开看具体内容**（只报标题不给图和地址 = 不合格）：

| 项 | 字段 | 对话里的写法 |
|----|------|-------------|
| 描述 | `description` | 原样转述（案例名 + 一句话说明），不改写成营销话术、不删信息 |
| 示意图 | `cover` | 远程图片地址内嵌渲染成图；**只用远程地址**——本地路径在对话里不渲染（边界 → [chat.md](chat.md)「对话呈现」），也不必为展示案例去下载。个别卡是 `http` 直链（对象存储签名地址），渲染不出时退化为「描述 + 地址」两件套并说明图没显示，**不因此少给案例** |
| 画布地址 | `canvas_url` | Markdown 链接（文案写「打开这条案例的画布」），独占一行、行尾无标点；整形规则见下 |
| 作者 / 分类 / 形态 | `author_name`、`tags`、`video_url` | 跟在描述后一行，如「作者：阿轻 · 故事版视频」；**有 `video_url` = 视频案例**，对话内播不出来（CSP 无 media-src），只标「视频案例」并以封面图作预览 |

多条案例按 1 / 2 / 3 编号成段，每条「描述 → 示意图 → 地址」上下连着排；一次呈现 3~5 条起步，
用户要更多再 `cursor` 翻页，不要一次倒十条把对话框压满。

**画布地址整形**（示例地址来自工具返回，按 [screen.md](screen.md)「4. 地址来源」处理，不臆造不改域名）：

1. `design` 卡返回 `#/canvas/<canvas_id>` → 画布页，按标准形态处理：去掉 `sessionId`、在 `?` 后整串补齐标准后缀 `{canvas_link.query_suffix}`（含固定参数组与 `title`、`from`）
2. `video` 卡返回 `#/video/<canvas_id>` → 案例回放页，**按返回值原样使用**、不加面板参数也不加 `title` 与 `from`
   （实测该路由没有左面板容器，正文直接是完整流程文本：用户输入 → 素材分析 / 创意框架 / 关键元素描述 /
   视频创意方案 → 分镜脚本，正是"打开后看具体内容"的那一页；细则与实测 → [screen.md](screen.md)「灵感案例地址」）
3. 域名沿用工具返回值，不写死、不拼接；只剩 `canvas_id` 时才按 screen.md 构造深链

**承接**（用户挑中某条后）：

1. **想看完整过程** → 案例详情是**完整画布回放**（用户输入 → 任务计划 → 分阶段产物，如故事片案例的
   "故事板生成 → 视频分段 → 完整合成"）：按 screen.md「1. 唤起」先取授权链接再在内置浏览器打开示例画布页
   （一次任务浏览器动作至多一次；用户没要求打开就只给链接，不代开）
2. **想复刻同款** → 把 `description` 当 prompt 思路（不是照抄），按 §2「需求怎么写」改写成自包含 prompt
   （主体 + 风格 + 构图 + 画幅比例），必要时先 `ifs_canvas_models` 挑模型 → 回 Chat 阶段 ① 发消息
3. 本模块**不直接发起生成**，改写后的 prompt 交回 Chat 执行（先过 SKILL.md §3 门禁）

## 5. 组合玩法示例

- 电商套图：一次对话一条消息发全套"场景图+手持图+摆放图+规格图"（说清不拼图）——套图规则见 [chat.md](chat.md)
- 故事分镜：单画布分轮续聊（先出脚本/分镜表，续聊确认后逐段成片）——灵感查询工具可用时（实时为准）可借「故事版视频」分类现成案例，否则按 §3 四问直接出脚本草案
- 品牌物性检查：对客口径见 [brand.md](brand.md)（演示时提醒算力消耗与充值边界）
