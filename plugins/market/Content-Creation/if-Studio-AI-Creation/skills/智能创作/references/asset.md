# 资产管理模块 — 历史画布 · 资产查询 · 产物落盘整理

> 定位：管理**非对话内容**——历史画布、历史资产与本地产物文件；对话过程本身归 [chat.md](chat.md)。
> 跨会话的历史画布/资产查询一律经**连接器查询**（工具以会话内实时 schema (tools/list) 为准）；
> 连接器不可用或无对应方法时，**如实提示「功能尚未就绪」**——不打开平台页面代查、不编造数据。
> 资产的轻量查看也可由用户信息模块承接（[user.md](user.md)），回看/续聊/落盘整理等深管理归本模块。

## 数据来源（两级）

| 场景 | 来源 | 说明 |
|------|------|------|
| 本会话生成过 | 会话内台账（上下文里的 `canvas_id` / `session_id` / 本地产物路径） | 直接用，免查询；"改一下/继续"走 [chat.md](chat.md) 续聊 |
| 跨会话 / 台账没有 | 连接器查询（工具以 tools/list 实时为准） | 无对应查询方法 → **如实提示功能尚未就绪**，不编造画布/资产列表；用户能给出画布链接或 ID 则直接用 |
| 连接器不可用 | 先按 [exception.md](exception.md) 处置授权/链路问题 | 处置完回到本口径；仍无对应方法 → 功能尚未就绪 |

## 画布回看（找画布 / 回看 / 续聊）

1. **有 `canvas_id` / `canvas_url`**（台账或历史消息里）→ 直接用：回看按 [screen.md](screen.md)
   打开**画布页**（画布页在外挂屏呈现范围内；地址按 screen.md「4. 地址来源」整形——去掉 `sessionId`、
   在 `?` 后整串照抄标准后缀 `{canvas_link.query_suffix}`（平台配置段注入，不逐参数重拼），**打开前先按 screen.md「1. 唤起」取授权链接**，
   已有同画布标签页则只聚焦不重开）；要"继续改"走 chat.md 阶段 ① 续聊
2. **没有 ID** → 查 `ifs_canvas_list`（参数只三个：`keyword` 按画布名称或画布 id 模糊过滤、`limit` 默认 20 / 上限 100、`cursor` 页码从 1 递增；返回按更新时间倒序，带 id / 名称 / 缩略图 / 时间 / 详情链接）——
   命中即按第 1 步走；**方法未挂载 → 如实提示功能尚未就绪**，并请用户提供画布链接或 ID（拿到即按第 1 步走）
   ——**不臆造路由、不编造画布列表、不打开资产库等管理页面翻找**。
   注意它**不收 `canvas_id`**（查的是列表，不是单个画布；按 id 找就把 id 放进 `keyword`）。
3. 回看内容：画布页读会话与产物（[screen.md](screen.md)「6. 页面内读取与操作」），聊天内转述摘要 + 预览
4. 用户要"继续改" → 从画布页或台账拿会话 ID → [chat.md](chat.md) 阶段 ① 续聊模式；
   拿不到会话 ID 就**只带画布 ID 续聊**（缺省取该画布最新会话，chat.md 阶段 ①）

## 资产查询（历史创作 / 历史上传）

- 经连接器查 `ifs_assets`（参数只四个：`file_type`（`image` / `video` / `audio`）、
  `source`（`ai` = 历史创作 / `user_upload` = 历史上传）、`limit`、`cursor`——**不收 `canvas_id`**；
  返回里每条已带 `url` / `thumbnail_url` / `canvas_id` / `canvas_name` / `canvas_url`，画布归属直接看字段；
  默认窗口**约最近 7 天**（实际以返回 `range.start` / `end` 为准），`total` / `has_more` 判翻页）
- 本会话产物直接报台账（本地产物路径），免查询
- 存量资产的**导出**：连接器无导出工具 → 需要落盘就把 `ifs_assets` 返回的 `url` 下载到用户指定目录；
  用户本人也可前往 IFS 平台资产库自行下载（助手不代开管理页、不代下、不编造下载地址）

## 项目与分组查询

连接器**没有项目查询工具**（画布不挂 projectId），CLI 侧以 `ifs mcp tools --json` 实时核对同样没有 → 用户问"我有哪些项目 /
某项目里有什么"时**如实提示「项目查询功能尚未就绪」**，不编造项目分组；后续 tools/list 出现
项目查询工具则直接使用。

## 产物落盘与整理（本会话产物）

- **默认落盘，不用等用户开口**：done 返回的**本轮新生成的产物**（图片、视频、音频、文本素材、其他未知类型素材、其他 `media[]` 成果）一律存到
  **工作区 `outputs/`**——`mkdir -p <工作区绝对路径>/outputs`，文件名沿用 `media[].url` 的资源名（文本素材取
  `media[].name` / `media[].title`，缺省按内容类型命名如 `笔记正文.md`；其他素材取
  `media[].name` / `media[].id`，缺省按 `素材_<序号>.json`）、重名加序号不覆盖。
  用户明确指定其他目录时按用户的来；没指定就用 `outputs/`，不追问。
- **只落新素材，原始素材不回流本地**：`media[]` 里与用户上传素材、画布输入原图/原视频同源的那些
  （同一 URL、同资源名、或本轮当参考用的原图）**不下载**——用户本地本来就有，再下等于把原始素材重新导进来。
  分不清就只落本轮 `message` 点名的成果，宁可少下不多下。
- **没有工作区的会话**：以 `pwd` 的当前目录为根落 `<该目录>/outputs/`——宿主给会话临时开的目录（路径带
  `/.qoderwork/workspace/`、`/.qoder/` 这类以点开头的宿主目录，实测**已预建 `outputs/` 与 `uploads/`**）也照这条走，
  **不往家目录乱写、不自建别的位置**；但交付时要说清「这是本次会话的工作目录，不在你的项目里」，
  并问一句要不要复制一份到用户指定目录（用户说不用就不动，不删除、不清空、不挪走）。
- 连接器侧：poll done 回 `media[].url`（图片/视频/音频）或 `media[].content`/`media[].text`（文本素材），
  有 URL 的落盘用 Bash 下载（`curl -L -o <工作区>/outputs/<文件名> <url>`）；
  文本素材用 Bash 写入 `.md` 文件（`cat <<'EOF' > <工作区>/outputs/<文件名>.md` 或 `printf`，
  文本内容原样保存、不截断、不改写）。
- CLI 降级侧：首选 MCP 直通（`ifs mcp call ifs_canvas_poll`）与连接器一致——done 回 `media[].url` 或文本内容，
  落盘同样用 Bash 下载/写入；只有原生命令便利层的 `canvas poll/run --save-dir` 自动落盘，结果在
  `downloaded[].local_path`；`--save-dir`
  传工作区内绝对路径（建议 `<工作区>/outputs`；相对路径以 CLI 进程 cwd 为基准，容易找不到）。
- 用户要"整理到某目录" → 用 Bash 把已落盘文件复制过去；目标目录必须用户明确，未指明就在 `outputs/` 不动。
- 重复下载去重：同一文件可能因重试落盘两次，用 shasum 对比后保留一份。
- 复查/补落盘：再 poll 原会话一次，把缺的 `media[].url` 补下载到 `outputs/`（chat.md 阶段 ⑤）。
- **落盘后必须回告位置**：回复里给出文件链接与所在目录（Markdown 指向绝对路径 + 一句"保存在 `<目录>`"），
  不要只说"已保存"。
- **文本素材**（画布返回的文本类产物，如笔记正文、文案、脚本等）：
  识别方式——`media[]` 中 `type` 为 `text`、或无 `url` 而带 `content` / `text` 字段的条目，
  或 done 返回的独立文本产物字段（以实际返回结构为准）。
  落盘为 `.md` 文件（文件名取 `media[].name` / `media[].title`，缺省按内容类型命名），
  文本原样保存、不截断、不改写、不添加额外格式。
  对话内呈现：文本素材**直接在对话里展示全文**（与图片/视频不同，文本可直接渲染），
  同时给出落盘文件链接与所在目录。
- **其他素材（obj 兜底）**（不属于图片/视频/音频/文本的任何其他产物，如 3D 模型文件、SVG、文档、未来新增的未知类型）：
  识别方式——`media[]` 中不属于前述图片/视频/音频/文本的条目（非 image/video/audio 类型、无 text/content，
  或 `type` 为未识别的值如 `model`、`document`、`file`、`3d` 等）。
  落盘按素材实际形态分两条路：
  - 有 `url` 字段的（如 .glb/.obj/.fbx 模型文件、.pdf 文档等）：
    用 Bash 下载原始文件（`curl -L -o`），文件名沿用 URL 资源名（保留原始扩展名），重名加序号不覆盖。
  - 无 `url` 但有结构化数据的（如纯 JSON 对象、未知结构的新类型）：
    将该条目整体序列化为 JSON 写入 `.json` 文件（文件名取 `media[].name` / `media[].title` / `media[].id`，
    缺省按 `素材_<序号>.json` 命名；**完整保留所有字段，不删减、不改写、不截断**）。
  对话内呈现：给出落盘文件链接与所在目录，并附一句摘要说明素材类型与关键信息
  （如"3D 模型文件，已保存为 `outputs/model.glb`"或"PDF 文档，已保存为 `outputs/report.pdf`"）。
- **视频/音频**：对话渲染面板 CSP 禁媒体，视频和音频在对话内播不出来（chat.md 阶段 ⑤「视频为什么不能
  在对话内播」）——落盘的本地文件就是唯一可播交付物。
  拉起系统播放器（macOS `open "<本地路径>"`、Windows `start "" "<本地路径>"`、Linux `xdg-open "<本地路径>"`，
  一次任务只拉一次，用户说"别自动打开"就跳过）；用户问"文件在哪"→ macOS `open -R "<本地路径>"`（Finder 选中）、
  Windows `explorer /select,"<本地路径>"`、Linux `xdg-open "<所在目录>"`。
  **图片**：对话内预览仍用 `media[].url` **远程地址**渲染（消息正文写本地路径不渲染，显示"图片无法显示"），
  落盘文件作为交付物与兜底；远程图也拿不到时改用本地文件链接。

## 典型组合

- "把我之前生成的海报找出来" → 台账没有 → `ifs_canvas_list`（`keyword` 找画布）→ 打开画布页回看或续聊
- "上周五那张图在哪" → `ifs_assets`（近 7 天，`file_type=image`）→ 按时间与画布名称对 → 给 `url` 或画布页
- "我上传过哪些素材" → `ifs_assets`（`source=user_upload`）
- "把上次那批图存到 ./exports" → 本会话产物直接 Bash 复制；存量资产无导出工具 →
  把 `ifs_assets` 返回的 `url` 下载到指定目录（不打开平台管理页、不编造地址）
- "这个画布里都有什么" → 有画布 ID → 画布页读取（[screen.md](screen.md)）→ 素材清单 + 会话摘要转述；
  没有 ID → `ifs_canvas_list` 查或请用户提供
