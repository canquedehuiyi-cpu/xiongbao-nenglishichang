# Chat 模块（中心模块）— 发消息 · 轮询呈现 · 中断答复 · 结果展示

> **Chat 是中心模块**：统一管理对话全生命周期——发消息、消息轮询/呈现、A2UI 中断、问题中断、
> 续聊、异常恢复与异常提示、结果显示；其余模块是它在执行中按需触发的子能力（见下表）。
> 可靠性契约总表见 SKILL.md §6「可靠性保障」，本文件是其逐阶段细则。
>
> IFS 的生成以**对话**组织：一张画布承载一段对话（`canvas_id` 定画布，`session_id` 定其中的会话线程）。
> 本期工具面只有两个对话工具：`ifs_canvas_create` = 在对话里**发一条消息**
> （新开、续聊、答复中断三合一）；`ifs_canvas_poll` = **等这条消息的回复**（带进度与落盘）。
> 降级期走 CLI 的 MCP 直通调用**同名同参数**的这两个工具（`ifs mcp call ifs_canvas_create …`，
> connector.md §4.2），本文件的阶段与分支口径原样适用。
> 不说"提交任务/重试任务"。
>
> 前置门禁：连接可用性验证未通过（`mcp_list` 查不到 ifs 方法 / 401 / 连接不可达）不得调用本模块工具
> （见 SKILL.md §3 原则 1）——先**主动唤起授权页**（宿主有连接器管理工具时；细则 → [connector.md](connector.md) §3）：
> 用户在浏览器完成登录同意后复验通过就直接开工；唤起不可用或仍未授权，再查**通道偏好**（`~/.qoder/if-Studio-AI-Creation/preferences.json`）：
> 偏好=CLI（用户此前选过「暂不授权」）→ 不再唤起、不弹框、直接进入降级模式；偏好=连接器 → 不弹框、
> 直接进入降级模式并如实说明（唤起已试过；连接器暂不可用、可能授权过期；降级≠改选择，不写偏好）；
> **偏好缺失（从未做过通道选择）→ 唤起失败后才停下，弹三选一对话框**（唯一一次「如何运行」询问：
> 已完成连接器授权/暂不授权/取消任务，推荐激活连接器、也支持先用 CLI 运行；话术 → SKILL.md §5、
> 细则 → [connector.md](connector.md) §3）由用户选择，不自行降级；用户选「暂不授权」→ **先写偏好
> （channel=cli，跨会话不再询问）**再进入降级模式（官方 ifs CLI 直连平台，**首选内置 MCP 直通**：
> `ifs mcp tools --json` 取实时方法面 → `ifs mcp call ifs_canvas_create / ifs_canvas_poll …` 同名同参同返回；
> `canvas run --create-only` + `canvas poll` 只作便利层），接入与调用细则见 connector.md §4（连接器请求模块）；
> 降级期间 CLI 干不了而连接器可完成时的反向升级 → connector.md §4.4。
> **技能门禁（先于发消息）**：进入阶段 ① 前必须已完成 SKILL.md §0 的专项判定——请求命中专业技能就先用 Skill 工具
> 激活它、按其业务规则收齐素材与必收维度再来发消息；命中却未激活、直接组织 prompt 发出去属错误执行
> （判定表 → SKILL.md §0，代理协议 → [pro-skills.md](pro-skills.md) §2）。
> 全流程只有一个循环骨架：**发消息 → 轮询 →（中断则答复后回到轮询）→ 呈现**。
> 中断都是正常流程而非错误：工具正常返回 JSON，只是没有最终媒体。

## 对话呈现（对用户可见的话术边界）

执行任务时，对话框里只呈现**用户需要的内容**：需求理解、正在做什么（有 `progress` 就报百分比）、
需要用户确认或补充的问题、结果预览与产物信息、需要用户本人操作时的步骤、异常的可理解结论。

**以下内容只用于内部执行，不写进对用户的回复**：工具名与调用参数、返回 JSON/字段名、URL 参数
（`session_panel` / `left_panel` / `top_panel` / `top_actions` / `zawarudo_*` / `title` / `from` / `sessionId`）、授权登录链接（`login_url` 及其域名与跳转细节）、
浏览器机制（WebSocket / reload / 落点判断 / 标签页聚焦）、配置与降级通道的内部实现。画布页会通过 WebSocket 自己实时更新——
**不需要向用户解释"为什么不用刷新/怎么呈现的"**。Canvas / Session ID 存入台账即可，**默认不展示**，
用户问起或排障需要时才给。用户主动问"怎么实现的/为什么"时，再按需解释。

**画布链接不额外给（2026-11-03 用户定）**：画布页已经在面板里打开并正常渲染时，进度与交付消息里
**不再附画布链接，也不单起「画布回看」「在 if Studio 打开这张画布」这类入口行**——面板里已经能看到，
再给一遍链接只是噪音。链接只在面板走不通时给一次（浏览器工具不可用 / 验证墙，见阶段 ⑤ 步骤 4
与 [screen.md](screen.md)「5. 链接兜底」）。

**执行实现不播报，也不使用内部术语**：连接探活、加载/查阅执行细则、确认工具与参数结构、组织 prompt、
轮询、存台账、落盘、落点判断等后台动作**直接做、不逐条告诉用户**；对话里不要出现内部模块名与流程名
（如"Chat 主循环""外挂屏""连接器请求""资产管理""异常管理"）。重点始终是**任务本身**：在做什么、进度、
结果和用户需要配合的事。

- **好**："收到，正在生成『未来版清明上河图』，画布已打开，进度会实时更新。"
- **好**："画布已打开，正在按您说的出 3 张 16:9 的商品主图，画面文案用您给的原文。"
  （带上关键要点 = 让用户能当场确认理解没偏，但只说要点，不贴整条消息、不提参数名）
- **好**："正在生成，当前约 40%。"
- **好**："已生成完成，共 1 张，点击图片可查看大图；文件也已存到工作区 outputs/ 目录。"
- **不好**："先做连接探活，同时加载 Chat 主循环的执行细则。"
- **不好**："开始走 Chat 主循环：先确认发消息工具的参数结构，并加载画布页呈现的细则。"
- **不好**："参数结构确认，现在发送生成需求——已把需求组织成完整自包含的创作描述。"
- **不好**："我把它整理成一段英文描述发给了服务端：A futuristic Qingming scroll…"
  （不整段回显消息、更不擅自换语言——用户要中文就按中文发，细则见阶段 ①「需求忠实」）
- **不好**："CLI 直通可用，把等待收进一次循环里，减少打断。"（用户只会理解成"已经降级到 CLI 了"）

**通道术语不进对话（硬口径）**：连接器 / 降级 / 官方 CLI / MCP 直通 / 终端等待循环 / 探活 / 工具名与命令
都是内部执行细节，**正常执行期间一个字都不要对用户说**。尤其不要把"换一种等待方式"讲成
"CLI 直通可用"——用户读到 CLI 就会理解为"已经降级到 CLI 了"，而事实是主通道未变（2026-10-27 实例：
对话框出现"CLI 直通可用，把等待收进一次循环里，减少打断"，用户随即追问"降级到 cli 执行了吗"）。

- 真发生降级（连接器不可用 / 授权过期，任务改由本机 CLI 承接）时，如实且用大白话说一句即可：
  "主连接暂不可用，我换了备用方式继续，任务不中断"；**不提 CLI、不提"直通"**。
- 只是采用「终端等待循环」这类等待节奏技巧时**什么都不说**（内部也不要以"可用/启用"句式播报它），
  对话里继续按节奏报进度与结果。
- 用户主动问"走的是哪条通道/是不是降级了"才解释，且必须一次讲清三件事：**主通道是连接器、当前是否
  真的降级、有没有因此改变任务行为**；不要混用内部词、不要让用户自己推断。

**服务端消息即时回显**：`ifs_canvas_poll` 每轮返回的 `message`（以及 A2UI 的 `planning_text`、
`response_blocks` 中的标题/描述/表单字段）是平台在对话里说的话——**收到新内容就立即转述到对话框**，
不要攒到 done 才说；相同内容只呈现一次，有新变化再发。转述保持原意（方案、问题、选项等关键信息
不改写），技术字段与 JSON 不外露。**每轮另外固定一句短进度**（已等待约几分钟 / 当前百分比），
让用户始终看得到在推进；同一句原话不重复发，也没有进度数字时不编造数字。

**长任务不提前收尾（硬规则）**：视频合成、高清出图、多张套图等慢任务，只要仍在生成（`in_progress`；
CLI 原生命令便利层是 `timeout` 但任务未终态），就**继续轮询同一会话直到终态**——`done` / 出错 / `quota_exceeded` /
`canceled` / 明确不可恢复；**轮询次数不设上限**。等待本身就是任务的一部分：**不把控制权交还用户**——
不写"服务端还没返回完成信号"就收尾、不问"要我继续盯着吗 / 回一句「继续」"、**不说"等一会儿跟我说声
『看下好了没』"**，也不以"可以先看画布页"替代跟进。每轮照常回显新消息与进度，让用户看得到在推进；
只有用户主动叫停才停止（见「停止对话」）。**撑住轮询有专门口径**（宿主对连续同参调用有保护，
poll 最易被掐）→ 见「轮询节奏：别让"等待"被宿主的相同调用保护掐断」。

## 子模块触发（Chat 按需调用）

| 环节 | 触发 |
|------|------|
| 发消息后开画布页 / 结果实时呈现 | 外挂屏 [screen.md](screen.md)「1. 唤起」「2. 激活与视图」（打开后不 reload，页面 WS 实时更新；A2UI 中断不在此列：它落在 Qoder 对话内，见阶段 ③） |
| 在历史画布上继续（缺画布/会话 ID 时） | 资产管理 [asset.md](asset.md)（连接器查询；无对应方法→如实提示未就绪）后，拿 ID 回本模块续聊 |
| 用户上传了本地参考图/视频/音频 | **先上传再发消息**：本地文件走票据直传（`ifs_canvas_upload_ticket` → 本地 curl → `upload_id` → `ifs_canvas_upload`）取回 URL → create 以该 URL 作参考媒体提交（细则 → 阶段 ①「上传前置」） |
| `quota_exceeded` 配额提示 / 充值入口 | 用户信息 [user.md](user.md)「算力不足：先复核再决定」：**先 `ifs_balance` 复核余额**再决定——不够就给充值入口（`quota_info` 转述 + 链接），够就在原会话续聊继续 |
| 工具调用约定与能力总览（参数以实时 schema 为准） | 连接器请求 [connector.md](connector.md) |
| 工具/链路报错（404/-32603/会话不存在等） | 异常管理 [exception.md](exception.md) 按症状查表；-32603 原样重试一次 |

## 流程总览

```
⓪ 用户带本地素材（图/视频/音频）→ 先上传取 URL：票据直传 ticket→本地 curl→upload_id→ifs_canvas_upload（上传前置）
① 发消息（ifs_canvas_create，新开/续聊/答复中断；参考媒体只传 ⓪ 返回的 URL）
   └→ 提交前两关自查：需求忠实（用户提的项一条不丢、不改、不加戏）+ 准确送达（参数对位 · 整段完整 · 定位对会话 · 受理态确认）
   └→ ② 等回复（ifs_canvas_poll）──┬→ in_progress（progress/message）→ 回显新消息+一句短进度，换 timeout 取值回② 继续轮询（勿靠调大等待；长任务按「轮询节奏」的终端等待循环）
                                   ├→ done               → ⑤ 结果呈现
                                   ├→ summary_feedback   → ③ A2UI 中断 → create 续聊发建议原文 → 回②
                                   ├→ ask_user           → ④ 表单中断 → create 携回填 response_blocks 提交 → 回②
                                   ├→ quota_exceeded     → 先查余额复核（user.md），不够给充值入口 / 够则原会话续聊
                                   └→ canceled           → 呈现已取消，停止轮询
```

> **轮询不是静默等待**：每次 poll 返回的新 `message` / 规划 / 表单都要即时回显到对话框（相同内容去重，
> 细则见「对话呈现」与阶段 ②-④），并且**每轮固定一句短进度**（已等待约几分钟 / 当前百分比）——
> 用户要能看到服务端的处理过程，而不是等到 done 才一次出现。
>
> **慢任务必须等到终态**：`in_progress`（CLI 原生命令便利层是 `timeout`）都不是结束信号——持续轮询同一会话直到
> done / 出错 / 配额 / 取消，轮询不设次数上限；**不提前收尾、不询问用户是否继续等**（细则见「对话呈现」）。
> 连续同参调用会被宿主的重复调用保护掐断，**被掐 ≠ 任务结束**——按阶段 ②「轮询节奏」三条对策继续等。

## 阶段 ①：发消息（ifs_canvas_create）

```json
{ "prompt": "<完整自包含需求>", "media_url": "<可选，参考媒体 URL（经 ifs_canvas_upload 取得）>", "media_type": "<可选 image/video，缺省按 URL 后缀推断>", "model": "<可选>", "skill": "<可选>" }
```

- **默认续聊（先定位当前画布，不新建）**：画布只从两处定位——① 用户本条消息给的画布链接 / ID；② 台账里最近一次
  `create` 的 `canvas_id`（`session_id` 可选缺省取该画布最新会话）。**两处都没有就直接新建画布**，不调
  `ifs_canvas_list` 去翻"最近一个画布"（它只在用户明确要回看 / 接着某个旧画布却没给链接或 ID 时才用，[asset.md](asset.md)）。
  prompt 为本轮增量需求，**用户本轮的原话要在里面**（增量 ≠ 助手复述；"更好看一点"这类模糊原话要么保留并补具体化，
  要么先澄清再发）。借旧画布续做（含换主题、换产物类型）时在交付首句点一句画布名，用户可随时纠正
- **新开对话（用户明确要求新建，或手上没有可续的画布）**：①② 都拿不到（首次使用、本会话还没发过消息），
  或用户明确说"新建画布 / 新开一个画布 / 换个画布"才不传画布 ID；此时 prompt 必须完整自包含（主体+风格+构图+画幅比例），
  禁止"继续/接着"类依赖上下文的词。**"重新生成 / 重做 / 换一版 / 再做一个"仍在当前画布续聊，不当新建理由**
- **答复中断也走本工具**（本期无独立 resume 工具）：A2UI 建议 → 续聊发送建议原文
  （阶段 ③）；ask_user 表单 → 回填 `response_blocks` 数组随消息提交（阶段 ④，参数名以实时 schema 为准；
  CLI 原生命令便利层对应 `--response-blocks-file`）
- **上传前置（用户消息带本地图片/视频/音频时强制，顺序不可反）**：参考媒体**只认 URL**——先上传取回 URL，
  再作为 `ifs_canvas_create` 的参考媒体参数提交；**严禁把本地路径直接传给 create**
  （本地路径对远程连接器无意义，不先上传就拿不到参考效果）。按素材来源选通道（参数与返回以实时 schema/返回为准）：

  | 素材来源 | 通道与步骤 |
  |---------|-----------|
  | 本机文件（用户附图/附件，只有本地路径） | **票据直传链**（首选，文件字节不进对话）：① `ifs_canvas_upload_ticket`（`filename` 必填，可带 `size_bytes`）→ ② 按返回的 `command` 在本地执行 curl，把 `LOCAL_FILE_PATH` 换成绝对路径（**`ticket` 字段排在 `file` 之前**；Windows cmd 单引号换双引号）→ ③ 响应 `data.upload_id` 交 `ifs_canvas_upload` → 取回参考媒体 URL |
  | 已有远程地址（用户给的 URL / 上一轮产物 `media[].url`） | `ifs_canvas_upload` 的 `url` 通道直接转传 |
  | 小图兜底（拿得到内容、体积很小） | `ifs_canvas_upload` 的 `data_base64` + `filename`；**大图/视频/音频不要用**——整段 base64 会灌进上下文 |

  边界：单文件上限 5MB（超限在取票阶段就被拒，**不硬试**）；票据一次性、`upload_id` 一次性且**不是 URL**；
  允许的扩展名按 `filename` 后缀返回（图片 / 视频 / 音频三组各不同）；**票据与 upload_id 按凭据对待**——
  不拼进地址、不写日志、不进对话。超限或上传没拿到 URL 时**不编 URL**：向用户说明素材暂不可用
  （过大先压缩/截短、或改给远程地址），处置 → [exception.md](exception.md) §3；连接器细则 → [connector.md](connector.md) §1
- 返回：立即返回不等生成（含 `session_id` 等台账字段；status 与字段以实际返回为准）——拿到就存台账并打开画布页
- **降级模式**：连接器不可用/未授权时（偏好=CLI 直接降级；偏好=连接器则自动降级并如实说明；
  无偏好则经三选一「暂不授权」记入偏好后降级——偏好细则见
  connector.md §3），改走官方 `ifs` CLI 的 **MCP 直通**（`ifs mcp call ifs_canvas_create --args-file create.json --profile {cli.profile}`
  + `ifs mcp call ifs_canvas_poll --args-file poll.json --profile {cli.profile}`，**同名、同 snake_case 参数、同返回字段**，
  **真实提交平台**，本阶段与阶段 ②-⑤ 的分支口径不变；stdout 是 MCP envelope，业务 JSON 在 `content[].text` 里，
  退出码非 0 即失败）；**CLI 每条命令显式带 `--profile {cli.profile}`**（环境绑定硬规则见 connector.md §4 开头；
  不带就沿用机器上的 current profile，可能落到预发）；接入、方法面发现与便利层边界见 [connector.md](connector.md) §4（连接器请求模块）；
  CLI 无法完成任务而连接器可完成时，按 §4.4 反向升级提示恢复连接器。
  **降级不改变本阶段的硬门禁**：发消息前先过 CLI 授权门禁（`ifs_ping` 校验；未登录先发起登录页、
  提示用户本人完成并**停下等确认**，用户确认后复验通过才发消息，细则 → connector.md §4.1）；
  `created` 后**同样必须执行步骤 2 打开内置浏览器画布页**——实时方法面有 `ifs_canvas_authorize`
  就同名 `ifs mcp call` 换 `login_url`，没有就直接开标准形态画布地址；阶段 ②-⑤ 与连接器逐项一致

### 需求忠实（发消息第一关：消息内容 = 用户的意思）

IFS 只能看见这一条消息里的文字，看不见用户与助手之间的对话史——**消息写偏一步，产物就偏一整轮，算力照扣**。
所以 `prompt` 的组织规则是**补全空白**，不是**重新创作**：

1. **先列硬要求清单（内部动作，不播报）**：从用户原话逐项提取——主体与数量、风格与情绪、构图与视角、
   画幅比例 / 尺寸、时长（视频）、**画面里要出现的文字原文**、参考素材及其用途、指定的模型 / 垂直技能、
   输出语言、否定项（"不要 X / 别出现 X"）。
2. **一条都不许丢、不许改**：说了 3 张不能写成"一组"；说了 16:9 不能只写"横版"；型号、品牌名、专有名词、
   价格、slogan 照原样进消息（**用户加引号的原文一字不改，含大小写与标点**）；用户要中文文案就别翻成英文，
   反之亦然——**用户没要求翻译就不翻译**。
3. **补全只补空白、不加戏**：风格 / 构图 / 画幅这类生成必需的维度缺失时补合理默认值；**不塞用户没提的主体、
   流派、额外元素，也不把自己的偏好写成约束**——补的内容与用户原话冲突时，以用户原话为准。
   **自己的推断不是用户意图**：用户没提过的形式、版式、附加内容都不写进消息，也不当验收判据；
   只有专业技能与「套图与垂直技能」里写明的既定规则才能带进消息。
4. **画面文字单独标注**：需要出现在画面上的文案用「需原样呈现的文字：……」的写法给出，别混在描述里被模型改写。
5. **否定项保留并点名区域**：`不要 X` 原样写进消息，并指到具体位置（如"背景里不要出现任何文字"）——
   只列抽象否定清单容易被模型部分忽略（2026-10 实测局部生效），但**不能因此省略**。
6. **不确定就别猜着发**：影响结果的空白（数量 / 比例 / 用途 / 主体有歧义）先用一次问卷式提问或
   A2UI / ask_user 的补问收齐，再发一条完整消息；**发错了不新开对话重来**，同会话续聊纠正
   （保留已有成果，也不双倍耗算力，规则见 SKILL.md §3 原则 3）。
7. **成品图只由平台出**：长图、信息图、图表、文案美化同样发消息生成（先看垂直技能「魔卡」，
   都不命中就不带 `skill`）；用户给的数字与文案原文整段进消息，不用本地 HTML / Canvas / 截图排版代替生成。

### 准确送达（发消息第二关：整条消息原样进平台、落对线程）

内容对了还要真的送到位，四条：

1. **参数对位，不填错不填漏**：参数名以会话内 tools/list 实时 schema 为准（实测 snake_case）；`model` 取
   `ifs_canvas_models` 的 `name`、`skill` 取技能名，**都不凭记忆编造**；用户点名模型 / 技能 / 比例 / 数量时
   **必须体现在这条消息里**（参数给出或文字写明）——只在对话框里答应、消息里不带，服务端并不知道，
   这就是"按用户意思发出去"最常见的漏洞。参考媒体只传上传返回的 URL（见上「上传前置」）。
2. **整段文本完整提交**：`prompt` 一次传完整，**不截断、不用省略号收尾、不把用户给的长文案 / 脚本摘成摘要**。
   降级走 CLI 时，含中文 / 引号 / 换行 / 数组的参数一律写进 JSON 文件用 `--args-file`（在 shell 里拼 JSON
   最容易把内容吃掉，connector.md §4.2）。
3. **定位到正确的线程**：续聊与答复中断的 `canvas_id` + `session_id` 按 SKILL.md §3 原则 3 的画布定位顺序取
   （用户给的链接 → 台账最近一次 `create`；都没有就按新画布发），**从返回值里取、不凭记忆敲、不跨画布混用**；
   多画布 / 多任务并行时逐个绑定，**一条消息只服务一个会话**。
4. **发送结果判定与幂等**：create 返回受理态（实测新开 `created` / 续聊 `submitted`）且 ID 齐全 = 这条消息
   已经送达，立即存台账再进阶段 ②；报参数不合法 / -32603 → **原样重试同一条**（不是重新组织一条）；
   仍失败转 [exception.md](exception.md)，**期间绝不发第二条内容相同或冲突的消息**——重复发消息是真事故
   （起两条线程、双份扣算力）。落错会话 / 会话不存在时改的是定位参数，不是重写需求。
5. **调用形态对位（宿主关，先于参数对错）**：先看调的是哪种入口——**直调**（工具名已含方法名，如
   `mcp__plugin_<插件名>_iconfont-ifs__ifs_canvas_create`，实际名以 `mcp_list` 返回为准）则 `prompt` 等业务参数**直接摊平传**，
   参数对象里**只有业务字段，`arguments`/`toolName` 一个都不能带（值给 `null` 也不行）**
   （带了就被拒：`params must NOT have additional properties`）；
   只有工具名本身是 `mcp_call` 的元工具才拼信封：`toolName` = `mcp_list` 实时返回的**全限定名**（别凭记忆拼前缀），
   与 `arguments` **平级**，业务参数**只进 `arguments`**（把它写进 `arguments` / 写成 `tool_name` / 摊到顶层
   都只会被判成缺 `toolName`）。这两类报错都是**请求根本没出本机**：按报错改形态（去外壳或补信封）
   **原样重发同一次调用**即可——不算「加发第二条消息」，也不扣算力（长中文 prompt 不影响解析，2026-11-02
   实测；细则 → [connector.md](connector.md) §1「先判调用形态」）。

**提交前自查（五条，缺任一条先改再发）**：① 用户提过的每一项在消息里都在；② 没有多出用户没要求的
主体 / 风格 / 元素；③ 引用的原话与画面文字一字未改；④ 定位参数来自台账、模型与技能取自实时清单；
⑤ 调用形态对位——直调时业务参数摊平、**没有 `toolName`/`arguments` 键（包括 `arguments: null`）**；经 `mcp_call` 时 `toolName`（实时全限定名）与 `arguments` 平级、业务参数全在 `arguments` 里，且没有该方法 schema 之外的字段（无入参的方法传空对象 `{}`；探活 `ifs_ping` 同理，**它不接 `keyword` 这类检索字段**，找方法用 `mcp_list`）。

**发送后立即动作（顺序固定，步骤 2 是硬门禁——不完成不得进步骤 4）**：

1. 把 `canvas_id` / `session_id` / `canvas_url` 存入上下文
2. **️ 必须用会话内置浏览器打开画布页（硬门禁，不可延后、不可跳过、不可留给"下一轮再开"）**：
   - **为什么是硬门禁**：画布页是用户观察生成进度与产物的主通道（WS 实时推送）；不打开 = 用户看不到
     右侧画布、只能靠对话里的文本和缩略图推断进展，体验断裂——**每次 `ifs_canvas_create` 返回
     `created` 都执行一次**（续聊返回 `submitted` 时画布页已开、不重复导航，只聚焦已有标签页）。
     即便是故事板这类多轮 A2UI 确认任务，**第一次 `created` 就打开画布**，后续 A2UI 确认与分段出片
     期间页面靠 WS 自行更新，不需要再动浏览器。
   - 地址 = `canvas_url` 按 [screen.md](screen.md)「4. 地址来源」整形——**去掉 `sessionId`**、在 `?` 后整串照抄标准后缀 `{canvas_link.query_suffix}`（平台配置段注入，不逐参数重拼）
     （面板参数隐藏会话面板/左侧栏/顶栏，`top_actions` 为平台口径的顶栏操作参数，`zawarudo_*` 为平台口径的画布交互开关（开关个数与取值以 `canvas_link.fixed_params` 为准、不写死字面值），外挂屏里只剩画布本体；`title` 与 `from` 取平台 config/platform.json 的配置值——`title` 只用编码值、不拼带空格的明文，`from` 标明访问来自本宿主/插件，取值口径见 screen.md §4；会话缺省即该画布最新会话）；
   - 整形后的地址先交 `ifs_canvas_authorize` 换回 `login_url`，**浏览器打开 `login_url`**（已登录直接进画布，未登录登录一次即自动回跳；取不到授权链接就直接开画布地址，不卡流程）；
   - 再按「1. 唤起」六步执行（`list_pages` → 判重 → 取授权 → `navigate_page` → 核对落点），已开同画布标签页则只激活聚焦（不重复取链），落点是登录页 / 绑定页按「3. 落点三判」停手等用户本人操作
   - **内置浏览器工具不可用时**（会话里没有 `list_pages`/`navigate_page` 工具族）：不阻塞流程，直接跳到步骤 3 的兜底链接输出，然后进步骤 4
3. 浏览器打开成功：回一句自然的进度话术，**里面带上用户提过的关键要点**（数量 / 画幅 / 主体这类，
   如"画布已打开，正在按您说的出 3 张 16:9 的主图"）——让用户一眼确认消息是按他的意思发出去的，
   理解偏了能当场喊停；**不播报"组织需求/发送消息"这类过程，也不在对话框里展示地址、
   参数或 Canvas/Session ID**（ID 存台账；用户问起或排障时才给，话术边界见「对话呈现」）；
   浏览器不可用或撞上用户本人也过不去的验证墙时，才回退输出链接（判定与格式见
   screen.md「5. 链接兜底」；地址按标准形态整形，但对话里只给链接本身、不解释参数）
4. 进入阶段 ②（**前提：步骤 2 已执行或已确认浏览器不可用**——不得带着未完成的步骤 2 直接 poll）

## 阶段 ②：等回复（ifs_canvas_poll）

```json
{ "session_id": "s_xxx", "canvas_id": "c_xxx", "timeout_seconds": 30 }
```

- 单次最长等待约 30 秒（`timeout_seconds` 可调 1-55，上限受链路约束）；**未完成返回 `in_progress`——
  继续调用而非靠调大等待来收尾**（取值按下方「轮询节奏」在 55/45/35 之间轮换，避免连续同参被宿主拦停）；
  会话 ID 必传（多会话画布缺省取最新会摸错线程），画布 ID 可选（用于画布详情链接）
- 连接器 poll **无落盘参数**：done 回 `media[].url`（图片/视频/音频）或文本内容（文本素材），**产物默认一律落盘到工作区 `outputs/`**（图片/视频/音频用 Bash 下载，文本素材用 Bash 写入 `.md` 文件；
  细则 → 阶段 ⑤；降级 MCP 直通同口径，只有 CLI 原生命令便利层的 `--save-dir` 会自动落盘，传该目录即可）
- 返回的 `status` 决定去向：

| status | 含义 | 去向 |
|--------|------|------|
| `in_progress` | 生成中（可能附 `progress` / `message`） | ① 本轮有**新的** `message`（或规划/表单文本）→ 立即原意转述到对话框（相同内容不重复发，不攒到 done）；② **每轮固定一句短进度**（已等待约几分钟 + 当前百分比；不提轮询/工具名等机制，话术见「对话呈现」）；③ 回本阶段继续轮询（单次等待上限约 55 秒，未完成就再调一次，**勿靠调大等待时间**；**下一轮换一个 `timeout_seconds` 取值**；**持续到终态、不设轮询上限，不中途交还控制权**——节奏细则见下方「轮询节奏」；**但「一直在 in_progress」不等于任务在跑**（会话 ID 错时 poll 不报错、照样回 in_progress，判死口见下方「轮询不会自己结束」））；**不动浏览器**（不 reload/不聚焦/不新开——进度由页面 WS 实时呈现，频次红线见 screen.md「刷新频次红线」） |
| `done` | 完成，`media[]` 已随返回给出（可能附 `message` / 总结） | 阶段 ⑤（先回显 `message` / 总结，再预览媒体） |
| `summary_feedback` | A2UI 规划确认挂起（`planning_text` + `response_blocks`） | 阶段 ③（先转述规划与建议，再问卷） |
| `ask_user` | 补充问题表单挂起（`response_blocks`） | 阶段 ④（先呈现表单，再问卷收集） |
| `quota_exceeded` | 算力配额不足（create 返回或 poll 返回） | 「异常恢复与提示」：先 `ifs_balance` 复核余额（[user.md](user.md)），不够给充值入口 / 够则原会话续聊 |
| `canceled` | 任务已被取消（平台侧） | 「异常恢复与提示」 |

- **回显优先级**：服务端消息（`message`）优先于百分比——先转述平台说了什么，再报进度；
  两者都没有新内容时**仍报一句短进度**（"还在生成，已等待约 3 分钟"），不静默消失、也不重复同一句原话。

- **轮询到终态，不提前交还控制权**：`in_progress` 只是中间态，不是"暂时没结果"——继续调用同一会话直到
  `done` / 出错 / `quota_exceeded` / `canceled`；**不能因为等得久就收尾**，也不能把"还没返回完成信号"
  当结论。用户没有叫停就一直等（用户说停 → 转「停止对话」）。

- 交互态识别共性：工具正常返回（非报错）、有 `status`、无 `media`；处理完对应阶段后回到本阶段重新轮询

### 轮询节奏：别让"等待"被宿主的相同调用保护掐断（2026-10-22 实测）

**宿主有一道相同调用保护**：同一工具、参数完全相同的调用连着四次放行，第五次被硬拦并回一句
"不要再调用它，改参数或直接给结论"；中间只要夹进一次**不同**的调用，计数就重新起算。
poll 正是最容易撞上的形态（同一个会话 ID 反复调），而单次等待又被锁死在 55 秒——
15 分钟的视频约 17 轮，硬撑必然被掐。**被掐那一刻任务通常还在生成，这不是终态**；
就此收尾等于把跟进责任丢回给用户（"等一会儿跟我说声『看下好了没』"就是这么来的）。

按顺序用三条对策，前一条够用就不往上升：

1. **轮换 `timeout_seconds`**：`55 → 45 → 35` 三个值轮着给，相邻两次取值不同即可（永远凑不出连续四次同参），
   顺带把单轮等待拉到接近上限、总轮数更少。`session_id` / `canvas_id` 保持稳定——
   **不要为了"制造变化"去动定位参数**。
   经元工具 `mcp_call` 轮询时（懒加载宿主）：**换的只是 `arguments` 里的取值**，`toolName` 与
   `arguments` 的平级结构不动——被拦停后"改参数"最容易顺手把 `toolName` 挪进 `arguments`，
   那会撞成 `MCP Call tool parameter validation failed: … 'toolName'`；直调形态反过来，**只改业务参数本身、
   一个信封键都不加（`arguments: null` 也不算）**（两种形态的判法与报错处置 → connector.md §1「先判调用形态」）。
2. **轮间夹一次不同调用**：落盘前的 `mkdir`、取一次时间戳、或做一次 `ifs_ping` 都算——它让 poll 不相邻同参，
   也把节奏拉开、不空转。
3. **已知长任务（视频合成 / 高清出图 / 套图 / 逐段故事板）把多轮 poll 收进一次 Bash 调用**——即
   **「终端等待循环」**：用本机官方 `ifs` 的 shell 循环等待同一会话，等待类调用数从十几次压到几次，
   天然不受这道保护影响。前提是本机 `ifs` 已有可用且与 `{cli.registry}` 一致的 OAuth profile
    （`ifs mcp call ifs_ping --args '{}' --profile {cli.profile}` 返回 `pong`）——**不满足就退回 1+2，
    绝不为了等待要求用户新登录**（profile 与插件环境不匹配时按 connector.md §4 开头的环境绑定规则处理）。
   **它是等待节奏技巧，不是降级**：主通道仍是连接器，发消息、上传、答复中断全部照旧走连接器，
   只有"等"这一步借用同一平台的循环；**不因此改变通道偏好、不向用户播报**（话术边界见「对话呈现」
   的"通道术语不进对话"）。

```sh
# 终端等待循环：一次调用内连续等待同一会话：命中终态退 0；预算用尽仍在跑退 2（报一行进度后再来一次）
sid=<session_id>; cid=<canvas_id>; end=$(( $(date +%s) + 100 ))
while :; do
  printf '{"session_id":"%s","canvas_id":"%s","timeout_seconds":50}' "$sid" "$cid" > /tmp/ifs_poll.json
  out=$(ifs mcp call ifs_canvas_poll --args-file /tmp/ifs_poll.json --profile {cli.profile}) || { echo "CLI_FAIL $out"; exit 1; }
  line=$(printf '%s' "$out" | python3 -c '
import json,sys
d=json.loads(json.load(sys.stdin)["content"][0]["text"])
print("%s|%s|%s" % (d.get("status"), d.get("progress",""),
                    (d.get("message") or "").replace("\n"," ")[:120]))')
  echo "$line"
  case "$line" in in_progress*) : ;; *) exit 0 ;; esac
  [ "$(date +%s)" -ge "$end" ] && { echo "STILL_RUNNING"; exit 2; }
done
# 退 2 只是预算用尽，可以再来一次；但「同一个会话累计等超经验上限、progress 一直为空」要判死（见上节），别无限重跑
```

- 每轮打印 `status|progress|message`：**取到终态就退出**，回到阶段 ②-⑤ 的同一套分支处理
  （终端等待循环拿到的返回结构与连接器完全一致，`summary_feedback` / `ask_user` 照样要先在对话里回显再收集）；
  退出码 `2` = 预算用尽仍在生成 → 报一句进度、再发起一次同样的循环
- 单轮 `50` 秒 × 预算 `100` 秒是安全值，**并把这次 Bash 调用的超时设到 3 分钟**（宿主默认 2 分钟会先掐）
- 循环里**只 poll，绝不重复 `create`**（重复发消息才是真事故）；用户中途叫停 → 结束循环转「停止对话」

### 轮询不会自己结束：会话 ID 错 = 永远 `in_progress`（2026-11-03 实测）

**实测**：`ifs_canvas_poll` 传一个不存在的 `session_id` 不报错，照样返回 `status=in_progress` + `poll_again=true`
（随便编个 `s_AAAAAAAAAAAAAA` 也是这个返回）。画布上该轮早已出图、服务端 `updated_at` 十几分钟不动，
poll 仍说「生成仍在进行中」。所以**一直 in_progress 不等于任务在跑**：定位参数错了就是永远等不到终态。

- `session_id` 只取**本次 `create` 返回的那一个**，原样复制：不手打、不从上一条消息或另一个会话推断
  （`l/I`、`0/O` 一抄错就永远 in_progress）。
- `polls` / `elapsed_seconds` 是**单次调用内部**的轮询次数与耗时（`timeout_seconds=50` 约 26 次），
  不是任务进度——别把 `message` 里的「已轮询 N 次」当成在推进。
- **判死条件**（任一满足就停，不再重跑等待循环）：① 连续 3 轮 `message` 一致且 `progress` 始终为空；
  ② 同一会话累计等待超过经验上限（图 5 分钟 / 套图 8 分钟 / 音频 5 分钟 / 视频 20 分钟）；
  ③ 已经拿到过 `done` 或这一轮的产物。
- **判死后先核实产物**：查 `ifs_assets`（近 7 天，**不收 `canvas_id` 过滤**——它只接 `file_type` / `source` / `limit` / `cursor`，画布归属看返回里的名称/链接自己对）或让用户看画布页——**有产物就交付**，
  如实说「服务端没回报完成状态」；没有就说明情况 + 给画布链接，等用户回看或稍后重试。
- **缺图不要靠继续 poll 等**：要 3 张只出 2 张 → `create` 续聊补那一张。

**三条都用完仍被拦停时的收尾口径**：如实说"还在生成（进度 X% / 已等待约 Y 分钟），我继续盯着这条会话"，
ID 留在台账；**用户下一句任意话都立刻接着 poll 同一会话**，不重发消息、不问"要不要继续等"。
**禁止**把等待推回给用户：跟我说声『看下好了没』、回一句『继续』、"服务端还没返回完成信号"就先收。

## 阶段 ③：A2UI 中断（status=summary_feedback，服务端出规划卡片等确认）

**识别**：`status=summary_feedback`、`completed=false`、无 `media`、工具正常返回。
服务端已产出规划（分镜脚本/方案卡片）并挂起，等用户确认后才继续生成。
**A2UI 的交互落在 Qoder 对话内、不在外挂屏**：由助手触发问卷式提问（AskUserQuestion 一类
宿主提问工具），用户在对话里点选答案并提交。

**数据定位**：

| 字段 | 内容 | 用途 |
|------|------|------|
| `planning_text` | 末条规划文案 | 转述给用户（长文提炼关键决策点，不全文倾倒） |
| `response_blocks[0].data.suggestions[]` | 每项含 `title` + `description` | 整理成编号选项列出 |
| `message` | 顶层引导语（如"接下来可以尝试"） | 先于问卷回显到对话框（复述下一步） |

`planning_text` 为空时（异常形态）回退：引导用户到画布页查看完整脚本。

**处理步骤**：

1. **先把方案发到对话框**：转述 `planning_text` 要点（长文提炼关键决策点，不全文倾倒）+ 复述 `message`
   ——用户要先看到规划内容，才知道在确认什么
2. **列出选项并用 Qoder 问卷式提问交互收集确认**：对话框里同步列出编号选项（各条
   `suggestions[].title` 原文 + `description` 说明），问卷选项与之一致；允许自由输入承接建议之外的意见；
   用户点选提交后进入下一步
3. 按用户答复用 `ifs_canvas_create` **续聊答复**（无独立 resume 工具，语义参照 CLI 以续聊消息表达确认）：
   - **选定某条建议** → 消息内容**必须传该条 `suggestions[].title` 原文**（一字不改，
     转述改写会匹配失败）：
     ```json
     { "prompt": "<suggestions[].title 原文>", "canvas_id": "c_xxx", "session_id": "s_xxx" }
     ```
   - **建议之外的新要求** → 同样续聊，消息内容为用户原话（画布 ID + 增量需求），
     服务端按新意图重新规划
4. create 返回 → 回阶段 ② 轮询（会先 `in_progress` 再到结果）

**红线**：服务端在等输入，消息列表不会变化——未答复前**严禁重复轮询**（只会白等到超时）。
**可能多次出现**：确认后服务端可能逐段推进并再次请求确认（如逐张故事板），循环本阶段直到 `done`。

## 阶段 ④：问题中断（status=ask_user，服务端反问表单回填）

**识别**：`status=ask_user`、正常返回非报错。服务端判定需求条件不充分（如"设计一个 logo"未指明行业/风格），
返回 `response_blocks` 反问表单。**是对话中的反问不是错误：不重发、不报错、不重复轮询。**

**表单结构**（`response_blocks[].type=ask_user_form`，业务数据在 `data` 内）：

```json
{
  "type": "ask_user_form",
  "data": {
    "mode": "form", "state": "editing",
    "title": "请补充 Logo 设计的关键信息",
    "description": "为了生成更符合您需求的 Logo，请选择以下维度（已为您预填默认值）",
    "allowCustom": true,
    "fields": [
      { "name": "industry", "label": "行业/用途", "type": "select",
        "value": "创新、智能、未来感", "defaultValue": "创新、智能、未来感",
        "options": [
          { "label": "科技互联网", "value": "创新、智能、未来感" },
          { "label": "餐饮消费", "value": "温暖、美味、地道" }
        ],
        "allowCustom": true, "required": true }
    ]
  },
  "message": "请补充 Logo 设计的关键信息"
}
```

**处理步骤**：

1. **先把表单发到对话框**：呈现 `message` 与表单的 `title` / `description`，并逐字段列出
   （`label` + 各 `options[].label` + 默认值）——让用户看到服务端在问什么；再用 Qoder 问卷式提问
   交互收集选择，问卷字段与之一致；`allowCustom: true` 时说明可直接自由描述
2. 收集用户选择后**组装回填 `response_blocks` 数组**（直接作为 create 参数给出，无需写文件），三条硬规则：
   - 字段 `value` **必须用 `options[].value`**（如 `"创新、智能、未来感"`），不是 label（如 `"科技互联网"`）——服务端按 value 语义匹配
   - `data.state` 必须从 `editing` 改为 `submitted`
   - 整体用数组结构：`[ { "type": "ask_user_form", "data": { ...原表单, "state": "submitted", 各字段 value 已填 } } ]`（单对象也兼容，推荐数组）
3. 提交回填——由 `ifs_canvas_create` **携带 `response_blocks` 数组参数**提交（与 `canvas_id` + `session_id`
   搭配，本期无独立 resume 工具；提交时**不需再写 prompt**）：
   ```json
   { "canvas_id": "c_xxx", "session_id": "s_xxx", "response_blocks": [ { "type": "ask_user_form", "data": { "...": "已填值并改 state=submitted 的原表单" } } ] }
   ```
   降级 MCP 直通就是同一工具同一参数（把上面这段 JSON 写进 args.json 走 `ifs mcp call ifs_canvas_create --args-file args.json --profile {cli.profile}`）；
   CLI 原生命令便利层才用 `--response-blocks-file`（回填数组写进 form.json 后以文件传入）
4. 回到阶段 ② 轮询；表单可能多轮（一次反问未覆盖全部维度），循环本阶段

8. **对照用户原话验收**：呈现前把阶段 ①「需求忠实」列的逐项要求对着产物看——数量、画幅 / 尺寸、
   画面文字原文、指定主体与风格、否定项（不该出现的东西）。**标准只有用户原话**：自己补的默认值只是
   生成兜底，不拿来判不符；**画布怎么排布（并排 / 分栏 / 标题条）只是展示形态、不是产物形态**，
   核对只对产物本身。**看不清不断言**：整图缩略看不出文字与细节错误，
   按需用本机图像工具裁切放大局部（`sips` / `ffmpeg` 都可，没有就把远程图在画布页里放大看）目视核对；交付话术分开说**已满足 / 仍不符**
   两档，不替服务端遮丑、也不笼统说"已按您的要求完成"。
   **纠正有界**：确有不符 → 同会话续聊做精确纠正（点名哪个区域改成什么、引用用户原要求），不新开对话重做、
   不擅自替用户决定"这样也行"；**同一个问题只自动纠正一次**，再发后仍不符就如实说明、把选择交给用户
   （接受现状 / 换个改法），不再自动重发——用户没提的偏差不纠正。

**视频为什么不能在对话内播（2026-10-20 实测，别再试第二条路）**：对话内的 HTML 渲染面板带固定 CSP
（`default-src 'none'`，且**没有 `media-src`** → 媒体一律被拦；`img-src data:`、`connect-src 'none'`），
实测三种写法全部黑屏 0:00：远程 https 直挂 `<video src>`、`data:` 内嵌整段视频、以及想靠 `fetch` 造
`blob:` 再播（connect-src 也禁着，且平台 CDN `agi.alicdn.com` 不回 `Access-Control-Allow-Origin`、
OPTIONS 直接 403，跨域取不到数据）。**产物本身没问题**：落盘文件 ffprobe 为 H.264(High)/yuv420p + AAC、
`moov` 在文件头，远程地址 `Content-Type: video/mp4`、支持 Range（206）——在画布页与系统播放器里都能正常播。
所以视频的可播通道只有两条：**画布页**（页面原生播放器）与**本地文件**（系统播放器）。

**图片渲染的两条边界（2026-10-20 实测）**：① 消息正文里写**本地路径**图片（`![](/绝对路径.jpg)`）不渲染，
显示为"图片无法显示，打开文件"——图片一律用 `media[].url` 远程地址；② 对话内 HTML 渲染面板只允许
`img-src data:`，该面板里远程 https 图片同样不显示，要放图就得把图 base64 成 `data:` 内嵌。
两条都不成立时（远程图也不出）就退到文件链接：落盘 + Markdown 指向绝对路径 + 写明所在目录。

**复查与回看（本期无快照工具）**——poll 是等回复的对话驱动，需要复查/补落盘时：

- 再 `ifs_canvas_poll` 一次原会话：done 态返回与上次一致（media 已渲染过就不重复展示），按需用 Bash
  把缺的 `media[].url` 补下载到工作区 `outputs/`（CLI 原生命令便利层 `--save-dir` 指向该目录即自动落盘）
- 或按 [screen.md](screen.md) 打开画布页回看（完整会话史与产物以页面为准；地址在 `?` 后整串照抄标准后缀 `{canvas_link.query_suffix}`（含固定参数组与 `title`、`from`）、
  不带 `sessionId`，见 screen.md「4. 地址来源」；打开前按 screen.md「1. 唤起」先取授权链接）
- 隔会话回看：资产管理 [asset.md](asset.md)（连接器查询；无对应方法→如实提示未就绪）

## 停止对话（用户叫停）

触发：用户明确说"停掉/取消/不要了"，或发现需求发错。**用户没叫停就绝不擅自取消。**

本期无取消工具，处置顺序：

1. **立即停止轮询**：不再 poll、不重发、不再触发任何新消息
2. **引导用户手动停止**：按 [screen.md](screen.md) 打开画布页，告知用户在页面上自行点停止
   （停止按钮不是纯浏览控件，助手不代点）；或用户不介意就让本轮自然跑完/超时
3. 告知已停止跟进；之后要改结果，就同对话继续聊新需求（默认仍在该画布），只有用户明确要求新建画布才新开

## 异常恢复与提示（超时 / 配额 / 取消 / 服务端报错）

- **对用户只说结论与下一步**：一句可理解的原因 + 需要用户做什么、或可以等什么；**不贴原始报错 JSON、
  错误码堆栈、工具名与参数**（技术排障细节留在内部；用户主动问再解释，话术边界见「对话呈现」）
- **长任务不设等待上限**：poll 未完成只返回 `in_progress`——**继续调用而非调大等待**（单次上限约 55 秒）；
  CLI 原生命令便利层的 `timeout` 同样**不是终态**，可加大 `--timeout` 续 poll 原会话（降级 MCP 直通返回的仍是
  `in_progress`，继续调用即可）；一直等到
  done / 出错 / 配额 / 取消（**「一直在 in_progress」有判死口**，见下方一条）。**严禁**以"等太久 / 还没返回完成信号"为由收尾，**严禁**询问用户
  "要不要继续等 / 回一句『继续』"；两条通道都严禁重复发消息
- **「一直 in_progress」≠ 任务在跑**（2026-11-03 实测：`session_id` 错时 poll 不报错、静默回 `in_progress`）：
  连续 3 轮 `message` 一致且 `progress` 为空、或超过经验上限仍在转 → **停止轮询**，先查 `ifs_assets` 核实产物（无画布过滤参数，看返回里的画布名称/链接对），
  有产物就交付、没有就如实说明 + 给画布链接。**不得无限重跑等待循环**（阶段 ②「轮询不会自己结束」）
- **被宿主的重复调用保护拦停 ≠ 任务失败**：连续同参 poll 到第四次后会被硬掐（提示改参数或直接给结论）。
  按阶段 ②「轮询节奏」处置——轮换 `timeout_seconds` / 轮间夹一次不同调用 / 长任务改走一次 Bash 调用内的
  **终端等待循环**（换的是等待形态，主通道仍是连接器，**不因此对用户提"CLI/直通"**，见「对话呈现」）；
  三条都用完仍被掐时按该节的收尾口径收（报进度 + 继续盯同一会话），**不把它当成终态**
- **只有任务确实卡死或报错**（如服务端明确报错、长时间无进度且状态异常）才同对话续聊改参重发
  （保留已有成果）；同一对话最多重发 3 次（**含按阶段 ⑤ 修正产物的纠正续聊，同一问题只纠正一次**），
  之后如实向用户说明卡点。**这 3 次上限只约束重发新消息，
  不约束对原会话的持续轮询**——任务没到终态就继续等，不因重发次数用完而停止跟进
- `quota_exceeded`（算力配额不足，create 返回或 poll 返回都算）：**先经连接器 `ifs_balance` 查一次余额确认**，
  再决定——余额确实不够 → 转述 `quota_info` 提示 + 余额，并给充值入口（有链接就给，没有让用户自行前往
  IFS 平台充值，[user.md](user.md)），**不重发、不编造、不代开页面、充值用户本人完成**，等用户处理后继续；
  余额够（提示与余额对不上）→ 说明情况后**原会话续聊**继续，仍报同样提示就停下如实说明；
  `ifs_balance` 不可用 → 按 `quota_info` 原样转述 + 充值入口，不编造余额数字
- `canceled`：停止轮询，呈现已取消；除非用户明确要求，不自动重新发起
- 服务端报错（`message` 带错误信息）→ 按 [exception.md](exception.md) 排障表处置；MCP 报 -32603 先原样重试一次

## 套图与垂直技能

- 套图（同一创作需求多张图）：一条消息说清整套需求（数量/差异/共同约束，明确"多张独立图片，不合成拼图"）；
  补图在原对话只重做指定项。
- 垂直技能：`skill` 参数传技能名（取 [pro-skills.md](pro-skills.md) §4 清单，一字不改，如「模特带货图」），与 `model` 参数互不冲突。
- 批量编排：连接器无批量编排的目录工具与执行通道——成套需求按上一条一次说清，要更多变体就拆成同画布多轮对话逐个执行，**不承诺一键批量**。
