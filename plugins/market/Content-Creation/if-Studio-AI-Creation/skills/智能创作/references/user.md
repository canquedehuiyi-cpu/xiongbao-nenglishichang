# 用户信息模块 — 算力积分 · 充值 · 资产查看

> 管理查询类信息（算力余额、消耗明细、账单、资产清单等）一律经**连接器查询**——可用工具以会话内
> 实时 schema（tools/list）为准；连接器不可用或没有对应查询方法时，**如实提示「功能尚未就绪」**：
> 不打开平台页面代查、不估算、不编造数字。核心红线不变：**充值永远用户本人完成，绝不代充**。

## 查询口径

- **连接器优先**：用户问算力/积分、消耗明细、账单、资产等管理查询类信息时，先看连接器有没有对应
  查询工具（以 tools/list 实时为准，算力余额用 `ifs_balance`，无入参；后续版本新增工具直接使用，
  不按本文清单判断有无）。
- **无对应方法 → 功能尚未就绪**：连接器没有对应查询工具时，如实告知用户"该查询功能尚未就绪"；
  连接器不可用本身属于授权/链路问题的，先按 [exception.md](exception.md) 处置（处置完回到本口径），
  仍无工具则同样提示功能尚未就绪。**不打开平台页面代查、不估算、不编造数据**。
- **`quota_info` 是算力信息首选来源**：生成/轮询返回中携带的 `quota_info`（底层自动检测提取）
  直接如实转述，不淡化也不编造数字。
- "这次生成花了多少"：单次消耗以返回中携带的消耗字段（如有）为准；返回未携带且连接器无查询工具
  → 功能尚未就绪，不估算。
- **资产查看**：用户问"我有哪些图/视频/资产" → 查 `ifs_assets`（近 7 天；参数只 `file_type` / `source` / `limit` / `cursor`，**不收 `canvas_id`**）查询呈现。**本会话产物不在此列**：
  直接报台账本地产物路径（默认在工作区 `outputs/`；CLI 原生命令便利层 `--save-dir` 落盘的 `downloaded[].local_path` / 连接器与降级 MCP 直通侧 Bash 下载的
  `media[].url` 文件）；回看/续聊/落盘整理等深管理
  → [asset.md](asset.md)。
- 历史画布查询：查 `ifs_canvas_list`（`keyword` / `limit` / `cursor` 三个参数，不收 `canvas_id`）；方法未挂载 → 功能尚未就绪。本会话台账内的画布直接续聊（[chat.md](chat.md) 阶段 ①）。

## 充值边界（强制）

1. **充值永远只给入口、用户本人完成，绝不代充**：返回中携带充值链接（如 `quota_info.recharge_url`）
   时直接把链接给用户；没有链接时告知用户前往 IFS 平台的算力/充值页自行充值——**不代为打开页面、
   不写死地址、不编造链接**，支付动作一律用户本人完成。
2. 不调用任何写类账务接口；余额只读查询走 `ifs_balance`，绝不用生成类工具变通支付。
3. 用户余额不足影响生成时：如实说明现状与哪些操作会消耗算力（生成/迭代），按上方口径给充值链接
   或告知自行前往；等用户处理后再继续对话。

## 算力不足：先复核再决定（create 与 poll 都适用）

`ifs_canvas_create` 返回或 poll 返回中出现算力不足（`status=quota_exceeded`，或 `message` / `quota_info`
提示算力、配额、积分不足）时，**不要直接宣布“算力不足”或让用户去充值**：先经连接器查一次余额确认，再决定下一步。

1. **查余额**：`ifs_balance`（无入参，参数传空对象 `{}`——直调形态不带 `arguments` 键；降级期 `ifs mcp call ifs_balance --args '{}'`）。
   实时方法面没有这个方法 → 跳到第 4 条。
2. **余额确实不够**：如实转述平台提示 + 查到的余额，给充值入口（返回里的 `quota_info.recharge_url`，
   没有就让用户自行前往 IFS 平台充值页），**不重发消息**，等用户处理完回原会话续聊。
3. **余额够**（提示与余额对不上）：告知“返回提示算力不足，但当前余额还有 ……，可能是并发占用或临时失败”，
   然后在**原会话**按 [chat.md](chat.md)「异常恢复与提示」续聊继续；续聊后仍报同样提示就停下如实说明，不反复重试。
4. **查不到余额**（方法未就绪 / 调用失败）：按返回的 `quota_info` 原样转述 + 给充值入口，
   说明“余额查询暂不可用”，**不估算、不编造数字**。

充值始终只给入口：用户本人完成，不代充、不代开页面、不写死地址（上方「充值边界」）。
