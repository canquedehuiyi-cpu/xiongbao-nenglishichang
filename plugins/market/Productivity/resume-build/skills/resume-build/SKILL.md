# 简历制作

> 本文件是技能的对外契约(指令式)。发布前三平台的 manifest/description 均以本文件为源。
> 依赖声明走 frontmatter dependency(官方位);不要另建 build/requirements.txt。

## 何时使用

用于求职者要做简历:用户给出目标岗位 JD 和个人素材（教育/经历/技能的自由文本），
本技能产出简历终稿。**素材里没有的经历，它不写**——起草由你（宿主）完成，
逐条验据由本地引擎完成：无据条目打回，不进终稿。

## 执行步骤（两段：你起草 → 引擎验据）

1. **你先起草**（生成侧是你的活）：按素材起草结构化 Markdown 草稿并保存为文件，
   遵守结构约定（引擎按它解析）与红线：
   - `## 教育经历` / `## 工作经历` / `## 项目经历` / `## 实习经历` / `## 技能`
     为待验节；每段经历先写 `### 起止时间 单位 职位`（如 `### 2019.07-2022.03 远山科技 后端工程师`），
     下一行起用 `- ` 列要点。
   - `## 基本信息` / `## 自我评价` 不核验（非事实主张节）。
   - **只用素材里的内容**：经历、数字、日期、头衔都来自素材；素材没有的宁可不写，
     不要补写"合理"的经历——引擎会把它打回，白跑一轮。
2. **再调引擎验据出终稿**。**路径基准:本 SKILL.md 所在目录 = 技能根**，
   宿主不预设工作目录，请先在命令行切换到本文件所在的技能根目录，再执行:

   ```bash
   python ./scripts/engine/main.py run --scenario resume-build --json --task verify --set draft-file="简历草稿的绝对路径" --set material-file="个人素材文件的绝对路径" --set jd-text="目标岗位 JD 全文"
   ```

   任务契约探测:`python ./scripts/engine/main.py tasks --scenario resume-build --json`
   环境自检(退出码 0=正常):`python ./scripts/engine/main.py selfcheck`
3. 读 stdout 严格 JSON:以 `state` / `artifacts` / `issues` 为准向用户转述。
   - 有 `review` 级 issue（N 条打回）：终稿不含这些条目——告知用户「不是写得不好，
     是素材里没有依据」。**问答引导（推荐）**：按打回清单的「建议」列逐条问用户——
     混合行问「无据部分是否属实」，属实就请用户口述补充进素材文本，再重跑；
     **不要替用户把打回条目硬塞回终稿，也不要编素材**。
   - `outputs.flagged` 是打回明细（缺的锚点/实义组/建议），原样转述。
4. 宣称"已生成"前，逐个核对 stdout 中 artifacts 声明的终稿与报告文件真实存在（文件名以当次运行输出为准）；报错原样转告,不猜不改输入。

## 异常与降级

- 引擎入口不可用（缺依赖、脚本报错、契约探测无响应）时:停止验据，把错误原样转告用户，
  并指引其先运行 selfcheck 排查；在引擎未实际运行前，不宣称终稿已生成。
- 草稿结构无法解析（缺待验节/时间行格式不对）时:原样回报解析失败位置，请用户补结构后重跑，
  不替用户改写草稿内容。

## 运行环境

- Python 3.10+;依赖见上方 frontmatter(首次使用先 pip install)。
- 推荐先设置环境变量 LOCAL_FLOW_DIST_ROOT 指向一个可写目录再运行,产物不落在插件目录内。

## 红线（不要做的事）

- 结论只认引擎报告;待人工项(冲突/不可比/未解析)如实转告用户。
- 引擎零 LLM 调用、零网络:宿主只整理输入与转述结论,不替引擎下判定。
- 不编造经历与数据;素材不足的条目打回;判定不了就转人工。
