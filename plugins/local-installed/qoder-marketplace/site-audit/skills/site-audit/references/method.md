# 方法说明（白盒）

## 取证位置决定结论是否成立

同一件事有三个可能的取证位置，它们不等价：

| 位置 | 能看到 | 看不到 |
| --- | --- | --- |
| 源码 | 意图、契约声明 | 构建期改动、托管侧注入 |
| 产物 `dist/` | 构建真正输出了什么 | 交付时被改写的部分 |
| 被服务的响应 | 访客实际拿到什么 | 构建期崩溃、门禁是否可信 |

「产物里没有第三方脚本」和「站点不加载第三方脚本」是两个不同的命题。历史上真正值钱的一条发现，
是在换成第三列取证时才出现的。所以 `LIVE-1` 的判定必须用**集合差**而不是单侧观察。

## 审门禁，而不是只看门禁的结果

`gates.mjs` 的立场：一道「绿」的门禁只有在它确实能变红时才算证据。因此：

- `SEC-4` 会**破坏门禁自己去读的那个输入**（一次一个，用完还原），看它是红还是继续自称通过；
- `SEC-1` 从项目文档里抠出凭据形态描述，造合成样本喂回扫描器提取的正则；
- `CTX-3` 造一条确定违反 README 契约的内容样本，喂进该校验器在 `--out` 里的副本。

这三项的共同点：**错了不会报错，只会静默失效**。所以必须由外部去制造失败，而不是信任它的输出。

## 为什么破坏性测试都在副本里做

`--out` 下会生成 `ctx3-worktree/`、`sec4-<gate>/`、`bld3/` 等副本目录，
复制时排除 `node_modules`、`.git`、`dist`。被审项目自己的树**只读**。
这条不可协商：一个审查工具如果会改它正在审的东西，它就不再是证据来源。

## 判据的转义感知

`INJ-1` 的载荷电池曾产生 5 个假阳性，原因是把「正文里出现了 `onerror=` 这段文字」
当成「存在内联事件属性」。正确判据必须要求危险构造处在 markup 位置（真实的 `<tag ... attr=`）。
改这个判据时，先拿一个已知正确转义的渲染器验证它**不报红**——selftest 里的 `MUST_NOT_FAIL` 就是干这个的。

## 跨轮结转

`ledger verify` 用「注册表适用项 − 本轮入账项」补 `not-run` 行，所以：

- 一项检查从「跑过」变成「没人跑」时，它会以 `not-run + 本轮无任何脚本覆盖该项` 重新出现，
  而不是安静消失；
- `LIVE-3` 靠 `served-snapshot.json` 对比状态码、CSP 指纹、第三方源集合，
  用来发现「修复上线后其实没生效」；
- 新一轮开始前先 `git diff --stat <上轮审过的 sha>..HEAD`：只改内容文件时，
  源码类检查降级为廉价复验，重心转向门禁可信度与内容契约漂移。

## 被拒的方案（以及为什么）

- **不做自动修复**：会改自己证据的审查工具不成立。
- **不用 YAML/JSON 定义检查**：注册表必须是代码，检查才能自带断言；DSL 只多一个解析器。
- **不装 Playwright/puppeteer**：违反「零依赖 + 新克隆可跑」。浏览器层交给宿主的浏览器工具，
  缺了就老实记 `not-run`。
- **不为 Astro/Next/Hugo 各写适配**：断言都落在 HTML 层，框架差异只是产物布局，`--dist-glob` 足够。
- **不做爬虫/站点图**：页面采样由 `--pages` 或产物清单决定，请求预算是硬约束。
- **不做遥测或云端账本**：账本留在用户的 `--out`，要不要进仓库由用户显式决定。
