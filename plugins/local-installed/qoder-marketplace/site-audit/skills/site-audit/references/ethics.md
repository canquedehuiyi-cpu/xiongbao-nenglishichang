# 边界与授权（黑盒）

## 你在替谁承担风险

黑盒模式下所有网络请求都发往一个**可能不属于使用者**的主机。这意味着：

- 请求会带着使用者所在网络的标识出现在对方的访问日志里；
- 某些探测（管理路径、并发拉取、提交表单）在多数司法辖区可能构成未授权访问；
- 对方可能部署了 WAF，会把你的行为判定为攻击并回报给执法/上游。

所以本工具的默认姿态是：**只读、限速、单源、不留痕、需要显式授权**。

## 代码强制的八条红线

`scripts/lib/net.mjs` 直接实现，改命令行参数绕不过：

1. **只允许 GET/HEAD**。其它方法在入口层抛 `PolicyViolation`。不提交任何数据。
2. **单一 origin（对目标站）**。审 A 站时不得顺手打 B 站。只有显式开启的外链探测走
   另一个池，允许换主机，但它对**内网/元数据地址永远先拒**，且这条判定排在「换主机」之前
   （放在之后就会被恶意页面绕过：内网地址排在第二条链接时照样拨出去——本轮实测过）。
3. **一轮请求预算 60 = target 池 40 + external 池 20**、并发 2、超时 8s、最小间隔 250ms。
   计数、间隔时刻与熔断都记在 `<OUT>/net-round.json` 里**跨脚本共享**——一轮由 4 个脚本发出请求，
   各记各的等于 4×预算、实测平均间隔 129ms。预算耗尽返回 `not-run` 而不是继续发。
4. **熔断**。连续 2 次 429 或 3 次 403 → 该站剩余检查一律 `not-run`，并写明（计数同样跨脚本共享：
   否则每个新进程的计数都从零开始，恶意站点只需每次给你 2 个 403 就能白买一次「无死链」）
   「被限流/屏蔽，**不能据此判断内容死活**」。
5. **不做子域枚举、不猜管理路径、不带任何字典**。
6. **不发送凭据、cookie、Authorization**，UA 里不带使用者联系方式（除非自己填）。
   URL 里带 `user:pass@host` 的链接**直接拒绝探测**，而不是摘掉凭据再发——摘掉后拿到的
   200/401 会被当成那条链接的死活结论，而工具承诺过从不带凭据。
7. **域名先解析再连**：解析结果落在内网/元数据段就拒绝连接。主机名黑名单看不见 A 记录，
   一条把 `evil.example.com` 指到 `127.0.0.1` 的记录就能绕过第 3 条里的内网红线。
8. **绝不在被审仓库里就地执行或写入**。要跑它的门禁/构建，一律复制进 `<OUT>` 的临时副本；
   副本用 `lstat` 遍历并跳过符号链接，避免被一个指回宿主目录的软链带出去。

## robots.txt 的立场

先取 `robots.txt`，把 `Disallow` / `Allow` / `Sitemap` 记进 `capabilities.json`，让人核对。

**如实说明当前边界**：本工具不爬站——页面清单来自 `--dist` 里的产物或 `--pages` 显式列表，
所以 `Disallow` **不会被自动排除**，「尊重 robots.txt」目前只是可见性而非强制。
跑黑盒前先照着 `capabilities.json` 里的 `robots.disallow` 过一遍你给的清单。
（原先实现的 `isDisallowed()` 没有任何调用点，属于「写了但没接上」的假实现，已删除并改为如实说明——
一个声称在做、实际没做的安全约束，比没有更糟。）

`robots.txt` 本身不是法律文件，但绕过它去审查别人的站，是把「我是研究者」当成免罪符。

## 外链存活：为什么默认关闭

`surface --probe-links` 会向第三方站点发请求。它有两重顾虑：一是同样的未授权问题，
二是**测不准**——数据中心 IP 被 Bloomberg/Reuters/WSJ 一类站点用 WAF 拦，
从审查机看到的 403/超时与真正的死链在响应层无法区分。

因此它的判定被分成三类，且只有第一类可以当结论用：

| 观察 | 可以说 | 不可以说 |
| --- | --- | --- |
| 404 / 410 | 已确认死亡 | — |
| 403 / 429 / 451 | 被 WAF 或限流挡住 | 「链接失效」 |
| 连接失败 / 超时 | 审查机到不了 | 「链接失效」 |

## 隐私：报告里也可能有别人的数据

被审站点的页面正文里可能有真实读者的邮箱、手机号、姓名。所以：

- 账本的 `evidence` 字段写盘前一律截断 200 字符并做形态脱敏（邮箱、电话、凭据形态 → `[REDACTED]`）；
- 第三方站点的 host 在账本里只记 SHA-256 前 12 位（`targetHash`），人类报告里才出现全文；
- 报告文件本身按机密材料对待：里面是「某站的具体缺陷清单」，别贴进公开 issue 或聊天群；
- 提醒事项 hook 默认不动作，且即使开启也只输出检查 ID 与计数，不输出 URL 或路径。

## 不能查的东西必须说清楚

黑盒模式下 `BLD-*`、`INJ-*`、`PIPE-*`、`SEC-*`、`CI-*` 全部是 `not-run`。
把这些留在报告里并逐条说明解锁方式，比给出一份「看起来完整」的报告更有用——
前者是诚实的不完整，后者会让人以为一个站的发布链路是安全的。
