## 填写说明

| 模板位置 | 数据来源 | 说明 |
|---------|---------|------|
| `{{skill-name}}` | Step 1 选题 | 小写字母+连字符，如 `homework-design` |
| `{{description}}` | Step 2 模块0 | 用建模产出的一句话定义：为谁+什么输入+什么输出 |
| 一句话定位 | Step 2 模块0 | 建模的缩句结果 + "不做什么"边界（至少2条） |
| 身份定位 | Step 2 模块B | 角色描述，强调辅助而非替代 |
| 使用场景 | Step 2 模块A | 教师回答的"什么时候用" |
| 前置条件 | Step 2 模块A | 教师回答的"需要输入什么" |
| 工作流程 | Step 2 模块B | 教师回答的"第一步第二步..." |
| 刚性前提 | Step 2 模块0 | 建模时识别的刚性前提清单，逐条显式写出 |
| 教学约束 | Step 2 模块C | 从约束库选取 + 刚性前提转化 + 教师自定义 |
| 理论支撑 | Step 2 模块B/C | 列出本智能体参考的理论文档，标注适用环节，说明如何通过 ima 知识库检索（如无理论依赖可省略此段） |
| 质量标准 | Step 2 模块D | 价值验证（固定项）+ 从测试清单选取检查项 |
| 学科适配 | Step 1 选题 | 根据教师选择的学科补充 |
| 启动语 | 自动生成 | 基于前置条件生成引导语 |
| 系统级需求备注 | 设计全程 | 超出智能体边界的需求登记，不写入工作流程 |
