# 可交互HTML实现

目标是解压后能演示主要流程的代码。默认HTML/CSS和少量JavaScript；多文件页面或单入口hash导航均可，依据页面数量选简单方案。不为此设计服务端、数据库、认证、支付、状态管理框架或部署平台。

支持手机App、移动网站、小程序和PC网站的交互原型。App与小程序沿用已确认的页面结构、导航和返回体验，在浏览器中模拟；移动网站与PC网站按各自目标视口实现，统一交付HTML及DESIGN.md。

此前的design-review/index.html只用于平铺效果图。只有当前整组效果图明确确认后才进入本阶段；交互实现使用单独prototype目录，继续保留审稿总览入口。

## 从图到页面

1. 打开采用图和DESIGN.md，先实现代表页的布局、字号层级、内容密度与主控件，在同一目标视口截屏比较。
2. 校正后复用CSS变量和共同导航／组件到其他页面，不把不同页面写成同一模板的文字替换。
3. 文字、按钮、输入框、菜单与主要卡片采用实际DOM。图片只承担照片、插画或确实属于视觉素材的部分，不使用整页截图背景加透明热点冒充HTML。
4. 保持图中的准确文案和层级，图中乱码按已确认需求文案修正并记录；无法判断的关键文案简短确认，普通示例值标为模拟数据。
5. 手机与PC按分别采用的图片实现。仅当用户要求响应式网页时共享内容并定义断点；双端不用简单等比例放大。处理手机安全区、固定底栏、弹层与滚动，不让主按钮被遮挡。

## 交互最小集

- 页面清单每页可从入口或真实导航到达；主要跳转与返回都有实现。
- 标签、筛选、选择、展开、弹窗能显示实际状态变化；按钮有明确反馈。
- 本次核心表单有标签、合理输入类型、基础必填检查和模拟成功／失败反馈。
- 模拟登录、下单、支付、导出等在README说明，不真实发送数据、付款或下载伪造业务结果。
- 有状态的演示可用内存或localStorage，需提供明确重置方式；示例内容不含真实个人资料。
- 用语义化button/link/input，支持键盘焦点、Esc关闭弹窗、可读对比度、足够点击区域；不得为追求截图一致让主要操作不可用。
- 次要功能可禁用并说明当前演示范围，不用死链接和无反应按钮冒充完成。

外部字体、图标、图片能本地化则随包保存，并保留所需许可。默认不用CDN／远程API或外部运行依赖；外部信息链接按用户需求保留并明确打开外部页面。避免无授权下载字体或第三方模板资产。

## 预览校正

用宿主实际浏览器打开项目，在每个页面记录的视口截图，对比采用图的主布局、颜色、字级、密度和导航。检查相邻宽度的溢出、遮挡、断图、文字换行和横向滚动。逐条点击主要流程及返回，验证模拟输入和状态重置；浏览器控制台可见时检查错误。

修复纯代码与交互问题直接继续。要改主布局、主配色或整体审美时回到图片迭代，避免HTML渐渐偏离已采用图。没有浏览器就交付可运行文件和启动指令，明确预览未验证；不要生成假的浏览器验收记录。

代码在浏览器跑通仅证明原型，不代表生产可用、真实业务闭环、全设备兼容或无障碍认证。
