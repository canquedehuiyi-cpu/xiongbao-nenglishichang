# 在Qoder持续预览同一总览

总览固定为design-review/index.html，每轮新图下载后更新这一文件，再使用宿主实际可用的文件展示／HTML预览／浏览器工具呈现。先发现工具及Schema，不臆造固定工具名或平台专属侧栏接口；支持右侧预览时优先右侧，不支持时使用实际可用浏览器。

1. update之后执行check --expected，以本轮真实下载记录核对新版、作品ID、图片哈希及HTML。不能拿总览旧清单当expected，也不能只更新board.json。
2. 打开／刷新已有总览入口，确认不是单张图片，核对页面数量、名称、基准图及本轮版本。HTTP预览每2秒检查本地刷新标记，查看放大图时延后刷新；纯文件预览重新打开或刷新。不另造一串独立版本总览。
3. 确认实际可见的新版本后，简短说明更新了哪些页面，继续接受一页或多页反馈。仍未看到新版时先修复预览或资源，不重新生图。
4. 用户明确整组确认并要求下一步前，一直停在审图阶段。报价确认、下载成功或单页满意不能代替整组确认。

若需要HTTP方式，只在已有工具环境允许时启动绑定127.0.0.1的静态服务，并给出实际端口／路径。宿主与本地文件系统隔离时，使用宿主明确支持的文件／预览通道；不要声称另一个环境的localhost可访问。服务退出后链接可能失效，始终保留自包含HTML。

无法自动打开时如实说明，交付总览HTML文件及手动打开方法，不写成“已在右侧打开”。无文件能力时说明尚未建立本地总览，保留已生成的结果，不假称完成同步。不自动上传或公开发布；用户软件原型的最终预览也遵守同样的能力核验。
